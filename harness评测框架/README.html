评测框架与 agent 脚手架

一句话：大模型榜单上那些分数 —— 谁出的题、谁判的卷、判得准不准，以及同一个模型换个"外壳"分数能差一大截是怎么回事。

27 篇笔记，分两大块 + 三份框架拆解。

★★★ 先解决一个词：harness 在这里有两个完全不同的意思

英文 harness 本意是"挽具、套具"—— 套在马身上让它能拉车的那套皮带。在大模型圈子里，这个词被借用了两次，指两个完全不同的程序。这是本目录最容易搞混的地方，先分清再往下读。

 ┌────────────────────────────────────────────────────────────┐
 │  ① evaluation harness（评测框架）  =  出题 + 判卷 的程序     │
 │                                                            │
 │     它站在模型【外面】当考官：                              │
 │     发题目 → 收答案 → 对标准答案 → 算分 → 出榜单            │
 │                                                            │
 │     例：lm-evaluation-harness、OpenCompass、EvalScope       │
 │     → 看 评测入门/                                          │
 └────────────────────────────────────────────────────────────┘
                            ⇕  完全不同的两个东西
 ┌────────────────────────────────────────────────────────────┐
 │  ② agent harness / scaffold（智能体脚手架）= 让模型干活的程序│
 │                                                            │
 │     它包在模型【外面】当手脚：                              │
 │     给工具（读文件、跑命令）→ 管上下文 → 管权限沙箱 → 循环   │
 │                                                            │
 │     例：Claude Code、Codex 的内部结构                        │
 │     → 看 agent脚手架/                                       │
 └────────────────────────────────────────────────────────────┘

为什么必须放在一个目录里讲：因为在 SWE-bench 这类"让模型真的去改代码"的榜单上，这两层会同时起作用 —— 考官（①）出的题，模型要靠手脚（②）才能做。所以同一个模型，配个好脚手架分数就高。agent脚手架/08-脚手架怎么影响榜单分数.md 讲的就是这件事。
