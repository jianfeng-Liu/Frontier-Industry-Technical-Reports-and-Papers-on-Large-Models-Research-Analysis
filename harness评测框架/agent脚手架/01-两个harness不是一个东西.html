01 · 两个 harness 不是一个东西

这一章只做一件事：把边界划清楚。
讲清楚脚手架从哪开始、到哪结束，后面七章才有地方可讲。

1.1 先把三个英文词摆清楚

★ 你在中文资料里会看到"harness""脚手架""agent 框架"混用。它们其实指两类东西：

   ★ 名词：harness
     字面意思是【挽具、马具】——套在牲口身上让它按你要的方式使劲的那套皮带。
     ⟹ 引申到工程上：★★【套在某个东西外面、规定它怎么被使用的那层程序】。

     ★★★ 问题就出在这儿：套在【模型】外面是一层意思，
          套在【题目】外面又是另一层意思。于是同一个词有了两种用法。

★★★ 两种用法摆在一起看（★ 这张表是全章的起点）：

用法 A：evaluation harness（评测框架） 用法 B：agent harness / scaffold（智能体脚手架）
套在谁外面 ★★ 套在【题目】外面 ★★ 套在【模型】外面
一句话职责 把 benchmark（评测集）里的题按统一格式喂给模型，收回答案，判对错，算分 给模型工具、跑它要的命令、把结果喂回去、管住上下文别爆、决定什么时候停
★ 代表实现 lm-evaluation-harness、OpenCompass、EvalScope、SWE-bench 自带的 run_evaluation.py SWE-agent、Claude Code、Codex CLI、OpenHands
谁讲它 ⟹ 隔壁目录 评测入门/ 讲的全是这个 ⟹ 🔑 本目录讲的全是这个 
   ★ 名词：scaffold（脚手架）
     ⟹ 和 agent harness 是同义词，业界两个词换着用。
     ★★ 盖楼时钢筋水泥是主体，脚手架是让工人上得去的架子——
        楼盖完脚手架就拆了，但没有它楼盖不起来。

   ★ 名词：agent（智能体）
     ⟹ 指【模型 + 脚手架】合起来的那个能自己动手干活的东西。
     ★★★ 注意：agent 不等于模型。这是全目录最容易搞混的一点。

⚠️ 还有第三个词也会混进来：agent 框架（agent framework，例如 LangChain、AutoGen、LlamaIndex）。它指的是"给你搭脚手架用的那套库"，是工具箱；而本目录讲的 scaffold 是搭出来的那个成品。★ 这一层区分在本目录里基本不重要，因为 SWE-agent / Claude Code / Codex 都是自己从底层写的，没用第三方 agent 框架。

1.2 两者的接口窄到只有一个文件

★★★ 这是本目录能独立成册的技术原因。

   题目                     agent 脚手架               评测框架
   (issue 文本 + 仓库)      (模型在里面反复折腾)       (跑测试、判分)
        |                        |                        |
        +-----------> 输入 ------+                        |
                                 |                        |
                                 +---- 一个 patch 文本 --->+
                                 |                        |
                                 |                        +--> resolved / 不 resolved
                                 |
                      ★★★ 交出去的只有一样东西：
                          一个 patch（补丁）文本
                      ★★ 中间这根箭头上，没有"跑了几轮""用了什么工具"
                         "花了多少钱"这些信息。一个字都没有。

✅ 这不是我编的，是 SWE-bench 判卷器的源码事实。评测入门 08 章 §8.1 逐行引了它的注释：

# pred (dict): Prediction w/ model_name_or_path, model_patch, instance_id

   ⟹ 🔑🔑 判卷器只认三个字段：
      instance_id        = 哪道题
      model_patch        = ★★ 你交上来的补丁文本
      model_name_or_path = ★ 一个你自己随便填的字符串（只当日志目录名用）

   ⟹ ★★★ 也就是说：
      【补丁怎么做出来的，评测框架一个字都不问。】

   ★★ 名词：patch（补丁），也叫 diff
     ⟹ 一段纯文本，写明"哪个文件的第几行，从什么改成什么"。
        git 生成它的命令就是 git diff。
     ★★★ 它是脚手架和评测框架之间【唯一的通信内容】。

⚠️ 注意 model_name_or_path 这个字段名很有误导性：它听起来像"你用了哪个模型"，但判卷器不校验也不使用它的内容，只拿它当输出目录名。★★★ 换句话说，你可以用 Claude 跑出补丁、把这个字段填成 gpt-4，判卷器照样给你算分 —— 它压根没有"模型"这个概念。

1.2b ⭐⭐ 并排对照表：两个 harness 各管什么、换掉谁会动分数

★★★ 这一节是本章的核心。上面两节说清了"它们是两个东西"，这一节说清为什么这件事值得单独写八章。

① 逐项对照

问的是什么 评测框架（evaluation harness） agent 脚手架（scaffold）
套在谁外面 题目 模型
输入是什么 ① 题目数据集 ② ★★ 别人交上来的答案（patch） ① 一道题的 issue 文本 ② 一个仓库的某个 commit ③ 一个模型 API 端点
输出是什么 ★ 一个分数（% Resolved / 准确率 / pass@k） ★ 一个 patch 文本，就这一样
谁提供它 ★★ 出题方（SWE-bench 作者）提供，开源，大家共用一份 ★★★ 报分的人自己搭，每家一套，通常不公开
它跑几次 每道题跑一次判卷（确定性流程） ★★ 每道题内部循环 N 轮（12 轮、21 轮、500 轮都有）
换掉它，分数会怎么动 ★★ 所有模型的分数一起动——因为尺子变了。✅ 一手证据：DeepSeek V3 报告 §4.4.2 承认框架改了几个月后，自家旧模型的分数就和上次公布的对不上了（见 评测入门 11 章） ★★★ 只有用这套脚手架的那一个模型的分数动，别人不动。✅ 一手证据：同一个 GPT-4 Turbo，2.67 → 11.00 → 18.00（§1.4）
🔑 它的贡献被算进谁的能力 ★ 不算进任何模型——它是公共的"口径" ★★★ 全额算进模型头上。榜单印的是"GPT-4 Turbo 18.00%"，不是"GPT-4 Turbo + SWE-agent 18.00%"
榜单上写不写 ★ 通常写（"用 SWE-bench 官方 harness 判卷"） ★★★ 通常不写，或者只写一个产品名
本仓库哪讲 隔壁 评测入门/ 12 章 🔑 本目录 8 章 
   ⟹ 🔑🔑🔑 ★★★ 这张表里只有一行需要你背下来：

      【评测框架换了，是"尺子变了"，大家一起变，还有人会提一句。
        脚手架换了，是"这个模型变强了"，只它一个变，而且没人提。】

   ⟹ ★★ 所以这两个 harness 虽然同名，在"分数可信度"这件事上
      扮演的角色完全相反：
      一个是【公开的、共用的、会被审的】；
      另一个是【私有的、各搭各的、没人审的】。

② 把一道题的七个步骤摊开，标出谁做、谁可以换

★★ 同一道 SWE-bench 题，从"给 issue"到"算出分数"，七步里前三步归脚手架，后四步归评测框架：

步 做什么 谁做 这一步可以换吗 ⚠️ 换了之后分数会怎么动
① 决定给模型看仓库的哪一部分 ★★★ 脚手架（报分方自己定） ★★ 完全自由 ✅ 同一个 Claude 2：BM25 检索 1.96%、oracle 4.80%（见 评测入门 07 章 §7.9）
② 给模型几个工具、工具长什么样 ★★★ 脚手架 ★★ 完全自由 ✅ 同一个 GPT-4 Turbo：有 edit 带 linter 18.0，没有 edit 只剩 shell 10.3（03 章）
③ 循环几轮、花多少钱停、上下文怎么扔 ★★★ 脚手架 ★★ 完全自由 ✅ 只留最近 5 条观察 18.0，留全部历史 15.0（04 章）
④ 起一个装好依赖的 Docker 容器 ★ 官方评测框架 不能（官方代码） —— 谁跑都一样
⑤ 把 patch 打进容器 ★ 官方评测框架 不能 ⚠️ 打不进去就是 0 分，但这是格式问题冒充能力问题
⑥ 跑出题时就定好的那份测试名单 ★ 官方评测框架 不能 —— 谁跑都一样
⑦ 判 FAIL_TO_PASS 和 PASS_TO_PASS 是否全绿 ★ 官方评测框架 不能 —— 谁跑都一样 
   ⟹ 🔑🔑 ★★★ 读这张表只带走一句：

      第 ④⑤⑥⑦ 步是【官方代码，谁跑都一样，所以可比】。
      第 ①②③ 步是【每家自己搭，完全不受约束，所以不可比】。

   ⟹ ★★ 而榜单上那个数字，是 ①②③ 和 ④⑤⑥⑦ 的【乘积】。
      只公布一个乘积，不公布前三个因子，
      ⟹ ★★★ 这就是本目录八章要解决的全部问题。

1.3 所以"脚手架"到底负责哪一段

⚠️ 下面这张职责表是我对公开实现（SWE-agent 论文 + 开源实现、Claude Code / Codex 官方文档）的归纳，不是某一篇论文的原话。但每一项在后面章节都有 ✅ 出处。

# 组成部分 ★ 它具体在做什么 这一项能把分数动多少 详见
① 循环（loop） 模型输出一个动作 → 脚手架真去执行 → 把执行结果拼成下一轮的输入 → 再问模型。★★ 这个圈转多少次、什么时候停，全由脚手架决定 ✅ 有脚手架 vs 一轮盲写：2.67 → 18.00 02 章
② 工具集 / ACI 给模型哪几个动作可用（读文件？跑 shell？搜索？），以及【每个动作的输出长什么样】 ★★★ ✅ 单这一项就值 7.7 个点（18.0 → 10.3） 03 章
③ 上下文管理 仓库几十万行，装不进模型的窗口。★★ 什么时候塞什么、旧的怎么压缩掉 ✅ 3.0 个点（18.0 → 15.0） 04 章
④ 权限与沙箱 允许它改哪些文件、能不能联网、要不要问一句再动手 ⚠️ 这一项在评测场景里通常全开，但在你公司里是头等大事 05 章
⑤ 采样与预算 ★★★ 只跑一遍？还是跑 6 遍挑最好的？花到多少钱掐断？ ★★★ ✅ 同一套 SWE-agent：pass@1 = 17.94，pass@6 = 32.67（§1.4b） 02 章 讲机制；08 章 讲它怎么毁掉可比性 
   ★ 名词：ACI（Agent-Computer Interface，智能体-计算机接口）
     ⟹ 专门为【模型】而不是为【人】设计的那套操作界面。
        这个词是 SWE-agent 论文提出来的，03 章整章在讲它。

   ⟹ ★★ 这五项的共同点：
      【它们全都不是"模型"，但它们全都会动"模型的分数"。】

1.4 一个反例：最简陋的"脚手架"长什么样

★★ 有对比才知道脚手架值多少钱。SWE-bench 自带一个最原始的版本（评测入门 08 章 引过它的源码）：

   ★ swebench/inference/run_api.py 的做法：

      拼一个大 prompt（把检索到的文件塞进去）
        → 调一次 API
        → 用正则从回复里抠出补丁
        → 完。

   ⟹ ★★ 一轮。没有工具。没有反馈。不跑测试。不知道自己改对没有。

✅ 这套做法在 SWE-bench Lite 上的成绩，SWE-agent 论文 Table 1 给了确切数字（✅ 下面三行全部是论文原表数据，arXiv:2405.15793）：

设置 模型 SWE-bench Lite % Resolved ✅ 论文同表给的平均成本
RAG（一轮盲写，BM25 检索） GPT-4 Turbo 2.67 $0.13
Shell-only agent（能跑 shell，但界面是原生 Linux；论文 Table 1 标题里叫 Basic CLI） GPT-4 Turbo 11.00 $1.46
SWE-agent（专门设计的 ACI） GPT-4 Turbo 18.00 $1.67 
   ⟹ 🔑🔑🔑 ★★★ 同一个模型，一个字没换。
      ✅ 模型 ID 是 gpt-4-1106-preview（论文 §4 写明）。
      2.67 → 11.00 → 18.00。
      ★★ 差出来的 15.33 个百分点，全是【脚手架】贡献的。

★★★ 这里有一个非常容易说错的地方，必须掰开：

   ⚠️⚠️ 百分点 vs 百分比，同一组数字能读出两个完全不同的说法：

      18.00 − 11.00 = 7.00            ⟹ 这叫【7.00 个百分点】
      (18.00 − 11.00) / 11.00 = 63.6% ⟹ 这叫【提升了 64%】（相对提升）

   ✅ 论文自己用的是后一种说法（★ 逐字）：
      "An LM-friendly ACI's value is confirmed by SWE-agent's 64%
       relative increase compared to Shell-only, both with GPT-4 Turbo."
      ⟹ 【换成对模型友好的 ACI，相对 Shell-only 提升了 64%。】

   ✅ 对 RAG 那一行，论文用的说法是"6.7 倍"：
      18.00 / 2.67 = 6.74 ⟹ "a 6.7-fold improved % Resolved rate"

   ⟹ ★★★ 所以同一件事，你会在三种不同的句子里看到它：
      「涨了 7 个百分点」「涨了 64%」「涨了 6.7 倍」——
      ★★ 这三句话都对，说的是同一个 11.00 → 18.00。
      ⚠️ 而把"7 个百分点"写成"涨了 7%"，就是错的。

   ⚠️ 我的判断：这个差距，大过当时（2024 年中）相邻两代前沿模型之间的差距。
      ⚠️ 这是我的归纳，论文没有做这个对比，没有一手数字支撑。

   ★ 名词：RAG（Retrieval-Augmented Generation，检索增强生成）
     ⟹ 先用关键词从代码库里搜出几个可能相关的文件，
        连同问题一起塞进 prompt，让模型一次性写出答案。
     ★★ 它不是 agent——因为它【只有一轮，不会根据执行结果调整】。

   ★ 名词：BM25
     ⟹ 一个经典的关键词检索打分算法（不涉及任何神经网络）。
        SWE-bench 的 RAG 基线用它来挑"看起来和 issue 相关"的文件。

1.4b ⭐⭐ 一个 agentic 分数，必须和哪八项口径一起出现

★★★ 上面那三个数字（2.67 / 11.00 / 18.00）之所以能拿来比，唯一的原因是：论文把下面这八项全写出来了。⚠️ 而榜单上的分数，这八项通常一项都没有。

① 八项口径清单 —— 用 SWE-agent 论文当"满分答卷"

# 口径项 ✅ SWE-agent 论文怎么交代的 ⚠️ 不写会怎样
① 数据集版本与题数 ✅ 写明：主结果用 SWE-bench 全量 test split（2,294 题，来自 12 个仓库），消融与分析用 Lite split（300 题） ⚠️ 全量 12.47 和 Lite 18.00 是同一次运行的两个数。混着比，就是比了两把不同的尺子
② ★★★ 脚手架版本与配置 ✅ 写明：温度 0.0、文件视窗 100 行、历史策略 "Last 5 Obs."（论文 §B.1 的超参扫描结论） ⚠️ ★★★ 这是本目录最核心的坑。同一个模型换这三个旋钮，论文自己的扫描里分数从 8.7 走到 15.1
③ 工具集清单 ✅ 逐个列了：find_file / search_file / search_dir / open / scroll_up / scroll_down / goto / create / edit / submit，另外允许用通用 Linux 命令 ⚠️ "有没有 edit 命令"一项就值 7.7 个点（03 章）
④ ★★ 是否允许运行测试 ✅ 允许。论文 Figure 7 的动作频次图里直接出现了 python / python3 / pytest 三个动作 ⚠️⚠️ 这一项最致命：SWE-bench 的规则是 agent 不能看到判卷用的 FAIL_TO_PASS 测试名单。允许它跑"仓库里已有的测试和它自己写的复现脚本"是正常的；如果脚手架把判卷测试名单也喂进去了，分数就没有意义了
⑤ 重试与格式错处理 ✅ 写明：格式不对就回一条报错让它重来，直到写对；并且 ✅ 论文 §B.9 报告"全部运行里只出现过两次 Early Exit"（连续格式错太多被强行结束） ⚠️ "重试不算失败"和"重试一次就算这题挂了"，是两个完全不同的分数
⑥ ★★★ 预算 / 步数 / 超时上限 ✅ 写明：每题预算 $4；✅ 并且写明超了之后的处理是"把现有改动自动交上去"（★ 逐字："if a run exceeded this budget, existing edits were submitted automatically"） ⚠️ ★★★ 每题 $2 和每题 $20 是两个完全不同的实验。榜单从来不写
⑦ ★★★ 跑几遍、怎么汇总（pass@k） ✅ 主表全部是 pass@1（即 % Resolved，跑一遍）；✅ 附录 §B.5 另外跑了 6 遍，给出 pass@1 到 pass@6 ⚠️ ★★★ 见下面 ② 节——同一套脚手架同一个模型，pass@1 是 17.94，pass@6 是 32.67
⑧ 模型 ID 与上下文窗口 ✅ 写明：gpt-4-1106-preview（128K 窗口）/ claude-3-opus-20240229（200K 窗口） ⚠️ "GPT-4" 这三个字在 2024 年指过至少四个不同的模型快照 
   ⟹ 🔑🔑🔑 ★★★ 把这张表的用法说死：

      ★★ 你看到一个 agentic 分数，这八项里缺任何一项，
         你就【不能】拿它和另一个分数比大小。
      ⚠️ 不是"比出来不准"，是【比出来的差值没有定义】。

   ⟹ ★ 这八项的速查版在 [附-速查表.md](附-速查表.md) G 节。

② ⚠️⚠️ 第 ⑦ 项单独拆：同一套脚手架能报出两个差 14.7 个百分点的分数

★ 顺带，这组数据还回答了一个常见疑问："同一套东西重跑，分数会抖多少？"

   ✅ 答案：在 Lite 300 题上，六遍的极差是 4 道题 = 1.34 个百分点，
      标准差 0.49 个百分点。
   ⟹ ★★ 这叫【重跑噪声】（run-to-run variance），来源是采样随机性。
   ⚠️ 注意它和下面 ③ 节讲的【题目抽样噪声】是两个不同的东西，
      ★★★ 量级也差了四倍多。初学者常把两者混成一个"误差"。

③ ⚠️⚠️ 差多少才算真有差别：把噪声下限算出来

★★★ 一个分数是在有限道题上量出来的，所以它自带一个统计误差。★ 最简单的估法：

   ★ 二项分布的标准误（standard error，SE）：

      SE ≈ sqrt( p * (1 - p) / n )

      p = 解决率（用小数写，比如 18% 写成 0.18）
      n = 题数
评测集 题数 n 假设解决率 p ★ 算式 SE（百分点）
SWE-bench Lite 300 0.18 sqrt(0.18 × 0.82 / 300) = sqrt(0.000492) ≈ 2.2
SWE-bench Verified 500 0.50 sqrt(0.25 / 500) = sqrt(0.0005) ≈ 2.2
SWE-bench Verified 500 0.80 sqrt(0.80 × 0.20 / 500) = sqrt(0.00032) ≈ 1.8
SWE-bench 全量 2294 0.12 sqrt(0.12 × 0.88 / 2294) = sqrt(0.0000460) ≈ 0.7 
   ⟹ 🔑🔑 ★★★ 带走一句：
      【SWE-bench Verified 只有 500 题，单个分数自带约 ±2.2 个百分点。
        所以榜单上差 1 个点，基本是噪声。】

   ⚠️ 两条必须跟上的限定，否则这个公式会被用错：

      ① ★★ 这个 SE 量的是【换一批题会抖多少】（题目抽样噪声），
         不是【同一批题重跑会抖多少】（上面 ② 节那个 0.49）。
         ⟹ 两个来源要分开说，不能加在一起也不能互相代替。

      ② ★★★ 比较【同一批题上的两个配置】时，真实噪声比 2.2 小——
         因为两边做的是同一道道题（统计上叫"配对"），
         ⚠️ 那些"两边都会做对"和"两边都做不对"的题互相抵消了。
         ⟹ 但它也不会小到可以忽略：Lite 上 1 个百分点 = 3 道题，
            ★★ 消融表里 ↓1.7 这种量级（约 5 道题）就已经不够硬了（03 章）。

④ ⚠️⚠️ 顺带把 pass@k 的三种算法钉死（★★★ 哪个有偏很反直觉）

★★ 第 ⑦ 项口径里那个 pass@k，公开材料里至少有三种算法，数值不同。✅ 出处是 HumanEval / Codex 论文（arXiv:2107.03374，OpenAI，2021）的 Appendix A。

   ★ 记号（三个字母贯穿下面全部）：
      n = 一道题实际采了几个样本
      c = 这 n 个里有几个通过了测试（correct）
      k = 你想报的那个 pass@k 里的 k
# 算法 公式 有偏吗 方差
① 组合数估计量（✅ 论文正式定义，要求 n ≥ k） 1 − C(n−c, k) / C(n, k) ✅ 无偏 ★ 小
② 插值法（看着最自然） 1 − (1 − c/n)^k ⚠️⚠️ ✅ 有偏，而且系统性偏低 小
③ 直接法：就采 k 次，看有没有对的 至少一个通过 → 1，否则 → 0 ✅ 无偏 ⚠️⚠️ ★★★ 极大 
   ⟹ 🔑🔑🔑 ★★★ 这里有一处广为流传的说法是错的：

      ⚠️ 常见错误说法：「直接采 k 次那种算法有偏」。
      ✅ 论文 Appendix A 的原话："only the empirical estimate used by
         Kulal et al. (2019), and (1) are unbiased."
         （其中 (1) 就是①那个组合数公式，前者就是③）
      ⟹ ★★ ③ 的问题是【方差极大】，不是有偏。
      ⟹ ★★★ 真正【有偏】的是②那个插值法，偏的方向是【偏低】。

   ⟹ 🔑 为什么必须分清："有偏"和"方差大"要用完全不同的办法对付：
      ★★ 方差大 ⟹ 多采几个样本就收敛了。
      ★★★ 有偏 ⟹ 换公式，采再多也不收敛到真值。

★ 用具体数字看①和②能差多少（✅ 这个算例和 评测入门 07 章 §7.7b 那一节是同一套）：

设定 n = 10、c = 3 ① 组合数估计量 ② 插值法 ⚠️ 差（百分点）
k = 1 1 − C(9,1)/C(10,1) = 1 − 0.9 = 30.00% 1 − 0.7¹ = 30.00% 0.00
k = 5 1 − C(7,5)/C(10,5) = 1 − 21/252 = 91.67% 1 − 0.7⁵ = 1 − 0.16807 = 83.19% ⚠️ 8.48
k = 10 1 − C(0,10)/C(10,10) = 1 − 0 = 100.00% 1 − 0.7¹⁰ = 1 − 0.02825 = 97.18% ⚠️ 2.82 
   ⟹ ★★ 只有 k = 1 时三种算法完全一致。
      ⟹ 🔑 这就是为什么绝大多数榜单只报 pass@1：
         ⚠️ 不是因为它最有信息量，而是因为它最不容易吵架。

★★★ 回到本章的真实数据，用 SWE-agent 的 6 次重跑做一个可验算的对照：假设某道题在 6 遍里只解决了 1 遍（n = 6、c = 1），要报 pass@6：

   ① 组合数估计量：1 − C(6−1, 6) / C(6, 6) = 1 − C(5,6)/1
      ★ C(5,6) = 0 —— 只有 5 个失败样本，抽不出"6 个全失败"的组合
      ⟹ 1 − 0 = 1.0000 = 100.0%
      ★ 直觉检查：我们【已经知道】这 6 遍里有 1 遍成功了，
        所以"从这 6 遍里取 6 遍、里面有成功的"当然是必然事件。

   ② 插值法：1 − (1 − 1/6)^6 = 1 − (5/6)^6
      (5/6)^2 = 0.694444
      (5/6)^3 = 0.578704
      (5/6)^6 = 0.578704^2 = 0.334898
      ⟹ 1 − 0.334898 = 0.665102 = 66.5%

   ⟹ ⚠️⚠️ ★★★ 同一道题、同一批 6 次采样结果：
      ①说 100.0%，②说 66.5%，差 33.5 个百分点。
   ⟹ 🔑 论文报的 pass@6 = 32.67（= 98/300 道题）用的是①。
      ★★ 如果换②来算，这个数会【明显偏低】——
      而两者都会被印成"pass@6"。
