agent 脚手架 · 总目录

面向新手的 agent harness / scaffold（智能体脚手架） 系统调研。
讲的是【包在模型外面、让它能真的动手干活的那层程序】——
Claude Code、Codex 这类工具的"本事"绝大部分装在这一层里。

★★★ 先解决一个词：这里的 harness，和隔壁目录的 harness 不是一个东西

隔壁 评测入门/ 讲的也叫 harness，但那是另一个意思。
同一个英文单词，两个完全不同的程序。

   ┌──────────────────────────────────────────────────────────────┐
   │  ★ evaluation harness（评测框架）                             │
   │    = 出题 + 判卷 的那个程序                                   │
   │    例：lm-evaluation-harness、SWE-bench 的 run_evaluation.py │
   │    ⟹ 隔壁目录 [评测入门/] 讲的是这个                          │
   ├──────────────────────────────────────────────────────────────┤
   │  ★ agent harness / scaffold（智能体脚手架）                   │
   │    = 让模型能读文件、跑命令、看报错、再改一遍 的那个程序      │
   │    例：SWE-agent、Claude Code、Codex CLI                     │
   │    ⟹ 🔑 本目录讲的是这个                                     │
   └──────────────────────────────────────────────────────────────┘

   ⟹ ★★★ 两者的接口窄到只有一个文件：
      脚手架跑完，产出一个补丁 → 评测框架收下这个补丁 → 判卷。
      ★★ 中间谁也不问谁。这就是为什么它们能被分成两个目录讲。

★★ 隔壁 08 章 用 SWE-bench 源码证明了这一点：
判卷器只认 instance_id / model_patch / model_name_or_path 三个字段，
补丁是谁生成的、跑了几轮、用了什么工具，它完全不问。
本目录补的就是"它不问的那一段"。

全目录最重要的五条

   ① ★★★ 脚手架不是"包装"，它本身就是能力的一部分。
      ✅ 证据：SWE-agent 论文标题就是这句话——
         "Agent-Computer Interfaces Enable Automated Software Engineering"
         （智能体-计算机接口，使自动化软件工程成为可能）

   ② ★★★ 界面设计的每一个细节都值好几个点。
      ✅ 证据：SWE-bench Lite 上，同一个 GPT-4 Turbo：
         编辑器带语法检查 18.0，不带 15.0，完全没有编辑命令 10.3。

   ③ ★★★ 给模型看得越多 ≠ 效果越好。
      ✅ 证据：文件视图一次给 100 行 = 18.0，给 30 行 = 14.3，
         给整个文件 = 12.7。★★ 两头都掉。

   ④ ★★★ 上下文要主动扔，不是留着就好。
      ✅ 证据：只保留最近 5 条观察 = 18.0，保留全部历史 = 15.0。

   ⑤ ★★★ 闭源产品的脚手架细节，公开的只有【配置面】，没有【实现面】。
      ✅ 证据：DeepSeek-V3.1 模型卡原话
         "SWE-bench is evaluated with our internal code agent framework."
         （SWE-bench 是用我们内部的 code agent 框架评测的。）
         ⟹ 承认了有，也就仅此而已。
