# agent 脚手架 · 总目录

> 面向新手的 **agent harness / scaffold（智能体脚手架）** 系统调研。讲的是【包在模型外面、让它能真的动手干活的那层程序】—— Claude Code、Codex 这类工具的"本事"绝大部分装在这一层里。

---

## ★★★ 先解决一个词：这里的 harness，和隔壁目录的 harness 不是一个东西

隔壁 [评测入门/](../评测入门/README.md) 讲的也叫 harness，但那是另一个意思。**同一个英文单词，两个完全不同的程序。**

| | ★ evaluation harness（评测框架） | ★ agent harness / scaffold（智能体脚手架） |
|---|---|---|
| **它是什么** | 出题 + 判卷 的那个程序 | 让模型能读文件、跑命令、看报错、再改一遍 的那个程序 |
| **例子** | lm-evaluation-harness、SWE-bench 的 `run_evaluation.py` | SWE-agent、Claude Code、Codex CLI |
| **谁讲它** | 隔壁 [评测入门/](../评测入门/README.md) | 🔑 **本目录** |

```
   ⟹ ★★★ 两者的接口窄到只有一个文件：
      脚手架跑完，产出一个补丁 → 评测框架收下这个补丁 → 判卷。
      ★★ 中间谁也不问谁。这就是为什么它们能被分成两个目录讲。
```

★★ 隔壁 [08 章](../评测入门/08-ClaudeCode与Codex怎么被评.md) 用 SWE-bench 源码证明了这一点：判卷器只认 `instance_id` / `model_patch` / `model_name_or_path` 三个字段，**补丁是谁生成的、跑了几轮、用了什么工具，它完全不问。** 本目录补的就是"它不问的那一段"。

## 阅读前：这套记号（与隔壁目录一致）

```
   ✅  = 论文原文 / 官方文档 / 源码原文可查证，我在正文里给了出处
   ⚠️  = 我的推断或补充说明，不是原文
   ★   = 句子级别的重点（★ 一般 / ★★ 重要 / ★★★ 最重要）
   🔑  = 关键结论
   ⭐   = 小节级别的重点，★★★【只在它所在那一章之内比较】
         （⭐ 这一章里的重点小节 / ⭐⭐ 这一章里最该反复读的 /
           ⭐⭐⭐ 这一章里最该读的那一节）
```

⚠️ ★★ 两把尺子别混：**⭐ 比的是「同一章里哪几节更重要」**，而下面章节目录里那个 **「重要度」列比的是「整本书里哪几章更该先读」**。⟹ 所以会出现「某章重要度只有 ★★，但它内部有 ⭐⭐⭐ 小节」的情况 —— ★ 那不是矛盾，是**受众窄但对那部分受众很关键**（05 章就是典型：只有要部署的人需要读，但要读就得读透）。

## 全书骨架：一个脚手架由五件事组成

★★★ 这张表是本目录 8 章的坐标系。

| 组成部分 | 一句话 | 本目录哪章 |
|---|---|---|
| ① 循环 | 模型说 → 执行 → 结果喂回去 | 02 |
| ② 工具集 / ACI | 给模型几个什么动作 | 03 |
| ③ 上下文管理 | 旧的东西怎么扔掉 | 04 |
| ④ 权限 / 沙箱 | 允许它动到哪 | 05 |
| ⑤ 采样 / 预算 | 跑几遍、花多少钱才停 | 02（它怎么毁掉可比性，见 08） |

⚠️ 这五格和 [评测入门 08 章 §8.2](../评测入门/08-ClaudeCode与Codex怎么被评.md) 那份"只列了名字、没有展开"的清单**不是逐格对应的**：§8.2 列的是 ① 工具集 ② 上下文管理 ③ 循环与停止条件 ④ 错误恢复 ⑤ 采样策略。本目录把【错误恢复】并进了 02、03 两章去讲，另外单独给【权限 / 沙箱】留了一整章（05）。

```
   ⟹ 🔑🔑 全目录定律：★★★
      【这五项每一项都能单独让 SWE-bench 分数动好几个点，
        而榜单上一项都不写。】
      ✅ 证据见 03 章那张 SWE-agent 消融表：
         把汇总式搜索换成逐条翻页式，18.0 → 12.0。
```

## 全目录最重要的五条

```
   ① ★★★ 脚手架不是"包装"，它本身就是能力的一部分。
      ✅ 证据：SWE-agent 论文标题就是这句话——
         "Agent-Computer Interfaces Enable Automated Software Engineering"
         （智能体-计算机接口，使自动化软件工程成为可能）

   ② ★★★ 界面设计的每一个细节都值好几个点。
      ✅ 证据：SWE-bench Lite 上，同一个 GPT-4 Turbo：
         edit 命令带语法检查 18.0，不带 15.0，完全没有 edit 命令 10.3。

   ③ ★★★ 给模型看得越多 ≠ 效果越好。
      ✅ 证据：文件视窗一次给 100 行 = 18.0，给 30 行 = 14.3，
         给整个文件 = 12.7。★★ 两头都掉。

   ④ ★★★ 上下文要主动扔，不是留着就好。
      ✅ 证据：只保留最近 5 条观察 = 18.0，保留全部历史 = 15.0。
      ⚠️ 同一组（✅ 论文 Table 3 的 Context 组）里还有一项：
         不给示范轨迹 = 16.3（↓ 1.7）——★ 论文把「给不给示范」
         也算进【上下文管理】，因为示范同样是一开始就塞进上下文的东西。

   ⑤ ★★★ 闭源产品的脚手架细节，公开的只有【配置面】，没有【实现面】。
      ✅ 证据：DeepSeek-V4 报告只交代到这个程度——
         "we evaluate DeepSeek-V4 series using an internally developed
          evaluation framework."
         （我们使用一个内部开发的评测框架来评测 DeepSeek-V4 系列。）
         ⟹ 承认了有，规格也给了，但没给实现。
      ⚠️ 这条在 2026 年 8 月出现了【一个例外】：DeepSeek 把脚手架本体
         开源了（deepseek-harness，MIT），实现面第一次可查——
         但仍然没说"跑分用的就是这份代码"。详见 07 章。
      ⟹ 🔑 对 Claude Code / Codex，这一条目前仍然完全成立。
```

⚠️ ②③④ 三条都出自同一张表（SWE-agent 论文 Table 3，GPT-4 Turbo × SWE-bench Lite 300 题）。它证明的是【差异存在且量级很大】，**不是**"今天换个编辑器还能差 7.7 分"——2024 年的模型和今天的模型不是一回事。

⚠️⚠️ ★★ 读这些差值前先知道噪声有多大：✅ 论文 Table 10 把**完全相同的配置在同一批 300 题上跑了 6 遍**，分数是 17.33 / 18.00 / 18.00 / 18.67 / 17.33 / 18.33（均值 **17.94**，标准差 0.49），⟹ **极差 1.34 个百分点**。★★★ 所以 Table 3 里 ↓ 1.7 和 ↓ 2.3 那两行，差值本身就贴着噪声走，**不该当成确定结论**；↓ 5.3、↓ 6.0、↓ 7.7 那几行才是结实的。⟹ 详见 [附-速查表.md](附-速查表.md) K 节。
