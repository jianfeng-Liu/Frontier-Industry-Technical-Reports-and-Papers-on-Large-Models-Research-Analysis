01 · 为什么"给模型打分"比想象中难得多

标记：✅ = 论文/源码原文可查证 ｜ ⚠️ = 我的推断 ｜ ★ = 重点 ｜ 🔑 = 关键结论

1.1 先破除一个直觉

新手最自然的想法：

    评测不就是考试吗？
    ⟹ 出一堆题 → 让模型答 → 数对了几道 → 算个百分比
    ⟹ ★ 这有什么难的？

如果真这么简单，就不会有这份文档了。 先看一个真实现象：

    ⚠️（演示用的典型情形，非某次具体披露的实测）
    ★★ 同一个模型、同一套题（MMLU），换一家机构去测：

        A 机构报：  68.2
        B 机构报：  74.5
        C 机构报：  61.9

    ⟹ 模型没变，题没变，★ 差了 12.6 分。
    ⟹ 这不是谁作弊，是【评测方法不同】。

🔑 本章要建立的第一个认知：
分数不是模型的属性，是「模型 + 评测方法」这个组合的属性。
⟹ 脱离评测方法谈分数，等于没说。

1.2 名词先统一

因为后面会反复出现，这里一次讲清（这些词经常被混用，但指的不是一回事）：

词 全称 / 含义 举例
benchmark（基准 / 评测集） ★ 一堆题目和标准答案 MMLU、GSM8K、SWE-bench
harness（评测框架 / 评测台架） ★★ 跑这些题的那套程序 lm-evaluation-harness、OpenCompass
metric（指标） 从模型输出算出的数 准确率、pass@1
leaderboard（榜单） 把很多模型的分数排在一起的网页 Open LLM Leaderboard 
    ★★ 打个比方，如果 benchmark 是【试卷】：

      harness  = 监考老师 + 阅卷规则
                 （怎么发卷、给不给草稿纸、答案写歪了算不算对）
      metric   = 计分方式（按题算还是按分算）
      leaderboard = 光荣榜

    ⟹ 🔑 同一张试卷，换个监考和阅卷规则，分数就能差十几分。
       ★ 这就是 §1.1 那个现象的来源。

★ "harness" 这个词的字面意思是"马具/挽具"——套在马身上、把马和车连起来的那套皮带。
引申到工程里，指把被测对象套住、驱动它干活、并收集结果的那层外壳。
⟹ ★★ 记住这个意象：harness 本身不产生智能，它只是"套子"。
但套子怎么做，直接决定量出来的数是多少。

1.3 ★★ 难点一：模型的输出是【自由文本】

这是所有困难的总根源。

    传统机器学习的评测：
      模型输出 = 一个类别编号（比如 3）
      标准答案 = 3
      ⟹ ★ 相等就对，不等就错。★★ 没有任何歧义。

    大语言模型的评测：
      标准答案 = "72"
      模型输出 = "让我算一下。首先 12 × 6 = 72。所以答案是 72。"
      ⟹ ★★ 这算对吗？

当然算对。但程序怎么知道？

    ★ 要写一段代码，把 "72" 从那一大段话里【抠出来】。
      这段代码叫【答案抽取】（answer extraction）。

    ⟹ 然后问题就来了：

      模型输出 "答案是 72。"         ⟹ 抠出 72  ✅
      模型输出 "答案是 72"           ⟹ 抠出 72  ✅
      模型输出 "结果为 72 个"        ⟹ 抠得出来吗？取决于你的正则怎么写
      模型输出 "\\boxed{72}"          ⟹ 数学题常见格式，要单独处理
      模型输出 "是 72，不过如果..."   ⟹ 抠出 72，★ 但它其实在犹豫
      模型输出 "12 × 6 = 72"         ⟹ ⚠️ 有的抽取器会抠到【第一个数字 12】，判错！

    ⟹ 🔑 ★★★ 抽取规则写得不同，同一份模型输出能给出不同的分数。

★ 这不是假想。05 章 会给你看
lm-evaluation-harness 里真实的抽取代码——它的默认正则就是一行 #### (\-?[0-9\.\,]+)，
而这行正则只对某一种特定格式有效。

1.4 ★★ 难点二：怎么问，决定了答得怎么样

同一道题，换个问法，模型的表现能差很多。 这叫提示词敏感性（prompt sensitivity）。

    同一道 MMLU 题目，三种问法：

    ① 直接问：
       "以下哪个是哺乳动物？A.鲨鱼 B.鲸鱼 C.鳄鱼 D.企鹅"

    ② 加个身份设定：
       "你是一位生物学教授。以下哪个是哺乳动物？A.鲨鱼 B..."

    ③ 先给几个做过的例子（★ 这叫 few-shot，见 04 章）：
       "问：哪个是鸟类？A.猫 B.鸽子 ... 答：B
        问：以下哪个是哺乳动物？A.鲨鱼 B..."

    ⟹ ★★ 三种问法，同一个模型，分数可以差 5~10 分。

🔑 所以严肃的评测报告，一定会写清楚：
用了几个示例（0-shot / 5-shot / 25-shot） 示例是【怎么选】的（固定的？随机的？随机种子是多少？） 有没有加系统提示词 用了什么模板（chat template）
⟹ ⚠️ 看到只报数字、不报这些的，那个数字的可比性很低。

1.5 ★★ 难点三：题目可能已经被模型"背过了"

这叫数据污染（data contamination），是评测领域最棘手的问题。

    ★ 事情是这样的：

      ① 评测集（比如 GSM8K）是公开的，挂在网上
      ② 训练大模型要抓【全网数据】
      ③ ⟹ ★★ 评测集的题目和答案，很可能【进了训练数据】

    ⟹ 于是模型不是在"解题"，是在"回忆"。
    ⟹ 🔑 分数虚高，而且【你无法从分数本身看出来】。

    ★ 一个直观的类比：
      期末考的题从往年真题里出，而学生正好把往年真题背熟了。
      ⟹ 他考 95 分。★ 但你不知道他到底会不会。

⚠️ 这个问题没有干净的解法，只有一堆缓解手段（06 章 细讲）：
★ 用【新出的】评测集（模型训练截止日之后才出现的） ★ 用【私有】评测集（不公开题目，只公开分数） ★ 用【动态生成】的题（每次考的题都不一样） ★ 检测：看模型对题目的"熟悉程度"是否异常

1.6 ★★★ 难点四：现在的模型不只是"答题"了

这是最近两年评测领域最大的变化，也是你问到 Claude Code / Codex 时的核心。

    ★ 2020~2023 年的评测长这样：
      给一段文字 → 模型吐一段文字 → 比对答案
      ⟹ ★ 一问一答，一次结束

    ★★ 2024 年之后，要评的东西变成了这样：
      给一个【任务】："修复这个 GitHub issue"
      ⟹ 模型要：读代码库 → 想 → 改文件 → 跑测试 → 看报错 →
                 再改 → 再跑 → ... → 直到通过
      ⟹ ★★★ 可能来回几十轮，中间要【真的执行命令】

🔑 这已经不是"考试"了，是"试用期"。

```
⟹ ★★ 评测框架也必须跟着变：

  传统 harness 需要：  一块 GPU、一个模型、一个正则
  agentic harness 需要：
      ★ 一个【Docker 容器】（隔离的运行环境）
      ★ 一份【能跑起来的代码仓库】
      ★ 一套【真实的测试用例】
      ★ 一个能让模型【执行 shell 命令】的通道

⟹ 复杂度完全是另一个量级。

```

★ 名词解释：agentic（智能体式的）——
指模型不是被动答题，而是主动采取一系列行动、观察结果、再决定下一步。
agent 直译"代理人"，在这里就是"能自己干活的模型"。

这就是为什么 07 章 和
08 章 要单独讲：
评 Claude Code 和评 GPT 答 MMLU，是两套完全不同的机制。

1.7 本章小结

    ★★ 四个难点，一句话各一条：

    ① 输出是自由文本  ⟹ 必须【抠答案】，抠法不同分数不同     （05 章）
    ② 问法影响成绩    ⟹ 必须报清【few-shot 数、模板、种子】  （04 章）
    ③ 题可能被背过    ⟹ 数据污染，★ 没有干净解法             （06 章）
    ④ 模型会【干活】了 ⟹ 要真跑容器、真执行命令               （07/08 章）

    ⟹ 🔑🔑 全章最该记住的一句：
       ★★★【分数是"模型 + 评测方法"的联合产物，不是模型的固有属性。】
       ⟹ 看到任何分数，先问：谁测的？怎么测的？
