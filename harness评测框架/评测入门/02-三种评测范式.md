
# 02 · 三种评测范式：整个领域的地图

> ★★ 这一章是全书的骨架。把这三类分清，后面所有框架、所有榜单你都能归位。

---

## 2.1 一张总图

```
    ┌─────────────────────────────────────────────────────────────┐
    │                                                             │
    │  ① 判别式评测（选择题）                                       │
    │     ★ 不让模型说话，直接看它【觉得哪个选项更可能】             │
    │     代表：MMLU、HellaSwag、ARC                               │
    │     ⟹ 便宜、稳定、好复现                                     │
    │                                                             │
    │  ② 生成式评测（问答题）                                       │
    │     ★ 让模型自由生成，然后从输出里【抠答案】比对              │
    │     代表：GSM8K、HumanEval、MATH                             │
    │     ⟹ 更接近真实使用，★ 但要处理抽取，脏                      │
    │                                                             │
    │  ③ ★★ 交互式 / agentic 评测（实操题）                        │
    │     ★ 给一个环境和一个任务，让模型【真的动手做】               │
    │     代表：SWE-bench、Terminal-Bench、WebArena                │
    │     ⟹ ★★★ 最真实，也最贵、最难复现                           │
    │                                                             │
    └─────────────────────────────────────────────────────────────┘

    ⟹ 🔑 从上到下：【越来越真实，越来越贵，越来越难复现】。
```

## 2.2 ① 判别式评测：不让模型说话

**这是最反直觉、但最重要的一类。新手几乎都会误解它。**

### 直觉里的做法（★ 但主流 harness 不这么干）

```
    把题目连同选项发给模型：
      "以下哪个是哺乳动物？A.鲨鱼 B.鲸鱼 C.鳄鱼 D.企鹅"

    模型回答："B"
    ⟹ 比对答案 B ⟹ 对 ✅

    ⚠️ 问题在哪？
      模型可能回答 "B."、"B、鲸鱼"、"我认为是B"、"鲸鱼"、
      "The answer is B"、"选B" ……
    ⟹ ★ 你又掉进【答案抽取】的坑了（01 章 §1.3）
```

### ★★ 实际的做法：比"哪个选项更可能"

```
    ★ 不让模型生成，而是把【四个完整句子】分别喂给模型，
      问它：这句话你觉得有多"顺"？

      句子 A："以下哪个是哺乳动物？…… 答案：鲨鱼"   → 模型给出分数 −8.3
      句子 B："以下哪个是哺乳动物？…… 答案：鲸鱼"   → 分数 −2.1  ★ 最高
      句子 C："…… 答案：鳄鱼"                       → 分数 −7.9
      句子 D："…… 答案：企鹅"                       → 分数 −6.5

    ⟹ ★★ 选分数最高的 B ⟹ 判对 ✅
    ⟹ ★★★ 全程模型【一个字都没生成】，不存在抽取问题。
```

> ★ 名词解释：**loglikelihood（对数似然）**——
> 模型对一段文字的"认可程度"打的分。
> ```
>     ★ 直观理解：模型读到这段文字时有多"不意外"。
>       越不意外 ⟹ 分数越高（越接近 0）
>       越意外   ⟹ 分数越低（越负）
>
>     ⚠️ 为什么全是负数？因为它是概率取对数，
>        而概率 ≤ 1，取对数就 ≤ 0。★ 不用纠结，只要知道【越大越好】。
> ```

> 🔑 **这一类的优点，正好对应 01 章的两个难点**：
> ```
>     ✅ 没有抽取问题     ⟹ 不用写正则（避开难点一）
>     ✅ 完全确定性       ⟹ 同样输入必定同样输出，★ 好复现
>     ✅ 便宜             ⟹ 每题只要前向计算，不用逐字生成
> ```
>
> ⚠️ **但它的缺点也很致命**：
> ```
>     ✗ ★★ 和真实使用【完全不像】——
>       没有哪个用户会把四个选项分别念一遍看哪个顺
>     ✗ 对"会不会推理"几乎测不出来（模型只是在感觉哪个搭配眼熟）
>     ✗ ⚠️ 有些模型的对话模板（chat template）和这种用法冲突，分数会异常
> ```

## 2.3 ② 生成式评测：让模型自由发挥

```
    ★ 流程：
      ① 把题目发给模型
      ② 模型自由生成一段话，直到遇到【停止标记】
      ③ ★ 从这段话里抠出答案
      ④ 和标准答案比对
```

**关键概念：停止标记（stop sequence）**

```
    ⚠️ 问题：模型答完题不会自己停，它会继续编下一道题！

      你问： "问：小明有 12 个苹果...答："
      模型： "72。
              问：小红有 5 个橘子...     ← ★ 它自己出了下一道题
              答：15。
              问：..."                   ← ★★ 停不下来了

    ★ 解法：告诉它"看到【换行 + 问：】就停"
    ⟹ 这就是 stop sequence，在 lm-evaluation-harness 里叫 `until`
       （★ 所以那个原语的名字才叫 generate_until —— "生成到...为止"）
```

> ★★ **这一类是目前评测的主流**，因为它像真实用法。
> 代表：GSM8K（小学数学）、MATH（竞赛数学）、HumanEval（写函数）。
>
> ⚠️ **代价**：01 章 §1.3 讲的抽取问题，全部落在这一类头上。

### ★ 一个专属于这类的重要指标：pass@k

```
    ★ 写代码这类题有个特点：【答案不唯一，但对错可验证】
      ⟹ 可以让模型答 k 次，只要有一次对就算过

    pass@1  ：只给一次机会，答对的比例   ← ★ 最常报的
    pass@10 ：给十次机会，至少一次对的比例

    ⚠️ 看榜单时一定要看清是 pass@1 还是 pass@10。
    ★★ 同一个模型 pass@10 能比 pass@1 高十几个点 —— 但那不是同一件事。
```

> ✅ 这个指标出自 HumanEval 论文（[papers/HumanEval-Codex-arXiv-2107.03374.pdf](../papers/HumanEval-Codex-arXiv-2107.03374.pdf)），
> 就是 OpenAI 当年发 Codex 时提出的。★ 你问的 Codex，源头在这里。

## 2.4 ★★★ ③ agentic 评测：让模型真的动手

**这一类和前两类不是"更难一点"的关系，是【完全不同的东西】。**

```
    ★★ 前两类的世界观：
        输入(文本) ──→ 模型 ──→ 输出(文本) ──→ 打分
        ⟹ ★ 一次性、无状态、无环境

    ★★★ agentic 的世界观：

        ┌──────────────────────────────────────────┐
        │           一个真实的运行环境                │
        │  （Docker 容器：装好依赖的代码仓库）        │
        └──────────────────────────────────────────┘
              ↑                              │
              │ 模型发出的命令                 │ 环境返回的结果
              │ （改文件 / 跑测试 / 看日志）    │ （报错 / 输出 / 退出码）
              │                              ↓
        ┌──────────────────────────────────────────┐
        │                 模型                       │
        └──────────────────────────────────────────┘

        ⟹ ★ 这个循环可能转几十轮
        ⟹ ★★ 最后【不看模型说了什么】，只看【环境变成了什么样】
```

> 🔑🔑 **这是全章最重要的一句话**：
> ```
>     ★★★ agentic 评测不评"模型说得对不对"，
>          评的是【它有没有把事情办成】。
>
>     ⟹ SWE-bench 的判定标准不是"代码写得好不好看"，
>        是【原本失败的测试，现在过了没有】。
>     ⟹ ★ 这叫【基于执行的验证】（execution-based verification）
> ```

**代价有多大？**

| | 传统 harness | agentic harness |
|---|---|---|
| 每题耗时 | ⚠️ 毫秒~秒 | ★ **分钟~小时** |
| 每题成本 | 一次前向 | ★ 几十轮生成 + 容器启停 |
| 需要什么 | GPU | ★★ GPU + Docker + 磁盘 + 网络 |
| 能否完全复现 | ✅ 基本能 | ⚠️ **很难**（见下） |

```
    ⚠️★★ 为什么 agentic 评测难复现？

      ① 模型是随机的（temperature > 0）⟹ 每次行动路径不同
      ② 环境是活的：装依赖要联网 ⟹ ★ 上游包更新了，结果就变了
      ③ 有超时：机器慢一点，就从"通过"变成"超时失败"
      ④ ★ 多轮交互 ⟹ 前面一步走偏，后面全不一样（误差放大）

    ⟹ 🔑 所以 agentic 榜单的分数，⚠️ 波动天然比传统榜单大。
       ★ 严肃的报告会跑多次取平均，并报告【方差】。
```

## 2.5 ★ 三类的归位表

| | ① 判别式 | ② 生成式 | ③ agentic |
|---|---|---|---|
| **模型要做什么** | ★ 不说话，只打分 | 生成一段文字 | ★★ 多轮行动 |
| **怎么判对错** | 比哪个选项分高 | ★ 抠答案 + 比对 | ★★ 跑测试看结果 |
| **代表评测集** | MMLU、HellaSwag | GSM8K、HumanEval | SWE-bench、Terminal-Bench |
| **典型框架** | lm-eval-harness | lm-eval-harness、OpenCompass | ★ SWE-bench harness |
| **单题成本** | 极低 | 低 | ★★ 高 |
| **复现难度** | ★ 容易 | 中 | ⚠️ 难 |
| **像不像真实使用** | ⚠️ 很不像 | 比较像 | ★★ 最像 |
| **主要坑** | 模板不匹配 | ★ 答案抽取 | ★★ 环境漂移 |

> 🔑 **⚠️ 一个必须澄清的误解**：
> **这三类不是"进化关系"，不是说 ③ 出来了 ①② 就该淘汰。**
> ```
>     ★ 它们量的是不同的东西：
>       ① 量【知识储备】       —— 便宜，适合训练中途频繁监控
>       ② 量【推理与表达】     —— 平衡点，主流
>       ③ 量【能不能干成活】   —— ★ 最终目的，但贵到没法天天跑
>
>     ⟹ ★★ 真实做法是【组合使用】：
>        训练中每隔几百步跑 ①（快），
>        阶段性跑 ②（中），
>        发版前跑 ③（贵）。
> ```

## 2.6 本章小结

```
    ★★ 三种范式，三句话：

    ① 判别式：不生成，比选项的对数似然  ⟹ 便宜稳定，但不像真实使用
    ② 生成式：自由生成 + 抠答案         ⟹ 主流，脏在抽取
    ③ agentic：真环境里多轮动手         ⟹ 最真实，贵且难复现

    ⟹ 🔑 记住那句判定标准的差别：
       ①② 看【模型说了什么】
       ③  ★★★ 看【世界变成了什么样】
```
