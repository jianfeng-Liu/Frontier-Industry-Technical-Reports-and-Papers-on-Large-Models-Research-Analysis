
# 06 · 数据污染：评测领域最棘手的问题

> ★★ 这一章没有解法，只有缓解手段。
> **但不理解它，你会把很多虚高的分数当真。**

---

## 6.1 问题本身

```
    ★ 名词：数据污染（data contamination），也叫【测试集泄漏】

    ┌────────────────────────────────────────────────┐
    │  ① 评测集是公开的（挂在 GitHub / HuggingFace）  │
    │  ② 训练大模型要抓【尽可能多的网页】              │
    │  ③ ⟹ ★★ 评测题和标准答案进了训练数据           │
    │  ④ ⟹ 模型不是在解题，是在【回忆】               │
    └────────────────────────────────────────────────┘

    ⟹ 🔑 结果：分数虚高，★★★ 且【无法从分数本身察觉】。
```

> ★ 这在机器学习里本来是常识错误——**训练集和测试集必须分开**。
> ⚠️ 但大模型的训练数据是"全网抓取"，**你根本不知道里面有什么**。
> ```
>     ⟹ ★★ 传统机器学习：你亲手划分训练/测试集，★ 边界清楚
>     ⟹ ★★ 大模型：训练数据几十 TB，★★★ 边界【不可知】
> ```

---

## 6.2 ★★ 污染的四个层级（严重程度递增）

```
    ① 概念污染
       模型见过同类知识（★ 见过微积分教材）
       ⟹ ★★ 这【不算污染】，这就是我们要它学的东西

    ② 题目污染
       ⟹ 模型见过题面，但没见过答案
       ⟹ ★ 影响有限

    ③ ★★ 题目 + 答案污染
       ⟹ 模型见过完整的题和答案
       ⟹ ★★★ 严重。模型可以直接背出来

    ④ ★★★ 训练时被当成训练目标反复学过
       ⟹ 不只是"见过"，是"练过很多遍"
       ⟹ ⚠️ 分数可以刷到接近满分，而实际能力毫无变化
```

> 🔑 **注意 ① 和 ③ 的区别，这是本章最需要想清楚的地方**：
> ```
>     ★ 我们【希望】模型见过微积分知识（那是能力）
>     ★★ 我们【不希望】模型见过这道具体的题（那是作弊）
>
>     ⟹ ⚠️ 但这两者在训练数据里【长得一模一样】，都是文本。
>     ⟹ 🔑🔑 这就是为什么这个问题【没有干净解法】。
> ```

---

## 6.3 ★ 怎么检测

**没有可靠方法，只有几类信号（⚠️ 都只能提示嫌疑，不能证明）**：

```
    ① ★ 字符串匹配 / n-gram 重叠
       ⟹ 在训练数据里搜评测题的原文
       ⟹ ✅ 直接、可靠
       ⟹ ⚠️ 但前提是【你能拿到训练数据】——闭源模型完全没戏

    ② ★★ 看模型对题目的"熟悉度"异常
       ⟹ 让模型【续写题目本身】，看它能不能背出后半句
       ⟹ ★ 背得出 ⟹ 高度可疑
       ⟹ ⚠️ 背不出 ⟹ 也不能证明没污染

    ③ ★★ 选项顺序扰动
       ⟹ 把 ABCD 打乱重排，看分数掉多少
       ⟹ ★★★ 真会做的模型：分数基本不变
             背答案的模型：★ 分数显著下降
       ⟹ 🔑 这一招简单又有效，值得记住

    ④ ★ 新旧对比
       ⟹ 拿【训练截止日之后】才发布的新题去测
       ⟹ 新题分数远低于老题 ⟹ ★★ 强烈提示污染
```

> ★★ 框架里有对应的模块：
> ```
>     ✅ lm_eval/decontamination/     ← 顶层去污染模块
>     ✅ lm_eval/filters/decontamination.py ← 过滤器形式的实现
> ```
> ⚠️ 但要清楚：**它做的是 ① 那种字符串匹配**，
> 只有当你**手里有训练数据**时才用得上。★ 对评估别人家的模型，帮不上忙。

---

## 6.4 ★★ 缓解手段（都有代价）

| 手段 | 做法 | 代价 |
|---|---|---|
| **私有测试集** | ★ 只公布分数，不公布题目 | ⚠️ 无法独立复现，要信任测试方 |
| **动态生成** | ★ 每次考的题现场生成 | ⚠️ 题目质量难保证；难度不稳定 |
| **时间切分** | ★★ 只用模型训练截止日之后的新题 | ⚠️ 题量少；每隔几个月就要重做 |
| **扰动重排** | 打乱选项、改写题面 | ⚠️ 改写可能改变难度 |
| **人工新题** | 请专家现出题 | ⚠️★ 极贵，量小 |

> 🔑 **★★ 目前最被认可的是【时间切分】那一条**，因为它逻辑上最硬：
> ```
>     ★★★ 如果这道题在模型训练完之后才诞生，
>          那它【物理上不可能】出现在训练数据里。
>
>     ⟹ ★ 这就是 LiveCodeBench 这类"滚动更新"评测集的设计思路：
>        持续收录新出现的编程题，★★ 并【按日期切片】报告分数。
>     ⟹ ⚠️ 代价是评测集要一直维护，且旧模型和新模型的可比区间会不断变化。
> ```

## 6.5 ★★★ 一个必须理解的结构性问题

**污染不只是"有人作弊"，它还有一个更麻烦的成因。**

```
    ★★ 即使【所有人都诚实】，污染也会自然发生：

    ① 评测集公开
    ② 大家讨论它、写博客分析它、在论文里引用它的例题
    ③ ⟹ ★ 这些讨论文章本身进了下一代模型的训练数据
    ④ ⟹ ★★★ 于是模型间接学到了题和答案

    ⟹ 🔑 这叫【间接污染】，★★ 没有任何人做错事，但污染确实发生了。
```

```
    ⚠️★★ 更棘手的还有【榜单驱动的过拟合】：

      ① 某个榜单成为行业标准
      ② ⟹ 大家开始针对它调优（选数据、调格式、试提示词）
      ③ ⟹ ★★ 分数上涨，但涨的是【对这个榜单的适应】
      ④ ⟹ ★★★ 真实能力没有同步上涨

    ⟹ 🔑🔑 这不需要任何人接触测试集，★ 光靠反复试就能发生。
    ⟹ ⚠️ 这也是为什么【一个评测集用久了就会失效】。
```

> ★★ 这条规律有个名字，**古德哈特定律**（Goodhart's Law）：
> > **"当一个指标成为目标时，它就不再是一个好指标。"**
>
> 🔑 ⟹ **所以评测集需要【不断更新换代】。**
> 这不是因为旧的设计得不好，★★ 而是因为**它被用过了**。

## 6.5b ⭐⭐ ✅ 一份论文把污染【当场抓了个正着】

★★ 前面 6.1–6.5 讲的是"污染在原理上会怎样"。
这一节换成实证：**LiveCodeBench 论文**（arXiv:2403.07974，46 页，已校验）
用一个极干净的实验设计，把污染【画成了一条曲线】。

### 它的设计：给每道题打上"发布日期"

✅ 论文原文（摘要）：

> "we propose **LiveCodeBench**, a comprehensive and **contamination-free** evaluation
> of LLMs for code, which collects **new problems over time** from contests across three
> competition platforms, namely **LeetCode, AtCoder, and CodeForces**. …
> Currently, LiveCodeBench hosts over **five hundred coding problems** that were published
> between **May 2023 and May 2024**."

```
   ★ 名词补全：
   ★ LeetCode / AtCoder / CodeForces = 三个在线编程竞赛平台，每周出新题。
   ★★ 关键设计：★★★【每道题都带一个 release date（发布日期）标签】。
   ⟹ 🔑 于是可以按时间窗口切片评测：
      "只用 2023 年 9 月之后发布的题" 就是一次干净实验。
```

✅ 原文说明这个做法为什么必要（引言）：

> "While previous works have attempted decontamination using both exact and fuzzy matches,
> it can be a non-trivial task and **can be evaded using simple strategies like rephrasing**."

```
   ⟹ ★★★ 这正是 6.3 那一节的核心难点，也是 10.7b.3 里 DeepSeek 自己承认的
      "n-gram 挡不住换句话说的题"。
   ⟹ 🔑 LiveCodeBench 的答案是：★★★ 不去检测污染，而是【让污染在物理上不可能发生】
      —— 用模型训练截止日之后才出现的题。
```

### ✅ 抓到的结果：分数在截止日那天"掉下悬崖"

✅ 论文原文（Figure 1 说明 + 正文）：

> "Notice that **DeepSeek-Instruct and GPT-4-O perform considerably worse on problems
> released since September and November 2023 (their release and cutoff dates respectively!)**
> – indicating potential contamination for the earlier problems."

> "We observe a **stark drop** in the performance of DeepSeek, GPT-4-O, and Codestral on
> LeetCode problems released **after Aug 2023, Oct 2023, and Jan 2024** (Figure 1)."

✅ 最刺眼的一个数字（正文 §5.1）：

> "we find that even the **DS-Base-33B** model also suffers from contamination dropping from
> **Pass@1 ~60 in May problems to Pass@1 ~0 in September LeetCode problems**."

```
   ⚠️⚠️⚠️ ★★★ 请把这个数字读三遍：

   ┌───────────────────────────────────────────────────────────┐
   │  同一个模型、同一个平台（LeetCode）、同一种题型、          │
   │  同一套评测代码，唯一的差别是【题目的发布月份】：          │
   │                                                            │
   │      5 月发布的题  →  Pass@1 ≈ 60                          │
   │      9 月发布的题  →  Pass@1 ≈ 0                           │
   └───────────────────────────────────────────────────────────┘

   ⟹ 🔑🔑🔑 这不是"能力下降"，能力不会在一个月内从 60 掉到 0。
      ★★★ 这是【记忆的边界被看见了】。
      ⚠️ 5 月那 60 分里，有相当大一部分不是"会做"，是"见过"。
```

✅ 另一条同样干净的对照（Codestral）：

> "Codestral achieves **Pass@1 36.5** on problems released between May'23 and Jan'24 and
> **Pass@1 28.3** on problems since Feb'24."

✅ 而且论文给出了一个非常重要的**阴性对照**（negative control）：

> "Irrespective of the release or cutoff dates, we **do not find any drastic performance
> variations across the months** [for GPT-4-Turbo, Gemini-Pro, Mistral-L, Claude-3s],
> particularly compared to the DeepSeek models."

> "we find that this drop in performance **primarily occurs for the LeetCode problems only**
> and that the model performance is **relatively smooth across the months for problems from
> other platforms**."

```
   ⟹ 🔑🔑 阴性对照是这个实验最值得学的地方，★★★ 它排除了两个替代解释：

   ① "会不会是 9 月的题本身更难？"
      ⟹ ⚠️ 如果是题变难，★★ 所有模型都该一起掉。但别的模型没掉。

   ② "会不会是这个模型整体就不行？"
      ⟹ ⚠️ 如果是模型不行，★★ 它在 AtCoder 上也该掉。但它只在 LeetCode 上掉。

   ⟹ ★★★ 只有【这个模型 + 这个平台 + 这个时间点】三者同时成立才掉，
      🔑 这个交叉模式，指向的唯一合理解释就是：★★★ LeetCode 老题进了训练集。
```

### ✅ 顺带抓到的第二件事：过拟合到基准上

★★ 论文还做了一个 6.5 节"Goodhart 定律"的直接证据。

✅ 原文：

> "**DS-Ins-1.3B** which achieves **59.8% Pass@1 on HumanEval+** but only **26.3% on LCB-Easy**."

> "**DS-Ins-33B** is merely **4.3 point behind GPT-4-Turbo on HumanEval+** but **16.2 points
> (69%)** [behind] on LCB code generation scenario."

> "the green-shaded cluster contains **base models or closed-access models**, while the
> **red-shaded cluster primarily comprises fine-tuned variants of open-access models**.
> The well-separated clusters suggest that many models that perform well on HumanEval
> might be **overfitting on the benchmark**."

```
   ⟹ 🔑 这张散点图（论文 Figure 5）说的是：

   ★ 横轴 = HumanEval+ 分数，纵轴 = LiveCodeBench-Easy 分数。
   ★★ 如果两个基准测的是同一种能力，所有点该落在对角线附近。
   ⚠️ 实际却分成两团：
      ● 绿色团（落在对角线上）= base 模型 + 闭源模型
      ● 红色团（HumanEval+ 高但 LCB 低）= 开源模型的微调版本

   ⟹ 🔑🔑 ★★★ 这就是 Goodhart 定律的可视化：
      ⚠️ 【一个指标一旦成为优化目标，它就不再是一个好指标。】
      ★★ 微调时刻意往 HumanEval 这类基准上使劲，
      ⟹ 分数上去了，但【上去的那部分没有迁移到别的题上】。

   ⟹ ★★ 而 base 模型和闭源模型落在对角线上，
      ⚠️ 一个可能的解释是它们没有针对 HumanEval 做专门优化。
      （✅ 这是论文的观察；⚠️ 具体原因论文没有断言，我也不断言。）
```

### 🔑 这一节给你的三条可操作结论

```
   ① ★★★ 看到一个"新模型在老基准上刷出高分"，
      ⟹ ⚠️ 先问：这个基准发布于该模型的训练截止日之前吗？
      ⟹ 是的话，这个分数【无法区分"会做"和"见过"】。

   ② ★★★ 判断污染最有力的证据不是绝对分数，是【时间切片曲线】。
      ⟹ 🔑 单点分数永远说不清；分数在截止日附近的断崖说得清。

   ③ ★★ 一个模型在两个"测同种能力"的基准上分数背离，
      ⟹ ⚠️ 大概率其中一个被过拟合了。
      ⟹ 🔑 所以 11 章会说：★★★ 永远不要只看一个基准。
```

## 6.6 ★ 实践建议

```
    ★★ 你自己评模型时，怎么降低被污染误导的风险：

    ① 永远【多个评测集一起看】
       ⟹ ★ 单个评测集虚高的可能性远大于全部一起虚高

    ② ★★ 关注【新旧题目的分数差】
       ⟹ 老题 85 分、新题 55 分 ⟹ ★★★ 高度可疑

    ③ ★ 一定要用【你自己的真实任务】测一遍
       ⟹ 🔑 这是唯一不可能被污染的评测集
       ⟹ ★★ 哪怕只有 50 条人工标注的样本，也比榜单可信

    ④ ★ 用扰动测试做交叉验证（§6.3 的第 ③ 招）
       ⟹ 打乱选项顺序，看分数稳不稳

    ⚠️ 别做的事：
       ✗ 看到某模型某榜单第一就下结论
       ✗ 比较【不同时期】发布的模型在【老评测集】上的分数
         （⟹ ★ 新模型的训练数据更可能包含它）
```

> 🔑🔑 **★★★ 本章最实用的一句话**：
> **你自己业务上的 50 条真实样本，比任何公开榜单都值钱。**
> ⟹ 因为它**一定没被污染**，而且**测的正好是你在意的东西**。

## 6.7 本章小结

```
    ★★ 七句话：

    ① 污染 = 评测题进了训练数据 ⟹ ★ 分数虚高且看不出来
    ② ⚠️ 分不清"该学的知识"和"不该见的题目"，★★★ 所以没有干净解法
    ③ ★ 检测靠信号不靠证明：字符串匹配 / 背诵测试 / ★★ 选项扰动 / 新旧对比
    ④ ★★ 最硬的缓解手段是【时间切分】：训练之后诞生的题，物理上不可能污染
    ⑤ 🔑 古德哈特定律：★★★ 评测集【被用过就会失效】，必须持续换代

    ⑥ ✅ 实证（LiveCodeBench 论文，§6.5b）：同一模型在 LeetCode 上，
       5 月的题 Pass@1 ≈ 60，9 月的题 Pass@1 ≈ 0 ——
       ★★★ 断崖恰好落在它的训练截止日上。
    ⑦ ✅ 同篇论文的过拟合证据：DS-Ins-1.3B 在 HumanEval+ 拿 59.8，
       在 LiveCodeBench-Easy 只有 26.3 ⟹ ★★★ 古德哈特定律的可视化。

    ⟹ 🔑🔑 给你的行动项：★★★ 攒一套自己业务的小评测集。
```
