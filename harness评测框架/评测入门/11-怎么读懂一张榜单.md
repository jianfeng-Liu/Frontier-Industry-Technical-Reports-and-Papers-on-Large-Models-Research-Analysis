# 11 · 怎么读懂一张榜单

> ★ 这一章不引入新概念，是把前十章的教训压成【一套可执行的动作】。
> ⟹ 🔑 目标：★★★ 让你看到任何一个分数，都知道下一句该问什么。

---

## 11.1 先建立一个心态：分数不是测量，是【一次实验的结果】

```
   ★★ 类比：体温计量出 37.2℃，你会认为这是"人的属性"。
      ⟹ 因为体温计的口径是全球统一的：单位、位置（腋下/口腔）、时长。

   ⚠️ 但 LLM 评测【没有这样的统一】：
   ┌──────────────────────────────────────────────────────┐
   │  同一个"MMLU 87 分"，可能是                           │
   │   ① 判别式、5-shot、无对话模板                        │
   │   ② 生成式、0-shot、套了对话模板、正则抽 A/B/C/D      │
   │  ⟹ ★★★ 两者【不是同一个测量】                       │
   └──────────────────────────────────────────────────────┘

   ⟹ 🔑🔑 所以正确的读法是：
      ★★★ "在【某套具体设置】下，这个模型得了 87 分"。
      ⚠️ 而不是 "这个模型的 MMLU 水平是 87"。
```

★★ 10 章已经给了这个说法最硬的证据：DeepSeek 自己承认框架改了几个月，
自家旧模型的分数就和上次公布的对不上了（✅ §4.4.2）。

## 11.2 三步法

★★★ 遇到任何一个分数，按这个顺序走。

```
   ┌─ 第 1 步：这是【哪一类】评测？──────────────────────┐
   │  ① 判别式（选择题、比对数似然）                     │
   │  ② 生成式（让它写出来，再抽答案）                   │
   │  ③ agentic（真跑环境、执行验证）                    │
   │  ⟹ ★★ 三类的坑完全不同，问的问题也不同。           │
   └────────────────────────────────────────────────────┘
                          ↓
   ┌─ 第 2 步：按类别，问对应的问题（§11.3-11.5）───────┐
   └────────────────────────────────────────────────────┘
                          ↓
   ┌─ 第 3 步：问三个【共通】的问题（§11.6）────────────┐
   └────────────────────────────────────────────────────┘
```

★ 怎么判断是哪一类？看基准名字就够了：

```
   ┌──────────────────────────────┬──────────────────────┐
   │ MMLU / HellaSwag / ARC /     │ ★ 通常是 ①判别式     │
   │ CMMLU / C-Eval / WinoGrande  │ ⚠️ 但 chat 模型上    │
   │                              │   常改成 ②           │
   ├──────────────────────────────┼──────────────────────┤
   │ GSM8K / MATH / AIME /        │ ★ ②生成式           │
   │ HumanEval / MBPP / IFEval    │                      │
   ├──────────────────────────────┼──────────────────────┤
   │ SWE-bench / Terminal-Bench / │ ★ ③agentic          │
   │ Aider / OSWorld              │                      │
   ├──────────────────────────────┼──────────────────────┤
   │ MT-Bench / Arena / AlpacaEval│ ★★ 特例：LLM 裁判    │
   │ / Arena-Hard                 │ ⟹ 走 09 章那套问题   │
   └──────────────────────────────┴──────────────────────┘
```

## 11.3 如果是【判别式】：问四件事

```
   ┌───┬──────────────────┬──────────────────────────────────┐
   │ ① │ ★★ shot 数是多少 │ 0 / 5 / 25 差别巨大（10 章 §10.4）│
   │ ② │ ★★ 提示词模板     │ 是哪套？自己写的还是照抄的？      │
   │ ③ │ ★★★ 有没有套对话  │ chat 模型不套模板 ⟹ 分数虚低     │
   │   │ 模板              │ ⚠️ 这是最常见的隐性错误           │
   │ ④ │ ★ 选项归一化方式  │ 按长度归一？按字节？还是不归一？  │
   └───┴──────────────────┴──────────────────────────────────┘
```

```
    ⟹ 🔑 一个即刻可用的判别技巧：
       ★★★ 如果榜单上【闭源模型和开源模型混在一起排】，
          那闭源那几个【一定不是判别式测的】（03 章：API 不给 logprobs）。
       ⟹ ⚠️ 这一列的可比性天然存疑。
```

---

## 11.4 如果是【生成式】：问五件事

```
   ┌───┬─────────────────────┬───────────────────────────────┐
   │ ① │ ★★ 答案怎么抽出来的 │ 正则？宽松还是严格？          │
   │ ② │ ★★★ 抽取失败率多少  │ ⚠️ 几乎没人报，但它藏在分数里 │
   │ ③ │ ★★★ max_tokens 多少 │ 推理模型被截断 = 白跑         │
   │   │                     │ ✅ DeepSeek 全场 8192          │
   │ ④ │ ★★ 温度 / 跑几遍    │ greedy 可复现；多次平均更稳    │
   │ ⑤ │ ★ 用没用 CoT        │ 同一个基准，CoT 和非 CoT      │
   │   │                     │ ✅ DeepSeek 分两行报          │
   └───┴─────────────────────┴───────────────────────────────┘
```

```
    ★★ 第 ⑤ 条有现成例子。✅ DeepSeek-V3 报告 Table 6：
       LiveCodeBench (Pass@1-COT)  40.5
       LiveCodeBench (Pass@1)      37.6
    ⟹ 🔑 同一个模型、同一个基准，★★ 差 2.9 分，差别只在有没有 CoT。
       ⟹ 他们把两行【都列出来】，这是负责任的做法。
```

## 11.5 如果是【agentic】：问 08 章那六件事

★★ 直接复用，因为这是变量最多的一类。

```
   ┌───┬──────────────────────┬────────────────────────────────┐
   │ ① │ 哪个子集？            │ full / Lite / Verified          │
   │ ② │ ★★★ 什么脚手架？     │ ✅ 例：DeepSeek 用 Agentless    │
   │ ③ │ ★★★ 几次尝试？       │ pass@1 还是 N 选 1              │
   │ ④ │ ★★★ 挑选时看没看     │ 看了 = 拿答案挑答案             │
   │   │ f2p 测试？            │                                 │
   │ ⑤ │ ★★ 预算多少？        │ 轮数 / token / 墙钟时间         │
   │ ⑥ │ ★ 模型版本和日期？    │ 同名模型不同快照分数会变        │
   └───┴──────────────────────┴────────────────────────────────┘
```

```
    ⟹ 🔑🔑 10 章已经演示过 ② 的威力：
       ★★★ 同一张表里 Claude-3.5-Sonnet 在 Agentless 下是 50.8，
       而各家用自家 agent 报出来的数是另一回事。
       ⟹ 两个数都真，但【回答的是不同问题】。
```

## 11.6 三个共通问题（不分类别，都要问）

### ① ★★★ 这个差距超过噪声了吗？

```
    ✅ DeepSeek-V3 报告 Table 3 表注：
       "Scores with a gap not exceeding 0.3 are considered to be at the same level."

    ✅ 09 章：Arena 类榜单用 bootstrap 算置信区间。

    ⟹ 🔑 操作：
      ┌──────────────────────────────────────────────┐
      │ 看到 "A 87.3 vs B 87.1"                       │
      │ ⟹ ★★★ 这是平手，不是"A 更强"。              │
      │ 看到 "Elo 1247 vs 1244，区间都是 ±10"         │
      │ ⟹ ★★★ 这是平手。                            │
      └──────────────────────────────────────────────┘
```

### ② ★★★ 对比数字是【自己跑的】还是【抄来的】？

```
    ✅ DeepSeek 的做法："We evaluate all these models with our internal
       evaluation framework, and ensure that they share the same evaluation setting."

    ⟹ 🔑🔑 这一句是【整份报告可信度的分水岭】。

    ┌─ 自己统一跑 ────────────────────────────────────────┐
    │ ★★ 口径一致，差距可信。★ 代价：贵，且要有算力。    │
    ├─ 抄各家自己公布的 ─────────────────────────────────┤
    │ ⚠️ 每家用的 shot 数、提示词、脚手架全都不同。       │
    │ ⟹ ★★★ 放进同一张表就是【苹果比橘子】。            │
    │ ⚠️ 而且有个系统性偏差：★★ 每家报自己的数时          │
    │    都是【调到最优】的，抄来的数天然偏高。           │
    └────────────────────────────────────────────────────┘

    ⟹ 🔑 看到表格里有脚注写 "†results taken from [X]"，
       ★★★ 那一行就不能和自测行直接比。
```

### ③ ★★★ 这个基准是不是已经过期了？

```
    ⟹ 回到 06 章的古德哈特定律：★★ 评测集【被用过就会失效】。

    ┌─ 过期的三个信号 ────────────────────────────────────┐
    │ ① ★★ 榜首挤成一团（比如都在 89-91 之间）           │
    │    ⟹ 已经饱和，★★★ 区分不出能力了                 │
    │ ② ★★ 基准发布时间早于模型训练截止时间               │
    │    ⟹ 06 章：污染的必要条件已满足                    │
    │ ③ ★ 新模型的提升幅度突然变得很小                    │
    │    ⟹ 可能是模型没进步，也可能是尺子到头了          │
    └────────────────────────────────────────────────────┘

    ⟹ 🔑🔑 HumanEval 是最典型的例子：
       ★★ 2021 年发布时是硬骨头，现在基本只当【最低门槛】看。
    ⟹ ★★★ 对抗手段：看 LiveCodeBench 这类【只用训练截止后的新题】的基准。
```

## 11.7 三个常见的误读，逐个拆

### 误读 A：「模型 X 在 MMLU 上 88，模型 Y 87，所以 X 更强」

```
    ⚠️ 三重问题：
      ① 88 和 87 可能在噪声内（§11.6①）
      ② ★★ 两个数可能来自不同 harness（判别式 vs 生成式）
      ③ ★★★ MMLU 只测【选择题知识】，
         ✅ MT-Bench 论文原话：MMLU 和 HELM "cannot effectively tell the
            difference between these aligned models and the base models"
         ⟹ 🔑 它【测不出好不好用】。

    ⟹ ★★★ 正确读法：两者在这一项上是同级；
       至于谁"更强"，★★ MMLU 回答不了这个问题。
```

### 误读 B：「这个模型 SWE-bench 70%，那我的仓库它也能修好 70%」

```
    ⚠️ 四重问题：
      ① ★★ SWE-bench 是 12 个【热门开源 Python 库】，
         你的仓库大概率是私有代码 + 不同语言 + 更混乱
      ② ★★★ 那 70% 背后有一整套脚手架（08 章），你的环境没有
      ③ ★★ 题目自带【真人写好的验收测试】，你的需求没有
      ④ ★★★ Verified 是【人工筛掉过表述不清的题】的子集（07 章 §7.8），
         而你的真实工单里，表述不清的占比很高

    ⟹ 🔑🔑 结论：★★★ 榜单分数是【能力上界的一个指示】，
       不是【你的场景的预期成功率】。
```

### 误读 C：「Arena 排名第一，所以它最好」

```
    ⚠️ Arena 类榜单测的是【人类投票偏好】。
      ① ★★ 受 09 章冗长偏差影响：长而工整的回答天然占便宜
      ② ★★★ 投票的是【随机网友的随机问题】，
         不是你的业务问题
      ③ ★ 排名第一和第三的 Elo 差可能在置信区间内

    ⟹ 🔑 它很有价值——★★ 它是唯一大规模测"人喜不喜欢"的东西。
       ⚠️ 但"人喜欢"和"能干成你的活"是两件事。
```

## 11.8 一张速用卡

★★★ 建议截图存下来。

```
   ╔══════════════════════════════════════════════════════════╗
   ║           看到一个分数，依次问这七句                      ║
   ╠══════════════════════════════════════════════════════════╣
   ║ 1. ★★ 判别式 / 生成式 / agentic / LLM 裁判？             ║
   ║ 2. ★★ shot 数、提示词模板、对话模板？                    ║
   ║ 3. ★★★ 答案怎么抽的？max_tokens 多少？                   ║
   ║ 4. ★★★ agentic 的话：脚手架是什么？几次尝试？            ║
   ║ 5. ★★★ 这个差距超过噪声了吗？（DeepSeek 划线 0.3）       ║
   ║ 6. ★★★ 对比数字是自己跑的还是抄的？                      ║
   ║ 7. ★★ 这个基准饱和了吗？可能被污染了吗？                 ║
   ╠══════════════════════════════════════════════════════════╣
   ║ ⟹ 🔑 七问里有三问答不上来 ⟹ 这个分数【只能当参考】。    ║
   ║ ⟹ 🔑🔑 全都答得上来 ⟹ 恭喜，你遇到了一份好报告。        ║
   ╚══════════════════════════════════════════════════════════╝
```

## 11.9 本章总结

```
    🔑 五条带走：

    ① ★★★ 分数不是模型的属性，是【一次实验的结果】
       ⟹ 读法永远是"在某套设置下得了多少分"
    ② ★★ 三步法：先分类 → 问该类的问题 → 问三个共通问题
    ③ ★★★ 三个共通问题最值钱：
       超过噪声吗 / 自己跑的还是抄的 / 这基准过期了吗
    ④ ★★ 三大误读：把噪声当差距、把榜单当业务预期、
       把偏好当能力
    ⑤ 🔑🔑 ★★★ 榜单的作用是【排除明显不行的】，
       不是【选出最适合你的】。
       ⟹ 后者只有一个办法，就是下一章。
```
