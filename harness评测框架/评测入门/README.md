## 四个名词，先分清（全书基础）

```
   ★ benchmark（基准 / 评测集）   = 题目本身。例：MMLU、GSM8K、SWE-bench
   ★ harness（评测框架）          = 跑题目的那个程序。例：lm-evaluation-harness
   ★ metric（指标）               = 怎么算分。例：accuracy、pass@1、Elo
   ★ leaderboard（榜单）          = 把很多分数排在一起的那张表

   ⟹ 🔑 "harness" 这个词字面意思是【挽具、马具】——
      套在模型身上、让它按统一方式跑题的那套东西。
```

⚠️ 同一个英文单词 harness 在 agentic 评测里还指另一个东西（智能体脚手架），见下面第三部分的提示框。

---

## 全书骨架：三种评测范式

★★★ 02 章建立的这张分类表，是后面十章的坐标系：

| 范式 | 怎么判对错 | 需要抽取答案吗 | 典型基准 |
|---|---|---|---|
| **① 判别式**（不让模型说话） | 比较各个选项的概率 | 不需要 | MMLU、HellaSwag |
| **② 生成式**（自由发挥） | 让模型写一段，再从文本里抽取 | ★★ 需要 —— 而且**抽取会失败** | GSM8K、MATH、HumanEval |
| **③ agentic**（智能体式，真动手） | 真开容器、真跑代码 | ★★★ 不需要，靠执行验证 | SWE-bench、Terminal-Bench |

⟹ 🔑🔑 全书定律：★★★【越真实 ⟺ 越贵 ⟺ 越难复现】

## 全书最重要的五条

```
   ① ★★★ 分数是【模型 + 评测方法】的联合产物，不是模型的固有属性。
      ✅ 证据：DeepSeek-V3 报告自承，"由于过去几个月我们评测框架的变化"，
         V2-Base 的分数和上次公布的结果出现了差异（权重一个字节没改）。
         ⚠️ 原文用词是 "a slight difference"，别把它读成"差很多"。

   ② ★★★ 抽取失败 ≠ 答错，但在分数上完全等价，而且【看不见】。
      ⟹ 05 章。这是"同模型差十几分"最常见的技术原因之一。

   ③ ★★★ agentic 分数 = 模型能力 × 脚手架设计 × 尝试预算。
      ✅ 证据：SWE-agent 论文，同一个 GPT-4 Turbo 在 SWE-bench Lite 上，
         RAG 检索 2.67 → 纯 shell 无示范 7.33 → 纯 shell 11.00 → SWE-agent 18.00。
         模型没换，只换了外面那层程序。

   ④ ★★★ 污染让"会做"和"见过"无法区分。
      ✅ 证据：LiveCodeBench 论文，DS-Base-33B 在 LeetCode 上
         5 月发布的题 Pass@1 约 60，9 月发布的题 Pass@1 约 0。

   ⑤ ★★★ 榜单的作用是【排除明显不行的】，不是【选出最适合你的】。
      ⟹ 后者只有一条路：12 章，自己攒 50 条真实样本。
```
