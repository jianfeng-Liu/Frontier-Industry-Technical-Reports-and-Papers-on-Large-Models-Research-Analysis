B. 三种范式对照卡

┌────────────┬─────────────┬──────────────┬─────────────┬──────────┐
│            │ ① 判别式    │ ② 生成式     │ ③ agentic   │          │
├────────────┼─────────────┼──────────────┼─────────────┼──────────┤
│ 模型输出   │ 不输出       │ 一段文本      │ 多轮动作     │          │
│ 怎么判     │ 比概率       │ 抽取 + 匹配   │ 真跑测试     │          │
│ 需要抽取吗 │ ❌ 不需要   │ ✅ 需要 ★★★ │ ❌ 不需要   │          │
│ 闭源 API   │ ⚠️ 做不了   │ ✅ 可以      │ ✅ 可以     │          │
│ 单题成本   │ 极低         │ 低           │ ★★★ 极高   │          │
│ 可复现性   │ 高           │ 中           │ 低           │          │
│ 典型基准   │ MMLU        │ GSM8K/MATH   │ SWE-bench   │          │
└────────────┴─────────────┴──────────────┴─────────────┴──────────┘

⟹ 🔑 定律：★★★【越真实 ⟺ 越贵 ⟺ 越难复现】

⚠️ 那个"闭源 API 做不了判别式"的格子最容易被忽略：
   ★★★ GPT/Claude 的 API 不返回 logprobs ⟹ 无法做判别式评测
   ⟹ 同一张榜单上的开源模型和闭源模型，可能【口径根本不同】。

C. 看到一个分数，问这七件事（11 章速用卡）

   ① ★★ 这是哪种范式？（判别式 / 生成式 / agentic）
   ② ★★ few-shot 几 shot？用了什么提示词模板？
   ③ ★★★ 生成式的话：抽取规则是什么？抽取失败算什么？
   ④ ★★★ agentic 的话：脚手架是什么？跑了几次？怎么挑的？
   ⑤ ★★ 温度多少？跑几遍？pass@1 是哪种定义？
   ⑥ ★★ 这个数是自己跑的，还是从别人报告里抄的？
   ⑦ ★★★ 这个基准发布于该模型训练截止日之前吗？（污染）

   ⟹ 🔑 七个里答不上三个以上，这个分数只能当【非常粗的参考】。

D. ⚠️⚠️ 三个"同名不同义"的陷阱

★★★ 这三个是全书最容易踩的坑，单独拎出来。

① pass@1 有两种完全不同的定义

   ┌─ HumanEval 那一系（取最大值语义）───────────────────┐
   │  pass@k = 采样 k 个，★ 只要有一个对就算对            │
   │  ⟹ k 越大分数越高。pass@1 = 只采一个。              │
   └──────────────────────────────────────────────────────┘
   ┌─ DeepSeek-R1 那一系（取平均语义）────────────────────┐
   │  pass@1 = (1/k)·Σ pᵢ ，★★ k 次各自对错取【平均】     │
   │  ⟹ ✅ R1 用 k=64（AIME/GPQA）、16（MATH/CF）、8（LCB）│
   │  ⟹ k 越大分数【不变高，只变稳】                      │
   └──────────────────────────────────────────────────────┘

   ⚠️ 🔑 两张榜单都写 "pass@1"，一个是 greedy 跑一次，
      一个是采样 64 次取平均 ⟹ ★★★【这两个数不能直接比】。

② "可复现"有两种

   ① 逐次可复现（同输入 → 同输出）   ← greedy 提供这个
   ② 统计可复现（同配置 → 同分数）   ← 多次采样取平均提供这个

   ✅ R1 报告的发现：长输出推理模型用 greedy 会
      "higher repetition rates and significant variability
       across different checkpoints"
   ⟹ 🔑 ★★★ 对长输出模型，② 比 ① 重要得多。

③ SWE-bench 有三个不同的题集

   ┌──────────────┬────────┬──────────────────────────────┐
   │ 名字         │ 题数    │ 说明                          │
   ├──────────────┼────────┼──────────────────────────────┤
   │ SWE-bench    │ 2,294  │ ✅ 全量                       │
   │ Lite         │   300  │ ✅ 论文给出的精简子集         │
   │ Verified     │   500  │ ⚠️ 人工核验过题目可解的子集   │
   └──────────────┴────────┴──────────────────────────────┘

   ⚠️ 🔑 ★★★ 三个数【绝对不能横向比较】。Verified 上的分数
      系统性高于全量，因为它剔除了描述不清、根本做不了的题。

F. 排查清单：分数明显不对时按这个顺序查

   ⚠️ 顺序是按【出错概率从高到低】排的，不要跳着查。

   1. ★★★ 对话模板（chat template）用对了吗？
      ⟹ 04 章。chat 模型套了 base 模型的拼法 = 分数腰斩。
      ⟹ lm_eval 里对应 --apply_chat_template

   2. ★★★ 抽取规则匹配得上模型的输出格式吗？
      ⟹ 05 章。看几条原始输出（--log_samples），
         对比 resps 和 filtered_resps。
      ⟹ ⚠️ 大量 "[invalid]" = 抽取挂了，不是模型笨。

   3. ★★ few-shot 数量和别人一致吗？示例是怎么选的？
      ⟹ 04 章 + 10.4。

   4. ★★ 停止符（until）设对了吗？
      ⟹ 设错会把答案截断，或者让模型继续编下一道题。

   5. ★★ 温度 / 采样次数和对比对象一致吗？
      ⟹ 10.7b。

   6. ★ 数据集版本 / 子集选对了吗？
      ⟹ 例：SWE-bench 全量还是 Verified。

   7. ★ 模型 checkpoint 或 API 版本变了吗？
      ⟹ 闭源 API 会静默升级。

G. 常用命令（lm-evaluation-harness）

# 冒烟测试：只跑 20 条，看流程通不通
lm_eval --model hf --model_args pretrained=<model> \
        --tasks gsm8k --limit 20 --log_samples --output_path ./out

# ★★★ chat 模型必须加这个
lm_eval --model hf --model_args pretrained=<model> \
        --tasks mmlu --apply_chat_template

# 改 shot 数
lm_eval ... --tasks mmlu --num_fewshot 5

# ★★ 加载你自己写的任务 yaml
lm_eval ... --include_path ./my_tasks --tasks my_task

   ⟹ 🔑 三个必用参数：
   ★★★ --log_samples   保存每条的原始输出，★ 出问题时唯一的线索
   ★★  --limit         先跑 20 条，别一上来就烧钱
   ★★★ --apply_chat_template   chat 模型的默认动作
