一、一句话总览

Kimi K3 = 2.8T 总参 / 104B 激活的原生多模态 MoE，1M 上下文，相比 K2 扩展效率提升约 2.5×。

报告的组织方式非常清晰——沿三个维度扩展"信息流动"：

维度 技术 一句话
序列长度 KDA + Gated MLA 混合注意力 用固定大小的"笔记本"代替不断变长的 KV cache
网络深度 AttnRes（注意力残差） 每层自己挑要读哪些前面的层，而不是被动累加
模型宽度 Stable LatentMoE 896 专家选 16，但专家在半宽的隐空间里干活

外加：原生视觉 MoonViT-V2 + Per-Head Muon 优化器。

二、改进点 1：KDA —— 把"图书馆"换成"记事本"

最简单的类比

  • Transformer 的 softmax 注意力：读过的每一页都留在桌上，随时可以翻回去查。精确，但桌子越堆越大（KV cache 随长度线性增长）。
  • KDA（线性注意力）：边读边往一个固定大小的记事本上记。成本恒定，但会遗忘。

K3 的选择是 3:1 混合：每个 block 里 3 层 KDA + 1 层 Gated MLA，主干末尾再额外加一层 MLA，保证最后一层一定是全局注意力。

直觉：75% 的层"记笔记"，25% 的层"留全本"。日常推进靠笔记本，需要精确回忆时靠那 1/4 的全局层。

记事本具体怎么写：Delta Rule

记事本就是一个矩阵 S ∈ R^(d_k × d_v)，可以理解成一张表：key 是栏目名，value 是内容。

写入：k_t v_tᵀ   ——  "在 k_t 这一栏，写下 v_t"
读取：o_t = Sᵀ q_t  ——  "拿 q_t 去查这张表"

朴素线性注意力直接累加：S += k vᵀ。问题是同一栏反复写，会越叠越糊。

Delta rule 的做法是"先擦再写"：

S_t = (I − β_t k_t k_tᵀ) · Diag(α_t) · S_{t−1}  +  β_t k_t v_tᵀ
       └── 擦掉 k_t 栏的旧内容 ──┘  └遗忘┘        └── 写入新值 ──┘
  • (I − β k kᵀ)S：把 k_t 这一栏的旧内容按比例擦掉。β=1 完全覆盖，β=0 不动。这就是"改写"而不是"叠加"。
  • Diag(α_t)：channel-wise 遗忘门——这是 Kimi 的核心贡献。不是整本笔记统一褪色，而是每一行（每个 key 通道）有自己的遗忘速度："这栏记的是人名，慢点忘；那栏是临时数字，快点忘。"

KDA = Delta rule + 逐通道遗忘门。 名字里的 Delta 是改写规则，Kimi 加的是那个精细的门。

各个量的参数化（原文 Eq.2）：q, k 都过 ShortConv → Swish → L2Norm，v 过 ShortConv → Swish，β 过 Sigmoid，衰减 logit z 走一个低秩投影 + 每头独立的 bias。

K3 相对 Kimi Linear 的两个改动

① 下界化衰减：一个"数值范围换算力"的漂亮例子

KDA 实际计算是分块（chunkwise）的：块内并行、块间递归。块内计算时需要除以累积衰减 Γ（把 key 重新放缩回来）。

问题来了：α 全都小于 1，连乘 16 个可以变得任意小，它的倒数就任意大 → BF16 溢出。

  • Kimi Linear：g = −e^A · Softplus(z) ∈ (−∞, 0)，下不封底。所以对角块只能走昂贵的"逐位置对比"慢路径。
  • Kimi K3：换成带下界的 scaled sigmoid

g = g_min · Sigmoid(e^A · z) ∈ (g_min, 0), g_min = −5 (固定) α = exp(g) ∈ (e^−5, 1) ≈ (0.0067, 1)

于是一个 16-token tile 内的累积 log 衰减必落在 (−80, 0)，倒数上界 e^80，BF16 装得下。

结果：对角块也能用 Tensor Core 稠密矩阵乘了，块内最大的瓶颈直接消失。 一个数值上的约束换来了算力上的解放——这是这篇报告里最漂亮的一处设计。

② 全秩输出门

Kimi Linear 的输出门是低秩的，K3 改成 input-dependent 全秩投影：

y_t = W_o [ Sigmoid(W_g x_t) ⊙ RMSNorm(õ_t) ]

Gated MLA 那 1/4 层

  • 沿用 DeepSeek-V2 的 MLA（把 KV 压成低维 latent 缓存，用时再上投影）
  • 同样加了全秩输出门，让每个 token 自己调制"从全局注意力里读哪些通道"
  • 训练时把 flash attention 的输出保持 FP32，修正舍入偏差；代价是片上占用翻倍，所以重新设计 kernel，让它和 KV staging buffer 重叠而不是和 query tile 重叠

最关键的一个决定：全模型 NoPE

K3 彻底不用任何位置编码——没有 RoPE，没有 ALiBi，什么都没有。

位置信息完全由 KDA 的衰减和门控隐式提供（越久远衰减越多，天然就是位置信号）；MLA 层则纯粹负责"无位置偏好的全局内容交互"。

直接收益：扩展到 1M 上下文时不需要动任何位置编码参数——不用重调 RoPE frequency base，不用 YaRN 插值。模型直接外推。

这是第一个前沿级别模型全面采用 NoPE。

三、改进点 2：AttnRes —— 把残差从"累加"变成"检索"

📄 AttnRes 有独立论文，不是 K3 报告首发：《Attention Residuals》arXiv:2603.15031，Kimi Team，2026-03-16，比 K3 报告（07-28）早四个多月，代码在 MoonshotAI/Attention-Residuals。
✅ K3 报告正文确认：N ≈ 8 的 block 版本能在各个模型规模上拿回 Full AttnRes 的大部分收益。
⚠️ 开销数字请谨慎：K3 报告全文没有给出任何百分比形式的墙钟开销，只给了 O(Ld) → O(Nd) 的渐近界；独立论文的摘要页也只有定性的 "minimal overhead"。社区流传的"推理 <2%""训练 +4%""算力优势 1.25×"等数字，我无法回溯到一手来源，本文不再采用。
它的谱系：DenseFormer（2402.02622，输入无关的标量深度加权）→ DeepCrossAttention（2502.06785，Google，可学习且输入相关的跨层权重）→ MUDDFormer（把每个块的输入解耦成 Q/K/V/残差四路）→ AttnRes（单伪 query 的深度 softmax 注意力）。
后续工作已经出现两篇（均为 Luo / Cai / Hu 同一组作者，以下描述已按摘要逐条核对）：
- Delta Attention Residuals（2605.18855，2026-05）——批评 AttnRes 在累加隐状态上做路由，这些状态高度冗余，导致深层出现"路由塌陷"、注意力分布趋于均匀（峰值权重仅 ≈ 0.2）；改成在相邻隐状态之差（增量）上路由后峰值升到 ≈ 0.6。220M–7.6B 上验证困惑度改善 1.7%–8.2%，且可由已有 checkpoint 经普通微调转换。
⚠️ 一处对不上的地方，如实标出：K3 报告式 8 写的是 $f_i(h_i)$（增量），块内求和 $b_n=\sum_j f_j(h_j)$ 也只有在增量语义下才讲得通——与该文"AttnRes 路由的是累加状态"的表述矛盾。可能是记号差异，也可能是独立论文原版与 K3 部署版的差异，仅凭摘要无法判断。
- Multi-Head Attention Residuals（2607.27230，2026-07）——批评 AttnRes 读深度时用的是整个宽度共享的单个 query，所有特征子空间被迫用同一个分布去读历史层，子空间之间越"意见不合"代价越大，而这种分歧随宽度增长（⚠️ "rank-1"是我的转述，摘要原文并未使用这个词）。做法是把路由 query 拆成 H 个子空间头做块对角读取，零新增参数，H=1 退化回原版，最优在 H ≈ 4~8。100M/350M/1B 上验证损失 −0.061 / −0.149 / −0.140；8B 中训转换 +3.2 GSM8K / +3.1 GPQA。
⚠️ 它同时暴露了成本：即便配上融合 Triton kernel，吞吐也只有 baseline 的 0.55~0.88×（不融合时仅 0.2~0.5×）。

🔑 注意这两篇攻击的，正好是让 AttnRes 便宜的那两处简化："每层只有一个 query"和"源该怎么取"。这是三家残差改动里唯一一个已经长出独立研究线的。

问题

标准残差 h_l = h_{l-1} + f_l(h_{l-1}) 把所有历史层的信息压进单个状态。报告的原话很精准：

这是一个瓶颈，让人想起 RNN 在时间维度上的问题——只不过这次发生在深度维度上。

Transformer 当年就是用注意力替换了时间上的递归。AttnRes 就是把同样的方法论用在深度上。

机制

第 l 层有一个可学习的"伪 query" w_l（注意：它不依赖输入，是这一层固定的一个"提问"）。拿它去和前面每一层的输出做注意力：

key = value = { 第 i 层【写出的那一份】f_i(h_i) },  其中 i = 0 时是 token embedding
         ★★ 注意是【增量】f_i(h_i)，不是【累加状态】h_i
            —— 拿累加值当源会高度冗余（每个源都含前面所有源），根本挑不出东西
         ★  且 key 与 value 是同一个东西：没有 W_K，也没有 W_V

α_{i→l} = softmax_i ( w_lᵀ · RMSNorm(k_i) )

h_l = Σ_{i=0}^{l−1} α_{i→l} · v_i

翻译成人话：每一层自己决定"我要读前面哪几层的输出"，而不是被动接收一个累加结果。

RMSNorm 的作用：防止某一层输出幅度特别大就霸占全部权重。

Block 版本：控制开销

朴素实现要保留所有层的输出，内存和流水线并行的跨阶段通信是 O(Ld)。

于是分块：93 层切成 8 个 block，每块 12 层（算上 embedding 层共 9 个源）。

  • 块内：层输出直接求和
  • 块间：只对 N 个 block 级表示做全注意力

开销从 O(Ld) 降到 O(Nd)。而且 block 结构限定了推理时的状态大小，块间并行结果可以用 online softmax 和块内顺序部分和高效合并，显著降低推理成本。报告说 N ≈ 8 就能拿到大部分收益。

四、改进点 3：Stable LatentMoE —— 极端稀疏 + 三个稳定器

Latent 是什么意思：让专家在窄空间里干活

普通 MoE 的问题：每个被选中的专家都要收到完整的 7168 维 token。选 16 个专家，通信量和专家权重读取流量就 ×16。

LatentMoE 的解法：把"模型宽度"和"路由专家宽度"解耦。

共享专家：直接吃全宽 7168 的 x        ← 负责"人人都要的通用变换"
路由专家：先降到 latent ℓ = 3584 再分发  ← 负责"专门化"

u = Σ_{i∈T_k(x)}  p_i · E_i^routed( W↓ x )
y = Σ_j E_j^shared(x)  +  W↑ · RMSNorm(u)

通信量和专家权重流量直接减半，省下的预算换成了专家数翻倍。 于是 K3 能做到 896 个路由专家、每 token 激活 16 个（稀疏度 56×）+ 2 个全宽共享专家。

极端稀疏放大了两个失效模式

报告很坦率地列出了问题：

  1. 激活爆炸：路由路径变成了 W↓ → 门控多分支专家 FFN → W↑ 这样近乎四次连续矩阵乘的病态链条，配上 2.8T 的规模，内部激活会炸。
  2. 负载均衡失灵：接近 10³ 个专家，超出了现有 auxiliary-loss-free bias 更新方法仍能正常工作的范围。

三个解药对应下去：

① Up-projection 前插 RMSNorm

原始 LatentMoE 直接对聚合结果 u 用 W↑，而 u 的尺度会随选中的专家和路由权重变化。K3 在中间插一个 RMSNorm，降低对尺度波动的敏感度。除了稳定训练，还一致地改善了验证 loss 和下游 benchmark。

② SiTU-GLU：给 SwiGLU 两个分支都加软上限

SwiGLU 的问题：Swish(W_g x) ⊙ W_u x，两个乘数都是无界的。两边同时出现大坐标 → 激活离群值 → 低精度算术溢出。而原始 GLU 的 sigmoid 门虽然有界，却丢掉了 Swish 在正半轴那个近似线性的响应。

SiTU-GLU 的做法：用 softcap(x, β) = β·tanh(x/β) 分别封住 Swish 门的线性因子和 up 分支：

SiTU-GLU(x) = [ β₁·tanh(W_g x / β₁) ⊙ Sigmoid(W_g x) ] ⊙ [ β₂·tanh(W_u x / β₂) ]

K3 取 β₁ = 4（门分支）, β₂ = 25（up 分支）  →  |f(x)| ≤ β₁β₂ = 100

tanh 在原点附近近似线性、大值处饱和，所以 SiTU-GLU 在原点附近几乎和 SwiGLU 重合，在大值处却是有界的。既保住了 SwiGLU 的局部响应，又控住了两个因子的乘积。

③ Quantile Balancing：把一个超参直接解掉

旧办法（aux-loss-free）：给每个专家一个 bias b_j 加到路由分上参与 Top-k，然后

b_j ← b_j + γ · sign(目标负载 − 实际负载)

γ 是固定步长——大了震荡，小了跟不上。896 个专家时更难调。

QB 的做法：不迭代，直接解出来。

① 路由时用 Top-(k+1) 而不是 Top-k
   → 第 (k+1) 名的分数就是"想挤进 token i 的 Top-k 需要跨过的门槛" α_i
   （从 Top-(k+1) 取门槛，就不用再单独算一次 token 侧的分位数）

② margin_{i,j} = s_{i,j} − α_i    "专家 j 对 token i 还差多少能进"

③ 想让专家 j 恰好收到目标负载 q = mk/n 个 token？
   把 b_j 设成这些 margin 的 (1 − k/n) 分位数的相反数即可
   —— 正好 q 个 margin 高过门槛，一个不多一个不少

④ 最后统一减去均值（不影响 Top-k 选择）

γ 这个敏感超参直接消失了。

★ 为什么"分位数"恰好是对的？ 报告附录 C 给了完整推导：把负载均衡写成「最大得分的均衡指派」（每 token 选 k 个、每专家恰好收 mk/n 个）这个线性规划，它是二部图 b-matching，LP 松弛的最优解天然是整数，所以松弛不损失任何东西；取拉格朗日对偶后做交替坐标最小化，token 侧和专家侧两个子问题的闭式解都是 (1 − k/n) 分位数——一个沿 token 轴、一个沿专家轴，方法的名字就来自这里。

⭐ 最漂亮的一处（报告式 27）：对偶目标对 β_j 的梯度恰好等于「目标负载 − 实际负载」。
也就是说——上面那个旧的 sign 更新，正是这同一个目标的 SignSGD 版本（只保留误差方向、丢掉大小，所以必须配一个步长 γ）；而 QB 直接跳到同一目标的精确坐标最小值。
这一个视角同时解释了：① 为什么 QB 没有任何类似学习率的超参 ② 为什么近 10³ 个专家也能在几步内平衡。

训推一致来自一个不对称：最优解里 token 侧阈值 α 对同一行是常数、不影响行内排序，于是被消掉——路由只需要专家侧的 n 个阈值，α 是绑在当前 batch 上的中间变量，用完即弃。部署时就是固定 Top-k + 一个冻结的 bias，不需要算任何分位数。

📘 完整推导（对偶、交替求解器、直方图误差界、以及报告自己给的 BIP 负面结果）见 大模型架构入门 §10.5。

工程上，全局 batch 的 margin 有几百万个、散在各个 rank 上，精确分位数不可行。K3 用直方图估计：每个 rank 统计自己的 bin 计数，一次 all-reduce 求和，从池化后的计数读出分位数。因为计数是可加的，不管 token 怎么切分，直方图代表的都是完整的全局 batch，通信成本只有每专家几百个 bin。

（另外：bias b 只参与 Top-k 选择，不进入混合权重 p_i，所以它调度而不干扰梯度。推理时 bias 冻结。）

五、改进点 4：Per-Head Muon

K2 就用 Muon 了，K3 对注意力投影做了细化：

不对完整的 Q、K、V 投影矩阵做 Newton–Schulz 正交化，而是把动量矩阵按 head 维度切开，每个 head 的块单独正交化。

直觉：整矩阵正交化把所有 head 当成一个耦合块，梯度/动量尺度大的 head 会主导共享的更新方向，尺度小的 head 得到的归一化不足。逐 head 做就把更新尺度在 head 之间拉平了。

顺带还更便宜——在瘦高的 per-head 块上跑 Newton–Schulz 比在完整投影矩阵上跑要省。

⚠️ 优先权提示：GLM-5 技术报告（arXiv:2602.15763，2026-02-17）里的 Muon Split 是同一个想法——"把这些矩阵按 head 切成小矩阵，对每个 head 的独立小矩阵分别做正交化"，动机也一样（避免大尺度 head 主导共享的更新方向）。比 K3 报告早五个月。 详见 GLM-5.2.md §三。

六、原生视觉：MoonViT-V2 从零训练

这里有一个很有价值的实证结论。

通常做法：视觉编码器用 SigLIP / CLIP 这类对比学习预训练模型初始化，理由是"预训练视觉知识给模型一个起跑优势"。K2.5 自己也是这么做的。

K3 反其道而行：MoonViT-V2 完全从零、用 next-token prediction 训练。

理由是稳定性：报告给了梯度范数曲线（Fig. 6）——SigLIP 初始化的 MoonViT-3D 梯度范数持续更高且频繁 spike，而从零训的 MoonViT-V2 全程平稳。

结论：MoonViT-V2 在视觉评测上追平了 SigLIP 初始化的基线，说明——

在规模化的多模态语言模型上，对比学习预训练作为初始化是不必要的。

架构细节：27 层 ViT、约 0.4B 参数、patch size 14、用 RMSNorm、移除所有线性层和注意力投影的 bias 项（进一步稳定从零优化）。图像和视频完全共享参数：注意力分解成帧内空间 + 帧间时间两趟，时间维再做池化压缩。投影前用 2×2 pixel shuffle 把视觉 token 数降 4 倍，让 3584×3584 的输入在 1M 上下文里放得下。

七、预训练

四阶段渐进扩上下文：

预训练：8K → 64K
冷却期：256K → 1M

把昂贵的长序列计算集中在总训练预算的一小部分里，既省钱又让模型逐步适应长程依赖。

光有长度不等于有长程能力。所以 K3 专门合成长上下文数据：精心排列和拼接多模态文档与子任务，让内嵌的任务只有靠注意力横跨完整 1M 上下文才解得开。这是为了防止注意力退化成局部模式。

一个有意思的 scaling law 发现：报告在各自独立搜索最优超参的前提下比较 cosine decay 和 WSD，发现两者的最优峰值学习率和 batch size 差异很大——所以用同一套超参比较两个 schedule 是不公平的。在各自最优配置下，cosine decay 一致取得更低的最终 loss，K3 因此默认用 cosine。

其他：Per-Head Muon + K2 的 weight clipping，QB 做负载均衡，1% 线性 warmup，weight decay 0.1 全程。

八、后训练：三段式 + 9 个专家 + MOPD

① SFT     → 冷启动，XTML chat template，从这一步起就开 QAT
② RL      → 3 领域 × 3 档 effort = 9 个专家模型
③ MOPD    → 多教师 on-policy 蒸馏，合成一个统一模型

RL：9 个专家

三个领域各训一个专家，每个 effort 档位各一份：

  • general：通用体验、视觉、推理、忠实性、搜索、知识工作
  • general agents：长周期助理任务、深度研究、段落级写作
  • coding agents：软件工程、编码体验、kernel 任务、Web 开发

3 领域 × {low, high, max} = 9 个专家模型

Reasoning Effort RL 怎么控：给每道题一个由冷启动模型估出的初始 token 预算 b₀(x)，凡是总预算超过 τ · b₀(x) 的轨迹，任务奖励直接覆盖为 −1。训练按 τ 做课程：先训一个大 τ 的 max 版本（但仍设硬上限防过度思考），再退火 τ 得到 high 和 low。

Partial rollout：每轮采样 N × K 条轨迹，只要有 λ 比例完成就暂停生成，直接进入优化，不等长尾。暂停的轨迹入队，下一轮优先恢复。代价是数据变陈旧（一条长轨迹可能横跨多个迭代），靠逐 token 正则把更新约束在局部邻域内来容忍这种极端 off-policy。

Agentic GRM：不可验证的通用任务用生成式奖励模型，锦标赛式二元比较。judge 必须遵守强制协议：

① 读产出 → ② 生成 rubric → ③ 按 rubric 给每个候选打分 → ④ 记入 scorepad

防 reward hacking 的手段也很直接：输出长度超过 σ · ℓ₀ 的候选自动判负（和 effort 控制同构）。

MOPD：把 OPD 做成 RL 的稠密 reward

给定领域 d 和采样到的 effort 档 e，用对应的那个教师 π_teacher^(d,e)。逐 token 的 OPD 奖励：

r_opd(y_t | e, x, y_<t) = clip( sg( log [ π_teacher(y_t|x,y_<t) / π_θ(y_t|e,x,y_<t) ] ), −R_max, R_max )

sg 是 stop-gradient，clip 约束极端优势信号。

这是最值得注意的一点——K3 没有把蒸馏写成一个 KL loss，而是把 log 概率比当成稠密奖励塞进已有的 RL 框架。好处是：partial rollout 这类为长周期任务做的基建原封不动就能复用。

报告还提到试过更细粒度的 top-k 蒸馏目标，但"在收敛速度和最终性能上都没有明显优势"。

⚠️ 优先权提示：GLM-5 报告 §3.5 的 On-Policy Cross-Stage Distillation 用的是同一个形式——Â = sg[log(π_teacher / π_θ)] 当 GRPO 的 advantage，同样早五个月。区别在用途：GLM 用它跨阶段找回被后续 RL 冲掉的能力，K3 用它把 9 个专家合并成一个模型。另外 GLM 挖出了这个形式的一个额外好处——advantage 既然直接来自与教师的差距，GRPO 的 group size 就可以设成 1，吞吐直接拉满（K3 报告没提这一点）。见 GLM-5.2.md §八。

部署导向的后训练

  • MXFP4 QAT：MoE 专家权重量化到 MXFP4、激活 MXFP8；注意力投影、latent MoE 投影、共享专家、路由器保持高精度。从 SFT 一路贯穿到 RL 全程做 QAT，RL 阶段 rollout 和训练用同一套量化方案，彻底消除 train–inference mismatch。
  • Draft model：把预训练的 MTP 层微调成 EAGLE-3 风格的草稿模型。输入融合第 1、第 4、最后一个 AttnRes block 的低/中/高层特征，融合矩阵 W_E3 初始化为 [0 0 I]——初始时刻等价于只用高层特征（也就是 MTP 层原本被训练的输入），再慢慢学着吸收低中层。
    训练目标也换了：不优化常规 KL 代理，而直接优化 LK loss——接受率的负对数 −log Σ_x min(p(x), q(x))。因为对容量受限的草稿模型来说，最小化 KL 并不保证最大化接受率。

九、Infra 亮点

  • FlashKDA：针对 KDA 状态的串行依赖，每个执行 regime 一个专用 kernel（训练/prefill 用 chunkwise，解码另设）。已开源。
  • KDA Context Parallelism + state-aware prefix caching：把 KDA 固定大小状态"便宜可传输"这个特性用满——设备内、跨设备、跨请求三个层次。
  • MoonEP：完美均衡的专家并行。因为 QB 保证了均衡，每个 rank 收到的 token 数恰好是 S×K，所有层的计算形状静态可知——于是消除了每层的 MoE host 同步（传统实现必须每层等设备回报实际形状才能启动）。融合的 permute/unpermute 算子做零拷贝通信：规划 kernel 预先算好每个 token 的目的地，直接发到远端 rank 的专家分组位置。最坏不均衡下 DeepEP 需要 S×K×R 的缓冲区，MoonEP 只要固定的 S×K。
  • 统一激活管理器：重计算、量化、offload 都只是同一个存储抽象下的"策略"，可以在张量粒度自由组合，用轻量标注声明，和模型代码完全解耦。
  • 1M agentic RL：外部 KV cache pool（写回策略，空闲前缀淘汰出 GPU 时才写到 CPU DRAM，下次复用前预取；KDA 状态和对应的 MLA KV 块一起 offload/prefetch，生命周期对齐）+ 可恢复的 microVM 沙箱。
