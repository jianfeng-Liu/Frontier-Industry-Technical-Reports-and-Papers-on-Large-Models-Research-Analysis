0. 在进目录之前：先把一句话走完一遍

这一页不是索引页的装饰。如果你从来没有见过 Transformer，下面这三节就是你需要的全部前置知识——看完你会知道"文字怎么变成数、数怎么变回文字"，然后再进目录读 01 章就不会懵。

📌 先约定几个词（缩写在本教程第一次出现都会给全称，查不到就翻 附录速查表 的缩写总表）：

词 全称 一句话
token（词元） — 模型眼里的最小单位。不是"字"也不是"词"，是子词：常见词一整块，罕见词拆几块
Tokenizer（分词器） — 把一串文字切成 token、再把每个 token 换成一个整数编号的那个程序
Embedding（词嵌入） — 一张 [词表大小 × 宽度] 的大表。给它一个整数编号，它还你一行实数向量
hidden dim（隐藏维，记作 d） hidden dimension / d_model 每个 token 被表示成多少个实数。openPangu-2.0-Pro 是 5120
FFN（前馈网络） Feed-Forward Network 对每个 token 单独做的一小段非线性变换
MoE（混合专家） Mixture of Experts 把一个大 FFN 拆成很多个小 FFN，每个 token 只用其中几个
LM Head（语言模型输出头） Language Model Head 最后那个矩阵乘法，把向量变回"每个候选词得几分"
logits（未归一化打分） — LM Head 吐出来的原始分数，还没变成概率
softmax（归一化指数函数） — 把一串任意实数变成一串非负、加起来等于 1 的概率

0.1 全流程：一句话进去，一个词出来

模型做的事情只有一件：给它前面的若干个 token，让它猜下一个 token 是什么。"写一篇文章"只是把这件事重复几千次，每次把刚猜出来的词接到输入末尾再猜一遍。

下面这张图就是这一件事的全部。以 openPangu-2.0-Pro（✅ 报告 Table 8 的配置：50 层、d=5120、词表 151,552）为例：

输入文本    "今天天气不错"
   |
   |  (1) Tokenizer：切成 3 个 token，每个查表换成一个整数编号
   v
token 编号  [3271, 8402, 1195]
   |
   |  (2) Embedding：拿编号当行号，去大表 E 里把那一行抄出来
   v
x           3 个 token，每个 5120 个实数
   |
   |=== 以下 50 层结构完全一样，x 的形状从头到尾不变 ===============
   |
   |  (3) Attention 注意力：让 3 个 token 互相看一眼    x = x + Attn(Norm(x))
   |  (4) FFN / MoE     ：每个 token 各自再加工一遍    x = x + FFN(Norm(x))
   |
   |=== 重复 50 次 ================================================
   |
   |  (5) 最后一次归一化
   v
x_final     还是 3 个 token，每个 5120 个实数
   |
   |  (6) LM Head：乘一个 5120 x 151552 的大矩阵
   v
logits      3 个位置，每个位置给 151552 个候选词各打一个分
   |
   |  (7) 只要最后一个位置那一行，softmax 把分数变成概率
   v
概率        151552 个数，全都 >= 0，加起来正好 = 1
   |
   |  (8) 按这个概率抽一个编号出来，反查词表
   v
输出        "，"

每一步的张量形状（形状写在图外，图里只画流向）：

步骤 数据 形状 代入 openPangu-2.0-Pro
输入 文本 — "今天天气不错"（6 个汉字）
(1) 后 token 编号 [L] [3]
(2) 后 x [L, d] [3, 5120]
(3)(4) 每层后 x [L, d] [3, 5120] ← 50 层里一直是这个形状
(6) 后 logits [L, V] [3, 151552]
(7) 后 概率 [V] [151552]
(8) 后 下一个 token — 1 个整数

📌 这张图里最反直觉、也最重要的一点：中间 50 层没有改变形状。进去是 [3, 5120]，出来还是 [3, 5120]。50 层不是在"把东西越变越大"，而是在原地反复改写同一块 [3, 5120] 的内容——像 50 个人轮流在同一张草稿纸上修改同一段笔记。

这就是 03 章 残差流 那个"总线"比喻的来源，也是全教程最值得先记住的一张图。

🔑 另一个新手常卡住的点：图里第 (7) 步只取了最后一个位置。那前面两个位置的 logits 呢？推理时丢掉，训练时全都要——训练时第 0 个位置在预测第 1 个词、第 1 个位置在预测第 2 个词，一次前向就得到 L 份监督信号。这是 Transformer 训练效率高的直接原因，见 05 章 §5.4 因果掩码。

0.2 最小数值走查：把上图缩小到能用手算

把 d 从 5120 缩到 4，词表从 151,552 缩到 4，序列长度取 3。结构一个箭头都不变，但现在每个数你都能自己验算。

📌 这一节只走两端：文字 → 数（第 (1)(2) 步）和 数 → 文字（第 (6)(7)(8) 步）。中间那 50 层在这里是个黑箱。 想看黑箱里面每一层的 Q、K、V、softmax、残差具体是多少，去 16 章 最小数值走查——那一章把同样尺寸的例子从头到尾逐步算完了，包括注意力矩阵。

设定：词表只有 4 个词，Embedding 矩阵 E 是 4 行 4 列。

编号   词      E 的第几行          这一行的 4 个数
 0    "猫"       第 0 行         1   0   1   0
 1    "追"       第 1 行         0   1   0   1
 2    "鼠"       第 2 行         1   1   0   0
 3    "。"       第 3 行         0   0   1   1

文字 → 数（对应上图第 (1)(2) 步）：

输入 "猫追鼠"
  (1) Tokenizer  ->  ["猫", "追", "鼠"]  ->  编号 [0, 1, 2]
  (2) Embedding  ->  把 E 的第 0、1、2 行抄出来叠成一个 3x4 的表：

       x  =   1   0   1   0        <- "猫"
              0   1   0   1        <- "追"
              1   1   0   0        <- "鼠"

🔑 "查表"是字面意义的查表，没有任何计算。 教科书上会写成 x = one_hot(t) @ E（一个 151552 维的 0/1 向量乘一个 151552×5120 的矩阵），那只是数学上的写法；真实代码就是 x = E[ids]，一次按行索引。⚠️ 如果真的去做那个矩阵乘，会白白浪费 99.999% 的乘法（15 万个数里只有 1 个是 1）。

中间：这个 3 x 4 的表进入 50 层黑箱，出来还是一个 3 x 4 的表。假设最后一个位置（"鼠"）出来的那一行是

x_final["鼠"]  =   1.0   0.5   1.0   0.0

数 → 文字（对应上图第 (6)(7)(8) 步）。这里用权重绑定（weight tying，输出层直接复用 E，见 02 章 §2.3），所以 LM Head 就是"拿 x_final 和词表里每一行做内积"：

候选词 E 的那一行 内积算式 logit
猫 1 0 1 0 1.0×1 + 0.5×0 + 1.0×1 + 0.0×0 2.0
追 0 1 0 1 1.0×0 + 0.5×1 + 1.0×0 + 0.0×1 0.5
鼠 1 1 0 0 1.0×1 + 0.5×1 + 1.0×0 + 0.0×0 1.5
。 0 0 1 1 1.0×0 + 0.5×0 + 1.0×1 + 0.0×1 1.0

📌 看懂这张表，就看懂了 LM Head 的全部：logit 就是内积，内积就是方向相似度。LM Head 在问的是一句大白话——"现在这个状态，最像词表里哪个词的方向？"

最后一步 softmax，把这 4 个分数变成 4 个概率。公式 P_i = exp(logit_i / T) / Σ_j exp(logit_j / T)，T 是温度（temperature）。把三种温度并排算出来：

候选词 logit T=0.5 的 exp T=1 的 exp T=2 的 exp P (T=0.5) P (T=1) P (T=2)
猫 2.0 e^4.0 = 54.598 e^2.0 = 7.389 e^1.00 = 2.718 0.644 0.455 0.350
追 0.5 e^1.0 = 2.718 e^0.5 = 1.649 e^0.25 = 1.284 0.032 0.102 0.165
鼠 1.5 e^3.0 = 20.086 e^1.5 = 4.482 e^0.75 = 2.117 0.237 0.276 0.273
。 1.0 e^2.0 = 7.389 e^1.0 = 2.718 e^0.50 = 1.649 0.087 0.167 0.212
— — 和 = 84.791 和 = 16.238 和 = 7.768 和 = 1.000 和 = 1.000 和 = 1.000

第 (8) 步：按 T=1 那一列的概率抽签——45.5% 抽到"猫"、10.2% 抽到"追"、27.6% 抽到"鼠"、16.7% 抽到"。"。抽到编号 0，反查词表得到 "猫"，输出"猫"。然后把"猫"接到输入末尾变成 "猫追鼠猫"，回到第 (1) 步再来一轮。

🔑 三列概率放在一起看，温度是什么就一目了然了：
T 小（0.5） -> 强者更强：最高分从 0.455 拉到 0.644，最低分从 0.102 压到 0.032 输出稳定、可复现，但容易重复、呆板 T = 1 -> 忠实反映模型自己算出来的概率 T 大（2） -> 拉平：0.350 / 0.165 / 0.273 / 0.212 四个词几乎一样 输出有创造性，但也更容易胡说 T -> 0 -> 退化成"永远取最高分"（贪心解码 / argmax），采样这一步消失
⚠️ 温度只改变"怎么从分布里抽"，不改变模型本身。 同一个模型、同一段输入，logits 永远是那 4 个数，变的只是抽签规则。

最后，把玩具尺寸和真机尺寸并排放一次，你就知道刚才手算的那几步在真实模型里有多大：

玩具（上面这个例子） openPangu-2.0-Pro（✅ 报告 Table 8） 放大了多少倍
词表 V 4 151,552 3.8 万倍
宽度 d 4 5,120 1280 倍
层数 N 1（还是黑箱） 50 50 倍
序列 L 3 最长 524,288（512K） 17 万倍
Embedding 表的格子数 4 × 4 = 16 151,552 × 5,120 = 7.76 亿 4850 万倍
一次前向的乘加次数 几十次，手算得完 约 343 亿次 / token —

📌 "约 343 亿次"是怎么来的：前向的浮点运算次数 ≈ 2 × 真正参与乘法的激活参数量 = 2 × 17.2 B ≈ 34.3 GFLOP（Embedding 那 0.78 B 只是查表，不做乘法）。这个"乘 2"来自"一次乘加 = 1 次乘 + 1 次加 = 2 次浮点运算"。激活参数量怎么从 505B 里拆出来的，见 01 章 §1.4。

0.3 读到这里你已经有的东西

✅ 知道模型只干一件事：给前面的 token，猜下一个 token
✅ 知道文字 -> 整数编号 -> 向量 是三步，其中第二步就是查表
✅ 知道向量 -> 文字 是"和词表里每个词比方向"，比完 softmax 抽签
✅ 知道中间 50 层不改形状，是在同一块数据上反复改写
⬜ 还不知道：中间那 50 层到底在改什么     -> 从 01 章开始，一章讲一格
