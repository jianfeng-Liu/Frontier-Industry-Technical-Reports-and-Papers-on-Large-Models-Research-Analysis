01 · 鸟瞰：一个 token 的完整旅程

这一章的目标：给你一张完全不需要理解细节就能看懂的全景图，后面每一章都是在放大其中一格。
读完你应该能回答：模型里到底有哪些东西？"505B 参数"这个数字是怎么来的？为什么所有架构创新都只发生在三个位置？

本章关键词

token（词元）—— 模型处理的最小单位，一段文本被切成若干个 token。
Embedding（词嵌入）—— 一张 [V, d] 的查找表，把 token 的整数编号换成一行 d 个实数。
残差流（Residual Stream）—— 贯穿所有层的那一条 [L, d] 数据流，每一层都在上面做加法而不是替换。
Attention（注意力）—— 让不同位置的 token 互相读取信息的模块，横向。
FFN（Feed-Forward Network，前馈网络）—— 对每个 token 单独做的非线性变换，纵向。
MoE（Mixture of Experts，混合专家）—— 把一个大 FFN 拆成很多个小 FFN，每个 token 只激活其中几个。
LM Head（Language Model Head，语言模型输出头）—— 最后那个 [d, V] 的矩阵，把向量变回"每个候选词得几分"。
logits（未归一化打分）—— LM Head 的原始输出，还没过 softmax。
FLOP（Floating-point Operation，浮点运算次数）—— 衡量计算量的单位；一次乘加算 2 FLOP。
MFU（Model FLOPs Utilization，模型算力利用率）—— 实际达到的 FLOPS ÷ 硬件峰值 FLOPS。

1.1 全景图

模型只干一件事：给它前面若干个 token，让它猜下一个 token。生成一整篇文章，就是把这件事重复几千次，每次把刚猜出来的那个 token 接到输入末尾再猜一遍。

下面这张图就是这一件事的全部：

输入文本    "今天天气"

   v
token 编号  [1234, 567, 890]
   |
   |  (2) Embedding 查表：拿编号当行号，取出 E 的那一行
   v

   |
   |=== 以下重复 N 层（五家 N = 50 ~ 93），x 的形状全程不变 ========
   |
   |  (3) x = x + Attention( Norm(x) )      让 token 之间交换信息
   |  (4) x = x + FFN_or_MoE( Norm(x) )     让每个 token 自己加工信息
   |
   |=== 第 N 层结束 ==============================================
   |
   |  (5) 最后一次 Norm

   |

每一步的张量形状（标注写在图外，图里只画流向；代入 openPangu-2.0-Pro 的 d=5120、V=151552、N=50）：

步骤 数据 通用形状 代入本例 这一步做了什么
输入 文本 — "今天天气" —
(1) 后 token 编号 [L] [3] 查 tokenizer 的词表，纯查表
(2) 后 x [L, d] [3, 5120] 查 Embedding 表，纯查表，零乘法
(3) 每层 x [L, d] [3, 5120] 加上注意力的输出
(4) 每层 x [L, d] [3, 5120] 加上 FFN/MoE 的输出
(5) 后 x_final [L, d] [3, 5120] 最后一次归一化
(6) 后 logits [L, V] [3, 151552] 唯一一次维度从 d 涨到 V
(7) 后 概率 [V] [151552] 非负、和为 1

📌 这张图里最反直觉、也最该先记住的一点：中间 N 层没有改变形状。进去是 [3, 5120]，第 50 层出来还是 [3, 5120]。N 层不是"把东西越堆越大"，而是在同一块 [L, d] 的数据上原地反复改写。这就是 03 章 残差流 那个"总线"比喻的全部来源。

🔑 第 (7) 步只取了最后一个位置，那前面那些位置的 logits 呢？
推理时：丢掉。你只想要下一个词，只有最后一个位置在预测它 训练时：全都要。第 0 个位置在预测第 1 个词，第 1 个位置在预测第 2 个词 …… 一次前向就拿到 L 份监督信号 —— 这是 Transformer 训练效率高的直接原因
为什么第 0 个位置看不见第 1 个词，见 05 章 §5.4 因果掩码。

这张图就是全部。 一个 500B 参数的前沿模型，结构上和一个 100M 的玩具模型没有任何区别——只是 N 更大、d 更宽、FFN 换成了 MoE。想看这张图上每个数字的真实取值（缩到 d=4、V=4 的玩具尺寸，全部能手算），见 16 章 最小数值走查。

1.2 只有两种积木

整个 Transformer 只有两种"积木"在交替堆叠：

积木 方向 干什么 一句话
Attention 横向 让不同位置的 token 互相看 "第 100 个词该参考前面哪些词？"
FFN / MoE 纵向 每个 token 独立地加工自己的向量 "把这个词的表示变得更有用" 
   pos:            t1    t2    t3    t4    t5      <- 序列里的 5 个位置
                   |     |     |     |     |
   Attention:      o=====o=====o=====o=====o       横向连线：token 之间交换信息
                   |     |     |     |     |
   FFN:            #     #     #     #     #       竖直独立：每个 token 各算各的
                   |     |     |     |     |          （同一份参数，但互不影响）
   Attention:      o=====o=====o=====o=====o
                   |     |     |     |     |
   FFN:            #     #     #     #     #
                   :     :     :     :     :

🔑 记住这个二分法。五家所有的架构改动，最后都能归到三个位置之一：

(1) 改 Attention —— 怎么横向交换 -> 第 05 / 07 / 08 章 (2) 改 FFN / MoE —— 怎么纵向加工 -> 第 09 / 10 章 (3) 改这两块之间的连接 —— 残差流本身 -> 第 03 / 04 章

为什么恰好是这两种

这不是随便设计的。任何一个序列模型都必须回答两个问题：

问题 1：不同位置的信息怎么混合？    <- 必须有，否则模型看不见上下文
问题 2：单个位置的信息怎么变换？    <- 必须有，否则模型没有非线性表达力

历史上的答案：

模型 怎么混合位置（问题 1） 怎么变换单点（问题 2） 任意两点的路径长度 问题
RNN / LSTM 沿时间递归，一步传一步 门控 + tanh $O(L)$ 串行，没法并行训练；长程信息经过 L 步衰减
CNN 卷积核，只看邻域 逐点非线性 $O(L / k)$，$k$ 为卷积核 感受野有限，看远处要堆很多层
Transformer 注意力：任意两个位置直接连通 FFN $O(1)$ 计算量 $O(L^2)$，长序列贵

Transformer 赢在"任意两点一步可达"：第 100 万个 token 和第 1 个 token 之间的路径长度是 1，不是 100 万（RNN）也不是 100 万 ÷ 卷积核大小（CNN）。梯度不需要走长路，信息不会被逐步稀释。

代价就是 $O(L^2)$。这一代五份技术报告，一半篇幅都在还这笔债。（见 06 KV cache、08 高效注意力）

1.3 一个常见的误解：N 层不是循环 N 次

❌ 错误理解：一层参数，反复用 N 次（像 RNN 那样）
✅ 正确：第 1 层和第 50 层各有【完全独立的一整套参数】

所谓"505B 参数"，就是这 50 层的权重全部加起来（再加上 embedding）。

不同层学到的东西差别很大（这是可解释性研究的共识）：

浅层（1~10）    ->  语法、词性、局部搭配、"这个 token 是不是标点"
中层（10~40）   ->  语义、指代消解、事实关联、任务识别
深层（40~50）   ->  输出规划、"下一个词具体是什么"
最后 1~2 层     ->  几乎只在做"把内部表示翻译成词表分布"

📌 这个分层现象直接支撑了两处真实的架构设计：
- DeepSeek-V4 把浅层的 MoE 改成哈希路由——浅层做的事简单且通用，不太需要"聪明的路由"（见 10 MoE）
- openPangu 的 mHC 门控塌陷恰好发生在早期层，需要专门的块级后归一化来救（见 04 归一化）

1.4 参数量是怎么算出来的

这一节能帮你把"505B"这种数字从抽象变具体。

1.4.1 先用一个稠密（非 MoE）模型热身

设 $d$ = hidden dim、$d_{ff}$ = FFN 中间维、$N$ = 层数、$V$ = 词表。⚠️ 下面这组数是为了好算而虚构的一个稠密模型（d=5120, d_ff=13824, N=50, V=153600），不是任何一家的真实配置；真机的账在 §1.4.2。

组件 参数量公式 代入 数值
Embedding $V \times d$ 153600 × 5120 0.79 B
LM Head $V \times d$（常与上面绑定共享） 153600 × 5120 0.79 B（绑定则为 0）
每层 Attention $4d^2$（$W_Q, W_K, W_V, W_O$ 各一个 $d\times d$） 4 × 5120² 105 M
每层 FFN（SwiGLU 三个矩阵） $3\,d\,d_{ff}$ 3 × 5120 × 13824 212 M
每层 Norm $2d$（可忽略） 2 × 5120 10 K
每层小计 $4d^2 + 3d\,d_{ff}$ 105 M + 212 M 317 M
N 层合计 $N(4d^2 + 3d\,d_{ff})$ 50 × 317 M 15.9 B
总计（绑定） $N(\cdots) + Vd$ 15.9 + 0.79 16.6 B
总计（不绑定） $N(\cdots) + 2Vd$ 15.9 + 1.57 17.4 B

两个可以直接记住的经验比例：

(1) FFN 占约 2/3 的参数，Attention 占约 1/3
    因为 d_ff ≈ 2.7d，所以 3·d·d_ff ≈ 8.1d²  vs  Attention 的 4d²
    8.1 / (8.1 + 4) = 67%

(2) 参数量随 d 是【平方】增长，随 N 是【线性】增长
    -> 想加参数，加宽比加深"效率"高，但加宽会让每层的计算和通信都变重

1.4.2 ★ 真机推演：把 openPangu-2.0-Pro 的 505B 一项一项加出来

✅ 下面所有输入数字都来自 openPangu-2.0 技术报告 附录 Table 8（架构超参表），可逐项回溯：

Total Layers 50      Dense Layers 3      MoE Layers 47
Hidden Size 5120     Vocabulary Size 151552
Attention Heads 64   Query Projection Rank 1536   Key-Value Projection Rank 512
Non-Positional QK Dimensions 128   RoPE Dimensions 64   Value Head Dimensions 128
Dense FFN Intermediate Size 16128
Routed Experts 384   Shared Experts 1   Activated Routed Experts 8
Expert Intermediate Size 1792

第一步：一个专家有多大。 一个专家就是一个小 SwiGLU，三个矩阵（gate / up / down），每个 d × 专家中间维：

项 算式 数值
一个专家 $3 \times 5120 \times 1792$ 27.53 M
一个 MoE 层的全部专家 $(384 + 1) \times 27.53\,\text{M}$ 10.60 B ← 一层就 106 亿
47 个 MoE 层 $47 \times 10.60\,\text{B}$ 498.07 B

第二步：其余部分。

项 算式 数值 占 505B
47 个 MoE 层的专家 上表 498.07 B 98.7 %
3 个稠密层的 FFN $3 \times (3 \times 5120 \times 16128)$ 0.74 B 0.15 %
Embedding + LM Head（按不绑定算） $2 \times 151552 \times 5120$ 1.55 B 0.31 %
50 层的注意力（⚠️ 下面推算） $50 \times 80.0\,\text{M}$ 4.00 B 0.79 %
合计 504.36 B —
✅ 报告写的总参数 505 B 差 0.13 %

⚠️ 注意力那一行是推算，不是报告直接给的。 报告只给了各个 rank，没有逐个矩阵列参数量。按 MLA（Multi-head Latent Attention，多头潜在注意力，见 07 章）的标准参数化拆开是这样：
```
W_DQ Q 降维 5120 x 1536 = 7.86 M
W_UQ Q 升维 1536 x 64 x (128 + 64) = 18.87 M
W_DKV KV 降维 5120 x 512 = 2.62 M
W_KR RoPE 那支 5120 x 64 = 0.33 M
W_UK K 升维 512 x 64 x 128 = 4.19 M
W_UV V 升维 512 x 64 x 128 = 4.19 M
W_O 输出投影 64 x 128 x 5120 = 41.94 M

每层合计 = 80.02 M
```
推算值加起来离报告值只差 0.13%，说明这个拆法基本对。 剩下那 0.6 B 是各层 RMSNorm 权重、mHC 的门控系数、PAS（Parametric Attention Sink，参数化注意力汇）的 128 对可学习 KV 等零碎项——⚠️ 报告没有逐项披露，这里不做进一步拆分。另外 ✅ 报告的 3 个 MTP（Multi-Token Prediction，多 token 预测）层看起来没有被计入这 505B，否则总数会明显超出。

🔑 这张表最该带走的一句话：505B 里有 98.7% 是专家。 注意力只占 0.79%，Embedding 加 LM Head 只占 0.31%。所以"大模型很大"这件事，在 MoE 时代基本等价于"专家很多"。10 章 MoE 讲的就是这 98.7% 怎么花。

1.4.3 激活参数：同一张表换个问法

总参数决定显存，激活参数决定算力和速度。 同样的配置，换成"一个 token 实际用到多少参数"：

项 算式 数值 占 18B
50 层注意力（每层都参与） $50 \times 80.0\,\text{M}$ 4.00 B 22.3 %
47 个 MoE 层，每层只激活 8+1 个专家 $47 \times 9 \times 27.53\,\text{M}$ 11.64 B 64.9 %
3 个稠密层的 FFN 同上表 0.74 B 4.1 %
LM Head $151552 \times 5120$ 0.78 B 4.3 %
Embedding（只查表，不做乘法） $151552 \times 5120$ 0.78 B 4.3 %
合计 17.94 B —
✅ 报告写的激活参数 18 B 差 0.3 %

📌 一个漂亮的巧合，值得停下来看一眼：稠密层的 FFN 中间维是 16128，而 MoE 层激活的 9 个专家合起来是 $9 \times 1792 = \mathbf{16128}$——一模一样。

也就是说：MoE 层和稠密层，一个 token 走过去的计算量完全相等。MoE 没有让单个 token 变贵，它只是把"同一份预算"从"1 个固定的 FFN"换成了"385 个里挑 9 个"。⚠️ 这个等式是我从 Table 8 的两个数字里看出来的，报告没有明说它是刻意设计；但 16128 = 9 × 1792 这么整齐，很难是巧合。

1.4.4 ⚠️ "稀疏度 48 倍"这个说法要小心

❌ 常见的错误说法："384 选 8，所以这个模型稀疏 48 倍 / 省了 48 倍"

✅ 三个数字，三个不同的问题，不能混用：
   384 / 8   = 48.0 倍   <- 只是【路由专家】的选择比
   385 / 9   = 42.8 倍   <- 算上那 1 个【共享专家】后的 FFN 稀疏比
   505 / 18  = 28.1 倍   <- ★ 全模型 总参数 / 激活参数
                            这才是"显存账 vs 算力账差多少"的正确口径

为什么会从 48 掉到 28：因为注意力、稠密层、Embedding、LM Head 这些部分一点都不稀疏，每个 token 都要全量走一遍。它们在总参数里只占 1.3%，在激活参数里却占了 35%。稀疏只发生在专家那一块。

总参数   = Embedding + LM Head + N x 注意力 + 稠密层 FFN + 47 x 【385 个专家】
激活参数 = Embedding + LM Head + N x 注意力 + 稠密层 FFN + 47 x 【被选中的 9 个】
                      \___________ 这一整段不稀疏 ___________/

openPangu-2.0-Pro:  505B 总参数  /  18B 激活参数
                    ^ 决定显存        ^ 决定算力和单 token 成本

详细的 MoE 参数账、路由怎么选、为什么要有共享专家，见 10 MoE。

1.5 计算量：训练和推理是两笔完全不同的账

这一节先埋个伏笔，06 KV cache 会展开。

一次前向的 FLOPs（每 token 每层）：

$$\underbrace{8d^2}{\text{Attention 的四个投影}} + \underbrace{6d\,d}{\text{FFN}} + \underbrace{4Ld}$$}

📌 这三项的 2 倍系数是哪来的：一次乘加 = 1 次乘 + 1 次加 = 2 FLOP。所以"$W_Q$ 有 $d^2$ 个参数"对应"$2d^2$ FLOP"，四个投影就是 $8d^2$；FFN 的三个矩阵有 $3d\,d_{ff}$ 个参数，对应 $6d\,d_{ff}$。一句话记法：前向 FLOPs ≈ 2 × 参与计算的参数量。

前两项和序列长度无关，第三项随 L 线性增长（对整条序列就是 $L^2$）。

L = 4K 时：    4Ld = 4 x 4096 x 5120     ≈ 8.4e7    vs   8d²+6d·d_ff ≈ 6.3e8
               -> 注意力矩阵只占 8.4 / (8.4 + 63) ≈ 12%，可以忽略

L = 1M 时：    4Ld = 4 x 1048576 x 5120  ≈ 2.1e10   vs   6.3e8
               -> 注意力矩阵占 97%，【完全主导】

🔑 这就是"长上下文"的全部困难所在：
短序列时注意力不是瓶颈，长序列时它是唯一的瓶颈。 而且它是平方增长的——长度从 128K 到 1M 是 8 倍，整条序列的这一项涨 64 倍（按单个 token 算是 8 倍；平方来自"每个 token 都要多看 8 倍的历史，而 token 数本身也多了 8 倍"）。

推理还要再分两个阶段（06 章详解）：

Prefill（处理你输入的提示词）：一次并行处理 L 个 token   ->  算力受限（compute-bound）
Decode （一个一个吐字）      ：一次处理 1 个 token       ->  访存受限（memory-bound）
                                                             ^ 这个非常反直觉，是第 06 章的核心

1.5.1 真机推演：各组件的计算量占多少

延续 §1.4.3 的 openPangu-2.0-Pro 激活参数账，前向 FLOPs ≈ 2 × 激活参数：

组件 算式 GFLOP / token 占比
注意力的各个投影 $2 \times 4.00\,\text{B}$ 8.00 23.3 %
FFN（47 层各 9 个专家 + 3 个稠密层） $2 \times 12.39\,\text{B}$ 24.77 72.2 %
LM Head $2 \times 0.78\,\text{B}$ 1.55 4.5 %
Embedding 查表，无乘法 0 0 %
小计（与 L 无关的部分） $2 \times 17.16\,\text{B}$ 34.33 100 %

再把随 L 变化的注意力矩阵那一项加进来。 openPangu 每层 64 个头、QK 维 128+64=192、V 维 128，所以每 token 每层是 $2L \times 64 \times 192 + 2L \times 64 \times 128 = 40960\,L$ FLOP，50 层就是 $2.05\times 10^{6} \times L$：

序列长度 L 若用全注意力 占总量 ⚠️ 实际的 DSA-SWA 架构 省了多少
4 K 8.4 GFLOP 20 % 2.1 GFLOP 4 倍
128 K 268 GFLOP 89 % 2.1 GFLOP 127 倍
512 K 1074 GFLOP 97 % 2.1 GFLOP 507 倍

⚠️ 右边两列是推算，不是报告给的数。 推算依据：✅ 报告写 DSA:SWA = 1:2、SWA Window Size = 512，DSA 每个 token 只挑固定 K 个历史 token 参与注意力、报告举的例子是 K = 2048（原文写的是 "e.g., 2,048"，⚠️ 所以未必是最终配置）。按 1:2 推 50 层里约 17 层 DSA、33 层 SWA，代入得 $17 \times 40960 \times 2048 + 33 \times 40960 \times 512 \approx 2.1$ GFLOP，与 L 无关。

⚠️ 但不能说"L² 项消失了"。 ✅ 报告 Table 1 明确列出 DSA-SWA 的 prefill FLOPs 仍有一个 $S^2$ 系数，来自 Lightning Indexer（轻量索引器，负责挑出那 K 个 token）——只是它作用在一个便宜得多的低维索引表示上。报告没给索引器的头数和维度，⚠️ 无法定量，所以上表右列是下界。

🔑 这张表就是这一代五份报告的共同动机：全注意力在 512K 下要多烧 30 倍的算力（1074 vs 34.3），而这 1074 里绝大部分是在看不相关的历史。08 高效注意力 讲的就是五家各自怎么把这一项砍掉。

1.5.2 训练那笔账：为什么是 6N

推理只有前向，训练还要反向。反向传播要算两种梯度，各自的代价都和前向一样：

这一趟在算什么 每个参数的 FLOP 说明
前向 $2N$ 算出每一层的输出
反向 · 对输入求梯度 $2N$ 把梯度继续往前一层传
反向 · 对权重求梯度 $2N$ 这一层的参数该怎么改
合计 $\mathbf{6N}$ ⚠️ 不含优化器更新，也不含激活重计算 
训练总 FLOPs ≈ 6 x N x D        N = 参与计算的参数量，D = 训练 token 总数
                                ⚠️ MoE 模型这里的 N 要用【激活参数】，不是总参数

代入 openPangu-2.0-Pro（✅ 报告：语料约 34 万亿 token，激活参数 18B）：

6 x 18e9 x 34e12 = 3.67e24 FLOP

⚠️ 6N 漏掉了注意力矩阵那一项。 补全式是 $6N + 12 \cdot L_{\text{layers}} \cdot s \cdot h$（$s$ 为序列长，$h$ 为 hidden dim）。以 Llama-3-70B（80 层、$h$=8192、$N$=70B）为例：
s = 4096：12 x 80 x 4096 x 8192 = 3.22e10 vs 6N = 4.2e11 -> +7.7% s = 8192：12 x 80 x 8192 x 8192 = 6.44e10 vs 6N = 4.2e11 -> +15.3%
序列越长这个补正越不能省。 ⚠️ 但它假设的是全注意力；对 openPangu 这种 DSA-SWA 架构，注意力矩阵是常数级的（见 §1.5.1），这个补正项不适用。

换算成机时（⚠️ openPangu 实际训在昇腾 NPU 上，下面只是"如果换成 H100"的等效换算，用来建立量级感）：

项 数值 来源
H100 SXM5 稠密 BF16 峰值 989 TFLOPS ⚠️ 常被写成 1979 TFLOPS，那是 2:4 结构化稀疏值，当稠密用会把屋脊点从 295 算成 591 FLOP/Byte
假设 MFU（模型算力利用率） 35 %（⚠️ 在 H100 + 千卡级 MoE 训练上的常见区间，⚠️ 无一手来源） —
有效算力 989 × 0.35 = 346 TFLOPS —
总机时 3.67e24 ÷ 3.46e14 = 1.06e10 GPU·秒 ≈ 295 万 GPU·小时 —
4096 张卡要跑多久 295 万 ÷ 4096 ≈ 720 小时 ≈ 30 天 —

1.5.3 训练的显存账：为什么是"每个参数 16 字节"

混合精度 + AdamW 的标准配方，每个参数要存五份东西：

存的是什么 精度 字节 / 参数 AdamW Muon
权重（前向反向用的那份） BF16 2 ✅ ✅
梯度 BF16 2 ✅ ✅
FP32 主权重（更新在它身上做） FP32 4 ✅ ✅
一阶动量 $m$ FP32 4 ✅ ✅
二阶动量 $v$ FP32 4 ✅ ❌ Muon 不需要
合计 16 字节 / 参数 12 字节 / 参数

⚠️ 最容易记错的一点：$m$ 和 $v$ 是各 4 字节，不是加起来 4 字节。少算这一份，整个显存预算会小 25%。

代入 505B：

AdamW： 505e9 x 16 = 8.08e12 字节 = 8080 GB = 7525 GiB = 7.35 TiB
        ÷ H100 的 80 GB  ->  ★ 光是静态状态就要 101 张卡

Muon ： 505e9 x 12 = 6.06e12 字节 = 6060 GB = 5644 GiB = 5.51 TiB
        ÷ 80 GB          ->  76 张卡，比 AdamW 少 25 张

⚠️ GB 和 GiB 不是一回事：1 GB = 10⁹ 字节，1 GiB = 2³⁰ ≈ 1.074×10⁹ 字节，差 7.4%。H100 标称的"80 GB"是十进制口径。本教程凡是写 GB 的地方都是十进制，写 GiB 的地方都是二进制。

⚠️ 上面这两个数只是"静态状态"，不含激活值、不含通信缓冲、不含 KV cache。真实训练还要再加一大块，所以实际卡数远不止 101 张。

📌 ✅ 报告原文说 Muon "只跟踪一阶动量，把优化器状态显存减半"——对照上表就是 $m + v = 8$ 字节降到 $m = 4$ 字节，确实是减半。但要注意减半的是"优化器状态"那一项，不是总显存：总显存从 16 降到 12，是减少 25%。⚠️ "某项减半"≠"总量减半"，这类偷换在读报告时非常常见。 Muon 的原理见 13 章。

1.7 本章小结

(1) 模型 = Embedding -> [Attention + FFN] x N -> LM Head
    中间 N 层不改变形状，全程都是 [L, d]

(2) 只有两种积木：Attention 横向混合，FFN 纵向变换
    所有架构创新只发生在三个位置：改 Attention / 改 FFN / 改残差

(3) N 层是 N 套独立参数，不是循环

(4) 参数量（稠密）：FFN 占 2/3，Attention 占 1/3；随 d 平方、随 N 线性
    参数量（MoE）：openPangu-2.0-Pro 的 505B 里 98.7% 是专家
                    激活 18B 里 65% 是专家、22% 是注意力

(5) 前向 FLOPs ≈ 2 x 激活参数；训练 FLOPs ≈ 6 x 激活参数 x token 数
    ⚠️ 6N 不含优化器；显存 16 字节/参数（Adam 的 m、v 各 4）

(6) 短序列时注意力不是瓶颈，长序列时它是唯一瓶颈
    512K 下全注意力要多烧 30 倍算力，这就是五家全在改注意力的原因

(7) "384 选 8" 不等于"省 48 倍"。全模型口径是 505/18 = 28 倍
