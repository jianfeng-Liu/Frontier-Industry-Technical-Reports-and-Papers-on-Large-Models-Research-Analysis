01 · 鸟瞰：一个 token 的完整旅程

这一章的目标：给你一张完全不需要理解细节就能看懂的全景图，后面每一章都是在放大其中一格。
读完你应该能回答：模型里到底有哪些东西？"505B 参数"这个数字是怎么来的？为什么所有架构创新都只发生在三个位置？

1.1 全景图

        输入文本 "今天天气"
             │
             │  ① Tokenizer：切成 token，查表变成整数 ID
             ▼
        [1234, 567, 890]                      形状 [L] = [3]
             │
             │  ② Embedding：每个 ID 查一个 d 维向量
             ▼
        ┌──────────────────┐                  形状 [L, d] = [3, 5120]
        │  x  (残差流起点)  │
        └──────────────────┘
             │
    ╔════════╪══════════════════════════════════════╗
    ║        ▼        重复 N 层（N = 50~93）          ║
    ║   ┌─────────────────────────────────────────┐ ║
    ║   │  x = x + Attention( Norm(x) )           │ ║  ← ③ 让 token 之间交换信息
    ║   │  x = x + FFN_or_MoE( Norm(x) )          │ ║  ← ④ 让每个 token 自己加工信息
    ║   └─────────────────────────────────────────┘ ║
    ╚════════╪══════════════════════════════════════╝
             │
             │  ⑤ 最后一次 Norm
             ▼
        ┌──────────────────┐
        │   LM Head (W_out) │                  [L, d] × [d, V] → [L, V]
        └──────────────────┘
             │
             ▼
        每个位置上，对 V 个候选词的打分（logits）
             │
             │  ⑥ softmax → 概率 → 采样
             ▼
        下一个 token："真"

这张图就是全部。 一个 500B 参数的前沿模型，结构上和一个 100M 的玩具模型没有任何区别——只是 N 更大、d 更宽、FFN 换成了 MoE。

1.2 只有两种积木

整个 Transformer 只有两种"积木"在交替堆叠：

积木 方向 干什么 一句话
Attention 横向 让不同位置的 token 互相看 "第 100 个词该参考前面哪些词？"
FFN / MoE 纵向 每个 token 独立地加工自己的向量 "把这个词的表示变得更有用" 
        位置 →   t1    t2    t3    t4    t5
                 │     │     │     │     │
 Attention:      ●━━━━━●━━━━━●━━━━━●━━━━━●     横向连线：token 之间交换信息
                 │     │     │     │     │
 FFN:            ▓     ▓     ▓     ▓     ▓     竖直独立：每个 token 各算各的
                 │     │     │     │     │     （同一份参数，但互不影响）
 Attention:      ●━━━━━●━━━━━●━━━━━●━━━━━●
                 │     │     │     │     │
 FFN:            ▓     ▓     ▓     ▓     ▓
                 ⋮     ⋮     ⋮     ⋮     ⋮

🔑 记住这个二分法。五家所有的架构改动，最后都能归到三个位置之一：

① 改 Attention —— 怎么横向交换 → 第 05 / 07 / 08 章 ② 改 FFN / MoE —— 怎么纵向加工 → 第 09 / 10 章 ③ 改这两块之间的连接 —— 残差流本身 → 第 03 / 04 章

为什么恰好是这两种

这不是随便设计的。任何一个序列模型都必须回答两个问题：

问题 1：不同位置的信息怎么混合？    ← 必须有，否则模型看不见上下文
问题 2：单个位置的信息怎么变换？    ← 必须有，否则模型没有非线性表达力

历史上的答案：

模型 怎么混合位置（问题 1） 怎么变换单点（问题 2） 问题
RNN / LSTM 沿时间递归，一步传一步 门控 + tanh 串行，没法并行训练；长程信息经过 L 步衰减
CNN 卷积核，只看邻域 逐点非线性 感受野有限，看远处要堆很多层
Transformer 注意力：任意两个位置直接连通 FFN $O(L^2)$，长序列贵

Transformer 赢在"任意两点一步可达"：第 100 万个 token 和第 1 个 token 之间的路径长度是 1，不是 100 万（RNN）也不是 100 万/卷积核大小（CNN）。梯度不需要走长路，信息不会被逐步稀释。

代价就是 $O(L^2)$。这一代五份技术报告，一半篇幅都在还这笔债。（见 06 KV cache、08 高效注意力）

1.3 一个常见的误解：N 层不是循环 N 次

❌ 错误理解：一层参数，反复用 N 次（像 RNN 那样）
✅ 正确：第 1 层和第 50 层各有【完全独立的一整套参数】

所谓"505B 参数"，就是这 50 层的权重全部加起来（再加上 embedding）。

不同层学到的东西差别很大（这是可解释性研究的共识）：

浅层（1~10）    →  语法、词性、局部搭配、"这个 token 是不是标点"
中层（10~40）   →  语义、指代消解、事实关联、任务识别
深层（40~50）   →  输出规划、"下一个词具体是什么"
最后 1~2 层     →  几乎只在做"把内部表示翻译成词表分布"

📌 这个分层现象直接支撑了两处真实的架构设计：
- DeepSeek-V4 把浅层的 MoE 改成哈希路由——浅层做的事简单且通用，不太需要"聪明的路由"（见 10 MoE）
- openPangu 的 mHC 门控塌陷恰好发生在早期层，需要专门的块级后归一化来救（见 04 归一化）

1.4 参数量是怎么算出来的

这一节能帮你把"505B"这种数字从抽象变具体。以一个稠密（非 MoE）模型为例，设 $d$ = hidden dim、$d_{ff}$ = FFN 中间维、$N$ = 层数、$V$ = 词表：

┌─────────────────┬────────────────────────┬─────────────────────────────┐
│ 组件             │ 参数量                  │ 代入 d=5120, d_ff=13824,     │
│                 │                        │ N=50, V=153600               │
├─────────────────┼────────────────────────┼─────────────────────────────┤
│ Embedding        │ V × d                  │ 0.79 B                      │
│ LM Head          │ V × d（常与上面共享）    │ 0.79 B（或 0）               │
├─────────────────┼────────────────────────┼─────────────────────────────┤
│ 每层 Attention   │ 4 d²  (W_Q,W_K,W_V,W_O)│ 105 M                       │
│ 每层 FFN(SwiGLU) │ 3 d·d_ff               │ 212 M                       │
│ 每层 Norm        │ 2 d（可忽略）            │ 10 K                        │
│ ── 每层小计 ──    │ 4d² + 3d·d_ff          │ 317 M                       │
├─────────────────┼────────────────────────┼─────────────────────────────┤
│ N 层合计         │ N(4d² + 3d·d_ff)       │ 15.9 B                      │
│ 总计             │                        │ ≈ 17.5 B                    │
└─────────────────┴────────────────────────┴─────────────────────────────┘

两个可以直接记住的经验比例：

① FFN 占约 2/3 的参数，Attention 占约 1/3
   （因为 d_ff ≈ 2.7d，所以 3·d·d_ff ≈ 8d²  vs  Attention 的 4d²）

② 参数量随 d 是【平方】增长的，随 N 是【线性】增长的
   → 想加参数，加宽比加深"效率"高，但加宽会让每层的计算和通信都变重

MoE 模型怎么算（这就是"505B / 18B"两个数字的由来）：

总参数   = Embedding + N × (Attention + 【全部 384 个专家】)
激活参数 = Embedding + N × (Attention + 【被选中的 8 个专家】)

openPangu-2.0-Pro:  505B 总参数  /  18B 激活参数     稀疏度 = 384/8 = 48×
                    ↑ 决定显存        ↑ 决定推理速度和成本

详细的 MoE 参数账见 10 MoE。

1.5 计算量：训练和推理是两笔完全不同的账

这一节先埋个伏笔，06 KV cache 会展开。

一次前向的 FLOPs（每 token 每层）：

$$\underbrace{8d^2}{\text{Attention 的四个投影}} + \underbrace{6d\,d}{\text{FFN}} + \underbrace{4Ld}$$}

前两项和序列长度无关，第三项随 L 线性增长（对整条序列就是 $L^2$）。

L = 4K 时：    4Ld = 4×4096×5120 ≈ 8.4e7      vs   8d²+6d·d_ff ≈ 6.4e8
              → 注意力矩阵只占 ~12%，可以忽略

L = 1M 时：    4Ld = 4×1048576×5120 ≈ 2.1e10  vs   6.4e8
              → 注意力矩阵占 97%，【完全主导】

🔑 这就是"长上下文"的全部困难所在：
短序列时注意力不是瓶颈，长序列时它是唯一的瓶颈。 而且它是平方增长的——长度从 128K 到 1M 是 8 倍，这一项涨 64 倍。

推理还要再分两个阶段（06 章详解）：

Prefill（处理你输入的提示词）：一次并行处理 L 个 token   →  算力受限（compute-bound）
Decode （一个一个吐字）      ：一次处理 1 个 token       →  访存受限（memory-bound）
                                                           ↑ 这个非常反直觉，是第 06 章的核心

1.7 本章小结

① 模型 = Embedding → [Attention + FFN] × N → LM Head
② 只有两种积木：Attention 横向混合，FFN 纵向变换
③ N 层是 N 套独立参数，不是循环
④ 参数量：FFN 占 2/3，Attention 占 1/3；随 d 平方、随 N 线性
⑤ 短序列时注意力不是瓶颈，长序列时它是唯一瓶颈（L² 项）
⑥ 所有架构创新只发生在三个位置：改 Attention / 改 FFN / 改残差
