# 02 · Embedding 与词表：怎么把"今天"变成向量

> **这一章的目标**：讲清模型的入口和出口。读完你应该能回答：token 是怎么切出来的？为什么词表是 15 万？"hidden dim 5120 是五家最窄"这句话意味着什么？

---

## 2.1 第一步：Tokenizer，把文本切成 token

计算机不认识"天气"，只认识数字。所以第一步是**查表**。但在查表之前，得先决定**怎么切**。

### 三种切法，各有致命问题

```
① 按字符切     "今天天气" → ["今","天","天","气"]
   ✅ 词表极小（几千个字）
   ❌ 序列变得极长 → 回忆 01 章：L² 的代价。而且单个汉字信息量太低

② 按词切       "今天天气" → ["今天","天气"]
   ✅ 序列短、语义完整
   ❌ 词表爆炸（中文词组几百万），而且永远会遇到没见过的词（OOV）

③ 按【子词】切  ← 现在所有模型的选择
   常见词整个是一个 token，罕见词拆成几块
   "今天" → 1 个 token        "反刍动物学" → 可能拆成 3~4 个
```

### BPE：子词是怎么"学"出来的

**BPE（Byte Pair Encoding）本质是一个贪心的压缩算法**，你有算法基础的话看一遍就懂：

```
初始：把所有文本拆成最小单位（UTF-8 字节），词表 = 256 个字节

循环（直到词表达到目标大小，比如 15 万）：
    ① 统计当前语料里【相邻两个 token 的组合】出现次数
    ② 找出出现最多的那一对，比如 ("t", "h") 出现了 100 万次
    ③ 把 "th" 作为一个【新 token】加入词表
    ④ 语料里所有 "t","h" 相邻的地方，合并成 "th"
```

```python
def bpe_train(corpus_tokens, vocab_size):
    vocab, merges = set(b for t in corpus_tokens for b in t), []
    while len(vocab) < vocab_size:
        pairs = Counter()
        for word in corpus_tokens:
            for a, b in zip(word, word[1:]):
                pairs[(a, b)] += 1
        best = pairs.most_common(1)[0][0]        # 出现最多的相邻对
        merges.append(best)                       # 记下这条合并规则
        vocab.add(best[0] + best[1])
        corpus_tokens = [merge(w, best) for w in corpus_tokens]
    return vocab, merges                          # merges 是有序的，推理时按序重放
```

**推理时**：把 `merges` 这个有序列表按顺序重放一遍，就得到确定的切分。**同一段文本永远切出同一个结果。**

> 🔑 **一个非常实际的结论**：**token 数 ≠ 字数**。
> ```
> 英文：平均 1 个 token ≈ 4 个字符 ≈ 0.75 个单词
> 中文：平均 1 个 token ≈ 1~1.5 个汉字（好的中文 tokenizer 能到 1.5~2）
>
> 所以 "512K 上下文" 对中文大约是 60~100 万字，对英文大约是 200 万单词
> ```
> **这也是国产模型都很在意 tokenizer 中文效率的原因**——同样的 1M 上下文，中文 token 效率高 30%，就等于上下文长了 30%，而且推理成本降 30%。

### 一个必须知道的坑：tokenizer 决定了模型的某些"愚蠢"

```
"strawberry 里有几个 r？"    模型答错，因为它看到的是 ["str","aw","berry"]，
                             根本没有"字符"这个概念

数字 "12345"                 可能被切成 ["123","45"]，所以算术能力天生受损
                             → 现在的做法是【强制数字逐位切分】
```

**这不是模型笨，是输入表示层的信息就已经丢了。**

## 2.2 第二步：Embedding，查表

```
词表（vocabulary）：一个固定的、训练前就定好的清单
    ...
    1234 → "今天"
    567  → "天气"
    ...

Embedding 矩阵 E：形状 [V, d]，比如 [153600, 5120]
    第 1234 行就是 "今天" 这个词的 5120 维向量
```

### 数学

设 token ID 为 $t$，one-hot 向量 $e_t \in \mathbb{R}^{V}$（第 $t$ 位是 1，其余是 0），则

$$x = e_t^\top E, \qquad E \in \mathbb{R}^{V \times d}$$

实际实现**不会真的做这个矩阵乘**（那是 15 万维乘 5120 维的巨大浪费）——**one-hot 乘矩阵等价于按行索引**：

```python
x = E[token_ids]          # [L] → [L, d]，就是一次查表，O(L·d)
```

### 这些向量长什么样

**Embedding 是可学习的参数，训练开始时是随机的**，训练结束后会自发形成几何结构：

```
    语义相近的词，向量方向也相近（余弦相似度高）

    "国王" − "男人" + "女人"  ≈  "女王"      ← 经典的类比结构
    "北京" − "中国" + "法国"  ≈  "巴黎"

    ⚠️ 注意：这在 word2vec 时代是显式性质，在大模型里没那么干净
       因为 embedding 只是【第 0 层的输入】，真正的语义在中间层才形成
```

**一个更准确的理解**：Embedding 层不负责"理解语义"，它只负责**把离散的符号变成一个模型能做算术的连续向量**。真正的语义加工在后面 50 层里。

## 2.3 第三步（跳到最后）：LM Head，从向量回到词

模型最后一层输出 $x_L \in \mathbb{R}^{L\times d}$，要变回"下一个词是什么"：

$$\text{logits} = x_L\,W_{\text{out}},\qquad W_{\text{out}} \in \mathbb{R}^{d\times V}$$

```
    [L, 5120] × [5120, 153600] → [L, 153600]
                                      ↑ 每个位置对每个候选词的【打分】
```

**然后 softmax 变成概率**：

$$P(\text{word}_i) = \frac{\exp(\text{logit}_i / T)}{\sum_j \exp(\text{logit}_j / T)}$$

$T$ 是**温度**（temperature）：

```
T → 0    退化成 argmax，永远取最高分的词（贪心，输出确定但呆板）
T = 1    按模型的原始概率采样
T > 1    分布被拉平，输出更随机、更有创造性
```

### 权重绑定（weight tying）

**很多模型让 $W_{\text{out}} = E^\top$**，即输入和输出共享同一份矩阵。

```
✅ 省一份 V×d 的参数（7.9 亿）
✅ 直觉合理：进和出用同一套"词 ↔ 向量"的对应关系
❌ 在超大模型上这个约束可能过强，所以前沿模型不一定绑定
```

> 📌 五家的报告里这一格大多没明说。**但注意 [16 数值走查](16-最小数值走查.md) 里我用的是绑定版本**，因为它让例子更短。

## 2.4 三个你需要有量级感的数字

| | 是什么 | 五家的量级 | 影响什么 |
|---|---|---|---|
| **V**（词表） | 有多少个不同的 token | 15 万左右（openPangu-2.0 **149,600**⁄**151,552**⚠️见下，GLM **154,880**） | Embedding 参数量；tokenizer 效率 |
| **d**（hidden dim） | 每个 token 的向量宽度 | **5120 ~ 7168** | ⭐ **几乎所有矩阵的大小** |
| **Embedding 参数** | `V × d` | 15 万 × 5120 ≈ **7.9 亿** | 显存；且它不适合用 Muon（[13 章](13-优化器与Muon.md)） |

> ⚠️ **openPangu 那一格要解释一下，因为它的报告里【同时存在两个数】**（我逐页核对过）：
> ```
> ✅ §2.6 Table 4（tokenizer 那一节）：openPangu-2.0-single-digit = 149,600
>    ——这是【真正训出来的 BPE 词表大小】，报告正文写明 2.0 采用的就是这个变体
> ✅ 附录超参表（架构配置）：Vocabulary Size = 151,552（三个尺寸都一样）
>    ——这是【Embedding 矩阵的宽度】，为了张量并行切分而【补齐】过
>
> ★ 两个数都是报告原文，不矛盾，只是【问的问题不同】：
>    "tokenizer 认识多少个 token" → 149,600
>    "Embedding 矩阵有多宽"       → 151,552（多出来的 1,952 行是永远不会被查到的占位）
> ⚠️ 顺带纠一个容易抄错的数：153,376 是 openPangu-【1.0】的词表，不是 2.0 的。
> ```
> ★ 这个"补齐"的机制本身见 §2.4；数据侧的完整对照表在
> [数据教程 9.4 / 9.6](../../数据格式和数据处理/09-Tokenizer与词表.md)。

> 🔑 **`d` 是整个模型最重要的一个超参**。回忆 [01 章](01-鸟瞰全景.md) 的参数量公式：
> ```
> 每层参数 = 4d² + 3d·d_ff  ——  随 d 是【平方】增长的
> ```
> **所以 openPangu 把 d 定在 5120（五家最窄），是一个杠杆极大的决定**：相比 K3 的 7168，同样层数下每层参数只有 $(5120/7168)^2 = 51\%$。
>
> 这就是 [../模型技术对比.md](../模型技术对比.md) §二里"Hidden dim 5120（五家最窄）"那一格的分量——它是 openPangu 把激活参数压到 18B 的**第一个**手段（另外三个是浅层数、多专家、小专家，见 [10 MoE](10-MoE.md)）。

## 2.5 挂回五家

**Embedding 这一块，五家的架构改动几乎为零。** 但有两处值得记：

### ① Embedding 不用 Muon

五家高度一致地把 embedding、LM head、所有 norm 权重、所有 bias **排除在 Muon 之外，继续用 AdamW**。

**原因**（[13 章](13-优化器与Muon.md)详解）：Muon 的整个逻辑建立在"这是一个**矩阵**、它的奇异值谱有意义"之上。而 embedding 矩阵**不是一个作用于向量空间的线性映射**，它只是 15 万个彼此独立的行向量堆在一起。**对它做 SVD 正交化没有任何意义。**

### ② 词表大小的取舍

```
词表大  →  同样文本 token 数少  →  上下文更长、推理更便宜
        →  但 Embedding 和 LM Head 更大，且 softmax 更贵
        →  且罕见 token 训练不充分

五家都收敛在 15 万左右，说明这大概是当前的甜点区
```

## 2.6 本章小结

```
① Tokenizer 用 BPE（贪心合并最高频的相邻对）把文本切成子词
   → token 数 ≠ 字数；中文 tokenizer 效率直接换算成上下文长度和成本
② Embedding = 一次查表，把整数 ID 变成 d 维向量
③ LM Head = 反向的一次投影，回到词表维度，再 softmax + 温度采样
④ d 是最重要的超参，参数量随它平方增长
   → openPangu 的 d=5120 是它压低激活参数的第一个杠杆
⑤ 这一层五家不改；唯一值得记的是它不用 Muon
```
