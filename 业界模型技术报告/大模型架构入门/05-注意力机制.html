05 · 注意力：从"查字典"讲到公式

这一章的目标：讲清 Transformer 里唯一真正"新"的东西。
读完你应该能回答：Q/K/V 分别是什么？为什么要除以 $\sqrt{d_h}$？因果掩码是干什么的？多头为什么有用？以及——为什么 softmax 的"和必须为 1"会一路影响到量化？

5.1 先建立直觉：一次查字典

假设你在读这句话，正在处理第 5 个词 "它"：

    "小明  把  书  给  了  它 ..."
      1    2   3   4   5   6

模型需要知道 "它"指的是什么。它该去看前面哪个词？

注意力做的事，就是让"它"这个位置去问前面所有位置一遍，然后按相关度加权取回信息。

   ┌─────────────────── 查字典的比喻 ───────────────────┐
   │                                                    │
   │   Query  (查询)  = 我想找什么                        │
   │        "它" 发出：我在找一个【可以被指代的名词】       │
   │                                                    │
   │   Key    (键)    = 我是什么，可以被谁找到             │
   │        "书" 挂出：我是个【名词、物品】                │
   │        "把" 挂出：我是个【介词】                      │
   │                                                    │
   │   Value  (值)    = 如果你选中我，你拿走什么           │
   │        "书" 交出：关于"书"的实际语义内容              │
   │                                                    │
   └────────────────────────────────────────────────────┘

   匹配度 = Query · Key   （内积越大越匹配）
   输出   = Σ 匹配度归一化后的权重 × Value

🔑 注意 Q/K/V 都是从【同一个】输入 $x$ 算出来的（这叫自注意力，self-attention）：
$$Q = xW_Q,\qquad K = xW_K,\qquad V = xW_V$$
同一个词，用三个不同的投影矩阵，扮演三个不同的角色。 这是最容易卡住的一点，多读两遍。

用 03 章的总线视角说：$W_Q, W_K, W_V$ 是三个不同的"读取器"，各自从残差流上读走它关心的那部分频道。

5.2 公式

$$\boxed{\ \text{Attention}(Q,K,V) = \text{softmax}!\left(\frac{QK^\top}{\sqrt{d_h}} + M\right)V\ }$$

逐块拆开（设 $L$ 个 token，每个头维度 $d_h$）：

① Q, K, V             形状都是 [L, d_h]

② S = Q Kᵀ            [L, d_h] × [d_h, L] → [L, L]
                      S[i][j] = 第 i 个词的 Query 和第 j 个词的 Key 的内积
                      ★ 这个 L×L 就是 [01 章] 说的 L² 代价的来源

③ S / √d_h            缩放（§5.3 讲为什么）

④ + M                 加因果掩码（§5.4）

⑤ A = softmax(S)      [L, L]，【每一行】和为 1
                      A[i][j] = 第 i 个词分给第 j 个词的注意力权重

⑥ O = A V             [L, L] × [L, d_h] → [L, d_h]
                      O[i] = Σ_j A[i][j] · V[j]，加权求和

一张图

              K1    K2    K3    K4    K5           V1  V2  V3  V4  V5
              │     │     │     │     │            │   │   │   │   │
    Q5 ───────●─────●─────●─────●─────●            │   │   │   │   │
              │     │     │     │     │            ▼   ▼   ▼   ▼   ▼
   内积:     3.2   0.1   8.7   1.4   2.0
              │     │     │     │     │
   /√d_h,softmax ↓  ↓     ↓     ↓     ↓
   权重:     0.05  0.01  0.85  0.03  0.06     ← 和 = 1
              └─────┴─────┴─────┴─────┴────→  加权求和  →  O5
                          ↑
                    "它" 主要看了第 3 个词 "书"

numpy 实现

def attention(Q, K, V, mask):
    d_h = Q.shape[-1]
    S = Q @ K.T / np.sqrt(d_h)        # [L, L]
    S = S + mask                       # 未来位置是 -inf
    A = softmax(S, axis=-1)            # 每行和为 1
    return A @ V                       # [L, d_h]

整个注意力就是这四行。 剩下的所有复杂性都是围绕"怎么让这四行更快、更省显存"。

5.3 为什么要除以 √d_h

这个细节值得单独讲，因为它是第 04 章 §4.5 softmax 饱和问题的源头。

假设 $q$ 和 $k$ 的每个分量独立、均值 0、方差 1。那么内积

$$q\cdot k = \sum_{i=1}^{d_h} q_i k_i$$

是 $d_h$ 个独立零均值项之和，所以

$$\mathbb{E}[q\cdot k] = 0,\qquad \text{Var}[q\cdot k] = d_h$$

标准差是 $\sqrt{d_h}$。

d_h = 128  →  内积的典型量级是 ±11
d_h = 512  →  内积的典型量级是 ±23

    不缩放的话，送进 softmax 的数值随 d_h 增大而增大
    → softmax([23, -5, 3]) ≈ [1.0, 0.0, 0.0]  几乎 one-hot
    → 【softmax 在饱和区的导数趋近 0】→ 学不动

除以 $\sqrt{d_h}$ 之后方差回到 1，内积的典型量级稳定在 ±1，与 $d_h$ 无关。

🔑 这就是那个 $\sqrt{d_h}$ 的全部原因：让 softmax 的输入尺度不随头维度变化。

⚠️ 但注意：这个论证依赖"$q,k$ 分量方差为 1"的假设，而训练中权重会漂移，假设会失效。这正是 04 章 §4.5 的 QK-Norm 存在的理由——它把这个假设从"希望成立"变成"强制成立"。

5.4 因果掩码：不许看未来

语言模型是自回归的：预测第 $i$ 个词时，只能看第 $1..i$ 个词。

但注意 §5.2 的 $S$ 是一个完整的 $L\times L$ 矩阵，它把每个位置和每个位置都算了。所以要把"未来"那一半屏蔽掉：

$$M_{ij} = \begin{cases} 0 & j \le i \quad(\text{允许看}) \ -\infty & j > i \quad(\text{禁止})\end{cases}$$

        j=1   j=2   j=3   j=4        softmax 后
 i=1  [  0   -inf  -inf  -inf ]     [ 1.0   0     0     0  ]
 i=2  [  0    0    -inf  -inf ]  →  [ 0.4  0.6    0     0  ]
 i=3  [  0    0     0    -inf ]     [ 0.2  0.3   0.5    0  ]
 i=4  [  0    0     0     0   ]     [ 0.1  0.2   0.3   0.4 ]
      下三角保留，上三角封死          exp(-inf) = 0

🔑 为什么用 $-\infty$ 而不是直接删掉：因为这样可以保持整个矩阵是规整的，一次矩阵乘就算完，GPU 效率最高。$\exp(-\infty)=0$，softmax 会自动把它们的权重变成 0。

📌 这个掩码是训练能并行的关键：一次前向，$L$ 个位置的 loss 全部算出来，而每个位置都只看到了它该看到的历史。没有掩码，训练就得像 RNN 一样一步一步来。

5.5 ⚠️ softmax 的一个致命性质：和必须为 1

这是全教程最重要的一条伏笔，请一定读。

$$\sum_j A_{ij} = 1 \qquad \text{恒成立，无法违反}$$

这意味着：

❌ 模型【没有】"这一层我什么都不想看"这个选项

    即使前面所有 token 对当前 token 都毫无意义，
    softmax 依然会把 100% 的权重分配出去
    → 强行往残差流里写入无用信息（噪声）

模型自己发明的解法：注意力沉降（attention sink）

实验观察（这已经是被反复复现的现象）：训练好的模型会把大量注意力权重倾倒在几个特定 token 上——通常是序列的第一个 token（比如 BOS 或第一个词）。

    真实模型的注意力分布（示意）：

    token:    <s>   今天   天气   很   好
    权重:    0.87  0.03  0.04  0.03  0.03
              ↑
      这个 token 语义上毫无价值，
      但拿走了 87% 的注意力

    → 它就是【垃圾桶】：模型把"我不想看任何东西"这个意图，
      编码成"那我全看第一个 token 好了"

为什么第一个 token：因为因果掩码下，它是唯一被所有位置都能看到的位置，是唯一可以充当全局垃圾桶的候选。

⚠️ 这条因果链会一路走到量化章

    softmax 和必须为 1
        ↓
    模型需要一个泄压阀 → attention sink
        ↓
    要让 sink token 稳定拿到 ~90% 权重，它的 K 向量需要有【异常大的数值】
        ↓
    ★ 这就是激活值离群值（outlier）的一个主要来源
        ↓
    离群值是低比特量化最大的敌人（一个 100 倍大的值会毁掉整个量化区间）
        ↓
    → SmoothQuant、旋转法、per-group 量化，全是为了对付它

📌 完整展开见 08 章 §attention sink 和 14 章 §14.6。

🔑 顺带解释一个现象：这一代模型普遍引入了"显式 sink 机制"（可学习的 sink token、或者给 softmax 加一个不参与输出的额外项）。理由就是上面这条链——与其让模型自己扭曲某个真实 token 的数值来当垃圾桶，不如直接给它一个官方垃圾桶。 openPangu 的 PAS（128 个可学习 KV / 层）在功能上就有这一层含义（见 08 章）。

5.6 多头注意力：为什么要拆

上面讲的是一个头。实际模型会把 $d$ 维拆成 $H$ 个头，每个头 $d_h = d/H$ 维，各自独立做一遍注意力，最后拼回来。

$$\text{MHA}(x) = \text{Concat}(\text{head}_1,\ldots,\text{head}_H)\,W_O,\qquad \text{head}_i = \text{Attention}(xW_Q^i,\ xW_K^i,\ xW_V^i)$$

       x  [L, 5120]
         │
    ┌────┼────┬────┬─── ... ───┐     拆成 H=40 个头，每个 d_h=128
    ▼    ▼    ▼    ▼           ▼
  head1 head2 head3 head4 ... head40    每个头独立算 QKᵀ、softmax、加权
    │    │    │    │           │
    └────┴────┴────┴─── ... ───┘
         │  Concat → [L, 5120]
         ▼
       W_O  [5120, 5120]           ← 唯一的"写回残差流"的矩阵
         │
         ▼  [L, 5120]

为什么多头比单头好

① 一个 softmax 只能表达【一种】关注模式
   因为权重和为 1，注意力被"抢"走给了 A，就分不给 B

   "它" 这个词可能同时需要：
        · 找语法上的主语        ← 头 3 负责
        · 找语义上的指代对象     ← 头 17 负责
        · 找最近的名词          ← 头 25 负责
   单头做不到，多头可以并行做

② 可解释性研究里发现了很具体的"专业头"：
   induction head（复制模式：看到 [A][B]...[A] 就预测 [B]）
   previous-token head（永远看前一个词）
   syntactic head（跟随句法依存关系）

⚠️ 多头【不增加参数量】：$H$ 个头的 $W_Q^i$ 拼起来正好是一个 $[d, d]$ 的矩阵。所以 01 章的 $4d^2$ 里，$H$ 完全不出现。多头是免费的表达力。

🔑 但多头【极大地增加了 KV cache】——每个头都要存自己的 K 和 V。这就是下一章的全部内容，以及 07 章 MQA/GQA/MLA 的起因。

5.7 计算复杂度和 FlashAttention

复杂度

计算量 显存（朴素实现）
$QK^\top$ $O(L^2 d_h)$ $O(L^2)$ ← 矩阵 $S$
softmax $O(L^2)$ $O(L^2)$
$AV$ $O(L^2 d_h)$ $O(L d_h)$

注意那个 $O(L^2)$ 的显存：

L = 128K，H = 40 个头，FP16：
    128K × 128K × 2 字节 × 40 头 = 1.3 TB     ← 完全不可能

FlashAttention：不要把 S 存下来

核心洞察：$S$ 只是个中间结果，最终只需要 $O$。那就【不要显式构造它】。

朴素实现：
    ① 算出完整的 S [L,L]      ← 写进显存
    ② softmax(S)               ← 读出来、算、再写回
    ③ A @ V                    ← 再读出来
    显存访问量 O(L²)，而且 HBM 读写是 GPU 上最慢的操作

FlashAttention：
    把 Q、K、V 切成小块，在 GPU 的【片上 SRAM】里
    一块一块地算，边算边用【在线 softmax】累积结果
    → S 从来没有完整存在过
    → 显存 O(L)，HBM 访问量降一个数量级

在线 softmax 是关键技巧——softmax 需要全局的最大值和求和，但可以用一个"running max + running sum"增量地维护：

# 处理新的一块 S_block 时
m_new = max(m_old, S_block.max())
l_new = l_old * exp(m_old - m_new) + exp(S_block - m_new).sum()
O_new = O_old * (l_old * exp(m_old - m_new) / l_new) + ...   # 重新缩放旧结果

🔑 FlashAttention 不改变任何数学，结果和朴素实现【逐比特相同】（在同精度下）。它纯粹是一个 IO 优化。

但它改变了整个领域的可能性：
① 长上下文从"显存不够"变成"只是慢" ② 【所有】新的注意力变体，必须能写出 Flash 版本的核函数，否则没有实用价值 → 这就是为什么 Kimi K3 要专门做 FlashKDA、MiniMax 的 MSA 要用块级结构 → 见 [08 章](08-高效注意力.md)

📌 注意 FlashAttention 只解决了显存，$O(L^2)$ 的计算量一点没少。计算量要靠稀疏化来减（08 章）。

5.9 本章小结

① 注意力 = 查字典。Q 是"我要找什么"，K 是"我是什么"，V 是"选中我拿走什么"
   Q/K/V 都从【同一个】x 用三个不同投影算出来
② 公式：softmax(QKᵀ/√d_h + M)V，四行代码
③ √d_h 是为了让 softmax 输入尺度不随 d_h 变化（内积方差 = d_h）
   QK-Norm 是把这个"希望"变成"强制"
④ 因果掩码用 -inf 屏蔽未来，保持矩阵规整 → 训练能并行
⑤ ★ softmax 和必须为 1 → 模型没有"不看"的选项 → attention sink
   → 巨大激活 → 离群值 → 低比特量化的头号敌人（一路通到 14 章）
⑥ 多头【不增加参数】，但【极大增加 KV cache】→ 下一章
⑦ FlashAttention 不改数学，只改 IO：不显式构造 S，显存从 O(L²) 降到 O(L)
   代价是：任何新注意力变体都必须能写出 Flash 核函数
