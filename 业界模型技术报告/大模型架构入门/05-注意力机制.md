# 05 · 注意力：从"查字典"讲到公式

> **这一章的目标**：讲清 Transformer 里唯一真正"新"的东西。
> 读完你应该能回答：Q/K/V 分别是什么？为什么要除以 $\sqrt{d_h}$？因果掩码是干什么的？多头为什么有用？以及——**为什么 softmax 的"和必须为 1"会一路影响到量化**？
> **读法**：本章的核心是 §5.2.3 那个 4×4 的手算例子。**那三张表请拿计算器按一遍**——按完之后 §5.3 到 §5.7 就只剩"怎么让这四行更快"这一件事了。

---

**本章关键词**（每个缩写第一次出现都给中英文全称，后面直接用缩写）

**Q / K / V**（Query / Key / Value，查询 / 键 / 值）—— 注意力的三个角色，全部由同一个输入 $x$ 经三个不同的投影矩阵算出。

**MHA**（Multi-Head Attention，多头注意力）—— 把 $d$ 维拆成 $H$ 个头各算一遍注意力，本章 §5.6 的主题。

**MQA**（Multi-Query Attention，多查询注意力）／ **GQA**（Grouped-Query Attention，分组查询注意力）／ **MLA**（Multi-head Latent Attention，多头潜在注意力）—— 三种省 KV cache 的头配置，详见 [07 章](07-MHA到MLA.md)。

**KV cache**（Key-Value Cache，键值缓存）—— 推理时把算过的 K、V 存下来复用，[06 章](06-KV-cache.md)整章在讲它。

**FLOP**（Floating-Point Operation，浮点运算次数）—— 本章数计算量的单位。**注意它不是 FLOPS**（每秒浮点运算次数，带 S 的是速率）。

**HBM**（High Bandwidth Memory，高带宽显存）—— GPU 的主存，H100 SXM5 是 80 GB / 3.35 TB/s。本章说"显存"都指它。

**SRAM**（Static Random-Access Memory，静态随机存储器）—— GPU 的片上存储，在 CUDA 里就是共享内存，H100 每个 SM（Streaming Multiprocessor，流式多处理器）最多 228 KB。

**FA**（FlashAttention，闪电注意力）—— 一族**精确**（不是近似）的注意力算子实现，§5.7 讲思路，实现细节见 [../../大模型算子开发/04-FlashAttention全系.md](../../大模型算子开发/04-FlashAttention全系.md)。

**BOS**（Begin Of Sequence，序列起始符）—— 放在句子最前面的特殊 token，§5.5 的"垃圾桶"通常就是它。

---

## 5.1 先建立直觉：一次查字典

假设你在读这句话，正在处理第 6 个词 **"它"**：

```
    "小明  把  书  给  了  它 ..."
      1    2   3   4   5   6
```

模型需要知道 **"它"指的是什么**。它该去看前面哪个词？

**注意力做的事，就是让"它"这个位置去问前面所有位置一遍，然后按相关度加权取回信息。**

**查字典的比喻**（这张表就是 Q/K/V 三个角色的全部含义）：

| 角色 | 一句话含义 | 在这个例子里 | 谁算出来的 |
|---|---|---|---|
| **Query**（查询） | 我想找什么 | "它" 发出：我在找一个**可以被指代的名词** | $Q = xW_Q$ |
| **Key**（键） | 我是什么，可以被谁找到 | "书" 挂出：我是个**名词、物品**；"把" 挂出：我是个**介词** | $K = xW_K$ |
| **Value**（值） | 如果你选中我，你拿走什么 | "书" 交出：关于"书"的实际语义内容 | $V = xW_V$ |

两步就完了：

```
匹配度 = Query · Key        内积越大越匹配
输出   = Σ (匹配度归一化后的权重) × Value
```

> 🔑 **注意 Q/K/V 都是从【同一个】输入 $x$ 算出来的**（这叫**自**注意力，self-attention）：
> $$Q = xW_Q,\qquad K = xW_K,\qquad V = xW_V$$
> **同一个词，用三个不同的投影矩阵，扮演三个不同的角色。** 这是最容易卡住的一点，多读两遍。

用 [03 章](03-残差流.md)的总线视角说：**$W_Q, W_K, W_V$ 是三个不同的"读取器"，各自从残差流上读走它关心的那部分频道；而 $W_O$ 是唯一那个"写回器"。** 一次注意力 = 三次读 + 一次写。

## 5.2 公式

$$\boxed{\ \text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_h}} + M\right)V\ }$$

### 5.2.1 逐块拆开

设 $L$ 个 token，每个头维度 $d_h$：

```
① Q, K, V             形状都是 [L, d_h]

② S = Q Kᵀ            [L, d_h] × [d_h, L] → [L, L]
                      S[i][j] = 第 i 个词的 Query 和第 j 个词的 Key 的内积
                      ★ 这个 L×L 就是 [01 章] 说的 L² 代价的来源

③ S / √d_h            缩放（§5.3 讲为什么）

④ + M                 加因果掩码（§5.4）

⑤ A = softmax(S)      [L, L]，【每一行】和为 1
                      A[i][j] = 第 i 个词分给第 j 个词的注意力权重

⑥ O = A V             [L, L] × [L, d_h] → [L, d_h]
                      O[i] = Σ_j A[i][j] · V[j]，加权求和
```

### 5.2.2 一张图：一个 query 问遍所有 key

下面这张图只画**一个** query（第 5 个词）问 5 个 key 的过程。注意它是**先算完全部内积，再一次性 softmax，再一次性加权求和**——不是边算边选。

```
    Q5
    |
    +-------+-------+-------+-------+
    |       |       |       |       |
    K1      K2      K3      K4      K5
    |       |       |       |       |
    s1      s2      s3      s4      s5        <- 第 1 步：内积 s_j = q5 . k_j
    |       |       |       |       |
    a1      a2      a3      a4      a5        <- 第 2 步：除 sqrt(d_h)，再一次性 softmax
    |       |       |       |       |
    V1      V2      V3      V4      V5
    |       |       |       |       |
    +-------+-------+-------+-------+  ->  O5  <- 第 3 步：O5 = Sum_j a_j * V_j
```

**三步的顺序不能调**：必须**先算完全部 5 个内积**，才能做 softmax（因为分母要用到全部 5 项）；softmax 出来之后才能加权求和。**这个"必须先看全"的依赖，就是 §5.7.4 在线 softmax 要绕开的东西。**

每一步的具体数字：

| 位置 $j$ | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 内积 $q_5\!\cdot\!k_j$ | 3.2 | 0.1 | 8.7 | 1.4 | 2.0 |
| 除 $\sqrt{d_h}$ 后（设 $d_h=64$，即除 8） | 0.40 | 0.01 | 1.09 | 0.18 | 0.25 |
| $\exp(\cdot)$ | 1.4918 | 1.0126 | 2.9668 | 1.1912 | 1.2840 |
| softmax 权重 $A_{5j}$（分母 7.9465） | 0.1877 | 0.1274 | **0.3734** | 0.1499 | 0.1616 |
| 最终取走的份额 | 18.8% | 12.7% | **37.3%** | 15.0% | 16.2% |

> 📌 **这张表有一个新手常见的错觉要破掉**：8.7 是 0.1 的 **87 倍**，但最后的权重只是 $0.3734 : 0.1274 \approx$ **2.9 倍**。**因为 softmax 看的是【差】不是【比】**，而且 $\sqrt{d_h}$ 这一除把差也压小了。真实模型里注意力分布常常比你想象的平——"某个头死盯一个词"是**训练出来的结果**，不是公式自带的。

### 5.2.3 ★ 一个能手算的例子：seq=4、$d_h$=4，三步全部算出来

这一节是全章的地基。**取 $L=4$（四个 token）、$d_h=4$，所有数字都是整数，可以拿计算器按完。** 换成 $L=4096$、$d_h=128$ 之后每一步**一模一样**，只是表格大一点。

四个 token 假装是 `小明 / 把 / 书 / 它`。先给 Q、K、V（真实模型里这三个是 $x$ 乘三个投影矩阵算出来的，这里直接给结果）：

| token | $q_i$ | $k_i$ | $v_i$ |
|---|---|---|---|
| 1 `小明` | `[1, 0, 0, 0]` | `[2, 0, 0, 0]` | `[1, 0, 0, 2]` |
| 2 `把` | `[0, 1, 0, 0]` | `[0, 2, 0, 0]` | `[0, 1, 0, 2]` |
| 3 `书` | `[1, 1, 0, 0]` | `[0, 0, 2, 0]` | `[0, 0, 1, 2]` |
| 4 `它` | `[0, 0, 2, 0]` | `[2, 2, 0, 0]` | `[1, 1, 1, 2]` |

> 📌 **怎么读这组数**：$k_3 = [0,0,2,0]$ 意思是"书"把自己挂在**第 3 号频道**上（[03 章](03-残差流.md)的总线视角）；而 $q_4 = [0,0,2,0]$ 意思是"它"**正好去第 3 号频道找东西**。所以下面 $S_{43}$ 一定是这一行里最大的——这是我故意造的，为了让"它 → 书"这条指代关系在数字上看得见。

**第一步：$S = QK^\top$。** $S_{ij} = q_i \cdot k_j$，一共 16 个内积，每个是 4 次乘 + 3 次加。

| $S_{ij}$ | $j$=1 | $j$=2 | $j$=3 | $j$=4 |
|---|---|---|---|---|
| $i$=1 `小明` | **2** | 0 | 0 | 2 |
| $i$=2 `把` | 0 | **2** | 0 | 2 |
| $i$=3 `书` | 2 | 2 | **0** | 4 |
| $i$=4 `它` | 0 | 0 | **4** | 0 |

验一个：$S_{34} = q_3 \cdot k_4 = [1,1,0,0]\cdot[2,2,0,0] = 1{\times}2 + 1{\times}2 = 4$ ✓

**第二步：缩放 + 掩码 + softmax。** $\sqrt{d_h} = \sqrt{4} = 2$，所以每个数除以 2；然后把 $j > i$ 的格子换成 $-\infty$（§5.4 讲为什么）。

| $S/2 + M$ | $j$=1 | $j$=2 | $j$=3 | $j$=4 |
|---|---|---|---|---|
| $i$=1 | 1 | $-\infty$ | $-\infty$ | $-\infty$ |
| $i$=2 | 0 | 0.5 | $-\infty$ | $-\infty$ |
| $i$=3 | 1 | 1 | 0 | $-\infty$ |
| $i$=4 | 0 | 0 | 2 | 0 |

逐行做 softmax（$\exp(-\infty) = 0$，所以被掩掉的格子权重是 0）。**第 4 行摊开给你看**：

```
exp(0) = 1        exp(0) = 1        exp(2) = 7.38906        exp(0) = 1
分母 = 1 + 1 + 7.38906 + 1 = 10.38906
a41 = 1 / 10.38906       = 0.09626
a42 = 1 / 10.38906       = 0.09626
a43 = 7.38906 / 10.38906 = 0.71123      <- "它" 把 71% 的注意力给了 "书"
a44 = 1 / 10.38906       = 0.09626
校验：0.09626 x 3 + 0.71123 = 1.00001   (四舍五入)
```

四行都算完，得到注意力矩阵 $A$：

| $A_{ij}$ | $j$=1 | $j$=2 | $j$=3 | $j$=4 | 行和 |
|---|---|---|---|---|---|
| $i$=1 | **1.00000** | 0 | 0 | 0 | 1.0 |
| $i$=2 | 0.26894 | **0.73106** | 0 | 0 | 1.0 |
| $i$=3 | 0.42232 | 0.42232 | 0.15536 | 0 | 1.0 |
| $i$=4 | 0.09626 | 0.09626 | **0.71123** | 0.09626 | 1.0 |

> 📌 **第 1 行是 1.00000，不是"因为它重要"**：第 1 个 token 只剩它自己可看，softmax 对一个元素做的结果必然是 1。**这是 §5.5 那条"和必须为 1"的第一个后果**——第一个 token 被迫 100% 看自己，模型没有"我先不看"的选项。

**第三步：$O = AV$。** 每一行输出 = 用该行的权重对 4 个 $v$ 做加权求和。把第 4 行摊开：

```
O4 = 0.09626 x [1,0,0,2]        ("小明")
   + 0.09626 x [0,1,0,2]        ("把")
   + 0.71123 x [0,0,1,2]        ("书")
   + 0.09626 x [1,1,1,2]        ("它" 自己)

第 1 维: 0.09626x1 + 0 + 0 + 0.09626x1 = 0.19252
第 2 维: 0 + 0.09626x1 + 0 + 0.09626x1 = 0.19252
第 3 维: 0 + 0 + 0.71123x1 + 0.09626x1 = 0.80749
第 4 维: (0.09626 + 0.09626 + 0.71123 + 0.09626) x 2 = 1 x 2 = 2.00000
```

四行输出：

| $O_i$ | 第 1 维 | 第 2 维 | 第 3 维 | 第 4 维 |
|---|---|---|---|---|
| $O_1$ | 1.00000 | 0 | 0 | 2.0 |
| $O_2$ | 0.26894 | 0.73106 | 0 | 2.0 |
| $O_3$ | 0.42232 | 0.42232 | 0.15536 | 2.0 |
| $O_4$ | 0.19252 | 0.19252 | **0.80749** | 2.0 |

**从这张表能直接读出三件事，每一件都是后面几章的伏笔：**

```
① O4 的第 3 维是 0.807，远大于另外两维
   -> "它" 确实把 "书" 的语义内容取回来了。指代消解在数值上就是这样发生的。

② 第 4 维【每一行都恰好是 2.0】
   因为我故意让四个 v 的第 4 维全等于 2，而权重和恒为 1，所以 Sum(a_j x 2) = 2。
   -> 注意力【永远输出 value 的一个凸组合】，绝对跑不出四个 v 张成的那个凸包。
   -> 这就是 §5.5 "和必须为 1" 的几何含义：注意力只会【内插】，不会【外推】。

③ 上三角全是 0，而且第 1 行只有一个非零
   -> 因果掩码下，有用的格子只占 (L+1)/(2L) ~ 一半。§5.4 会把这一半的账算出来。
```

**FLOP 对账**（顺手把 §5.7 的公式在小例子上验一次）：

| 步骤 | 通用公式 | 本例代入 | 手数一遍 |
|---|---|---|---|
| $S = QK^\top$ | $2 \cdot L^2 \cdot d_h$ | $2{\times}4^2{\times}4 = 128$ | 16 个内积 × (4 乘 + 3 加) = 112 |
| $O = AV$ | $2 \cdot L^2 \cdot d_h$ | $2{\times}4^2{\times}4 = 128$ | 16 个输出元素 × (4 乘 + 3 加) = 112 |
| softmax | $\approx 5 \cdot L^2$ | $\approx 80$ | 忽略不计 |

> 📌 **为什么公式给 128 而手数是 112**：业界的 FLOP 口径把一次"乘加"（multiply-add）算成 **2 FLOP**，也就是按 $2\cdot m \cdot n \cdot k$ 数矩阵乘，**不去扣掉"$n$ 个数求和只需 $n-1$ 次加法"这一点零头**。$L$ 大起来之后这点差别可以忽略（$112/128 = 87.5\%$，$d_h=128$ 时是 $255/256 = 99.6\%$）。**全教程和 [../../大模型算子开发/02-屋顶线与性能剖析.md](../../大模型算子开发/02-屋顶线与性能剖析.md) 都用 $2mnk$ 这个口径**，否则两边的数字对不上。

### 5.2.4 numpy 实现

```python
def attention(Q, K, V, mask):
    d_h = Q.shape[-1]
    S = Q @ K.T / np.sqrt(d_h)        # [L, L]
    S = S + mask                       # 未来位置是 -inf
    A = softmax(S, axis=-1)            # 每行和为 1
    return A @ V                       # [L, d_h]
```

**整个注意力就是这四行。** 剩下的所有复杂性都是围绕"怎么让这四行更快、更省显存"。

## 5.3 为什么要除以 √d_h

这个细节值得单独讲，因为它是[第 04 章 §4.5](04-归一化.md) softmax 饱和问题的源头。

**假设** $q$ 和 $k$ 的每个分量独立、均值 0、方差 1。那么内积

$$q\cdot k = \sum_{i=1}^{d_h} q_i k_i$$

是 $d_h$ 个独立零均值项之和，所以

$$\mathbb{E}[q\cdot k] = 0,\qquad \text{Var}[q\cdot k] = d_h$$

**标准差是 $\sqrt{d_h}$。** 这一步可以用最小的例子验：设 $q,k$ 的每个分量都是随机的 $\pm 1$，那么 $q\cdot k$ 就是 $d_h$ 个随机 $\pm 1$ 的和，方差显然是 $d_h$。

**把这件事对 softmax 的后果列成一张表。** 场景：三个候选，最高分比中间分高一个标准差，中间分比最低分再高一个标准差。

| $d_h$ | 内积标准差 $\sqrt{d_h}$ | **不缩放**：$\text{softmax}([+\sigma, 0, -\sigma])$ | **缩放后**：$\text{softmax}([+1, 0, -1])$ |
|---|---|---|---|
| 4 | 2.00 | `[0.867, 0.117, 0.016]` | `[0.665, 0.245, 0.090]` |
| 64 | 8.00 | `[0.9997, 3.4e-4, 1.1e-7]` | `[0.665, 0.245, 0.090]` |
| 128 | 11.31 | `[0.99999, 1.2e-5, ~0]` | `[0.665, 0.245, 0.090]` |
| 512 | 22.63 | `[1.0, 1.5e-10, ~0]` | `[0.665, 0.245, 0.090]` |

> 🔑 **看右边那一列：四行完全一样。这就是 $\sqrt{d_h}$ 的全部作用**——**让 softmax 的输入尺度不随头维度变化**，从而让"初始化、学习率、warmup"这一整套超参可以跨模型尺寸复用。
>
> 而左边那一列是在说：不缩放的话，$d_h=128$ 时 softmax 已经**几乎是 one-hot**（$0.99999$），**导数趋近 0，这个头当场学不动了**。

> ⚠️ 但注意：这个论证依赖"$q,k$ 分量方差为 1"的假设，而**训练中权重会漂移，假设会失效**。这正是 [04 章 §4.5](04-归一化.md) 的 **QK-Norm** 存在的理由——它把这个假设从"希望成立"变成"强制成立"。
>
> ⚠️ 另外注意 §5.2.3 那个 $d_h=4$ 的手算例子**不满足这个假设**（那里的 $q,k$ 是我手挑的稀疏整数向量，内积落在 0–4 而不是均值 0）。小例子是为了能手算，不是为了符合统计假设。

## 5.4 因果掩码：不许看未来

语言模型是**自回归**的：预测第 $i$ 个词时，只能看第 $1..i$ 个词。

**但注意 §5.2 的 $S$ 是一个完整的 $L\times L$ 矩阵**，它把每个位置和每个位置都算了。所以要把"未来"那一半屏蔽掉：

$$M_{ij} = \begin{cases} 0 & j \le i \quad(\text{允许看}) \\ -\infty & j > i \quad(\text{禁止})\end{cases}$$

```
        j=1   j=2   j=3   j=4        softmax 后
 i=1  [  0   -inf  -inf  -inf ]     [ 1.0   0     0     0  ]
 i=2  [  0    0    -inf  -inf ]  -> [ 0.4  0.6    0     0  ]
 i=3  [  0    0     0    -inf ]     [ 0.2  0.3   0.5    0  ]
 i=4  [  0    0     0     0   ]     [ 0.1  0.2   0.3   0.4 ]
      下三角保留，上三角封死          exp(-inf) = 0
```

> 🔑 **为什么用 $-\infty$ 而不是直接删掉**：因为这样可以**保持整个矩阵是规整的**，一次矩阵乘就算完，GPU 效率最高。$\exp(-\infty)=0$，softmax 会自动把它们的权重变成 0。
>
> 📌 **这个掩码是训练能并行的关键**：一次前向，$L$ 个位置的 loss 全部算出来，而每个位置都只看到了它该看到的历史。**没有掩码，训练就得像 RNN 一样一步一步来。**

### 5.4.1 ⚠️ 掩码省掉的那一半，到底算不算在账里

有用的格子是下三角，共 $L(L+1)/2$ 个，占满矩阵的比例是 $\dfrac{L+1}{2L}$：

| $L$ | 有用格子数 | 占 $L^2$ 的比例 |
|---|---|---|
| 4（§5.2.3 的例子） | 10 | **62.5%** |
| 128 | 8,256 | 50.4% |
| 4,096 | 8,390,656 | 50.01% |
| 131,072（128K） | 8,590,000,128 | 50.0004% |

> ⚠️ **这是一个非常容易搞错口径的地方，一定要分清两件事**：
>
> ```
> 【算法上】因果掩码让一半的格子变成 0，所以理论上 QKᵀ 和 PV 各能省掉约一半的 FLOP
>          -> FlashAttention-2 确实做了这个优化：完全在上三角的块【整块跳过】
>             （见 [../../大模型算子开发/04-FlashAttention全系.md] §4.4.4）
>
> 【记账上】业界通用的训练 FLOP 公式 6N + 12·L·s·h 里的 12·L·s·h 这一项，
>          数的是【完整的 L×L 矩阵】，没有除以 2。
>          -> 所以那个公式是【上界】。你要是自己也除一次 2，就和别人的 MFU 对不上了。
> ```
>
> **口径不统一是这一带最常见的"数字打架"来源。** 本教程统一：**讲算法省了多少，说"约一半"；报训练总 FLOP，用不打折的 $12\cdot L\cdot s\cdot h$。** §5.7.3 会把这笔账完整走一遍。

## 5.5 ⚠️ softmax 的一个致命性质：和必须为 1

**这是全教程最重要的一条伏笔，请一定读。**

$$\sum_j A_{ij} = 1 \qquad \text{恒成立，无法违反}$$

**这意味着**：

```
X 模型【没有】"这一层我什么都不想看"这个选项

    即使前面所有 token 对当前 token 都毫无意义，
    softmax 依然会把 100% 的权重分配出去
    -> 强行往残差流里写入无用信息（噪声）
```

§5.2.3 那张输出表的第 4 维已经把这件事画出来了：**四个 $v$ 的第 4 维都是 2，于是输出的第 4 维在每一行都恰好是 2.0，无论权重怎么分配。注意力只能在 value 张成的凸包里【内插】，不能【外推】，也不能输出 0。**

### 5.5.1 模型自己发明的解法：注意力沉降（attention sink）

**实验观察**（这已经是被反复复现的现象）：训练好的模型会把**大量注意力权重倾倒在几个特定 token 上**——通常是**序列的第一个 token**（比如 BOS 或第一个词）。

```
    真实模型的注意力分布（示意值，不是实测）：

    token:   [BOS]  今天   天气   很   好
    权重:    0.87   0.03  0.04  0.03  0.03
             ^^^^^
      这个 token 语义上毫无价值，
      但拿走了 87% 的注意力

    -> 它就是【垃圾桶】：模型把"我不想看任何东西"这个意图，
      编码成"那我全看第一个 token 好了"
```

**为什么第一个 token**：因为因果掩码下，**它是唯一被所有位置都能看到的位置**，是唯一可以充当全局垃圾桶的候选。

### 5.5.2 ⚠️ 这条因果链会一路走到量化章 —— 而且中间那一步可以算出来

先把链条摆出来：

```
    softmax 和必须为 1
        |
    模型需要一个泄压阀 -> attention sink
        |
    要让 sink token 稳定拿到 ~90% 权重，它的 K 向量需要有【异常大的数值】
        |
    ★ 这就是激活值离群值（outlier）的一个主要来源
        |
    离群值是低比特量化最大的敌人（一个 100 倍大的值会毁掉整个量化区间）
        |
    -> SmoothQuant、旋转法、per-group 量化，全是为了对付它
```

**"异常大的数值"到底要多大？这一步可以算出来，不用信我。** 设序列长 4096，我们要让 sink 拿到 90% 的权重，剩下 4095 个 token 平分 10%（即它们的缩放后 logit 都相等，记为 0）。设 sink 的缩放后 logit 是 $\Delta$：

```
0.9 = exp(Delta) / ( exp(Delta) + 4095 x exp(0) )

=>  exp(Delta) x (1 - 0.9) = 0.9 x 4095
=>  exp(Delta) = 0.9 x 4095 / 0.1 = 36855
=>  Delta = ln(36855) = 10.5
```

| 要的 sink 权重 | 需要的缩放后 logit 差 $\Delta$（$L$=4096） | 对比：§5.3 说正常 logit 的量级是 ±1 |
|---|---|---|
| 50% | $\ln(4095) = 8.3$ | 高 8 倍 |
| 90% | $\ln(36855) = 10.5$ | 高 **10 倍** |
| 99% | $\ln(405405) = 12.9$ | 高 13 倍 |

> 🔑 **这张表就是那条因果链的定量版本**：$\sqrt{d_h}$ 好不容易把 logit 压到 ±1 的量级（§5.3），而 sink 机制**要求某一个 logit 顶到 +10 以上**。logit $= q\cdot k/\sqrt{d_h}$，$q$ 是正常量级，那唯一的出路就是 **$k_{\text{sink}}$ 的数值比正常的 $k$ 大一个数量级**。
> **模型不是"不小心"产生了离群值，是被 softmax 的结构逼出来的。**

📌 完整展开见 [08 章 §8.6](08-高效注意力.md)（Attention Sink：所有稀疏方案的必备补丁）和 [14 章 §14.6](14-量化.md)（真正的敌人：离群值）。

> 🔑 **顺带解释一个现象**：**这一代模型普遍引入了"显式 sink 机制"**（可学习的 sink token、或者给 softmax 加一个不参与输出的额外项）。理由就是上面这条链——**与其让模型自己扭曲某个真实 token 的数值来当垃圾桶，不如直接给它一个官方垃圾桶。** openPangu 的 **PAS（128 个可学习 KV / 层）**在功能上就有这一层含义（见 [08 章](08-高效注意力.md)）。

## 5.6 多头注意力（MHA）：为什么要拆

上面讲的是**一个头**。实际模型会把 $d$ 维拆成 $H$ 个头，每个头 $d_h = d/H$ 维，**各自独立做一遍注意力**，最后拼回来。

$$\text{MHA}(x) = \text{Concat}(\text{head}_1,\ldots,\text{head}_H)\,W_O,\qquad \text{head}_i = \text{Attention}(xW_Q^i,\ xW_K^i,\ xW_V^i)$$

```
   x  [L, 5120]
   |
   |  (1) 三个投影：W_Q / W_K / W_V，各 [5120, 5120]
   v
   Q, K, V  [L, 5120]  ——按最后一维切成 40 段，每段 128 维
   |
   +-- head 1  : Q[:, 0:128]      K[:, 0:128]      V[:, 0:128]      独立做一遍注意力
   +-- head 2  : Q[:, 128:256]    K[:, 128:256]    V[:, 128:256]    独立做一遍
   +-- head 3  : Q[:, 256:384]    ...                               独立做一遍
   +-- ...
   +-- head 40 : Q[:, 4992:5120]  ...                               独立做一遍
   |
   |  (2) Concat：40 个 [L, 128] 的输出拼回 [L, 5120]
   v
   W_O  [5120, 5120]        <- 唯一那个"写回残差流"的矩阵
   |
   v
   输出  [L, 5120]
```

> 📌 **"切成 40 段"是理解多头最省事的说法**：投影矩阵**没有** 40 份，就是一份 $[5120, 5120]$；多头只是**把输出的 5120 维按 128 一组分块，每块各自算注意力**。所以下面那条"不增加参数"是显然的。

### 5.6.1 形状与字节账：多头贵在哪、不贵在哪

以 $d=5120$、$H=40$、$d_h=128$、$L=4096$、BF16（2 字节）为例，**一层**：

| 对象 | 形状 | 元素数 | BF16 字节 | 随 $H$ 变吗 |
|---|---|---|---|---|
| 输入 $x$ | $[L, d]$ | 20.97 M | 41.9 MB | ❌ 不变 |
| $Q$ / $K$ / $V$ 各一份 | $[L, d]$ | 20.97 M | 41.9 MB | ❌ 不变 |
| $W_Q,W_K,W_V,W_O$ 参数合计 | $4d^2$ | **104.9 M** | 210 MB | ❌ **不变** |
| 单个头的 $S$ | $[L, L]$ | 16.78 M | 33.6 MB | — |
| **全部头的 $S$** | $[H, L, L]$ | **671 M** | **1.342 GB** | ✅ **正比于 $H$** |
| KV cache（每 token） | $2\,H\,d_h$ | 10,240 | **20 KiB** | ✅ **正比于 $H$** |

> ⚠️ **多头【不增加参数量】**：$H$ 个头的 $W_Q^i$ 拼起来正好是一个 $[d, d]$ 的矩阵。所以 [01 章](01-鸟瞰全景.md)的 $4d^2$ 里，$H$ 完全不出现。**多头是免费的表达力。**
>
> ⚠️ **但多头【极大地增加了中间矩阵和 KV cache】**：表里那 1.342 GB 是 $41.9\,\text{MB} \times 32$，倍数正好是 $L/d_h = 4096/128 = 32$。**序列越长，这个倍数越大**，这就是 §5.7 FlashAttention 要解决的问题。而 20 KiB/token 的 KV cache **就是下一章的全部内容**，也是 [07 章](07-MHA到MLA.md) MQA / GQA / MLA 的起因。

> ⚠️ **一个高频算错的地方**：KV cache 的正确口径是**每 token 每层 $= 2 \times n_{kv} \times d_h \times \text{字节数}$**，$n_{kv}$ 是**KV 头数**，不是 $d_{\text{model}}$。
> ```
> MHA（H_kv = 40, d_h = 128）：2 x 40 x 128 x 2 = 20,480 字节 = 20 KiB   ✓
>   这时恰好等于 2 x d_model x 2 字节，因为 H_kv x d_h = d_model
>
> GQA-16（MiniMax M3：64 个 query 头 / 4 个 KV 头，d_h=128）：
>   正确：  2 x  4 x 128 x 2 =  2,048 字节 = 2 KiB
>   算错：  2 x 6144(d_model) x 2 = 24,576 字节 = 24 KiB    <- 高估 12 倍！
> ```
> **一旦用了 GQA / MQA / MLA，$H_{kv}\times d_h \neq d_{\text{model}}$，套 MHA 的 $d_{\text{model}}$ 公式会高估好几倍到十几倍。** [06 章 §6.3](06-KV-cache.md) 用的就是正确口径。

### 5.6.2 为什么多头比单头好

```
(1) 一个 softmax 只能表达【一种】关注模式
    因为权重和为 1，注意力被"抢"走给了 A，就分不给 B

    "它" 这个词可能同时需要：
         - 找语法上的主语        <- 头 3 负责
         - 找语义上的指代对象     <- 头 17 负责
         - 找最近的名词          <- 头 25 负责
    单头做不到，多头可以并行做

(2) 可解释性研究里发现了很具体的"专业头"：
    induction head（复制模式：看到 [A][B]...[A] 就预测 [B]）
    previous-token head（永远看前一个词）
    syntactic head（跟随句法依存关系）
```

> 📌 **用 §5.2.3 的例子说第 (1) 条**：那里 $O_4$ 的三个语义维是 `[0.19, 0.19, 0.81]`——**"它"已经把 81% 的份额给了"书"，就只剩 19% 分给"小明"和"把"。** 如果这一层同时还想知道"'它'的主语是谁"，单头无解，必须再开一个头。**"权重和为 1"是多头存在的直接理由。**

## 5.7 计算复杂度和 FlashAttention

### 5.7.1 逐块的 FLOP 与显存口径

把 §5.2.1 的六步逐行记账。设 $L$ 个 token、$H$ 个头、$d_h$ 每头维度、$d = H\cdot d_h$，**一层、一条序列、前向**：

| 步骤 | 每头 FLOP | **全部 $H$ 头合计** | 中间结果显存 |
|---|---|---|---|
| $Q,K,V$ 三个投影 | — | $3\times 2Ld^2 = 6Ld^2$ | $3\cdot L\cdot d$ |
| $S = QK^\top$ | $2L^2 d_h$ | $\boxed{2L^2 d}$ | $H\cdot L^2$ ← **矩阵 $S$** |
| softmax | $\approx 5L^2$ | $\approx 5HL^2$ | 可原地覆盖 $S$ |
| $O = AV$ | $2L^2 d_h$ | $\boxed{2L^2 d}$ | $L\cdot d$ |
| $W_O$ 投影 | — | $2Ld^2$ | $L\cdot d$ |
| **注意力核心两项合计** | | **$4L^2 d$** | |
| **四个投影合计** | | **$8Ld^2$** | |

> 🔑 **要记的就是加粗的两个式子：$QK^\top$ 和 $PV$ 各 $2\cdot L^2\cdot d$。** 注意 $H$ 不出现——因为每头是 $2L^2 d_h$，乘上 $H$ 个头正好补成 $d$。**多头对 FLOP 是中性的**（§5.6.1 已经说过它对参数也中性）。
>
> ⚠️ **这两项都是"不打因果折扣"的口径**（§5.4.1）。真实 kernel 会跳过上三角的块，实际算出来**约一半**。

**两项谁大？比值是 $\dfrac{4L^2d}{8Ld^2} = \dfrac{L}{2d}$**，也就是说**序列长到 $L = 2d$ 时，注意力核心才和四个投影打平。** 代入 Kimi K3 的 $d = 7168$（打平点 $L = 14336$）：

| 序列长 $L$ | 注意力核心 $4L^2d$ | 四个投影 $8Ld^2$ | 核心/投影 $=L/2d$ | 核心占一层的 |
|---|---|---|---|---|
| 4,096 | 481 GFLOP | 1,684 GFLOP | 0.286 | 22% |
| 16,384 | 7,697 GFLOP | 6,733 GFLOP | 1.14 | 53% |
| 131,072（128K） | 492,576 GFLOP | 53,875 GFLOP | **9.14** | **90%** |

> 📌 **这张表解释了一个常被问倒的问题："$L^2$ 到底什么时候才真的疼？"**
> **答：短上下文根本不疼**（4K 时注意力只占一层 22%，是那四个 $d\times d$ 投影在干活）。**是 128K 之后它吃掉 90%，才变成非改不可的事。** 这就是为什么 [08 章](08-高效注意力.md)那些稀疏方案全是**为长上下文**发明的，而 2020 年前后大家并不觉得注意力贵。

### 5.7.2 显存账：那个 $O(L^2)$ 才是真正先崩的

$S$ 的形状是 $[H, L, L]$，**它比输入 $x$ 大 $L/d_h$ 倍**（§5.6.1 已经验过：4096/128 = 32 倍）。

| 序列长 $L$ | $S$ 一层的字节（$H$=40，BF16，$B$=1） | 换成 GiB | 备注 |
|---|---|---|---|
| 4,096 | 1.342 GB | 1.25 GiB | 一层就吃掉 80 GB 卡的 1.6% |
| 32,768 | 85.9 GB | 80 GiB | **一层填满一整块 H100** |
| 131,072（128K） | 1.374 TB | **1.25 TiB** | 完全不可能 |

> ⚠️ **口径三件事，别混**：
> ```
> (1) 上表是【一层、batch=1】的量。乘上层数或 batch 就更离谱。
> (2) GB 是十进制（10^9 字节），GiB 是二进制（2^30 字节），差 7.4%。
>     131072^2 x 2 x 40 = 1,374,389,534,720 字节 = 1.374 TB = 1.25 TiB。两个都对，别混着说。
> (3) 这是【朴素实现】才需要的显存。FlashAttention 之后这一行根本不存在——见下。
> ```

### 5.7.3 把注意力放进训练总账：$6N + 12\,L_{\text{layer}}\,s\,h$

[01 章 §1.5](01-鸟瞰全景.md) 给过训练的经验公式。这里把它补全，并且说清每一项的口径：

$$\text{每 token 训练 FLOP} \;=\; \underbrace{6N}_{\text{参数那部分}} \;+\; \underbrace{12\,L_{\text{layer}}\cdot s\cdot h}_{\text{注意力的 }L^2\text{ 那部分}}$$

```
6N  的来头：  2N 前向  +  4N 反向（反向是前向的 2 倍：要算输入的梯度 + 权重的梯度）
              ⚠️ 不含优化器更新（AdamW 那几步、Muon 的 Newton-Schulz 都不在里面）
              ⚠️ 不含重计算（做了 activation checkpointing 就要再加一遍前向，见 [../../大模型算子开发/02-屋顶线与性能剖析.md] §2.6.3）

12·L·s·h 的来头：
              一层一个 token 的注意力核心 = 4·s·d（就是 §5.7.1 的 4s²d 除以 s）
              前向 + 反向 = ×3
              => 每层每 token 12·s·h，再乘 L 层
              ⚠️ 这里的 L 是【层数】，s 是【序列长】，h 是【hidden dim】——三个字母别看串
              ⚠️ 不打因果折扣（§5.4.1）
```

代入一个 **$N$ = 70B、$L_{\text{layer}}$ = 80、$h$ = 8192** 的模型（$6N$ = 420 GFLOP / token）：

| 序列长 $s$ | $12\,L\,s\,h$（每 token） | 占 $6N$ 的比例 | 总计 |
|---|---|---|---|
| 4,096 | 32.2 GFLOP | **+7.7%** | 452 GFLOP |
| 8,192 | 64.4 GFLOP | **+15.3%** | 484 GFLOP |
| 32,768 | 257.7 GFLOP | +61.4% | 678 GFLOP |
| 131,072（128K） | 1,030.8 GFLOP | +245% | 1,451 GFLOP |

自己验算 $s$=8192 那一行：$12 \times 80 \times 8192 \times 8192 = 6.442\times 10^{10}$，除以 $4.2\times 10^{11}$ = 15.3% ✓

> 🔑 **这张表的用法**：**报 MFU（Model FLOPs Utilization，模型算力利用率）时，$s \le 8\text{K}$ 用光 $6N$ 误差在 15% 以内，勉强能接受；$s \ge 32\text{K}$ 还只用 $6N$ 就是在虚报效率**（把分子少算了 60%，MFU 被低估同样的幅度）。
> 完整的 MFU 推演见 [../../大模型算子开发/02-屋顶线与性能剖析.md](../../大模型算子开发/02-屋顶线与性能剖析.md) §2.6。

### 5.7.4 FlashAttention：不要把 $S$ 存下来

**核心洞察：$S$ 只是个中间结果，最终只需要 $O$。那就【不要显式构造它】。**

```
朴素实现：
    (1) 算出完整的 S [L,L]      <- 写进 HBM
    (2) softmax(S)              <- 从 HBM 读出来、算、再写回
    (3) A @ V                   <- 再从 HBM 读出来
    HBM 访问量 O(L²)，而 HBM 读写是 GPU 上最慢的操作

FlashAttention：
    把 Q、K、V 切成小块，在 GPU 的片上 SRAM 里一块一块地算，
    边算边用【在线 softmax】累积结果
    -> S 从来没有完整存在过
    -> 中间结果显存从 O(L²) 降到 O(L)，HBM 访问量降一个数量级
```

**在线 softmax** 是关键技巧——softmax 需要全局的最大值和求和，但可以用一个"running max + running sum"增量地维护：

```python
# 处理新的一块 S_block 时
m_new = max(m_old, S_block.max())
l_new = l_old * exp(m_old - m_new) + exp(S_block - m_new).sum()
O_new = O_old * (l_old * exp(m_old - m_new) / l_new) + ...   # 重新缩放旧结果
```

> ⚠️ **一处很多材料（包括本教程旧版）说错的地方，这里改过来**：
> ```
> ✅ 正确：FlashAttention 在【数学上】和朴素实现恒等，不是近似算法。
>          它不丢任何一项，不做任何截断。
> ❌ 错误："结果和朴素实现逐比特相同（bitwise identical）"。
>          浮点加法【不满足结合律】，而 FA 改变了求和的顺序和分块方式，
>          所以最后几位尾数通常是【不同】的。
>          -> 实践后果：换 FA 版本 / 换分块大小 / 换 GPU，loss 曲线会有末位差异；
>             这不是 bug。要"bitwise 一致"必须锁死实现，见 [../../大模型算子开发/11-训推一致性算子层.md]。
> ```

> 🔑 **它改变了整个领域的可能性**：
> ```
> (1) 长上下文从"显存不够"变成"只是慢"
> (2) 【所有】新的注意力变体，必须能写出 Flash 版本的核函数，否则没有实用价值
>     -> 这就是为什么 Kimi K3 要专门做 FlashKDA、MiniMax 的 MSA 要用块级结构
>     -> 见 [08 章](08-高效注意力.md)
> ```

> 📌 注意 FlashAttention **只解决了显存和访存**，$O(L^2)$ 的**计算量一点没少**（§5.7.1 那 $4L^2d$ 该算的照算）。计算量要靠稀疏化来减（[08 章](08-高效注意力.md)）。

> 📌 **算子实现侧不在本章重复**。在线 softmax 的 6 元素逐块手算表、FA1/FA2/FA3 三代各改了哪一层、块开多大、causal 怎么整块跳过、反向为什么重计算连时间都省——全部在 [../../大模型算子开发/04-FlashAttention全系.md](../../大模型算子开发/04-FlashAttention全系.md)（§4.2 在线 softmax、§4.3–§4.5 三代、§4.4.4 causal、§4.6 反向）。**本章只需要你接受"$S$ 可以不落地"这一件事。**

**注意力的这个基本公式，五家一个字都没改。** 改的全是三件事：

(1) 怎么减少【存】的量（KV cache）   -> [06](06-KV-cache.md) / [07](07-MHA到MLA.md) 章

(2) 怎么减少【算】的量（L² 项）      -> [08](08-高效注意力.md) 章

     RoPE / NoPE
```

## 5.9 本章小结

```
(1) 注意力 = 查字典。Q 是"我要找什么"，K 是"我是什么"，V 是"选中我拿走什么"
    Q/K/V 都从【同一个】x 用三个不同投影算出来
(2) 公式：softmax(QKᵀ/√d_h + M)V，四行代码
    ★ §5.2.3 的 4×4 手算例子是全章地基：S -> 缩放掩码 softmax -> AV，三张表算到底
(3) √d_h 是为了让 softmax 输入尺度不随 d_h 变化（内积方差 = d_h）
    不缩放时 d_h=128 的 softmax 已经是 0.99999 的准 one-hot，当场学不动
    QK-Norm 是把"分量方差为 1"这个希望变成强制
(4) 因果掩码用 -inf 屏蔽未来，保持矩阵规整 -> 训练能并行
    ⚠️ 算法上省约一半 FLOP，但训练总账公式 12·L·s·h 不打这个折扣，口径别混
(5) ★ softmax 和必须为 1 -> 注意力只能【内插】不能【外推】-> 模型没有"不看"的选项
    -> attention sink -> 要 90% 权重就要 logit 差 +10.5，而正常 logit 只有 ±1
    -> 巨大激活 -> 离群值 -> 低比特量化的头号敌人（一路通到 [14 章 §14.6]）
(6) 多头【不增加参数】（4d² 里没有 H），但【S 和 KV cache 都正比于 H】
    KV cache 每 token 每层 = 2 × n_kv × d_h × 字节数
    ⚠️ 用 d_model 硬套 MHA 公式去算 GQA，会高估好几倍到十几倍
(7) FLOP：QKᵀ 与 PV 各 2·L²·d；四个投影合计 8·L·d²；比值 = L/(2d)
    -> 4K 时注意力只占一层 22%，128K 时占 90%。L² 是【长上下文】的病，不是所有场景的病
(8) 显存：S 是 [H,L,L]，128K / 40 头 / BF16 一层就是 1.374 TB（= 1.25 TiB）
    FlashAttention 不改数学（但也不是 bitwise 相同），只改 IO：
    不显式构造 S，中间显存 O(L²) -> O(L)
    代价是：任何新注意力变体都必须能写出 Flash 核函数
```

**下一章是本教程第二关键的一章**：KV cache。看完你就懂了为什么五家全在改注意力。
