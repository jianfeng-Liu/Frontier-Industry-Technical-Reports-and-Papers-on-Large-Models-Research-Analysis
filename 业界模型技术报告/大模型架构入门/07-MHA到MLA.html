07 · 省 KV 的四条路：MHA → MQA → GQA → MLA

这一章的目标：回答 06 章四个下手点里的第 ② 个——每层到底要存多少东西。
读完你应该能回答：MQA/GQA 为什么会掉效果？MLA 的低秩压缩是怎么做到"存得少还不掉效果"的？矩阵吸收是什么魔法？以及一个很多人讲不清的问题：为什么 RoPE 和 MLA 天然冲突，必须做 decoupled RoPE？

📖 先把这四个缩写的全称和中文列出来（本章从头到尾就在讲它们）：

缩写 全称 中文 一句话
MHA Multi-Head Attention 多头注意力 原版。每个头一套自己的 K、V
MQA Multi-Query Attention 多查询注意力 所有头共用一套 K、V
GQA Grouped-Query Attention 分组查询注意力 折中：分几组，组内共用
MLA Multi-head Latent Attention 多头潜在注意力 不共用，改成压缩成低维再存

记忆线索：前三个在讨论"几个头共用一套 KV"，只有 MLA 换了个思路——"存之前先压缩"。

7.1 问题重述

回忆 05 章的多头注意力：$H$ 个头，每个头有自己的 $K^i, V^i$，都是 $d_h$ 维。

$$\text{每 token 每层要存：} \quad 2\times H \times d_h = 2d \quad\text{个数}$$

d = 5120，BF16：  2 × 5120 × 2 字节 = 20 KB / token / 层

这一章的四种方案，就是把这个 $2d$ 变小的四种办法。

MQA/GQA 为什么会掉效果

回忆 05 章 §5.6：多头的价值在于不同的头可以关注不同的模式。

MHA：  头 3 的 K 专门编码"我是主语"，头 17 的 K 专门编码"我是物品"
       → 每个头有【自己的一套语义空间】

MQA：  所有 8 个头共用同一份 K
       → K 必须同时满足所有头的需求 → 被迫编码一个"通用"的、模糊的表示
       → 头之间的【专业化被削弱了】

GQA：  折中，组内共享。组数越多越接近 MHA

✅ MiniMax M3 是五家里唯一还在用 GQA 的：64 个 query 头 / 4 个 KV 头（GQA-16，即 16 个 query 共享一组 KV）。

⚠️ 这不是"落后"。M3 只有 230B / 10B 激活，走的是小而快的路线，GQA 的工程成熟度和算子支持是最好的。MLA 需要重写一整套推理核函数。

7.3 MLA：核心思路是低秩压缩

直觉

观察：MHA 存的 $2d$ 个数里有大量冗余——$K$ 和 $V$ 都是从同一个 $x$（$d$ 维）线性投影出来的，信息量上限就是 $d$ 维，却存了 $2d$。

那就不存 $K$ 和 $V$，存一个能重建出它们的【压缩表示】。

    x  [d=5120]
     │
     │  W^DKV：向下投影（Down-projection）
     ▼
    c  [512]      ★★★ 只存这个！
     │
     ├──── W^UK：向上投影 ───→  K  [d]     ┐
     │                                     ├ 用的时候现场解压
     └──── W^UV：向上投影 ───→  V  [d]     ┘

$$c^{KV} = W^{DKV}x \in \mathbb{R}^{512},\qquad K = W^{UK}c^{KV},\qquad V = W^{UV}c^{KV}$$

为什么这不是"有损压缩导致效果下降"

关键在于：$W^{UK}$ 和 $W^{UV}$ 是【可学习的】，而且训练时它们和 $W^{DKV}$ 一起学。

❌ 错误理解：先有一个完整的 K，然后压缩，丢失了信息
✅ 正确理解：K 从来就【不是】独立存在的。
             整个 x → c → K 的通路是端到端学出来的，
             模型自己决定"什么信息值得留在 512 维里"

    这等价于给 W_K 这个矩阵加了一个【低秩约束】：
        W_K = W^UK · W^DKV      rank ≤ 512

    而实践发现：注意力的 K/V 投影矩阵【本来就近似低秩】
    → 这个约束几乎没有代价

🔑 这就是 MLA 优于 MQA/GQA 的机制性理由：
```
MQA/GQA：削减【头的数量】→ 直接损失表达的多样性
MLA： 削减【秩】 → 只要真实秩本来就低，就没有损失

而且 MLA 解压出来的每个头【依然是不同的】（各有各的 W^UK 分块）
→ 头的专业化被完整保留了 ★
```

7.4 矩阵吸收：MLA 真正的杀手锏

上面有个明显的问题：每次用都要解压，那不是白省了吗？

    存 512 维，但每次计算前要展开成 5120 维 → 计算量没省，还多了解压的开销

答案：根本不用解压。

推导

注意力分数是 $q^\top k$。代入 MLA 的定义（$q = W^{UQ}c^Q$，$k = W^{UK}c^{KV}$）：

$$q^\top k = \left(W^{UQ}c^{Q}\right)^\top\left(W^{UK}c^{KV}\right) = c^{Q\top}\underbrace{\left(W^{UQ\top}W^{UK}\right)}_{\text{★ 这一坨与输入无关}}c^{KV}$$

$$\boxed{\ q^\top k = c^{Q\top}\,\widetilde{W}\,c^{KV},\qquad \widetilde{W} = W^{UQ\top}W^{UK}\ \text{（训练完就固定了，可预先算好）}\ }$$

    ★★★ 全程在【512 维的压缩空间】里做内积，从来没有展开到 5120 维 ★★★

    W^UQᵀ W^UK  可以在模型加载时算一次，融进权重里
    → 推理时的计算量【也】变小了

输出侧同理：$o = \sum_j A_j v_j = \sum_j A_j W^{UV}c_j^{KV} = W^{UV}\left(\sum_j A_j c_j^{KV}\right)$，$W^{UV}$ 可以吸收进后面的 $W_O$。

🔑 这就是"矩阵吸收"（matrix absorption）：
MQA/GQA：省了存储，计算量不变 MLA： ★ 存储和计算【同时】变小，而且效果不掉
这是 MLA 成为主流的真正原因。

7.5 ⚠️ RoPE 和 MLA 的天然冲突

这是很多人讲不清、但极其关键的一点。

冲突在哪

11 章会详讲 RoPE，这里只需要一个性质：RoPE 是在 $q$ 和 $k$ 上乘一个依赖位置的旋转矩阵：

$$q_m \leftarrow R_m q_m,\qquad k_n \leftarrow R_n k_n$$

现在把 RoPE 加进 §7.4 的推导：

$$q_m^\top k_n = \left(R_m W^{UQ}c^{Q}m\right)^\top\left(R_n W^{UK}c^{KV}_n\right) = c_m^{Q\top}\,W^{UQ\top}\underbrace{R_m^\top R_n}$$} m, n}W^{UK}\,c_n^{KV

    ★ 问题来了：R_mᵀ R_n = R_{n−m} 【夹在中间】，而它依赖具体的位置对 (m,n)

    → W^UQᵀ R_{n−m} W^UK 无法预先算好，因为 (n−m) 每对位置都不同
    → ★★ 矩阵吸收失效了 ★★
    → 必须真的把 c 解压成 5120 维、加 RoPE、再算内积
    → MLA 的全部优势消失

🔑 一句话说清冲突：
矩阵吸收要求"$W^{UQ\top}W^{UK}$ 是常数"，而 RoPE 在两者之间插入了一个"随位置变化"的矩阵。二者不可兼得。

解法：Decoupled RoPE（解耦 RoPE）

DeepSeek 的方案：把 K 拆成两部分，一部分不加 RoPE（可吸收），一部分专门加 RoPE（不吸收，但很小）。

$$k = \Big[\ \underbrace{W^{UK}c^{KV}}{\text{压缩部分，无 RoPE，可吸收}}\ ;\ \underbrace{\text{RoPE}(W^{KR}x)}\ \Big]$$}

分数变成两项相加：

$$q^\top k = \underbrace{c^{Q\top}\widetilde{W}c^{KV}}{\text{在 512 维压缩空间算，吸收生效}} + \underbrace{q^{R\top}k^{R}}$$}

✅ openPangu-2.0-Pro 的真实配置

┌──────────────────────────────────────────────────────────┐
│  c^KV = W^DKV · x           压缩的 KV latent    512 维    │
│  k^R  = RoPE(W^KR · x)      解耦的位置分量       64 维    │
│  ─────────────────────────────────────────────────────   │
│  ★ 每 token 每层入 cache 的总维度 = 512 + 64 = 576        │
└──────────────────────────────────────────────────────────┘

注意 $k^R$ 只有 64 维，而且它是【所有头共享的】（像 MQA 那样）——因为位置信息本身不需要每个头有一套。

省了多少

                        每 token 每层     50 层，BF16     128K 上下文
    MHA (d=5120)          2×5120 = 10240      20 KB          128 GB
    MLA (576)                       576      1.13 KB         7.2 GB
                                            ────────       ─────────
                                            压缩 17.8×      省 121 GB

🔑 这就是 06 章那个"1 MB/token"变成"56 KB/token"的过程。
结合 08 章 的稀疏化，才有了 DeepSeek-V4 报告的"1M 上下文下 KV cache 仅约 2%"。

7.7 numpy 走一遍

# ---------- 标准 MHA 的 KV cache ----------
class MHACache:
    def __init__(self, H, d_h):
        self.K, self.V = [], []           # 每步 append 一个 [H, d_h]
    def step(self, x, W_K, W_V):
        self.K.append(x @ W_K)             # 存 H*d_h 个数
        self.V.append(x @ W_V)             # 再存 H*d_h 个数

# ---------- MLA 的 KV cache ----------
class MLACache:
    def __init__(self):
        self.C, self.KR = [], []
    def step(self, x, W_DKV, W_KR, pos):
        self.C.append(x @ W_DKV)                    # 512 维
        self.KR.append(rope(x @ W_KR, pos))         # 64 维
        # ★ 一共只存 576 个数，而不是 10240 个

# ---------- 矩阵吸收后的分数计算 ----------
def mla_scores(cQ, qR, cache, W_absorbed):
    # W_absorbed = W_UQ.T @ W_UK，加载时算一次
    C  = np.stack(cache.C)                  # [L, 512]
    KR = np.stack(cache.KR)                 # [L, 64]
    part1 = cQ @ W_absorbed @ C.T           # ★ 全程 512 维，没解压
    part2 = qR @ KR.T                       # 64 维的位置项
    return (part1 + part2) / np.sqrt(d_h)

7.8 本章小结

① 问题：MHA 每 token 每层要存 2d 个数（d=5120 → 20 KB）
② MQA（共享 1 组 KV）/ GQA（分组共享）省了存储，但削弱了头的专业化，掉效果
   且【计算量一点没省】
③ MLA 换了思路：不共享，而是【低秩压缩】
   x → c(512 维) → 用的时候解压出 K、V
   因为 W^UK/W^UV 是端到端学的，等价于给 W_K 加低秩约束，几乎无损
④ ★ 矩阵吸收：qᵀk = c^Qᵀ (W^UQᵀ W^UK) c^KV
   括号里与输入无关，可预先算好 → 全程在 512 维算，【存储和计算同时变小】
⑤ ★ RoPE 与 MLA 天然冲突：R_mᵀR_n = R_{n−m} 夹在中间，随位置变化，吸收失效
   解法 = decoupled RoPE：K 拆成【可吸收的压缩部分】+【带 RoPE 的小部分】
   openPangu：512 + 64 = 576 维入 cache，相比 MHA 压缩 17.8×
⑥ 五家四家用 MLA 系，只有 M3 用 GQA → MLA 已形成共识
