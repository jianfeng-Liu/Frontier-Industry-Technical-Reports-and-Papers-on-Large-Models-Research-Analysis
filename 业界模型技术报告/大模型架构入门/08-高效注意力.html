08 · 把注意力本身改掉：四条路

这一章的目标：这是五家分歧最大、创新最密集的一章，也是五份技术报告篇幅占比最高的部分。
07 章回答了"每个 token 存多少"，本章回答"到底要不要看那么多 token"。
读完你应该能回答：滑窗、稀疏、压缩、线性这四条路各自的原理和代价是什么？为什么线性注意力这一代又火了、但 MiniMax 从它退回去了？ 为什么 attention sink 是所有稀疏方案的必备补丁？

8.1 问题：$L^2$ 这笔债

回忆 01 章 §1.5 和 06 章：

    注意力矩阵 S 是 [L, L]

    L = 4K：    L² = 1.7e7      在总 FLOPs 里占 ~12%
    L = 128K：  L² = 1.6e10     开始主导
    L = 1M：    L² = 1.1e12     占 ~97%，【完全主导】

    ★ 而且长度翻 8 倍，这一项涨 64 倍

05 章的 FlashAttention 解决了显存（$O(L^2)\to O(L)$），但计算量一点没减。

要减计算量，只能改数学本身。 只有四种改法：

┌──────────────────────────────────────────────────────────────┐
│  ① 滑窗    只看最近的 w 个 token          O(L·w)             │
│  ② 稀疏    动态挑出最相关的 k 个 token    O(L·k)             │
│  ③ 压缩    把远处的 token 打包成"摘要"     O(L·L/r)          │
│  ④ 线性    换掉 softmax，变成 RNN 式状态   O(L)              │
└──────────────────────────────────────────────────────────────┘

五家的方案全部是这四条路的组合。 下面一条一条讲。

8.2 路线①：滑动窗口（SWA, Sliding Window Attention）

原理：最简单的那个

只看最近的 $w$ 个 token，更早的直接不看。

        j=1  j=2  j=3  j=4  j=5  j=6  j=7  j=8      w = 3
 i=5  [  ✗    ✗   ✓    ✓    ✓   -inf -inf -inf ]
 i=6  [  ✗    ✗   ✗    ✓    ✓    ✓   -inf -inf ]
 i=7  [  ✗    ✗   ✗    ✗    ✓    ✓    ✓   -inf ]
         ↑ 太远，看不见            ↑ 未来，因果掩码

✅ 计算量：O(L·w)，【和 L 成线性】
✅ KV cache：只需要存最近 w 个 → 【常数显存】，与 L 无关！
❌ 信息只能靠层层堆叠慢慢传递

感受野：为什么它还能工作

    第 1 层：位置 i 能看到 [i−w, i]
    第 2 层：能看到"能看到 [i−w,i] 的那些位置"能看到的 → [i−2w, i]
    第 N 层：[i − N·w, i]

    ★ 有效感受野 = N × w（线性增长，像 CNN）

    openPangu: 50 层 × 512 = 25,600      ← 远小于 512K 上下文！

⚠️ 注意这个数字：openPangu 的 SWA 窗口是 512，50 层堆起来理论感受野只有 25.6K，而它宣称支持 512K。
所以 SWA 绝不能单独用——必须和"能看全局"的层混合。这正是它做 DSA–SWA 1:2 交错的原因（§8.6）。

⚠️ 三份负面证据：SWA 没有大家想的那么好

这是本章最有价值的一段，因为它是这一代报告里罕见的"公开的失败数据"。

✅ 证据一（GLM-5.2 报告的 GLM-9B 消融，一手数据）：
128K RULER 得分 全注意力 75.28 固定交错 SWA 6.51 ← 崩了
68.77 分的断崖。 这不是"略有下降"，是长上下文能力基本报废。

✅ 证据二（MiniMax M2 报告 §2.2.2）：MiniMax 在 M2 里从线性/高效注意力退回了全注意力，明确记录了这个回退。

✅ 证据三：openPangu 用 SWA，但窗口只有 512，且必须按 1:2 与 DSA 交错——如果 SWA 真的好用，不会配得这么保守。

🔑 结论：
SWA 的省是真的，但它单独用的代价也是真的。这一代没有任何一家敢纯用 SWA。
它现在的定位是"廉价的局部层"，必须和全局能力的层混合。

8.3 路线②：动态稀疏（代表方案 DSA, DeepSeek Sparse Attention）

原理：不是"看最近的"，而是"看最相关的"

SWA 的问题在于"最近"是个很笨的启发式。 有用的信息可能在 30 万字之前。

DSA 的做法：先用一个便宜的方法估计"哪些 token 最相关"，只对这 top-k 个算真正的注意力。

        ① 便宜的打分：用一个【小的索引器】给所有 L 个位置打分
                      比如把 K 压到 32 维再和压缩的 Q 算内积

        score:  0.1  0.9  0.2  0.8  0.1  0.1  0.7  0.1  ...
                      ↑         ↑              ↑
        ② 选 top-k（比如 k=2048），只对这些算完整注意力

        ③ 其余位置的权重直接置 0

✅ 计算量 O(L·k)，且【k 是常数】，不随 L 增长
✅ 保留了"看任意远处"的能力 —— 这是相比 SWA 的根本优势
❌ 索引器本身要花钱（虽然便宜）
❌ top-k 是【不可微】的操作，训练需要技巧
❌ 稀疏的 gather 在 GPU 上不友好，需要专门的核函数

⭐ DSA 的底座是 MLA——为什么偏偏是它

✅ 事实先摆出来：目前用 DSA 的三家，底座清一色是 MLA（第 7 章讲的那个"把 KV 压成低维 latent"的方案）。

模型 注意力配置
DeepSeek-V3.2 MLA + DSA（token 级 top-2048）
GLM-5.2 MLA-256 + DSA + IndexShare
openPangu-2.0-Pro MLA + DSA / SWA 按 1:2 交错

第一步：它俩省的根本不是同一样东西

所以不是二选一，是叠乘。

    MLA  → 砍【每个 token 的 KV 有多宽】   2048 维 → 576 维 latent   ⇒ 省显存
    DSA  → 砍【一共要看多少个 token】       L 个    → 固定 2048 个    ⇒ 省算力 + 访存

              KV cache 的实际读取量  =  看多少个 token  ×  每个有多宽
                                          ↑ DSA 砍这个      ↑ MLA 砍这个

一个走序列长度方向，一个走特征维度方向，正交，可以同时用。

第二步：关键在上面那个 ❌「gather 不友好」

稀疏真正的代价是 gather——拿着 top-k 算出来的下标，去显存里一个一个地"抓" KV。这些地址不连续，是 GPU 最不喜欢的访存模式。那么 gather 要抓几趟，就成了成败的关键。

⚠️ 我的理解（这一步的因果关系官方没有明说，是我从各家配置反推的）：

```
MHA / GQA 底座：每个头（或每个 KV 组）各选各的 top-k
→ 有几组就要 gather 几趟 ❌

MLA 底座 ：解码时是【MQA 吸收形态】，所有头共用同一份 latent KV
→ 一次 gather 就服务了全部头 ✅
```

✅ 其中"MLA 解码走 MQA 形态"这件事本身是有报告原文的，见 ../openPangu-2.0-Pro.md §十「训推不一致解剖」（原文："MLA switching between Absorptive (MQA, decode) and Non-Absorptive (MHA, training/prefill) modes"）。

这解释了 DSA 为什么敢用最激进的形式：token 级的 top-k，而且全部注意力头共用同一份选择。因为在 MLA 底座上，这份选择只需要 gather 一趟。

反过来看 MiniMax 的 MSA 就更清楚了：同样是"精确 softmax + 动态稀疏选择"、同样落在 2048 的预算上，但它的底座是 GQA，4 个 KV 组得各选各的——于是它退了一步，改成块级选择（16 个块 × 每块 128 token）。块内地址是连续的，正好把 gather 的开销摊薄。

📌 底座决定了稀疏的形态，这条对照的完整版在 ../模型技术对比.md §3.1.2。

第三步：但"必须建在 MLA 上"是错的

DSA 依赖 MLA 是工程上的划算，不是原理上的必需。三个反例：

  ① MiniMax MSA  —— 同样的动态稀疏，装在 GQA 上，跑通了（代价是退到块级）
  ② openPangu    —— DSA 只装在 1/3 的层上，另外 2/3 是 SWA，照样工作
  ③ ★ DeepSeek-V4 —— 它自己下一代【根本不用 MLA】：报告全文没出现过 MLA，
                      改走 CSA + HCA 的压缩路线（见 §8.4），
                      内核直接就是共享 KV 的 MQA

还有一条旁证：DSA 模型基本都是从已有的稠密 MLA 模型转换出来的（DeepSeek-V3.2 花 943.7B tokens，GLM-5 只花 20B，openPangu 花 100B + 8B 预热）。是"转换"而不是"重新设计"——这说明 DSA 是长在 MLA 之上的一个增量模块，而不是一套从头设计的新注意力。

⚠️ 一个待核的细节：lightning indexer 用的是独立的一套小 Q/K 投影，还是复用 MLA 的 latent？几份报告都没写清楚。已知的只有 GLM-5.3 的配置显示索引器自己带 RoPE（indexer_rope_interleave: true），这更像是独立的一套。

GLM 的 IndexShare：一个很聪明的工程优化

观察：索引器本身也要对全部 $L$ 个位置打分，也是 $O(L)$ 的。层数一多就不便宜了。

✅ GLM-5.2 的做法：每 4 层只算一次索引，4 层共享同一套 top-k 选择。

    层 1  ── 算索引 ──┐
    层 2  ────────────┤
    层 3  ────────────┤  共用同一套 top-k
    层 4  ────────────┘
    层 5  ── 算索引 ──┐
    ⋮                 ⋮

假设：相邻层关注的位置高度重叠。这是个合理的假设（可解释性研究确实观察到相邻层注意力模式相似），而且 GLM 用实测效果验证了它。

8.4 路线③：压缩注意力

原理：远处的 token 不需要逐个看，打包成摘要就行

    最近的：       逐个看，全精度
    ├─ t_L  t_{L−1}  t_{L−2}  ...

    远处的：       每 r 个打包成 1 个"摘要 token"
    ├─ [t1..t4]→c1   [t5..t8]→c2   [t9..t12]→c3  ...
         ↑ 压缩率 r=4

    → 序列长度从 L 变成 L/r，计算量降到 O(L²/r²)

"打包"通常是一个小的可学习池化或卷积。

✅ DeepSeek-V4 的双注意力

V4 报告明确给出的两种注意力：
CSA (Compressed Sparse Attention，压缩稀疏注意力)： 4:1 【重叠】压缩 HCA (Heavily Compressed Attention，重度压缩注意力)：128:1 【稠密】
✅ 两个全称都是报告摘要里的原文："a hybrid attention architecture that combines
Compressed Sparse Attention (CSA) and Heavily Compressed Attention (HCA)"。
⚠️ 注意 HCA 的名字里没有 "Sparse"——✅ 报告写得很明确：
"HCA applies more aggressive compression to the KV caches but keeps dense attention"。

    CSA  4:1  重叠压缩   → 中等压缩率，重叠保证边界信息不丢
    HCA  128:1 稠密      → 极高压缩率，但【稠密】：所有摘要都看，不做稀疏选择

    两者组合：
      · CSA 提供较细的粒度（4 个 token 一个摘要）
      · HCA 提供极廉价的全局视野（128 个 token 一个摘要，但一个不漏地全看）

🔑 "稠密"这个词是关键：HCA 压缩了 128 倍之后，序列长度只剩 $L/128$，此时再做完整的 $O((L/128)^2)$ 注意力也很便宜（1M → 8K，完全可接受）。

这是一个很干净的设计：用极致压缩把"看全局"这件事变得便宜到可以不做稀疏。 它避开了 §8.3 提到的 top-k 不可微和 gather 不友好的全部麻烦。

✅ MiniMax M3 的 MSA：块级结构

M3 报告的配置：块大小 $B_k = 128$，选 $k=16$ 个块 → 有效上下文 $16\times128 = 2048$。

    把序列切成 128 个 token 一块，
    以【块】为单位做 top-k 选择（选 16 块），
    块内做完整注意力

🔑 为什么按块而不按 token 选：
```
按 token 选 2048 个 → GPU 要做 2048 次分散的随机访存 → 极慢
按块选 16 块 → 16 次连续访存，每次 128 个 → GPU 友好 ★

这是【算法迁就硬件】的典型例子，和 §5.7 FlashAttention 是同一种思路
```

8.5 路线④：线性注意力（Linear Attention）

这条路最激进，也是数学上最有意思的一条。

🔑 先说清楚它和前三条路的根本区别，否则后面全是公式：

```
路线①②③（滑窗 / 稀疏 / 压缩）
骨架还是 O(L²) 那张【L × L 的大表】，只是把大部分格子划掉不算
→ 省，但没有【消灭】那张表；KV cache 仍然随长度增长

路线④（线性注意力）
★ 把那张表从公式里【彻底消掉】
→ 历史不再逐个存着，而是压进【一个固定大小的矩阵】
→ 代价：压缩就会有损，所以它【必然遗忘】
```

一句话：前三条是"少看几个 token"，第四条是"根本不存 token"。

第一步：$L^2$ 到底卡在哪一个符号上

标准注意力（05 章）写成逐个 token 的形式：

$$O_i = \frac{\sum_{j\le i}\exp(q_i^\top k_j)\,v_j}{\sum_{j\le i}\exp(q_i^\top k_j)}$$

为什么这一定要算 $L^2$ 次？ 因为分子里的 $\exp(q_i^\top k_j)$ 同时缠住了 $i$ 和 $j$：

    想算第 i 个 token 的输出，就得对每一个 j 单独求一次 exp(q_i·k_j)
    换一个 i，前面算的全部作废，因为 exp 里的 q 变了
        → L 个 i × L 个 j = L² 次，一次都省不掉

📌 这里要引入一个词：「可分解」。
```
可分解 = 能写成 f(q_i) · g(k_j) 的形式，两个因子各自只依赖一边

exp(q·k) ❌ 不可分解 —— q 和 k 被锁死在同一个 exp 里
φ(q)ᵀ φ(k) ✅ 可分解 —— 一个只碰 q，一个只碰 k，中间是普通内积
```
整条路线的全部动机，就是把不可分解的 $\exp$ 换成可分解的东西。 至于为什么"可分解"就能省掉 $L^2$——那是下一步，也是本节最关键的一步。

第二步：★★ 核心 —— 矩阵乘法的结合律

这一步是整节的心脏。如果只看懂一段，就看这一段。

先忘掉 softmax，只看注意力最裸的骨架 $\;O = (QK^\top)V$。矩阵乘法有结合律，所以括号可以换个位置：

   记 L = 序列长度（比如 1,000,000），d = 每个头的维度（比如 128）
   Q: [L, d]      K: [L, d]      V: [L, d]

┌─ 先算 QKᵀ ─（标准做法）──────────────────────────────────┐
│                                                          │
│    Q [L,d] × Kᵀ[d,L]  →  【 L × L 】 ← ★ 这张巨表就是 O(L²)│
│                              ↓  × V [L,d]                │
│                          结果 [L, d]                      │
│                                                          │
│    L=1M 时这张表有 10¹² 个数 —— 存都存不下                 │
└──────────────────────────────────────────────────────────┘

┌─ 先算 KᵀV ─（线性注意力）────────────────────────────────┐
│                                                          │
│    Kᵀ[d,L] × V [L,d]  →  【 d × d 】 ← ★ 和 L 完全无关！   │
│                              ↑  Q [L,d] 再乘上来          │
│                          结果 [L, d]                      │
│                                                          │
│    d=128 时这个矩阵只有 16,384 个数 —— 一直是这么大        │
└──────────────────────────────────────────────────────────┘

   ★★ 两条路的【结果完全相同】，只是先算哪一步不同 ★★

算一笔账（乘加次数）：

(QKᵀ)V ：  L·L·d  +  L·L·d  =  2L²d
Q(KᵀV) ：  d·L·d  +  L·d·d  =  2Ld²
                                 ↑ L 和 d 换了位置

    两者之比 = L / d

    L = 4K，  d=128  →   32 倍
    L = 128K，d=128  →  1024 倍
    L = 1M，  d=128  →  ★ 8192 倍

🔑 这就是"线性"两个字的全部来历：$2L^2d \to 2Ld^2$，对 $L$ 从平方变成了一次。
代价也一目了然：中间那个 $[d,d]$ 的矩阵，就是"全部历史"被压缩成的唯一容器。$L$ 再大它也不变大——省就省在这里，忘也忘在这里。

第三步：为什么必须先把 $\exp$ 换掉

因为 softmax 让你没法挪括号。

    有 exp：   O = softmax(Q Kᵀ) V
                          └──┬──┘
                     exp 是【逐元素】作用在乘完之后的 L×L 表上
                     → 那张表必须先【真的算出来】，才能取 exp
                     → 括号焊死了，挪不动

    换成 φ：   O = (Φ_Q Φ_Kᵀ) V   →   Φ_Q (Φ_Kᵀ V)
                                        ↑ 纯矩阵乘法，结合律随便用

所以把 $\exp(q^\top k)$ 换成 $\phi(q)^\top\phi(k)$（$\phi$ 是某个特征映射，早期工作用 $\mathrm{elu}(x)+1$）：

$$O_i = \frac{\sum_{j\le i}\phi(q_i)^\top\phi(k_j)\,v_j}{\sum_{j\le i}\phi(q_i)^\top\phi(k_j)} = \frac{\phi(q_i)^\top\left(\sum_{j\le i}\phi(k_j)v_j^\top\right)}{\phi(q_i)^\top\left(\sum_{j\le i}\phi(k_j)\right)}$$

逐字看懂右边这一步是怎么来的（很多材料到这里就一句"提出来"带过了）：

① φ(q_i)ᵀφ(k_j) 是一个【标量】（两个向量的内积）
② 标量 × 向量 v_j，可以改写成矩阵形式：
        [φ(q_i)ᵀ φ(k_j)] · v_jᵀ  =  φ(q_i)ᵀ · [φ(k_j) v_jᵀ]
         └──── 标量 ────┘             └──── 外积，[d_k, d_v] ────┘
   ★ 这一步用的就是结合律：(aᵀb)cᵀ = aᵀ(bcᵀ)
③ φ(q_i) 与求和变量 j 无关 → 提到 Σ 外面

   于是括号里剩下   Σ_{j≤i} φ(k_j) v_jᵀ    ← 【完全不依赖 i】

⚠️ 顺带说一句 $\phi$ 为什么不能随便取：分母是 $\phi(q)^\top\sum\phi(k_j)$，如果 $\phi$ 能取负值，分母可能接近 0 甚至变号，输出直接爆炸。所以早期方案都要求 $\phi$ 非负（$\mathrm{elu}(x)+1>0$ 就是为此）。
K3 的 KDA 换了个办法：不用 $\phi$，而是对 $q,k$ 做 L2Norm（把向量长度固定成 1），后面会看到这个选择还有一个更漂亮的用处。

第四步：因果掩码，把"一次大矩阵乘"变成"一个滚动累加"

这是很多讲解跳过、但恰恰是 RNN 冒出来的地方。

如果没有因果掩码（每个 token 能看全序列）：
    Σ_{j≤i} 里的 i 就消失了，所有 token 共用【同一个】 Kᵀ V
    → 一次矩阵乘算完，干净利落

但语言模型必须因果（第 i 个字看不到未来）：
    → 上界是 i，每个 token 的括号内容都【不一样】
    → 看起来又要算 L 次？

★ 但它们之间只差一项：

    第 i 个 token 的括号  =  第 (i−1) 个的括号  +  φ(k_i) v_iᵀ
                                                  └─ 只跟第 i 个 token 有关 ─┘

    这就是一个【滚动累加】(running sum)：
        来一个 token，往上加一项，前面的结果完全复用，不重算

    ★★ 而"用上一步的状态 + 当前输入，算出这一步的状态"
       —— 这在数学上就是【递推式】，也就是一个 RNN ★★

第五步：于是得到一个 RNN

$$\boxed{\ S_t = S_{t-1} + \phi(k_t)v_t^\top,\qquad o_t = \phi(q_t)^\top S_t\ }$$

★ 先把形状钉死（不看形状就永远读不懂这个式子）：

    φ(k_t)          [d_k]          第 t 个 token 的"地址"
    v_t             [d_v]          第 t 个 token 的"内容"
    φ(k_t) v_tᵀ     [d_k, d_v]     ← 外积！一个矩阵，不是一个数
    S_t             [d_k, d_v]     ★ 状态矩阵，模型全部的"记忆"
    φ(q_t)ᵀ S_t     [d_v]          读出来的结果

    ★★ 注意 S 的形状里【没有 L】—— 这就是全部的秘密

把它当成一张会被反复涂改的表来读：

    ┌─────────────────────────────────────────────────────────┐
    │  S 是一张表：  key 是【栏目名】，value 是【栏目内容】     │
    │                                                          │
    │  每来一个 token：                                        │
    │    ① 写：把 φ(k_t) v_tᵀ 加到表上                          │
    │         ——"在 k_t 这一栏，记下 v_t"                       │
    │    ② 读：用 φ(q_t) 去查这张表，得到 o_t                    │
    │         ——"我想找 q_t 这样的东西，表里有什么？"            │
    └─────────────────────────────────────────────────────────┘

📌 分母去哪了？ 上面那个方框里只有分子。现代实现（包括 K3 的 KDA）确实把分母丢掉了——报告式 (1) 写的就是干净的 $\tilde o_t = S_t^\top q_t$，没有归一化项。
⚠️ 原因是我的解释，不是报告的说法：分母 $\phi(q)^\top\sum\phi(k_j)$ 会随序列变长而不断增大，是个已知的不稳定来源；改成"对 $q,k$ 做 L2Norm + 输出侧再过 RMSNorm 和门控"来控制尺度，工程上更稳（✅ 这套参数化是报告式 (2) 明确写的）。

第六步：★ 算一笔真实的账，感受一下差多少

这才是这条路线的卖点所在（⚠️ 以下是我按标准配置的估算，不是任何一家的官方数字）：

设 d_k = d_v = 128（单个头），BF16 每个数 2 字节，看【一层、一个头】：

┌─ 标准注意力的 KV cache ─────────────────────────────────┐
│   每个 token 存 K 和 V 两份：2 × 128 × 2 字节 = 512 字节  │
│   L = 1K     →      512 KB                              │
│   L = 128K   →       64 MB                              │
│   L = 1M     →  ★   512 MB      ← 随长度【线性增长】     │
└─────────────────────────────────────────────────────────┘

┌─ 线性注意力的状态 S ────────────────────────────────────┐
│   S 是 [128, 128] 的矩阵：128 × 128 × 2 字节 = 32 KB     │
│   L = 1K     →       32 KB                              │
│   L = 128K   →       32 KB                              │
│   L = 1M     →  ★    32 KB      ← 【一个字节都不涨】     │
└─────────────────────────────────────────────────────────┘

    1M 上下文下相差 512 MB / 32 KB = 【16,384 倍】

🔑 回到 06 章 那条主线：decode 是访存受限的，省下的字节几乎直接变成速度。这就是为什么明知道线性注意力会遗忘，五家里还是有人愿意用它当主力层。

⚠️ 三个必须知道的代价

① ★ 必然遗忘 —— 这是【信息论层面】的，不是工程没做好
     1M 个 token、每个 128 维的 value，一共 1.34 亿个数
     全部要塞进 S 的 16,384 个数里 → 压缩比 8192 : 1
     ★ 压缩比这么高，丢信息是【数学上必然的】，不可能靠调参解决

② 训练并行需要特殊算法
     递推式天生是【串行】的（S_t 要等 S_{t−1}），而 GPU 要的是并行
     解法：chunkwise（分块）—— 块【内】并行、块【间】递推
     ✅ K3 报告式 (3) 写的就是这个：
        O[t] = (Γ ⊙ Q[t]) S[t]  +  A[t] Ṽ[t]
                └ 块间：读入状态 ┘   └ 块内：并行算 ┘
     ⚠️ 而块内计算要【除以累积衰减 Γ】，衰减连乘会变得极小、倒数极大
        → 这正是 K3 把衰减改成"有下界"的原因，见 [../Kimi-K3.md](../Kimi-K3.md) §二
        ★ 一个很典型的因果链：数学形式 → 数值范围 → 必须改设计

③ 精确检索会崩
     "大海捞针"这类任务要的是【原样召回】，而它给的是【有损摘要】
     → 所以没有一家纯用线性注意力，见本节末

🔑 一句话对比：
softmax 注意力：把所有历史【原样存着】，每次精确检索 → 完美但 O(L²) 线性注意力： 把所有历史【压进一个矩阵】，有损检索 → O(L) 但会忘 ★ 这就是 RNN 和 Transformer 之争的现代版本

Delta rule：让它学会"覆盖"而不只是"累加"

朴素线性注意力的致命问题：$S_t = S_{t-1} + \phi(k_t)v_t^\top$ 只会【加】，从不【删】。

    "小明住在北京。……（500 字后）……小明搬到了上海。"

    朴素线性注意力：北京和上海的信息【都在 S 里叠着】
    → 问"小明住在哪"，读出来的是两者的混合 → 错

★ 为什么恰好是 $(I-\beta k k^\top)$ 这个形状

这个式子不是凑出来的，它是一步梯度下降。 ⚠️（以下推导是标准结果，用于解释形式的来源，不是 K3 报告的原文论证。）

① 先问：我们希望 S 满足什么？
      希望"用 k_t 去读，能读出 v_t"，也就是   Sᵀ k_t ≈ v_t

② 把它写成一个损失函数：
      ℒ(S) = ½ ‖ Sᵀ k_t − v_t ‖²

③ 对 S 求梯度：
      ∇_S ℒ = k_t ( S ᵀ k_t − v_t )ᵀ

④ 用学习率 β 走一步梯度下降：
      S_t = S_{t−1} − β k_t ( S_{t−1}ᵀ k_t − v_t )ᵀ
          = S_{t−1} − β k_t k_tᵀ S_{t−1} + β k_t v_tᵀ
          = ( I − β k_t k_tᵀ ) S_{t−1} + β k_t v_tᵀ        ★ 正是 delta rule

⭐ "delta"这个名字就来自第 ④ 步的括号：$\delta = v_t - S_{t-1}^\top k_t$ 是"想要的" 减去 "现在读到的"，也就是误差。更新量正比于这个 $\delta$——这是 1960 年 Widrow–Hoff 的经典 delta rule，在这里被搬进了注意力。

🔑 换句话说：每读入一个 token，模型就在对自己的记忆做一次在线学习。

★ 顺带解释一个细节：为什么 KDA 要对 $k$ 做 L2Norm

⚠️ 报告只写了"query 和 key 进一步用 L2Norm 归一化"，没有给理由；下面是我的推导。

    取 β = 1，并且 ‖k_t‖ = 1（L2Norm 保证的），验算一下写完之后读出什么：

        S_tᵀ k_t = [ (I − k kᵀ) S_{t−1} + k vᵀ ]ᵀ k
                 = S_{t−1}ᵀ ( k − k·‖k‖² ) + v·‖k‖²
                 = S_{t−1}ᵀ · 0 + v            ← 因为 ‖k‖² = 1
                 = v_t                          ★ 【精确等于新值】

    ★ 结论：L2Norm 不是可有可无的归一化，
      它让 β=1 变成一次【干净利落的完全覆盖】——旧内容一点不剩。
      如果 ‖k‖ ≠ 1，擦除就会擦不干净或者擦过头。

完整的 KDA 更新式

$$S_t = \underbrace{\left(I - \beta_t k_t k_t^\top\right)}{\text{擦除 }k_t\text{ 方向的旧内容}}\cdot\underbrace{\text{Diag}(\alpha_t)},\qquad \tilde o_t = S_t^\top q_t$$}}\cdot S_{t-1} + \underbrace{\beta_t k_t v_t^\top}_{\text{写入新内容}

✅ 这就是 K3 报告的式 (1)，逐符号核对过。

项 形状 作用
$I - \beta_t k_t k_t^\top$ $[d_k,d_k]$ 沿 $k_t$ 方向的投影擦除。$\beta_t=1$ 完全擦掉旧值，$\beta_t=0$ 完全不擦
$\beta_t$ 标量 ✅ 报告：$\beta_t=\mathrm{Sigmoid}(W_\beta x_t)\in(0,1)$，控制"写入强度"
$\text{Diag}(\alpha_t)$ $[d_k,d_k]$ 对角阵 ⭐ 逐通道（channel-wise）遗忘门——见下
$\alpha_t$ $[d_k]$ ✅ 报告原文："channel-wise one-step retention factor"，$\alpha_t\in(0,1)^{d_k}$
$\beta_t k_t v_t^\top$ $[d_k,d_v]$ 写入新的键值对 
★ 读式子要【从右往左】读（矩阵乘法的作用顺序）：

    S_{t−1}                       ← 上一刻的记忆
      ↓ × Diag(α_t)               ① 先让每一栏各自淡化一点
      ↓ × (I − β_t k_t k_tᵀ)      ② 再把 k_t 这一栏的旧内容擦掉 β 的比例
      ↓ + β_t k_t v_tᵀ            ③ 最后把新的 v_t 写进这一栏
    S_t                           ← 这一刻的记忆

    ✅ 报告的措辞也是这个顺序："KDA 在 delta-rule 更新【之前】施加逐通道衰减"

⭐ "逐通道"三个字是 Kimi 的核心贡献，别读漏了：
普通遗忘门：整张表用【同一个】衰减率 → 所有记忆一起褪色 逐通道遗忘：S 的【每一行】有自己的衰减率 → "这一栏记的是人名，慢点忘" "那一栏是临时数字，快点忘" ★ α_t 是 d_k 维向量而不是一个标量，差别就在这里
★ 这就是一个可微、可学习的读写内存：读写地址、写入强度、遗忘速度，全部由数据学出来。

✅ Kimi K3 的 KDA：混合而不是替换

✅ 报告原文（§2.1）："每个 block 包含 3 层 KDA + 1 层 Gated MLA，即 3:1 的混合比例，该模式在整个主干中重复。主干末尾额外放置一层 Gated MLA，确保最后一层永远是全局注意力。"

★ 拿架构表验算一遍（17 章 §17.5 那条"数字要能互相印证"的实践）：

    93 层 = 23 个 block × 4 层  +  末尾额外 1 层 MLA
                ↓
    KDA = 23 × 3 = 69
    MLA = 23 × 1 + 1 = 24
                ↓
    ✅ 和报告架构表里的 "69 KDA + 24 MLA" 完全对上，69 + 24 = 93 ✓

为什么必须留那 24 层全注意力：线性注意力必然遗忘（见上面代价①），纯用会在"大海捞针"这类精确检索任务上崩。留下的 MLA 层充当"精确检索通道"。 这和 §8.2 里 SWA 必须和全局层混合是同一个道理——

🔑 本章一个反复出现的模式：
所有便宜的注意力都会丢东西，所以它们全都得和"完整的那种"混着用。区别只在于混多少、怎么排。

⚠️ MiniMax 的反例值得记住：M2 报告 §2.2.2 记录了从线性注意力退回全注意力。
这一代线性注意力的地位是："作为混合方案里的廉价层可以，作为主力不行。"

8.6 Attention Sink：所有稀疏方案的必备补丁

回忆 05 章 §5.5 的伏笔

    softmax 权重和必须 = 1
        → 模型没有"什么都不看"的选项
        → 它自己发明了 attention sink：把 ~90% 权重倒给第一个 token

⚠️ 稀疏化会把 sink 弄丢

    滑窗 w=512，当前在第 100000 个位置：
        窗口 = [99488, 100000]
        ★ 第 1 个 token 【不在窗口里】了！

    → sink 消失 → 那 90% 的权重被迫重新分配给窗口内的普通 token
    → 模型行为剧烈改变 → 输出崩坏

这是一个被反复观察到的现象：朴素的滑窗实现，一旦滑过初始 token，困惑度会突然爆炸。

解法：显式给一个官方垃圾桶

① StreamingLLM 式：永远保留最前面的 4 个 token，不管窗口滑到哪
② 可学习的 sink token：加几个专门的、不代表任何真实内容的 KV
③ 给 softmax 加一个不参与输出的额外项（"softmax + 1"）

✅ openPangu 的 PAS

PAS = 每层 128 个可学习的 KV（华为报告明确给出）。

    在每一层的 KV cache 里，除了真实 token 的 KV，
    再放 128 个【可学习的、与输入无关的】KV 对。
    它们永远可见，不受任何稀疏/滑窗规则影响。

它同时干了两件事：

① 充当官方 sink：模型想"什么都不看"时，就把权重倒给 PAS
   → 不用再扭曲某个真实 token 的数值当垃圾桶
   → ★ 这条对 [14 量化](14-量化.md) 有直接好处：少一个离群值来源

② 充当"全局寄存器"：128 个可学习的槽位可以存放任务级的全局信息
   即使在滑窗层，模型也有一条稳定的全局通道

📌 PAS 的消融数据在 ../模型技术对比.md §3.1.3。

🔑 这一代模型普遍引入显式 sink 机制，根因就是 §8.2~8.5 全面的稀疏化。
稀疏化打破了模型自己找到的平衡，就必须补一个官方机制回去。

8.7 五家的组合：一张总表

路线组合 具体配置 混合比
DeepSeek-V4 ③ 压缩 ×2 CSA 4:1 重叠 + HCA 128:1 稠密 两种注意力并用
Kimi K3 ④ 线性 + 全注意力 KDA（delta rule）+ MLA 3:1
GLM-5.2 ② 稀疏 DSA + IndexShare（每 4 层算一次索引） —
MiniMax M3 ② 稀疏（块级） MSA：块 128，选 16 块 → 2048 + GQA-16
openPangu-2.0-Pro ② 稀疏 + ① 滑窗 DSA + SWA（窗口 512）+ PAS 128 DSA : SWA = 1 : 2

⚠️ 几个值得记住的横向观察

① 【没有一家纯用一条路】
   全部是混合。原因：每条路都有一个致命弱点，必须靠另一条补
      滑窗 → 看不见远处      → 混全局层
      线性 → 必然遗忘        → 混全注意力层
      稀疏 → top-k 可能选错  → 混稠密层或滑窗

② 【压缩（③）这条路最"安全"】
   DeepSeek-V4 的 HCA 是稠密的 —— 不做任何选择，一个不漏地看全部摘要
   → 没有"选错"的风险，只有"摘要有损"的风险
   ⚠️ 这是我的判断，V4 报告没有这样对比过

③ 【线性注意力的地位在下降】
   K3 只给它 3/4 的层，且必须配全注意力
   MiniMax 在 M2 里直接退回去了
   → 从"可能取代 Transformer"降级为"混合方案里的廉价层"

④ 【所有稀疏方案都需要 sink 补丁】
   这是 §5.5「softmax 和必须为 1」这条约束的下游后果

8.8 本章小结

① 只有四条路减少 O(L²)：滑窗 / 稀疏 / 压缩 / 线性
② 滑窗最简单，KV cache 变常数，但感受野只有 N×w
   ⚠️ 三份负面证据：GLM-9B 消融 128K RULER 从 75.28 掉到 6.51
      → 这一代没人敢纯用 SWA
③ 稀疏（DSA）：便宜的索引器打分 → 只算 top-k
   保留了看远处的能力，但 top-k 不可微、gather 不 GPU 友好
   GLM 的 IndexShare：每 4 层共享一次索引
④ 压缩：远处打包成摘要。V4 的 HCA 128:1 【稠密】——
   压得够狠之后，全看也很便宜，从而避开稀疏选择的全部麻烦
   M3 的 MSA 按【块】选（128×16=2048），为的是 GPU 访存连续
⑤ 线性：换掉 softmax → S_t = S_{t−1} + φ(k_t)v_tᵀ，变成 RNN
   KV cache 变成固定大小的矩阵，O(L) 计算
   ⚠️ 但只会加不会删 → Delta rule 加上"擦除 + 遗忘门"
      S_t = (I − β k kᵀ)·Diag(α)·S_{t−1} + β k vᵀ
   K3 的 KDA 用它，但必须 3:1 配 MLA；MiniMax 在 M2 里退回了全注意力
⑥ ★ 所有稀疏化都会弄丢 attention sink → 必须补显式机制
   openPangu 的 PAS（128 个可学习 KV/层）同时充当 sink 和全局寄存器
   这条线索来自 [05 章] 的"softmax 和必须为 1"，会一直通到 [14 章] 量化
⑦ 五家【无一例外都是混合方案】—— 每条路都有致命弱点，必须互补

注意力的三章到此结束（05 讲原理、06 讲代价、07/08 讲解法）。下一章开始讲模型的另一半：FFN。
