# 09 · FFN 与激活函数：模型 2/3 的参数都在这里

> **这一章的目标**：讲清模型的另一半积木。
> 读完你应该能回答：FFN 到底在干什么？为什么是"先扩再缩"？SwiGLU 的门控是什么意思、为什么那个 2/3 因子？以及一条完整的因果链——**为什么想做 4-bit 量化，就必须给激活函数加界**？

---

## 9.1 FFN 是什么

回忆 [01 章](01-鸟瞰全景.md)的二分法：**Attention 横向混合，FFN 纵向变换。**

**FFN（Feed-Forward Network）对每个 token 独立地做同一件事，位置之间毫无交流。**

$$\text{FFN}(x) = W_{\text{down}}\ \text{act}\!\left(W_{\text{up}}\,x\right)$$

```
    x  [5120]
      │
      │  W_up  [5120, 13824]     ★ 先【扩张】到 2.7 倍
      ▼
    h  [13824]
      │
      │  act(·)：非线性激活          ← 这一步是整个模型唯一的非线性来源之一
      ▼
      │  W_down  [13824, 5120]   ★ 再【压缩】回来
      ▼
    y  [5120]
```

### 为什么要"先扩再缩"

```
① 如果不扩张，直接 [5120 → 5120] 两层线性，中间夹一个激活：
   表达力有限，而且参数量只有 2d²

② 扩张到 d_ff 之后，中间层有 13824 个神经元
   每个神经元可以检测一个【特征】：
       "这个 token 是不是一个人名？"
       "上下文是不是在讨论数学？"
       "这个位置需不需要一个动词？"

   然后 W_down 根据激活了哪些特征，决定往残差流写什么
```

> 🔑 **用 [03 章](03-残差流.md)的总线视角说得更准确**：
> ```
> W_up   的每一【行】  = 一个从残差流上【读取】的方向（"检测器"）
> W_down 的每一【列】  = 一个往残差流【写入】的方向（"结论"）
>
> FFN = 13824 个 [检测器 → 结论] 的规则，激活函数决定哪些规则被触发
> ```
> **这是一个非常有解释力的图景**：FFN 常被理解为**键值记忆**（key-value memory）——$W_{up}$ 是键，$W_{down}$ 是值，激活函数决定匹配度。可解释性研究确实找到了很多这样的"事实神经元"。

## 9.2 激活函数的演化

```
┌── ReLU (2010) ────────────────────────────────────┐
│   f(x) = max(0, x)                                 │
│                    ╱                               │
│   ────────────────●                                │
│                                                    │
│   ✅ 极简、极快   ❌ x<0 时梯度恒为 0（神经元"死亡"） │
│                   ❌ 在 0 处不可导                   │
└────────────────────────────────────────────────────┘

┌── GELU (2016) ────────────────────────────────────┐
│   f(x) = x · Φ(x)      Φ 是标准正态的累积分布函数    │
│                    ╱                               │
│   ──────────╲___╱                                  │
│              ↑ 负半轴有个小凹陷，不是硬截断           │
│   ✅ 平滑可导  ✅ GPT/BERT 时代的标准                 │
└────────────────────────────────────────────────────┘

┌── SiLU / Swish (2017) ────────────────────────────┐
│   f(x) = x · σ(x) = x / (1 + e^{−x})               │
│   ✅ 和 GELU 形状几乎一样，但【算得更快】             │
│      （只需要一个 sigmoid，不需要 erf）              │
│   ★ 现在的事实标准                                  │
└────────────────────────────────────────────────────┘
```

**SiLU 的形状**：

```
       f(x)
        ▲
      3 ┤                          ╱
      2 ┤                       ╱
      1 ┤                    ╱
      0 ┼───────────────╱──────────────→ x
     -1 ┤      ╲____╱
        └────┬────┬────┬────┬────
           -4   -2    0    2    4
              ↑ 最小值 ≈ −0.278 @ x ≈ −1.278
```

> 📌 **注意负半轴那个小凹陷**：它意味着**中等负值的输入会得到一个小的负输出**，而**很负的输入趋近 0**。这给了模型一个"软的"抑制机制，比 ReLU 的硬截断信息量大。

## 9.3 GLU：加一个门

**GLU（Gated Linear Unit）是这一代 FFN 的标配。它的改动是：把 $x$ 投影两次，一份过激活当"门"，一份不过激活当"内容"，然后逐元素相乘。**

$$\text{SwiGLU}(x) = W_{\text{down}}\Big(\underbrace{\text{SiLU}(W_{\text{gate}}\,x)}_{\text{门：开多大}}\ \odot\ \underbrace{W_{\text{up}}\,x}_{\text{内容：传什么}}\Big)$$

```
              ┌──── W_gate ──→ SiLU ──┐
    x  [5120]─┤                        ⊙  ──→ W_down ──→ y [5120]
              └──── W_up ─────────────┘
                                       ↑
                              逐元素相乘（element-wise）

    门 ≈ 0  →  这个通道被【关闭】，内容传不过去
    门 ≈ 1  →  内容原样通过
    门 < 0  →  内容被【反向】传递
```

### 为什么门控有用

```
① 标准 FFN：act(W·x) —— 一个神经元是否激活，只取决于【一个】线性投影
② GLU：     两个独立的投影，一个决定"传不传"，一个决定"传什么"
   → 【乘法交互】。乘法比加法的表达力强得多：
      加法只能叠加特征，乘法可以表达"条件"和"选择"

   这和 LSTM 的门控、[08 章](08-高效注意力.md) delta rule 的遗忘门是同一种思想
```

**实证上 SwiGLU 稳定优于 ReLU/GELU FFN**（Noam Shazeer 的原论文里做了完整的消融）。**五家全部用 GLU 系。**

### ⚠️ 那个奇怪的 2/3 因子

**GLU 有【三个】矩阵（$W_{gate}, W_{up}, W_{down}$），而标准 FFN 只有两个。** 为了参数量公平对比：

$$3\,d\,d_{ff}^{\text{GLU}} = 2\,d\,d_{ff}^{\text{标准}}\quad\Longrightarrow\quad d_{ff}^{\text{GLU}} = \tfrac{2}{3}\,d_{ff}^{\text{标准}}$$

```
    标准 FFN 的惯例：d_ff = 4d
    GLU 版本：      d_ff = (2/3) × 4d = 8d/3 ≈ 2.67d

    d = 5120  →  d_ff ≈ 13653  →  取整到 128 的倍数 → 13824
```

> 🔑 **这就是你在配置文件里看到 `intermediate_size: 13824` 这种"奇怪"数字的原因。**
> 它不是随便定的，是 $\frac{8}{3}d$ 向上对齐到硬件友好的倍数。

## 9.4 ⚠️ SwiGLU 的一个大麻烦：它无界

**这一节是本章最重要的部分，它连着 [14 量化](14-量化.md)。**

### 问题

```
    SwiGLU(x) = SiLU(W_g x) ⊙ (W_u x)

    ① SiLU 在正半轴是【线性增长】的：SiLU(100) ≈ 100
    ② W_u x 也是【无界】的线性投影
    ③ 两个无界的东西【相乘】 → 输出可以到 【平方级别】的大

    输入 100 → 输出可能到 10,000
```

**再叠加 [05 章 §5.5](05-注意力机制.md) 那条链**（softmax 和为 1 → attention sink → 巨大激活），FFN 的输入本来就可能带着离群值进来，**经过 SwiGLU 的乘法会被平方放大**。

### 后果

```
① 训练不稳定：偶发的巨大激活 → loss spike → 甚至 NaN
② ★ 量化崩溃：一个 10,000 的离群值和一堆 0.1 的正常值在同一个量化组里
   → 量化区间被离群值撑满 → 正常值全部塌成 0
   → 详见 [14 章 §14.6](14-量化.md)
```

### 解法一：硬截断（clamp）

$$\text{clamp}(z, -c, +c) = \min(\max(z, -c), +c)$$

> ✅ **DeepSeek-V4：SwiGLU 输出 clamp 到 $[-10, 10]$**
> ✅ **MiniMax M3：clamp 到 $7.0$**

```
✅ 极简，几乎零开销
✅ 硬保证了上界 → 量化区间可控
❌ 截断处梯度为 0 → 被截断的通道"学不动"了
❌ 不平滑，理论上不优雅
```

### 解法二：软饱和 —— Kimi K3 的 SiTU-GLU

> ✅ **K3 报告给出的完整形式**：
> $$\text{SiTU-GLU}(x) = \Big[\beta_1\tanh\!\left(\tfrac{W_g x}{\beta_1}\right)\odot\sigma(W_g x)\Big]\ \odot\ \beta_2\tanh\!\left(\tfrac{W_u x}{\beta_2}\right)$$
> **参数：$\beta_1 = 4$，$\beta_2 = 25$。**

**逐块拆解**：

```
① β₁·tanh(z/β₁)     ← 把 z 【软性地】限制在 (−β₁, +β₁) = (−4, 4)
                       ★ 关键：|z| 很小时 tanh(z/β)·β ≈ z，几乎不改变
                                |z| 很大时饱和到 ±β₁

② ⊙ σ(W_g x)        ← 这就是 SiLU 的 sigmoid 部分（门）
   ①②合起来 ≈ 一个【有界版本的 SiLU】，上界 4

③ β₂·tanh(W_u x/β₂) ← 内容分支也软性限制在 (−25, 25)
```

$$\Rightarrow\quad |\text{SiTU-GLU}(x)| \le \beta_1\times\beta_2 = 4\times 25 = \boxed{100}$$

```
    ★★ 输出被【硬性数学保证】在 [−100, 100] 之内 ★★

    ✅ 处处平滑可导，没有梯度为 0 的死区（tanh 的导数处处 > 0）
    ✅ 小值区几乎恒等 —— 正常范围内的行为和 SwiGLU 一样
    ✅ 大值区软饱和 —— 离群值被自动压住，但仍保留大小顺序
```

### 对比

```
        clamp（V4/M3）              SiTU-GLU（K3）
              ┌────                       ┌──────
             ╱│                          ╱
    ────────╱ │              ────────╱‾‾
           ╱  │                     ╱
      ────┘   ▲                ────┘
              截断处梯度=0        处处可导，软饱和

    简单、够用                复杂、更优雅、上界更精确可控
```

> 🔑 **为什么 K3 值得做这么复杂的东西**：见下一节的因果链。

## 9.5 ★ 一条完整的因果链

**这条链把 09 章和 14 章连起来了，是全教程最有价值的推论之一。**

```
    ① 想把模型量化到 【4-bit】（省 4 倍显存和带宽）
             ↓
    ② 4-bit 只有 16 个量化档位，PTQ（训练后量化）在这个精度下必崩
       → 【必须用 QAT】（量化感知训练，训练时就模拟量化）
             ↓
    ③ QAT 期间，任何一个巨大的离群值都会毁掉整个量化组
       （详见 [14 章 §14.6](14-量化.md) 的手算例子）
             ↓
    ④ 而 SwiGLU 是【无界】的，且是两个无界量相乘（平方放大）
       → 它是离群值最大的产地
             ↓
    ⑤ ★ 所以：【必须给激活函数加界】
             ↓
    ⑥ 加界的两种方式：硬截断（简单）/ 软饱和（优雅）
```

### 反向验证：用这条链去看五家

| | 激活函数处理 | 量化目标 | 是否吻合 |
|---|---|---|---|
| **Kimi K3** | **SiTU-GLU**（软饱和，界 = 100） | **MXFP4 QAT**，贯穿 SFT 到 RL | ✅ 目标最激进 → 处理最讲究 |
| **DeepSeek-V4** | SwiGLU + **clamp [−10, 10]** | **FP4** 存 + FP8 算 | ✅ 目标激进 → 加了界 |
| **GLM-5.2** | SwiGLU | **INT4**（MoE）+ W8A8 QAT | ✅ 有 4-bit 目标 |
| **MiniMax M3** | SwiGLU + **clamp 7.0** | **MXFP8** | ✅ 只到 8-bit，但仍加了界 |
| **openPangu-2.0-Pro** | ❓ **报告中完全没提** | **W8A8**（疑似 PTQ） | ⚠️ 见下 |

### ⚠️ openPangu 那个空格

> **一个已核对的事实**：openPangu-2.0-Pro 技术报告中，`SwiGLU` / `GLU` / `SiLU` / `激活函数` 这几个关键词的命中次数是 **0**。

```
    这有两种可能的解读：

    ① 它就是用的标准 SwiGLU，因为太常规所以没写
    ② 它确实没做任何激活函数的加界处理
```

> ⚠️ **我倾向于第二种，但这只是推断，华为报告没有任何相关表述。** 理由是那条因果链的**反向**：
>
> ```
> openPangu 的量化目标只到 【W8A8】（8-bit），而且疑似是 PTQ 而非 QAT
>          ↓
> 8-bit 有 256 个档位，对离群值的容忍度比 4-bit 高【16 倍】
>          ↓
> ★ 所以它【不需要】给 SwiGLU 加界 —— 那个空格是自洽的
> ```
>
> **⚠️ 再次强调：这是一个自洽的解释，不是被验证的因果。** 也完全可能只是报告没写。

> 📌 但这个视角本身是有用的：**当你看到一份报告在某个位置什么都没做，去看它在下游的目标是什么，往往能解释得通。**

## 9.7 本章小结

```
① FFN = 先扩张到 2.7d，过激活，再压缩回 d。对每个 token 独立
   总线视角：W_up 的行是【检测器】，W_down 的列是【结论】
   → 常被理解为"键值记忆"
② 激活函数演化：ReLU → GELU → SiLU（x·σ(x)，形状同 GELU 但更快）
③ GLU 门控：两个投影，一个当门一个当内容，逐元素相乘
   乘法交互比加法表达力强 → 实证稳定优于普通 FFN，五家全用
   三个矩阵 → d_ff 要乘 2/3 才公平 → 8d/3 ≈ 13824 这个"怪"数字的由来
④ ★ SwiGLU 是【无界】的，且两个无界量相乘 → 离群值的主要产地
   解法一：clamp（V4 [−10,10]，M3 7.0）—— 简单，但截断处梯度为 0
   解法二：SiTU-GLU（K3）—— β₁tanh(·/β₁)⊙σ ⊙ β₂tanh(·/β₂)
           β₁=4, β₂=25 → 数学保证 |输出| ≤ 100，且处处可导
⑤ ★ 因果链：想要 4-bit → 必须 QAT → 必须治离群值 → 必须给激活加界
   反向看，openPangu 只做 8-bit（容忍度高 16 倍），所以那个空格是自洽的
   ⚠️ 但这是我的推断，报告没这么说
```
