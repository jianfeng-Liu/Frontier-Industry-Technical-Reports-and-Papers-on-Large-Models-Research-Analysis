11 · 位置编码：RoPE 与长度外推

这一章的目标：讲清模型怎么知道词的顺序，以及"4K 训练怎么推到 1M"这件事到底是怎么做到的。
读完你应该能回答：RoPE 为什么是旋转？那个漂亮的相对位置性质怎么证？base 这个超参在控制什么？PI / NTK-aware / YaRN 三种外推法的区别？以及 Kimi K3 为什么敢完全不用位置编码（NoPE）？

11.1 为什么需要位置编码

回到 05 章的公式：

$$O_i = \sum_j \text{softmax}_j(q_i^\top k_j)\,v_j$$

    ★ 这个式子里【完全没有位置信息】

    "小明打了小红"  和  "小红打了小明"
    → 两句话的 token 集合完全一样
    → 如果不注入位置，注意力的输出【一模一样】

注意力是"置换等变"的：把输入顺序打乱，输出也只是跟着打乱，内容完全不变。这对语言是灾难性的。

📌 对比一下：RNN 天然有顺序（一步一步走），CNN 天然有局部位置（卷积核的相对位置）。只有注意力是完全无序的——这是它"任意两点一步可达"（01 章）的代价。

11.2 三代方案

┌── ① 绝对位置编码（原始 Transformer, 2017）──────────────┐
│                                                          │
│   x_i ← x_i + PE(i)      在 embedding 上【加】一个位置向量  │
│                                                          │
│   PE 可以是学出来的，也可以是正弦函数                       │
│                                                          │
│   ❌ 学出来的：训练时见过多长，就只能用多长（硬上限）        │
│   ❌ 加在 embedding 上，位置信息会随着层数【被冲淡】         │
│   ❌ 模型学的是"第 5 个位置"，而不是"隔了 3 个词"           │
│      → 泛化差：训练时"隔 3 个词"的模式在位置 5 和位置 500    │
│        要分别学两遍                                        │
└──────────────────────────────────────────────────────────┘

┌── ② 相对位置编码（T5 等）────────────────────────────────┐
│                                                          │
│   直接在注意力分数上加一个偏置 b(i−j)                       │
│   ✅ 只依赖【相对距离】，泛化好                             │
│   ❌ 要显式构造一个 [L, L] 的偏置矩阵 → 和 FlashAttention   │
│      冲突，长序列开销大                                    │
└──────────────────────────────────────────────────────────┘

┌── ③ RoPE（2021）★ 现在的绝对主流 ────────────────────────┐
│                                                          │
│   不加任何东西，而是把 q 和 k 【旋转】一个角度              │
│   ✅ 形式上是绝对的（每个位置独立旋转），                    │
│      效果上是相对的（内积只依赖 i−j）                       │
│   ✅ 不需要 [L,L] 矩阵，和 FlashAttention 完全兼容          │
└──────────────────────────────────────────────────────────┘

    五家全部用 RoPE 系（K3 除外，见 §11.7）

11.3 RoPE：把向量转个角度

二维的情形

先只看两个维度。位置 $m$ 处的向量 $(q_0, q_1)$，旋转角度 $m\theta$：

$$\begin{pmatrix}q_0'\ q_1'\end{pmatrix} = \underbrace{\begin{pmatrix}\cos m\theta & -\sin m\theta\ \sin m\theta & \cos m\theta\end{pmatrix}}_{R_m}\begin{pmatrix}q_0\ q_1\end{pmatrix}$$

              位置 0            位置 1            位置 2
                ↑ q               ↗                →
                │              旋转 θ            旋转 2θ
                │             ╱                ╱
                ●            ●                ●

    ★ 向量的【长度不变】，只有【方向】随位置转动

那个漂亮的性质

$$\langle R_m q,\ R_n k\rangle = (R_m q)^\top(R_n k) = q^\top R_m^\top R_n\,k = q^\top R_{n-m}\,k$$

因为旋转矩阵满足 $R_m^\top = R_{-m}$ 且 $R_a R_b = R_{a+b}$（旋转是一个群）。

$$\boxed{\ \langle R_m q,\ R_n k\rangle = \langle q,\ R_{n-m}k\rangle\ }$$

    ★★★ 内积【只依赖 n − m】，与 m、n 的绝对值无关 ★★★

    "位置 5 和位置 8"  与  "位置 1005 和位置 1008"
    → 注意力分数完全相同

    这就是"形式绝对、效果相对"的含义

🔑 这是 RoPE 全部魅力的来源：它用一个逐位置独立的操作（好实现、好并行、和 FlashAttention 兼容），实现了相对位置的效果（泛化好）。

复数形式：更简洁

把 $(q_0,q_1)$ 看成复数 $q_0 + iq_1$，旋转就是乘一个单位复数：

$$\text{RoPE}(q, m) = q\cdot e^{im\theta},\qquad \langle q e^{im\theta},\ k e^{in\theta}\rangle = \text{Re}!\left[q\bar{k}\,e^{i(n-m)\theta}\right]$$

旋转 = 乘 $e^{i\theta}$，两次旋转 = 指数相加。 群性质在复数形式下一目了然。

11.4 高维：多个频率

一个头有 $d_h$（比如 128）维，两两配对成 $d_h/2$ 组，每组用不同的旋转频率：

$$\theta_i = \text{base}^{-2i/d_h},\qquad i = 0, 1, \ldots, d_h/2 - 1$$

base 通常是 10000（原始设定）。

    i = 0：   θ_0 = 10000^0    = 1           ← 转得最快，周期 ≈ 6.3 个 token
    i = 1：   θ_1 = 10000^{-2/128} ≈ 0.87
    ⋮
    i = 63：  θ_63 = 10000^{-126/128} ≈ 0.00011   ← 转得最慢，周期 ≈ 57000 个 token

    维度对 0-1    ●→●→●→●→●→●→●    高频：区分【相邻】的词
    维度对 2-3    ●─→●─→●─→●
    维度对 4-5    ●──→●──→●
        ⋮
    维度对 126-127 ●─────────→      低频：区分【很远】的词
                                    在整个上下文里可能还没转完一圈

🔑 这就像时钟：秒针（高频）分辨秒，时针（低频）分辨小时。多个频率叠加，就能唯一地表示一个很大的位置范围。

def rope(x, pos, base=10000.0):
    d = x.shape[-1]
    i = np.arange(0, d, 2)
    theta = base ** (-i / d)                  # [d/2]
    ang = pos * theta                          # [d/2]
    x0, x1 = x[..., 0::2], x[..., 1::2]        # 偶数位、奇数位配对
    return np.stack([x0*np.cos(ang) - x1*np.sin(ang),
                     x0*np.sin(ang) + x1*np.cos(ang)], -1).reshape(x.shape)

11.5 长度外推：4K 训练怎么用到 1M

问题

    模型在 4K 上训练 → 只见过 m−n ∈ [0, 4096] 的旋转角度
    直接用到 128K   → 出现了从未见过的角度
        ↓
    ★ 注意力分数完全失控，模型输出崩坏

这是一个被反复验证的现象：不做任何处理，超出训练长度后困惑度会指数爆炸。

方法一：位置插值（PI, Position Interpolation）

思路：把位置"压缩"回训练范围内。

$$m \leftarrow m\cdot\frac{L_{\text{train}}}{L_{\text{target}}}$$

    训练 4K，目标 128K，缩放因子 = 1/32

    位置 128000 → 当作位置 4000 来算

    ✅ 所有角度都落回见过的范围，不会崩
    ❌ ★ 相邻 token 的角度差被压缩了 32 倍
       → 高频维度几乎【分辨不出相邻的词】
       → 局部精度严重损失，需要额外微调才能恢复

方法二：NTK-aware 缩放

核心洞察：不该对所有频率一视同仁地压缩。

    ★ 高频维度（区分相邻词）：训练时【见过完整的周期】，不需要压缩
    ★ 低频维度（区分远距离）：训练时【连一圈都没转完】，是它们在外推

    → 只压低频，不压高频

实现上非常简单：不改位置，改 base。

$$\text{base} \leftarrow \text{base}\times s^{\frac{d_h}{d_h-2}},\qquad s = \frac{L_{\text{target}}}{L_{\text{train}}}$$

    因为 θ_i = base^{−2i/d_h}：

    base 变大 →  i=0（高频）：θ_0 = base^0 = 1，【完全不变】 ★
                 i 大（低频）：θ_i 显著变小 → 转得更慢 → 能覆盖更长范围

    ★★ 一个超参就实现了"高频不动、低频拉伸"的分段效果 ★★

🔑 NTK-aware 的优雅之处：它不需要改任何代码，只需要改一个数字。

方法三：YaRN

NTK-aware 的精细化版本，把维度显式分成三段：

    ① 高频段（训练时转过 > 1 圈）  → 完全不动
    ② 低频段（训练时不到 1 圈）    → 按 PI 方式插值
    ③ 中间段                      → 平滑过渡（斜坡插值）

    + 另加一个【注意力温度】修正：
      logits 乘一个略大于 1 的常数，补偿长序列下 softmax 被摊薄的效应

YaRN 通常效果最好，但超参最多。

三者对比

改什么 高频 低频 需要微调
PI 位置 $m$ 被压缩 ❌ 被压缩 ✅ 需要
NTK-aware base 不变 ✅ 被拉伸 ✅ 少量或不需要
YaRN 分段处理 base + 温度 不变 ✅ 插值 ✅ 少量

11.6 ✅ openPangu 的 base 阶梯：实际工程是怎么做的

真实的做法不是"训完再外推"，而是【边训边逐步拉长，每一档配一个 base】。

openPangu-2.0-Pro 报告给出的完整阶梯：

训练阶段的上下文长度 RoPE base
4K 10,000
8K 100,000
32K 400,000
128K 1,600,000
512K 6,400,000 
    观察这个数列：

    4K → 8K     长度 ×2      base ×10
    8K → 32K    长度 ×4      base ×4
    32K → 128K  长度 ×4      base ×4
    128K → 512K 长度 ×4      base ×4

    ★ 后三档是【严格的 base ∝ 长度】的线性关系

🔑 这就是 NTK-aware 思想的工程落地：
不做一次性的大跨度外推（那样必崩）， 而是【分 5 个阶段渐进拉长】，每一阶段： ① 按新长度调大 base ② 在新长度上【继续训练】一段，让模型适应新的角度范围 ↓ ★ 每一步的外推倍数都很小（2~4×），模型有机会真正学会

📌 注意第一跳 4K→8K 的 base 涨了 10 倍，明显超过长度的 2 倍。 ⚠️ 报告没有解释原因，我推测是为了给后续阶段留出更宽的低频覆盖余量，但这只是猜测。

11.7 ✅ Kimi K3 的 NoPE：干脆不要位置编码

K3 报告：不使用位置编码（NoPE, No Positional Encoding）。

这怎么可能

回忆 §11.1：注意力是置换等变的，没有位置编码应该完全无序。

但那个论证漏了两件事：

① ★ 因果掩码本身就携带位置信息！
   位置 i 能看到 i 个 token，位置 i+1 能看到 i+1 个
   → 每个位置"能看到多少东西"是不同的
   → ★ 模型可以从"可见集合的大小"反推出自己的绝对位置

   已有理论工作证明：带因果掩码的 Transformer 【可以】学出位置信息

② ★ K3 是 KDA + MLA 【3:1 混合】的（[08 章](08-高效注意力.md)）
   KDA 是【线性注意力】，它是一个 RNN：S_t = f(S_{t−1}, k_t, v_t)
   → ★★ 递归结构【天然有顺序】，位置信息是内建的 ★★

🔑 所以 K3 的 NoPE 不是"大胆"，是【它的架构本来就不需要】：
3/4 的层是 KDA（RNN，自带顺序） 1/4 的层是 MLA（靠因果掩码隐式获得位置） ↓ ★ 位置信息已经从两个渠道进来了，再加 RoPE 是冗余的

白赚的好处

✅ 彻底没有长度外推问题 —— 没有 RoPE 就没有"没见过的角度"
   → 这是 K3 敢标 1M 上下文的一个底气
✅ 和 MLA 的矩阵吸收【完全兼容】
   → 回忆 [07 章 §7.5](07-MHA到MLA.md)：RoPE 破坏矩阵吸收，
     必须做 decoupled RoPE 这个补丁
   → ★ NoPE 直接把这个问题消灭了，MLA 的 1/4 层可以完整吸收
✅ 省掉 RoPE 的计算和那 64 维的解耦 KV

📌 这是全教程里我最喜欢的一个设计：K3 在 08 章选了线性注意力，副作用是在本章白赚了一个"不需要位置编码"。架构决策之间是有耦合的，好的组合会产生额外收益。

11.8 Partial RoPE：只给一部分维度加

除 K3 外的四家都用 "Partial RoPE"：只对每个头的一部分维度施加 RoPE，其余维度保持不变。

    q  [128 维]
    ├── 前 64 维：加 RoPE      ← 携带位置信息
    └── 后 64 维：不加         ← 纯内容信息，与位置无关

为什么：

① 有些语义匹配【本来就不该依赖位置】
   "这段话在讲数学" 这个判断，和它在第几个 token 无关
   → 强行给所有维度加位置旋转，会污染这类纯语义匹配

② ★ 和 MLA 的兼容性（[07 章 §7.5](07-MHA到MLA.md)）
   不加 RoPE 的部分 → 可以矩阵吸收
   加 RoPE 的部分   → 走 decoupled 通路，单独存
   → openPangu 的 512（压缩，无 RoPE）+ 64（解耦，有 RoPE）就是这个结构

③ 长度外推更容易：只有一部分维度需要处理

11.9 挂回五家

位置编码 关键配置
DeepSeek-V4 Partial RoPE ★ 只转最后 64 维；⚠️ 和 MLA 无关（V4 不用 MLA），是配合 CSA/HCA 的压缩 KV，见下方 ⭐
Kimi K3 ⭐ NoPE KDA 的递归 + 因果掩码提供位置
GLM-5.2 Partial RoPE —
MiniMax M3 Partial RoPE —
openPangu-2.0-Pro Partial RoPE ⭐ base 五级阶梯：10K@4K → 100K@8K → 400K@32K → 1.6M@128K → 6.4M@512K

⭐ DeepSeek-V4 那一格值得单独讲一下，因为它有一个别家没有的动作。

⚠️ 先纠正一个很容易犯的错（我自己先前就写错过）：V4 已经不用 MLA 了——它的报告全文没有出现过 "MLA"，注意力是 CSA + HCA，内核是共享 KV 的 MQA（见 08 章）。所以 V4 的 partial RoPE 不是"配合 MLA 的 decoupled 结构"，它解决的是另一个问题。

```
✅ 报告原文（§2.3 Partial Rotary Positional Embedding）：
"for each query vector and KV entry vector used in CSA and HCA,
we apply RoPE to its last 64 dimensions"
→ 只有最后 64 维被旋转，其余维度不带位置信息

★★ 真正特别的是下面这一步 —— 先看问题出在哪：

CSA / HCA 把每 ℓ 个 token 的 KV 压成【一条】KV entry，
而这一条 entry ★【同时充当 key 和 value】（共享 KV 的 MQA）。

key 那一路：q 和 k 做内积 → RoPE 的相对性成立 ✅
value 那一路：⚠️ 输出 o_t = Σ(权重 × KV entry)，是一堆
【已经带了绝对位置旋转】的向量加权求和
→ ★ 于是输出里混进了【绝对位置】，而不是相对位置

✅ 报告原话：the naive core attention outputs "will carry absolute
position embeddings, derived from the weighted sum of KV entries"

✅ V4 的解法：给【输出】再补一次【位置为 −t 的】RoPE，转回去
（t = 当前 query 的位置；⚠️ 提取版 PDF 里下标字符有乱码，
但 "apply RoPE with position −t on the last 64 dimensions of each o"
这句话本身是清楚的）

效果（报告原文）：输出也变成【相对】位置编码 ——
"the contribution of each KV entry to the core attention outputs
will also be related to the distance between the query and the KV entry"
```

🔑 一句话理解：R_{−t} 把 R_位置 抵消成 R_位置−t，也就是距离。
这和 §11.3 那个核心性质 $\langle R_m q, R_n k\rangle = \langle q, R_{n-m}k\rangle$ 是同一个群性质（$R_a R_b = R_{a+b}$），只不过 V4 把它从 key 那一路搬到了 value 那一路上用。

★ 为什么只有 V4 需要这一步：因为只有它让同一条压缩 entry 同时当 key 和 value。别家的 value 是不带 RoPE 的，自然没有这个问题。

🔑 这一格的分歧其实是【上一章分歧的下游后果】：
谁用了线性注意力（K3）→ 谁就可以不用位置编码 谁用纯 softmax 注意力 → 谁就必须处理 RoPE + 长度外推
这再次说明：架构决策不是独立的旋钮，是一张互相约束的网。

11.10 本章小结

① 注意力是【置换等变】的，不注入位置就分不清"小明打小红"和"小红打小明"
   （RNN/CNN 天然有位置，只有注意力没有 —— 这是它"任意两点一步可达"的代价）
② RoPE = 把 q、k 按位置【旋转】一个角度，不改长度只改方向
   ★ 核心性质：⟨R_m q, R_n k⟩ = ⟨q, R_{n−m}k⟩ —— 内积只依赖相对距离
     证明只需要旋转矩阵的群性质 R_mᵀ = R_{−m}、R_a R_b = R_{a+b}
   → 形式绝对（好实现、兼容 FlashAttention），效果相对（泛化好）
③ 高维用多个频率 θ_i = base^{−2i/d_h}：高频分辨相邻，低频分辨远距离（像时钟）
④ 长度外推三法：
   PI        改位置，一刀切压缩 → 高频精度受损
   NTK-aware 只改 base → 高频不动、低频拉伸 ★ 一个数字就搞定
   YaRN      分三段 + 注意力温度，效果最好但超参最多
⑤ openPangu 的 base 五级阶梯就是 NTK-aware 的工程落地：
   分 5 段渐进拉长，每段外推倍数只有 2~4×，每段都继续训练适应
⑥ ★ K3 的 NoPE 不是冒险：
   因果掩码本身携带位置 + KDA 是 RNN 自带顺序
   → 白赚：没有外推问题 + 和 MLA 矩阵吸收完全兼容
⑦ Partial RoPE（其余四家）：只给一部分维度加，剩下的走矩阵吸收通路
   openPangu 的 512 + 64 就是这个结构

第三部分到此结束。 到这里，一个完整的模型你已经全部看过了。接下来三章讲的是"怎么让它跑得快、训得动"——这是这一代技术报告里篇幅最大、也最工程的部分。
