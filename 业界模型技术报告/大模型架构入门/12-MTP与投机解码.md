# 12 · MTP 与投机解码

> **这一章的目标**：MTP 这个词在五份报告里到处出现，但它其实身兼**两个完全不同的职责**——训练时是"更密的监督信号"，推理时是"免费的草稿模型"。大部分解读只讲了其中一个。**本章把两条线都走一遍。**
>
> 读完你应该能回答：投机解码为什么"完全不掉质量"（含四行完整证明）？接受长度那个数字怎么算？为什么 Medusa 的并行头不如 MTP 的串行模块？以及五家在这里的分歧到底在哪三处？

---

## 12.1 起点：decode 为什么慢得离谱

回到 [06 章](06-KV-cache.md)。生成文字时，模型是**一个 token 一个 token 吐**的，每吐一个都要把整整 50 层完整跑一遍：

```
跑完 50 层  →  吐出 "真"
跑完 50 层  →  吐出 "好"
跑完 50 层  →  吐出 "，"
       ↑
   完全串行，第 2 次必须等第 1 次结束才能开始
```

这里有一个**极其浪费**的事实。回忆 [06 章 §6.4](06-KV-cache.md) 的 roofline 分析：

```
decode 一步要做的事：
   ① 把 500B 的模型权重（或者 MoE 下激活的那 18B）从显存读进计算单元    ← 慢，受带宽限制
   ② 把 KV cache 从显存读进来                                          ← 慢，受带宽限制
   ③ 拿这些权重去乘 1 个 token 的向量                                   ← 快到可以忽略
```

**代价几乎全在"搬运"上，真正的"计算"几乎不花时间。**

于是出现一个很反直觉的性质：

```
一次前向处理  1 个 token  → 耗时 T
一次前向处理  5 个 token  → 耗时 ≈ T（几乎不变！）
                             因为权重只搬一次，多算 4 个 token 的乘法几乎是白送的
```

> 🔑 **这一条是整个投机解码的物理基础**：
> **"一次验证 5 个 token" 和 "一次生成 1 个 token" 花的时间几乎一样。**
>
> 换句话说：**GPU 在 decode 阶段大部分算力是空转的，我们有免费的算力可以拿来"猜"。**

## 12.2 核心洞察：出题很慢，判卷很快

```
生成（串行）              验证（并行）
  ┌───┐                  ┌───┬───┬───┬───┐
  │ ? │  必须一个一个来   │ 真│ 好│ ， │适合│  可以一次全部检查
  └───┘                  └───┴───┴───┴───┘
   慢                        和只检查 1 个一样快
```

**所以策略是**：找个便宜的东西先"猜"几个 token，再让大模型**一次性判卷**。

- 猜对了 → 白赚，这几个 token 一次前向就出来了
- 猜错了 → 从错的那个位置截断，用大模型自己的答案纠正，**一点损失都没有**（下面会证明）

---

## 12.3 投机解码的完整一轮

```
当前已生成： "今天天气"

┌─ 第 1 步：草稿（便宜、快） ────────────────────────────────┐
│  草稿模型连猜 4 个：  "真"  "好"  "，"  "适合"              │
│  同时记下它给每个 token 的概率 q(·)                        │
└───────────────────────────────────────────────────────────┘
                          │
┌─ 第 2 步：验证（贵，但只跑一次） ──────────────────────────┐
│  把 "今天天气" + "真好，适合" 一起送进大模型               │
│  一次前向，拿到 5 个位置上的真实分布 p(·)                  │
│                                                            │
│   位置1 (在"今天天气"后)  p → 大模型认为该出什么           │
│   位置2 (在"...真"后)     p                                │
│   位置3 (在"...真好"后)   p                                │
│   位置4 (在"...真好，"后) p                                │
│   位置5 (在"...真好，适合"后) p  ← 这个是"白送的下一个 token"│
└───────────────────────────────────────────────────────────┘
                          │
┌─ 第 3 步：逐位置裁决 ──────────────────────────────────────┐
│  "真"    p 也很高  → ✅ 接受                                │
│  "好"    p 也很高  → ✅ 接受                                │
│  "，"    p 也还行  → ✅ 接受                                │
│  "适合"  p 很低（大模型想说"出门"） → ❌ 拒绝               │
│          → 截断！后面的全部丢弃，从大模型的分布里重采一个   │
└───────────────────────────────────────────────────────────┘

本轮产出： "真" "好" "，" "出门"  =  4 个 token
本轮成本： 1 次大模型前向 + 4 次草稿模型前向（草稿模型很便宜）
                    ↑
              原本要 4 次大模型前向
```

**注意第 5 个位置那个"白送的 token"**：如果 4 个全接受，验证时位置 5 的输出可以直接当第 5 个 token 用。所以猜 $\gamma$ 个，**最好情况能产出 $\gamma+1$ 个**。

## 12.4 ★ 为什么"完全不掉质量"——拒绝采样的证明

这是投机解码最漂亮的部分，也是它和"小模型代打"的本质区别。**它有数学保证：输出分布和不用投机解码时逐 token 严格相同。**

**规则**（Leviathan et al. 2023）：设草稿分布 $q$、大模型真实分布 $p$，草稿采出了 token $x$：

$$
\begin{aligned}
&\textbf{接受概率：}\quad \min\left(1,\ \frac{p(x)}{q(x)}\right)\\[4pt]
&\textbf{若拒绝：}\quad \text{从"残差分布"重新采样}\quad p'(x) = \frac{\max\big(0,\ p(x)-q(x)\big)}{\sum_{x'}\max\big(0,\ p(x')-q(x')\big)}
\end{aligned}
$$

**直觉**：
- 草稿模型给某个词的概率**比大模型还低**（$q<p$）→ 无条件接受，因为它已经"保守"了
- 草稿给得**太高**（$q>p$）→ 按比例 $p/q$ 随机接受一部分，把多给的那部分退回去
- 拒绝时不能随便从 $p$ 采（那会重复计入已经被接受的质量），而要从"$p$ 比 $q$ 多出来的那块"采

**证明它等于 $p$**（只有四行）：

$$
\begin{aligned}
P(\text{输出 } x) &= \underbrace{q(x)\cdot\min\Big(1,\tfrac{p(x)}{q(x)}\Big)}_{\text{草稿采到 }x\text{ 且被接受}} \;+\; \underbrace{P(\text{拒绝})\cdot p'(x)}_{\text{拒绝后重采到 }x}\\[4pt]
&= \min\big(p(x),q(x)\big) \;+\; \beta\cdot\frac{\max(0,\,p(x)-q(x))}{\beta}\\[4pt]
&= \min(p,q)(x) + \max(0,\,p-q)(x)\\[4pt]
&= p(x) \qquad\blacksquare
\end{aligned}
$$

其中用到了一个恒等式：$P(\text{拒绝}) = 1-\sum_x\min(p,q)(x) = \sum_x\max(0,p-q)(x) = \beta$，**分母正好被约掉**。

```python
def verify_one_position(draft_token, q, p, rng):
    """q, p 都是长度为 V 的概率向量"""
    x = draft_token
    if rng.uniform() < min(1.0, p[x] / q[x]):
        return x, True                      # 接受
    residual = np.maximum(p - q, 0)
    residual = residual / residual.sum()    # 归一化残差分布
    return rng.choice(len(p), p=residual), False   # 拒绝，重采并截断
```

> 🔑 **一句话**：**投机解码是纯粹的加速，不是近似。** 草稿模型质量差只会让它"猜得少"（变慢），**永远不会让输出变差**。这也是为什么各家敢无条件在生产里开它。

## 12.5 能快多少：接受率与接受长度

**单步接受率** $\alpha$ 有一个非常干净的闭式：

$$\alpha = \mathbb{E}_x\big[\min(p,q)\big] = \sum_x \min\big(p(x),q(x)\big) = 1 - \mathrm{TV}(p,q)$$

**接受率 = 1 − 两个分布的总变差距离。草稿模型和大模型越像，接受率越高。**

一轮猜 $\gamma$ 个，**接受长度**（accept length，各家报告里的核心指标）的期望是等比数列求和：

$$\mathbb{E}[\text{accept length}] = \sum_{i=0}^{\gamma}\alpha^i = \frac{1-\alpha^{\gamma+1}}{1-\alpha}$$

代入感受一下：

```
α = 0.7, γ = 3  →  E = (1−0.7⁴)/0.3 = 2.53      每轮 2.53 个 token
α = 0.8, γ = 3  →  E = (1−0.8⁴)/0.2 = 2.95
α = 0.8, γ = 7  →  E = (1−0.8⁸)/0.2 = 4.16
α = 0.9, γ = 7  →  E = (1−0.9⁸)/0.1 = 5.70
```

**实际加速比**还要扣掉草稿模型的成本：

$$\text{speedup} \approx \frac{\mathbb{E}[\text{accept length}]}{1 + \gamma\cdot c},\qquad c = \frac{\text{草稿模型单步耗时}}{\text{大模型单步耗时}}$$

> 📌 **这就是为什么 GLM-5.2 报告里那个 "2.76" 是个有分量的数字**——它不是"猜了 3 个"，而是"**平均每轮真的产出 2.76 个 token**"，直接约等于解码吞吐翻 2.76 倍（再扣草稿开销）。
>
> 也解释了**为什么 $\gamma$ 不能无限加大**：$\alpha^i$ 是指数衰减的，猜到第 8 个时接受概率已经只有 $0.8^8=0.17$，**但草稿成本 $\gamma c$ 是线性增长的**。所以存在一个最优 $\gamma$。

## 12.6 草稿模型从哪来：四种方案的演化

现在问题变成：**这个"便宜又和大模型很像"的草稿模型，哪儿来？**

```
① 另训一个小模型（原始方案，2023）
   用同系列的 1B 模型给 500B 当草稿
   ✅ 简单     ❌ 要另外训一个模型；两个模型分布差得远，α 不高；还要多占显存

② Medusa（并行多头，2024）
   在主模型最后一层上挂 K 个独立的线性头，同时预测 t+1, t+2, t+3
        h ──┬──▶ head_1 → t+1
            ├──▶ head_2 → t+2       ← 三个头互相看不见
            └──▶ head_3 → t+3
   ✅ 极便宜   ❌ head_2 在预测 t+2 时不知道 t+1 是什么 → 猜得不准，α 低

③ EAGLE（在特征层面自回归，2024）
   草稿模型不预测 token，而是预测主模型的 hidden state，并且是自回归的
   ✅ α 高很多  ❌ 仍是一个需要单独训练的附加模块

④ MTP（Multi-Token Prediction，DeepSeek-V3 起成为标配）
   ⭐ 在预训练阶段就把"预测后面第 2、3 个 token"当成额外的训练目标
      于是草稿能力是**预训练顺带练出来的**，不用事后补训
```

### ⭐ MTP 是谁提的：一条四段的出处链

> ⚠️ **先纠正一个常见误解**：**MTP 不是 DeepSeek 发明的**，DeepSeek-V3 做的是**把它变成前沿大模型的标配**。
> ✅ 下面这条链不是我编的——**DeepSeek-V4 报告自己在正文里就是这么引的**：
> *"Multi-Token Prediction (MTP) [DeepSeek-AI, 2024; **Gloeckle et al., 2024**; Li et al., 2024; **Qi et al., 2020**]"*。

| 年份 | 谁 | 论文 | 贡献 |
|---|---|---|---|
| **2018-11** | Mitchell **Stern** 等（Google） | ✅ [arXiv:1811.03115](https://arxiv.org/abs/1811.03115) *Blockwise Parallel Decoding for Deep Autoregressive Models* | ★ **最早的源头**：一次预测多个位置、再回头验证，**投机解码的原型**就在这里 |
| **2020-01** | Weizhen **Qi** 等（微软） | ✅ [arXiv:2001.04063](https://arxiv.org/abs/2001.04063) *ProphetNet* | ★ 第一次把"**同时预测未来 n 个 token**"做成**预训练目标**（future n-gram prediction） |
| **2024-04** | Fabian **Gloeckle** 等（Meta） | ✅ [arXiv:2404.19737](https://arxiv.org/abs/2404.19737) *Better & Faster Large Language Models via Multi-token Prediction* | ★★ **"Multi-Token Prediction"这个名字和现代形态**：多个输出头共享主干，并指出它**顺带就是草稿模型** |
| **2024-12** | **DeepSeek-V3** | ✅ [arXiv:2412.19437](https://arxiv.org/abs/2412.19437) | ★★★ 改成**串行因果**的 MTP 模块（不是并行头）+ 在千亿级模型上验证，**此后五家全跟进** |

> 🔑 **DeepSeek 真正的增量是"③ → ④"那一步**：把 Gloeckle 的**并行多头**改成**串行因果模块**（下一段的对照图）。
> ★ 这也是为什么本教程把 MTP 放在投机解码这一章讲——**它的两个身份（提升基座 / 当草稿）从出处上就是分开来的两条线，在 V3 这里合流。**

**②→④ 最关键的一处进化，是从"并行"变成"串行（因果）"**：

```
Medusa（并行）                        MTP（串行 / 因果）
  h ──┬─▶ t+1                          h ─▶[模块1]─▶ t+1
      ├─▶ t+2  ← 不知道 t+1                     │ 把真实的 t+1 喂进来
      └─▶ t+3  ← 不知道 t+1, t+2                ▼
                                             [模块2]─▶ t+2   ← 知道 t+1 是什么
                                                  │
                                                  ▼
                                             [模块3]─▶ t+3   ← 知道 t+1, t+2
```

**MTP 的每个模块都能看到前面模块"应该"产出的 token**，所以预测质量高得多，接受率 $\alpha$ 也就高得多。代价是这几个模块必须**顺序执行**，不能并行——但它们每个只有 1 层，很便宜。

## 12.7 MTP 到底长什么样

> DeepSeek-V3 的定义，五家都在这个基础上改。

**先明确一件事：MTP 模块不是"一个头"，而是"一个完整的 Transformer 层"。**

```
             ┌──────────────────────────────────────────────┐
             │            主模型（50~93 层）                 │
             └───────────────────┬──────────────────────────┘
                                 │  h_i⁰ = 第 i 个位置的最终 hidden state
        ┌────────────────────────┼───────────────────────────┐
        │                        │                           │
        ▼                        ▼                           ▼
  [共享输出头]            ┌─ MTP 模块 1 ─┐            （主模型自己的输出）
        │                 │              │
        ▼                 │  ① 拼接：     │
     预测 t_{i+1}         │  h_i⁰  ⊕  Emb(t_{i+1})  ← 把"下一个真实 token"喂进来
     （主任务）            │     ↓ 各自先 RMSNorm     │
                          │  ② 投影 M₁：2d → d       │
                          │     ↓                    │
                          │  ③ 一个完整的 Transformer 层 │
                          │     （注意力 + FFN）      │
                          │     ↓ h_i¹               │
                          │  ④ 送进【共享的】输出头   │
                          └──────┬───────────────────┘
                                 ▼
                            预测 t_{i+2}
                                 │  h_i¹ 继续往下传
                                 ▼
                          ┌─ MTP 模块 2 ─┐
                          │  h_i¹ ⊕ Emb(t_{i+2})  │
                          │      ... 同样结构 ...  │
                          └──────┬───────────────┘
                                 ▼
                            预测 t_{i+3}
```

**公式**（$k$ 表示第 $k$ 个 MTP 模块，$k=0$ 是主模型）：

$$
\begin{aligned}
h_i^{\prime k} &= M_k\Big[\ \mathrm{RMSNorm}\big(h_i^{k-1}\big)\ ;\ \mathrm{RMSNorm}\big(\mathrm{Emb}(t_{i+k})\big)\ \Big] &&\text{拼接后投影，}M_k\in\mathbb{R}^{d\times 2d}\\
h_{1:L-k}^{k} &= \mathrm{TRM}_k\big(h_{1:L-k}^{\prime k}\big) &&\text{过一个完整的 Transformer 层}\\
P_{i+k+1}^{k} &= \mathrm{OutHead}\big(h_i^{k}\big) &&\text{共享输出头，得到词表分布}
\end{aligned}
$$

**三个必须记住的设计要点**：

| 要点 | 内容 | 为什么 |
|---|---|---|
| **Embedding 和输出头是共享的** | 所有 MTP 模块和主模型用同一份 `Emb` 和 `OutHead` | 这两块参数最大（各 ~8 亿，见 [02 章](02-Embedding与词表.md)），复制 D 份显存吃不消；共享还能保证草稿和主模型"说同一种语言" |
| **每个模块有自己独立的 `M_k` 和 `TRM_k`** | 模块 1 和模块 2 的 Transformer 层参数不同 | 预测"下一个"和预测"下下个"是两个不同难度的任务 |
| **训练时喂的是真实 token（teacher forcing）** | $\mathrm{Emb}(t_{i+k})$ 用的是训练数据里的真值 | 和主模型的训练方式一致；推理时才换成"上一模块自己猜的" |

```python
def mtp_forward(h_main, tokens, modules, emb, out_head):
    """h_main: 主模型输出 [L, d]；返回 D 个额外的预测分布"""
    h, preds = h_main, []
    for k, mod in enumerate(modules, start=1):
        tok_emb = emb[tokens[k:]]                       # 第 i 个位置取 t_{i+k}
        cat = np.concatenate([rmsnorm(h[:-k]), rmsnorm(tok_emb)], axis=-1)
        h = transformer_layer(cat @ mod.M, mod.params)  # [L-k, d]
        preds.append(h @ out_head.T)                    # 预测 t_{i+k+1}
    return preds
```

## 12.8 训练目标

每个 MTP 深度算一份自己的交叉熵，再加权并进总损失：

$$\mathcal{L}_{\text{MTP}}^{k} = -\frac{1}{L}\sum_{i=1}^{L-k}\log P_{i+k+1}^{k}\big[t_{i+k+1}\big],\qquad \mathcal{L} = \mathcal{L}_{\text{main}} + \lambda\cdot\frac{1}{D}\sum_{k=1}^{D}\mathcal{L}_{\text{MTP}}^{k}$$

$\lambda$ 通常取 0.1~0.3——**主任务永远是主角，MTP 只是配角**，否则会伤害主模型质量。

## 12.9 ★ MTP 的两个身份（这一点最容易被漏掉）

```
身份 A：训练时 —— 一个更密的监督信号
   普通训练：每个位置只被教一件事 "下一个词是什么"
   开 MTP  ：每个位置同时被教 D+1 件事 "接下来 D+1 个词分别是什么"

   效果：迫使模型在 h_i 里编码更长程的规划信息，而不是只做"局部续写"
   ⭐ 关键：即使推理时完全不用投机解码，MTP 也能让主模型本身变好
        （DeepSeek-V3 报告的消融就是这么说的：MTP 一致地改善了大多数评测）

身份 B：推理时 —— 一个免费的草稿模型
   那 D 个 Transformer 层拿来就是现成的草稿器，零额外训练成本
   不想用可以直接丢掉，主模型完全不受影响
```

> 🔑 **所以 MTP 是那种少见的"两头都赚"的设计**：训练时它是正则化/更强的监督，推理时它是加速器。**这是它三年内变成所有前沿模型标配的原因。**

## 12.10 推理时怎么用：链式 vs 树形

```
链式（chain，最常见）
    模块1 猜 "真" → 模块2 拿着"真"猜 "好" → 模块3 拿着"真好"猜 "，"
    一次验证 3+1 个位置

树形（tree / Medusa 式，把免费算力用满）
    模块1 猜出 top-2:  "真" / "很"
                        ├─ "真" → 模块2 猜 top-2: "好" / "不错"
                        └─ "很" → 模块2 猜 top-2: "热" / "冷"
    一次验证一整棵树（用特制的树形注意力掩码，让每条路径只看到自己的祖先）
    ✅ 接受长度更高    ❌ 掩码复杂、验证的 token 数变多
```

## 12.11 一个真实存在的坑：训练深度 ≠ 推理深度

**DeepSeek-V3 的 MTP 深度是 1（只训了 1 个模块），但推理时想一次产出 2 个 token。**

```
训练时：  模块1 收到的输入 = 主模型的真实 hidden  h⁰
推理时：  第 1 步一样；但如果想再往前猜一格，就得把 模块1 自己的输出 h¹ 再喂回 模块1
          ↑
       模块1 从来没见过"自己的输出"这种输入分布  →  训推不一致  →  接受率掉
```

**GLM-5.2 的解法特别干净**：

```
想预测后 3 个 token，就要 3 个 MTP 模块 → 显存 ×3          ❌
GLM 的做法：3 个模块【共享同一份参数】

   ┌───────────────┐
   │  MTP 层（一份） │ ◀── 循环使用 3 次
   └───────────────┘

✅ 显存和只有 1 层时持平
✅ 因为训练时这一份参数就被反复喂过"自己上一轮的输出"，
   推理时的输入分布和训练时完全一致 → 训推不一致被消除
```

**结果：接受长度 2.76**（DeepSeek-V3.2 是 2.55）；GLM-5.2 自己的消融里从 4.56 提到 5.47。

## 12.12 五家的 MTP 配置

| 家 | MTP 配置 | 接受长度 | 特点 |
|---|---|---|---|
| **DeepSeek-V4** | 深度 1，**完全沿用 V3 未改** | 未给 | 报告原文："we adopt the same strategy without modification"——V4 的创新预算全花在注意力和残差上了 |
| **Kimi K3** | 把预训练的 MTP 层**微调成 EAGLE-3 风格草稿模型** | 未给 | 见下方 ⭐ |
| **GLM-5.2** | **3 层参数共享** | **2.76** | 唯一给了可比数字的一家；解决训推不一致 |
| **MiniMax M3** | **7 个 MTP module（五家最多）** | 未给 | 押注树形/深链，配合它开源的 kernel |
| **openPangu-2.0-Pro** | 深度 3，**MTP 内部的注意力一律用 SWA 窗口 2048** | 未给 | 见下方 💡 |

> 💡 **openPangu 为什么敢在 MTP 里只用 512K 上下文中的最近 2048 个 token？**
>
> 因为**草稿模型不需要准，只需要快**。猜错了有 §12.4 的拒绝采样兜底，一点质量都不会掉。而"下一个词大概是什么"这件事，**绝大多数情况下只取决于最近几百个 token**。
> 于是：把 MTP 的注意力从"看 512K"砍到"看 2048"，草稿成本（公式里的 $c$）大幅下降，接受率 $\alpha$ 只掉一点点，**净收益为正**。
> **这是"投机解码的容错性可以直接兑换成工程简化"的一个漂亮例子。**

> ⭐ **Kimi K3 那一处非常值得单独看：它换掉了草稿模型的训练目标。**
>
> 常规做法是让草稿模型去最小化和主模型的 **KL 散度**（"学得像一点"）。K3 指出这是**错的代理目标**：
>
> $$\text{真正想最大化的是接受率}\quad \alpha = \sum_x\min\big(p(x),q(x)\big)$$
>
> 而对一个**容量受限**的草稿模型来说，**最小化 KL 并不等于最大化 $\alpha$**——KL 会逼着它去拟合 $p$ 的尾巴，但接受率只关心两个分布**重叠的那部分质量**。
> 所以 K3 直接优化 **LK loss**：$-\log\sum_x\min\big(p(x),q(x)\big)$，也就是**接受率的负对数**。
>
> 另外它的输入也做了改造（EAGLE-3 风格）：融合**第 1 个、第 4 个、最后一个 AttnRes block**（见 [03 章 §3.6](03-残差流.md)）的低/中/高层特征，融合矩阵 $W_{E3}$ 初始化成 $[0\ \ 0\ \ I]$——**初始时刻严格等价于"只用高层特征"（即 MTP 层原本被训练的输入），再慢慢学着吸收低中层。** 这个初始化技巧保证了微调起点不劣化。
>
> 详见 [../Kimi-K3.md](../Kimi-K3.md) §八。

## 12.13 本章小结

```
物理事实：decode 是访存受限的  →  "验证 5 个" 和 "生成 1 个" 一样快
    ↓
投机解码：先猜再验，拒绝采样保证输出分布不变       （纯赚，不掉质量）
    ↓
草稿从哪来：小模型 → Medusa 并行头 → EAGLE → MTP  （越来越像主模型，α 越来越高）
    ↓
MTP 的两个身份：训练时是更密的监督，推理时是免费草稿
    ↓
五家的分歧只在三处：几个模块、参不参数共享、模块内部的注意力用多大窗口
```

**关键公式回顾**：

```
接受概率      min(1, p(x)/q(x))
残差分布      p' = max(0, p−q) / β
单步接受率    α = Σ min(p,q) = 1 − TV(p,q)
接受长度      E = (1 − α^{γ+1}) / (1 − α)
加速比        ≈ E / (1 + γc)
MTP 模块      h'^k = M_k[RMSNorm(h^{k−1}); RMSNorm(Emb(t_{i+k}))]
MTP 损失      L = L_main + (λ/D)·Σ_k L^k_MTP
```
