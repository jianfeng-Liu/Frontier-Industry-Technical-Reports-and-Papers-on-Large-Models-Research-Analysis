# 14 · 量化：把模型压小

> **这一章的目标**：量化看起来只是"用更少的比特存数"，但它牵扯到**三件互相独立的事**——**存什么格式**、**按什么粒度定标**、**在训练的哪个阶段做**。五家的差异全部落在这三个维度上。
>
> 读完你应该能回答：为什么 MXFP4 是"4.25 位"？为什么 scale 不能随便定在任意维度上（**全章最重要的一条铁律**）？离群值到底从哪来（这一节会把前面所有伏笔收口）？以及为什么 openPangu 的报告里 SwiGLU 是个空格？

---

## 14.1 为什么必须量化：先算一笔账

```
openPangu-2.0-Pro 有 505B 参数。按不同格式存：

BF16     每个数 2 字节    →  1010 GB    需要 13 张 H100（80 GB）
FP8/INT8 每个数 1 字节    →   505 GB    需要  7 张
FP4      每个数 0.5 字节  →   253 GB    需要  4 张
```

**这不是"省点钱"的问题，而是"能不能跑起来"的问题。** 13 张卡和 4 张卡是**两个完全不同的部署形态**（跨机 vs 单机）——跨机意味着要走网络做张量并行，延迟和复杂度都是另一个量级。

而且回忆 [06 章 §6.4](06-KV-cache.md)：**decode 阶段是访存受限的**。权重从 1010 GB 变成 505 GB，意味着每生成一个 token 要搬的字节数减半——**在带宽受限的场景下，这几乎直接等于速度翻倍**。

> 🔑 **量化的收益有三份，很多人只想到第一份**：
> ```
> ① 显存占用变小    →  能用更少的卡 / 能开更大的 batch / KV cache 能存更长
> ② 访存字节数变少  →  ★ decode 直接提速（因为它是 memory-bound）
> ③ 低精度矩阵乘本身更快 —— 但这个【有条件】，见 §14.9
> ```

## 14.2 先补最底层的一课：一个数在计算机里长什么样

这一节是纯基础，但不补上，后面 FP8 / FP4 / MXFP4 这些名字就只能死记。

**浮点数由三段组成**：

$$x = (-1)^{\text{sign}} \times 2^{\,\text{exponent}-\text{bias}} \times (1.\text{mantissa})$$

```
       符号位   指数位（决定"能表示多大范围"）  尾数位（决定"精度多细"）
        │              │                             │
FP32   [S][ E E E E E E E E ][ M M M M M M M M M M M M M M M M M M M M M M M ]
        1        8 位                        23 位                      = 32 位

FP16   [S][ E E E E E ][ M M M M M M M M M M ]
        1     5 位            10 位                                     = 16 位

BF16   [S][ E E E E E E E E ][ M M M M M M M ]
        1        8 位（和 FP32 一样！）  7 位                            = 16 位

FP8-E4M3  [S][E E E E][M M M]                                           =  8 位
FP8-E5M2  [S][E E E E E][M M]                                           =  8 位
FP4-E2M1  [S][E E][M]                                                   =  4 位
```

**这里有一个非常重要的分工，一定要理解**：

| | 指数位多 | 尾数位多 |
|---|---|---|
| 决定 | **动态范围**（最大能表示多大、最小能表示多小） | **相对精度**（相邻两个能表示的数挨多近） |
| 不够会怎样 | **溢出 / 下溢**（变成 inf 或 0）—— **灾难性** | **舍入误差**变大 —— **渐进性** |

> 🔑 **"灾难性 vs 渐进性"这个区分是整章的底层逻辑**：一次溢出就 NaN，整个训练作废；而舍入误差只是让模型变差一点点，而且可以被后续训练吸收。**深度学习永远优先保动态范围。**

**BF16 战胜 FP16 成为训练默认格式，原因就在这张表里**：

```
FP16：5 位指数，最大只能表示 65504。深层网络梯度一大就溢出成 inf
      → 必须配 "loss scaling"（把 loss 乘个大数，反传完再除回来）这种补丁

BF16：8 位指数，动态范围和 FP32 完全一样（~3.4×10³⁸），几乎不会溢出
      代价是尾数只有 7 位，精度差
      → ★ 但深度学习对精度不敏感、对溢出极其敏感，所以这个交换非常划算
```

> 📌 **一个真实的反例，正好在五家里**：**openPangu 是唯一没用 BF16 的**——它用 **FP16 + 动态 loss scaling**（[13 章 §13.9](13-优化器与Muon.md)）。**这是"硬件决定数值格式"的一个直接样本。** 见 [../openPangu-2.0-Pro.md](../openPangu-2.0-Pro.md)。

**FP4 到底能表示哪些数？只有 16 个值，可以全部列出来**（E2M1）：

```
±{ 0,  0.5,  1.0,  1.5,  2.0,  3.0,  4.0,  6.0 }
   └──────────────────────────────────────────┘
      ★ 注意间距是【不均匀】的：小的地方密，大的地方疏
        0 → 0.5 间隔 0.5；4 → 6 间隔 2.0

      这正是浮点相对于定点的优势 ——
      它天然适配"大部分权重集中在 0 附近"这个真实分布
```

**整数格式（INT）则是均匀的**：

```
INT8 : −128 … 127        共 256 个等间距的档位
INT4 :   −8 … 7          共  16 个等间距的档位
```

| | 浮点（FP） | 整数（INT） |
|---|---|---|
| 档位分布 | **非均匀**，0 附近密 | **均匀** |
| 适合 | 长尾分布的权重/激活 | 分布比较平坦的场景 |
| 硬件 | 需要 FP8/FP4 张量核（H100 / Blackwell / 新代昇腾） | INT8 张量核**几乎所有加速器都有** |

> 📌 **最后一行解释了 openPangu 为什么选 INT 而不是 FP8**：它要在**昇腾**上跑，还要覆盖报告里提到的**9 个国产芯片平台**（GLM 也有类似诉求）。**INT8 是兼容性最好的那个格式。**

## 14.3 量化的数学：一个仿射映射

**核心操作只有一个**：把一段实数区间**线性地压进**一小撮整数档位。

**非对称（asymmetric）量化**，需要两个参数：缩放因子 $s$ 和零点 $z$：

$$
s = \frac{x_{\max}-x_{\min}}{2^{b}-1},\qquad
z = \mathrm{round}\!\left(-\frac{x_{\min}}{s}\right),\qquad
x_q = \mathrm{clip}\Big(\mathrm{round}\big(\tfrac{x}{s}\big)+z,\ 0,\ 2^b-1\Big)
$$

**反量化**（把整数还原成浮点）：

$$\hat x = s\,(x_q - z)$$

**对称（symmetric）量化**是它的简化版，强制 $z=0$：

$$s = \frac{\max|x|}{2^{b-1}-1},\qquad x_q = \mathrm{clip}\Big(\mathrm{round}\big(\tfrac{x}{s}\big),\ -2^{b-1},\ 2^{b-1}-1\Big),\qquad \hat x = s\,x_q$$

```python
def quantize_symmetric(x, bits=8, axis=-1):
    qmax = 2 ** (bits - 1) - 1                      # INT8 → 127, INT4 → 7
    s = np.abs(x).max(axis=axis, keepdims=True) / qmax
    xq = np.clip(np.round(x / s), -qmax - 1, qmax)
    return xq.astype(np.int8), s

def dequantize(xq, s):
    return xq.astype(np.float32) * s
```

**权重几乎都用对称量化**（分布本来就大致以 0 为中心，而且省掉 $z$ 能让矩阵乘的展开式干净很多——见 §14.5）；**激活有时用非对称**（比如 ReLU 之后全是正数，用对称等于白白浪费一半档位）。

### 误差有多大

round 到最近档位，误差落在 $[-s/2,\ s/2]$，近似均匀分布，所以

$$\mathbb{E}[\epsilon]=0,\qquad \mathrm{Var}[\epsilon]=\frac{s^2}{12},\qquad \mathrm{SNR} \approx \frac{\mathrm{Var}[x]}{s^2/12}$$

> 🔑 **★★ 关键推论，全章都在处理它的后果：**
> $$\text{误差完全由 } s \text{ 决定，而 } s \text{ 完全由这组数的【最大值】决定}$$
> **也就是说：一组数里最大的那一个，单独决定了这组里所有数的精度。**
>
> ```
> 正常值 0.5，最大值 12  →  s = 12/7 = 1.71  →  0.5 被 round 成 0，全丢
> 正常值 0.5，最大值 0.8 →  s = 0.8/7 = 0.11 →  0.5 被 round 成 4，误差 3%
>
> ★ 同一个 0.5，精度差了无穷倍 —— 差别只在于"它和谁分在一组"
> ```
> **§14.5（粒度）和 §14.6（离群值）就是这一条推论的两个直接后果。**

**记号约定**（读报告必备）：

```
W8A8   =  权重 8-bit，激活 8-bit
W4A16  =  权重 4-bit，激活保持 16-bit（"weight-only 量化"）
W4A8   =  权重 4-bit，激活 8-bit
KV8    =  KV cache 量化到 8-bit（第三个独立的量化对象）
```

## 14.4 三个可以独立量化的对象

**这是一个很多人混在一起的地方。模型里有三种性质完全不同的数：**

```
┌──────────────┬─────────────────┬──────────────────────────────────┐
│              │     性质         │            难度                   │
├──────────────┼─────────────────┼──────────────────────────────────┤
│ ① 权重 W      │ 静态、离线就知道 │ 最简单：可以离线慢慢优化怎么量化   │
│              │ 训完就不变       │ 4-bit 是常规操作                  │
├──────────────┼─────────────────┼──────────────────────────────────┤
│ ② 激活 X      │ 动态、依赖输入   │ 最难：离群值严重（§14.6），       │
│              │ 每个 token 都不同│ 而且必须【在线】算 scale           │
│              │                 │ 8-bit 已经不容易，4-bit 很难       │
├──────────────┼─────────────────┼──────────────────────────────────┤
│ ③ KV cache    │ 动态但一次写入   │ 中等：长上下文下它可能比权重还大   │
│              │ 之后反复读       │ （回忆 [06 章] 的 240 GB）        │
└──────────────┴─────────────────┴──────────────────────────────────┘
```

> 🔑 **为什么权重比激活容易得多**：
> ```
> 权重量化 = 一个【离线优化】问题
>            你有无限时间、能看到全部数值、可以反复试不同的 scale
>
> 激活量化 = 一个【在线】问题
>            推理时才知道数值，只能用极廉价的规则（比如"取这一行的最大值"）现算
> ```
> 这就是为什么 **W4A16**（只量化权重）是最常见的社区方案，而 **W8A8** 已经算是有工程投入的方案。

## 14.5 粒度：全章最重要的一个旋钮

回忆 §14.3 的推论：**误差由这组数的最大值决定**。所以最自然的想法是——**别把太多数分在一组里**。

```
一个权重矩阵 W，形状 [输出通道 N, 输入通道 K]

① per-tensor（整个矩阵一个 scale）
   ┌─────────────────────┐
   │                     │  1 个 scale
   │        s            │  ✅ 最省、最快
   │                     │  ❌ 一个离群值毁掉整个矩阵
   └─────────────────────┘

② per-channel（每个输出通道一个 scale）
   ┌─────────────────────┐  s₁
   ├─────────────────────┤  s₂    N 个 scale
   ├─────────────────────┤  s₃    ✅ 权重量化的标配，几乎【免费】（见下）
   └─────────────────────┘  s₄

③ per-group / block-wise（沿输入通道每 32 或 128 个一组）
   ┌────┬────┬────┬────┐
   │ s₁₁│ s₁₂│ s₁₃│ s₁₄│    N × (K/32) 个 scale
   ├────┼────┼────┼────┤    ✅ 4-bit 量化基本【必须】用这个
   │ s₂₁│ s₂₂│ s₂₃│ s₂₄│    ❌ scale 本身也占空间、也要参与计算
   └────┴────┴────┴────┘

④ per-token（激活侧：每个 token 一个 scale）
   token 1 ─────────────  s₁
   token 2 ─────────────  s₂    ✅ 激活量化的标配
   token 3 ─────────────  s₃
```

### ★★ 铁律：scale 必须在"求和维"上是常数

**为什么 per-channel（权重）和 per-token（激活）"几乎免费"，而 per-group 需要硬件支持？**

**这是整个量化工程里最重要的一个技术细节。看一遍矩阵乘的展开就明白了：**

$$y_{n} = \sum_{k=1}^{K} x_k\, w_{n,k} \;\approx\; \sum_{k=1}^{K} (s_x x^q_k)(s_w w^q_{n,k}) \;=\; \underbrace{s_x s_w}_{\text{提到外面}} \sum_{k=1}^{K} x^q_k w^q_{n,k}$$

**$s$ 能被提到求和号外面的前提，是它在求和维度 $k$ 上是常数。**

```
✅ 权重 per-channel：scale 随 n 变，【n 不是求和维】
                     → 可以提出去 → 整数点积一路算到底，最后乘一次 scale

✅ 激活 per-token  ：scale 随 token 变，【token 也不是求和维】
                     → 同样可以提出去

❌ per-group       ：★ scale 随 k 变 —— k 【正是】求和维！
                     → 求和被切成一段一段，每段结束都要乘上自己的 scale 再累加
                     → 需要硬件在【累加器层面】支持"分段重缩放"
```

> 🔑 **这条铁律的用处远不止解释 MX 格式**。它还直接解释了 §14.10 里"**为什么 K 比 V 难量化**"——因为 K 要和 Q 做点积，K 的通道维**正是求和维**。
>
> **记住这一条，你就能自己判断任何一个量化方案在硬件上好不好实现。**

### 这正是 MX（Microscaling）格式被造出来的原因

```
MXFP4 = 每 32 个元素为一组，组内每个元素 4 位 FP（E2M1）
                            组共享一个 8 位的【2 的幂次】scale（E8M0）

  每元素实际开销 = 4 + 8/32 = 4.25 位

  ┌──────── 32 个 FP4 元素 ────────┐ ┌ E8M0 ┐
  │ ▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪ │ │ 2^e  │
  └────────────────────────────────┘ └──────┘
   ⭐ 关键：这个"分组 + 共享 scale"是【张量核硬件原生支持】的，
      不需要在软件里拆循环。Blackwell / 新一代昇腾都直接支持。

MXFP8 = 同样的分组结构，但元素是 8 位 FP（E4M3 或 E5M2）
```

> 📌 **两个细节值得注意**：
> ```
> ① scale 是【2 的幂次】（E8M0，只有指数没有尾数）
>    → 乘 scale 退化成【移位指数】，硬件上几乎零成本
>    → 而且不引入额外的舍入误差
>
> ② "MXFP4" 不只是 "FP4"
>    裸 FP4 只有 16 个档位、最大值 6，动态范围小得可怜，
>    单独用根本没法表示一个真实的权重矩阵
>    ★ 是那个【每 32 个元素一换的 scale】把动态范围救回来的
> ```
> 五家里 **K3 和 M3 用的都是 MX 系列**。

## 14.6 ★ 真正的敌人：离群值（outlier）

现在把 §14.3 的推论和 §14.5 的粒度放在一起，看看真实数据长什么样。

### 一个具体的数值例子（建议自己按一遍计算器）

```
一组 8 个激活值：
   [0.5,  −0.3,  0.8,  −0.6,  12.0,  0.2,  −0.4,  0.7]
                                ↑ 离群值，比其他大 15 倍

▼ 方案 A：INT4 对称、per-tensor（整组一个 scale）
   s = 12.0 / 7 = 1.714
   round(0.5/1.714)  = round(0.29) = 0     ❌
   round(−0.3/1.714) = round(−0.17)= 0     ❌
   round(0.8/1.714)  = round(0.47) = 0     ❌
   round(−0.6/1.714) = round(−0.35)= 0     ❌
   round(12.0/1.714) = 7                    ✅
   ...
   结果：[0, 0, 0, 0, 7, 0, 0, 0]  →  除了离群值，全部信息被抹平成 0
                                       💀 这一层等于废了

▼ 方案 B：INT4 对称、per-group（每 4 个一组）
   组 1 [0.5, −0.3, 0.8, −0.6]：s = 0.8/7 = 0.114
        → q = [4, −3, 7, −5] → 还原 [0.457, −0.343, 0.800, −0.571]   ✅ 误差很小
   组 2 [12.0, 0.2, −0.4, 0.7]：s = 12/7 = 1.714
        → q = [7, 0, 0, 0]   → 还原 [12.0, 0, 0, 0]                  ❌ 后三个仍然塌了

   ★ 结论：分组【大幅缓解】了问题，但【没有根治】——
          只要离群值和正常值还在同一组里，这一组就还是废的
```

> 🔑 **这就是为什么光有 §14.5 的粒度不够，还需要 §14.7 那四类方法。**

### 为什么大模型必然有离群值

这不是偶然，而是一个在 **~6.7B 参数以上必然涌现**的现象（LLM.int8() 论文最早系统记录）：

```
① 离群值高度集中在【极少数固定的 hidden 维度】上
   比如 5120 维里可能就那么 2~4 维，幅度是其他维的 100 倍以上

② 这些维度在【所有 token 上都是同一批】—— 不是随机的

③ 它们对模型性能【极其重要】，直接砍掉会让模型崩溃
```

**这些"巨大激活"是干什么的？** 目前学界比较一致的一个解释是——**它们在充当注意力的泄压阀**。

```
回忆 [05 章 §5.5](05-注意力机制.md) 和 [08 章 §8.6](08-高效注意力.md)：

softmax 强制每一行权重和 = 1，模型"什么都不想看"时也【必须】把质量分出去。
于是模型学会了一个办法：在某几个固定维度上造出巨大的激活值，
让某些 token（常常是句首 token 或换行符）变成一个"注意力垃圾桶"。

     ⚠️ 这是模型自己【被逼出来】的一个 hack
        它解决了注意力的问题，却给量化制造了灾难
```

> 🔑 **★★ 这条因果链把全教程的三章串在一起，是本教程最重要的一条推论**：
> ```
> softmax 的和必须为 1                       （[05 章 §5.5]）
>       ↓  模型缺一个"什么都不看"的出口
> 自发形成巨大激活当泄压阀 = attention sink   （[08 章 §8.6]）
>       ↓  这些巨大激活【就是】离群值
> 量化的 scale 被它们绑架                     （§14.3 的推论）
>       ↓
> 低比特量化困难                              （§14.6）
> ```
> **而 gpt-oss 的 sink logit 和华为的 PAS（128 个可学习 KV），本质上是给模型一个"官方的泄压阀"，让它不必再自己造巨大激活。**
>
> **这解释了为什么这一代模型普遍在做显式 sink 机制——它【同时】服务于长上下文和低比特量化两个目标。一个机制，两个战场。**

**另一个离群值来源就是 [09 章 §9.4](09-FFN与激活函数.md) 讲过的 SwiGLU**：

$$\mathrm{SiLU}(W_g x)\ \odot\ W_u x \qquad \text{两个乘数都无界，乘起来更加无界}$$

**所以 V4 的 clamp[−10,10]、K3 的 SiTU-GLU 软上限（$|f|\le 100$）、M3 的 limit=7.0，本质上都是在给量化铺路。**

## 14.7 对付离群值的四类方法

```
① 混合精度分解（LLM.int8()）
   把离群值所在的那几列单独拎出来用 FP16 算，其余走 INT8，最后加起来
   ✅ 简单有效     ❌ 破坏了规整的矩阵乘，kernel 效率掉

② 迁移难度（SmoothQuant 类）—— 主流
   激活难量化、权重好量化，那就把难度从激活挪一部分给权重

③ 保护关键部件
   只量化 MoE 专家，注意力投影 / router / 共享专家 / embedding 保持高精度
   ✅ K3 和 GLM 都明确这么做

④ 旋转（QuaRot / SpinQuant 类）
   用一个正交矩阵把离群值"摊平"到所有维度上
```

### 关于 ③ 的一个重要直觉：错误的"性质"不同

```
    MoE 专家占了【绝大部分参数量】，但每个专家对最终结果的影响
    被稀疏路由稀释了（384 选 8）→ 量化误差是【渐进的】

    ★ 但 router 一旦量化出错，会【选错专家】
      → 输出完全换了一条计算路径
      → 这是【灾难性】的错误，不是渐进性的

    同理：embedding / LM head 直接连着离散的词表，
         一点误差就可能换一个词
```

> 🔑 **判据**：**问"这个部件出错，是让结果差一点，还是让结果换一个？"** 后者必须保高精度。
> **注意这和 [13 章 §13.6](13-优化器与Muon.md) 那个"哪些参数不用 Muon"的名单高度重合**——embedding、LM head、router。**它们在两个完全不同的问题里都是特殊的，因为它们本质上都在处理【离散】的东西。**

### ② SmoothQuant 的数学（很优雅，值得看）

注意到 $y = X W$ 对任何可逆对角阵 $\mathrm{diag}(s)$ 都有

$$XW = \big(X\,\mathrm{diag}(s)^{-1}\big)\big(\mathrm{diag}(s)\,W\big) = \hat X\hat W$$

**结果完全不变，但难度被重新分配了**：$\hat X$ 的离群值被压小，$\hat W$ 被放大一点。取

$$s_j = \frac{\big(\max|X_j|\big)^{\alpha}}{\big(\max|W_j|\big)^{1-\alpha}},\qquad \alpha\in[0,1]\ \text{典型取 }0.5$$

$\alpha$ 就是那个"难度分配旋钮"：$\alpha=1$ 全部难度给权重，$\alpha=0$ 全部留给激活。

```
    ★ 为什么这招管用：
      离群值集中在【固定的几个通道】上（§14.6 的观察 ①②）
      → 所以一个【逐通道的对角缩放】就能精准地压住它们
      → 如果离群值是随机分布的，这招就没用了
```

> 📌 **✅ 华为在这里做了一处推广**：把 SmoothQuant 里 $\alpha + (1-\alpha) = 1$ 这个**强制耦合**放开，改成**两个独立的指数做二维搜索**。
> **直觉是**："激活侧该压多少"和"权重侧能扛多少"本来就是两个独立的量，没有理由被一个参数绑死。见 [../openPangu-2.0-Pro.md](../openPangu-2.0-Pro.md)。

### ④ 旋转的数学（更优雅，是近两年的新方向）

对任意正交矩阵 $Q$（$Q^\top Q = I$）：

$$XW = X\,QQ^\top W = (XQ)(Q^\top W)$$

```
结果同样不变，但 XQ 把原来集中在几个维度上的巨大值【均匀摊到所有维度】

    量化前（离群值集中）        旋转后（能量摊平）
    ▁▁▁▁█▁▁▁▁▁▁▁▁▁▁▁      →     ▃▃▃▃▃▃▃▃▃▃▃▃▃▃▃▃
      一根尖峰绑架 scale            没有尖峰，scale 贴合整体

    实践中用 Hadamard 矩阵（元素全是 ±1/√d），
    乘法可以做成 O(d log d) 的快速变换，
    而且很多情况下能直接【吸收进相邻的权重矩阵】，推理时零额外开销
```

> 🔑 **注意 ② 和 ④ 是同一个思想的两个版本**：
> ```
> 都利用了"存在一个变换 T，使得 XW = (XT⁻¹)(TW) 恒等"
> ② 用【对角阵】：只能逐通道缩放，但可以精准针对已知的离群通道
> ④ 用【正交阵】：能真正把能量摊开，但会破坏权重原本的稀疏/结构性质
> ```

## 14.8 什么时候做量化：PTQ vs QAT

```
PTQ（Post-Training Quantization，训练后量化）
   模型已经训完 → 拿一小批"校准数据"（几百条样本）跑一遍前向，
   统计各处的数值范围 → 定出 scale → 存成低比特

   ✅ 便宜（几十分钟到几小时）、不需要训练基础设施
   ❌ 位宽越低掉点越多。8-bit 通常没事，4-bit 掉点明显

QAT（Quantization-Aware Training，量化感知训练）
   训练（或微调）时就在前向里【模拟】量化误差，让模型自己学着适应

   ✅ 能压到 4-bit 甚至更低而基本不掉点
   ❌ 贵，要重新跑训练流程
```

> 🔑 **QAT 为什么能救回精度**：
> ```
> PTQ：模型是在"数值可以很精确"的假设下训出来的，
>      然后你【事后】告诉它"其实只有 16 个档位"
>      → 它没有任何机会调整
>
> QAT：训练时模型就知道"我的权重最终只会有 16 个档位"
>      → ★ 它会主动把权重【挪到档位附近】，把重要信息编码到
>         那些量化后仍然可分辨的方向上
>      → 相当于模型自己找了一个"量化友好"的解
> ```

**PTQ 的校准怎么定 scale**——不是只有 min-max 一种：

```
min-max      ：s 由观察到的最大值定        →  ❌ 最容易被单个离群值毁掉
percentile   ：取 99.9% 分位数当上界       →  牺牲极少数点，换整体精度
MSE / KL 最优：搜索使 ‖x − x̂‖² 最小的截断点 →  ✅ 最常用，稍慢
```

### QAT 的关键技术：伪量化 + 直通估计器（STE）

前向传播里插入一个"量化再反量化"的操作（数值上被量化过，但类型还是浮点，所以叫 **fake quant**）：

$$\hat x = s\cdot\mathrm{round}\big(\mathrm{clip}(x/s)\big)$$

**问题来了**：`round` 的导数**几乎处处为 0**（它是个阶梯函数）。梯度一过来就全部变成 0，什么都学不了。

**STE（Straight-Through Estimator）的解法简单粗暴——反向传播时假装这个 round 不存在**：

$$\frac{\partial \hat x}{\partial x} \approx \begin{cases}1 & \text{在 clip 范围内}\\ 0 & \text{被截断了}\end{cases}$$

```python
def fake_quant_ste(x, s, qmax):
    xq = np.clip(np.round(x / s), -qmax - 1, qmax) * s
    # 前向：用量化后的值   反向：梯度直接穿过去
    return x + stop_gradient(xq - x)
    #      └─────┬──────┘
    #        前向 = x + (xq − x) = xq   ✅ 用的是量化值
    #        反向 = ∂x/∂x = 1          ✅ 梯度原样通过
```

> 🔑 **这个 `x + sg(xq − x)` 的写法是所有 QAT 实现里的标准套路**，值得记住——**一行代码同时实现"前向用量化值、反向当量化不存在"**。
>
> ⚠️ **STE 在数学上是"错"的**（它算的不是真梯度），但它在实践中极其有效。**这类"明知有偏但管用"的估计器在深度学习里很常见**——重要的是梯度方向大致对，而不是精确。

## 14.9 推理时到底发生了什么：省显存 ≠ 省算力

**这是一个非常容易搞混的点。**

```
▼ W4A16（只量化权重）
   显存里：4-bit 的权重
   计算时：读进来 → 在寄存器里【反量化成 FP16】→ 用 FP16 张量核做矩阵乘

   ✅ 显存 ÷4，访存字节数 ÷4
   ❌ FLOPs 完全没变（矩阵乘还是 FP16 的）

   👉 对 decode 极其有效（因为 decode 是 memory-bound，[06 章 §6.4]）
      对 prefill 帮助有限（prefill 是 compute-bound）

▼ W8A8（权重和激活都量化）
   计算时：直接用【INT8 张量核】做整数矩阵乘，
           累加器用 INT32，最后一次性乘回 scale

   ✅ 显存 ÷2，访存 ÷2，而且 FLOPs 吞吐通常翻倍
   ❌ 必须同时解决激活离群值 → 工程量大得多
```

```
     整数矩阵乘的完整流程（W8A8）

  x (FP16) ──[量化, per-token]──▶ x_q (INT8) ┐
                                              ├─▶ INT8 GEMM ─▶ acc (INT32)
  W 已经是 INT8（离线量化, per-channel）  ────┘                    │
                                                                  ▼
                                                         × s_x · s_w  → FP16 输出
                                                              ↑
                                          ★ 这一步能"最后一次性乘"，
                                            完全依赖 §14.5 的那条铁律
```

> 🔑 **所以选 W4A16 还是 W8A8，取决于你的瓶颈在哪**：
> ```
> 单用户长对话、batch 小   →  decode 主导  →  memory-bound  →  weight-only 就够
> 高并发服务、batch 大     →  大 batch / prefill 主导 → compute-bound
>                            → ★ 需要真正的低精度【计算】
> ```
> **五家都是【服务厂商】**，面对的是高并发场景，**所以都往 W8A8 / W4A8 这类"激活也量化"的方向走，而不是社区最流行的 W4A16。**
>
> 📌 这个观察和 [06 章 §6.4](06-KV-cache.md) 的"decode 算术强度 ≈ batch size"是同一件事的两面：**batch 一大，decode 也会从 memory-bound 滑向 compute-bound。**

## 14.10 第三个战场：KV cache 量化

回忆 [06 章](06-KV-cache.md)：**1M 上下文下 KV cache 可能有 240 GB，比权重还大。** 所以它是独立的第三个量化对象。

```
KV8（8-bit）：基本无损，现在算标配
KV4（4-bit）：有掉点，需要更细的粒度或旋转
```

### 一个实践中的非对称现象：K 比 V 难

```
   V（value）比较好量化，per-token 就够
       因为 V 参与的是 A @ V，V 的【token 维】是求和维，【通道维】不是
       → 按 token 定 scale，scale 在求和维上是常数 ✅

   K（key）  更难 —— 它的离群值沿【通道】方向分布，
             而 K 要和 Q 做点积 q·k = Σ_c q_c k_c
             → ★ 通道【正是】求和维（回忆 §14.5 的铁律）
             → 按通道定 scale 就提不出去了
             → 常见做法：对 K 先做一次 Hadamard 旋转（§14.7 ④），
               把通道方向的离群值摊平，再走 per-token 量化
```

> 🔑 **这是 §14.5 那条铁律的第二次发力。** 同一条规则，先解释了 MX 格式为什么需要硬件支持，又解释了 K/V 的量化难度不对称。**这就是好的第一性原理该有的样子。**

> 📌 **注意 MLA（[07 章](07-MHA到MLA.md)）和 KV cache 量化是两种【正交】的省法**，可以叠加：
> ```
> MLA    ：把 KV 从 16384 维压到 576 维    —— 改结构，省【维度】
> KV 量化 ：把每个数从 16 位压到 8 位      —— 改精度，省【每维的比特】
>
> 两者相乘：28× × 2× = 56×
> ```

## 14.11 五家的量化方案：一张表和一条因果链

| 家 | 方案 | PTQ / QAT | 值得注意的细节 |
|---|---|---|---|
| **DeepSeek-V4** | **FP4 存 + FP8 算**（MoE 专家） | ✅ QAT | ⭐ **关键设计：FP4→FP8 的反量化是【无损】的**。因为 E4M3 的指数位比 E2M1 多，FP4 的 16 个值全部能被 FP8 精确表示 → **可以直接复用已有的 FP8 训练框架，不用重写 kernel**。主权重仍保 FP32 |
| **Kimi K3** | **MXFP4 权重 + MXFP8 激活** | ✅ QAT，**从 SFT 一路贯穿到 RL 全程** | ⭐ 保护关键部件：注意力投影、latent MoE 投影、共享专家、router **全部保持高精度**。⭐⭐ 最重要的一点：RL 阶段 **rollout 和训练用同一套量化方案**，从根上消除 train–inference mismatch |
| **GLM-5.2** | **INT4（MoE 专家）+ W8A8（其余）** | ✅ QAT，在 SFT 阶段做 | ⭐ 量化 kernel **训练和推理共用同一份**，做到 **bitwise 一致** |
| **MiniMax M3** | **MXFP8 出货** | ⚠️ 无 4-bit 证据 | 停在 8-bit |
| **openPangu-2.0-Pro** | **W8A8 纯整数** | ❌ **报告未提 QAT，看起来是 PTQ** | 1009 GB → **517 GB（1.95×）**。⚠️ **注意不是正好 2×**——说明有一部分层被保留在高精度。SmoothQuant 的二维解耦指数搜索（§14.7） |

### ⭐ 两处"消除不一致"的设计，值得单独看

```
K3：RL 的 rollout 和训练用【同一套量化】
    → 常见做法是 rollout 用量化模型（快）、训练用全精度（准）
    → ★ 但这样策略梯度算的是"另一个模型"的梯度 —— train-inference mismatch
    → K3 把两边统一，从根上消除

GLM：训练和推理【共用同一份量化 kernel】，bitwise 一致
    → 消除的是另一种不一致：QAT 时模拟的量化 和 部署时真实的量化 不完全一样
    → ★ bitwise 一致意味着"训练时看到的就是部署时发生的"
```

> 🔑 **这两处的共同点是：把"训练时的模型"和"部署时的模型"变成【同一个】。**
> **这和 [12 章 §12.11](12-MTP与投机解码.md) GLM 的 MTP 参数共享（消除训推不一致）是完全相同的思路。**
> **⚠️ 这一代技术报告里"消除 train–inference mismatch"出现的频率非常高，可能是比任何单个架构创新都更重要的一条主线。**

### ★ 那条最漂亮的因果链

> ```
> 想压到 4-bit
>      ↓  PTQ 在 4-bit 上掉点太多
> 必须做 QAT
>      ↓  QAT 时低精度前向会因为激活离群值而溢出/失稳
> 必须处理激活离群值
>      ↓  SwiGLU 的两个乘数都无界，是离群值的主要来源之一
> 必须给 SwiGLU 加界（clamp / softcap）
>
> ────────── 反过来看 ──────────
>
> 停在 8-bit
>      ↓  PTQ 就够用了
> 不需要 QAT
>      ↓  8-bit 有 256 个档位，对离群值的容忍度高【16 倍】
> 离群值压力小
>      ↓
> ★ 没有给 SwiGLU 加界的动力
> ```
>
> **这条链完美解释了 [09 章 §9.5](09-FFN与激活函数.md) 里那个空格**：openPangu 的报告里 `SwiGLU` / `GLU` / `SiLU` / "激活函数" **命中 0 次**。
> **这不是疏忽，而是【自洽的】**——它停在 W8A8，就没有必须给激活加界的压力。
>
> ⚠️ **但要注意这只是一个自洽的解释，不是被验证的因果。** 华为报告没说"我们因为停在 8-bit 所以不加界"，这是我从五家的横向模式里推出来的。见 [../模型技术对比.md](../模型技术对比.md) §3.4 / §3.7。

## 14.12 本章小结

```
量化 = 三个互相独立的选择

① 存什么格式        INT8 / INT4（均匀）    vs   FP8 / FP4（非均匀，0 附近密）
                    指数位管【动态范围】（溢出=灾难性）
                    尾数位管【精度】（舍入=渐进性）→ 所以 BF16 赢了 FP16
                    裸 FP4 不能用，必须配分组 scale → MXFP4（4 + 8/32 = 4.25 位）

② 按什么粒度定标     per-tensor → per-channel → per-group(32/128) → 越细越准越贵
                    ⭐⭐ 铁律：scale 必须在【求和维】上是常数，
                             否则硬件要原生支持分段重缩放
                    这一条同时解释了：MX 为什么需要硬件支持、K 为什么比 V 难量化

③ 在哪个阶段做      PTQ（便宜，8-bit 够用）  vs   QAT（贵，4-bit 必须）
                    QAT 的核心技巧只有一个：STE，写法就是 x + sg(xq − x)
                    QAT 之所以能救回精度：模型会主动把权重挪到量化档位附近

────────────────────────────────────────────────

全部困难只来自一件事：★ 离群值
   scale 被【最大值】绑架（§14.3）
   而大模型【必然】产生巨大激活（当 attention 的泄压阀，[05/08 章]）
   SwiGLU 的无界乘法是第二个来源（[09 章]）

四类解法：混合精度分解 / SmoothQuant 迁移难度 / 保护关键部件 / 正交旋转摊平
   ②④ 是同一思想的两个版本：找一个 T 使 XW = (XT⁻¹)(TW)
   ③ 的判据：这个部件出错，是让结果【差一点】还是【换一个】？

────────────────────────────────────────────────

五家的位置：
   4-bit 阵营（必须 QAT）：DeepSeek-V4、Kimi K3、GLM-5.2
   8-bit 阵营（PTQ 够用）：MiniMax M3、openPangu

⭐ 一条主线：K3 统一 rollout/训练的量化，GLM 做到训推 bitwise 一致，
   GLM 的 MTP 参数共享消除训推不一致 ——
   "消除 train–inference mismatch" 可能是这一代最重要的隐藏主题
```
