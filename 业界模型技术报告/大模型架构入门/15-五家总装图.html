三个可以直接读出来的结论

① ★★ 长上下文是这一代的唯一主题
   位置 4 五家全改，且是每一家投入最大的地方
   -> 而这直接来自 06 章的 roofline：decode 访存受限，KV cache 就是瓶颈

② ★ 残差流从"不能碰的东西"变成了"可以设计的东西"
   2017-2024：残差就是一根 y = x + F(x) 的加号，八年没人动
   2025-2026：三家同时开始在上面做文章（mHC / AttnRes）
   -> 03 章 3.7 节的"三家改、两家不改"就是这个新战场的地图

③ 位置 6 的 W_O 零改动，是一个信息量很大的空白
   ⚠️ 我的解读：W_O 是纯粹的"写回残差流"的通道（03 章），
      它既不涉及 token 之间的交互（那是位置 4），
      也不涉及信息该往哪读（那是位置 2），
      -> 它没有可以下手的结构性约束，改它只是改参数量

15.3.3 ★ 每个维度的代价：天下没有白拿的

上面那张表只写了"选了什么"，没写"付了什么"。而架构设计里真正难的部分全在代价这一侧。

维度 这一格能换到什么 ⚠️ 代价付在哪
① 省 KV decode 是访存受限的，省下的 KV 字节数几乎等比例变成吞吐（06 章 §6.4） 每条路都有一个致命弱点，所以没有一家纯用一条路：压缩 → 摘要有损，且阶还是平方，到约 4M 会被线性追上；线性 → 必然遗忘，长程召回弱（M3 在 M2 上试过后退回来了）；稀疏 → 要付"挑"的开销，而且只省算力不省显存（KV 还得全存着）；滑窗 → 看不见远处。★ 另外所有稀疏方案都必须单独给 sink 打补丁（位置 ⑤），这是 05 章 §5.5 那条约束的下游后果
② FFN 稀疏 总参数涨（换来容量），激活参数不涨（算力和延迟不变） 显存照总参数算，一分不少；all-to-all 通信常常成为真正的瓶颈（10 章 §10.3）；负载均衡是最大的工程问题——不管它，少数专家会被打爆、其余闲置
③ 位置编码 NoPE 是白赚的：省掉一整套旋转计算，而且没有"训练长度"这个上限 NoPE 只在有线性递推层时才成立（K3 靠 KDA 的递归 + 因果掩码提供位置），纯 softmax 的四家用不了；base 阶梯的代价是要多训 5 个阶段，不是一个推理期的开关
④ 归一化 稳定性。它是唯一一个"不改也完全能跑"的维度 ⭐ 归一化不是创新点，它是稳定器。谁在这里做了额外动作，说明谁在别处冒了额外的险——华为的 sandwich + 块级后归一化是为了修 mHC 的门控塌陷（04 章 §4.4），V4 / M3 的 QK-Norm 是为了压 softmax 饱和，K3 的额外 RMSNorm 是因为 AttnRes 要做纯方向匹配
⑤ 优化器 Muon 在谱范数下做最速下降，更新方向各向同性；八年来第一次真正换掉 AdamW Newton–Schulz 那 5 步正交化是严格串行的，小矩阵打不满 GPU，是纯延迟；Embedding / LM Head / 一维参数不能用 Muon（13 章 §13.6），所以实际是混合优化器；粒度越细越稳，但实现越碎
⑥ 精度 直接的显存倍数：8-bit 省一半，4-bit 省四分之三 ★ 这是一条长长的连锁：想要 4-bit → PTQ 掉点太多 → 必须做 QAT → QAT 时低精度前向会被激活离群值搞失稳 → 必须给激活加界 → 于是逼出了位置 ⑩ 的 clamp / SiTU-GLU。⚠️ 停在 8-bit 的那一家（华为）因此没有加界的动力，这正好解释了它报告里那个空格。另外 ⚠️ INT4 在 Hopper 上还会静默掉速（14 章 §14.9）

🔑 把这张表竖着读一遍，你会发现一个规律：六个维度里只有 ④ 归一化是"纯赚"的（代价只是几个 RMSNorm 的访存），其余五个每一个都是明确的取舍。而五家在 ④ 上几乎完全一致——这不是巧合：没有取舍的地方，大家自然会收敛到同一个答案。

反过来说：凡是五家分歧最大的地方（① 和 ⑦），一定是因为那里的取舍还没有定论。

15.4 ★ 三条贯穿全书的因果链，最后过一遍

如果这份教程你只带走三样东西，请带走这三条。

链条 ①：softmax → 离群值 → 量化困难

softmax 每一行的和【必须】为 1
      |   模型缺一个"我什么都不想看"的出口
      v
自发在几个固定维度上造出【巨大激活】当泄压阀
= attention sink 现象
      |   这些巨大激活【就是】离群值
      v
量化的 scale 被最大值绑架
      v
★ 低比特量化困难

------ 这条链解释了三件表面无关的事 ------
1. 为什么这一代普遍出现【显式 sink 机制】（V4 的 sink logit、华为的 PAS）
2. 为什么稀疏化注意力必须【单独给 sink 打补丁】
3. 为什么 4-bit 量化这么难

这条链每一步的出处：05 章 §5.5 → 08 章 §8.6 → 14 章 §14.6 → 14 章 §14.3。

链条 ②：想要 4-bit → 必须给激活加界

想压到 4-bit
      |   PTQ 在 4-bit 上掉点太多
      v
必须做 QAT（量化感知训练）
      |   QAT 时低精度前向会因激活离群值失稳
      v
必须处理激活离群值
      |   SwiGLU 两个乘数都无界，是主要产地
      v
★ 必须给激活函数加界（clamp / softcap）

------ 反过来 ------
停在 8-bit -> PTQ 够用 -> 不需要 QAT -> 离群值压力小得多
           -> 没有加界的动力
           -> ⚠️ 这解释了 openPangu 报告里那个空格

出处：14 章 §14.1 的显存账 → 14 章 §14.8 的 PTQ vs QAT → 09 章 §9.4 的"SwiGLU 无界" → 09 章 §9.5 那个空格的推断。

链条 ③：decode 访存受限 → 省 KV cache = 提吞吐

decode 每步只处理 1 个 token，但要把全部激活权重和 KV cache 搬一遍
      v
算术强度 ~= batch size，远小于 H100 的屋脊点 295
      |   295 = BF16 稠密算力 989 TFLOP/s / HBM3 带宽 3.35 TB/s
      |   ⚠️ 别用 1979 TFLOPS，那是 2:4 结构化稀疏值，会把屋脊点算成 591
      v
★ decode 是【访存受限】的，算力大量空转
      v
两个直接推论：
  1. 省 KV cache 的字节数 ~= 直接提吞吐  -> 解释了五家在位置 4 上的全部投入
  2. 免费的算力可以拿来"猜"            -> 解释了 MTP / 投机解码

出处：06 章 §6.4 的 roofline → 12 章 的投机解码。

🔑 注意这三条链的形状是一样的：
一个看似无害的数学性质（softmax 归一化 / 4 bit 只有 16 档 / 搬运比计算慢），在被放大到 500B 参数和 1M 上下文的尺度后，逼出了一整套架构层面的对策。

这就是读技术报告时最值得练的能力：不要问"他们用了什么技术"，要问"是什么约束逼他们必须这么做"。

15.5 一张选择树：如果让你来设计

把五家的分歧整理成一棵决策树，你会发现它其实没那么多自由度：

你的主要目标是什么？
|
+- 极致的长上下文（1M+）
|  |
|  +- 愿意冒结构风险 ----> 线性注意力混合（K3 的 KDA 3:1）
|  |                       白赚：可以 NoPE、状态大小恒定
|  |                       风险：长程召回弱，M3 在 M2 上试过后退回来了
|  |
|  +- 要稳 -------------> 动态稀疏（GLM 的 DSA / M3 的 MSA）
|                         保留完整 softmax 语义
|                         代价：要付"挑选"的开销 -> IndexShare / 块级
|
+- 极致的推理成本（每 token 最便宜）
|  +--------------------> 压激活参数（openPangu：最浅 50 层 + 最窄 d=5120
|                         + 多而小的专家 384 个 x 中间维 1792）
|                         + 硬件亲和的量化（W8A8 纯整数）
|                         + 层级分工（1/3 全局 DSA + 2/3 滑窗 SWA）
|
+- 极致的能力上限
   +--------------------> 保住 softmax，只压 KV（V4 的 CSA/HCA 压缩）
                          + 在残差流上加容量（mHC 4 条车道）
                          + 最激进的量化换更大的模型（FP4 存 1.6T 总参数）

--------------------------------------------
不管选哪条，下面这些是【五家共识】，可以直接抄：
   ✅ Pre-Norm + RMSNorm            ✅ SwiGLU 系
   ✅ MoE + aux-loss-free 均衡      ✅ MTP
   ✅ 不用 MHA（MLA 或 GQA 或 MQA） ✅ Muon（矩阵参数）

⚠️ 最后一行原来写的是"MLA 或 GQA（不要 MHA）"，这里改准一点：五家的共识是"不用 MHA"，而不是"都用 MLA"。严格用 MLA 的是 3 家，V4 用的是共享 KV 的 MQA，M3 用的是 GQA。共识在"结论"上，不在"手段"上——这个区别在判断一项技术成熟度时很要紧（07 章 §7.6）。

15.6 本章小结

(1) 一层 Transformer 有 10 个可以动手的槽位（位置 1-10），
    再加 3 个层外的（优化器 / MTP / 量化），一共 13 个。
    五家动的位置高度集中：
       位置 4  看哪些 token  -- 5/5，绝对主战场
       位置 2  Q/K/V 投影    -- 5/5 都不是 MHA，但只有 3 家是严格的 MLA
       位置 7  残差流        -- 3/5，这一代的【新】战场
       位置 6  W_O           -- 0/5，唯一没人碰的地方

(2) 五家的一句话：压缩 / 换线性 / 稀疏挑选 / 块级选择 / 层级分工

(3) 六个维度并排看（15.3.2），只有【归一化】是纯赚的，
    其余五个每一个都是明确的取舍 —— 分歧最大的地方，就是取舍还没有定论的地方

(4) ⚠️ 稀疏度要用【总参数 / 激活参数】口径：
    openPangu 是 505/18 = 28.1 倍，不是 384/8 = 48 倍

(5) ★ 三条因果链是全书的骨架：
       softmax 归一化 -> 离群值 -> 量化难
       要 4-bit -> 要 QAT -> 要给激活加界
       decode 访存受限 -> 省 KV = 提速 + 有免费算力可以拿来猜

(6) 读报告的正确姿势：不问"用了什么技术"，问"什么约束逼他们必须这么做"
