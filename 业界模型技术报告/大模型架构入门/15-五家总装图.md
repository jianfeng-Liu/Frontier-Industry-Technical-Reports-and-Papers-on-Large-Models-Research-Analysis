## 15.2 ★ 数一数：创新集中在哪里

**把上面 13 个位置按"有几家动了"排个序，会看到一个非常清晰的分布：**

| 位置 | 动了的家数 | 说明 |
|---|---|---|
| **④ 看哪些 token** | **5 / 5** | ⭐⭐ **绝对的主战场，没有一家用原版全注意力** |
| ⑬ 量化 | 5 / 5 | 全部有明确方案，分成 4-bit 和 8-bit 两个阵营 |
| ⑧ 负载均衡 | 5 / 5 | 全部用 aux-loss-free，但细则各不同 |
| ⑫ MTP | 5 / 5 | 全部有，分歧在深度和参数共享 |
| ⑪ 优化器 | **4 / 5** | Muon，八年来第一次换优化器 |
| ⑩ 激活函数 | 3 / 5 | 加界的，都是为了 4-bit |
| ② Q/K/V 投影 | 4 / 5（MLA） | MLA 基本成为标配 |
| **⑦ 残差流** | **3 / 5** | ⭐ **这一代的新战场，2025 年之前几乎没人动** |
| ⑤ sink 机制 | 2 / 5 | 新出现，且都是配合稀疏化 |
| ③ 位置编码 | 1 / 5 有大改 | 只有 K3 的 NoPE 是结构性的 |
| ① 归一化 | 1 / 5 | 只有华为改了布局 |
| ⑥ W_O | **0 / 5** | ✅ **没有一家动它** |
| ⑨ 专家结构 | 1 / 5 | 只有 K3 的 LatentMoE 是结构性的 |

### 三个可以直接读出来的结论

```
① ★★ 长上下文是这一代的唯一主题
   ④ 位置五家全改，且是每一家投入最大的地方
   → 而这直接来自 [06 章] 的 roofline：decode 访存受限，KV cache 就是瓶颈

② ★ 残差流从"不能碰的东西"变成了"可以设计的东西"
   2017–2024：残差就是一根 y = x + F(x) 的加号，八年没人动
   2025–2026：三家同时开始在上面做文章（mHC / AttnRes）
   → [03 章 §3.7] 的"三改两不改"就是这个新战场的地图

③ ⑥ W_O 零改动，是一个信息量很大的空白
   ⚠️ 我的解读：W_O 是纯粹的"写回残差流"的通道（[03 章]），
      它既不涉及 token 之间的交互（那是 ④），也不涉及信息该往哪读（那是 ②），
      → 它没有可以下手的结构性约束，改它只是改参数量
```

## 15.4 ★ 三条贯穿全书的因果链，最后过一遍

**如果这份教程你只带走三样东西，请带走这三条。**

### 链条 ①：softmax → 离群值 → 量化困难

```
softmax 每一行的和【必须】为 1              （[05 章 §5.5]）
      ↓  模型缺一个"我什么都不想看"的出口
自发在几个固定维度上造出【巨大激活】当泄压阀
= attention sink 现象                      （[08 章 §8.6]）
      ↓  这些巨大激活【就是】离群值
量化的 scale 被最大值绑架                   （[14 章 §14.3]）
      ↓
★ 低比特量化困难                            （[14 章 §14.6]）

────── 这条链解释了三件表面无关的事 ──────
① 为什么这一代普遍出现【显式 sink 机制】（V4 的 sink logit、华为的 PAS）
② 为什么稀疏化注意力必须【单独给 sink 打补丁】
③ 为什么 4-bit 量化这么难
```

### 链条 ②：想要 4-bit → 必须给激活加界

```
想压到 4-bit                                （[14 章 §14.1] 的显存账）
      ↓  PTQ 在 4-bit 上掉点太多
必须做 QAT                                  （[14 章 §14.8]）
      ↓  QAT 时低精度前向会因激活离群值失稳
必须处理激活离群值
      ↓  SwiGLU 两个乘数都无界，是主要产地   （[09 章 §9.4]）
★ 必须给激活函数加界（clamp / softcap）

────── 反过来 ──────
停在 8-bit → PTQ 够用 → 不需要 QAT → 离群值压力小 16 倍
→ 没有加界的动力 → ⚠️ 这解释了 openPangu 报告里那个空格
```

### 链条 ③：decode 访存受限 → 省 KV cache = 提吞吐

```
decode 每步只处理 1 个 token，但要把全部权重和 KV cache 搬一遍
      ↓
算术强度 ≈ batch size ≪ H100 的 ridge point (≈295)   （[06 章 §6.4]）
      ↓
★ decode 是【访存受限】的，算力大量空转
      ↓
两个直接推论：
  ① 省 KV cache 的字节数 ≈ 直接提吞吐  → 解释了五家在 ④ 上的全部投入
  ② 免费的算力可以拿来"猜"            → 解释了 MTP / 投机解码（[12 章]）
```

> 🔑 **注意这三条链的形状是一样的**：
> **一个看似无害的数学性质（softmax 归一化 / 4 bit 只有 16 档 / 搬运比计算慢），在被放大到 500B 参数和 1M 上下文的尺度后，逼出了一整套架构层面的对策。**
>
> **这就是读技术报告时最值得练的能力：不要问"他们用了什么技术"，要问"是什么约束逼他们必须这么做"。**

## 15.5 一张选择树：如果让你来设计

**把五家的分歧整理成一棵决策树，你会发现它其实没那么多自由度：**

```
你的主要目标是什么？
│
├─ 极致的长上下文（1M+）
│  │
│  ├─ 愿意冒结构风险 ────▶ 线性注意力混合（K3 的 KDA 3:1）
│  │                        白赚：可以 NoPE、状态恒定
│  │                        风险：召回能力弱，M3 试过后退回来了
│  │
│  └─ 要稳 ──────────────▶ 动态稀疏（GLM 的 DSA / M3 的 MSA）
│                           保留完整 softmax 语义
│                           代价：要付"挑选"的开销 → IndexShare / 块级
│
├─ 极致的推理成本（每 token 最便宜）
│  └──────────────────────▶ 压激活参数（openPangu：最浅 + 最窄 + 多而小的专家）
│                            + 硬件亲和的量化（W8A8 纯整数）
│                            + 层级分工（1/3 全局 + 2/3 滑窗）
│
└─ 极致的能力上限
   └───────────────────────▶ 保住 softmax，只压 KV（V4 的 CSA/HCA 压缩）
                              + 在残差流上加容量（mHC）
                              + 最激进的量化换更大的模型（FP4 存 1.6T）

────────────────────────────────────────────
不管选哪条，下面这些是【五家共识】，可以直接抄：
   ✅ Pre-Norm + RMSNorm          ✅ SwiGLU 系
   ✅ MoE + aux-loss-free 均衡     ✅ MTP
   ✅ MLA 或 GQA（不要 MHA）       ✅ Muon（矩阵参数）
```
