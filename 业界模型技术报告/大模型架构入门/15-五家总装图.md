# 15 · 五家总装图：把所有改动挂回一张图

> **这一章不引入任何新知识**，它是前十四章的**收口**。
> 现在你有全部零件了。这一章把它们装回一张图上，标出五家各自动了哪个位置——然后我们数一数，**看看这一代的创新到底集中在哪里**。

## 15.1 完整的一层，标注了五家动过的位置

**先看骨架。** 一层 Transformer 的全部结构就是下面这张图，**五家没有一家改过它的形状**——所有的改动都发生在图上那 10 个编号的槽位里。

```
         x
         |
         +---------------------------+     <- 残差旁路（位置 7）
         v                           |
      [ Norm ]                       |     <- 位置 1
         |                           |
         v                           |
      [ Attention ]                  |     <- 位置 2 3 4 5 6
         |                           |
         v                           |
        (+) <----------------------- +
         |
         +---------------------------+     <- 残差旁路（位置 7）
         v                           |
      [ Norm ]                       |
         |                           |
         v                           |
      [ MoE ]                        |     <- 位置 8 9 10
         |                           |
         v                           |
        (+) <----------------------- +
         |
         v
     下一层
```

📌 **这张图为什么只有两个"箱子"和两个加号**：因为 Transformer 只有两种积木（横向混合的 Attention、纵向变换的 FFN/MoE），外加一条把它们串起来的总线（残差流）。这是 [01 章](01-鸟瞰全景.md) 和 [03 章](03-残差流.md) 的结论，这里只是再确认一次：**五家的全部创新，都挤在这三样东西上。**

### 15.1.1 层内的 10 个槽位：谁动了哪一个

**表格里的每一行，就是上面那张图里的一个编号。**

| 位置 | 它在图里的哪里 | 它干什么 | 五家各选了什么 |
|---|---|---|---|
| **①** | 第一个 `[ Norm ]` | 把每个 token 的向量长度拉回可控范围 | 全部 RMSNorm + Pre-Norm；**华为**额外加 sandwich + 块级后归一化；V4 / M3 在 Q、K 上另加 QK-Norm（[04 章 §4.5](04-归一化.md)） |
| **②** | `[ Attention ]` 入口 | 把 `x` 投成 Q、K、V，**决定 KV cache 存多少** | **MLA**：GLM（latent 256）／华为（512+64=576）／K3（只有 1/4 的层）。**GQA**：M3（64 q 头 / 4 kv 头）。⚠️ **V4 两者都不是**：CSA/HCA 的内核是**共享 KV 的 MQA** |
| **③** | `[ Attention ]` 内 | 告诉模型 token 的先后顺序 | **Partial RoPE**：V4 / GLM / M3 / 华为。**NoPE**（干脆不要）：K3。华为另加 base 五级阶梯 10K→6.4M |
| **④** | `[ Attention ]` 内 | **决定每个 token 去看哪些 token** ← ★ 主战场 | 见下面 §15.1.2 单独一张表 |
| **⑤** | `[ Attention ]` 内 | 给"我什么都不想看"留一个出口 | **V4**：每个头一个可学习的 sink logit。**华为**：PAS（Parametric Attention Sink，参数化注意力汇），每层 128 对可学习 KV |
| **⑥** | `[ Attention ]` 出口 | 输出投影 `W_O`，把结果写回残差流 | ✅ **没有一家动它** |
| **⑦** | 两条残差旁路本身 | 那个加号 | **mHC**（manifold-constrained Hyper-Connections）：V4 / 华为，4 条车道 + 双随机约束。**AttnRes**（跨层注意力检索）：K3。**不改**：GLM / M3 |
| **⑧** | `[ MoE ]` 入口 | 路由：这个 token 该交给哪几个专家 | aux-loss-free 偏置调整：**五家全部**。**K3** 另加 Quantile Balancing；**华为**把偏置更新的 sign 换成 RMS 归一化 + EP-group 辅助损失；**V4** 用 Sqrt(Softplus) 打分 + 浅层哈希路由 |
| **⑨** | `[ MoE ]` 内 | 专家本身长什么样、有几个、选几个 | 384 选 6（V4）／896 选 16（K3）／256 选 8（GLM）／128 选 4（M3）／384 选 8（华为）。**K3** 的 Stable LatentMoE 是唯一改了专家**结构**的（工作宽度 latent 3584 = 模型宽度的一半） |
| **⑩** | `[ MoE ]` 内 | 激活函数 | **V4**：SwiGLU + clamp[−10, 10]。**K3**：SiTU-GLU（软饱和）。**M3**：SwiGLU + clamp 7.0。**GLM**：不改。**华为**：❓ 报告没写（[09 章 §9.5](09-FFN与激活函数.md) 有对这个空格的推断） |

> ⚠️ **⑥ 那一行的"没有一家动它"不是我漏查了**，它是一个真实的空白，§15.2 的第三个结论会专门解释它为什么空着。

### 15.1.2 位置 ④ 单独拉出来：五家投入最大的地方

**"去看哪些 token"这一格，五家全部动了，而且每一家都是拿它当主要卖点的。** 四条路的原理见 [08 章](08-高效注意力.md)，这里只并排放结果：

| 做法 | 一句话 | 谁在用 | 具体配置 |
|---|---|---|---|
| **全部看** | 基线，$O(L^2)$ | **没有一家** | — |
| **压缩后看** | 远处的 token 打包成摘要 | **DeepSeek-V4** | CSA 4:1 重叠压缩 + HCA 128:1 稠密摘要，两种注意力并用 |
| **稀疏挑一小撮** | 只看最相关的约 2048 个 | **GLM-5.2** | DSA top-2048 + IndexShare（每 4 层才重算一次索引） |
| **稀疏挑一小撮（块级）** | 以 128 个 token 为一块来挑 | **MiniMax M3** | MSA：块大小 128，选 16 块 = 2048 个 token |
| **滑窗只看邻居** | 只看最近 512 个 | **openPangu**（2/3 的层） | DSA : SWA = 1 : 2，窗口 512，再加 PAS 兜底 |
| **换成线性状态** | 不存 KV，存一个固定大小的状态 | **Kimi K3**（3/4 的层） | KDA（delta rule）: MLA = 3 : 1，即 69 层线性 + 24 层全注意力 |

> 🔑 **五家在这一格上撞到了同一个数：2048。** GLM 的 DSA top-2048、MiniMax 的 MSA 16×128=2048——不同底座、不同粒度、不同团队，收敛到同一个数字。⚠️ 这只能算"当前长上下文的一个经验甜点"，**不是什么定律**（[08 章 §8.7](08-高效注意力.md)）。

## 15.2 ★ 数一数：创新集中在哪里

**把上面 13 个位置按"有几家动了"排个序，会看到一个非常清晰的分布：**

| 位置 | 动了的家数 | 说明 |
|---|---|---|
| **④ 看哪些 token** | **5 / 5** | ⭐⭐ **绝对的主战场，没有一家用原版全注意力** |
| **② Q/K/V 投影** | **5 / 5** | ⭐ **也没有一家用原版 MHA。**⚠️ 但"都不是 MHA"≠"都是 MLA"：严格用 MLA 的只有 3 家（GLM / 华为 / K3 的 1/4 层），V4 是 CSA/HCA（MQA 内核），M3 是 GQA |
| ⑧ 负载均衡 | 5 / 5 | 全部用 aux-loss-free 偏置调整，但细则各不同 |
| ⑫ MTP | 5 / 5 | 全部有，分歧在深度和参数共享 |
| ⑬ 量化 | 5 / 5 | 全部有明确方案，分成 4-bit 和 8-bit 两个阵营 |
| ⑪ 优化器 | **4 / 5** | Muon，八年来第一次换优化器（M3 报告未明确） |
| **⑦ 残差流** | **3 / 5** | ⭐ **这一代的新战场，2025 年之前几乎没人动**（V4 / 华为 mHC、K3 AttnRes） |
| ⑩ 激活函数 | 3 / 5 | 加界的三家（V4 / K3 / M3），都是为了 4-bit |
| ⑤ sink 机制 | 2 / 5 | 新出现，且都是配合稀疏化（V4 sink logit、华为 PAS） |
| ① 归一化（布局） | 1 / 5 | 只有华为改了**放法**；QK-Norm 那种局部补丁另有 2 家 |
| ③ 位置编码 | 1 / 5 有大改 | 只有 K3 的 NoPE 是结构性的，其余四家都是 Partial RoPE |
| ⑨ 专家结构 | 1 / 5 | 只有 K3 的 LatentMoE 改了结构；其余四家只是把"几个 / 多大 / 选几个"这三个旋钮拧到不同刻度 |
| ⑥ W_O | **0 / 5** | ✅ **没有一家动它** |

### 三个可以直接读出来的结论

```
① ★★ 长上下文是这一代的唯一主题
   位置 4 五家全改，且是每一家投入最大的地方
   -> 而这直接来自 06 章的 roofline：decode 访存受限，KV cache 就是瓶颈

② ★ 残差流从"不能碰的东西"变成了"可以设计的东西"
   2017-2024：残差就是一根 y = x + F(x) 的加号，八年没人动
   2025-2026：三家同时开始在上面做文章（mHC / AttnRes）
   -> 03 章 3.7 节的"三家改、两家不改"就是这个新战场的地图

③ 位置 6 的 W_O 零改动，是一个信息量很大的空白
   ⚠️ 我的解读：W_O 是纯粹的"写回残差流"的通道（03 章），
      它既不涉及 token 之间的交互（那是位置 4），
      也不涉及信息该往哪读（那是位置 2），
      -> 它没有可以下手的结构性约束，改它只是改参数量
```

> 📌 **顺手澄清一个数**：上面说"13 个位置"，其中 **10 个在一层之内**（①–⑩，就是 §15.1 那张图上的槽位），**3 个在一层之外**（⑪ 优化器 / ⑫ MTP / ⑬ 量化）。

**这三条链接分别指向**：[06 章 §6.4](06-KV-cache.md)、[03 章 §3.7](03-残差流.md)、[03 章](03-残差流.md)。

> ⚠️⚠️ **② 那一行的稀疏度，口径一定要看清楚。** 这是本教程最容易被写错的一个数：
> ```
> openPangu 举例，同一个模型有三个都叫"稀疏度"的数：
>     384 / 8   = 48.0 倍   <- 只是【路由专家】的选择比
>     385 / 9   = 42.8 倍   <- 算上那 1 个共享专家后的 FFN 稀疏比
>     505 / 18  = 28.1 倍   <- ★ 全模型口径：总参数 / 激活参数
>
> 上面表格第二行给的是最后那个（全模型口径），因为只有它能回答
> "这个模型每吐一个字要花多少算力"。
> ⚠️ 48 倍那个数会把省下来的量夸大 1.7 倍。
> ```
> **为什么会从 48 掉到 28**：因为注意力、稠密层、Embedding、LM Head 这些部分**一点都不稀疏**，每个 token 都要全量走一遍。它们在总参数里只占 1.3%，在激活参数里却占了 35%。**稀疏只发生在专家那一块。** 完整推演见 [01 章 §1.4.4](01-鸟瞰全景.md)。

**换成同一口径的稀疏度**（总参数 ÷ 激活参数；V4 / K3 / 华为三列的数据同 [01 章 §1.6](01-鸟瞰全景.md)，M3 那一列按下面的 ⚠️ 修正过）：

| | DeepSeek-V4 | Kimi K3 | GLM-5.2 | MiniMax M3 | openPangu-2.0-Pro |
|---|---|---|---|---|---|
| 总参数 | 1.6 T | 2.78 T | 未披露 | 428 B | 505 B |
| **激活参数**（≈ 单 token 成本） | 49 B | **104 B（五家最贵）** | 未披露 | ~23 B | **18 B（已披露里最便宜）** |
| **稀疏度（总 ÷ 激活）** | **32.7 ×**（最稀疏） | 26.7 × | 未披露 | 18.6 ×（最不稀疏） | 28.1 × |
| 前向 FLOPs / token（≈ 2 × 激活参数） | ≈ 98 GFLOP | ≈ 208 GFLOP | 未披露 | ≈ 46 GFLOP | ≈ 36 GFLOP |

> ⚠️ 最后一行是按"前向 ≈ 2 × 激活参数"推的**粗估**，只用来做横向量级比较：它忽略了注意力矩阵项，也忽略了各家 Embedding 是否权重绑定。**别拿它当各家报告的披露值。**
>
> ⚠️⚠️ **MiniMax M3 这一列要注意一个很容易踩的坑**：**428B / ~23B 是 M3，229.9B / 9.8B 是上一代 M2。** 两者的层数（60 / 62）、hidden dim（6144 / 3072）、专家配置（128 选 4 / 256 选 8）全都不同——⚠️ **专家数和 top-k 都减半了，激活参数反而涨了 2.3 倍**（省下来的注意力算力被换成了 FFN 容量与多模态容量；M3 没有技术报告，这是推测）。M3 的一手配置来自 HF `config.json`，见 [../MiniMax-M3.md](../MiniMax-M3.md) §三。
>
> ⚠️ **GLM-5.2 的总参数 / 激活参数在本教程覆盖的那一版报告里没有披露。** 更新后的 [../模型技术对比.md](../模型技术对比.md) §二 给了下一版 GLM-5.3 的数字（744B / 40B），⚠️ **那不是 GLM-5.2 的数**，不要混用。

> 📌 **⑦ 残差和 ⑫ MTP 没有进上面这张六维表**，不是因为它们不重要——恰恰相反，⑦ 是这一代最新的战场。它们在 §15.2 那张"数一数"的表里，那张表的口径是"有几家动了"，比"各自选了什么"更适合它们（因为有两家的选择就是**不动**）。

### 15.3.3 ★ 每个维度的代价：天下没有白拿的

**上面那张表只写了"选了什么"，没写"付了什么"。而架构设计里真正难的部分全在代价这一侧。**

| 维度 | 这一格能换到什么 | ⚠️ 代价付在哪 |
|---|---|---|
| **① 省 KV** | decode 是访存受限的，**省下的 KV 字节数几乎等比例变成吞吐**（[06 章 §6.4](06-KV-cache.md)） | **每条路都有一个致命弱点，所以没有一家纯用一条路**：压缩 → 摘要有损，且**阶还是平方**，到约 4M 会被线性追上；线性 → **必然遗忘**，长程召回弱（M3 在 M2 上试过后退回来了）；稀疏 → 要付"**挑**"的开销，而且**只省算力不省显存**（KV 还得全存着）；滑窗 → 看不见远处。★ 另外**所有稀疏方案都必须单独给 sink 打补丁**（位置 ⑤），这是 [05 章 §5.5](05-注意力机制.md) 那条约束的下游后果 |
| **② FFN 稀疏** | 总参数涨（换来容量），激活参数不涨（**算力和延迟不变**） | **显存**照总参数算，一分不少；**all-to-all 通信**常常成为真正的瓶颈（[10 章 §10.3](10-MoE.md)）；**负载均衡**是最大的工程问题——不管它，少数专家会被打爆、其余闲置 |
| **③ 位置编码** | NoPE 是**白赚**的：省掉一整套旋转计算，而且没有"训练长度"这个上限 | NoPE 只在**有线性递推层**时才成立（K3 靠 KDA 的递归 + 因果掩码提供位置），纯 softmax 的四家用不了；base 阶梯的代价是**要多训 5 个阶段**，不是一个推理期的开关 |
| **④ 归一化** | 稳定性。它是**唯一一个"不改也完全能跑"的维度** | ⭐ **归一化不是创新点，它是稳定器。谁在这里做了额外动作，说明谁在别处冒了额外的险**——华为的 sandwich + 块级后归一化是为了修 mHC 的门控塌陷（[04 章 §4.4](04-归一化.md)），V4 / M3 的 QK-Norm 是为了压 softmax 饱和，K3 的额外 RMSNorm 是因为 AttnRes 要做纯方向匹配 |
| **⑤ 优化器** | Muon 在**谱范数**下做最速下降，更新方向各向同性；八年来第一次真正换掉 AdamW | Newton–Schulz 那 5 步正交化是**严格串行**的，小矩阵打不满 GPU，是纯延迟；**Embedding / LM Head / 一维参数不能用 Muon**（[13 章 §13.6](13-优化器与Muon.md)），所以实际是混合优化器；粒度越细越稳，但实现越碎 |
| **⑥ 精度** | 直接的显存倍数：8-bit 省一半，4-bit 省四分之三 | ★ **这是一条长长的连锁**：想要 4-bit → PTQ 掉点太多 → **必须做 QAT** → QAT 时低精度前向会被激活离群值搞失稳 → **必须给激活加界** → 于是逼出了位置 ⑩ 的 clamp / SiTU-GLU。⚠️ 停在 8-bit 的那一家（华为）**因此没有加界的动力**，这正好解释了它报告里那个空格。另外 ⚠️ INT4 在 Hopper 上还会**静默掉速**（[14 章 §14.9](14-量化.md)） |

> 🔑 **把这张表竖着读一遍，你会发现一个规律**：**六个维度里只有 ④ 归一化是"纯赚"的**（代价只是几个 RMSNorm 的访存），其余五个每一个都是明确的取舍。**而五家在 ④ 上几乎完全一致——这不是巧合：没有取舍的地方，大家自然会收敛到同一个答案。**
>
> **反过来说：凡是五家分歧最大的地方（① 和 ⑦），一定是因为那里的取舍还没有定论。**

## 15.4 ★ 三条贯穿全书的因果链，最后过一遍

**如果这份教程你只带走三样东西，请带走这三条。**

### 链条 ①：softmax → 离群值 → 量化困难

```
softmax 每一行的和【必须】为 1
      |   模型缺一个"我什么都不想看"的出口
      v
自发在几个固定维度上造出【巨大激活】当泄压阀
= attention sink 现象
      |   这些巨大激活【就是】离群值
      v
量化的 scale 被最大值绑架
      v
★ 低比特量化困难

------ 这条链解释了三件表面无关的事 ------
1. 为什么这一代普遍出现【显式 sink 机制】（V4 的 sink logit、华为的 PAS）
2. 为什么稀疏化注意力必须【单独给 sink 打补丁】
3. 为什么 4-bit 量化这么难
```

**这条链每一步的出处**：[05 章 §5.5](05-注意力机制.md) → [08 章 §8.6](08-高效注意力.md) → [14 章 §14.6](14-量化.md) → [14 章 §14.3](14-量化.md)。

### 链条 ②：想要 4-bit → 必须给激活加界

```
想压到 4-bit
      |   PTQ 在 4-bit 上掉点太多
      v
必须做 QAT（量化感知训练）
      |   QAT 时低精度前向会因激活离群值失稳
      v
必须处理激活离群值
      |   SwiGLU 两个乘数都无界，是主要产地
      v
★ 必须给激活函数加界（clamp / softcap）

------ 反过来 ------
停在 8-bit -> PTQ 够用 -> 不需要 QAT -> 离群值压力小得多
           -> 没有加界的动力
           -> ⚠️ 这解释了 openPangu 报告里那个空格
```

**出处**：[14 章 §14.1](14-量化.md) 的显存账 → [14 章 §14.8](14-量化.md) 的 PTQ vs QAT → [09 章 §9.4](09-FFN与激活函数.md) 的"SwiGLU 无界" → [09 章 §9.5](09-FFN与激活函数.md) 那个空格的推断。

### 链条 ③：decode 访存受限 → 省 KV cache = 提吞吐

```
decode 每步只处理 1 个 token，但要把全部激活权重和 KV cache 搬一遍
      v
算术强度 ~= batch size，远小于 H100 的屋脊点 295
      |   295 = BF16 稠密算力 989 TFLOP/s / HBM3 带宽 3.35 TB/s
      |   ⚠️ 别用 1979 TFLOPS，那是 2:4 结构化稀疏值，会把屋脊点算成 591
      v
★ decode 是【访存受限】的，算力大量空转
      v
两个直接推论：
  1. 省 KV cache 的字节数 ~= 直接提吞吐  -> 解释了五家在位置 4 上的全部投入
  2. 免费的算力可以拿来"猜"            -> 解释了 MTP / 投机解码
```

**出处**：[06 章 §6.4](06-KV-cache.md) 的 roofline → [12 章](12-MTP与投机解码.md) 的投机解码。

> 🔑 **注意这三条链的形状是一样的**：
> **一个看似无害的数学性质（softmax 归一化 / 4 bit 只有 16 档 / 搬运比计算慢），在被放大到 500B 参数和 1M 上下文的尺度后，逼出了一整套架构层面的对策。**
>
> **这就是读技术报告时最值得练的能力：不要问"他们用了什么技术"，要问"是什么约束逼他们必须这么做"。**

## 15.5 一张选择树：如果让你来设计

**把五家的分歧整理成一棵决策树，你会发现它其实没那么多自由度：**

```
你的主要目标是什么？
|
+- 极致的长上下文（1M+）
|  |
|  +- 愿意冒结构风险 ----> 线性注意力混合（K3 的 KDA 3:1）
|  |                       白赚：可以 NoPE、状态大小恒定
|  |                       风险：长程召回弱，M3 在 M2 上试过后退回来了
|  |
|  +- 要稳 -------------> 动态稀疏（GLM 的 DSA / M3 的 MSA）
|                         保留完整 softmax 语义
|                         代价：要付"挑选"的开销 -> IndexShare / 块级
|
+- 极致的推理成本（每 token 最便宜）
|  +--------------------> 压激活参数（openPangu：最浅 50 层 + 最窄 d=5120
|                         + 多而小的专家 384 个 x 中间维 1792）
|                         + 硬件亲和的量化（W8A8 纯整数）
|                         + 层级分工（1/3 全局 DSA + 2/3 滑窗 SWA）
|
+- 极致的能力上限
   +--------------------> 保住 softmax，只压 KV（V4 的 CSA/HCA 压缩）
                          + 在残差流上加容量（mHC 4 条车道）
                          + 最激进的量化换更大的模型（FP4 存 1.6T 总参数）

--------------------------------------------
不管选哪条，下面这些是【五家共识】，可以直接抄：
   ✅ Pre-Norm + RMSNorm            ✅ SwiGLU 系
   ✅ MoE + aux-loss-free 均衡      ✅ MTP
   ✅ 不用 MHA（MLA 或 GQA 或 MQA） ✅ Muon（矩阵参数）
```

> ⚠️ **最后一行原来写的是"MLA 或 GQA（不要 MHA）"，这里改准一点**：五家的共识是**"不用 MHA"**，而不是"都用 MLA"。严格用 MLA 的是 3 家，V4 用的是共享 KV 的 MQA，M3 用的是 GQA。**共识在"结论"上，不在"手段"上**——这个区别在判断一项技术成熟度时很要紧（[07 章 §7.6](07-MHA到MLA.md)）。
