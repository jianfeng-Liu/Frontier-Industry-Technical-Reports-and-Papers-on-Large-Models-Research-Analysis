# 17 · 接下来读什么

> 这一章是**出口**。你已经有了读懂那五份技术报告所需要的全部概念，这里给出一条推荐的阅读顺序，以及这份教程**没有覆盖**的部分在哪里。

---

## 17.1 推荐顺序

```
① 先读 [../模型技术对比.md](../模型技术对比.md) 的 §一（五条长上下文路线）
      → ★ 你现在应该能看懂那五句话在说什么了
      → 如果看不懂，回去补 [08 章](08-高效注意力.md)

② 挑一家单独读完整的模型文件
      ⭐ 推荐从 [../openPangu-2.0-Pro.md](../openPangu-2.0-Pro.md) 开始
         理由：它的报告最完整、工程细节最全，而且它【一个模型里】
         同时用了 MLA + DSA + SWA + PAS + mHC + Muon + MoE + MTP
         —— 等于把本教程十四章的东西全部用了一遍

      如果你更关心"新想法"而不是"完整工程"，
      那就先读 [../Kimi-K3.md](../Kimi-K3.md)（KDA / NoPE / AttnRes / SiTU-GLU / LK loss，
      每一处都是独立的创新）

③ 再回到 [../模型技术对比.md](../模型技术对比.md) 的 §三（逐维度深入）
      每一小节都对应本教程的某一章，见下表

④ 想再往下挖，读 [../papers/](../papers/) 里的原始 PDF
```

## 17.5 ★ 最后：读技术报告的几条经验

**这几条是我在整理这五份报告的过程中最有用的习惯，比任何单个知识点都值钱。**

```
① ★ 不要问"他们用了什么技术"，要问"是什么约束逼他们必须这么做"
   技术是果，约束是因。[15 章 §15.4] 那三条因果链就是这么找出来的

② ★ 看空白，不只看内容
   一份报告【没写什么】往往和写了什么一样有信息量
   → [09 章 §9.5] openPangu 的激活函数空格，是从"它只做 8-bit"反推出来的
   → [15 章 §15.2] 五家都没动 W_O，这个 0/5 本身就是一个结论

③ ★ 警惕"事后归因"
   技术报告记录的是"我们做了什么、结果如何"，
   而"为什么有效"那部分常常是【事后叙述】，不是受控实验
   → [13 章 §13.8] 三家对同一现象给出三种互斥归因，没有一家做了消融

④ ★ 数字要能互相印证 —— 但先确认两个数在【同一个口径】上
   最有效的自检是【两条独立的路算出同一个数】。两个真例子：

   ✅ openPangu 的 505B：按报告 Table 8 的配置一项一项加出来是 504.36B，
      和报告写的 505B 只差 0.13% —— 说明这个拆法基本对（[01 章 §1.4.2]）
   ✅ 它 8K 和 128K 的 TPOT 几乎一样（9.53 vs 9.55 ms，只差 0.02 ms）——
      说明 KV cache 读取在 128K 下依然不是主导项，
      和"MLA 相对 MHA 压 17.8× + 2/3 的层是窗口 512 的 SWA"一致
      （TPOT = Time Per Output Token，每吐一个字的延迟，见 [06 章 §6.1]）

   ⚠️⚠️ 反面例子（这一条我先前自己就写错过）：
      "18B 激活参数 ÷ 带宽 = 延迟理论下界，再和实测 TPOT 对照"
      这个除法在 openPangu 身上【做不成】，两个口径都对不上：
        ① 它跑在昇腾 NPU 上，不是 H100。910B3 的 HBM 带宽约 1.6 TB/s
           （⚠️ 推断值），只有 H100 的 3.35 TB/s 的一半
        ② 更要紧：它是 MoE 且走 EP（专家并行），报告的部署是 2P1D 八节点，
           那 18 GB 激活权重被【摊到几十张卡上并行读】，每卡只读自己那一份
      ⟹ 分子分母不在一个口径上，算出来的 6 ms 既不是下界也不是上界
         完整讨论见 [06 章 §6.4]
   → 所以：当两个数字对不上时，先问是不是【口径】不对，
     而不是急着宣布"报告错了"或者"✅ 自洽"

⑤ ★ 一手报告 > 二手解读
   本教程里归属到厂商的配置与数字，都在对应的模型文件里标了出处，
   多数可以在 [../papers/](../papers/) 的 PDF 里回溯到原文，有疑问以 PDF 为准
   ⚠️ 但覆盖度不齐：papers/ 里 DeepSeek-V4 只有一份英文 model card
      （V4.1 才有完整技术报告），MiniMax M3 根本没有技术报告
      —— 它的架构数字来自 HF 的 config.json，见 [../MiniMax-M3.md](../MiniMax-M3.md) §三
   ⟹ 看到"⚠️ 推断"标记，就是原文没写、我从别处推出来的
```

## 17.6 最后的最后

```
    这份教程正文十七章，外加两章加餐（[18 Engram 与条件记忆] / [19 算子开发与实现]），
    但真正需要记住的只有三件事：

    ① Transformer 只有两块积木（横向混合的 Attention，纵向变换的 FFN），
      和一条把它们串起来的总线（残差流）。
      所有创新都发生在这三个地方。            → [01 章] / [03 章]

    ② decode 是访存受限的。
      这一条解释了这一代 80% 的架构决策。      → [06 章]

    ③ softmax 每行的和必须是 1。
      这一条解释了剩下的 20%。                → [05 章 §5.5] / [14 章 §14.6]
```
