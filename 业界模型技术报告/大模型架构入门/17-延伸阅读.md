```

## 17.3 ⚠️ 本教程没有覆盖的部分

**这份教程只讲【模型架构】。以下几块同样重要，但完全不在范围内：**

| 主题 | 为什么重要 | 在哪些文件里 |
|---|---|---|
| **后训练 / RL / on-policy 蒸馏** | ⭐ 这一代模型能力差距的**主要来源可能在这里，而不在架构** | 五份模型文件的「后训练」章 + 对比 §3.6 |
| **训练基础设施**（并行策略、通信、kernel） | MoE 的 all-to-all 通信常常是真正的瓶颈（[10 章 §10.3](10-MoE.md)） | 五份模型文件的「Infra」章 + 对比 §四 |
| **多模态**（ViT、视觉 token） | — | [../Kimi-K3.md](../Kimi-K3.md) §六、[../MiniMax-M3.md](../MiniMax-M3.md) |
| **训推一致性 / 数值确定性** | 和 [14 章 §14.11](14-量化.md) 那条"消除 mismatch"主线直接相关 | [../openPangu-2.0-Pro.md](../openPangu-2.0-Pro.md)（这块它做得最深）+ 对比 §七 |
| **数据**（配比、清洗、合成） | 各家披露都极少 | 各模型文件零散提及 |

> ⚠️ **特别提醒第一行**：**架构只解释了一部分能力差异。** 这一代五家的架构差异其实没有想象中大（[15 章 §15.5](15-五家总装图.md) 那份"五家共识"清单很长），**而后训练的差异可能更大，只是各家披露得更少、更难比较。**
>
> **不要因为读完了架构，就以为解释了排行榜。**

## 17.5 ★ 最后：读技术报告的几条经验

**这几条是我在整理这五份报告的过程中最有用的习惯，比任何单个知识点都值钱。**

```
① ★ 不要问"他们用了什么技术"，要问"是什么约束逼他们必须这么做"
   技术是果，约束是因。[15 章 §15.4] 那三条因果链就是这么找出来的

② ★ 看空白，不只看内容
   一份报告【没写什么】往往和写了什么一样有信息量
   → [09 章 §9.5] openPangu 的激活函数空格，是从"它只做 8-bit"反推出来的
   → [15 章 §15.2] 五家都没动 W_O，这个 0/5 本身就是一个结论

③ ★ 警惕"事后归因"
   技术报告记录的是"我们做了什么、结果如何"，
   而"为什么有效"那部分常常是【事后叙述】，不是受控实验
   → [13 章 §13.8] 三家对同一现象给出三种互斥归因，没有一家做了消融

④ ★ 数字要能互相印证
   openPangu 的 18B 激活参数 ÷ 3 TB/s 带宽 ≈ 6 ms 理论下界，
   而它实测 TPOT 9.53 ms —— ✅ 自洽
   （TPOT = Time Per Output Token，每吐一个字的延迟，见 [06 章 §6.1]）
   它 8K 和 128K 的 TPOT 几乎一样（9.53 vs 9.55）——
   ✅ 说明 KV cache 读取确实不是它的瓶颈，和 MLA 压缩 17.8× 一致
   → 当一个数字对不上时，往往是你理解错了，或者报告漏了条件

⑤ ★ 一手报告 > 二手解读
   本教程里所有归属到厂商的数字，都能在 [../papers/](../papers/) 的 PDF 里回溯到原文
   有疑问以 PDF 为准
```

    但真正需要记住的只有三件事：

      这一条解释了这一代 80% 的架构决策。      → [06 章]

    ③ softmax 每行的和必须是 1。
      这一条解释了剩下的 20%。                → [05 章 §5.5] / [14 章 §14.6]
```
