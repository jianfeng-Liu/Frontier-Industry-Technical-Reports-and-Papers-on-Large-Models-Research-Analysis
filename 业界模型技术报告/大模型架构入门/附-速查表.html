A. 形状与记号

─ 形状 ────────────────────────────────────────────────
  x            [B, L, d]          残差流（"总线"）
  Q, K, V      [B, H, L, d_h]     注意力的三个角色
  scores       [B, H, L, L]       ★ O(L²) 就在这里
  KV cache     [B, L, H_kv, d_h] × 2 × 层数   ★ 是 H_kv，不是 H
  logits       [B, L, V]          每个位置对词表的打分

─ 记号 ────────────────────────────────────────────────
  B    = batch                  L    = 序列长度
  d    = hidden 维（d_model）    H    = 注意力头数
  H_kv = ★ KV 头数（GQA 里比 H 少几倍，MQA = 1）
  d_h  = 每头维度                d_ff = FFN 中间维
  V    = 词表大小                N    = 层数
  γ    = 投机解码一次猜几个       α    = 单步接受率
  g    = 量化分组大小            c    = 草稿/主模型单步耗时比

  约定：本教程用【行向量】，即 x @ W（x 在左）

  ⚠️ 唯一的例外：`6N`（训练 FLOPs）和 `16 字节/参数` 这两笔账里的 N
     沿用文献习惯，指【参数量】。本表其余所有地方 N 一律是【层数】。
  ⚠️ 单位口径：算容量一律 GiB / KiB（2³⁰ / 2¹⁰），算带宽才用十进制 GB / TB。
     两套差 7.4%，混着用是这个主题最常见的错账来源。

B. 核心公式

─ 前向 ────────────────────────────────────────────────
  RMSNorm(x)  = x / √(mean(x²)+ε) ⊙ g
  Attention   = softmax(QKᵀ/√d_h + M) V
  RoPE        θ_i = base^(−2i/d_h)，位置 m 转 m·θ_i
    核心性质  ⟨R_m q, R_n k⟩ = ⟨q, R_{n−m} k⟩   只依赖相对距离
    ★ V4 变体 压缩后的 KV entry 兼作 value，输出会带【绝对】位置
              → 给输出再补一次位置 −t 的 RoPE 转回相对  [11.9]

  SwiGLU(x)   = W_d( SiLU(W_g x) ⊙ W_u x )
    SiLU(x)   = x·σ(x)
    ⚠️⚠️ d_ff = 8d/3 【不是定律】。8/3 只是"GLU 有三个矩阵，要乘 2/3
       才和 d_ff = 4d 的两矩阵 FFN 等参数"这个【折算系数】，不是最终答案。
       真实配置的 d_ff / d：
         LLaMA-2-7B  2.69      LLaMA-2-13B 2.70      LLaMA-2-70B 3.50
         LLaMA-3-8B  ★ 3.50（h=4096、intermediate=14336）
         LLaMA-3-70B 3.50      Mistral-7B  3.50
       ⟹ 既不是 4，也不是 8/3。见到恰好 4.0 反而要怀疑它没用 GLU  [9.3]

  MoE(x)      = Σ_{i∈TopK} (s_i/Σs) · E_i(x)
  残差        x_{l+1} = x_l + F_l(x_l)
    mHC       x_{l+1} = B_l x_l + C_l F_l(A_l x_l)，B 双随机
    AttnRes   x_l = Σ_{i<l} α_{i→l} · f_i(x_i)   ★【替换】累加
      源 k_i = v_i = f_i(x_i)【增量】，i=0 是 embedding；无 W_K / W_V
      α_{i→l} = softmax_i( w_lᵀ · RMSNorm(k_i) )   无 1/√d
      标准残差 = α ≡ 1 的特例；Σα = 1 → √N 增长消失
      K3 Block 版：93 层切【8 块】（7 个满块 × 12 层 + 1 个 9 层尾块），
                   块【内】求和、块【间】注意力  [3.6.8]

─ MLA ────────────────────────────────────────────────
  只缓存 c^KV = x W_DKV（低维），用时再升维
  矩阵吸收    qᵀk = c^Q ᵀ(W^UQ ᵀ W^UK) c^KV
    ★ 被吸的是【上投影矩阵】，方向是：W^UK → 吸到 Q 侧，W^UV → 吸到输出侧
  ⚠️⚠️ 吸收【不改变 cache 里存什么】—— 照样缓存压缩后的 c^KV，
        这正是 MLA 省显存的全部来源。写成"吸收后 K 直接算出来、
        不用存 c^KV"就全错了（那样存的是全维 K，压缩率归零）
  ⚠️ 吸收也不是"计算量也变小"：head_dim 从 128 变成 512，注意力 FLOPs ×4。
     赚的是 decode 不必物化 K/V ⟹ 训练/Prefill 走非吸收式、Decode 走吸收式
  ⚠️ RoPE 会插在两个上投影矩阵中间 → 吸收失效 → decoupled RoPE
  openPangu：512（压缩，无 RoPE）+ 64（解耦，有 RoPE）= 576     [7.4/7.5]

─ 线性注意力 ──────────────────────────────────────────
  ★★ 全部来自结合律：(QKᵀ)V → Q(KᵀV)
     2L²d  →  2Ld²    省 L/d 倍（L=1M, d=128 → 8192×）
     ↑ 中间那个 [d,d] 就是"全部历史"被压成的唯一容器
  前提     exp(qᵀk) 不可分解 → 换成 φ(q)ᵀφ(k) 才能挪括号
  因果掩码 → 上界随 i 变 → 滚动累加 → ★ 这就是 RNN 递推
  S_t = S_{t−1} + φ(k_t) v_tᵀ,      o_t = φ(q_t)ᵀ S_t
    φ(k)v ᵀ 是【外积】[d_k,d_v]；S 的形状里【没有 L】
  delta rule  S_t = (I − β_t k_t k_tᵀ)·Diag(α_t)·S_{t−1} + β_t k_t v_tᵀ
    来历：对 ½‖Sᵀk_t − v_t‖² 走一步梯度下降（Widrow–Hoff）
    α_t ∈ (0,1)^{d_k} 【逐通道】遗忘门 ← Kimi 的核心贡献
    β_t ∈ (0,1) 是【标量】写入强度；‖k‖=1 时 β=1 即精确覆盖
  ★ 状态大小恒定，与 L 无关 —— 但召回能力受限于状态容量
    1M 上下文单头：KV cache 512 MiB  vs  状态 32 KiB（16384×）  [8.5]

─ 训练 ────────────────────────────────────────────────
  训练目标    L = −(1/L) Σ log P(x_{t+1} | x_≤t)

  前向 FLOPs  ≈ 2N   （N = 参与计算的参数量；MoE 这里要用【激活参数】）
  训练 FLOPs  ★ ≈ 6N = 2N 前向
                     + 2N 反向算【输入】梯度（往前一层传）
                     + 2N 反向算【权重】梯度（这一层参数怎么改）
    ⚠️ 6N 【不含】优化器更新，也不含激活重计算
    补全式    6N + 12 · L_layers · s · h     ← 把注意力矩阵那一项补回来
              Llama-3-70B（80 层 / h=8192 / N=70B）：
                 s = 4096  →  3.22e10 vs 6N = 4.2e11  →  ★ +7.7%
                 s = 8192  →  6.44e10 vs 6N = 4.2e11  →  ★ +15.3%
    ⚠️ 该补正项【未扣因果掩码】（实际只算一半），是【上界】；
       对 DSA-SWA 这类注意力成本常数化的架构不适用           [1.5.2]

  显存        ★ 16 字节 / 参数
              = BF16 权重 2 + 梯度 2 + FP32 主权重 4 + Adam m 4 + Adam v 4
    ⚠️⚠️ m 和 v 是【各】4 字节，不是加起来 4。漏掉一半就会把
          70B 的 1120 GB 写成 560 GB、14 张 80 GB 卡写成 7 张
    Muon 不要 v → 12 字节 / 参数
          ⚠️ "优化器状态减半"≠"总显存减半"：16 → 12 是降 25%   [1.5.3/13.6]

  AdamW       θ ← θ − η( m̂/(√v̂+ε) + λθ )   ★ λθ 不过 √v
  Muon        G = UΣVᵀ → 用 UVᵀ 更新
    真正含义  谱范数球上的最速下降（不是"拉平奇异值"这个技巧）
    Newton-Schulz  X ← aX + b(XXᵀ)X + c(XXᵀ)²X
                   (a,b,c) = (3.4445, −4.7750, 2.0315)
                   ★ p'(0)=a 很大 → 极小奇异值也能被快速拉起；p(1)=0.701≠1
    用/不用   矩阵形参数 ✅ ／ embedding、LM head、norm ❌
    ★ 正交化谁  对象应是【逻辑上的一个线性映射】，不是显存里连续的一块。
                融合张量要先切开：
                W_qkv     → 按 Q/K/V、再按 head（GLM 的 Muon Split）
                W_gate_up → chunk(2) 各自正交化    ⚠️ 五家均未披露
                见 §13.7
  MoE 均衡    b_i ← b_i − γ(F_i − Q_i)/RMS(F−Q)   本质是积分控制器（I 控制器）

─ 投机解码 / MTP ──────────────────────────────────────
  接受概率    min(1, p(x)/q(x))
  残差分布    p' = max(0, p−q) / β
  单步接受率  α = Σ_x min(p(x), q(x)) = 1 − TV(p, q)

  ★★ 期望接受长度   E = (1 − α^(γ+1)) / (1 − α)     ← 就是几何级数求和
    ⚠️⚠️ 【不是 α × γ】，也不是 α × γ + 1。
          α = 0.95、γ = 4 的真值是 ★ 4.52（α×γ 给 3.80，α×γ+1 给 4.80）
          ★ α 越低，线性错法错得越离谱
    🔑 天花板  E → 1 / (1 − α)   （γ → ∞）
          α = 0.95 → 20.0    α = 0.8 → 5.0    α = 0.5 → 2.0
          ⟹ γ 加到多大都突破不了它；α 一掉，上限直接被压死        [12.5]

  加速比      ≈ E / (1 + γc)      c = 草稿/主模型单步耗时比
  MTP 模块    h'^k = M_k[RMSNorm(h^{k−1}); RMSNorm(Emb(t_{i+k}))]
  MTP 损失    L = L_main + (λ/D)·Σ_k L^k_MTP,   λ ≈ 0.1~0.3（主任务永远是主角）

  ✅ DeepSeek-V3 的官方口径（被传错得最厉害的一组数）：
       第二个 token 的接受率 ★ 85%~90%，据此解码吞吐（TPS）提升 ★ 1.8×
    ⚠️⚠️ 【不是 3×】。V3 的深度是 1，即 γ=1，代入 α=0.875 得 E = 1+α = 1.875，
          与官方 1.8× 吻合；而 γ=1 时理论天花板就是 1+α < 2，
          ★ 3× 在数学上根本到不了                                 [12.12]

  ★ 输出分布严格等于不用投机解码时 —— 纯加速，不是近似
  ⚠️ 但"配好了"≠"线上一定开"：batch 大到 decode 已算力受限时它会净亏

─ 量化 ────────────────────────────────────────────────
  对称量化    s = max|x| / (2^(b−1) − 1),   x_q = round(x/s)
  误差方差    Var[ε] = s²/12
  ★★ 铁律    scale 必须在【求和维】上是常数，否则提不出求和号

  有效位宽（★ scale 自己也占字节，所以"4-bit = 省 4 倍"只是上界）
    MXFP4  g=32、E8M0 scale（纯指数）→ 4 + 8/32 = 4.25 bit   压缩 3.76×
    INT4   g=128、非对称、FP16 scale → ★ 4.15625 bit（不是 4 bit）
                                       压缩 ★ 3.85×（不是 4×）   [14.5]

  十进制有效位 = log₁₀(2^有效数位)
    E4M3 ★ ≈ 1.2 位（尾数 3 bit + 隐含位 = 4 bit 有效数）
    E5M2   ≈ 0.9 位      INT8 ≈ 2.4 位      INT4 ≈ 1.2 位      BF16 ≈ 2.4 位
    ⟹ ★★ FP8 赢在【动态范围】，不赢在精度 —— E4M3 和 INT4 精度同量级，
         FP8 多出来的位全花在指数上，一位都没花在精度上
    ⟹ 分工：训练梯度能跨好几个数量级 → 必须 FP8；
            推理里没有离群值时 ★ INT8 per-channel 反而更准        [14.2]

  SmoothQuant  XW = (X·diag(s)⁻¹)(diag(s)·W)    结果不变
               s_j = max|X_j|^α / max|W_j|^(1−α),   α ≈ 0.5
  旋转量化     XW = (XQ)(Qᵀ W)，Q 正交           结果不变
  QAT 的 STE   forward = x_q, backward = 1   写作 x + sg(x_q − x)
  记号         W8A8 / W4A16 / W4A8 / KV8

C. 关键的量级感

─ H100 SXM5：一切估算的锚点 ───────────────────────────
  BF16 / FP16 【稠密】算力   ★ 989 TFLOPS
  FP8（E4M3 / E5M2）        1979 TFLOPS
  INT8                      1979 TOPS
  FP32                      67 TFLOPS
  HBM3                      80 GB / 3.35 TB/s（实际可用 79.6 GiB）
  ★ 屋脊点（ridge point）   BF16    989 / 3.35 ≈ ★ 295 FLOP/字节
                            FP8·INT8             ≈ ★ 591（正好翻倍）

  ⚠️⚠️ BF16 的 1979 TFLOPS 是【2:4 结构化稀疏】值（要求每 4 个权重有 2 个是 0），
        稠密只有 989。拿 1979 去算 BF16 屋脊点会得到 591，
        把后面所有"算力受限还是访存受限"的判断整整带偏一倍。
        ★ 看到任何算力数字，第一句话先问：稠密还是稀疏？         [6.4/14.9]

─ KV cache 通式（★ 全教程最高频的算错点）──────────────
  每 token 每层 = 2 × H_kv × d_h × 字节数        ← 2 是 K、V 各存一份
  全量          = 上式 × 层数 × L × batch
                  （bytes：BF16 = 2，FP8 = 1，INT4 = 0.5）

  ⚠️⚠️ 公式里那个头数必须是 n_kv_heads，【不是 n_heads】。
        流传很广的简写「每 token 每层 = 4 × d_model 字节」只对 MHA 成立
        （只有 MHA 才有 H_kv × d_h = d_model）。套到别的架构上会高估：

          Llama-3-70B（GQA，80 层，64 q / 8 kv，d_h=128）
                正确 320 KiB/token   ❌ 硬套 2560 KiB   高估 ★ 8 倍
          同规模改成 MQA（1 kv 头）
                正确  40 KiB/token   ❌ 硬套 2560 KiB   高估 ★ 64 倍
          DeepSeek-V3（MLA，61 层，latent 512 + 解耦 RoPE 64）
                正确 68.6 KiB/token  ❌ 硬套 1708 KiB   高估 ★ 25 倍

  ★ 看到任何 KV cache 估算，第一件事是去 config.json 确认
    `num_key_value_heads`，而不是照抄公式                          [6.3]

─ 显存账 ──────────────────────────────────────────────
  505B 权重   BF16 1010 GB / INT8 505 GB / FP4 253 GB
              （✅ openPangu 报告实测 BF16 1009 GB、W8A8 517 GB）
  MHA 500B 级（50 层、d=5120、64 头、d_h=80、BF16）
              ★ 1000 KiB ≈ 1 MB / token   ⟹ 128K 就已经装不进一张卡
  GQA-16（M3 口径：64 q / 4 kv、d_h=128、60 层、1M、BF16）
              2 × 4 × 128 × 2 = 2 KiB /层/token → 120 KiB/token
              ⟹ ★ 约 120 GiB（≈ 128.8 GB）
  MLA-576（512+64、50 层、512K、BF16）
              576 × 2 × 50 = 56.25 KiB/token  ⟹ 约 28 GiB
  训练静态状态 505B × 16 字节 = 8080 GB = 7525 GiB = 7.35 TiB
              ⟹ ★ 光是静态状态就要 101 张 80 GB 卡（不含激活、通信缓冲、KV）

  ⚠️ 上面这几行 KV 数字是按标准配置的【推演】，用来建立直觉，
     不是任何一家的官方披露值。

─ 卡间带宽（★ 口径最容易被放大一倍的地方）──────────────
  NVLink      标称 900 GB/s 是【双向聚合】带宽 → 算单向要用 ★ 450 GB/s
  InfiniBand  400 Gb/s 里的小写 b 是【比特】 → ÷ 8 = ★ 50 GB/s 才是字节口径
  ⟹ 同口径下 NVLink : IB = 450 : 50 = ★ 9 倍，【不是 18 倍】
     （900 ÷ 50 = 18 是拿双向比特混着单向字节比出来的）           [2.3/10.5]

─ 计算账 ──────────────────────────────────────────────
  单层 FLOPs（每 token）≈ 8d² + 6d·d_ff + 4Ld
        └ 8d² 四个注意力投影   6d·d_ff 三个 FFN 矩阵   4Ld 注意力矩阵
    L = 4K 时 4Ld 项占 ~12%
    L = 1M 时 4Ld 项占 ~97%   ← ★ 长上下文的全部麻烦就在这一项
  长度 128K → 1M：单 token 的这一项 ×8，【整条序列】的这一项 ×64
  记法：前向 FLOPs ≈ 2 × 参与计算的参数量（一次乘加 = 2 FLOP）

─ 稀疏度：口径决定结论 ────────────────────────────────
  ✅ 正确口径    总参数 ÷ 激活参数   —— 这才是"显存账 vs 算力账"的比值
       openPangu-2.0-Pro：505B / 18B = ★ 28.1 ×
       其余：V4-Pro 32.7× ／ K3 26.7× ／ M3 见 §E 的 ⚠️
  ❌ 错误口径    路由专家数 ÷ 激活专家数（384 / 8 = 48×）
       那只是【路由选择比】，不是全模型稀疏度。
    ⚠️ 差别来自"注意力 + Embedding 这部分【完全不稀疏】"：
       它只占 openPangu 总参数的 ★ 1.3%，却占激活参数的 ★ 35%。
       分母里那 35% 拖住了整体稀疏度，48× 因此虚高                [1.4.4]
  参数量经验：MoE ≈ √(总参数 × 激活参数) 量级的稠密模型   ⚠️ 很粗糙

─ 两个阶段 ────────────────────────────────────────────
  prefill：一次处理 L 个 token   → compute-bound  → 决定 TTFT
  decode ：一次处理 1 个 token   → memory-bound   → 决定 TPOT
    TTFT = Time To First Token   首字延迟，按回车到第一个字（秒）
    TPOT = Time Per Output Token 每字延迟，之后每个字的间隔（毫秒）
           = 你看到的「打字速度」，10 ms → 每秒 100 字
    TPS  = Tokens Per Second     吞吐量，一块卡每秒总产出
           ★ TPS ≈ batch ÷ TPOT，两者互相打架（延迟 ↔ 吞吐取舍）
    ISL / OSL = 输入 / 输出序列长度（"8K+1K" = ISL 8K，OSL 1K）
    ★ decode 的算术强度 ≈ batch size（远小于屋脊点 295）
    ★★ 所以：省 KV cache 的字节数 ≈ 直接提吞吐

─ 读数字时的五个陷阱（★ 每条都值一倍的误差）────────────
  ① GB ≠ GiB
       1 GB = 10⁹ 字节，1 GiB = 2³⁰ ≈ 1.074×10⁹ 字节，差 7.4%。
       容量用 GiB、带宽用十进制 GB；厂商标的"80 GB"是十进制口径。
  ② 「时间减少 X%」≠「加速 X%」
       加速倍数 = 1 / (1 − 时间减少比例)
       时间减少 60%  ⟹  加速 ★ 2.5 倍（不是 1.6 倍，更不是"快 60%"）
       反过来：加速 2 倍 ⟹ 时间减少 50%
  ③ MFU（Model FLOPs Utilization，模型算力利用率）★ 必须带硬件平台
       "35% MFU"在 H100 千卡 MoE 训练上和在昇腾 NPU 上完全不是一件事。
       ⚠️ 而且分子用 6N 还是补全式也会差出 15%：
          s ≥ 32K 还只用 6N 算分子，就是在虚报效率。
  ④ 「某项减半」≠「总量减半」
       Muon 把优化器状态从 8 字节降到 4 字节是减半，
       但每参数总显存 16 → 12 只是降 25%。这类偷换在读报告时极常见。
  ⑤ 无一手来源的「实测」数字，一律标 ⚠️ 之后再引用。

D. ★ 三条因果链（全书骨架）

① softmax 每行和必须为 1
     → 模型自造巨大激活当泄压阀（attention sink）
     → 这些巨大激活就是离群值
     → 量化 scale 被绑架
     → ★ 低比特量化困难
   ⟹ 解释了：显式 sink 机制的兴起、稀疏化必须打 sink 补丁、4-bit 为何难

② 想要 4-bit → PTQ 不够 → 必须 QAT
     → QAT 下激活离群值会失稳 → 必须治离群值
     → SwiGLU 无界相乘是主要产地 → ★ 必须给激活加界
   反向：停在 8-bit → 容忍度高 16 倍 → 没有加界的动力
   ⟹ 解释了：V4 clamp / K3 SiTU-GLU / M3 clamp，以及 openPangu 那个空格

③ decode 访存受限（算术强度 ≈ batch size ≪ 295）
     → ① 省 KV cache ≈ 直接提速   ⟹ 解释了五家在注意力上的全部投入
     → ② 有免费算力可以拿来"猜"  ⟹ 解释了 MTP / 投机解码

G4. ★ 推理性能指标（报告"部署"一节几乎只报这几个）

缩写 全称 中文 一句话
TTFT Time To First Token 首字延迟 按下回车 → 看见第一个字，等了多久（秒）。由 Prefill 决定
TPOT Time Per Output Token 每字延迟 之后每多蹦一个字的间隔（毫秒）。由 Decode 决定。★ 就是你看到的"打字速度"，10 ms ≈ 每秒 100 字
ITL Inter-Token Latency 词间延迟 和 TPOT 是同一个东西，不同论文的不同叫法
TPS Tokens Per Second 吞吐量 一块卡每秒总共吐多少 token
ISL / OSL Input / Output Sequence Length 输入/输出长度 表头的 "8K+1K" = 输入 8192、输出 1024 
★★ TPOT 和 TPS 最容易混，务必分清：

   TPOT  「我这一个用户要等多久」   延迟   越小越好
   TPS   「这块卡一共干了多少活」   产能   越大越好

   两者的关系：  TPS ≈ batch ÷ TPOT
   ⚠️ 而且它们互相打架：batch 开大 → TPS 涨，但每个人的 TPOT 变差

   ✅ openPangu 报告里就是一对活例子（同一个模型的两个取舍点，8K+1K）：
       超低延迟档： TPOT  9.53 ms                      ← 延迟优先
       高吞吐档：   TPOT 23.2 ms，batch 40，1727 TPS   ← 吞吐优先
   ⚠️ 这两组数【不能凑在一起用】（报告没给超低延迟档的 batch 和 TPS）。
      验算：40 ÷ 0.0232 s ≈ 1724 TPS，和 1727 只差 0.2% —— 高吞吐档自洽

   一次完整对话的耗时 ≈ TTFT + TPOT × 输出字数
