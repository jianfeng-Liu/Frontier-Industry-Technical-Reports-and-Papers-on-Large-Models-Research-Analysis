| **MiniMax M3** | ⚠️ **有机制论文，无模型报告** | 30 + 35 | ⚠️ **MSA 论文**（arXiv:2606.13392）讲清了注意力机制但实验在 **109B/6B 试点**上做；**M2 系列报告**（arXiv:2605.26494）讲的是上一代。M3 自身的训练流程、语料规模、后训练配方**全部缺失** |

**后果**：下表中 GLM 与 MiniMax 两列凡是标 `—(未披露)` 的，含义是"公开材料没把它列为改动点"，**不等于没做**。GLM 的 5.1 → 5.2 增量、MiniMax 的 M2 → M3 训练侧增量，都**完全没有公开材料**。

**但 MiniMax 有一个别家没有的补偿**：M3 的 Hugging Face `config.json` 把 `sparse_attention_config` 完整公开了，且**每一个超参都和 MSA 论文一致**（`sparse_block_size:128` = B_k、`sparse_topk_blocks:16` = k、`sparse_num_index_heads:4` = KV 头数、`sparse_init_block:0` / `sparse_local_block:1` 正好对应论文 §C.2 的最终配方）。**所以"论文描述的是不是出货模型"这个问题，MiniMax 是五家里唯一能被出货配置直接验证的。**

### ⚠️ openPangu 的资料不对称是另一种性质：报告很全，但没有对手

openPangu 有一份 45 页的完整一手报告，架构、超参、课程、后训练、Infra、消融都披露得很细——**这一维度上它和 V4/K3 是同一档的。**

**但它的报告里没有任何对照模型。** 全文关键词计数：

```
Kimi / MiniMax / Claude / GPT- / Gemini  →  0 次
Qwen                                      →  1 次（仅参考文献）
GLM                                       →  2 次（1 次参考文献，1 次说明自家 OPD 与 GLM-5 的实现差异）
```

**Table 5 唯一的对照维度是 Flash vs Pro、Thinking vs Non-Thinking。** 所以本文 §5 里所有涉及 openPangu 的横向分数**都是我跨厂商拼出来的**，采样协议不同、评测子集口径不同，**方向可信，具体分差不可信到小数点**。

另外，**openPangu 报告里完全没有长上下文评测**：`RULER` / `MRCR` / `NIAH` 关键词命中 0 次。它宣称 512K，但没有任何逐长度召回数据——比 GLM-5.2 的"1M 无曲线"更彻底，而且它是五家里唯一**不到 1M** 的。

所以本文的对比强度是：

```
架构层        →  五方可比
后训练层      →  四方可比（M3 无材料）
横向性能      →  V4/K3/GLM/M3 之间有桥接节点；openPangu 是孤岛，只能拼

版本增量      →  GLM 5.1→5.2、MiniMax M2→M3 完全不可比
```

## 一、核心分歧：五条不同的长上下文路线

五家都把「原生百万级上下文」当成这一代的目标（openPangu 是唯一的例外，停在 512K），但赌的是不同的东西：

> **V4 说**："softmax 注意力是对的，只是 KV 太多了，那就**压缩它**。"
> **K3 说**："1M 长度下 softmax 注意力本身就该**退居配角**，主力换成固定状态的线性注意力。"
> **GLM-5.2 说**："softmax 注意力和 KV 都别动，**只挑重要的那 2048 个看**——然后再把'挑'这个动作本身的开销跨层摊薄。"
> **MiniMax M3 说**："**我们三条路都跑过了。**线性注意力在长上下文多跳推理上不行（M1→M2 退回全注意力），全注意力太贵，所以走**块级动态选择**——每个 GQA 组各选 16 个 128-token 块，也是 2048。"
> **openPangu 说**："**分工。**三层里一层做全局稀疏选择（DSA），两层做固定 512 窗口的局部（SWA）——全局层负责长程依赖，局部层负责邻域交互，各干各的。"

- **V4（压缩派）** 保留 softmax 注意力的全部语义，在它前面加一层「学出来的压缩」——CSA 压 4:1 做精读、HCA 压 128:1 做泛读，交替堆叠。KV cache 仍随长度增长，只是常数被压到约 2%。
- **K3（换核派）** 直接换掉 75% 的注意力层：KDA 是线性注意力，状态是**固定大小的矩阵**，与序列长度无关；只留 25% 的 Gated MLA 承担"精确回忆"。
- **GLM-5.2（选择派·token 级）** 走 DeepSeek 的 DSA 路线：KV 全量保留、注意力仍是 softmax，只用一个轻量 indexer 给每个 query 选 top-2048。它的独创点不在稀疏本身，而在**发现 indexer 已经变成新瓶颈**（200K prefill 下占 81% 延迟），然后用 IndexShare 让 4 层共用一次索引计算。
- **MiniMax M3（选择派·块级）** 也是稀疏选择，但粒度是**块**而非 token：`B_k=128` 的块、每组选 `k=16` 块，恰好也是 2048。它的独创点在**怎么把 indexer 训准**——KL 对齐 + 梯度 detach + indexer warmup 三件套，以及一整章的 GPU kernel 协同设计。
- **openPangu-2.0（层间分工派）** 是唯一一个把**稀疏选择和位置先验混在同一个模型里**的：`DSA → SWA → SWA` 的 1:2 交错，SWA 窗口固定 512。DSA 只装在 1/3 的层上，全局选择的成本按比例砍到 1/3；SWA 层则用最便宜的方式覆盖局部。它的独创点是给这套混合配了 **PAS（参数化注意力汇聚点）**——因为 SWA 层"窗口里没东西可看时也必须把注意力质量分出去"，需要一个固定的兜底通道。

**五条路线其实是同一个问题的五个层次**：

```
V4：        减少「要看的东西」的数量      —— 压缩表示
K3：        减少「要存的东西」的数量      —— 更换机制
GLM：       减少「决定看什么」的成本      —— 摊薄元开销
MiniMax：   提高「决定看什么」的准确率    —— 训练 indexer 本身
openPangu： 减少「需要决定的层」的数量    —— 只让 1/3 的层去做选择
```

**GLM 和 MiniMax 落在同一格里**（精确 softmax + 动态稀疏选择 + 2048 预算），但**关心的子问题正好互补**：GLM 问"indexer 太贵怎么办"，MiniMax 问"indexer 选不准怎么办"。两者不冲突，理论上可以叠加。

**openPangu 则和 GLM 的 IndexShare 是同一类思路的两种极端形式**：

```
IndexShare（GLM）  ：所有层都是 DSA，但每 4 层只算一次索引，其余层复用位置列表
DSA-SWA（openPangu）：只有 1/3 的层是 DSA，其余层根本不做全局选择，改用固定窗口
```

**GLM 让"不算索引"的层继续做全局稀疏注意力；openPangu 让它们退化成局部注意力。** 前者保住了全局覆盖但省得少，后者省得更彻底但把长程依赖全押在 1/3 的层上。**这两种取舍谁更对，目前没有任何一方做过对照实验。**

有意思的是，**GLM 的路线是五者中最保守的**（不改残差、不改激活函数、不换注意力核），却在 agentic 编程上拿到了开源里最好的成绩之一。这本身就是一个信号：**这一代的能力差距，架构贡献可能小于后训练贡献。**

**而 MiniMax 提供了这个信号的反面佐证**：它是唯一一家把"efficient attention 到底行不行"做成可复核实验并公开的团队，结论是——**在 32K 以内几乎无差别，问题全部出在 32K 以上**（见 §3.1 的 SWA 消融对照）。

**openPangu 又给这条线加了第三份同向证据，而且是唯一给出量化安全线的一份**：它试过 SWA:DSA = 3:1 和 5:1，**在 4K 上性能不掉，但扩到 32K/128K 时训练 loss 退化**，最终定在 1:2。见 §3.1.1。

## 三、逐维度深入分析

### 3.1 长上下文：压缩 vs 换核 vs 选择 vs 分工

| | V4（压缩派） | K3（换核派） | GLM-5.2（选择派·token） | MiniMax M3（选择派·块） | openPangu（分工派） |
|---|---|---|---|---|---|
| KV 增长 | 线性，常数极小（1M 下约基线 2%） | KDA 层**恒定**，1/4 MLA 层线性 | **线性、全量**——这是它的明确代价 | **线性、全量**（但 KV 头减半到 4） | **2/3 的层恒定**（512 窗口），1/3 的层线性 |
| 精度损失来源 | 压缩本身有损（4:1 / 128:1） | 线性注意力**会遗忘** | **top-k 之外的 token 直接看不见** | **top-k 之外的块直接看不见** | **SWA 层看不见 512 以外**；DSA 层看不见 top-k 以外 |
| 补偿手段 | 重叠压缩抹平块边界 + 128 滑窗 + attention sink | 3:1 混合，末尾强制一层 MLA；逐通道遗忘门 | k=2048 已足够大；indexer 是学出来的 | **KL 对齐 + 梯度 detach + warmup** 把 indexer 训准；强制局部块；前 3 层全注意力 | **1:2 比例是扫出来的**（3:1、5:1 在 4K 尚可，32K/128K 就退化）；**PAS 给 SWA 层一个恒定的注意力泄压口** |
| 硬约束 | 需要 Lightning Indexer 做 top-k | 需要**下界化衰减** g_min=−5 让 BF16 不溢出 | **indexer 本身 O(NL²)** 成为新瓶颈 → IndexShare | **必须 detach**，否则 KL 梯度回流主干会引发 loss 发散 | **Indexer 辅助 loss 系数必须小（0.1）**，"a large coefficient yields excessive gradients that compromise training stability" |
| 副产品 | QK-RMSNorm 顺带免掉 Muon 的 QK-Clip | NoPE 让 1M 外推**不需要改任何位置编码参数** | Muon Split 顺带免掉 attention logit clipping | 免 exp 的 top-k（softmax 保序）+ LSE 融合省掉 KL 的一次前向 | DSA 只装在 1/3 的层上 → **prefill FLOPs / 解码 cache 读取 / 解码 cache 显存三项都是同构纯 DSA 的 1/3** |
| 独有洞察 | 交替"精读/泛读"层：没有一层既细又全，堆起来两者都有 | 状态大小与长度解耦 → KV pool 能 offload/prefetch | **稀疏注意力的瓶颈已经从"算注意力"转移到"决定算哪些"** | **不 detach 的话模型会作弊**——它不去学"选得更准"，而是去学"把主分支注意力分布简化到容易选" | **省的不是"每层算多少"，而是"有多少层需要做决定"**——只让 1/3 的层承担选择成本 |

**GLM 那条"独有洞察"值得单独拎出来**。IndexCache 论文测出来：30B DSA 模型在 200K 上下文下，**prefill 阶段 81% 的时间花在 indexer 上**（10K 时只有 27%）。这意味着 DeepSeek 那条 DSA 路线走到长上下文极限时，省下的主注意力开销会被 indexer 吃回去。而 GLM 的解法基于一个很干净的实证观察：**相邻层的 top-k 选择重合度 70~100%**——那就没必要每层都算。

**MiniMax 那条"独有洞察"同样值得单独拎出来**（MSA 论文 §B.3）。如果不给 Index Branch 的输入做 `stopgrad`，KL loss 就变成了对主干的一个额外目标，于是出现**自蒸馏效应**：模型发现"把主分支的注意力分布变得更尖锐、更容易被索引命中"比"改进 Index Branch"更容易降低 KL——**结果是 indexer 没学好，主干反而被削弱了**，短上下文 benchmark 慢性回退。这是所有"用辅助 loss 训练路由/索引模块"的设计都会踩的坑。

**openPangu 提供了这个坑的第三方独立佐证，而且给的是另一种解法。** 华为的 Lightning Indexer 同样用一个辅助目标去拟合原生全注意力分数，报告写得很直白：**"a large coefficient yields excessive gradients that compromise training stability"**，所以系数只敢取 **0.1**。

```
同一个失效模式，两种止损方式：
  MiniMax  → 结构性隔断：KL 对齐 + 梯度 detach，让辅助梯度根本进不了主干
  华为     → 幅度性压制：保留梯度通路，但把系数压到 0.1
```

**两家独立踩到同一个坑，说明它不是某一份实现的 bug，而是"用辅助 loss 训索引模块"这个范式自带的结构性风险。** 而两种解法的分野也很清楚：detach 是把病因去掉，小系数是把症状压住——后者更简单，但"多小才够小"仍然是个需要扫的超参。

### 3.1.1 ⭐ 五家里最有价值的一份负面结果：MiniMax M2 的 SWA 消融

这是整份对比里**唯一一处有量化数据的失败实验**。别家都只说"我们评估过并放弃了"，MiniMax M2 系列报告 §2.2.2 把表放出来了——在 M2 架构量级上**续训了"数千亿到数万亿 tokens"**，扫过 SWA/全注意力比例、RoPE 设置、层内与层间混合、sink token 等维度：

| | 预训练阶段（全注意力 vs 混合 SWA） | SFT 之后 |
|---|---|---|
| **32K 以内** | **完全打平**：MMLU 85.5/85.6、MATH 60.3/60.3、RULER-32K CWE 99.0/99.0 | **互有胜负**：SWA 在 IFBench +4.1、XBench-ds +5.0、τ²-retail +5.2 上**反超** |
| **32K 以上** | **崩**：RULER-128K CWE **90.0 → 72.0**、MTOB e-k ChrF **44.8 → 27.2**、HELMET ICL 75.8 → 72.7 | **崩得更狠**：SWE-verified −4.5、BrowseComp-zh −4.1、τ²-telecom **−11.5** |

**把这张表和 GLM-5 报告的 SWA 消融、openPangu 的比例扫描并排看，三家独立得出了完全同向的结论**：

| | GLM-9B（RULER，无额外训练） | MiniMax M2 架构量级（续训数千亿~数万亿 token） | **openPangu**（MoE15B-A2B 消融） |
|---|---|---|---|
| **固定交错 SWA** | 128K 只剩 **6.51**（全注意力 75.28） | RULER-128K CWE **72.0**（全注意力 90.0） | **SWA:全局 = 3:1 / 5:1 在 4K 上不掉，扩到 32K/128K 训练 loss 退化** |
| **搜索/调优后的 SWA** | SWA Pattern 能到 **53.95** | 各种混合配置**全部**在检索、多跳推理、ICL 上退化 | **退到 1:2**（每 3 层必有 1 层全局），并给 SWA 层配 PAS 兜底 |
| 结论 | 固定位置模式是灾难性的 | **没有任何变体能在生产场景下可靠追平全注意力** | **滑窗比例有硬上限，而且这个上限随上下文长度收紧** |

**openPangu 这一份的独特价值在于它给出了"安全线"而不只是"红线"**。GLM 和 MiniMax 证明的是"SWA 会崩"，华为回答的是"崩在哪个比例上"——而且明确指出**同一个比例在 4K 上完全看不出问题、到 32K 才暴露**。这直接解释了为什么很多团队的短序列消融会给出过于乐观的结论。

⚠️ 但这三份证据的**可比性是有限的**：GLM 用的是 RULER 分数、MiniMax 用的是 RULER + 下游任务、华为用的是**训练 loss**（而且没有公开任何长上下文评测——`RULER`/`MRCR`/`needle` 在报告全文命中 0 次）。**"训练 loss 退化"和"长上下文检索崩掉"不是同一个量，只能说方向一致。**

**而 MSA 的对照数字是**：RULER-128K Overall **72.12 vs 全注意力 72.00（+0.12）**，HELMET-128K Overall 45.93 vs 46.53（−0.60）。

```
同样是"限制 receptive field"：
  固定位置的滑窗      → RULER-128K CWE 掉 18 分
  动态按内容选的 MSA  → RULER-128K 整体掉 0（甚至微涨）
```

**这是"动态选择 vs 位置先验"这个问题目前最干净的一组证据。** MSA 论文 §B.6 还专门做了 **FLOPs 对齐**的滑窗基线（同样的 token 预算、去掉 Index Branch），结果在 agent 任务困惑度上**全程劣于 MSA**——排除了"MSA 只是算得多"的解释。

> ⚠️ **但 M2 那张表不能推广成"SWA 不行"**。SWA 在 IFBench / XBench-ds / τ²-retail 上是**真的赢了**。它证明的是"**在 MiniMax 关心的长程 agent 任务上，SWA 的覆盖限制是致命的**"——换一家公司、换一个产品定位，同一张表完全可能读出相反的结论。

**五条路线的风险画像**：

- **V4 最保守**：softmax 的能力边界已知，压缩率是可调旋钮。
- **K3 最激进**：换掉了 75% 的注意力机制，但换来了两个别人拿不到的东西（状态与长度解耦、零成本长度外推）。
- **GLM 最省事**：DSA 是 DeepSeek 已经验证过的方案，GLM 只用 **20B tokens** 就完成了从 dense 到 DSA 的适配（**DeepSeek-V3.2 用了 943.7B，差 47 倍**）。IndexShare 也是在已有架构上的增量改动。**这种"低风险高杠杆"的选择，和它把预算重心压在后训练上是一致的。**
- **MiniMax 最有经验**：它是唯一一家把三条路（线性 → 全注意力 → 稀疏）都真跑过的。代价是**多花了整整一代**（M2 是纯全注意力，等于在效率上原地踏步一轮），收益是它对"什么会失败、为什么失败"的判断有实验支撑，而不是靠推理。
- **openPangu 最折中，也最没有验证**：把 SWA 的便宜和 DSA 的覆盖各取一半，成本三项都降到 1/3。但它同时也是**唯一一个既压了上下文（512K）又完全没公开长上下文评测的**——这套混合到底在 512K 上召回如何，目前无法核实。

**⭐ 顺带得到一个跨三家的数字：DSA 适配预算的离散度大得惊人**

| | 从 dense 转 DSA 的预算 | 附加条件 |
|---|---|---|
| **DeepSeek-V3.2** | **943.7B tokens** | — |
| **openPangu-2.0-Pro** | **100B tokens**（+ 8B dense 预热 @lr 1.0e-3） | 只在 512K 末段做，且**只转换全局层，SWA 层原封不动** |
| **GLM-5** | **20B tokens** | 1000 步 dense 预热 @lr 5e-3 → 2e-4 |

**47 倍的跨度。** 三家最终都声称"适配后与原模型持平"，那么这个预算显然不是由 DSA 本身决定的，而是由**基座状态、预热配方、以及"持平"的判定标准**决定的。华为的数字之所以落在中间，一个可能的解释是它只需要转换 1/3 的层——但报告没有做这个归因，**这仍是一个开放问题**。

### 3.1.2 ⭐ MSA vs DSA：两家走到同一个 2048，但每一步选择都不同

GLM-5.2 的 DSA 和 MiniMax M3 的 MSA 是这五家里**唯一一对可以逐条对照的方案**——同属"精确 softmax + 动态稀疏选择"，连预算都一样。（openPangu 用的也是 DSA，但它只装在 1/3 的层上、且是从 SWA 混合模型的末段转换而来，不构成同条件对照；相关差异单列在最后一行。）

| | **MSA**（MiniMax M3） | **DSA**（DeepSeek → GLM-5.2） |
|---|---|---|
| 底座注意力 | **GQA**（64 q / 4 kv） | **MLA**（解码时是 MQA 形态） |
| 选择粒度 | **块级**（`B_k = 128`） | **token 级** |
| 每 query 预算 | `k·B_k = 16 × 128 = **2048**` | **top-2048** |
| 谁来选 | **每个 GQA 组独立 Top-k**（4 组各选各的） | **所有头共用一个 Top-k** |
| 打分方式 | index Q·K 点积 → **块内取 max** | ReLU lightning indexer |
| indexer 规模 | 每组 1 个 Q 头 + **全局共享 1 个 K 头**，dim 128 | **32 头 / dim 128** |
| indexer 怎么训 | **KL 对齐 + 梯度 detach + warmup** | LM 梯度 |
| 引入方式 | **从零稀疏训练（MSA-PT）** 或 从 dense 转换（MSA-CPT） | **从 dense 转换**（continued pre-training） |
| 转换预算 | **400B tokens**（109B 试点上） | **20B tokens**（GLM-5）／943.7B（DeepSeek-V3.2） |
| 已知瓶颈 | 索引构建/反向索引物化/query gather 的实现开销 | **indexer 本身 O(NL²)**，200K prefill 占 81% 延迟 |
| 对应解法 | 一整章 kernel 协同设计（KV-outer + Q gather 等） | **IndexShare**：4 层共用一次索引 |
| **openPangu 的同项做法** | — | **只把 DSA 装在 1/3 的层上**（其余走 512 SWA）；转换预算 100B + 8B 预热；indexer 用**系数 0.1 的辅助 loss** 拟合原生全注意力分数（介于 GLM 的"纯 LM 梯度"和 MSA 的"KL + detach"之间） |

**四点观察**：

1. **两家独立收敛到 2048。** 不同底座、不同粒度、不同团队，落到同一个数字上——这大概是当前长上下文的一个经验甜点。
2. **每组独立选 vs 全头共选，是被底座决定的。** MLA 解码时天然是 MQA 形态，全局单一 Top-k 是自然选择；GQA 有 4 个独立的 KV 组，让它们各选各的才不浪费。MSA 论文附录 A 的可视化证明这个自由度**确实被用上了**——不同 GQA 组追踪不同的长程条带，只共享局部对角线和 sink 列。

   > ⚠️ **底座决定的其实是 gather 要抓几趟**（这层因果关系是我从两家配置反推的，官方均未明说）：稀疏的真实代价是拿着 top-k 下标去显存里离散地抓 KV。**MLA/MQA 底座下所有头共用同一份 latent KV，一次 gather 服务全部头**——所以 DSA 敢用最激进的 token 级 top-k；**GQA 底座下 4 组各抓各的**，MSA 于是退到块级（`B_k=128`，块内地址连续），把 gather 开销摊薄。换句话说，**表里"选择粒度"这一行不是审美差异，是被"底座注意力"那一行逼出来的。** 展开版见 [大模型架构入门/08-高效注意力.md](大模型架构入门/08-高效注意力.md) §8.3。
   >
   > 📌 但**"DSA 必须建在 MLA 上"是错的**——MSA 在 GQA 上跑通了；openPangu 只把 DSA 装在 1/3 的层上；★ DeepSeek 自己下一代 **V4 根本不用 MLA**（见 §3.1 CSA/HCA）。MLA 是划算的搭档，不是前置条件。
3. **两家关心的子问题正好互补。** GLM 问"indexer 太贵"，MiniMax 问"indexer 选不准"。**理论上 IndexShare 可以直接叠加到 MSA 上**（把 MSA 的块级索引在相邻层间复用），目前没有任何一方做过这个组合。
4. **MSA 相对 NSA 是做减法。** NSA（DeepSeek 早期）有压缩、选择、滑窗三条支路，MSA **只保留选择**，论文自称 "deliberately streamlined"，理由是"便于在广泛的 GPU 上高效部署"。少一条支路 = 少一套 kernel = 直接能挂进 vLLM / SGLang。**这是明确的工程优先于精巧。**

### 3.1.3 ⭐ PAS vs gpt-oss sink：五家里唯一有人做过的一次 sink 对照

**这是 openPangu 报告最有独立价值的一处消融，因为另外四家都没做过这个比较。**

Attention sink 现在几乎是标配了：V4 给每个头一个可学习的 sink logit 加在 softmax 分母上，gpt-oss 的做法被广泛沿用。但**"sink 到底该长什么样"从来没有被公开对照过**——大家都是直接抄一个实现。

#### 三种 sink 的形态差别

```
gpt-oss 式        ：每个头一个标量 logit，只加在 softmax 分母上
                    → 效果等价于"允许注意力总和 < 1"，但不提供任何可读的内容

V4 式             ：同上（每头一个可学习 sink logit）

PAS（openPangu）  ：每层 128 个可学习的 KV 对（MLA 下是 latent KV）
                    → 是真正的虚拟 token：既能吸收注意力质量，也能被读出内容
                    → 推理时是常数大小的额外 KV 条目，与序列长度无关
```

**一句话概括差别**：gpt-oss 的 sink 是**一个泄压阀**，PAS 是**一组可写可读的暂存单元**。

#### 消融结论（MoE15B-A2B，250B tokens，FULL:SWA = 1:2）

报告给了三条结论，其中第二条最反直觉：

| 场景 | 结论 |
|---|---|
| **梯度稳定性** | PAS 让梯度范数曲线更平滑、尖峰更少（Fig. 9） |
| **全注意力基线上** | ⚠️ **没有明显的 loss 收益** |
| **混合 SWA 模型上** | **训练 loss 一致更优，且明显好于 gpt-oss 式 sink**（Fig. 10） |

**"在全注意力上没用、在 SWA 上有用"这条差异，恰好把 sink 的作用机制指出来了**：

```
全注意力层：视野里总有值得看的 token → 注意力质量总有地方去 → 不需要泄压口
SWA 层    ：视野被硬限制在 512 内，窗口里可能根本没有值得看的东西
            → 但 softmax 强制归一化，质量必须分出去
            → 只能倾倒在窗口内的真实 token 上，污染它们的表示
            → 这时一个固定的吸收通道才真正有价值
```

**换句话说：sink 的收益不是来自模型本身，而是来自"感受野被限制"这个约束。** 这解释了为什么 gpt-oss 这种大量使用 SWA 的架构最早需要 sink，也解释了为什么纯全注意力时代很少有人讨论它。

#### 为什么这条结论对另外四家有意义

| | 用 sink 吗 | 有 SWA 吗 | 这条结论适用吗 |
|---|---|---|---|
| **DeepSeek-V4** | ✅ 每头一个 sink logit | ✅ CSA 里有 128 滑窗 | **适用**——V4 的 sink 正好装在有滑窗的 CSA 层上，但 V4 没做过 sink 形态的对照 |
| **Kimi K3** | 未提及 | ❌ | 不适用（KDA 本身就是固定状态，没有"窗口内无物可看"的问题） |
| **GLM-5.2** | 未提及 | ❌（明确放弃 SWA） | 不适用 |
| **MiniMax M3** | ✅ MSA 的可视化里有明显 sink 列 | ❌（强制局部块 ≠ SWA） | **部分适用**——M3 的 sink 是自发涌现的而非设计的 |
| **openPangu** | ✅ PAS，128 个可学习 KV/层 | ✅ 2/3 的层是 SWA | 本条结论的来源 |

**所以这份消融真正回答的问题是**：如果你的架构里有滑窗层，那么**把 sink 从"一个标量"升级成"一组可学习 KV"是有收益的**；如果你是纯全注意力或纯线性注意力，这个升级可能白做。

⚠️ **三点保留**：

1. **只有曲线，没有数值表。** Fig. 9 / Fig. 10 都是训练曲线，报告没有给出任何 loss 数字或下游评测分数，**收益幅度无法量化**。
2. **消融规模是 15B-A2B / 250B tokens**，不是 505B 本体。"在 15B 上 PAS 更好"不自动等于"在 505B 上 PAS 更好"——这是所有小规模消融的通病，但在 sink 这类和注意力分布强相关的机制上尤其需要警惕。
3. **PAS 的推理开销没有披露。** 每层 128 个额外 KV 条目意味着常数级的 cache 增量和一次额外的注意力计算，报告只说"constant-size"，没给绝对数字。



### 3.2 残差改造：三家改，两家不改 —— 而且 mHC 现在有两份独立实践

这是五方对比里最有意思的一处**空白**。

- **V4 的 mHC 解决数值问题**。61 层 × 1.6T，如果 hyper-connection 的 `B` 谱范数 > 1，叠下来放大 3000 倍直接崩。把 `B` 关进 Birkhoff 多胞体（双随机矩阵）意味着"水量守恒"，谱范数 ≤ 1，且双随机矩阵对乘法封闭 —— 61 层连乘仍不放大。**这是一个安全带。**
- **K3 的 AttnRes 解决表达力问题**。标准残差把所有历史层压进单个状态，报告直接类比成"RNN 在深度维度上的瓶颈"。既然 Transformer 当年用注意力替换了时间维度的递归，那就用同样的方法论替换深度维度的递归。**这是一个新通路。**
- **openPangu 的 mHC 是为了下游收益**——和 V4 同一个组件、同样 4 支流、同样 20 次 Sinkhorn-Knopp 迭代，但动机完全不同：它给的是 Table 2 的**七项下游任务全赢、平均 0.594 → 0.615**，数值稳定只是顺带的副产品。
- **GLM-5.2 什么也没做**——而且它的层数取向是**往下走**（GLM-4.5 的 89 层 → GLM-5 的 75 层 MoE），理由是省专家并行的通信开销。
- **MiniMax M3 也什么都没做**，而且它是五家里**总参最小的**（60 层 / 428B / 23B 激活）。

**"规模触发"这条相关性，被 openPangu 打破了一半**：

```
K3        93 层 / 2.8T   → 撞墙 → AttnRes
V4        61 层 / 1.6T   → 撞墙 → mHC
openPangu 50 层 / 505B   → 没撞，但仍然上了 mHC —— 图的是下游收益
GLM-5.2   78 层 / 744B   → 没撞 → 不改
M3        60 层 / 428B   → 没撞 → 不改
```

**openPangu 是唯一一个"不为救火而改残差"的**。它 50 层 / 505B，比 GLM 更浅、比 GLM 更小，按 V4/K3 的逻辑完全不需要 mHC。它上 mHC 的理由是消融表里那 2.1 分——**这把 mHC 从"大模型的安全带"重新定位成了"通用的下游增益组件"**。

**代价这一行，两家改残差的都没给全**：DeepSeek-V4 给了 mHC 的 **6.7% 墙钟**，GLM 和 M3 都收 0，而**华为完全没有披露 mHC 的墙钟代价**——只说把它拆成了三个可重叠的算子（含一个专用 sinkhorn 算子）。对一个把 mHC 定位成"性价比组件"的团队来说，不给成本数字是个明显的缺口。

> ⚠️ **Kimi K3 这一栏同样是空的，需要更正一个流传很广的说法**：AttnRes 的"训练 +4% / 推理 +2%"**不是 K3 报告里的数字**。经全文检索，报告只给了 `O(Ld) → O(Nd)` 的渐近界，以及"checkpointing 后每层保存的激活与标准残差完全相同"这类工程结论，**没有任何百分比形式的墙钟开销**；独立论文 [arXiv:2603.15031](https://arxiv.org/abs/2603.15031) 的摘要页也只有定性的 "minimal overhead"。社区流传的 4%/2%、<2%、1.25× 互相不一致且都回溯不到一手来源。
>
> **所以在"代价"这一维度上，五家里其实只有 DeepSeek-V4 一家给了可比的实测数字。** 参见 [Kimi-K3.md](Kimi-K3.md) §三、[大模型架构入门/03-残差流.md](大模型架构入门/03-残差流.md) §3.6。

#### ⭐ 一份原论文和 V4 都没记录的失效模式：gate collapse

**这是 openPangu 报告对 mHC 这条技术线最实质的增量。**

按 mHC 原始论文的算子放置方式，华为观察到：**早期层的所有 H_pre / H_post 门控值全部趋近 0**，等于把这些层从残差流里整个摘出去——网络前段被"解耦"了。

解法是两级归一化：

```
① sandwich normalization ：在 H_post 写回残差流之前插一次归一化
② block-level post-norm  ：第 1 层之后、之后每 5 层，做一次块级后归一化
```

**为什么这件事值得单独记**：

| | mHC 原论文 | DeepSeek-V4 | **openPangu** |
|---|---|---|---|
| 支流数 | — | 未明确（报告只给了机制） | **4** |
| Sinkhorn 迭代 | — | **20** | **20**（完全一致） |
| gate collapse | ❌ 未记录 | ❌ 未记录 | ✅ **记录并给了解法** |
| 墙钟代价 | — | **6.7%** | ❌ 未披露 |

**两家用同一个组件、同一个迭代次数，只有一家报告了这个坑。** 这不能证明 V4 没遇到（也可能是它的算子放置本来就不同、或者规模不同没触发），但对任何想采用 mHC 的团队来说，**openPangu 这一节的实用价值高于 V4 报告的对应章节**——它是唯一一份写了"会怎么坏、怎么修"的材料。

⚠️ 同时注意：这两级归一化在报告里还承担了另一个职责——**华为把"Muon 下 attention logits 全程有界"归因给了它们**，而 GLM 把同一个现象归因给 Muon Split、V4 归因给 QK-RMSNorm。这条三方互斥的归因线见 §3.8。

（Raschka 的观察值得记：**在 K3 一堆改动里，AttnRes 是唯一一个不是"效率优化替换"的改动**——其他基本都在换更便宜的等价物，只有 AttnRes 是在加东西。）

### 3.3 MoE：五种预算分配

- **V4**：专家全宽 7168，384 选 6，稀疏度 64×。预算花在"每个专家更强"。
- **K3**：先把 token 降到 latent 3584 再分发，**通信量和专家权重流量直接减半**，省下的预算换成**专家数翻倍到 896、激活数翻倍到 16**。共享专家仍吃全宽。
- **GLM-5.2**：**256 选 8 + 1 共享，稀疏度 32×**，且专家中间维只有 2048（K3 是 3072）。
- **MiniMax M3**：**128 选 4 + 1 共享，稀疏度 32×**（与 GLM 相同），专家中间维 3072。
- **openPangu-2.0-Pro**：**384 选 8 + 1 共享，稀疏度 48×**，但专家中间维只有 **1792**——五家里最小，比 GLM 的 2048 还窄。

K3 的 LatentMoE 收益不是白拿的：路由路径变成 `W↓ → 门控多分支 FFN → W↑` 这种近乎四连乘的病态链条，在 2.8T 规模下会激活爆炸——所以才必须配上 RMSNorm + SiTU-GLU 两个稳定器。**它把稳定性的账单转移到了别处。**

GLM 的选择又是同一个模式：**不追极端稀疏，就不用给稳定性买单。** 256 选 8 是 DeepSeek-V3 那一代就验证成熟的配置。

**openPangu 是五家里唯一一个把"小"贯彻到每一个维度的**：

```
hidden 5120（最窄）× 50 层（最浅）× 专家中间维 1792（最小）
→ 激活量 18B（五家最低），却靠 384 个专家把总参撑到 505B
```

**它走的是"多而小"的极端**：专家数和 V4 一样多（384），但每个专家的中间维只有 V4 的一半不到，稀疏度落在 48×。这个组合意味着**单个专家的表达力被牺牲，换取更细的专家分工和更低的单 token 算力**——和 V4 的"少而强"正好相反，而 K3 的 LatentMoE 是第三条路（专家多且宽，但输入被降维）。**三种做法都声称有效，目前没有任何跨家的对照实验。**

**M3 这一格里藏着一个反直觉的事实**。M2 系列报告的标题就是《**Mini Activations** Unleashing Max Real-World Intelligence》，整篇论文在论证"极小激活量也能出前沿能力"，而且 §2.2.1 的消融表明确支持细粒度专家（128 选 8 优于 32 选 2）。**但 M3 反过来了**：

```
M2:  229.9B 总参 /  9.8B 激活  |  256 专家选 8
M3:  428B   总参 / ~23B 激活   |  128 专家选 4     ← 专家数减半、top-k 减半，激活量却涨 2.3×
```

**M3 没有技术报告，所以这个方向调整没有任何官方解释。** 合理猜测是省下来的注意力算力被换成了 FFN 容量，以及原生多模态需要更大的容量——但这**纯属推测**。这一格是五家里唯一一处"公开材料自相矛盾且无解释"的地方。

**顺带一提，openPangu 的 18B 激活反而更接近 M2 的取向**（"小激活也能出能力"），而 M3 自己放弃了这条线。**M2 论文的论点，最终是被华为而不是被 MiniMax 自己继续验证的。**

### 3.4 激活函数：三比一，外加一个「报告里根本没写」

同一个问题（SwiGLU 两个乘数都无界 → 低精度溢出），五种态度：

```
V4：       clip(linear, −10, 10)            硬截断，简单粗暴，梯度在边界处为 0
K3：       β·tanh(x/β)                      软上限，原点附近≈线性、大值处饱和，处处可导
MiniMax：  swigluoai(α=1.702, limit=7.0)    gpt-oss 式 clamp，α 让 Swish 逼近 GELU
GLM：      不改 SwiGLU                      通过 Muon Split 从优化器侧解决尺度问题
openPangu：❓ 报告全文 0 次提及               连"我们用的是 SwiGLU"这句话都没有
```

**四家有明确表态的里，三家在给 SwiGLU 加界，而且是三种不同的实现。** 这几乎可以算作这一代的一个共识：**在 4-bit/8-bit 训练成为标配之后，无界激活是一个必须处理的问题。**

K3 的 SiTU-GLU 最"讲究"：`β₁=4` 封门分支、`β₂=25` 封 up 分支，乘积上界 100，**在原点附近几乎和 SwiGLU 完全重合**。V4 报告自己也承认 SwiGLU 截断"缺乏理论解释"。MiniMax 走的是最省事的路——直接采用 gpt-oss 已经在用的 `swigluoai`，不自己发明。

**GLM 的路径最值得注意**：它没有在激活函数上动刀，而是报告"用了 Muon Split 之后预训练全程 attention logits 尺度保持稳定，不需要任何 clipping 策略"。**这是五家里唯一一个从优化器侧而不是从算子侧解决数值稳定的**（openPangu 的 sandwich norm 是第二个，但它归因给的是归一化而非优化器，见 §3.8）。当然，GLM 只做 INT4 权重量化（激活走 W8A8），压力比 K3 的 MXFP4 权重 + MXFP8 激活小得多——所以这个对比不完全公平。

⚠️ **openPangu 这一格的"空白"本身是一条信息**。已在正文提取上逐个核对过：`SwiGLU` / `swiglu` / `GLU` / `SiLU` / `activation function` / `clamp` / `softcap` **全部命中 0 次**。一份 45 页、连 Sinkhorn 迭代次数和 Muon 更新缩放系数都写了的报告，**完全不提激活函数**，最合理的解读是"沿用 SwiGLU、没改、不值得写"。这和它只做 W8A8（不上 4-bit）是自洽的——**低精度压力小，无界激活就不构成问题**。这一格反过来印证了上面那句"加界的动机来自低精度"。

### 3.5 负载均衡

- **V4（及业界主流）**：`b_j ← b_j + γ·sign(目标负载 − 实际负载)`。`γ` 大了震荡、小了跟不上。
- **K3 的 QB**：用 Top-(k+1) 的第 k+1 名分数当门槛 `α_i`，算出 margin，然后**把 `b_j` 直接设成 margin 的 (1−k/n) 分位数的相反数**——正好让目标数量的 token 越过门槛。**`γ` 这个超参直接消失了。**
- **GLM**：未披露。256 个专家的规模下大概还在 aux-loss-free 的舒适区内（K3 报告明确说接近 10³ 个专家时旧方法"超出了仍能正常工作的范围"）。
- **MiniMax M3**：未披露，但 `config.json` 里有 `use_routing_bias: true`，且 M2 报告明确说用"sigmoid 门控 + 可学习的专家特定 bias"，**所以几乎可以确定是 aux-loss-free bias 路线**。128 个专家更是远在舒适区内。
- **openPangu 的 Adaptive aux-loss-free**：保留 bias 更新框架，但**把 `sign(·)` 换成 RMS 归一化的误差**：

  ```
  旧： b_i ← b_i + γ · sign(F_i − Q_i)          只用误差的方向
  新： b_i ← b_i − γ · (F_i − Q_i) / RMS(F − Q)  保留误差的相对幅度
  ```

  **`sign` 把"超载 1%"和"超载 100%"同等对待**，这正是需要小心调 `γ` 的根源。除以全体专家误差的 RMS 之后，更新幅度自适应于当前不均衡的整体尺度，同时保持无量纲。消融结果：**LM loss 与基线持平，MaxVio 一致更低，而且优势随训练进行不断扩大。**

**这一格现在有三种技术路线，而且是一条清晰的谱系**：

```
sign（V4/GLM/M3）      → 只看方向，γ 敏感
RMS 归一化（openPangu） → 看方向 + 相对幅度，γ 变钝，仍需 γ
解析求解（K3 的 QB）    → 直接算出目标 b_j，γ 消失
```

**华为的方案是"最小改动"路线**：它不推翻 aux-loss-free 框架，只换掉一个函数——任何现有实现改两行就能用，代价是 `γ` 仍然存在。K3 的 QB 是"最彻底"路线，但需要 Top-(k+1) 路由、直方图分位数估计和一次 all-reduce，**改动面大得多**。**在 384 专家这个规模上，华为的证据表明简单方案已经够用了。**

⚠️ 另外注意 openPangu 是**唯一一个同时用三种均衡手段**的：Adaptive bias（全程）+ EP-group 辅助损失（2.0e-4）+ router z-loss（1.0e-6），**后两者只在 general 阶段开，之后全部关闭**。这个"先约束后放开"的课程安排在另外四家的报告里都没有对应描述。

**这一格的分布很能说明问题**：只有 K3 需要 QB，因为**只有 K3 把专家数推到了 896**。负载均衡方法的复杂度是专家数的函数——128（M3）、256（GLM）、384（V4 / openPangu）都还在老办法（或老办法的小改）能覆盖的范围里。

QB 的价值不只是省调参。它保证了完美均衡，于是 **MoonEP 可以静态知道每个 rank 收到的 token 数恰好是 S×K**，从而**消除每层的 MoE host 同步**、缓冲区从 `S×K×R` 降到固定的 `S×K`。**一个算法改动直接解锁了一整套 Infra 优化**——K3 报告里"算法与系统协同设计"最典型的例子。

### 3.6 后训练：同一个数学式子，四种用法

四家**在后训练范式上高度趋同**——都用「on-policy 蒸馏」做最后一步。但**用它干什么，四家各不相同**：

> ⚠️ **MiniMax M3 在这一节缺席**，因为它没有技术报告。M2 系列报告有完整的后训练章节（agent 数据管线、Forge RL 系统、M2.7 自演化），但那是**上一代**，不能拿来代表 M3。

| | DeepSeek V4 | Kimi K3 | GLM-5.2 | openPangu-2.0 | MiniMax M3 |
|---|---|---|---|---|---|
| 教师 | 各领域专家（SFT + GRPO） | **9 个**（3 领域 × 3 effort） | **前面各阶段的最终 checkpoint** | **4 个领域专家**（Reasoning / General / Agentic / Code） | **未披露** |
| 教师维度 | 领域 | 领域 × effort | **训练阶段** | 领域 | — |
| **要解决的问题** | 多个领域专家**无法合并** | 多个领域 × 档位专家**无法合并** | **多阶段 RL 顺序优化会累积性损害先前能力** | 多个领域专家**无法合并** | — |
| **目标形式** | **全词表逆 KL loss** | **per-token log-ratio 当 RL reward** | **log-ratio 当 GRPO advantage** | **log-ratio 当 GRPO advantage** | — |
| 公式 | `min Σ w_i·D_KL(π_s ‖ π_ti)` | `r = clip(sg[log(π_t/π_θ)], ±R_max)` | `Â = sg[log(π_t^infer / π_θ^train)]` | `A = sg[log(π^train_expert / π^train_θ)]` | — |
| **教师概率从哪来** | —（写成 loss，不涉及） | —（未明确） | **推理后端**（明说未来要迁到训练引擎） | ⭐ **训练引擎前向计算** | — |
| 额外技巧 | — | 长度惩罚 | group size = 1 | **近零 advantage 掩码 + log-ratio 裁剪 + 专家顺序载入共享 NPU 池** | — |

| 防 reward hacking | — | 输出长度超 `σ·ℓ₀` 自动判负 | — | 语法惩罚（工具调用格式错误） | — |

**四点观察**：

1. **K3、GLM、openPangu 的公式是同一个东西**：`sg[log(教师概率 / 学生概率)]` 当 advantage/reward，而不是写成 KL loss。**GLM-5 报告 2026-02，K3 报告 2026-07，openPangu 2026-07-31——GLM 早了五个月。三家独立收敛到同一个式子，这个形式基本可以认为是这一代的事实标准。**
2. **GLM 挖出了这个形式的一个额外好处**：既然 advantage 直接来自与教师的差距，就**不再需要每个 prompt 采一大组样本来估计 advantage**，于是 GRPO 的 group size 可以设成 1、batch size 拉到 1024，吞吐直接拉满。K3 和华为的报告都没有提到这一点。
3. ⭐ **openPangu 把 GLM 明说的"未来工作"做掉了**。GLM-5 报告承认自己是用**推理后端**取教师 logits，并计划迁到训练引擎；华为直接**用训练引擎的前向计算教师概率**。这一条差异华为在报告里是**主动点名 GLM-5 做对比的**——而这也是整份 openPangu 报告里唯二提到 GLM 的地方之一（另一处是参考文献）。**在一份完全不做横向评测的报告里，专门为这一点点名对手，说明团队自己认为这是实打实的增量。**
4. **"教师"的语义不同**：V4 / K3 / openPangu 是**横向合并**（把不同领域的能力捏到一起），GLM 是**纵向修复**（把被后续阶段冲掉的能力捞回来）。**同一个工具，三家用来做加法，一家用来做减法的逆运算。**

### 3.7 量化：五家都上低精度，覆盖范围差别很大

| | V4 | K3 | GLM-5.2 | MiniMax M3 | openPangu-2.0 |
|---|---|---|---|---|---|
| 专家权重 | FP4（FP32 主权重 → FP4 存 → FP8 算） | MXFP4 | **INT4** | —（出货有 MXFP8 版本） | **INT8（W8A8）** |
| 激活 | FP8 | MXFP8 | W8A8（Attention/MLP）/ W4A8（MoE，国产芯片） | MXFP8 | **INT8** |
| 保持高精度的部分 | embedding / norm / mHC 门控 | 注意力投影、latent MoE 投影、共享专家、路由器 | Attention / MLP 块（走 INT8） | 未披露 | 未明确 |
| **QAT 覆盖范围** | 预训练阶段 | **SFT 一路贯穿到 RL 全程** | **SFT 阶段** | **未披露是否做 QAT** | ⚠️ **报告未提 QAT，看起来是纯 PTQ** |
| 关键论点 | FP4→FP8 反量化**无损**，可直接复用现有 FP8 框架 | RL 的 rollout 和训练用同一套量化 → **彻底消除 train–inference mismatch** | 量化 kernel 同时用于训练和离线量化 → **训练与推理 bitwise 一致** | —（但 `swiglu_limit=7.0` 这个 clamp 本身就是为低精度算术服务的） | **把 SmoothQuant 的 `a+b=1` 约束解开**，改成二维解耦指数搜索；上投影用交替优化 |
| 落地目标 | 服务成本 | 服务成本 | **把 750B 塞进单台 Atlas 800T A3** | 服务成本 | **1009 GB → 517 GB（1.95×）** |

**K3 的 QAT 覆盖最激进**（SFT→RL 全程），**GLM 的动机最具体**（不是为了省钱，是为了让国产芯片单机装得下），**M3 这一格基本是空的**——只能从 `swigluoai` 的 clamp 反推出它在意低精度数值范围。

**openPangu 是五家里最保守的一个，而且保守得很一致**：不上 4-bit、不做 QAT、只有 W8A8。它的技术含量集中在**PTQ 算法本身**——把 SmoothQuant 的迁移强度约束 `a + b = 1` 放开成二维独立搜索，等于承认"权重和激活的最优迁移量不必互补"。

**这个保守选择和它前面几格是自洽的**：不上 4-bit → 数值范围压力小 → 不需要给激活函数加界（§3.4 的空白）→ 也不需要 QAT。**五家里唯一一条"全程不碰 4-bit"的技术路线。** 代价是压缩比只有 1.95×，而 GLM 的 W4A8 混合精度能把 750B 压进单台机器。

⚠️ 注意 **openPangu 和 GLM 在这一格的目标其实相同**（都是昇腾单机/少机部署），但**手段差了一档精度**。GLM 敢上 W4A8 的底气来自 INT4 QAT，华为没做 QAT 所以只能停在 W8A8——**这反过来说明 QAT 的价值不在精度本身，而在于它解锁了更激进的量化位宽。**

### 3.8 ⭐ "Muon 下 attention logits 为什么不爆炸"：三家给了三种互斥的归因

**这是整份对比里最值得单独成节的一条线索——因为三家报告描述了同一个现象，各自把功劳记在了完全不同的组件上，而且三者互不引用。**

#### 现象是同一个

用 Muon 训练大 MoE 时，attention logits 有爆炸的历史前科（Kimi K2 时代就是靠 **QK-Clip** 硬压住的，那是一个公认的"土办法"）。而这一代的三份报告都声称：**在自家配置下，attention logits 全程稳定，不需要任何 clipping。**

#### 但归因完全不同

| | 归因给谁 | 报告原话（要点） | 这个组件的"本职工作"是什么 |
|---|---|---|---|
| **GLM-5** | **Muon Split**（按 head 正交化） | 用了 Muon Split 之后"预训练全程 attention logits 尺度保持稳定，**不需要任何 clipping 策略**" | 让 MLA 在 Muon 下追平 GQA（性能问题） |
| **DeepSeek-V4** | **QK-RMSNorm** | 对 query 和压缩 KV 条目直接做 RMSNorm，"副作用是 Muon 里**不需要 QK-Clip** 了" | 防止 attention logits 爆炸（**就是本职**） |
| **openPangu-2.0** | **sandwich norm + block post-norm** | attention logits 全程有界在 **≈20**；并明说"**We leave a more systematic ablation of this phenomenon to future work.**" | 修 mHC 的 gate collapse（§3.2） |

```
GLM      ：优化器侧    —— 改变更新方向的分布
V4       ：算子侧·局部 —— 直接归一化 Q 和 K
openPangu：算子侧·全局 —— 归一化残差流本身
```

#### 为什么这条线值得记

**三个归因在机制上是互斥的**——它们作用在完全不同的位置，不可能同时是"那个原因"：

- 如果 GLM 是对的（Muon Split 是充分条件），那么 V4 的 QK-RMSNorm 和华为的两级归一化都是**多余的保险**。
- 如果 V4 是对的（QK-RMSNorm 才是关键），那 GLM 的稳定性就是**别的东西带来的**，Muon Split 只是恰好同时在场。
- 如果华为是对的（残差流归一化才是关键），那前两家的解释都**把因果搞反了**——真正起作用的是它们各自架构里别的归一化。

**更值得注意的是三家的"副产品"叙事结构完全一样**：每一家都把稳定性说成是某个**为别的目的引入的组件**顺带带来的好处。

```
GLM      ：为了性能引入 Muon Split      → 顺带稳定了 logits
V4       ：为了稳定引入 QK-RMSNorm      → 顺带免掉了 QK-Clip
openPangu：为了修 gate collapse 引入两级 norm → 顺带稳定了 logits
```

**只有 V4 那一条是"本职 + 副产品"的正常关系**（QK-RMSNorm 本来就是干这个的）。GLM 和华为都是**先观察到现象，再回头找了个在场的组件当解释**——这两条的因果强度明显更弱。

#### 三份证据的可靠性并不对等

| | 有对照实验吗 | 有量化数据吗 |
|---|---|---|
| **GLM-5** | ❌ 只有叙述性结论 | ❌ 没给 logits 曲线 |
| **DeepSeek-V4** | ❌ 只有叙述性结论 | ❌ 没给 logits 曲线 |
| **openPangu** | ❌ 没做消融，**且自己承认了** | ✅ **给了具体数值：全程有界在 ≈20** |

**华为是三家里唯一一个既给了数字、又主动承认"没做系统性消融"的。** 报告原文那句 "We leave a more systematic ablation of this phenomenon to future work" 在这个语境下反而是最诚实的一句——**另外两家做出了同样强度的断言，但连这句免责声明都没有。**

#### 这条线目前的实际结论

**没有人证明过任何一种归因。** 三家都是在自己的完整配方里观察到了稳定性，然后指向了配方里的某一味。对想复现的团队来说，实际可操作的结论只有两条：

1. **这一代的大 MoE + Muon 组合，确实不再需要 QK-Clip 了**——三家独立确认了这个事实层面的现象。
2. **但"去掉哪一个组件会重新爆炸"，目前没有任何公开材料能回答。** 想复现的话，三个组件（Muon Split / QK-RMSNorm / 残差流归一化）**至少得留一个**，而具体留哪个只能自己试。

⚠️ 补充一个可能的混淆因素：**openPangu 用的是 FP16 + 动态 loss scaling，是五家里唯一不用 BF16 训练的**。FP16 的尾数位更多、指数范围更窄，它对 attention logits 的数值行为影响与 BF16 不同——**华为观察到的"有界在 20"有多少是精度格式带来的，报告里没有讨论。**

> **注意 prefill / decode 的大小关系在两组数字之间是反的。** 我的分析（**非官方说法**）：论文的 7.6× 是"MSA vs GQA、其余全同"的干净对照；官方的 15× 是"M3 vs M2"，而 M3 相对 M2 还额外拿到 **KV 头从 8 减到 4**——解码是访存受限的，KV cache 读取量减半本身就接近 2× 的独立收益，`7.6 × 2 ≈ 15`。两个数字不矛盾，一个是控制变量的，一个是端到端的。
>
> **MSA 论文自己非常坦率地解释了为什么实测跟不上 FLOPs 比**：稀疏引入了索引构建、top-k、反向索引物化、query gather 和负载均衡的开销，访存也不如稠密规则；但这个差距**会随上下文增长而缩小**——因为稠密基线继续随全序列扩展，而 MSA 的主注意力预算是固定的。**28.4× 是理论上限，14.2× 是能兑现的部分，差的那一半就是稀疏本身的管理费。**

**五家 Infra 的取向各不相同**：

- **V4 强调确定性与可复现**（双 kernel 替代 split-KV、DeepGEMM 替代 cuBLAS、消除 atomicAdd），甚至专门写了一节给硬件厂商的建议（`C/B ≤ 6144 FLOPs/Byte` 比绝对带宽更重要）。
- **K3 强调状态可搬运**（KDA 固定状态在设备内/跨设备/跨请求三层复用）与**形状静态可知**（QB → MoonEP）。
- **GLM 强调 RL 训练吞吐与国产硬件落地**——40 页报告里最详的两块是异步 agentic RL 基建和 7 个国产芯片平台的适配。
- **MiniMax 强调 kernel 可移植**——MSA 论文有整整一章讲 GPU kernel 并且**开源了**（`github.com/MiniMax-AI/MSA`）。它相对 NSA 主动砍掉两条支路的理由就是"便于在广泛的 GPU 上高效部署"。**五家里只有它把"这个机制别人也能跑起来"当成设计约束。**
- **openPangu 强调"在非 NVIDIA 硬件上把整条链路跑通"**——从训练算子、CP 方案（Felix）、超节点组网（CloudMatrix 384）到推理图编译（ACL Graph + Superkernel）全在昇腾栈内自研。

> ### ⭐ GLM 和 openPangu 在国产硬件这条线上是**两个完全不同的动作**
>
> 这一点很容易被"都支持昇腾"糊掉：
>
> ```
> GLM-5.2   ：在 NVIDIA 上训练  →  训完之后适配到 9 个国产平台（含昇腾）
> openPangu ：全程在昇腾上训练  →  报告里根本没有"适配"这个概念，因为没有别的平台可迁
> ```
>
> **"适配"证明的是模型能在国产芯片上跑推理；"全程训练"证明的是国产芯片能撑住 505B/34T 的完整训练。** 后者是更强的一条结论，而且**五家里只有华为给出了这条证据**。
>
> ⚠️ 但要注意它也**只有**这条证据：报告没有和 NVIDIA 平台做任何 MFU / 成本 / 墙钟的对照，所以"能训"成立，"训得同样划算"没有材料支持。

> ### ⚠️ 一个不该被忽略的口径差：openPangu 的效率数字是"部署实测"，另外四家不是
>
> | 家 | 效率数字的性质 |
> |---|---|
> | V4 | 架构 FLOPs / KV cache 的**相对比例**（vs V3.2） |
> | K3 | **扩展效率**倍数（vs K2），口径未细说 |
> | GLM-5.2 | **FLOPs 估算**（2.9×），端到端证据来自 30B 旁证模型 |
> | MiniMax | 论文侧是**注意力单层**的实测；官方侧是**整模型 vs 上一代** |
> | **openPangu** | ⭐ **具体硬件、具体 batch、具体序列长度下的 TPOT / TPS / TTFT 绝对值** |
>
> **绝对值比倍数更难造假，但也更难横向比**——它绑死在 Atlas A3 + 2P1D 这一套配置上，换硬件就不成立。而另外四家的倍数虽然可比性差，却至少能跨硬件读。**这两种披露方式没有优劣，但混在一张表里读会得出错误结论。**

### 5.3 五家都承认（或都体现出）的同一个短板结构

**这是最值得记的一条共性结论**。V4 报告写得最直白：

> **推理能力更依赖架构与训练方法，知识能力更依赖数据。**

这句话在五家的数字上都成立：

- **V4**：需要**推导**的任务（Codeforces、HMMT、LiveCodeBench）打平甚至超过闭源；需要**记住事实**的任务（SimpleQA-Verified 差 17.7 分、MMLU-Pro 差 3.5 分）明显落后。
- **K3**：需要**执行流程**的任务（Agent、搜索、工具调用、文档理解）全面领先；需要**深厚知识 + 硬推理**的任务（HLE、CritPt）落后闭源前沿一档。
- **GLM-5.2**：数学竞赛（AIME 99.2、IMO 91.0）全场第一；HLE 40.5 vs Opus 4.8 的 49.8，CritPt 20.9 vs GPT-5.5 的 27.1。
- **MiniMax M3**：SWE-bench Verified 80.5、BrowseComp 83.5 这类**流程执行**任务很强；HLE 37.0 在 V4/K3/GLM/M3 这四家里最低——**同一个缺口，同一个方向**。
- **openPangu-2.0**：**最极端的一个样本**。数学（AIME 95.4）已经和第一梯队同档，知识（HLE 27.1、SimpleQA 34.9）和 Agent（BrowseComp 65.7、MCP-Atlas 61.3）却落后 10~25 分。**同一个模型内部，两类能力的差距被拉到了五家里最大。**

**结论**：架构创新已经把"能力上限"推到了闭源同级，剩下的差距主要在**训练语料的质量与知识密度**——这是架构改不动的部分。**五家独立得出同一个诊断，这个结论的置信度相当高。**

**openPangu 这个样本还额外加强了一条**：它的架构工作（DSA-SWA 混合、PAS、mHC、Muon 分组、KPop/R3 训推对齐）在五家里论述最完整、工程最深，**但这些完全没有转化成知识与 agent 能力上的追赶**。这几乎是"架构不是瓶颈"这条论断能拿到的最干净的一个反证样本——**如果架构是瓶颈，做了这么多架构工作的模型不该在这两项上垫底。**

| 组件堆叠导致架构"**不够优雅**" | 不回传 thinking history / 中途切换会话会导致**行为不稳定** | **SWE-Marathon 等超长周期任务有待提升**（官方博客承认） | **无技术报告，因此没有任何自我承认的局限** | **Muon 下 logits 稳定的归因"留给未来工作做更系统的消融"**（§3.8） |
| 前瞻路由和 SwiGLU 截断**缺乏理论解释** | 对模糊指令**过度自主** | 1M 长上下文**无公开逐长度召回数据** | MSA 论文承认：**实测加速远小于 FLOPs 缩减**（14.2× vs 28.4×），差额是稀疏的管理费 | **训推一致性的白盒逐层对齐方法论"仍在进行中"**，报告只给了预览 |
| 事实性知识仍落后顶尖闭源 | 相比 Fable 5 和 GPT-5.6 Sol 在**用户体验上有明显差距** | 5.1→5.2 的训练侧改动**完全没有公开材料** | M2 报告承认：**"可靠地比较不同注意力架构异常困难"**，代理指标与下游表现的相关性"脆弱" | ⚠️ **不是它承认的、但客观存在**：全篇零对照模型、零长上下文评测、mHC 墙钟代价未披露 |

五组局限的性质各不相同：

> **V4 承认的是"科学上不干净"，K3 承认的是"产品上不好用"，GLM 的问题是"透明度不够"，MiniMax 承认的是"我们不知道怎么可靠地评估"，openPangu 承认的是"有些机制我们观察到了但没解释"。**

**MiniMax 那一条其实最深刻**。M2 报告 §2.2.2 的核心论点不是"线性注意力不行"，而是"**我们没有能力可靠地判断它行不行**"——标准 benchmark 上看起来打平，规模上去以后多跳推理才暴露缺陷；代理指标在更大规模或没见过的任务分布上就不成立；统计显著的评测所需算力随任务复杂度快速增长。**这是一条元层面的局限，而且它适用于本文所有的架构对比。**

**openPangu 那一条则是最容易被忽略的一种诚实**：在两处（Muon logits 归因、白盒对齐方法论）主动写下"还没做完/还没搞清楚"，而同一个位置上另外两家（GLM 的 Muon Split、V4 的 QK-RMSNorm）做出了同等强度的断言却没有任何免责。**报告的诚实度不该只看它承认了多少缺点，也要看它在没把握的地方是否收住了话。**

这某种程度上反映了五家在这一代的侧重和处境——V4 是一份偏系统与效率的报告，K3 是一份偏能力与产品的报告，GLM-5.2 **根本没有报告**，MiniMax 则有一份**只讲一个组件**的论文，而 openPangu 是一份**工程细节最完整、但完全不面向竞争**的报告。

## 六、时间线：谁先做了什么

五方对比暴露出一个之前看两家时看不到的问题：**GLM 在两个关键技术上都是最早发表的，但因为它把这些技术埋在一篇"以 agentic 工程为主题"的报告里，社区讨论度远低于 Kimi。**

| 技术 | GLM-5 报告 | Kimi K3 报告 | 差距 |
|---|---|---|---|
| **注意力投影按 head 正交化** | **Muon Split**（2026-02-17）<br>"we split these matrices into smaller matrices for different heads and apply matrix orthogonalization to these independent matrices" | **Per-Head Muon**（2026-07-28）<br>"把动量矩阵按 head 维度切开，每个 head 的块单独正交化" | **GLM 早 5 个月** |
| **log-ratio 当 on-policy 蒸馏的 advantage/reward** | **On-Policy Cross-Stage Distillation**（2026-02-17）<br>`Â = sg[log(π_teacher / π_θ)]` | **MOPD**（2026-07-28）<br>`r = clip(sg[log(π_teacher/π_θ)], ±R_max)` | **GLM 早 5 个月** |

两处的**动机描述也高度一致**：Muon Split 是为了"让不同注意力头的投影权重以不同的尺度更新"，Per-Head Muon 是为了避免"梯度/动量尺度大的 head 主导共享的更新方向"——同一个诊断的两种表述。

**这不是指控抄袭**——这类想法在两个团队独立冒出来完全正常，而且 K3 的 Per-Head Muon 报告了额外的收益（在瘦高的 per-head 块上跑 Newton–Schulz 更便宜）。但它确实说明一件事：**评估"某个技术是谁的贡献"时不能只看讨论度。**

反过来，**GLM 也有明确借用 DeepSeek 的地方**：DSA、lightning indexer、MLA 都直接来自 DeepSeek，报告也如实标注了。IndexShare 是在 DSA 之上的原创增量。

**加入 openPangu 之后，这一节多了一个新的观察角度**——它是五家里**引用密度最高、原创密度最低**的一份报告：

```
mHC        → 直接标注引用 DeepSeek arXiv:2512.24880（连 Sinkhorn 20 次都一样）
DSA        → 直接标注引用 DeepSeek-V3.2
MLA        → 直接标注引用 DeepSeek-V2
Muon       → 直接标注引用，Newton-Schulz 系数明说取自 modded-nanogpt
aux-loss-free → 直接标注引用 DeepSeek
TITO       → 与 GLM-5 同名同法
OPD 的 log-ratio 形式 → 与 GLM-5 / K3 同形（且报告主动说明了自己与 GLM-5 的差异）
```

**这不是缺点，反而是一个有用的信号**：一份大量复用他人组件、且逐条标注出处的报告，它**真正原创的那几处就特别可信**——因为作者显然没有把"看起来像自己的贡献"当成写作目标。openPangu 独有的四处是：**PAS**、**mHC gate collapse 的诊断与修复**、**RMS 归一化的 aux-loss-free bias 更新**、**训推一致性的三类根因解剖 + KPop/R3**。**它们全都落在"别人报告里一笔带过、或者根本没提"的位置上。**

### 6.0 加入 MiniMax 和华为之后：稀疏注意力这条线的完整时间线

把 MSA 和 openPangu 的 DSA-SWA 放进去，稀疏注意力这一支的谱系才完整。**这条线上没有"谁抄谁"的问题，而是一个非常清晰的"同一个问题被多拨人接力打磨"的样本**：

| 时间 | 工作 | 归属 | 相对前一步的增量 |
|---|---|---|---|
| 2024-02 | **MoBA** | MoonshotAI | 块级选择，块表示用 **block-mean**（块内 key 求平均） |
| 2025-02 | **NSA** | DeepSeek | 三分支（压缩 / 选择 / 滑窗）+ 门控融合，原生可训练 |
| 2025 | **InfLLM-V2** | — | 简化为单一选择分支 |
| 2025-09 | **DSA** | DeepSeek（V3.2） | ReLU **lightning indexer** 打分，**token 级** top-2048，全部 head 共用同一份选择；底座是 MLA/MQA |
| 2026-02 | **DSA 上生产** | Z.ai（GLM-5） | **20B token 续训**就把 dense 基座转成 DSA（DeepSeek 用了 943.7B） |
| **2026-06-12** | **MSA** | **MiniMax** | **GQA 原生**：每 GQA 组一个 index query head + **全模型共享一个 index key head**；**块级** top-16×128；indexer 用 **KL 对齐 + 梯度 detach** 单独训练 |
| 2026-06-16 | **IndexShare** | Z.ai（GLM-5.2） | 正交方向：不改选择方式，改**选择的频率**——每 4 层只跑 1 次 indexer |
| **2026-07-31** | **DSA-SWA 混合** | **华为（openPangu-2.0-Pro）** | 又一个正交方向：不改选择方式，改**在哪些层用**——先按 1:2 混进 SWA，最后**只把剩下的 full 层转 DSA**；适配预算 **8B dense warm-up + 100B replay**；indexer 辅助目标的系数压到 **0.1** |

三个观察：

1. **MSA 和 DSA 独立收敛到 2048 这个数字**（DSA 是 token 级 top-2048，MSA 是 16 块 × 128 = 2048），而两家的底座、粒度、训练方式全都不同。**一个跨团队、跨架构的独立收敛，比任何单家的消融都更能说明"2048 大概就是够用的量级"。**
2. **MSA 论文（06-12）和 IndexShare 上线（06-16）只差 4 天**，但解决的是**完全不同的两个子问题**——MiniMax 问"怎么选得更准"，Z.ai 问"怎么少选几次"。两者原则上可以叠加。
3. ⭐ **华为又加了第三个正交维度："在哪些层选"。** 于是这条线上现在有了一组完整的、**理论上可以两两叠加**的改进：

   ```
   选得更准（MSA）  ×  选得更少次（IndexShare）  ×  只在部分层选（DSA-SWA）
        粒度/归属          层间频率                  层的分工
   ```

   **三家分别占住了一个维度，而且没有任何一家同时做了两个。** 这是本文五家里唯一一组**互补而非竞争**的架构改动——也意味着这条线远没有走到头。

   ⚠️ 但要注意一个现实约束：**华为的 DSA-SWA 已经把 2/3 的层交给了 SWA，剩下能叠 IndexShare 的 full 层只有 1/3**，收益空间被自己压掉了。三者能不能真的相乘，没有任何一家验证过。

### 6.1 补充：另外三条被压缩的时间线（2026-08-04 检索补充）

| 技术 | 真实首发 | 本文原先的归属 | 说明 |
|---|---|---|---|
| **AttnRes** | **Kimi《Attention Residuals》arXiv:2603.15031，2026-03-16** | K3 报告（07-28） | 是 Kimi 自己的独立论文，早四个月，且已长出后续研究线（Delta AttnRes 2605.18855 / Multi-Head AttnRes 2607.27230） |
| **LatentMoE** | 早于 K3，K3 的贡献是前缀 "**Stable**"（三个稳定器） | — | **NVIDIA Nemotron 3 Ultra（2026-06-04）也用 LatentMoE**，措辞是"压到低秩隐空间再路由，同等推理成本下专家数 ×4"——与 K3 的动机一字不差 |
| **MOPD 这个缩写** | **Nemotron 3 Ultra（2026-06-04）** 已在用 "Multi-teacher On-Policy Distillation"，把 10+ 个专用教师蒸进一个学生 | K3 报告（07-28） | K3 早一步的是"log-ratio 当 reward"的具体形式；但更早的是 GLM-5（02-17）。**三家 + NVIDIA 四方独立收敛** |

**这一条补充实质性地加强了 §七 的结论**：原先"共识技术栈"最大的软肋是**样本全是中国实验室、互相读论文**，收敛可能只是信息传播。而 Nemotron 3 Ultra 是一个**美国团队、不同硬件栈、独立训练**的样本，却同时命中了 LatentMoE + 混合注意力 + MTP 投机解码 + 4-bit 级 QAT（NVFP4）+ 多教师 on-policy 蒸馏这五项。**收敛的置信度因此显著上升。**

**MiniMax 又补上了一个不同性质的样本**。它的价值不在于"又一家做了同样的事"，而在于它是**唯一一家把三条路线都真正跑过一遍并且写下失败原因的团队**：

```
MiniMax-01 / M1（2025）  → 线性注意力（lightning attention）——和 K3 同一条路
MiniMax-M2  （2026-05）  → 退回全注意力，并公开写下为什么退  ← 这一步是五家里独有的
MiniMax-M3  （2026-06）  → 动态块稀疏（MSA）——和 GLM 同一条路
```

所以 §一那张"五条路线"图里，**MiniMax 是唯一一个自己走过其中两条、并且主动放弃了一条的**。K3 押注线性注意力、Z.ai 评估后放弃线性注意力，这两家是**同一时点上的相反选择**；MiniMax 是**同一团队在时间轴上的先后选择**——后者的证据强度更高，因为它排除了"团队能力/数据/基建差异"这个混杂因素。详见 §3.1.1。

**openPangu（2026-07-31）补的是第三种性质的样本：同一份报告内部的横向搜索。**

前面这些证据都是"不同团队/不同世代之间"的对比，混杂因素永远去不干净。华为报告的 SWA 消融是**同一批数据、同一套超参、同一次实验里**把 FULL:SWA 的 1:2、3:1、5:1 三档一起跑出来的：

```
4K 训练长度   → 三档训练 loss 基本无差
32K / 128K    → 3:1 和 5:1 明显退化，只有 1:2 站得住
```

**这是本文所有 SWA 证据里控制得最干净的一组**（GLM 的 SWA 表跨了两种模式、MiniMax 的是跨代际观察）。它给出的结论也最具体：**问题不在"要不要用 SWA"，而在"全局层的比例能压到多低"——1:2 是可行的，1:4 以上不行。**

⚠️ 但它同样有自己的边界：**只测了训练 loss，没有测长上下文召回**。所以它能证明"5:1 会伤害语言建模本身"，不能直接对上 GLM 那张"128K 上 RULER 掉到 6.51"的表——**后者测的是能力，前者测的是拟合。**

## 七、结论：分歧之外的高度收敛

对比做到最后，**比差异更值得注意的是收敛**。五家在长上下文路线上分道扬镳，但在其他几乎所有位置得出了相同结论：

| 收敛点 | V4 | K3 | GLM-5.2 | MiniMax M3 | openPangu |
|---|---|---|---|---|---|
| **Adam 不够，必须上 Muon 系** | Muon | Per-Head Muon | Muon + Muon Split | ❓ 无材料 | **Muon**（γ=0.2 对齐 AdamW RMS） |
| **注意力投影要按 head 单独正交化** | ✗ | Per-Head Muon | **Muon Split（最早）** | ❓ 无材料 | **分 4 组 head**（不是逐 head，见下） |
| **专家权重要做 4-bit 级 QAT** | FP4 + FP8 | MXFP4 + MXFP8 | INT4 + W8A8 | ⚠️ 只知出货是 **MXFP8**，无 4-bit 证据 | **✗ —— 停在 W8A8，且无 QAT** |
| **量化必须训推一致** | FP4→FP8 反量化无损 | SFT→RL 全程 QAT | 训推 bitwise 一致的量化 kernel | ❓ 无材料 | ⭐ **五家里做得最彻底**（KPop + R3 + 三类根因解剖），但走的是**不量化训练**的路 |
| **后训练最后一步 = on-policy 蒸馏** | 全词表逆 KL | log-ratio 当 reward | **log-ratio 当 advantage（最早）** | ❓ 无材料（M2 报告是上一代） | **Multi-Expert OPD**（log-ratio，教师概率走训练引擎） |
| **推理 effort 要分档** | 3 档各训专家 | 3 档 × 3 领域 = 9 专家 | 编程多档 effort | **3 档 thinking level** | **仅 2 档**（Thinking / Non-Thinking，五家最少） |
| **MTP / 投机解码是标配** | 深度 1 | EAGLE-3 风格草稿模型 | 3 层参数共享 | **7 个 MTP 模块（最多）** | 深度 3，且 **MTP 内部一律 SWA-2048** |
| **长上下文的瓶颈是成本不是能力** | 让 1M 便宜到能当默认值 | 1M 训练即原生 | IndexShare 摊薄索引成本 | MSA 把每 query 的 KV 钉死在 2048 | ⚠️ **唯一没有跟进 1M 的**（512K 封顶） |
| **RL 基建比模型架构更需要投入** | 可抢占 rollout + WAL | Partial rollout + microVM | 异步解耦 + TITO + Orchestrator | **M2 报告 35 页里 32 页在讲这个** | **TITO + 在线动态过滤 + 训推一致性专章** |
| **弱项都在事实性知识，不在推理** | SimpleQA 差 17.7 | HLE / CritPt 落后一档 | HLE 40.5 / CritPt 20.9 | HLE 37.0 | **HLE 27.1 / SimpleQA 34.9（五家最低，缺口也最大）** |
| **原生多模态开始成为默认项** | ✗ | MoonViT-V2（27 层，从零训） | ✗ | **32 层 ViT + 3D RoPE** | ✗（纯文本，tokenizer 预留） |
| 标准残差不够用，必须改 | mHC | AttnRes | **✗（不改）** | **✗（不改）** | **mHC（与 V4 同款，含 20 次 Sinkhorn）** |
| SwiGLU 无界是个真问题 | 硬截断 `[−10,10]` | SiTU-GLU 软上限 | **✗（靠 Muon Split 从优化器侧解决）** | **`swigluoai` clamp（limit=7.0）** | ❓ **报告 0 次提及激活函数** |
| MoE 稀疏度要往上推 | 384 选 6（64×） | 896 选 16（56×） | 256 选 8（32×） | 128 选 4（32×） | **384 选 8（48×）**，但专家中间维只有 **1792（五家最小）** |
| **注意力必须做成非均质的（分层/分工）** | CSA / HCA 交替 | KDA / MLA 3:1 | DSA + IndexShare 分 Full/Shared 层 | 全层 MSA（**唯一均质的**） | **DSA / SWA / SWA 1:2** |

**这份收敛清单基本勾勒出了 2026 年这一代前沿开源模型的共识技术栈。** 加入 openPangu 之后有五处变化值得单独记：

- **SwiGLU 无界这一行，五家里出现了一个"❓"而不是"✗"。** V4 硬截断、K3 软上限、M3 用 gpt-oss 风格 clamp，GLM 明说靠 Muon Split 从优化器侧解决——**四家都对这个问题表了态**，只有华为的报告从头到尾没有出现过 `SwiGLU`/`GLU`/`SiLU`/激活函数这些词。这不是"不认为是问题"，而是**没有留下任何可核对的记录**。见 §3.4。
- **残差改造从"两家改两家不改"变成"三家改两家不改"，而且原来那条干净的规模分界线被打破了。** 改的三家里，V4（1.6T）和 K3（2.8T）是被规模逼的，**openPangu 只有 505B 却也上了 mHC——而且它给的理由不是稳定性，是下游收益**（Table 2：7 个任务全赢，均分 0.594 → 0.615）。**"mHC 只有超大模型才需要"这个判断因此不成立了。** 见 §3.2。
- **量化这一行出现了第一个反向样本。** 四家都在往 4-bit 推，华为停在 W8A8 且看不到 QAT。**但它在"训推一致性"这一行反而是做得最深的**——这两件事其实是同一个取舍的两面：**它选择了"训练侧不引入量化误差，转而在推理侧把误差逐层查清楚"，而另外四家选择了"把量化误差提前灌进训练里让模型自己适应"。** 两条路都成立，但只有前者能拿到 §3.8 那种层级的根因分析。
- **`Muon 分 head 正交化`这一行第一次出现了中间态。** GLM 逐 head、K3 逐 head，华为**分成 4 组**——它明确写了这是在"正交化粒度"和"算子效率"之间取的折中。**三个样本、三种粒度，说明这个超参本身可能没那么敏感。**
- **多了一行"注意力必须做成非均质的"**。这是加入第五家之后才浮现出来的收敛点：**五家里有四家把不同的层交给了不同的注意力机制**，只有 M3 是全层同构。**这可能比"用哪种稀疏"更接近这一代的真正共识——即"一层解决所有问题"的时代结束了。**

分歧集中在三处：

1. **在 1M 尺度上，softmax 注意力该被压缩（V4）、被替换（K3）、被稀疏化（GLM / MiniMax）、还是被分工（华为）？** 四条路线都拿出了能打的结果。但**加入 MiniMax 和华为之后，"被替换"这一侧的证据进一步变弱**——K3 是唯一还在押注线性注意力的，Z.ai 评估后放弃、MiniMax 跑过一代后主动退回、华为则**根本没有把线性注意力列入候选**（报告里没有任何线性注意力的讨论）。**四比一。**
2. **要不要为了"更深更大"付出改残差 + 改激活函数的代价？** V4、K3、华为说要，GLM 和 MiniMax 说不必——**而 GLM 在 agentic 编程上、M3 在 SWE-bench Verified 上都没有因此落后一个档次**。这暗示这一代的能力差距里，架构贡献可能小于后训练与数据贡献。**openPangu 是这条判断最强的一个佐证**：它的架构工作量在五家里排第一或第二，能力却排第五。见 §5.3。
3. ⭐ **上下文长度到底该冲到哪一档？** 前四家全部押 1M，**华为停在 512K 且不给任何长上下文评测**。这是本文唯一一处"四对一"的路线分歧，而且**没有任何一方给出过论证**——四家没说 1M 为什么必要，华为也没说 512K 为什么够。**这一格是整份对比里证据最薄的一格。**

**最后一条观察**：五家的公开材料篇幅分配很能说明它们各自认为什么最重要——

```
DeepSeek-V4（58 页报告）  ：架构 + Infra + 效率           → "让 1M 便宜到能当默认值"
Kimi K3    （47 页报告）  ：架构 + 能力 + 产品            → "开源的前沿智能"
openPangu  （45 页报告）  ：架构 + 训推一致性 + 昇腾工程   → "在自家硬件上把整条链路跑通"
GLM-5      （40 页报告）  ：后训练 + RL 基建 + 国产芯片   → "从 vibe coding 到 agentic engineering"
MiniMax M2 （35 页报告）  ：后训练 + RL 系统（架构仅 3 页）→ "怎么把 RL 跑对"
MiniMax MSA（30 页论文）  ：一个组件的机制 + kernel       → "怎么把稀疏注意力做快"
GLM-5.2                  ：（无）
MiniMax M3               ：（无）
```

**两家最新的旗舰都没有技术报告。** 这本身是一个信号：**当竞争焦点从"架构创新"转移到"后训练配方与 RL 基建"时，厂商公开的意愿会明显下降**——因为架构可以写成论文，RL 配方是护城河。

MiniMax 提供了这个趋势下的一种**折中形态**：**不发模型报告，但把单个可发表的组件（MSA）单独写成论文，并把 kernel 开源、把完整配置写进 `config.json`。** 结果是——M3 的注意力部分反而是五家里**唯一能拿论文逐条核对出货配置**的（见 §零）。这或许是一条比"要么全写要么不写"更现实的路。

**openPangu 则给出了第三种形态，而且是与前两种正交的一种**：

```
DeepSeek / Kimi   →  写完整报告，但只开权重
MiniMax           →  不写报告，但开 kernel + 完整 config
华为              →  写完整报告，并且开了预训练代码 + 后训练代码 + 训练算子
```

**"开源训练代码"这件事，五家里只有华为做了。** 一份报告的可复核性最终取决于别人能不能重跑它——**权重只能验证结论，代码才能验证过程。** 这是 openPangu 在这份对比里最容易被忽略、但可能最有长期价值的一格。

⚠️ 同时要注意它换来的代价：**许可从 MIT 退成了 `OPENPANGU MODEL LICENSE 2.0`**。所以五家在"开放"这个维度上其实是两条不同的轴——**GLM 开得最"自由"（MIT），华为开得最"完整"（代码 + 算子），两者并不是同一件事。**
