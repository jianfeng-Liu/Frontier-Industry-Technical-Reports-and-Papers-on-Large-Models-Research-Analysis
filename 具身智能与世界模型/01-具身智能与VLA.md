# 01 具身智能与 VLA：机器人的「大脑」长什么样

> 上一章说了：具身智能的三个根本约束是 **【不可撤销】【实时】【数据极贵】**。
> 这一章讲现在主流的解法，以及它撞上的墙。

---

## 1.1 先给 VLA 一个准确定义

> 📖 **VLA = Vision-Language-Action Model，视觉-语言-动作模型。**
> 一个模型，**输入**是摄像头画面（Vision）+ 自然语言指令（Language），**输出直接就是机器人的控制指令**（Action）。

| | 内容 | 形状 |
|---|---|---|
| **输入** Vision | 摄像头看到的画面（可能好几个机位） | 每机位一张 RGB 图，如 `[3, 224, 224]` |
| **输入** Language | 「把桌上的红色杯子递给我」 | 一串文本 token |
| ↓ | **VLA 模型** | — |
| **输出** Action | 7 个关节各转多少度 + 夹爪开合 | ★ `[8]`，每一维都是**连续实数** |

> ★★ **最后一行是 VLA 和普通视觉语言模型的真正分界**：语言模型输出的是**词表上的一道选择题**（从十几万个 token 里挑一个），VLA 输出的是**连续实数向量**。挑错一个词读者还能看懂，关节角差 5 度杯子就摔了 —— 这个差别会在 1.3 节变成一个实打实的技术难点。

> ★ **想看这张表里每一行的具体数字**（图像切成几个图块、拼起来一共多少 token、动作块是多大一个数组、控制器多久要一条指令），[00 章](00-一个例子讲清关系.md) 第七节有一次从头到尾的走查，本章后面会反复引用它。

**为什么这个设计是个突破**：在 VLA 之前，机器人得靠工程师针对每个任务写规则、调参数。VLA 的想法是——**把已经在互联网上学过「什么是杯子、什么叫递给我」的视觉语言大模型，直接接上电机**。

> 📖 **VLM = Vision-Language Model，视觉语言模型**，就是能看图说话的多模态大模型。**VLA 就是在 VLM 屁股后面接了一个「动作输出」。**
>
> 🔎 有研究者强调这一点是 VLA 的**定义性特征**：主干必须是在大规模视觉-语言数据上**预训练过**的；没有预训练的，只能叫「多模态策略」（multimodal policy），不配叫 VLA。**因为 VLA 全部的泛化能力都来自那个预训练主干。**

## 1.3 ★ 第一个技术难点：动作怎么「输出」

这是 VLA 最核心、也最反直觉的一个工程问题。

```
    ⚠️ 语言模型输出的是【一个词】—— 从词表里选一个，是【选择题】
    ⚠️ 机器人要输出的是【7 个关节的角度】—— 连续实数，是【填空题】

    ⟹ 怎么让一个只会做选择题的模型去做填空题？
```

目前三条路：

### 路线① 离散分箱：把连续值硬切成格子

```
    关节角度范围 −180° ~ +180°，切成 256 个格子
    ⟹ 「转 37.4 度」≈ 第 148 号格子 ⟹ 变成了选择题，语言模型直接能做

    ✅ 优点：改动最小，语言模型的整套训练流程直接复用
    ⚠️ 缺点：精度被格子大小卡死；要输出 20 步动作 x 8 维（7 关节 + 夹爪）
             = 160 个 token，太慢
```

### 路线② 扩散 / 流匹配：让模型直接「画」出连续动作

> 📖 **扩散模型（Diffusion）/ 流匹配（Flow Matching）**：本来是画图用的技术——从一团随机噪声出发，一步步「去噪」，最后变成一张清晰的图。**用在机器人上就是：从一团随机数出发，去噪成一串平滑的关节轨迹。**

```
    ✅ 优点：天生输出连续值，动作平滑；一次能出一整段（叫【动作块 action chunk】）
    ⚠️ 缺点：要迭代好几步才出结果，推理慢；⚠️ 而且它【给不出动作的概率】
             —— 这一条在 1.6 会变成一个大麻烦
```

★ π0 系列走的就是这条路。

### 路线③ 更聪明的动作分词器

```
    ✅ FAST：专为 VLA 设计的【动作块分词器】
       🔎 思路是先把一段动作变换到【频域】再量化，
          ⟹ 一段动作的低频部分（大致往哪挪）几个系数就描述完了，
             原来要几百个 token 的东西能压到几十个量级
       ⟹ 证明了「离散 token」这条路也能做好，不一定非要上扩散
    🔎 ICLR 2026 上的新分词器进一步用了【残差矢量量化】
       （Residual Vector Quantization，RVQ：先量化一遍，
         再对「量化误差」量化第二遍，层层补残差）等技术
```

### ★★ 四种做法横着比一遍

上面三条路讲的是**「一个动作怎么编码」**。但真实系统里还有一个和它**正交**的选择——**「一次输出几个动作」**。把四件事摆在一张表里，这个领域的选型就清楚了：

| | **① 连续向量回归** | **② 离散 token 分箱** | **③ 扩散 / 流匹配** | **④ 动作分块**（叠加项） |
|---|---|---|---|---|
| **一句话** | 动作头直接吐 8 个实数 | 每一维切 256 格，当成词输出 | 从随机噪声去噪成一段轨迹 | 一次吐一整段，而不是一步 |
| **输出形状** | `[8]` | H × 8 个整数 token | `[H, 8]` | 把上面任一种的 H 从 1 变成 50 |
| **出 1 秒动作<br>（50 步 × 8 维）要解码几次** | 1 次前向 | ⚠️ **400 个 token**，自回归就是 400 次 | 去噪迭代 **10~50 次**<br>（每次都出完整的 `[50, 8]`） | — |
| **能不能和语言模型<br>共享同一套词表** | ❌ 不能，得换一个回归头 | ✅ **能** —— 这是它最大的卖点 | ❌ 不能，要外挂一个「动作专家」 | 与此无关 |
| **延迟** | ✅ 最低 | ⚠️ 随 H **线性**涨，最慢 | ⚠️ 中等，被去噪步数支配 | ✅ ★ **把延迟摊薄**：想一次管 H 步 |
| **动作平滑度** | ⚠️ 步与步之间可能跳变 | ⚠️ 被格子量化，有台阶感 | ✅ 天生平滑 | ✅ 块内天然连贯 |
| **★ 多峰性** | ❌ **会取平均**，平均出一个两边都不对的动作 | ✅ softmax 分布天然多峰 | ✅ 天生多峰 | 与此无关 |
| **给不给得出<br>这个动作的概率** | ❌ 不给 | ✅ **给**（就是 softmax 那一列数） | ❌ **不给** ⟹ 1.6 节的大麻烦 | 与此无关 |
| **训练难度** | ✅ 最简单（一个均方误差就完了） | ✅ 和训语言模型一模一样（交叉熵） | ⚠️ 要调噪声调度、去噪步数 | ⚠️ 块越长越难，还要处理「块和块怎么接上」 |
| **代表** | 早期行为克隆的回归头 | RT-1 / RT-2 / OpenVLA / FAST | π0 系列 / Diffusion Policy | ACT、π0，以及 2024 年后几乎所有系统 |

> 📖 **多峰性**（multimodality，多模态分布 —— ⚠️ 注意这个「多模态」和「图文多模态」是两个完全不同的词，只是中文撞名）：**对同一个画面，可能有好几个都正确的动作。**
> ```
>     杯子正前方挡着一个碗，手要绕过去。
>       左绕  ==> 对
>       右绕  ==> 也对
>     ① 连续向量回归学到的是这两者的【平均】==> 直直撞上碗。
>     ==> ★★ 这就是扩散策略被请进机器人领域的头号理由：
>         它建模的是【一个分布】，不是【一个数】。
> ```

> ★★ **这张表最要紧的一句话：④ 和 ①②③ 不在同一个维度上，可以任意叠加。**
> ⟹ RT-2 ≈ ②；π0 ≈ ③ + ④；FAST ≈ ② + ④。看到一篇新论文，先把这两件事拆开问：**动作怎么编码？一次出几步？**

**为什么④几乎成了标配——把延迟和控制周期并排一除就知道了**（沿用 [00 章](00-一个例子讲清关系.md) 第七节那套数字：控制周期 20 ms，一次要出 1 秒 = 50 步动作）：

```
    走 ② 这条路，50 步 x 8 维 = 400 个 token 要自回归吐出来。
    哪怕一个 token 只要 1 ms：

      不分块（每步重想一次）：  8 token x 1 ms =   8 ms  想一步
                               ==> 控制周期 20 ms，勉强跟得上，
                                   但大脑【什么别的都干不了】

      分块一次出 1 秒：        400 token x 1 ms = 400 ms 想一次
                               ==> 这 400 ms 换来 1000 ms 的动作
                               ==> ★ 占空比 40%，还剩 60% 的余量，能跑

    ==> ★★ 动作分块不是为了动作更好看，是为了【把一次昂贵的思考
        摊到几十个控制周期上】，让大模型在毫秒级控制环里活下来。
    ==> ⚠️ 代价：块内这 1 秒是【睁眼瞎】—— 动作早就定好了，
        中途看到杯子滑了也改不了。所以实际系统只执行块的前一小段
        就重新规划（00 章那个例子是 50 步只执行 10 步）。
    ==> 🔎 这也正是 FAST 那类分词器的价值：把 400 个 token 压到几十个，
        占空比就从 40% 掉到个位数。

    ⚠️ 上面只算了【吐 token】的时间，没算「看一眼画面 + 过一遍主干」
       那一次前向 —— 那才是大头（1.7 节会算出它在边缘芯片上要 68 ms）。
       把它加回去：
         不分块：每 20 ms 要跑一次 68 ms 的前向  ==> ★ 根本不成立
         分块：  (68 + 400) ms 换 1000 ms 的动作 ==> 占空比约 47%，还能跑
       ==> ⚠️ 所以「不分块勉强跟得上」只在纸面上成立；
          真实系统里动作分块不是优化项，是【准入条件】。
```

> 🔑 **这一节记住**：VLA 的一半工程量，花在「怎么把连续动作塞进一个语言模型的框架里」。
> ★ 而且这笔工程量有一半不是为了「准」，是为了「快」—— 上面那个占空比的账，就是全部原因。

## 1.4 ★★ 第二个技术难点：快慢两个脑子

回到第 00 章那三条约束里的**【实时】**：

```
    ⚠️ 矛盾：
       看懂「把红杯子递给我」需要一个【大】模型 ⟹ 慢，一秒钟顶多跑几次
       控制手臂不摔倒需要【高频】刷新          ⟹ 快，一秒钟要跑几百次

    ★★ 一个模型不可能同时又大又快。
```

**解法：分层，两个脑子按不同频率跑。** 这在 2025 年后几乎成了行业共识：

| | **System 2**（慢脑 / 大脑） | **System 1**（快脑 / 小脑） |
|---|---|---|
| **是什么** | 视觉语言大模型，理解场景和指令 | 🔎 一个小得多的网络（Helix 是 **80 M** 参数） |
| **输入** | 图像 + 语言指令 | 图像 + 机器人当前姿态 + **上面传下来的语义向量** |
| **输出** | 一个「语义向量」或一句子任务描述 | 具体的关节指令 |
| **频率** | 🔎 约 **7~9 Hz** | 🔎 **200 Hz** |
| **周期** | ⚠️ 约 **111~143 ms** | ⚠️ **5 ms** |

两者之间传的就是那一句「现在去抓那个杯把」。**为什么非拆成两个不可？把频率换算成周期就看出来了**：

```
    快脑周期   1 / 200 Hz  =    5 ms
    慢脑周期   1 / 8 Hz    =  125 ms
                              --------
    相差                        25 倍

    ⟹ 慢脑想一次的工夫，快脑已经要发出 25 条关节指令。
    ⟹ ★★ 所以这【不是】工程上图省事，是物理上没有选择：
       让 200 Hz 的控制环去等一个 125 ms 的大模型，
       机器人在那 125 ms 里就是一具僵住的躯体。
```

> ⚠️ 7~9 Hz 和 200 Hz 都是 🔎 Figure 公布的 Helix 数字，**换个本体、换个任务会差很多**；要记的是**两者差一到两个数量级**这个结构，不是这两个具体数。完整的频率阶梯（高层规划秒级 / 轨迹百毫秒级 / 关节控制毫秒级）见 [09 章](09-本体运动与触觉.md)。

> ★ **这个「慢的负责想、快的负责动」的分工，和人类神经系统的大脑/小脑分工是一个道理。**
>
> 🔎 各家的具体叫法不同：NVIDIA GR00T 叫 System 2 / System 1；Figure 叫 System 2 / System 1（Helix-02 🔎 还加了个 system0 全身控制器）；Google 则是让模型**先用语言把思路想出来，再转成动作**。
> ⚠️ 以上频率与参数量均来自二手报道，未回溯官方技术报告。

## 1.5 ★★★ 第三个、也是最要命的难点：数据

回到第 00 章那三条约束里的**【数据极贵】**。这是具身智能和大语言模型最本质的差别：

```
    ⚠️ 大语言模型：互联网上有几十万亿 token 的现成文本，免费
    ⚠️ 机器人：   「看到这个画面，该转多少度」这种数据，
                   互联网上【一条都没有】—— 因为没人会把关节角度发到网上
```

### ★★ 先把「极贵」换算成数量级——不然这一节只是情绪

**「数据贵」这三个字说一百遍也没用，得算出来差多少。** ⚠️ 难点在于两边的单位根本不是一回事：文本按 **token（词元）** 计，机器人数据按 **条（轨迹 / episode）** 计。

```
    ⚠️ 第一件要避开的事：
       「10^13 个 token」  除以  「10^6 条轨迹」  是【没有意义】的。
       分子分母不是同一种东西，相除得到的数不代表任何现实。

    ==> 必须先把两边换成【同一个单位】再比。下面换两次：按 token 比一次，按小时比一次。
```

**换算用到的假设**（⚠️ **全部是本文自己设的量级估值，不是任何论文的结论**；换一组假设，结果会在一两个数量级内浮动）：

| 假设项 | 取值 | 为什么这么取 |
|---|---|---|
| 一条遥操作轨迹多长 | 20 秒 | 桌面抓放类任务的典型时长 |
| 记录频率 | 10 Hz | ⟹ 一条 = 20 × 10 = **200 个时间步** |
| 一个时间步的监督信号 | 8 维动作 | 沿用 1.1 节那个 `[8]` |
| 一维动作折合几个 token | 1 个 | 按 1.3 节路线②「离散分箱」口径 ⟹ **一步 = 8 个动作 token** |

**口径一：都换成 token。**

```
    文本侧（🔎 公开披露的前沿配方在这个量级）：
      预训练语料  ~ 1.5 x 10^13 token

    机器人侧（🔎 公开数据集最大的一档，Open X-Embodiment 约 100 万条）：
      时间步总数 = 10^6 条  x 200 步/条     = 2.0 x 10^8 步
      动作 token = 2.0 x 10^8 x 8 token/步 = 1.6 x 10^9 token

    相除（现在单位一致了，可以除）：
      1.5 x 10^13  /  1.6 x 10^9  =  约 9,400 倍

    ==> ★★ 差【四个数量级】。
```

**口径二：都换成小时。** 这个口径更好懂，也更能看清各类数据之间的阶梯：

| 数据种类 | 量级（小时） | 有没有动作标签 | 代表 |
|---|---|---|---|
| **互联网视频** | **10⁶** 小时 | ❌ 没有 | 🔎 V-JEPA 2 预训练用了「超过 100 万小时」（见 [02 章](02-世界模型三条路线.md) 2.4 节） |
| **人类第一视角视频** | **10⁴** 小时 | ❌ 没有 | 🔎 Ego4D 约 3,700 小时；GR00T N1.7 的 EgoScale 约 20,854 小时 |
| ★ **带动作标签的真机数据** | **10³ ~ 10⁴** 小时 | ✅ **有** | 🔎 Open X-Embodiment 约 100 万条 ≈ 5,600 小时（= 10⁶ × 20 秒 ÷ 3600）；DROID 约 350 小时 |

```
    ==> ★ 每往下一档，【量】掉一到两个数量级，【可用性】升一档。
    ==> 上面那张「五条出路」表里的每一条，本质都是同一句话：
        拿上面两档的【量】，去补最下面一档的【质】。
```

**口径三：换成人力——这才是「贵」字落地的地方。**

```
    一条轨迹 20 秒，但真实采集还要摆场景、复位、挑废片。
      一个人一小时实际能采到的 ==> 约 50 条（⚠️ 本文估值）

    要采满 10^6 条：
      10^6 / 50          = 2 x 10^4 人·小时
      按一人一年工作 2,000 小时
      2 x 10^4 / 2,000   = ★★ 10 个人全职干一整年

    ==> 而这 10 人年换来的，是比文本语料小【四个数量级】的东西。
    ==> 文本那 10^13 token 的采集成本是【零】—— 它本来就躺在互联网上。
```

> ★★ **这个四个数量级的差距，是本领域一切技术选择的根源。** 仿真、手持采集装置、人类视频预训练、世界模型生成数据 —— 它们看上去是四件不相干的事，其实都在回答同一个问题：**怎么绕开那 10 个人年。**
> ⚠️ **但请只记量级，别记具体数**：上面每一步都挂着假设（20 秒一条、50 条一人时、8 token 一步）。换一组合理的假设，倍数会在 **10³ ~ 10⁵** 之间浮动。**能确定的是「三到五个数量级」，不是「三倍五倍」。**

现在的五条出路，按成本从高到低：

| 路子 | 怎么做 | 代价 |
|---|---|---|
| **真机遥操作** | 人拿着手柄/动捕设备遥控机器人干活，全程录下来 | ⚠️ 最贵、最慢，但**质量最高**，目前不可替代 |
| **UMI 一类手持夹爪** | 人拿一个装了相机的手持夹爪自己干活，不用机器人 | ✅ 便宜很多，质量接近真机 |
| **人类第一视角视频** | 拿人戴着相机干活的海量视频来预训练 | ⚠️ **没有动作标签**，得想办法反推（见下） |
| **仿真** | 在物理引擎里跑 | ⚠️ **sim2real 差距**：仿真里学会的到真机上未必work |
| **世界模型生成** | ★★ 用生成模型批量造数据 | **← 这正是第 03 章的主题** |

> 📖 **没有动作标签怎么办**——两个主流补法：
> ① **潜动作（latent action）**：让模型自己从「前一帧 → 后一帧」的变化里，**倒推出一个抽象的动作表示**，拿它当伪标签。
> ② **逆动力学模型**：先预测「接下来画面会怎么变」，再用一个专门的模型问「**要做什么动作才会导致这个变化**」，反推出动作。

**★ 数据规模开始出 scaling law 了**（🔎 二手，需复核）：

```
    🔎 GR-2 ：视频片段 80 万 ⟶ 3800 万，随参数增大效果持续提升
    🔎 GR00T N1.7 的 EgoScale：用 20,854 小时人类第一视角视频预训练
       NVIDIA 宣称是【机器人灵巧性的第一个 scaling law】：
       1,000 小时 ⟶ 20,000 小时，平均任务完成度【翻倍以上】
```

## 1.6 ★★ 2026 年最重要的一次突破：让 VLA 从失败里学

> ✅ 论文：*π\*0.6: a VLA That Learns From Experience*（arXiv 2511.14759，Physical Intelligence）

**先说清楚它解决的病**：

```
    ⚠️ 模仿学习的死穴 ——【误差累积】

    教它的数据全是人类专家的【成功】演示。
    ⟹ 机器人从没见过「搞砸了之后长什么样」
    ⟹ 一旦第一步有点偏，它就进入了训练数据里【从未出现过】的状态
    ⟹ 于是第二步偏得更多 …… 雪崩

    ★ 人类不是这样学的：人会犯错、被纠正、然后记住。
```

**解法 RECAP**（RL with Experience and Corrections via Advantage-conditioned Policies）：

```
    ① 先用【离线强化学习】预训练一个通才 VLA
       📖 离线强化学习 offline RL：只拿【已经录好】的数据训，
          训练过程中不和真实环境交互 —— 和「在线」相对
    ② 让它上机器人真干活，同时收集两种东西：
         · 它自己跑出来的轨迹（有成功有失败）
         · ★ 人类专家在它快搞砸时【实时接管纠正】的操作
    ③ 用这些数据训一个【价值函数】，判断「某个动作到底是好是坏」
       📖 价值函数 value function：吃进「当前状态（+ 动作）」，
          吐出一个数，表示「从这里往下走，预计能拿到多少好处」
    ④ 把这个好坏判断（叫【优势 advantage】）作为【条件】喂回给 VLA
```

> ★★ **最精妙的一步在 ④**，它绕开了一个硬约束：
> ```
>     ⚠️ 1.3 说过，流匹配输出的动作【给不出概率值】
>        📖 PPO = Proximal Policy Optimization，近端策略优化
>        📖 SAC = Soft Actor-Critic，软演员-评论家
>        ⟹ 这两类标准强化学习算法【全都用不了】——
>           它们都要算「新策略给这个动作的概率 ÷ 旧策略给的概率」，
>           而流匹配根本不输出概率，这个比值无从算起
>
>     ✅ RECAP 的绕法：不算概率，改成给每个动作贴「好/坏」标签，
>        把标签当成【输入条件】训练。
>        部署时，永远把条件设成「好」⟹ 模型就只生成它认为好的动作。
> ```
> ⚠️ 这段机制描述来自二手解读，未回溯论文原文。

**效果**（🔎 二手转述）：

```
    🔎 最难的任务上：吞吐量【翻倍以上】，失败率【大约减半】
    🔎 实测场景：连续 18 小时不间断做意式咖啡；
                 在一个【没去过的新家】叠 50 件没见过的衣服；
                 装配 59 个真实工厂纸箱
```

> ⚠️ **读这几个数之前，先过一道噪声门槛。** 机器人论文的真机试验常常只有几十次，而成功率的标准误是 `SE ≈ √(p(1−p)/n)` —— **n = 20、p = 0.5 时 SE 就有 11 个百分点**。上面这几条转述**没有给出试验次数**，所以只能当**趋势**看，不能当可比的数。完整门槛与配对检验的做法见 [附-速查表](附-速查表.md) F2 节。
> ⚠️ **还有一个口径要分清**：「失败率大约减半」和「成功率提升 X%」是两回事。失败率 30% → 15%，等于成功率 70% → 85%，是**涨了 15 个百分点**；写成「提升 15%」会被读成 70% → 80.5%，差了一截。

> 🔑 **为什么这件事重要**：这是「机器人真正开始**自我改进**」的第一个生产级信号。
> ⟹ 但注意——**它靠的是真机试错**。真机试错依然又慢又贵。
> ⟹ ★★ **「那能不能在想象里试错？」——这就直接引出了世界模型。**

## 1.7 ⚠️ VLA 目前公认的四堵墙

```
    ① 泛化：换个房间、换个光照、换个没见过的物体，成功率就掉
    ② 长程：需要几十上百步的任务，中途某一步崩了就全崩
    ③ 实时：模型越大越准，但边缘设备上跑不动
    ④ 数据：高质量真机数据的获取成本，是压在所有人头上的天花板

    ⟹ ★★ 注意 ①②④ 三堵墙，世界模型都能直接给出对策
       —— 这就是 2026 年世界模型「杀回来」的原因。
```

### ★★ 每堵墙具体卡在哪个数字上

**「四堵墙」说出来很顺口，但不给数字就只是口号。** 每一堵墙其实都卡在一个可以写出来的数上：

| | 墙 | ⚠️ 它具体卡在哪个数字上 | 这个数哪来的 |
|---|---|---|---|
| ① | **泛化** | 卡在**训练数据覆盖的场景数**：🔎 公开真机数据集里场景最多的 DROID 约 **564 个场景**，Open X-Embodiment 约 **22 种本体**；而光是「别人家的厨房」这一类，真实布局就远不止几百种 | 🔎 数据集公开数字 |
| ② | **长程** | 卡在 **99.31%**：一个 100 步的任务想做到 50% 成功率，**单步成功率必须 ≥ 0.5^(1/100) = 99.31%** | ⚠️ 本文推算，见下 |
| ③ | **实时** | 卡在 **68 ms**：一个 7B（70 亿参数）VLA 按 BF16 存是 **14 GB**；边缘芯片 Jetson AGX Orin 的显存带宽是 **204.8 GB/s** ⟹ 光把权重读一遍就要 14 ÷ 204.8 = **68 ms**，频率上限 **14.6 Hz** | ✅ 公开规格 + ⚠️ 本文推算 |
| ④ | **数据** | 卡在 **10 个人年**和 **四个数量级**：见 1.5 节那三笔账 | ⚠️ 本文推算 |

**② 长程那个 99.31% 是怎么来的**（⚠️ **示意模型**，只用来看量级）：

```
    假设：每一步成功与否互相独立，而且失败【不可挽回】。
          单步成功率 p，N 步全做对的概率 = p^N

      p = 0.95, N =  10   ==>  0.95^10   = 60%
      p = 0.95, N =  50   ==>  0.95^50   =  7.7%
      p = 0.99, N =  50   ==>  0.99^50   = 61%
      p = 0.99, N = 100   ==>  0.99^100  = 37%

    反过来问：100 步的任务想做到 50% 成功率，单步要多准？
      p = 0.5^(1/100) = 99.31%

    ==> ★★ 这就是「长程」两个字的全部含义 ——
        它要的不是「做得对」，是【99.3% 那一档的对】。
        而 1.5 节刚算过，训练数据只有文本的万分之一。

    ⚠️ 这个模型是【下界】，不是实际值：真实任务里步与步并不独立，
       有些偏差下一步能自己修回来。
    ==> ★ 但正因为如此，1.6 节那套「从失败里学」的意义才看得清楚：
        它不是把 p 从 0.99 推到 0.993，
        而是给系统【装上纠错能力】，让「连乘」这个模型本身失效。
```

**③ 实时那个 68 ms 还解释了 1.4 节的频率表是怎么来的**：

```
    理论上限      14 GB / 204.8 GB/s        = 68 ms  ==> 14.6 Hz
    打个带宽折扣  实际利用率按 70% 算        ==> 约 10 Hz
    再加上视觉编码器、动作头、数据搬运        ==> 落进 ★ 7~9 Hz

    ==> ★★ 1.4 节那个「慢脑 7~9 Hz」不是谁拍脑袋定的，
        它基本就是【权重除以带宽】这道除法的结果。
    ⚠️ 只算了「把权重读一遍」这一项，是个乐观下界；
       真机上还要加上预处理、通信和调度。
```

> 🔑 **把四堵墙连起来读**：①④ 是同一堵墙的两面（数据不够 ⟹ 覆盖不住新场景），②是①的放大器（每步差一点，100 步后差很多），③是硬件给的硬天花板。⟹ ★★ 所以 ①②④ 才会一起指向同一个出口——**造数据、在想象里试错**，也就是接下来两章的全部内容。

## 🔑 本章一句话

> **VLA = 视觉语言大模型 + 一个动作输出头**，靠模仿人类演示学会干活。
> 它的两个核心工程问题是「**连续动作怎么输出**」和「**快慢两个脑子怎么分工**」，
> 而它的**天花板是数据**——⚠️ 这个天花板，是世界模型被请回来的直接原因。
>
> ★ **本章要带走的四个数**：动作分块把一次 **400 ms** 的思考摊到 **1 秒**的动作上（1.3 节）；慢脑 **7~9 Hz** 基本就是「14 GB 权重 ÷ 204.8 GB/s 带宽」这道除法的结果（1.4 / 1.7 节）；带动作标签的真机数据比文本语料小 **四个数量级**、折合约 **10 个人年**（1.5 节）；100 步的任务要 50% 成功率，单步得准到 **99.31%**（1.7 节）。
