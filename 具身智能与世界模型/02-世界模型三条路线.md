# 02 世界模型的三条路线：画像素、不画像素、可交互

> 上一章结尾说：VLA 撞了四堵墙，其中三堵世界模型都能给出对策。
> 这一章讲世界模型本身——**它有三种做法，彼此的分歧比你想的深。**

---

## 2.1 先把定义收紧

第 00 章给的定义是：

```
    世界模型（ 当前状态 , 我要做的动作 ）  ⟹  预测：下一刻的状态
```

★ 这里有**两个词**决定了它和普通视频生成模型的区别：

```
    ★ 「我要做的动作」 ⟹ 【动作条件的 action-conditioned】
       同样的画面，我向左走 和 我向右走，它得给出【不同】的未来。
       ⚠️ 只会根据文字提示生成一段好看视频的模型，不算世界模型 ——
          因为你没法在中途「操作」它。

    ★ 「下一刻的状态」 ⟹ 它必须能【一步步往下滚】
       预测出的下一刻，要能作为输入再喂回去，预测下下刻。
```

> ⚠️ **一个仍在争论的问题**：视频生成模型（Sora 那种）到底算不算世界模型？
> 🔎 支持方说：模型规模一大，3D 一致性、物体恒存性、真实物理就**自己涌现**出来了。
> 🔎 反对方说：画面对 ≠ 物理对，生成视频里的物理常常是「看起来像」而已。
> ★ 这个分歧直接导致了下面的路线① vs 路线②。

### ★★ 「能往下滚多少步」才是世界模型的第一指标

上面第二个词说「它必须能一步步往下滚」。**但没人问过一句最要紧的话：能滚几步？** 这个数决定了一个世界模型到底能干什么活，比它的参数量、分辨率都重要得多。

```
    ⚠️ 为什么滚不远？因为【自己的输出要当下一步的输入】。

      第 1 步：  真实画面      ==>  预测画面 1    （带一点点误差）
      第 2 步：  预测画面 1    ==>  预测画面 2    （在带误差的输入上又错一点）
      第 3 步：  预测画面 2    ==>  预测画面 3    （错上加错）
      ...

    ==> 📖 这叫【误差累积 / 复合误差】（compounding error）。
        它不是某个模型的 bug，是【自回归推演】这种做法的固有性质。
```

**把它写成一个最简单的式子，就能算了**（⚠️ **以下全是示意推演，不是任何论文的实测数据**，只用来看「量级怎么变」）：

```
    记：δ = 每一步【新增】的相对误差
        λ = 上一步的误差传到这一步会被放大的倍数

      λ = 1.0  ==> 误差只是【累加】，不放大（最理想）
      λ > 1.0  ==> 误差被【放大】，越滚越快崩（现实）

    滚到第 N 步时的总误差：
      λ = 1  :  e_N = δ x N
      λ > 1  :  e_N = δ x (λ^N - 1) / (λ - 1)
```

取 δ = 1%（单步 1% 的误差，已经算相当准了），把三种 λ 并排滚一遍：

| 滚到第 N 步 | **λ = 1.0**（误差不放大） | **λ = 1.1** | **λ = 1.3** |
|---|---|---|---|
| 1 | 1.0% | 1.0% | 1.0% |
| 5 | 5.0% | 6.1% | 9.0% |
| 10 | 10.0% | 15.9% | 42.6% |
| 14 | 14.0% | 28.0% | 128% |
| 20 | 20.0% | 57.3% | 630% |
| 50 | 50.0% | 1164% | 天文数字 |
| ★ **把「误差 > 30%」算崩，能滚几步** | **30 步** | **14 步** | **8 步** |

**现在把这三个数字和「世界模型能干什么活」对上**（这三档的划分见 [07 章](07-世界模型的四种用法.md) 7.5 节的问题二）：

| 能滚的步数 | 能当什么用 | 对应 λ / δ 大概要到什么水平 |
|---|---|---|
| **几步** | 只能当**数据工厂**（生成几帧画面当训练样本） | λ = 1.3、δ = 1% 就是这一档 |
| **几十步** | 能当**前瞻模块**（动手前推演一下） | λ = 1.1、δ = 1% ⟹ 14 步，刚够下限 |
| ★ **几百步** | 才谈得上**在里面做强化学习** | ⚠️ **λ 必须 ≈ 1.0 且 δ ≤ 0.1%** ⟹ 0.30 ÷ 0.001 = 300 步 |

> ★★ **最后一行是这一小节的全部重点**：想滚到几百步，**光把单步做准是不够的**。
> ```
>     固定 λ = 1.1，只把单步误差 δ 往下压：
>       δ = 1%     ==>  能滚 14 步
>       δ = 0.1%   ==>  能滚 36 步      （δ 降 10 倍，只多 22 步）
>       δ = 0.01%  ==>  能滚 60 步      （再降 10 倍，又只多 24 步）
>
>     ==> ★ 这是【对数增长】：精度每提高一个数量级，
>         步数只是【加】二十几步，不是【乘】十倍。
>     ==> ★★ 所以要跨进「几百步」那一档，唯一的办法是把 λ 压到 1.0 ——
>         也就是让模型【不放大误差】，错了还能自己拉回来。
>     ==> 而「不放大误差」意味着模型真的受物理约束支配，
>         而不只是在外推一段看起来对的画面。
>         ⟹ 这正是 2.7 节硬伤一的另一种说法。
> ```

> ⚠️ **这套推演的边界要说清楚**：真实的世界模型误差不是一个标量，λ 也不是常数（有的区域稳、有的区域一崩到底）。**上面的表只能用来理解「为什么从几十步到几百步这么难」，不能拿去估任何具体模型的步数。** 真实系统的滚动步数要靠实测。

## 2.2 ★★ 三条路线的总览

| | **① 像素派** | **② 潜空间派** | **③ 交互式世界派** |
|---|---|---|---|
| **一句话** | 把未来**画出来** | 只预测**抽象表示**，坚决不画像素 | 像素派 + **实时可玩** |
| **代表** | Genie 3、NVIDIA Cosmos、Sora、GAIA-2 | Dreamer 系列、Meta V-JEPA 2 | Genie 3、Decart Oasis、World Labs |
| **✅ 优势** | 直观；能当仿真器和数据工厂；**人能直接看懂对不对** | 便宜、快；适合做规划和强化学习 | 能拿着手柄真的走进去 ⟹ **天然就是训练智能体的环境** |
| **⚠️ 代价** | 贵；大量算力花在「毛衣的纹理」这种**和决策无关**的细节上 | 人看不见它在想什么，难调试；效果难以直观验证 | 实时性要求极高；**长时间一致性**是最大难点 |

> ⚠️ **①③ 有重叠**：③ 是 ① 里对「实时 + 可操控」有额外要求的一支，不是另起的一条技术路线。所以后面几节比较成本时会把 ① 和 ③ 放一起谈，只在讲一致性时才把 ③ 单拎出来。

### 代表作 A：Genie 3（Google DeepMind）

    ★★ 它【不依赖任何硬编码的物理引擎】—— 物理规律是从视频里学出来的
    ★  每一帧都是【自回归】生成的：根据「世界描述 + 智能体刚才的动作」画下一帧
       ⟹ DeepMind 把它的空间一致性称为一种【涌现能力】
```

## 2.4 ★★ 路线② 潜空间派：坚决不画像素

**这一派的核心论点，是一句很有说服力的反问**：

```
    ⚠️ 「你要预测一个人下一秒会不会摔倒，
         需要先把他毛衣上每一根线的走向都画出来吗？」

    ★★ 不需要。那些像素细节：
       ① 占了模型绝大部分的算力
       ② 而且【本质上不可预测】—— 树叶下一秒往哪边飘，谁也算不准
       ③ 模型为了硬预测这些不可预测的东西，会被逼着学一堆没用的东西
```

> 📖 **JEPA = Joint-Embedding Predictive Architecture，联合嵌入预测架构。**
> Yann LeCun 主推的路线。做法是：**把画面先压成一个抽象向量（潜表示），然后只预测「这个向量在动作之后会变成什么」，全程不还原成图像。**

```
    像素派：   画面(t)  --模型-->  完整画面(t+1)              （几十万个像素值）

    潜空间派： 画面(t)  --编码-->  向量(t)  --模型-->  向量(t+1)  （几百个数）

    ==> ★ 潜空间派【到此为止】：那个 向量(t+1) 【不会】被解码回图像。
```

### ★★ 「便宜」到底便宜多少——把维度算出来

上面那个「几十万个像素值 vs 几百个数」说得很爽，但得算出来才有分量。**沿用 [00 章](00-一个例子讲清关系.md) 第七节那套设定：一帧 256 × 256 的 RGB 图。**

```
    一帧原始 RGB  =  256 x 256 x 3  =  ★ 196,608 个数

    而潜空间派预测的那个向量，量级是【几百维】，这里取 512。

      196,608 / 512 = ★★ 384 倍
```

**但这里有一个必须说破的误导**：⚠️ **「像素派」这个名字会让人以为它在逐像素回归，其实它也不是。** 现代的像素派（Genie、Cosmos、各类视频扩散模型）都先用一个**变分自编码器**把画面压一道，在压缩后的潜码上做预测，最后才解码回图像。所以三档摆出来是这样的：

| 这一档是什么 | 一帧要预测多少个数 | 相对最省的那一档 | 谁在用 |
|---|---|---|---|
| 原始 RGB（256 × 256 × 3） | **196,608** | 384 倍 | ⚠️ **没人真这么干** |
| 📖 **VAE 潜码**：空间压 8 倍、16 个通道 ⟹ 32 × 32 × 16 | **16,384** | **32 倍** | ★ 像素派的真实工作空间 |
| 语义潜向量（量级） | 约 **512** | **1 倍** | ★ 潜空间派 |

> 📖 **VAE = Variational AutoEncoder，变分自编码器。** 一个「压缩-还原」的配对：编码器把图压成一小串数，解码器能从这串数把图还原回来。**关键约束是「必须还原得回去」**，所以它不敢压太狠。

> ★★ **于是两派的分歧可以精确地重述一遍**，这比「画不画像素」准确得多：
> ```
>     像素派：  压缩后【必须还原得回图像】 ==> 只敢压 12 倍（196,608 -> 16,384）
>     潜空间派：压缩后【根本不打算还原】   ==> 敢压 384 倍（196,608 -> 512）
>
>     ==> 真正的分歧不是「有没有压缩」，
>         是【压的时候要不要保住还原图像所需的信息】。
>     ==> ★ 保住它，你就能用肉眼检查模型想得对不对（像素派的优势）；
>         不保住它，你就省下 32 倍的预测量（潜空间派的优势）。
> ```

**再乘上步数，这就是「潜空间派便宜」的具体含义**：

```
    往前滚 50 步（按 00 章那套设定，正好是 1 秒的动作）：

      像素派   16,384 x 50 = 819,200 个数要预测
               ⚠️ 而且每一步还要【解码回图像】才能给 VLA 看
                  —— 多一次 VAE 解码器前向

      潜空间派    512 x 50 =  25,600 个数要预测
               ✅ 全程不解码

    ==> 维度上差 32 倍，再算上解码和扩散的迭代次数，
        真实的算力差会被放大到【三个数量级】。
    ==> 具体一笔 FLOP 账见本章 2.8 节。
```

### 代表作 A：V-JEPA 2（Meta）

```
    ✅ 先用【超过 100 万小时】的互联网视频做自监督预训练
    ✅ 然后只用【62 小时】没有标注的机器人视频，给它加上「动作条件」
    ★★ 结果：在不同实验室的真实机械臂上，零样本抓取放置成功率约 80%
       —— 【没有针对任务做任何训练】
```

> ★ **这个数字对比才是重点**：100 万小时 vs 62 小时。
> ⟹ **绝大部分关于「世界怎么运转」的知识，是从无标注视频里白嫖来的**；
> 机器人数据只用来告诉它「我的动作对应哪种变化」。
> ⚠️ 这正好对着第 01 章那堵「数据墙」开了一个口子：100 万小时无标注视频正好是 [01 章](01-具身智能与VLA.md) 1.5 节那张阶梯表的最上一档，62 小时是最下一档——**这一条结果等于说「最上一档可以替掉最下一档的绝大部分」。**

> ⚠️ **那个「约 80%」要留个心眼**：🔎 论文给的是一组任务（够取 / 抓取 / 取放）**各自**的成功率，彼此差别不小，「80%」是其中较好的一档，不是所有任务的平均；而且真机试验次数不多。⟹ 读之前先过一遍成功率的噪声门槛（`SE ≈ √(p(1−p)/n)`，见 [附-速查表](附-速查表.md) F2 节）。⚠️ 本条未回溯论文原文，具体口径以原文为准。

### 代表作 B：Dreamer 系列（DeepMind）

```
    ★ 这是「在梦里做强化学习」这个说法的源头：
       智能体不在真环境里练，而是在自己学出来的潜空间世界模型里练。

    ✅ Dreamer 4：在 Minecraft 里学会了【挖钻石】——
       这是一个需要 2 万步以上连续正确决策的任务，
       ★★ 而且是【纯离线】学的：训练全程【没有和游戏环境交互过一次】
```

> 🔑 **为什么这条结果对机器人意义重大**：如果一个模型能**只看视频**就学会世界的运转规律、并推断出该怎么行动，那么「仓库导航」「叠衣服」理论上适用同一套范式——**而这意味着不必先摔坏一屋子机器人**。

## 2.5 ★ 两派的正面分歧：到底该不该画像素

这是全篇最值得记住的一处技术对照。**两边都有很硬的道理**：

| | **潜空间派**（LeCun / Dreamer / JEPA） | **像素派**（Genie / Cosmos / WMPO） |
|---|---|---|
| 核心主张 | 像素细节是**浪费**，还**不可预测** | 像素是**唯一能被验证**的东西 |
| 算力 | ✅ 省得多 | ⚠️ 贵 |
| 可调试性 | ⚠️ 看不见它在想什么 | ✅ 生成的视频人眼直接能判断对不对 |
| ★ 和 VLA 接口 | ⚠️ **表示不匹配**：VLA 主干是在**像素图像**上预训练的，潜空间对不上 | ✅ **天然对齐**：想象出来的画面，VLA 直接就能看 |

> ★★ **最后一行是 2026 年一个关键的实践理由**。✅ WMPO 论文（arXiv 2511.09515）明确选择了**像素空间**，理由正是：
> *「许多既有的基于模型的强化学习用潜空间世界模型，这与在富像素图像上预训练的强大 VLA 基础模型之间存在表示失配。」*
>
> ⟹ ⚠️ 换句话说：**潜空间在理论上更优雅，但像素空间更容易接上现成的 VLA。** 这是一次典型的「理论优雅」输给「工程可对接」——⚠️ 这句评价是我的判断，不是论文原话。

## 2.6 路线③ 交互式世界：把世界模型变成一个可以住进去的地方

这一支的野心最大：**不只是预测，而是造一个能让智能体长期生活、练习的环境。**

> ★★ **代表性成果：SIMA 2 × Genie 3（DeepMind，2025-11）**

```
    SIMA 2 = 一个通用的虚拟世界智能体（内核是 Gemini）
    Genie 3 = 一个能凭空生成 3D 世界的世界模型

    ★ 组合起来：
      ① Genie 3 生成一批【从没存在过】的世界
      ② SIMA 2 被扔进去，尝试完成任务
      ③ 用一个 Gemini 做的【奖励模型】给它的表现打分
      ④ 拿打分结果训练自己 ⟹ 回到 ①

    🔎 论文结果：几乎所有训练任务提升 25 分以上，
       而且提升能【迁移到完全不同的测试环境】
       ⚠️ 「25 分」的口径没说清：是【百分点】还是某套 0~100 的评分？
          ★ 不管哪种，它都【不等于】「提升 25%」——
            成功率 40% 涨到 65% 是涨了 25 个【百分点】，
            相对提升却有 62%。这两个数差了一倍半。
```

> 🔑 Demis Hassabis 管这个循环叫「**无限训练循环**」（Infinite Training Loop）：
> **AI 生成世界 → AI 在里面练 → 练出更强的 AI → 再生成更难的世界。**
>
> ⚠️ **但要泼一盆冷水**（✅ DeepMind 自己也承认）：目前动作空间**很有限**；而且有研究者直接质疑——**游戏画面是给人看的、本来就好懂，真实世界的摄像头画面难得多，能迁移多少是未知数。**

### ③ 这一支的硬指标：实时性和一致性，都能换成数字

路线③ 比路线① 多扛两条要求，**而这两条都可以写成数**：

| 要求 | 换成数字是什么 | 现状 |
|---|---|---|
| **实时** | 24 帧每秒 ⟹ **每帧必须在 1 ÷ 24 = 41.7 ms 内出来**，而且是**每一帧都不能超时**，不是平均够快就行 | ✅ Genie 3 做到了 720p / 24 fps |
| **长时间一致** | 2.1 节那个「能滚多少步」：按 24 fps 换算，🔎 Genie 2 的 10~20 秒 = **240~480 帧**；Genie 3 的「好几分钟」按 3 分钟算 = **4,320 帧** ⟹ **跨了约 9~18 倍** | ★ 这是量级跨越，但见下面那条警告 |

> ⚠️ **「能滚 4,320 帧」和「能滚 4,320 步还物理正确」是两个指标，千万别当成一个。**
> ```
>     前者衡量的是：画面有没有闪、物体有没有凭空消失、走回头路认不认得原来的房间
>     后者衡量的是：在里面做出的决策，拿到真实世界还成不成立
>
>     ==> ★★ Genie 3 公开的是【前者】。后者目前没有公认的度量方式，
>         这正是 2.7 节硬伤三。
>     ⚠️ 所以不能把「保持几分钟一致」直接读成
>        「可以在里面滚几千步做强化学习」—— 那是两回事。
> ```

---

## 2.7 ⚠️ 世界模型自己的三个硬伤

```
    ⚠️ 硬伤一：画面对，不代表物理对
       生成的视频看起来很真，但可能出现「物理上假的」现象
       （水穿过杯壁、物体凭空消失）。⟹ 而机器人恰恰要靠物理关系做决策。

    ⚠️ 硬伤二：只会响应【见过的动作】
       世界模型也是从数据里学的，你给它一个训练数据里从没出现过的动作，
       它给出的未来往往是瞎编的。
       ★★ 而强化学习恰恰要靠【尝试没做过的动作】才能改进 —— 这是个死结。

    ⚠️ 硬伤三：怎么评价一个世界模型好不好，本身就没有共识
       视频质量指标（FID、FVD 那些）衡量的是【好不好看】，
       不是【物理对不对】、更不是【拿去训练策略有没有用】。
```

## 2.8 ⚠️ 三条路线的推理成本，放到同一个口径上

前面几节反复说「像素派贵、潜空间派省」，这一节把它变成一笔**能自己验算的账**。

> ⚠️⚠️ **先声明：整节是示意推演，不是实测。** 每一行的假设都写在表里，换一组假设结论会变。**它要回答的只有一个问题：这三条路线的成本差，是差一倍、差十倍，还是差一千倍？**

**统一口径**：往前推演**一步**要多少浮点运算（FLOP）、在一张 H100 上要多少毫秒。用的近似公式只有一条：

```
    一次 Transformer 前向的 FLOP  ≈  2 x 参数量 x token 数

    （这个「2」已经把一次乘法 + 一次加法算进去了。
      📖 FLOP = Floating-point OPeration，浮点运算次数。）
```

| 逐步算 | **① 像素派** | **② 潜空间派** | **③ 交互式世界** |
|---|---|---|---|
| ① 一步预测的是什么 | 一帧画面的 VAE 潜码<br>32 × 32 × 16 = 16,384 个数 | 一个语义潜向量<br>约 512 个数 | 同 ① |
| ② 折合多少个 token | 32 × 32 = **1,024** 个 | ⚠️ 量级 **64** 个 | 1,024 个 |
| ③ 模型规模（⚠️ 量级估） | **10⁹** 参数的扩散 Transformer | **10⁸** 参数的预测器 | 同 ①，但专门为实时做过裁剪 |
| ④ 单次前向 FLOP = 2 × ③ × ② | 2 × 10⁹ × 1,024 = **2.05 TFLOP** | 2 × 10⁸ × 64 = **0.013 TFLOP** | 2.05 TFLOP |
| ⑤ 一步要跑几次前向 | ⚠️ 扩散去噪 **20~50 次** | ★ **1 次** | ⚠️ 蒸馏后降到 **1~4 次** |
| ⑥ **一步合计 = ④ × ⑤** | 2.05 × 20 = **41 TFLOP** | **0.013 TFLOP** | 2.05 × 4 = **8.2 TFLOP** |
| ⑦ **相对②的倍数** | ⚠️ **约 3,200 倍** | **1 倍** | 约 640 倍 |
| ⑧ 在 H100 上要多久<br>（按实现算力 300 TFLOPS 估） | 41 ÷ 300 = **137 ms** | 0.013 ÷ 300 = 0.04 ms<br>⚠️ 这个尺度上已经不是算力受限了，实测会落在**亚毫秒到几毫秒** | 8.2 ÷ 300 = **27 ms** |
| ⑨ 还要不要解码回图像 | ⚠️ 要（多一次 VAE 解码器前向） | ✅ 不要 | ⚠️ 要 |

> ★★ **第 ⑦ 行是这一节的结论**：两派的成本差是**三个数量级**，不是几倍。而这三个数量级来自**两处相乘**——
> ```
>     token 数     1,024 / 64       =  16 倍
>     模型规模     10^9 / 10^8      =  10 倍
>     迭代次数     20 次 / 1 次     =  20 倍
>                                      --------
>     连乘         16 x 10 x 20     =  3,200 倍
>
>     ==> ★ 「三个数量级」不是某一项造成的，是三件事【连乘】出来的。
>     ==> 所以指望靠单项优化把它抹平是不现实的：
>         哪怕把去噪步数从 20 砍到 1（已经是最激进的蒸馏），
>         也还剩 16 x 10 = 160 倍。
> ```

**现在把它和控制周期并排放**，这才是这笔账的用处所在：

```
    00 章第七节那个例子里，控制器每 20 ms 要一条指令。

      像素派一步 137 ms  ==>  137 / 20 = ★ 超预算 约 7 倍
      交互式一步  27 ms  ==>  仍然超预算
      潜空间一步 亚毫秒~几毫秒  ==>  ★★ 唯一塞得进去的

    ==> 这就是 03 章 3.3 节「前瞻模块」那盆冷水的来源：
        不是工程没做好，是三个数量级的差距摆在那儿。
    ==> ★ 同时也解释了为什么【数据工厂】和【想象中做 RL】
        反而是像素派的主场 —— 那两种用法都【离线】，
        没有 20 ms 这个紧箍咒，慢一点无所谓。
```

> ⚠️ **一条必须补上的反例**：✅ Genie 3 实打实做到了 720p / 24 fps，也就是 **41.7 ms 一帧**，比上表给像素派估的 137 ms 快得多。⟹ 说明 137 ms 是「**拿通用做法在一张卡上**」的量级，**不是物理上限**：少步数蒸馏、专用加速器、并行流水，都能把它压下来。★ 但请注意 Genie 3 在那 41.7 ms 里**只在画画，并没有同时跑一个策略模型**——而前瞻模块需要的是「画完还要拿去评估并做决策」。**两件事的预算不是一回事。**

> 🔑 **这一节带走一句话**：像素派和潜空间派的成本差是**三个数量级**，所以它们不是在争同一块地盘——**离线的活（造数据、在想象里练）归像素派，在线的活（每一步都要用）归潜空间派。** ⟹ [03 章](03-两者如何结合.md)那四种结合方式，分界线正好画在这里。

## 🔑 本章一句话

> 世界模型有三条路：**画像素**（直观、能当仿真器、但贵）、**不画像素只预测抽象表示**（省、优雅、但难调试且接不上 VLA）、**造一个能住进去的交互世界**（野心最大、也最不成熟）。
> ⚠️ **三条路都还没解决同一个根本问题：「预测得好看」和「预测得物理正确」是两回事。**
>
> ★ **本章要带走的三个数**：一帧 256 × 256 的 RGB 是 **196,608** 个数，像素派实际在 **16,384** 维的 VAE 潜码上预测，潜空间派只预测约 **512** 维 ⟹ 推理成本差**三个数量级**（2.4 / 2.8 节）；误差一旦被放大（λ = 1.1、单步 1%），**14 步**就崩，而且单步精度每提高 10 倍只能多滚**二十几步**（2.1 节）；路线③ 的硬门槛是每帧 **41.7 ms**（2.6 节）。
