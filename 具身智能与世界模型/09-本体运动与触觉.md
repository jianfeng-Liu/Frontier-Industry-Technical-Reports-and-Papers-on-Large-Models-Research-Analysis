# 09 被忽略的半壁江山：本体、运动与触觉

> 前面八章讲的几乎全是「大脑」。但具身智能有**两拨人**，
> 而且这两拨人的技术栈**几乎不重叠**，最近才开始合流。
> ★★ 不知道这件事，就会对「为什么机器人后空翻已经很溜、但叠衣服还不行」感到莫名其妙。

---

**本章关键词**（每个词在正文第一次出现时还会再解释一遍）

**本体感受**（proprioception，也译本体感觉）—— 身体对自己状态的感知：关节角度、关节速度、姿态。闭上眼睛也知道手举多高，靠的就是它。
**IMU**（Inertial Measurement Unit，惯性测量单元）—— 陀螺仪 + 加速度计，测姿态和角速度。
**Sim2Real**（simulation to reality，仿真到真实）—— 把仿真器里练好的策略搬到真机上。
**域随机化**（domain randomization）—— 训练时把物理参数随机乱调，逼出一个对参数不敏感的策略。
**执行器**（actuator）—— 机器人的「肌肉」：电机 + 减速器 + 驱动器。
**带宽**（bandwidth）—— 一个环节「跟得上多快的变化」。这是本章后半最关键的一个词。
**视触觉传感器**（vision-based tactile sensor）—— 用摄像头拍软胶形变来测接触，**GelSight**、**DIGIT** 是两个代表。
**六维力 / 力矩传感器**（six-axis force/torque sensor）—— 测三个方向的力 + 三个方向的力矩，一共六个数。
**压阻式 / 电容式 / 压电式**（piezoresistive / capacitive / piezoelectric）—— 三类把压力变成电信号的传统触觉方案。
**相位裕度**（phase margin）—— 一个控制系统离「振起来」还剩多少余量，单位是度。

## 9.1 ★★ 两拨人，两套完全不同的方法论

| | **运动派**（locomotion，全身控制） | **操作派**（manipulation） |
|---|---|---|
| **出身** | 机器人控制 + 强化学习 | 大模型 / 计算机视觉 |
| **任务** | 走、跑、跳、被推了不摔、上楼梯、后空翻 | 抓、放、倒水、叠衣服、听指令干活 |
| **做法** | ★ 在**仿真器**里用强化学习练几十亿步，再零样本搬到真机 | ★ 收集**真机遥操作数据**做模仿学习（VLA） |
| **现状** | ✅ 已经相当成熟 —— 宇树、波士顿动力的炫技视频基本都出自这条路线 | ⚠️ 泛化能力还很弱（[01 章](01-具身智能与VLA.md)的四堵墙） |
| **数据从哪来** | ★ 仿真器**凭空造**，边际成本≈0 | ⚠️ 真人一条条**遥操作采**，边际成本极高 |

> ★★ **于是有了这一章真正要回答的问题**：同样是控制一副身体，**为什么走路能在仿真里练成，抓取却不行？**

### 答案：Sim2Real 鸿沟在**不同的感知通道上大小完全不同**

```
    走路主要依赖【本体感受】：
      📖 本体感受 proprioception：关节角度、关节速度、
         IMU（陀螺仪+加速度计）测出的姿态
      ⟹ ★★ 这些量在仿真和真实里【几乎一模一样】。
         一个关节转了 30 度，仿真里是 30 度，真机上也是 30 度。
         ⟹ Sim2Real 鸿沟极小。

    抓取主要依赖【视觉】：
      ⟹ 仿真渲染出来的图和真实摄像头的图差得很远
         （光照、材质、噪点、运动模糊）
      ⟹ ★★ Sim2Real 鸿沟极大。

    ★★★ 这一条是整章最重要的一句话：
        【能不能靠仿真练成，取决于你依赖哪个感知通道】。
    ⟹ 也正因如此，第 06 章那招「仿真器管物理、世界模型换皮肤」
       才显得如此关键 —— 它正是在补视觉这一个通道的鸿沟。
```

### 运动派的标准配方

```
    ① 大规模并行仿真（一张 GPU 几千个机器人同时练）
    ② 用 PPO 之类的强化学习算法练
    ③ 📖 域随机化 domain randomization：
       训练时把摩擦、质量、延迟、地面硬度【随机乱调】，
       逼模型学出一个在各种参数下都能站稳的策略
       ⟹ 真机的参数落在随机范围里，于是就直接能用
    ④ 📖 教师-学生蒸馏：
       先训一个能看到【特权信息】（§6.1）的「教师」，
       再让只能看到真实传感器的「学生」去模仿它
       ⟹ 因为真机上读不到地面摩擦系数，但仿真里读得到
```

### 把 Sim2Real 鸿沟量化一下：为什么本体感受过得去，视觉过不去

上面说「本体感受的鸿沟小、视觉的鸿沟大」。再往下追一层会发现，原因非常具体：**这两个通道的「差异」，能不能写成几个可以随机的数。**

| | **本体感受通道** | **视觉通道** |
|---|---|---|
| 仿真和真实差在哪 | 模型参数不准（质量、摩擦、延迟、电机常数） | 整个成像过程都不一样 |
| 这个差异能不能用少数几个数描述 | ✅ 能，十几到几十个标量就覆盖了 | ❌ 不能 —— 光照、材质、噪点、运动模糊、镜头畸变……写不完 |
| 域随机化管不管用 | ✅ 把那几个数抽着练就行 | ⚠️ 只能随机颜色 / 贴图 / 光照，覆盖不到真实分布 |
| 真机上量到的是什么 | 关节编码器，⚠️ 分辨率可到 0.01° 量级，几乎不受环境影响 | 相机，受光照、反光、运动模糊影响极大 |
| ⟹ 结果 | 鸿沟小，**零样本能过** | 鸿沟大，**零样本过不去** |

具体到域随机化在随机什么，一张示意表就清楚了（⚠️ 范围是示意量级，不同本体差别很大，不要当成某篇论文的配置）：

| 被随机的量 | 示意范围 | 为什么要随机它 |
|---|---|---|
| 连杆质量 | ×0.8 ~ ×1.2 | 真机装了电池、外壳、线束，和 CAD 图不一样 |
| 地面摩擦系数 | 0.3 ~ 1.2 | 瓷砖、地毯、草地差别很大 |
| 执行器力矩上限 | ×0.8 ~ ×1.2 | 电机发热之后出力会掉 |
| 观测延迟 | 0 ~ 20 ms | 通信和滤波带来的滞后 |
| 关节零位偏置 | ±1° ~ ±3° | 装配误差 |
| 随机外推力 | 随机时刻、随机方向 | 逼出「被推了不摔」 |

⟹ ★★ **于是「能不能靠仿真练成」可以改写成一句更锋利的话**：**仿真和真实的差，能不能写成一组可以随机的参数？** 走路能 —— 就上面这六行；抓取不能 —— 没有人写得出一组参数，抽一抽就把「真实厨房里所有的光照和材质」覆盖掉。

⟹ 这也正好解释了 [06 章](06-仿真器与世界模型.md)那招「仿真器管物理、世界模型换皮肤」为什么对症：它根本不去参数化视觉差异，而是**直接拿真实视频训出来的生成模型去补那一层皮**。

## 9.2 触觉：视觉根本看不见的那一半

```
    ★ 想一想这几件事，闭上眼睛你也能做，但光看【是看不出来的】：
       ▸ 插 USB —— 有没有对准，是【感觉】出来的
       ▸ 拧螺丝 —— 有没有滑丝，是【手感】
       ▸ 抓鸡蛋 —— 用多大力，靠的是【要滑了】这个信号
       ▸ 从一叠布里抽一层 —— 抓到了几层，眼睛看不出来

    ⟹ ★★ 这些任务里，【关键状态量根本不在画面里】。
       无论视觉模型多强，它都拿不到这个信息。

    主要传感器路线：
      ▸ 📖 视触觉传感器（GelSight / DIGIT 一类）：
        在指尖贴一层软胶，胶里装一个小摄像头，
        通过胶的形变【拍出】接触的形状和滑动
        ⟹ 巧妙之处：把触觉问题转成了视觉问题
      ▸ 📖 六维力/力矩传感器：
        装在手腕，测三个方向的力 + 三个方向的力矩
        ⟹ 🔎 §4.3 提到高端六维力传感器仍依赖进口，就是这个东西

    ⚠️ 触觉最大的困难：【没有 ImageNet】
       每家的触觉传感器原理不同、数据格式不同、不能互通，
       ⟹ 于是无法形成像视觉那样的大规模通用预训练数据。
          这也是触觉进展远慢于视觉的根本原因。
```

### 四条触觉路线，放进同一个口径

| | **压阻式**<br>piezoresistive | **电容式**<br>capacitive | **压电式**<br>piezoelectric | **视触觉**<br>GelSight / DIGIT 一类 | **六维力/力矩**<br>装在手腕 |
|---|---|---|---|---|---|
| **原理** | 受压电阻变 | 受压极板间距变、电容变 | 受**变化的**力产生电荷 | 摄像头拍软胶的形变 | 应变片测整体受力 |
| **空间分辨率** | ⚠️ 毫米级（阵列间距 1~5 mm） | ⚠️ 毫米级 | ❌ 基本没有（单点） | ★ 极高，⚠️ 可到几十微米量级 | ❌ 没有，整只手一个合力 |
| **频率（时间分辨率）** | ⚠️ 100 Hz ~ 1 kHz | ⚠️ 百 Hz ~ kHz | ★ 最高，kHz 以上 | ⚠️ 受相机限制，常见 30~60 fps | ★ 约 1 kHz |
| **能测什么** | 法向压力的**分布** | 法向压力；部分方案能解**剪切** | **只测变化**：振动、冲击、打滑 | 接触**形状**、**纹理**、**剪切**（看胶面标记点位移） | 3 个力 + 3 个力矩 |
| **测不到什么** | ❌ 剪切力、纹理 | ⚠️ 静态漂移、温漂 | ❌ **静态压力**（手不动就没信号） | ⚠️ 绝对力值要标定；胶会磨损 | ❌ 接触在哪、接触了几个点 |
| **成本量级** | ✅ 最低 | ✅ 低 ~ 中 | ✅ 低 | ⚠️ 中（相机 + 胶 + 灯，多为手工件） | ❌ 最高，⚠️ 高端仍依赖进口 |

⚠️ 表里的分辨率、频率、成本都是**公开资料里的典型量级**，不是某个具体型号的参数 —— 同一类方案不同厂家能差一个数量级。⚠️ 另外「视触觉能测剪切」说的是**能看出切向位移**，要换算成准确的剪切力仍然需要标定。

#### 把数据量级也算出来：从头到尾差了一千倍

这张表里最容易被忽略的一列是**数据量**。算一下就知道触觉的工程味道为什么这么重：

```
  六维力/力矩传感器
    6 个数 x 4 字节 x 1000 Hz = 24 KB/s

  16 x 16 压阻阵列
    256 个点 x 2 字节 x 1000 Hz = 512 KB/s            (约 21 倍)

  视触觉（640 x 480 RGB，30 fps）
    640 x 480 x 3 = 921600 字节/帧 = 0.92 MB
    0.92 MB x 30 = 27.6 MB/s                          (约 1150 倍)
```

⟹ ★ **从六维力到视触觉，数据率差了一千倍以上**，而且视触觉那一千倍里绝大部分是「胶面照片」这种**还得再跑一个视觉模型才能变成有用信息**的原始数据。⟹ 这就是为什么视触觉在实验室里很好用、上真机却立刻撞上带宽和功耗：十根手指同时开，就是 276 MB/s。

#### ★ 一个被忽略的矛盾：没有一种传感器同时拿到高空间分辨率和高频率

```
    检测【打滑】需要什么？ —— 高【时间】分辨率。
      打滑是在几毫秒到几十毫秒内发生的，要抓住它至少要几百 Hz。

    检测【纹理 / 接触形状】需要什么？ —— 高【空间】分辨率。

    ==> 可现有方案是这么分布的：
        压电式      时间分辨率最高，空间分辨率几乎没有
        视触觉      空间分辨率最高，时间分辨率最低（30~60 fps）
        压阻/电容   两头都中等
        六维力      频率高，但完全没有空间分辨率

    ==> ★★ 没有一种方案三样都拿（高空间 + 高时间 + 低成本）。
```

⚠️ **所以「GelSight 分辨率高，所以它能检测打滑」是一句说反的话**：它的分辨率高是**空间**上的，而打滑是**时间**现象。30~60 fps 意味着两帧之间隔了 16~33 毫秒 —— 一次打滑完全可能整个发生在两帧之间。⟹ 实践中常见的做法是**两种通道并用**（视触觉看形状、压电或其它高频通道抓打滑），这正是 §9.3 那个「灵巧手不可能三角」在传感器一侧的翻版。

### ⚠️⚠️ 触觉真正的难点：同一件事在不同传感器上「长得完全不一样」

上面那句「没有 ImageNet」值得展开，因为它经常被理解成「触觉数据少」。**不是少，是不能合并。**

先看一个具体例子。同一个物理事件：**手里捏着一个鸡蛋，鸡蛋轻微下滑了 0.3 毫米。** 三种传感器各自记下了什么（⚠️ 数值为示意）：

| 传感器 | 它记下的是什么 | 数据长什么样 |
|---|---|---|
| 16×16 压阻阵列 | 一张压力分布图，中心几个点从 3.2 N 掉到 2.8 N | `256` 个标量，单位牛顿 |
| 视触觉（GelSight 一类） | 胶面上的黑色标记点整体平移了约 0.3 mm | 一张 `640×480×3` 的 RGB 图 |
| 六维力 / 力矩 | Fz 从 3.2 N 降到 2.8 N，Mx 变了约 0.01 N·m | `6` 个标量，三个牛顿、三个牛顿·米 |

⟹ ★★ **同一个物理事件，三份数据没有任何一个公共字段**：维度不同（256 / 921600 / 6）、物理量不同（压力 / 像素亮度 / 力与力矩）、量纲不同（N / 无量纲 / N 与 N·m）、采样率也不同。⟹ 这才是「不可迁移」的字面意思 —— 不是「分布有点差异」，是**连数据是什么形状都不一样**。

#### 和视觉、语言对照一下，差别就刺眼了

| | **视觉** | **语言** | **触觉** |
|---|---|---|---|
| 有没有通用的「容器」 | ✅ `H×W×3` 的 RGB 数组 | ✅ token 序列 | ❌ **没有** |
| 换一台采集设备会怎样 | 还是 RGB 图，分辨率和色调略变 | 还是 token | **形状、物理量、量纲全变** |
| 不同设备的数据能不能喂同一个模型 | ✅ 能 | ✅ 能 | ❌ 不能 |
| 同一台设备、隔半年再采 | ✅ 基本稳定 | ✅ 稳定 | ⚠️ **会漂** —— 胶体磨损、温漂、重新标定 |
| 有没有 ImageNet 级别的公共数据 | ✅ 有 | ✅ 有（整个互联网） | ❌ 没有 |
| ⟹ 能不能做基础模型 | ✅ 已经做成了 | ✅ 已经做成了 | ❌ **前提就不成立** |

⟹ ★★★ **这一行对照解释了一个常被问起的问题：为什么触觉至今没有「基础模型」。** 基础模型的前提是「**海量来源不同的数据，能装进同一个表示里**」。视觉和语言天然满足 —— 一张图不管谁拍的还是一张图，一句话不管谁说的还是一串 token。触觉**不满足这个前提**，所以它缺的不是算力也不是热情，是那个**容器**。

⚠️ 更麻烦的是最后那条「跨时间也会漂」：视触觉的软胶会磨损、会被硌出印子，用几个月后**同一个传感器自己的数据分布都变了**。⟹ 于是触觉工作事实上每一篇都在自己那套硬件上自建数据集，规模常常只有几千条，而且换一个实验室基本不可复现。

#### ⟹ 那出路可能在哪？（⚠️ 以下是我的判断，不是业界共识）

```
    ① 统一到【物理量】，而不是原始读数
         不存「这个传感器读到 2.8」，存「接触点在哪、法向力多少、剪切力多少」
         ✅ 这样不同硬件才可能对齐
         ⚠️ 代价：每个传感器都要精确标定，而标定本身很贵

    ② 蹭视觉骨干：把触觉变成图像
         这正是视触觉路线被低估的价值 —— 它的输出本来就是一张图，
         ✅ 能直接复用海量视觉预训练
         ⚠️ 但也只在「视触觉」这一个家族内部通用

    ③ 多传感器同步采集，学一个跨传感器的共同表示
         同一次接触，用好几种传感器同时测
         ⚠️ 采集成本比单一传感器还高一个量级
```

⟹ 🔑 **一个可以直接用的判断标准**：以后看到任何自称「触觉基础模型」的工作，第一个该问的不是它有多大，而是 ★ **它在几种硬件上训的、能不能换一种传感器直接用**。如果答案是「只在我们自己这一款上」，那它是一个**不错的专用模型**，不是基础模型。

## 9.3 硬件：为什么「算法不是瓶颈」

承接 §4.3 的成本结构：

```
    ▸ 📖 执行器 actuator：机器人的「肌肉」。
      人形机器人常用【无框力矩电机 + 谐波减速器 / 行星滚柱丝杠】。
      ⚠️ 难点不是造得出来，是【一致性和寿命】——
         几十个关节，任何一个先坏，整机就停。

    ▸ 📖 灵巧手：★ 存在一个不可能三角：
         【自由度多】↔【可靠耐用】↔【成本可控】
         三者目前只能取二。
      ⟹ 这就是为什么很多商用方案宁可用【两指夹爪】——
         够用、便宜、几乎不坏。

    ★ 一个值得记住的对照：
      算法出了错，重训一次就好；
      ⚠️ 硬件出了错，是【几十万台的召回】。
      ⟹ 产业界对硬件的保守，是理性的，不是不思进取。
```

### ★★ 控制频率阶梯：理解整个具身栈的钥匙

上面说「硬件不是瓶颈但硬件说了算」，背后有一个很具体的原因：**这一摞东西不是跑在同一个时间尺度上的。** 把各层的频率并排摆出来，很多看起来是工程口味的设计，就变成了没得选的结论：

| 层 | 做什么 | 频率 | 周期 | 谁来做 | 这一层崩了会怎样 |
|---|---|---|---|---|---|
| **高层规划** | 理解指令、拆任务、决定「下一步干什么」 | ⚠️ 约 **1~10 Hz** | **100 ms ~ 1 s** | 视觉语言大模型（VLM） | 任务做错 —— 去拿了错的东西 |
| **轨迹生成** | 把「去抓杯把」变成一串目标位姿 | ⚠️ 约 **10~100 Hz** | **10 ~ 100 ms** | 小策略网络 / 运动规划器 | 动作笨拙、撞到东西 |
| **关节控制** | 把目标位姿变成每个电机的电流 | ⚠️ 约 **200~1000 Hz** | ★ **1 ~ 5 ms** | 传统控制器（PID / 阻抗控制），**跑在实时系统上** | ★★ **机器人物理上失稳** —— 摔倒、抖动、烧电机 |

```
    ★★ 关键不在每一层【多快】，而在相邻两层【差多少】：

      高层规划  ~  5 Hz    (200 ms)
                    |
                    |  差 10~20 倍
                    v
      轨迹生成  ~  50 Hz   ( 20 ms)
                    |
                    |  差 10~20 倍
                    v
      关节控制  ~ 500 Hz   (  2 ms)

    ⟹ 从上到下跨了【两到三个数量级】。
```

> ★★ **这就是为什么大模型「管不到」最后这一层。** 一次 VLM 前向要几十到几百毫秒，而关节控制环每 **2 毫秒**就要出一次结果 —— 中间差了**一百倍**。不是模型不够聪明，是**它根本来不及说话**。[01 章](01-具身智能与VLA.md) 那个 System 2 / System 1 的快慢双脑，就是这个阶梯在模型侧的投影（7~9 Hz 对 200 Hz，差 25 倍）。
>
> ⚠️ 表里的频率都是**典型量级**，换个本体、换个任务会差很多（轮式底盘比人形宽松得多），要记的是**层与层之间差一到两个数量级**这个结构，不是具体数字。
>
> ★ **一个有用的推论**：你听到某个方案说「我们用端到端大模型直接输出关节指令」时，第一个该问的是 —— **它跑多少 Hz？** 如果答案是几十 Hz 或更低，那它要么接了一个底层控制器（那就不是真端到端），要么只能用在对失稳不敏感的本体上。

### 频率阶梯还有看不见的两级：电流环，和执行器的机械带宽

上面那张表停在「关节控制 200~1000 Hz」。但这还不是最底层 —— 再往下还有两级，而且**其中一级的数字会让人意外**：

| 层 | 频率量级 | 谁在跑 | 说明 |
|---|---|---|---|
| 关节控制环 | ⚠️ 200~1000 Hz | 实时控制器 | 就是上表的最后一行 |
| **电流环 / 换向** | ⚠️ 10~20 kHz | 电机驱动器内部 | 比控制环还快一到两个数量级，通常对上层完全透明 |
| **执行器的机械带宽** | ★★ ⚠️ **只有几十 Hz** | 物理世界 | 电机 + 减速器 + 连杆真正「跟得上」的指令变化速度 |

```
    ★★ 注意最后一行的方向：

       机械带宽 (几十 Hz)   【低于】   控制环频率 (几百到上千 Hz)
                                         ^
                                         |
       这不是矛盾，而是控制系统的常识：
       采样和反馈必须【远快于】被控对象，才控得稳。
       经验法则：控制环频率取被控对象带宽的 5~20 倍。
       (采样定理那个「2 倍」只保证不混叠，不保证控得稳 —— 两件事别混。)
```

⟹ ★★ **这就是「执行器带宽决定控制频率上限」的准确含义**：不是「执行器限制了控制环能跑多快」，而是反过来 —— **执行器带宽决定了这套系统真正能响应多快的指令变化，而控制环频率必须是它的若干倍才控得稳。把控制环从 1 kHz 提到 10 kHz，机器人不会因此快一点。** 指令里高于机械带宽的那部分成分，会被机械系统自己低通掉（运气不好还会激起共振）。

#### 为什么机械带宽这么低：纯延迟吃掉的相位，可以算出来

带宽被三样东西限制：**机械柔性**（谐波减速器的柔轮本来就是弹性件，⚠️ 关节一阶共振常在几十 Hz 量级）、**传动间隙**，以及**纯延迟**（通信周期、电流环、PWM、滤波）。前两样要改硬件，最后一样可以直接算：

```
    纯延迟 tau 在频率 f 处带来的相位滞后：

        相位滞后(度) = 360 x f x tau
```

| 纯延迟 τ | 在 10 Hz 处 | 在 50 Hz 处 | 在 100 Hz 处 |
|---|---|---|---|
| 1 ms | 3.6° | 18° | 36° |
| 2 ms | 7.2° | 36° | 72° |
| 5 ms | 18° | 90° | ⚠️ 180°（完全反相） |
| 20 ms | 72° | ⚠️ 360°（整整绕一圈） | — |

> 📖 **相位裕度**（phase margin）—— 控制系统离「振荡发散」还剩多少余量，工程上通常要留 **30°~60°**。⟹ 对着上表读：**一个 5 ms 的纯延迟，到 50 Hz 就已经吃掉 90°**，裕度早就没了。⟹ 于是这个环的带宽基本被封死在几十赫兹，**和算法好不好完全无关**。

⟹ ⚠️ **所以一句很常见的话其实是错的**：「我们的控制频率是 1 kHz，所以响应时间是 1 毫秒。」❌ —— 1 kHz 只是「每 1 毫秒问一次」，末端真正跟上一个新目标要几十毫秒。**采样周期不是响应时间。**

#### 把大模型放进这笔账：它慢的不是「一点」，是一个数量级

```
    VLM 一次前向 ~ 200 ms  ==> 相当于每 200 ms 才给一条新指令 (5 Hz)
    一个机械带宽 50 Hz 的关节，其「可响应周期」 = 1 / 50 = 20 ms

    ==> 200 ms / 20 ms = ★ 10
        身体每能响应 10 次，大模型才说得上一句话。
```

⟹ 这给上面那条「先问它跑多少 Hz」的判据补了后半句：★ 光问控制频率还不够，再问三个 —— ① **执行器的带宽 / 关节一阶共振在哪？** ② **从传感器读数到力矩输出的纯延迟是多少毫秒？** ③ **控制环跑在实时系统上，还是 Linux 用户态？** ⟹ 这三个问题比「我们用了多大的模型」更能看出一个团队的成色。

⚠️ 本小节的频率、共振、带宽数字都是**控制工程的常见量级**，不是哪款产品的实测值；而 `相位滞后 = 360 × f × τ` 和「控制环取被控对象带宽 5~20 倍」是标准结论，可以自己验算 —— 但具体机器的数，要看具体机器。

## 9.4 ★★ 这半壁江山对「世界模型」意味着什么

这是本章最需要带走的一点，也是对第 02 章那场路线之争的一个**新角度**：

```
    世界模型预测的是【像素】（像素派）或【视觉潜表征】（潜空间派）。

    ⚠️ 但机器人真正需要预测的，常常是：
         ▸ 这个接触点会不会【打滑】？
         ▸ 我再用力一点会不会【捏碎】？
         ▸ 这个插头【对准】了没有？

    ★★ 这些量在画面里【几乎不可见】。
       杯子滑了 0.5 毫米，画面上可能一个像素都没变，
       但对任务来说这是成败的分水岭。

    ⟹ 这构成了对像素派最深的一个质疑：
       【你预测的这个空间里，可能根本不包含决策所需的信息。】

    ⚠️ 而这个质疑，恰恰和 §2.4 潜空间派的主张【殊途同归】：
       重要的不是画面，是画面背后那些决定成败的量。
       ★ 只不过 JEPA 说的是「像素里有太多无关信息」，
         触觉这边说的是「像素里【缺少】关键信息」。
       ⟹ 两个方向的批评，指向同一个结论：
          【视觉空间既冗余又不完整。】
```


### 顺带把 §9.2 的结论接过来：这里卡住的不止是数据，还有「该预测什么」

下面马上会说到「世界模型该不该预测触觉」，答案卡在没有数据。但 §9.2 那张对照表说明，**前面还有一层更早的卡点**：

```
    想让世界模型预测触觉，先得回答一个问题：
      【预测哪一种触觉？】

      预测 16x16 的压力阵列？    ==> 换一只手就作废
      预测 GelSight 的胶面图？   ==> 换一款传感器就作废
      预测 6 维力？              ==> 丢掉了「接触在哪、接触了几个点」

    ==> ★★ 视觉之所以能被预测，是因为「下一帧 RGB 图」是一个
        【所有人都认的预测目标】。触觉连这个目标都还没有。
```

⟹ 🔑 所以更准确的说法是：**触觉世界模型卡在两层** —— 外层是数据不够（§9.2），内层是**连「该预测什么」都还没有共识**。⚠️ 而内层这一条，比外层更难靠砸钱解决。

> 🔑 **顺着这个思路，一个自然的问题是**：世界模型该不该也预测**触觉和力**？
> ⚠️ 目前几乎没有工作这么做——**因为没有大规模的触觉数据（§9.2）**。
> ⟹ 这是一个数据瓶颈直接卡死了一整个研究方向的典型例子。

## 9.5 ⚠️ 这一章最容易说反的四句话

> ⚠️ 下面四条都是我在读资料时实际见过的说法，每一条都差一个关键的字。

| 常见说法 | 错在哪 | 该怎么说 |
|---|---|---|
| 「控制频率 1 kHz，所以响应时间 1 ms」 | 把**采样周期**当成了**响应时间** | 1 kHz 只是「每 1 ms 问一次」；末端跟上一个新目标要几十 ms，由机械带宽决定（§9.3） |
| 「GelSight 分辨率高，所以能检测打滑」 | 把**空间**分辨率当成了**时间**分辨率 | 打滑是毫秒级的时间现象；30~60 fps 的相机，一次打滑可能整个发生在两帧之间（§9.2） |
| 「触觉数据少，多采一点就好了」 | 把**不可合并**当成了**量不够** | 不同传感器的数据连形状都不一样，各采各的不会汇成一个大数据集（§9.2） |
| 「成功率从 50% 提到 60%，提升了 10%」 | 混了**百分点**和**百分比** | 涨了 **10 个百分点**；写成「提升 10%」会被读成 50% → 55%，差一倍 |

⚠️ 还有一个同类的坑，在机器人 demo 的宣传语里最常见：**「周期时间减少 60%」不等于「快了 60%」** —— 加速倍数 = `1 / (1 − 0.6)` = **2.5 倍**。完整版见 [附-速查表](附-速查表.md) §F4。

### 以及一条对这一章特别要紧的：成功率的噪声门槛

```
    成功率的标准误      SE = sqrt( p(1-p) / n )

      n = 20,  p = 0.5  ==>  SE = sqrt(0.25/20)  =  11.2 个百分点  ★★
      n = 50,  p = 0.5  ==>  SE = sqrt(0.25/50)  =   7.1 个百分点
      n = 100, p = 0.5  ==>  SE = sqrt(0.25/100) =   5.0 个百分点

    ==> ★★ 「20 次里成功 12 次 vs 成功 10 次」(60% vs 50%)
        差的 10 个百分点【小于单边的 11.2】 —— 说明不了任何问题。
```

> ⚠️ **比较两组时不要把两个 SE 相加** —— 那会把门槛抬得过高，反而漏掉真实差异。同一批任务、同一批初始条件下，应当用 **McNemar 配对检验**（看的是两组结果**不一致**的那些试验）。完整版见 [附-速查表](附-速查表.md) §F2。
> ⚠️ 这一条对触觉类工作尤其要紧：§9.2 说过，每篇触觉工作基本都在自己那套硬件上自建数据集，**试验次数常常只有几十**。⟹ 读到「加了触觉，成功率从 55% 涨到 70%」时，先翻到实验设置里找 n。

## 🔑 本章一句话

> 具身智能有**两拨人**：运动派在仿真里用强化学习练走跑跳（**已成熟**），操作派靠真机数据做模仿学习（**还很弱**）。
> ★★★ 差别的根源是：**走路依赖本体感受，仿真和真实几乎一样；抓取依赖视觉，仿真和真实差很远。**
> ⚠️ 而触觉这条通道提出了一个对世界模型的根本质疑：**决策需要的关键信息，可能根本不在画面里。**
> ⚠️ 触觉之所以至今没有基础模型，不是数据少，是**不同传感器的数据连形状都不一样**，没有「一张 RGB 图」那样的通用容器（§9.2）。
> ★ 而硬件侧最该记住的一条是：**执行器的机械带宽（几十 Hz）比控制环频率（几百到上千 Hz）低一两个数量级** —— 控制环跑得快是为了控得稳，不是因为身体能那么快（§9.3）。
