## 11.1 先用倒水的例子讲清它是什么

回到第 00 章那杯水。三种模型面对同一个画面，做的事情不一样：

```
    画面：桌上有个空杯子，旁边一个水壶

    ① VLA（第 01 章）        看画面 + 听指令 ──▶ 【下一步动作】
                             "手向右移 3 厘米"
                             ⚠️ 它不知道这么做之后会发生什么，也不关心

    ② 世界模型（第 02 章）    看画面 + 给一个动作 ──▶ 【下一帧画面】
                             "如果手向右移 3 厘米，画面会变成这样"
                             ⚠️ 它不会自己决定该做什么动作

    ★★ ③ WAM               看画面 ──▶ 【下一步动作】+【那之后世界的样子】
                             两件事【同一个模型、同一次训练】一起学
```

> 🔑 **一句话**：WAM = 一个模型同时回答「我该做什么」和「做完会怎样」。
> ⟹ 它不是把两个模型拼起来，关键在于**两个任务共享同一套参数**。

📖 **为什么中文里它有两个名字**：`World-Action Model` 直译是「世界-动作模型」，
产业里也常写成「世界动作模型」，还有人叫「统一世界模型」「动作世界模型」——**指的是同一件事**。
✅ 这个词最正式的一次使用，来自智元 Genie Envisioner 论文：它把自己的动作分支 **GE-Act 直接命名为 "World Action Model"**（arXiv:2508.05635）。

## 11.2 ★★ 为什么有人想合并？四个理由，一个比一个实际

```
    理由① 知识重叠
      "预测水会不会洒出来" 和 "决定手该怎么动"，
      背后需要的是【同一套关于物理和因果的理解】。
      ⟹ 拆成两个模型 = 同一份知识学两遍，还可能学得互相矛盾。

    理由② 动作是理解世界最好的"教鞭"
      ★ 让模型预测"随便一段视频的下一帧"，它可以靠画面惯性蒙混过关；
        让模型预测"我做了这个动作之后的下一帧"，它【必须】搞懂动作和后果的因果关系。
      ⟹ 加上动作条件，反而让世界模型学得更扎实。
      ✅ WorldVLA 的消融实验正好验证了反方向：
         "动作条件下的世界模型比纯视频预测模型对动作生成更有帮助"（arXiv:2506.21539）

    理由③ ★★★ 数据——这才是真正的驱动力
      第 01 章 1.5 节说过，VLA 的天花板是【带动作标签的真机数据太贵】。
      而互联网上有无穷无尽的视频，只是【没有动作标签】。
        │
        ├─ 纯 VLA：这些视频【一点用不上】（没有标签就没有监督信号）
        └─ ★ WAM：预测未来这个目标【根本不需要动作标签】
                  ⟹ 于是无标签视频可以拿来训练模型的一半，
                     再用少量真机数据把另一半（动作）接上。
      ⟹ ★★ 这是 WAM 相对 VLA 最硬的一条优势，也是它 2025 年后火起来的直接原因。

    理由④ 推理时省事
      两个模型 = 两次前向；一个模型 = 一次。对毫秒级的机器人不是小事。
```

> ⚠️ **提醒**：理由①②听起来最漂亮，但**理由③才是论文里真正被反复验证的那条**。
> 读任何一篇 WAM 论文，先看它有没有用上无动作标签的数据——没有的话，它的收益来源要打个问号。

## 11.3 ★★ 三种合并方式（本章的核心分类）

⚠️ **以下分类是我的归纳**，不是学界的标准划分，但它能把现有工作都装进去。

### 方式 A｜**交错序列式**：动作和画面在同一串 token 里轮流预测

```
    ★ 思路最"暴力"，也最贴近语言模型：
      把图像切成 token、把动作也切成 token，全塞进一个序列里自回归预测。

      [图像token...] [动作token...] [下一帧图像token...] [下一个动作token...] ...
                          │                 │
                     这是"策略"          这是"世界模型"
                     ⟹ ★ 其实是同一个 next-token 任务

    ✅ 代表：WorldVLA（arXiv:2506.21539）
       · 从 Chameleon（一个统一图像理解+生成的模型）初始化
       · 三个分词器：VQ-GAN 管图像、BPE 管文本、动作按每个维度切 256 个格子
         ⟹ 📖 这就是第 01 章 1.3 节说的「离散分箱」，在这里被复用了
       · ✅ 结论：合并之后，动作模型和世界模型【互相都变强了】

    ⚠️ 但它踩到一个坑，值得单独记住：
       连续自回归生成一串动作时，前面动作的误差会【滚雪球】传给后面。
       ✅ WorldVLA 的解法是加一个注意力掩码：生成当前动作时，
          【把之前的动作遮住】，强迫它只看画面。
          ⟹ 论文报告成功率提升 4%~23%。
       ★ 这个现象很能说明问题：动作和图像放进同一个序列，
         并不自动就是好事，还得防着它们互相污染。
```

### 方式 B｜**共享主干双分支**：一个身体，两个头

```
    ★ 工程上最常见、最好落地的一种：

           图像 + 指令
                │
        ┌───────▼────────┐
        │   共享主干      │  ← 两个任务的梯度都往这里回传
        └───┬────────┬───┘
            │        │
       ┌────▼───┐ ┌──▼──────┐
       │ 未来预测│ │ 动作输出 │
       │  分支   │ │  分支    │
       └────────┘ └─────────┘

    ✅ 代表一：Genie Envisioner（智元 AgiBot，arXiv:2508.05635）
       · GE-Base：指令条件的多视角视频扩散模型，
         ✅ 约 3000 小时视频-语言配对数据、超过 100 万条真实机器人操作片段
       · GE-Act：★ 论文原文称之为 "World Action Model"，
         一个【轻量的流匹配解码器】，把 GE-Base 的潜表示映射成可执行动作轨迹
         ⟹ 📖 流匹配 = 第 01 章 1.3 节路线②那个"直接画出连续动作"的技术
       · GE-Sim：动作条件的神经仿真器，可以给【别人家的策略】当闭环考场
       · EWMBench：配套评测基准（视觉保真、物理一致性、指令-动作对齐）
       ⟹ ★ 注意它一家做了四件事，正好对应第 03 章五种用途里的③④⑤

    ✅ 代表二：UWM / Unified World Models（arXiv:2504.02792，RSS 2025）
       ★★ 这一篇的设计特别优雅，值得单独讲：
       · 一个 transformer 里跑【两个扩散过程】：动作扩散 + 视频扩散
       · ★★ 关键：两个过程的【扩散时间步是各自独立的】
         ⟹ 只要调这两个旋钮，同一个模型就能当：
            策略（给画面出动作）/ 前向动力学（给动作出未来）/
            逆动力学（给两帧出中间动作）/ 纯视频生成器
       · ✅ 而且正因为时间步独立，它可以【直接吃无动作视频】
         —— 理由③在这里被做成了架构特性
```

### 方式 C｜**潜空间联合滚动**：干脆不生成像素

```
    ★ 血统来自 Dreamer 系列（第 02 章 2.4 节的潜空间派）：
      世界的演化和动作的选择，都在一个【压缩过的抽象状态空间】里进行，
      从头到尾不画一帧完整画面。

    ✅ 代表：Dreamer 4（arXiv:2509.24527，Google DeepMind，2025-09）
       · ✅ 论文把"在世界模型内部用 RL 训练行为"这件事命名为 imagination training
       · ✅ 用 block-causal transformer + shortcut forcing 从离线视频学时空动态
       · ✅ 号称能在【单张 GPU 上实时交互推理】
       ⟹ ★ "实时"这三个字是这条路线相对方式 A/B 的最大优势
         —— 因为生成像素太慢（第 03 章 3.3 节那盆冷水）

    ✅ 优点：快、省算力，天生适合放进控制回路
    ⚠️ 缺点：潜空间看不见摸不着，出了问题很难调试；
             而且它和现成的视觉语言大模型【接不上】（第 02 章 2.4 节已经说过）
```

### ★★ 三种方式对照表

| | 方式 A 交错序列 | 方式 B 共享主干双分支 | 方式 C 潜空间联合 |
|---|---|---|---|
| **怎么合并** | 图像/动作 token 混在一个序列 | 一个主干，两个输出头 | 状态和动作都在潜空间里滚 |
| **要不要生成像素** | 要 | 通常要 | ★ 不要 |
| **能吃无动作视频吗** | 能（只训预测那部分） | ✅ 能（UWM 做成了架构特性） | 能 |
| **推理开销** | ⚠️ 最重 | ⚠️ 重（但预测分支可以不跑） | ✅ 最轻 |
| **和现成 VLM 的兼容性** | ✅ 好（本来就是 token） | ✅ 好 | ⚠️ 差 |
| **可调试性** | ✅ 好（能看到它想象的画面） | ✅ 好 | ⚠️ 差 |
| **代表** | WorldVLA | Genie Envisioner、UWM | Dreamer 4 |

> ⚠️ **别把这张表当成"选型指南"**：三条路线目前【谁也没赢】，
> 而且没有任何一篇论文在同等数据、同等算力下把三者放在一起比过。

## 11.4 ★★ 潜动作（latent action）：WAM 生态里最该知道的一个技巧

理由③说「无标签视频能用上」，但有个绕不开的问题：

```
    ⚠️ 视频里没有动作标签，那"动作"这一格填什么？
```

**解法叫潜动作**：不去猜真实的关节角度，而是**从相邻两帧的变化里，反推出一个"抽象动作"**。

```
    第 t 帧 ──────┐
                  ├──▶ 【反推】这两帧之间"发生了什么" ──▶ 一个离散编号，比如 #37
    第 t+1 帧 ────┘         （用 VQ-VAE 之类的技术压成有限个格子）

    ⟹ ★ 于是任何一段视频，都被自动标上了一串"动作"，
      虽然这些编号和真实电机指令毫无关系。

    然后分两步：
      ① 用海量无标签视频，训模型"看画面 + 听指令 ⟹ 预测潜动作编号"
      ② 用少量真机数据，训一个小映射："潜动作 #37 ⟹ 我的机械臂该转多少度"
      ⟹ ★★ 第①步的数据量可以比第②步大好几个数量级
```

```
    ✅ 代表：LAPA / Latent Action Pretraining from Videos
       （arXiv:2410.11758，ICLR 2025，KAIST / 华盛顿大学 / 微软研究院 / NVIDIA / AI2）
       · ✅ 三阶段就是上面说的：VQ-VAE 学离散潜动作 ⟹ 预训练 ⟹ 真机微调
       · ⚠️ 注意一个实用细节：它放出的 checkpoint 输出的是【潜动作】，
            不是真实动作，✅ 必须自己微调才能驱动机器人

    🔎 同一思路的其它工作（本次未逐一核对细节，仅编号可信）：
       LAPO（用逆动力学 + 前向动力学做一致性）、
       Genie（用因果潜动作模型）、villa-X、
       LAWM（arXiv:2509.18428，把潜动作学习和世界建模合起来）
```

> 🔑 **为什么把它单列一节**：★★ **潜动作是"WAM 能吃互联网视频"这句话的技术兑现方式。**
> 没有它，理由③就只是一句口号。

## 11.5 训练一个 WAM，实际要做的事

```
    ★ 两个损失同时压在一个模型上：

      L = L_动作（模仿人类演示，和普通 VLA 一样）
        + λ · L_预测（预测未来的画面 / 潜表示）

    ⚠️ 关键就在那个 λ（两个目标的权重比）：
       λ 太小 ⟹ 预测分支形同虚设，等于白训一个 VLA
       λ 太大 ⟹ ★ 模型把容量花在"把画面画漂亮"上，动作反而变差
    ⚠️ 而这个 λ 怎么定，几乎没有论文认真讨论过，工业界更是没人公开。
       ⟹ 这是我认为本方向【最被低估的一个实操问题】。
```

**典型的三段式流程**（⚠️ 我按现有工作归纳，各家细节差别很大）：

```
    第一阶段：视频预训练     ── 海量无动作标签视频，只训预测（+潜动作）
        │                      ⟹ 这一段最贵，也最能拉开差距
        ▼
    第二阶段：动作对齐       ── 中等规模带动作数据（如 Open X-Embodiment，见第 05 章）
        │                      ⟹ 把"潜动作"接到"真实关节"上
        ▼
    第三阶段：任务微调       ── 少量本体上的真机数据
                               ⟹ 适配具体机器人的臂长、夹爪、相机位置
```

> ★ 对照第 01 章会发现：**WAM 只是在 VLA 的流程前面，多插了一段"不需要动作标签"的预训练。**
> ⟹ 从这个角度看，WAM 与其说是新架构，不如说是**一种把预训练数据来源扩大 100 倍的办法**。

## 11.6 ⚠️⚠️ 五盆冷水

```
    ⚠️ 冷水一：两个目标会打架
       "生成一帧看得过去的未来画面"比"输出 7 个关节角度"难得多、也占容量得多。
       ⟹ ★ 有理由怀疑：很多 WAM 的收益其实来自【多了一份预训练数据】，
         而不是来自"预测未来"这个任务本身有多神。
       ⟹ ⚠️ 要证伪这一点，需要"同样的数据、去掉预测分支"的对照实验——很少有人做。

    ⚠️ 冷水二：实时性
       第 03 章 3.3 节那盆冷水在这里【全部适用】：生成一帧画面几十上百毫秒，
       而机器人要毫秒级响应。
       ⟹ ★ 所以实用系统里，预测分支【推理时经常根本不跑】，只在训练时当辅助任务。
         这就引出下一节那个最狠的问题。

    ⚠️ 冷水三：世界模型的三个硬伤，WAM 一个不落全继承了
       （第 02 章 2.7 节：画面对 ≠ 物理对 / 只会响应见过的动作 / 没法评价好坏）
       ⟹ 而且更糟：世界模型现在【在决策回路里】，它编造的物理会直接变成错误动作。

    ⚠️ 冷水四：还是没有尺子
       第 05 章说过真机成功率无法互比。WAM 让这件事更难——
       现在要同时评"动作准不准"和"预测像不像"，而后者的指标（FID/FVD 那些）
       ✅ 衡量的是好不好看，不是物理对不对。
       ⟹ ★ Genie Envisioner 配套发布 EWMBench 正是为了补这个洞，⚠️ 但还远未成为公认标准。

    ⚠️ 冷水五：名字正在通胀
       "世界动作模型 / 统一世界模型"在 2026 年已经开始被当作宣传词用。
       ⟹ 下一节给一套辨别办法。
```

## 11.7 ★★ 五个问题，看穿任何一个自称 WAM 的东西

> 呼应第 07 章 7.5 节的「三个问题」，这里是 WAM 版。

```
    问题① 动作和预测，是【同一次训练、同一批参数】学出来的吗？
          ⟹ 如果是两个模型拼在一起用，那是第 03 章的范式③，不是 WAM。

    ★★ 问题② 推理的时候，它【真的会去想象未来】吗？
          ⟹ 这是最狠的一问。很多工作里，"预测未来"只是训练时的辅助损失，
            上机跑的时候预测分支【根本不启动】。
          ⟹ 这不算错，但它的本质是"用世界建模当预训练任务"，
            而不是"决策时会推演"——两者的价值完全不同，宣传时却经常混为一谈。

    问题③ 它能不能吃【没有动作标签】的视频？
          ⟹ 不能的话，理由③这条最大的好处它没拿到。

    问题④ 它预测的是【像素】还是【潜空间】？
          ⟹ 决定了它能不能实时（方式 C 快，方式 A 慢）。

    问题⑤ 有没有【去掉世界模型分支】的消融实验？
          ⟹ ★ 没有这个对比，就没法说明"合并"本身带来了什么。
            ✅ WorldVLA 是少数认真做了这件事的（它报告合并后两边都变强）。
```

## 11.8 ⚠️ 这条路线现在到哪一步了

```
    ✅ 已经确定的：
       · 合并是可行的，而且在受控实验里确实比单独的动作模型/世界模型好
       · 潜动作让无标签视频真正用起来了，这是实打实的数据增量
       · 已经有平台级的完整实现（Genie Envisioner：模型+仿真器+评测一套）

    ⚠️ 还没确定的：
       · 收益到底来自"架构合并"还是"数据变多"——缺对照实验
       · 推理时到底该不该真的想象——目前多数系统选择"不"
       · 三种合并方式谁更好——没人公平比过

    🔑 ⚠️ 我的判断：WAM 目前更像是【一种预训练方法】，
       而不是【一种新的推理架构】。
       ⟹ 它要成为后者，前提是"想象一步"的成本降到毫秒级——
         而这正是 Dreamer 4 那条潜空间路线在攻的方向。
```

## 🔑 本章一句话

> **WAM = 让同一个模型既输出动作、又预测这个动作导致的未来。**
> 三种做法：把动作和画面混进一个 token 序列（WorldVLA）、共享主干挂两个头（Genie Envisioner、UWM）、干脆全在潜空间里滚（Dreamer 4）。
> ★★ **它真正的价值不在"会预判"，而在"预测未来这个任务不需要动作标签"**——靠潜动作技术，海量无标签视频第一次能拿来训机器人策略，这直接对着第 01 章那堵数据墙。
> ⚠️ **但要清醒**：多数系统推理时并不真的想象未来，预测只是训练时的辅助任务；而"合并到底比不合并好在哪"，至今缺少干净的对照实验。
