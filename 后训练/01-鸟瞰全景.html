01 · ⭐ 鸟瞰：从 ckpt 到上线模型

这一章的目标只有一个：把"后训练"这条流水线的形状看清楚。
读完你应该能回答：预训练完的模型到底缺什么？为什么要分七个阶段？为什么 2026 年各家的技术报告有一半篇幅在讲强化学习？
读法：本章后半段的每个数字都给了出处和口径，除法都是能自己验算的。建议拿纸笔跟着算一遍 1.3 的三张表——算过一遍的数字才会变成直觉。

⚠️ 本章出现的缩写，先在这里一次性给全称，后面各章不再重复展开：ckpt = checkpoint（检查点，存到磁盘上的一份模型权重）· base = base model（基座模型，预训练跑完、还没做过任何对齐的权重）· SFT = Supervised Fine-Tuning（有监督微调）· RL = Reinforcement Learning（强化学习）· RLHF = Reinforcement Learning from Human Feedback（基于人类反馈的强化学习）· RLVR = Reinforcement Learning with Verifiable Rewards（基于可验证奖励的强化学习）· OPD = On-Policy Distillation（在策略蒸馏）· DPO = Direct Preference Optimization（直接偏好优化）· PPO = Proximal Policy Optimization（近端策略优化）· GRPO = Group Relative Policy Optimization（组相对策略优化）· RM = Reward Model（奖励模型）· CoT = Chain of Thought（思维链）。完整缩写总表见 附-速查表。

1.1 先看一眼"预训练刚训完"的模型有多难用

预训练模型学的唯一一件事是：给定前面的文字，猜下一个字。 所以你问它问题，它不会回答，它会接着往下编：

你输入：
   北京在哪？

一个纯 base 模型的典型输出：
   北京在哪？上海在哪？广州在哪？请在下面的地图上标出这三个城市的位置。
   （5 分）
   2. 简述我国四大直辖市的分布特点。（10 分）
   ...

★ 它没有做错任何事——它见过无数张试卷，"北京在哪？"后面统计上最可能跟着的就是下一道题。

所以 base 模型缺的不是知识，是三样别的东西：

缺的东西 具体表现 谁来补 为什么这件事补起来不难／很难
① 格式 不知道"轮到我说话了"，也不知道"我说完了"（不会停） SFT（02 章） 容易。这是一层很薄的"出场姿势"，几千条数据就能教会
② 偏好 两个都对的回答，不知道哪个是人想要的 RLHF / DPO（04 章） 中等。需要换一种数据形状（成对比较），但不需要模型变强
③ 能力的兑现 知识在参数里，但不会在需要时组织成正确的推理 RLVR / Agentic RL（05 / 07 章） 最难，也最贵。2026 年后训练算力的绝大部分砸在这一格

★★ 第 ③ 点是最反直觉的。base 模型其实"会"做很多题，只是它做对的概率很低。后训练里强化学习那部分，很大程度上在做的事是把已有的能力从"偶尔做对"变成"稳定做对"——这件事到底算不算"提升能力"，是 2025～2026 年争得最凶的一个问题，见 05.6。

🔑 看这张图和这张表最重要的三个认知：
① 真正换了优化目标的只有 ④⑤⑥⑦。 ①②③ 全都是"预测下一个 token"，只有 loss 加在哪不一样（02.1 会把这件事拆到 token 级）。所以"后训练"这个词其实横跨了两种完全不同的训练范式。
② SFT 只占整条流水线里很小的一段，而且它的地位在四年里一路下滑。 2022 年的后训练几乎 = SFT + 一点 RLHF；2026 年的后训练 = 一小段 SFT + 一大堆 RL + 一次蒸馏收口。
③ 数据量在 ③ 这一格断崖式下跌（10¹³ → 10⁹ 量级），算力却没有同比例下跌。 这个"数据少、算力不少"的组合，是后训练所有病（灾难性遗忘、过拟合、多样性坍缩）的共同根源。

⚠️ 顺手把三个会错一个数量级的除法说清楚

这三个错在后训练的中文材料里非常常见，而且它们都只是除法做错，不是概念理解错。

错误一：拿「token」除以「条」

比法 分子 分母 算出来 判定
❌ 流传最广的算法 预训练 10¹² token 后训练 10⁶ 条 10⁶ ⟹ "小六个数量级" ❌ token ÷ 条，量纲不同，这个商没有意义
✅ 先把「条」换成 token（R1 口径） 14.8 T = 1.48×10¹³ token ✅ V3 报告 80 万条 × 约 2000 token/条 ≈ 1.6×10⁹ token（⚠️ 平均长度是我估的，R1 的 SFT 数据里有大量长 CoT） 1.48×10¹³ ÷ 1.6×10⁹ ≈ 9.3×10³ ✅ 小 约四个 数量级
✅ 数据最多的那一端 同上 700 万条 × 约 10³ token/条 ≈ 7×10⁹ token 1.48×10¹³ ÷ 7×10⁹ ≈ 2.1×10³ ✅ 小 约三个 数量级

⟹ 结论：按 token 算，后训练比预训练小「三到四个」数量级，不是六个。

★ 还可以再扣一刀：SFT 里只有 assistant 段算 loss（02.1），一条多轮样本里 assistant 占比常在 30%~50%，所以真正产生梯度的 token 还要再打对折 ⟹ 按"有效梯度 token"算，差距是四到五个数量级。这一刀在 ../数据格式和数据处理/15-后训练数据格式.md 里算得更细。

错误二：把「时间减少 X%」说成「加速 X%」

加速倍数 = 1 / (1 − 时间减少比例)

   时间减少 20%  ⟹  1 / 0.8  = 1.25×   （不是 1.2×）
   时间减少 50%  ⟹  1 / 0.5  = 2.00×   （不是 1.5×）
   时间减少 80%  ⟹  1 / 0.2  = 5.00×   （不是 1.8×）

★ 反过来：加速 2× 意味着时间减少 50%，不是减少 200%（那不可能）。

错误三：把「百分点」说成「百分比」

某个评测从 60% 涨到 63%：

   ✅ 涨了 3 个【百分点】
   ✅ 相对提升 3 / 60 = 5%（这是【百分比】）
   ❌ "涨了 3%"  —— 这句话有歧义，读者无法判断是 63% 还是 61.8%

★★ 本教程的约定：涨跌一律写【百分点】，相对变化一律写明"相对"。
   ⚠️ 引用别人的数字时，如果原文没说清是哪一个，就把这个不确定性一起标出来。

1.4 ★★ 三个必须先建立的概念

后面每一章都会用到这三个词，这里一次性讲清楚。

概念一：rollout（采样 / 让模型跑一遍）

监督学习：            给它「题目 + 标准答案」，让它照着学
                      ★ 模型是被动的

强化学习：            只给「题目」，让它【自己写一个答案出来】
                      然后判分，再根据分数调整权重
                      ★ 模型是主动的，它先"动手"再被评价

   "让它自己写一遍" 这个动作，就叫 rollout

为什么 rollout 是 2026 年一切工程问题的源头：

监督学习的一步 强化学习的一步
要做什么 前向 + 反向 先生成几千个 token（Agentic 场景还要先跑十几轮工具调用），然后才是前向 + 反向
一步多久 几百毫秒 几十秒 ~ 几十分钟
长度可预测吗 ✅ 固定（padding / packing 到定长） ❌ 完全不可预测，同一批里能差几十倍
一批里谁决定总时间 所有样本一样快 ★★ 最慢的那一条（长尾问题）
需要推理引擎吗 ❌ 不需要 ✅ 需要，而且和训练引擎是两套代码

⟹ 一批 128 条 rollout，最慢的那条决定整批的时间；于是有了异步 RL、partial rollout（部分 rollout，把没写完的下一轮接着写）、可抢占 rollout……⚠️ 这些都是系统问题，本目录不展开，见 ../强化学习训练框架/02-架构主轴-同步到全异步.md 和 ../强化学习训练框架/03-权重同步.md。本目录只讲算法和数据那一半。

概念二：on-policy vs off-policy

先把这两个词的字面意思摆平：policy（策略）在 RL 里就是"模型"本身；on-policy = 用当前这一版模型自己生成的数据训它自己，off-policy = 用别人或旧版模型生成的数据训它。

off-policy（离策略） on-policy（在策略）
数据谁写的 人写的 / 更强的模型写的 / 上一版自己写的 当前这一版自己刚写的
典型代表 SFT、DPO、普通蒸馏 RLVR、Agentic RL、OPD
训练分布 vs 推理分布 ❌ 不一致 ✅ 一致
典型病 exposure bias（曝光偏差）：训练时它看到的永远是完美前缀，推理时它看到的是自己写歪的前缀 ⟹ 学到的东西"用不上" —
代价 便宜，数据可以反复用 ⚠️ 每一步都要重新 rollout，贵得多
数据会不会过期 ⚠️ 会。模型变了，数据还是老的（04.5 会把这件事讲透） ✅ 不会，信号永远新鲜

★★★ "从 off-policy 走向 on-policy"是这四年后训练最清晰的一条技术趋势。 你会在 08 章看到它的终点：连"蒸馏"这种最典型的 off-policy 手段，2026 年也被改造成了 on-policy 的。

概念三：奖励 reward

一条 rollout 出来了，怎么给它打分？这个问题的答案在过去四年换了三轮：

   2022  人来打分   → 训一个模型模仿人打分（奖励模型 RM）  → 04 章
   2024  规则打分   → 数学对答案、代码跑测试（验证器）      → 05 章
   2026  环境打分   → 让它真的去干，看任务成没成            → 07 章

★★ 这条线是全教程的脊柱，11 章会把它展开成一条完整的因果链。
代 奖励从哪来 一个具体例子 能不能规模化 典型失效方式
2022 人（标注员排序）→ 训 RM 模仿 "这两个回答你更喜欢哪个" ❌ 人不 scale reward hacking：模型学会讨好 RM 而不是讨好人（04.2）
2024 规则 / 验证器 数学比对标准答案、代码跑单元测试 ✅ 完全自动 只覆盖"有客观对错"的任务；验证器本身可能有漏洞（06.4）
2026 环境 把测试修好了没有、网页任务完成了没有 ⚠️ 自动，但环境本身要人造 瓶颈从"模型"转移到"环境"（07.2）

1.5 一条数据在后训练里的旅程

跟着一道数学题走一遍，把上面的抽象概念落到实处：

【SFT 阶段】
   题目：一个水池，进水管 3 小时注满，出水管 5 小时放空，同开几小时注满？
   人（或更强的模型）写好的标准解答：设水池容量为 1，进水速度 1/3 ...
        ↓
   拼成 messages 格式，只在 assistant 那段算 loss
        ↓
   模型学到的："遇到这种题，要先设未知数，然后..."
   ⚠️ 但它学的是【模仿这个写法】，不是【会解这类题】

【RLVR 阶段】
   同一道题，这次【不给答案】
        ↓
   让模型自己写 8 个解法（8 次 rollout）
        ↓
   把每个解法的最终答案和标准答案比：  对 错 错 对 错 对 错 错   → 3 对 5 错
        ↓
   GRPO：对的那 3 条，提高它们出现的概率；错的 5 条，降低
        ↓
   模型学到的：★【哪一类思路更容易走到正确答案】
              —— 这是标准答案里没有的信息，只能靠自己试出来

【Agentic RL 阶段】
   题目换成："这个仓库的测试挂了，修好它"
        ↓
   模型在一个真实容器里：读文件 → 改代码 → 跑 pytest → 看报错 → 再改
        ↓
   奖励 = 测试最后过没过（0 或 1）
        ↓
   ⚠️ 一条轨迹可能几十轮、几万 token、几分钟——这就是 07 章所有工程问题的来源

【OPD 收口阶段】
   数学专家、代码专家、Agent 专家各自练成了，但它们是三个模型
        ↓
   让一个学生模型自己做题（on-policy），
   在它写的每个 token 上，问对应领域的专家："你会给这个词多少概率？"
        ↓
   学生朝专家的分布靠拢 → 三个专家合并成一个模型   → 08 章

同一道题，四个阶段拿到的"监督信号"完全不同——这张表是理解整条流水线的另一个角度：

阶段 给模型什么 监督信号的粒度 信号里有多少信息 这个信号能不能告诉模型"更好的思路"
SFT 题目 + 一个标准解法 每个 assistant token 一个目标词 最稠密 ❌ 不能。它只说"照这样写"
RLVR 题目（不给答案） 一整条轨迹一个标量（对 / 错） 最稀疏 ✅ 能。靠 8 条里哪些对，比较出来
Agentic RL 任务 + 一个真实环境 一整条轨迹一个标量，但轨迹长几十倍 更稀疏（长程信用分配问题，见 07.6） ✅ 能，但归因很难
OPD 题目 + 一个教师模型 学生写的每个 token 上一整个概率分布 ★★ 比 SFT 还稠密 ✅ 能，而且逐 token 地说

★★ 这张表解释了 2026 年为什么是"RL 练能力 + OPD 收口"这个组合：RL 的信号最有信息量但最稀疏（样本效率低），OPD 的信号最稠密（样本效率高）但需要有一个已经练好的教师。先用贵的稀疏信号把能力练出来，再用便宜的稠密信号把它复制进一个模型里。

1.6 四年时间线（预告）

这张表是 11 章的缩略版，先扫一眼建立坐标系：

时间 标志事件 换了什么
2022-03 InstructGPT（arXiv:2203.02155） 确立 SFT → 奖励模型 → PPO 三步走
2022-12 Constitutional AI（arXiv:2212.08073） 打分的人开始被模型替代（RLAIF = Reinforcement Learning from AI Feedback）
2023-05 LIMA（arXiv:2305.11206） "1000 条精选数据就够了"——SFT 的数据量迷信被打破
2023-05 DPO（arXiv:2305.18290） 证明"最优策略"和"奖励函数"之间有闭式对应，于是偏好对齐不用 RL 也能做，门槛暴跌（04.4）
2024-02 DeepSeekMath / GRPO（arXiv:2402.03300） 去掉 critic（价值模型），RL 的显存账从 36 字节/参数降到 20 字节/参数（04.3）
2025-01 ⭐ DeepSeek-R1（arXiv:2501.12948） RLVR 范式确立：不用人打分，用"对不对"打分
2025 全年 DAPO / GSPO / CISPO 等变体 GRPO 的工程病被逐个修补
2025-10 ScaleRL（arXiv:2510.13786） RL 也有 scaling law（规模定律）了
2026 全年 五家报告：Agentic RL + OPD 收口 瓶颈从"模型"转到"环境"

1.7 这一章的四句话总结

① 后训练不是"微调一下"，它是一条七阶段的流水线，
   而且重心在过去四年从 SFT【彻底移到了 RL】。
   ★ 但注意：①②③ 三格的训练目标其实都还是"预测下一个 token"，
     真正换了优化目标的只有 ④⑤⑥⑦。

② 理解 2026 年这个领域的钥匙是两个词：
   【rollout 很贵】 和 【on-policy 更有效】。
   所有工程复杂度都来自第一个，所有算法演进都来自第二个。

③ 奖励从哪来（人 → 规则 → 环境），是这条演进线的真正主轴。

④ ⚠️ 引用这个领域的任何数字前，先问三句话：
   · 这是 token 还是「条」？（差三到四个数量级）
   · 这是"时间减少"还是"加速倍数"？（加速 = 1/(1−减少比例)）
   · 这是百分点还是相对百分比？
