# 02 · SFT：监督微调

> **SFT** = **Supervised Fine-Tuning**（有监督微调）。
> **一句话**：拿「问题 → 标准回答」的配对数据继续训模型，让它学会以"助手"的身份说话。
>
> 读完这一章你应该能回答：SFT 和预训练在机制上到底差在哪？为什么 2023 年说"1000 条就够"、2026 年却有人用 700 万条？以及——**为什么现在越来越多人说"SFT 分数高不是好事"**。

---

## 2.1 机制：底层什么都没变，只变了一件事

**这是全章最重要的一句话：SFT 还是"预测下一个 token"，唯一的区别是 loss 加在哪。**

```
预训练：一整篇文本，【每个 token 都算 loss】

   北 京 是 中 国 的 首 都 ， 位 于 华 北 平 原 ...
   ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑
   全部都要预测，全部都算 loss


SFT：一段对话，【只在 assistant 说的话上算 loss】

   <|system|> 你是一个助手 <|user|> 北京在哪？ <|assistant|> 北京位于华北平原北部。<|end|>
   └────────────── 不算 loss ──────────────┘ └──────── 算 loss ────────┘
                （但它们仍然作为"上文"被模型看到）
```

### 为什么 user 那段不能算 loss

```
如果 user 段也算 loss，模型就在学习【怎么提问】。

后果很具体：你问它"北京在哪"，它有一定概率回你
   "北京在哪？上海在哪？"
—— 因为它学过"用户会连着问"。

★★ 这个 bug 不会报错，只会让模型行为变得莫名其妙。
   loss mask 写错是 SFT 阶段最常见、也最难 debug 的错误。
```

## 2.2 SFT 到底在改变模型的什么

**一个很有用的直觉（⚠️ 这是简化的说法，但方向是对的）：**

```
预训练  ——  往模型里【装知识】
SFT     ——  给模型【换一个出场姿势】

★ SFT 几乎不给模型增加新知识。
  它做的是：把模型内部本来就有的能力，用"助手对话"这个接口暴露出来。
```

**证据**：LIMA 这篇论文（✅ [arXiv:2305.11206](https://arxiv.org/abs/2305.11206)，Chunting Zhou 等，2023-05）用 **1000 条**精心挑选的样本做 SFT，就得到了接近当时用几万条数据训出来的模型的对话质量。论文由此提出 **"表层对齐假说"（Superficial Alignment Hypothesis）**：

> **模型的知识和能力几乎全部在预训练阶段获得，对齐只是教它"用哪种子分布来和用户交互"。**

★★ 这个假说在 2023 年是革命性的，它把整个行业从"SFT 数据越多越好"的路上拽了回来。**但它只对"对话格式"成立，对"推理能力"不成立**——这一点要到 2025 年 R1 出来之后才被彻底看清，见 [11 章](11-演进主线-三代范式.md)。

## 2.3 数据量：从 1000 条到 700 万条，两个流派

**看起来矛盾，其实是在解两个不同的问题：**

```
【流派一：少而精】  LIMA 路线
   1000 ~ 几万条，人工精修
   目标：教会【格式、语气、拒答边界】
   ★ 这些东西确实不需要很多数据

【流派二：多而广】  2026 年工业界主流
   100 万 ~ 700 万条，绝大部分是【模型合成 + 拒绝采样筛出来的】
   目标：覆盖【所有能力域】—— 数学、代码、SWE、CUDA、金融推理、
        长上下文、安全、搜索、终端操作、SQL ...
   ★ 域一多，条数自然就上去了
```

**一个 2026 年的实际数字**（✅ Nemotron 3 Super 报告，[arXiv:2604.12374](https://arxiv.org/abs/2604.12374)，NVIDIA，2026-04）：

```
SFT 阶段：700 万样本，覆盖 15+ 个数据域
   竞赛数学 / 代码 / 软件工程 / 智能体编程 / CUDA / 金融推理 /
   长上下文 / 安全 / 搜索 / 终端使用 / SQL / ...
```

> ⚠️ **别把这两个流派当成"谁对谁错"。** 正确的读法是：
> **教格式用几千条就够（LIMA 是对的），教能力覆盖要几百万条（工业界是对的），而"教能力"这件事 2026 年主要不靠 SFT 了，靠 RL。**

## 2.4 几个必须调对的旋钮

```
① epoch（把数据完整过几遍）
   通用对话      2~3 遍就开始过拟合（回答变模板化、句式雷同）
   数学 / 代码   3~4 遍还在涨
   安全数据      1 遍足够，多了模型会【过度拒答】
   ⚠️ 一个 2026 年的经验值：把所有 SFT 样本打包成长序列单阶段训练时，
      约 1.5 个 epoch 达到最优（✅ Nemotron-Cascade 2，arXiv:2603.19220）

② 学习率
   典型比预训练末期的学习率高一点，但比预训练峰值低 1~2 个数量级
   ⚠️ 太高 → 灾难性遗忘，通用能力崩塌；太低 → 学不进格式

③ packing（把多条短样本拼成一条长序列）
   ★★ 必须开【文档级注意力掩码】，否则样本 A 会"看到"样本 B
      → 详见 ../数据格式和数据处理/13-打包与文档掩码.md

④ 长上下文分阶段
   常见做法：先在 32K 长度训一轮，再在 256K 长度训第二轮
   （✅ Qwen3-VL 的公开做法；⚠️ 具体长度各家不同）
```

## 2.5 ★★ SFT 的三个"已知病"

**这一节是本章最有价值的部分。2025～2026 年的研究，系统性地指出了 SFT 这个范式本身的缺陷。**

### 病一：它倾向于"背"，而不是"会"

✅ **SFT Memorizes, RL Generalizes**（[arXiv:2501.17161](https://arxiv.org/abs/2501.17161)，Tianzhe Chu 等，2025-01）

```
实验设计：造一个规则可变的纸牌算术游戏 + 一个视觉导航环境，
         训练时用规则 A，测试时换成规则 B（分布外，OOD）

结果：
   SFT   → 分布外性能【下降 8% ~ 80%】
   RL    → 分布外性能【提升 3% ~ 61%】

★★ 而且：即使 SFT 用的是【带错误的次优轨迹】，这个模式依然成立
   ⟹ 说明"背"这件事来自【训练目标的结构】，不是数据质量问题
```

> ⚠️ **但论文自己也强调了另一半**：SFT 仍然是必需的——它稳定了模型的输出格式，**没有这一步，后面的 RL 根本训不起来**。
> ★ 这句话是理解 2026 年 SFT 定位的关键：**SFT 从"主角"变成了"给 RL 铺跑道的人"。**

### 病二：它的损失函数里藏着一个畸形的隐式奖励

✅ **On the Generalization of SFT: A Reinforcement Learning Perspective with Reward Rectification**
（[arXiv:2508.05629](https://arxiv.org/abs/2508.05629)，Yongliang Wu 等，2025-08）

**这篇论文做了一件很漂亮的事：证明 SFT 其实是 RL 的一个特例。**

```
把 SFT 的梯度公式和策略梯度（policy gradient）公式并排放，会发现：

   SFT 的梯度  ≡  策略梯度，其中隐含的奖励 ∝ 1 / π_θ
                                              ↑
                                     模型当前对这个词的概率

翻译成人话：
   ★ 模型【越是想不到】的那个词，SFT 给它的"奖励"就【越大】
   ⟹ 一个模型觉得极不可能的 token，会得到一个爆炸性的梯度
   ⟹ 训练不稳、容易过拟合到个别怪样本
```

**修法（DFT，Dynamic Fine-Tuning）：一行代码。**

```
把每个 token 的 loss 乘上它自己的概率 π_θ，
把那个 1/π_θ 抵消掉，让所有 token 的权重变均匀。

✅ 论文报告：在 Qwen-2.5-Math 系列上，DFT 相比标准 SFT 收益成倍提升；
   标准 SFT 在 OlympiadBench / AIME 2024 / AMC 2023 上经常【掉分】，
   DFT 则稳定提升。
```

> ⚠️ 这是单一课题组在数学任务上的结果，尚未看到五家工业报告采用。**当成"重要的理论视角"，不要当成"必须换的配方"。**

### 病三：SFT 分数高，不等于是好的 RL 起点

✅ **Quagmires in SFT-RL Post-Training**（[arXiv:2510.01624](https://arxiv.org/abs/2510.01624)，Feiyang Kang 等，2025-10）

```
常规做法：SFT 训完，挑【评测分最高】的那个 ckpt 去做 RL

论文发现这个做法是错的：

   配方 A：少量样本 + 多 epoch + 大学习率
      → SFT 后 MATH-500 【+8.75%】     看起来赢麻了
      → 但接着做 RL，最终反而 【-1.43%】

   配方 B：更多样、不重复的数据
      → SFT 后分数【低 5 个点】        看起来很差
      → 接着做 RL，最终 【+5.94%】     赢了

★★★ 原因：多 epoch + 大学习率会把模型【压得很尖】——
    输出多样性坍塌，RL 阶段没东西可探索，等于把路先堵死了。
```

> 🔑 **实操结论（很硬的一条）**：
> **挑 SFT ckpt 的标准，不该是"SFT 后的评测分"，而该是"它做完 RL 能到多少"。**
> **实践中的代理指标是输出多样性 / 熵——宁可要一个分数低一点、但还"活着"的模型。**

## 2.6 SFT 还有存在的必要吗？

**2026 年有一派观点认为：SFT 不该是一个独立阶段。**

⚠️ 代表工作 **CHORD**（Qwen 团队）：把 SFT 重新定义为**在 on-policy RL 过程中的一个动态加权辅助损失项**，理由是——长时间在有限的专家数据上训练会过拟合，压低输出多样性，**严重限制后续 RL 的探索能力**。

⚠️ 另一条证据来自多模态：有研究报告在 7 个多模态基准上，8B 模型 **SFT 之后反而掉了 5.2 个点**（63.3% → 58.1%），做完 RL 才刚回到基线（63.3%）——**意味着 RL 可能是在"还债"而不是"增益"**。

```
⚠️ 我的判断：SFT 短期内不会消失，因为它解决的"格式与可控性"问题
   目前没有更便宜的替代品。但它的三个变化已经很清楚：

   ① 篇幅在缩短 —— 从"后训练的主体"变成"冷启动"
   ② 目标在改变 —— 从"拿高分"变成"给 RL 留足探索空间"
   ③ 边界在模糊 —— 越来越多方案把它和 RL 揉进同一个 loss 里
```

---

## 2.7 这一章的三句话总结

```
① SFT 机制上只做了一件事：把 loss 限制在 assistant 段。
   写错 loss mask 不会报错，只会让模型变怪。

② SFT 教得会【格式】，教不会【能力】。
   前者几千条就够，后者要靠 RL。

③ 2026 年挑 SFT ckpt 的正确标准是"它做完 RL 能到多少"，
   而不是"它现在考几分"。多样性比分数重要。
```
