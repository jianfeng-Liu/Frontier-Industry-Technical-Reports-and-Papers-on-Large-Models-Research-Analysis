# 02 · SFT：监督微调

> **SFT** = **Supervised Fine-Tuning**（有监督微调）。
> **一句话**：拿「问题 → 标准回答」的配对数据继续训模型，让它学会以"助手"的身份说话。
>
> 读完这一章你应该能回答：SFT 和预训练在机制上到底差在哪？为什么 2023 年说"1000 条就够"、2026 年却有人用 700 万条？以及——**为什么现在越来越多人说"SFT 分数高不是好事"**。
> **读法**：本章有三张可以自己验算的表——**loss mask 的逐 token 表**（2.1）、**超参的量级表**（2.4）、**全参 / LoRA / QLoRA 的显存表**（2.4）。这三张表里的数字都给了算法，建议动笔算一遍。

> ⚠️ **本章新出现的缩写**：**LoRA** = **Low-Rank Adaptation**（低秩适配）· **QLoRA** = **Quantized LoRA**（量化低秩适配）· **ChatML** = Chat Markup Language（一种把多轮对话拍平成一串 token 的模板格式）· **OOD** = Out-Of-Distribution（分布外）· **DFT** = Dynamic Fine-Tuning（动态微调，本章 2.5 会讲）。其余缩写见 [01 章开头](01-鸟瞰全景.md)。

## 2.1 机制：底层什么都没变，只变了一件事

**这是全章最重要的一句话：SFT 还是"预测下一个 token"，唯一的区别是 loss 加在哪。**

```
预训练：一整篇文本，【每个 token 都算 loss】

   北 京 是 中 国 的 首 都 ， 位 于 华 北 平 原 ...
   ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑
   全部都要预测，全部都算 loss

SFT：一段对话，【只在 assistant 说的话上算 loss】
     （user / system 的部分仍然作为"上文"被模型看到，只是不产生梯度）
```

### ★★★ 把 loss mask 逐 token 列出来：一条两轮样本

**"只在 assistant 段算 loss"这句话听起来很简单，但它具体长什么样，必须看到 token 级才算懂。** 下面这条样本是**两轮对话**——⚠️ **两轮的 assistant 都要算 loss，不是只算最后一轮**，这是新手最常犯的第二个错。

**原始样本**：

```json
{"messages": [
  {"role": "system",    "content": "你是一个严谨的助手。"},
  {"role": "user",      "content": "北京在哪？"},
  {"role": "assistant", "content": "北京位于华北平原北部。"},
  {"role": "user",      "content": "人口多少？"},
  {"role": "assistant", "content": "约 2100 万。"}
]}
```

**按 ChatML 模板拍平，逐段标 mask**（⚠️ 为了看得清，这里把"一个角色头 / 一段正文 / 一个结束符"当成一组；真实实现是逐 token 的）：

| # | token 段 | 属于谁 | `loss_mask` | 进 loss 吗 | 为什么 |
|---|---|---|---|---|---|
| 1 | `<\|im_start\|>system\n` | 模板 | **0** | ❌ | 角色头是框架写的，不是模型要生成的内容 |
| 2 | `你是一个严谨的助手。` | system | **0** | ❌ | 系统提示是**我们写给它的**，不是它说的 |
| 3 | `<\|im_end\|>\n` | 模板 | **0** | ❌ | 这一轮不属于 assistant，结束符也不学 |
| 4 | `<\|im_start\|>user\n` | 模板 | **0** | ❌ | 同 1 |
| 5 | `北京在哪？` | user | **0** | ❌ | ★★ **最关键的一行**：学了它，模型就会自己编问题 |
| 6 | `<\|im_end\|>\n` | 模板 | **0** | ❌ | 同 3 |
| 7 | `<\|im_start\|>assistant\n` | 模板 | **0** | ❌ | ⚠️ 易错：推理时这几个 token 是**框架替它写进去**的生成提示，不需要它学会打出来 |
| 8 | `北京位于华北平原北部。` | **assistant（第 1 轮）** | **1** | ✅ | 这才是要教的内容 |
| 9 | `<\|im_end\|>` | 模板 | **1** | ✅ | ★★ **必须学**：它是停止信号，不学它模型永远学不会"什么时候该停" |
| 10 | `\n` | 模板 | **0 或 1** | ⚠️ | 各家实现不一；★ 关键是**训练和推理用同一套模板** |
| 11 | `<\|im_start\|>user\n` | 模板 | **0** | ❌ | 第二轮开始 |
| 12 | `人口多少？` | user | **0** | ❌ | 同 5 |
| 13 | `<\|im_end\|>\n` | 模板 | **0** | ❌ | — |
| 14 | `<\|im_start\|>assistant\n` | 模板 | **0** | ❌ | 同 7 |
| 15 | `约 2100 万。` | **assistant（第 2 轮）** | **1** | ✅ | ★★★ **第二轮也要学！** 不是只学最后一轮，也不是只学第一轮 |
| 16 | `<\|im_end\|>` | 模板 | **1** | ✅ | 同 9 |

**这张表要读出来的四件事**：

| 要读出来的 | 具体是哪几行 | 写错会怎样（现象） |
|---|---|---|
| ① **mask=1 的区域是"多段"，不是"一段"** | 第 8-9 组 和 第 15-16 组 | 只给最后一轮打 1 ⟹ 前面几轮的监督信号全丢了，**多轮能力训不出来**，而且不报错 |
| ② **结束符 `<\|im_end\|>` 要算 loss，但只在 assistant 那几轮** | 第 9、16 组是 1；第 3、6、13 组是 0 | 全都不学 ⟹ **模型说完不停**，一路胡说到 max_len；全都学 ⟹ 模型会在 user 该说话的位置乱插结束符 |
| ③ **角色头不算 loss** | 第 1、4、7、11、14 组 | 学了它 ⟹ 模型会自己打出 `<\|im_start\|>assistant`，输出里出现模板残渣 |
| ④ **有效 token 占比很低** | 整条约 60 个 token，mask=1 的约 17 个 ⟹ **约 28%**（⚠️ 这两个数是估的） | 这就是 [01.3](01-鸟瞰全景.md) 说"真正产生梯度的 token 还要再打对折"的来历 |

**自检脚本（强烈建议每次改完数据格式都跑一遍）**：

```python
# ★★★ 把 mask==1 的位置解码回文本打印出来，肉眼比对
learned = tok.decode([t for t, m in zip(ids, mask) if m == 1])
print(repr(learned))
# ✅ 期望输出（两段顺序拼接，不多一个字不少一个字）：
#    '北京位于华北平原北部。<|im_end|>约 2100 万。<|im_end|>'
# ⚠️ 出现了 '北京在哪？'        → 你把 user 也学了
# ⚠️ 只出现了 '约 2100 万。'    → 你只学了最后一轮（多轮 mask 写错）
# ⚠️ 末尾没有 <|im_end|>        → 你漏了结束符
# ⚠️ 整体错开一格               → 移位（shift）差一错误
```

### 为什么 user 那段不能算 loss

```
如果 user 段也算 loss，模型就在学习【怎么提问】。

后果很具体：你问它"北京在哪"，它有一定概率回你
   "北京位于华北平原北部。人口多少？约 2100 万。你还想知道什么？..."
—— 它开始【自问自答】，因为它学过"用户会连着问"。

★★ 这个 bug 不会报错，只会让模型行为变得莫名其妙。
   loss mask 写错是 SFT 阶段最常见、也最难 debug 的错误。
```

> 📎 **chat template 怎么写、工具调用怎么编码、移位（shift）差一错误怎么查**——这些细节在 [../数据格式和数据处理/15-后训练数据格式.md](../数据格式和数据处理/15-后训练数据格式.md)（**那一章的 §15.3 有一份更长的逐 token 走查**），本章不重复。

## 2.2 SFT 到底在改变模型的什么

**一个很有用的直觉（⚠️ 这是简化的说法，但方向是对的）：**

```
预训练  ——  往模型里【装知识】
SFT     ——  给模型【换一个出场姿势】

★ SFT 几乎不给模型增加新知识。
  它做的是：把模型内部本来就有的能力，用"助手对话"这个接口暴露出来。
```

**证据**：LIMA 这篇论文（✅ [arXiv:2305.11206](https://arxiv.org/abs/2305.11206)，Chunting Zhou 等，2023-05）用 **1000 条**精心挑选的样本做 SFT，就得到了接近当时用几万条数据训出来的模型的对话质量。论文由此提出 **"表层对齐假说"（Superficial Alignment Hypothesis）**：

> **模型的知识和能力几乎全部在预训练阶段获得，对齐只是教它"用哪种子分布来和用户交互"。**

★★ 这个假说在 2023 年是革命性的，它把整个行业从"SFT 数据越多越好"的路上拽了回来。**但它只对"对话格式"成立，对"推理能力"不成立**——这一点要到 2025 年 R1 出来之后才被彻底看清，见 [11 章](11-演进主线-三代范式.md)。

## 2.3 数据量：从 1000 条到 700 万条，两个流派

**看起来矛盾，其实是在解两个不同的问题：**

| | **流派一：少而精**（LIMA 路线） | **流派二：多而广**（2026 年工业界主流） |
|---|---|---|
| 条数 | 1000 ~ 几万条 | 100 万 ~ 700 万条 |
| 数据怎么来 | **人工精修** | **模型合成 + 拒绝采样筛出来的**（见 [03.2](03-分训与合训.md)） |
| 想教会什么 | **格式、语气、拒答边界** | **覆盖所有能力域**：数学、代码、SWE、CUDA、金融推理、长上下文、安全、搜索、终端操作、SQL… |
| 为什么这个量就够 / 不够 | 这些东西确实不需要很多数据——"出场姿势"是一层很薄的东西 | 域一多，条数自然就上去了；一个域几万条 × 十几个域 = 几十万到几百万 |
| 换算成 token（⚠️ 平均长度按 10³ token/条估） | 10⁶ ~ 10⁷ token | 10⁹ ~ 10¹⁰ token |
| 它**教不会**什么 | 能力 | **也教不会能力**——只是把"格式"覆盖到了更多域 |

**一个 2026 年的实际数字**（✅ Nemotron 3 Super 报告，[arXiv:2604.12374](https://arxiv.org/abs/2604.12374)，NVIDIA，2026-04）：**SFT 阶段 700 万样本，覆盖 15+ 个数据域**（竞赛数学 / 代码 / 软件工程 / 智能体编程 / CUDA / 金融推理 / 长上下文 / 安全 / 搜索 / 终端使用 / SQL / …）。

**另一个可以逐步验算的实际数字**（✅ DeepSeek-R1 报告，[arXiv:2501.12948](https://arxiv.org/abs/2501.12948)，**论文 §B.3.3**）：

| 项 | 数值 | 出处 / 算法 |
|---|---|---|
| 推理类样本 | 约 **60 万**条 | ✅ 论文原文 "about 600k reasoning-related training samples" |
| 非推理类样本（写作、事实问答、自我认知、翻译） | 约 **20 万**条 | ✅ 论文原文 "approximately 200k training samples that are unrelated to reasoning" |
| **合计** | **80 万**条 | ✅ 论文称之为 "800K Supervised Data" |
| 换算成 token | 约 **1.6×10⁹** | ⚠️ 这一行是我算的：80 万 × 约 2000 token/条。平均长度是**估的**，论文没给 |
| 相对预训练（14.8 T token） | 小约 **四个**数量级 | ⚠️ 除法是我做的，口径见 [01.3](01-鸟瞰全景.md) |

> ⚠️ **别把这两个流派当成"谁对谁错"。** 正确的读法是：**教格式用几千条就够（LIMA 是对的），教能力覆盖要几百万条（工业界是对的），而"教能力"这件事 2026 年主要不靠 SFT 了，靠 RL。**

## 2.4 几个必须调对的旋钮

### ★★ 超参量级总表

> ⚠️ **口径声明（很重要）**：「典型值」一列是**经验范围**，不是规范，不是任何一家的官方推荐。只有「一手披露」一列标 ✅ 的才是论文里的原值。各家数据分布、模型尺寸、并行方式都不同，**照抄别人的超参是 SFT 最常见的失败原因之一**。

| 旋钮 | 典型值（⚠️ 经验范围） | 为什么是这个量级 | 一手披露的参照 | 调错的现象 |
|---|---|---|---|---|
| **学习率** | 1×10⁻⁵ ~ 5×10⁻⁵ | 见下面那一小节——**核心是"位移预算"，不是"数据少"** | ✅ R1 冷启动 / 第二阶段 SFT：**5×10⁻⁵ 余弦衰减到 5×10⁻⁶**（论文 §B.4.2） | 太高 → 灾难性遗忘，通用能力崩塌；太低 → 学不进格式，输出里还有 base 的续写味 |
| **学习率调度** | 余弦衰减到初值的 **1/10**（有时 1/100） | 末期学习率必须很低，否则模型在最优点附近震荡，存下来的 ckpt 是随机抽的一个震荡点 | ✅ R1 SFT 衰到 1/10；✅ R1 蒸馏也是"衰到初值的 1/10"（论文 §B.4.3） | 不衰减 → 同一次训练里不同 step 的 ckpt 分数能差几个点 |
| **warmup（预热）** | 总步数的 **0% ~ 5%**，或固定几十到一两百步 | **机制**：AdamW 的二阶动量 `v` 在最初几十步还没估准，此时 `m̂/√v̂` 会异常大，等效学习率远高于设定值 ⟹ 要先用小 lr 把 `v` 养起来。预训练总步数十万级、warmup 开 2000 步；SFT 总步数只有几千级，按同样比例就是**几十到一两百步** | ⚠️ 各家不同，R1 报告未披露 SFT 的 warmup | 完全不 warmup → 前几十步 loss 尖峰，严重时直接训崩 |
| **epoch** | **1 ~ 3** | 后训练数据量小，过几遍就开始记原文而不是学模式 | ✅ R1 冷启动与第二阶段 SFT 都是 **2~3 个 epoch**（论文 §B.4.2）；⚠️ Nemotron-Cascade 2 把所有样本打包成长序列做单阶段训练时，约 **1.5 个 epoch** 最优（arXiv:2603.19220） | 多了 → 回答变模板化、句式雷同、输出多样性坍塌（★ 这会直接毁掉后面的 RL，见 2.5 病三） |
| **全局 batch size** | **64 ~ 512 条**（token 口径 2²⁰ ~ 2²² token/步） | 太小 → 梯度噪声大，格式学得慢且不稳；太大 → 同样 epoch 下总步数变少，等效于学习率要同步上调 | ✅ R1 SFT：**128 条**（论文 §B.4.2）；✅ R1 蒸馏：**64 条**（论文 §B.4.3） | ⚠️ **口径坑**：R1 的 128 是**条**不是 token。32768 最大长度下 128 条的上界是 128 × 32768 = **4.19 M token/步**，但实际远小于此（多数样本短得多） |
| **最大序列长度** | 8K ~ 32K（有长 CoT 数据时必须往上走） | 长 CoT 样本动不动几千 token，截断就学不完整 | ✅ R1 SFT 与蒸馏都是 **32,768**（论文 §B.4.2 / §B.4.3） | ★ **一个很具体的坑**：被截断的样本结尾没有 `<\|im_end\|>`，模型从这些样本里学到的恰好是"不用停" |
| **是否冻结** | 默认**全参不冻结**；词表很大时有人冻结 embedding 和 lm_head | 这两层在小模型里能占参数量的 20%+，而 SFT 并不需要改词表的语义 | ⚠️ 未见一手报告披露冻结策略 | 冻结太多 → 学不进格式 |
| **packing（把多条短样本拼成一条长序列）** | 开，**且必须配文档级注意力掩码** | 不开掩码时样本 A 会"看到"样本 B 的内容 | — | ★★ 串味，而且不报错。详见 [../数据格式和数据处理/13-打包与文档掩码.md](../数据格式和数据处理/13-打包与文档掩码.md) |
| **长上下文分阶段** | 先在 32K 长度训一轮，再在 256K 长度训第二轮 | 长序列每步更贵，先在短长度上把格式打牢更划算 | ✅ Qwen3-VL 的公开做法；⚠️ 具体长度各家不同 | — |

### ★★★ 为什么 SFT 的学习率要比预训练低一个数量级

**⚠️ 先排除一个常见的错误解释：不是"因为数据少所以学习率要小"。** 真正的原因是**要避免破坏预训练已经学到的表示**。下面把这件事算出来。

**第一步：在 Adam / AdamW 下，"学习率"几乎就等于"每步每个参数走多远"。**

```
AdamW 的更新量：  Δθ = − lr · m̂ / (√v̂ + ε)

   m̂ 是梯度的一阶动量（滑动平均），√v̂ 是二阶动量的平方根（梯度幅度的滑动均方根）

★★ 当梯度方向比较稳定时， m̂ / √v̂ ≈ ±1
   ⟹ |Δθ| ≈ lr      —— 和梯度【大小】几乎无关！

★ 这是 Adam 和 SGD 最大的区别：
  SGD 的步长 = lr × 梯度大小（梯度小就走得少）
  Adam 的步长 ≈ lr      （梯度小也照样走这么远）

⟹ 所以在 Adam 下，「学习率」可以直接读成「每一步的位移预算」。
```

**第二步：把位移预算和"权重自身有多大"比一遍。**（⚠️ 下表是数量级估算，不是实测；权重标准差取 0.02 这个常见量级，真实值各层不同。）

| 配方 | 学习率 | 跑 2000 步，位移上界 `N·lr`（最坏情况：梯度全程同向） | 随机游走估计 `√N·lr`（更接近实际） | 游走估计 ÷ 权重尺度 0.02 | 判定 |
|---|---|---|---|---|---|
| ❌ 把预训练峰值学习率照搬过来 | 3×10⁻⁴ | 0.60 | 1.34×10⁻² | **0.67 倍** | ❌ 两千步就把权重挪了自身尺度的六成——**这是在重写表示，不是在微调** |
| ✅ 典型 SFT | 2×10⁻⁵ | 0.040 | 8.9×10⁻⁴ | **0.045 倍** | ✅ 只挪 4.5%，够改"出场姿势"，不至于动到底层表示 |
| ✅ R1-Zero 的 RL 阶段（对照） | 3×10⁻⁶（✅ 论文正文披露） | 0.006 | 1.34×10⁻⁴ | 0.007 倍 | ✅ RL 要训上万步，所以单步预算还要再低一个数量级 |

★ **这张表最该记住的是"倍数关系和步数无关"**：3×10⁻⁴ ÷ 2×10⁻⁵ = **15 倍**，不管跑 2000 步还是 20000 步，位移都差 15 倍。差别只在于"15 倍之后是不是已经越界"——而上表说明：**用预训练的学习率，两千步就越界了。**

**第三步：还有两个让 SFT 必须更保守的机制。**

| 机制 | 说的是什么 | 为什么它让 SFT 的学习率必须**更低**（而不是更高） |
|---|---|---|
| **梯度方向高度一致** | 预训练语料极杂（网页、代码、书、论坛），不同样本的梯度方向互相抵消，实际位移远小于 `N·lr` 这个上界。SFT 数据分布极窄：同一个 chat template、相似句式、相似任务 | ⟹ **同样的学习率下，SFT 的有效位移比预训练大**。所以"SFT 步数少"**不是**可以用大学习率的理由，恰恰相反 |
| **没有后续数据来修复** | 预训练阶段某一步把某个表示搞坏了，后面还有 10¹² token 可以慢慢修回来 | SFT 只有 10⁹ 量级 token（[01.3](01-鸟瞰全景.md)），坏了就坏了。★ **这才是"数据少"真正起作用的地方——它的作用方向是"更要小心"** |

**第四步：一个一手披露的旁证——模型越大，学习率越小。**（✅ R1 报告**论文 §B.4.3 Table 6**，六个蒸馏模型的初始学习率）

| 可训参数量 | base 模型 | 初始学习率 ✅ |
|---|---|---|
| 1.5 B | Qwen2.5-Math-1.5B | 1×10⁻⁴ |
| 7 B | Qwen2.5-Math-7B | 8×10⁻⁵ |
| 8 B | Llama-3.1-8B | 5×10⁻⁵ |
| 14 B | Qwen2.5-14B | 7×10⁻⁵ |
| 32 B | Qwen2.5-32B | 6×10⁻⁵ |
| 70 B | Llama-3.3-70B-Instruct | 2×10⁻⁵ |

```
★ 趋势很清楚：参数量涨 47 倍（1.5B → 70B），学习率降 5 倍（1e-4 → 2e-5）
   ⚠️ 拟一下大约是 lr ∝ N^(−0.42)，但【这个指数是我从六个点凑出来的，论文没有给】。

⚠️ 而且它不是严格单调的：
   Llama-3.1-8B 用 5e-5，Qwen2.5-14B 反而用 7e-5
   ⟹ 跨模型家族不可比（base 的预训练配方不同）。
   ★ 所以这张表只能读出"大体趋势"，不能当公式用。
```

> 🔑 **最后把"低几个数量级"这件事说准**：预训练**峰值**学习率的经验范围是 1×10⁻⁴ ~ 4×10⁻⁴（⚠️ 经验范围，模型越大越小），SFT 的典型值是 1×10⁻⁵ ~ 5×10⁻⁵。**所以常见情形是低 1 个数量级左右（5~20 倍），小模型上能到 1~2 个数量级。** 和预训练**末期**的学习率（通常已衰到峰值的 1/10）相比，SFT 则是**大致同量级**。⚠️ "低一到两个数量级"这个说法在 7B 量级成立，在 R1 这种 671B 上并不成立（R1 的 SFT 用了 5×10⁻⁵，只比常见的预训练峰值低 4~8 倍）——**引用这类说法时请带上模型尺寸。**

### ★★ 还有一个更前面的旋钮：到底训多少个参数（全参 / LoRA / QLoRA）

**LoRA** = **Low-Rank Adaptation**（低秩适配）：**把基座权重整个冻住，只在每个被选中的线性层旁边挂一对小矩阵 `A`（d_in × r）和 `B`（r × d_out），前向时算 `Wx + BAx`，反向时只更新 `A` 和 `B`。** `r` 叫 rank（秩），取 8~64 最常见。**QLoRA** = **Quantized LoRA**：在 LoRA 的基础上，把**冻结的基座权重量化到 4 bit** 存放，用的时候再反量化回 BF16 参与计算。

**下面这笔显存账要能自己算出来，而不是记住"省很多"。先把配置钉死**（换模型就把 `7×10⁹` 替换掉，其余算法不变）：

```
模型      7B 稠密模型，取 Ψ = 7.0 × 10⁹ 参数；32 层，隐藏维度 d = 4096
精度      BF16 混合精度 + AdamW
LoRA 配置 rank r = 16，挂在全部 32 层的 q / k / v / o 四个投影上

LoRA 可训参数量 = 32 层 × 4 个投影 × (d × r + r × d)
                = 32 × 4 × (4096 × 16 + 16 × 4096)
                = 32 × 4 × 131,072
                = 16,777,216  ≈  1.68 × 10⁷   =  7B 的 0.24%
```

**逐项把"模型状态"的显存列出来**（⚠️ **只算模型状态，不含激活和 KV cache**；按十进制 1 GB = 10⁹ 字节）：

| 显存项 | 字节/参数 | 作用在谁身上 | **全参 SFT** | **LoRA** | **QLoRA** |
|---|---|---|---|---|---|
| 基座权重 | BF16 = **2**；NF4 4 bit = **0.5** | 全部 7×10⁹ | 2 × 7e9 = **14.0 GB** | **14.0 GB**（冻结也照样要放） | 0.5 × 7e9 = **3.5 GB** |
| 量化常数（双重量化） | 约 0.127 bit/参数 ⚠️ | 全部 7×10⁹ | — | — | **0.11 GB** |
| 可训权重 | 2 | LoRA 的 1.68×10⁷ | （已含在基座里） | 0.034 GB | 0.034 GB |
| **梯度** | 2 | 可训参数 | 2 × 7e9 = **14.0 GB** | 0.034 GB | 0.034 GB |
| **FP32 主副本** | 4 | 可训参数 | **28.0 GB** | 0.067 GB | 0.067 GB |
| **Adam m（一阶动量）** | 4 | 可训参数 | **28.0 GB** | 0.067 GB | 0.067 GB |
| **Adam v（二阶动量）** | 4 | 可训参数 | **28.0 GB** | 0.067 GB | 0.067 GB |
| **合计** | | | **112.0 GB** | **14.3 GB** | **3.9 GB** |

```
⚠️ 全参那一列最容易算错的一处：Adam 的 m 和 v 是【两个】各 4 字节/参数的 FP32 张量。
   漏掉一个，就会把 7B 的 112 GB 写成 84 GB。
   ★ 记住这个口径：BF16 权重 2 + 梯度 2 + FP32 主副本 4 + m 4 + v 4 = 16 字节/参数
     7B × 16 = 112 GB    ✓ 和上表合计对得上

★★★ 现在做一次减法，看 LoRA 到底省掉了什么：

   112.0 − 14.3 = 97.7 GB

   而「梯度 + FP32 主副本 + Adam m + Adam v」这四项作用在 7B 上是：
   (2 + 4 + 4 + 4) × 7 × 10⁹ = 14 字节/参数 × 7 × 10⁹ = 98.0 GB

   98.0 − 97.7 = 0.3 GB   ← 正好是 LoRA 自己那 1.68×10⁷ 参数的优化器状态

⟹ ★★★ 结论：【LoRA 省掉的是优化器状态和梯度（14 字节/参数），
            不是权重本身（那 2 字节/参数还老老实实躺在显存里）。】
   ⟹ 只有 QLoRA 才动了权重那 2 字节，把它压成 0.5。
```

**⚠️ 三件 LoRA 并没有省到的事**（这三条是"LoRA 便宜"这个印象里最常被误解的部分）：

| 没省到的 | 为什么 |
|---|---|
| **激活显存** | 要让第 1 层的 LoRA 拿到梯度，反向传播必须**穿过全部 32 层**，所以前向激活照样要存。激活显存只和 `batch × 序列长 × 层数 × 隐藏维度` 有关，和"训多少参数"无关。⟹ **长序列 + 大 batch 下，激活可能比模型状态还大，这时 LoRA 的省法就不显著了** |
| **前向 / 反向的矩阵乘计算量** | 穿过冻结层的矩阵乘照样要算，只是算完不更新。LoRA 的加速主要来自**优化器步变小**和**梯度通信量变小**，不是来自矩阵乘 |
| **QLoRA 的算力** | 4 bit 权重在参与计算前要**反量化回 BF16**，所以 QLoRA 省显存但**不省算力，还要额外付反量化的开销** ⟹ ⚠️ 典型说法是训练变慢，具体幅度取决于实现，**没有统一的数字可引** |

**三条路线的横向对照**：

| 维度 | **全参 SFT** | **LoRA** | **QLoRA** |
|---|---|---|---|
| 可训参数量 | 7.0×10⁹（100%） | 1.68×10⁷（**0.24%**） | 同 LoRA |
| 模型状态显存（7B） | **112 GB** | **14.3 GB** | **3.9 GB** |
| 单张 H100 80 GB 放得下吗（只看模型状态） | ❌ 至少 2 张且要切分 | ✅ 宽裕 | ✅ 很宽裕 |
| 教"格式 / 语气 / 拒答边界" | ✅ | ✅ 基本无差 | ✅ 基本无差 |
| 教"新领域知识 / 大幅能力迁移" | ✅ | ⚠️ 明显落后 | ⚠️ 明显落后 |
| 对原有通用能力的破坏 | ⚠️ 更容易灾难性遗忘 | ✅ 遗忘更少（冻住基座相当于自带正则） | ✅ 同 LoRA |
| 一个基座挂多套适配器 | ❌ 每套都是一份完整权重 | ✅ 每套只有几十 MB | ✅ 同 LoRA |
| **什么时候够用** | 要**改能力**、要把产出当 **RL 的起点**（见 2.5 病三） | 垂类对话、风格定制、多租户共用一个基座 | 显存只有单张消费级卡 |

> ⚠️ **"LoRA 教能力落后、但遗忘更少"这个结论的出处**：公开工作里最常被引用的是 **《LoRA Learns Less and Forgets Less》**（Dan Biderman 等，2024）。⚠️ **这篇的 arXiv 编号我在本次写作时无法联网回溯**（arxiv.org 抓取被网络策略拦截），所以这里**只给标题和作者、不给编号**，引用前请自行核实。本教程其余 arXiv 编号的核对口径见 [README](README.md)。
> 🔑 **一句话选型**：**要把 SFT 产物交给后面的 RL，就别用 LoRA。** 原因在 2.5 病三——RL 需要的是一个"输出还有多样性"的起点，而 LoRA 的低秩约束本身就在限制模型能走到的分布范围。⚠️ 这是推论，不是某篇论文的结论。

## 2.5 ★★ SFT 的三个"已知病"

**这一节是本章最有价值的部分。2025～2026 年的研究，系统性地指出了 SFT 这个范式本身的缺陷。**

> ⚠️ **本节所有百分数的口径提示**：下面引用的论文数字，原文有的给**相对变化**、有的给**百分点**，我没有逐条回到 PDF 核对是哪一种。**所以请把这些数字当"方向和量级"，不要当精确值**；真要引用请回一手论文确认口径。方向本身是确定的（哪个涨哪个跌），这是本节要传达的全部内容。

### 病一：它倾向于"背"，而不是"会"

✅ **SFT Memorizes, RL Generalizes**（[arXiv:2501.17161](https://arxiv.org/abs/2501.17161)，Tianzhe Chu 等，2025-01）

```
实验设计：造一个规则可变的纸牌算术游戏 + 一个视觉导航环境，
         训练时用规则 A，测试时换成规则 B（分布外，OOD = Out-Of-Distribution）

结果（⚠️ 口径见本节开头的提示）：
   SFT   → 分布外性能【下降】，幅度 8% ~ 80%
   RL    → 分布外性能【提升】，幅度 3% ~ 61%

★★ 而且：即使 SFT 用的是【带错误的次优轨迹】，这个模式依然成立
   ⟹ 说明"背"这件事来自【训练目标的结构】，不是数据质量问题
```

> ⚠️ **但论文自己也强调了另一半**：SFT 仍然是必需的——它稳定了模型的输出格式，**没有这一步，后面的 RL 根本训不起来**。
> ★ 这句话是理解 2026 年 SFT 定位的关键：**SFT 从"主角"变成了"给 RL 铺跑道的人"。**

### 病二：它的损失函数里藏着一个畸形的隐式奖励

✅ **On the Generalization of SFT: A Reinforcement Learning Perspective with Reward Rectification**（[arXiv:2508.05629](https://arxiv.org/abs/2508.05629)，Yongliang Wu 等，2025-08）

**这篇论文做了一件很漂亮的事：证明 SFT 其实是 RL 的一个特例。**

```
把 SFT 的梯度公式和策略梯度（policy gradient）公式并排放，会发现：

   SFT 的梯度  ≡  策略梯度，其中隐含的奖励 ∝ 1 / π_θ
                                              ↑
                                     模型当前对这个词的概率

翻译成人话：
   ★ 模型【越是想不到】的那个词，SFT 给它的"奖励"就【越大】
   ⟹ 一个模型觉得极不可能的 token，会得到一个爆炸性的梯度
   ⟹ 训练不稳、容易过拟合到个别怪样本
```

**为什么会这样，用一个 token 级的例子算一遍**（⚠️ 这是为讲解构造的数字）：

| 标准答案里的这个 token | 模型当前给它的概率 `π_θ` | SFT 的 loss = `−log π_θ` | 隐式奖励 ∝ `1/π_θ` | 这个 token 对本步梯度的贡献 |
|---|---|---|---|---|
| 一个很自然的常见词 | 0.50 | 0.69 | 2 | 正常 |
| 一个略意外的词 | 0.05 | 3.00 | 20 | 已经是上一行的 10 倍 |
| 一个标注员笔误 / 风格怪癖 | 0.001 | 6.91 | **1000** | ★★ **500 倍**——一个错标的 token 就能主导整批的梯度方向 |

⟹ ★★★ **所以 SFT 对"个别脏样本"的敏感度不是线性的，是 `1/π` 级的。** 这解释了一个很多人遇到过的现象：**SFT 数据里混进几十条格式怪异的样本，就能让整个模型的风格跑偏。**

**修法（DFT = Dynamic Fine-Tuning，动态微调）：一行代码。**

```
把每个 token 的 loss 乘上它自己的概率 π_θ，
把那个 1/π_θ 抵消掉，让所有 token 的权重变均匀。

✅ 论文报告：在 Qwen-2.5-Math 系列上，DFT 相比标准 SFT 收益成倍提升；
   标准 SFT 在 OlympiadBench / AIME 2024 / AMC 2023 上经常【掉分】，
   DFT 则稳定提升。
```

> ⚠️ 这是单一课题组在数学任务上的结果，尚未看到五家工业报告采用。**当成"重要的理论视角"，不要当成"必须换的配方"。**

### 病三：SFT 分数高，不等于是好的 RL 起点

✅ **Quagmires in SFT-RL Post-Training**（[arXiv:2510.01624](https://arxiv.org/abs/2510.01624)，Feiyang Kang 等，2025-10）

```
常规做法：SFT 训完，挑【评测分最高】的那个 ckpt 去做 RL

论文发现这个做法是错的（⚠️ 百分数口径见本节开头）：

   配方 A：少量样本 + 多 epoch + 大学习率
      → SFT 后 MATH-500 【+8.75】      看起来赢麻了
      → 但接着做 RL，最终反而 【−1.43】

   配方 B：更多样、不重复的数据
      → SFT 后分数【低 5 个点】         看起来很差
      → 接着做 RL，最终 【+5.94】       赢了

★★★ 原因：多 epoch + 大学习率会把模型【压得很尖】——
    输出多样性坍塌，RL 阶段没东西可探索，等于把路先堵死了。
```

**把"压得很尖"这件事和 RL 连起来**（这是全章最该想明白的一条因果链）：

| 步骤 | 发生了什么 | 为什么下一步成立 |
|---|---|---|
| ① 多 epoch + 大学习率 | 模型在每个位置上把概率质量集中到一个 token 上 | 这就是"过拟合"在 token 级的样子 |
| ② 输出分布的熵下降 | 同一道题采 8 次，8 条几乎一模一样 | 概率集中 ⟹ 采样结果趋同 |
| ③ RL 的组内优势退化 | GRPO 靠"同一组里谁对谁错"算优势；8 条全一样 ⟹ 全对或全错 ⟹ 优势全为 0 | 见 [05.2](05-RLVR-可验证奖励.md) 的 GRPO 公式：组内标准差为 0 时优势无定义 / 为 0 |
| ④ RL 学不到东西 | 梯度为 0，白跑 | ⟹ ★★ **SFT 阶段省下的那几个点，在 RL 阶段要赔回去好几倍** |

> 🔑 **实操结论（很硬的一条）**：**挑 SFT ckpt 的标准，不该是"SFT 后的评测分"，而该是"它做完 RL 能到多少"。实践中的代理指标是输出多样性 / 熵——宁可要一个分数低一点、但还"活着"的模型。** 怎么量这件事见 [10.3](10-评测与回归.md)。

## 2.6 SFT 还有存在的必要吗？

**2026 年有一派观点认为：SFT 不该是一个独立阶段。**

⚠️ 代表工作 **CHORD**（Qwen 团队）：把 SFT 重新定义为**在 on-policy RL 过程中的一个动态加权辅助损失项**，理由是——长时间在有限的专家数据上训练会过拟合，压低输出多样性，**严重限制后续 RL 的探索能力**（★ 就是 2.5 病三那条链）。

⚠️ 另一条证据来自多模态：有研究报告在 7 个多模态基准上，8B 模型 **SFT 之后反而掉了 5.2 个百分点**（63.3% → 58.1%），做完 RL 才刚回到基线（63.3%）——**意味着 RL 可能是在"还债"而不是"增益"**。（★ 这里 63.3 − 58.1 = 5.2 是**百分点**，不是相对百分比。）

```
⚠️ 我的判断：SFT 短期内不会消失，因为它解决的"格式与可控性"问题
   目前没有更便宜的替代品。但它的三个变化已经很清楚：

   ① 篇幅在缩短 —— 从"后训练的主体"变成"冷启动"
   ② 目标在改变 —— 从"拿高分"变成"给 RL 留足探索空间"
   ③ 边界在模糊 —— 越来越多方案把它和 RL 揉进同一个 loss 里
```

## 2.7 这一章的三句话总结

```
① SFT 机制上只做了一件事：把 loss 限制在 assistant 段。
   ★ 多轮对话里【每一轮】的 assistant 都要算，不是只算最后一轮。
   写错 loss mask 不会报错，只会让模型变怪。

② SFT 教得会【格式】，教不会【能力】。
   前者几千条就够，后者要靠 RL。
   ★ 学习率要比预训练低一个数量级，原因是「位移预算」
     —— 要避免重写预训练学到的表示，不是因为数据少。

③ 2026 年挑 SFT ckpt 的正确标准是"它做完 RL 能到多少"，
   而不是"它现在考几分"。多样性比分数重要。
   ★ 所以要给 RL 当起点的 SFT，别用 LoRA，也别多跑 epoch。
```
