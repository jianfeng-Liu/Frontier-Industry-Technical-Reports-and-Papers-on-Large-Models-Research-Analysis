03 · ⭐ 分训与合训：领域专家怎么造、怎么合回一个模型

这一章回答一个很具体的问题：从一个 base ckpt 出发，业界怎么先训出几个"领域专家"，再把它们变回一个模型？

★★ 这是 2026 年五家技术报告后训练章节的共同骨架。看懂这一章，那五份报告的第八章就都能读了。

⚠️ 本章新出现的缩写：RFT = Rejection sampling Fine-Tuning（拒绝采样微调）· STaR = Self-Taught Reasoner（自学推理器，拒绝采样这条路线的早期命名）· OPD = On-Policy Distillation（在策略蒸馏）· MOPD = Multi-expert On-Policy Distillation（多专家在策略蒸馏）· TIES / DARE = 两种参数空间合并方法的缩写（TIES = TrIm, Elect Sign & Merge；DARE = Drop And REscale）· GRPO = Group Relative Policy Optimization（组相对策略优化）· SOP = Standard Operating Procedure（标准作业流程）。其余缩写见 01 章开头和 附-速查表。

3.1 先把"分训"这个词拆成两种

中文里"分训"是个模糊的词，业界指的是第一种：

含义 A ── 并行分支（parallel per-domain training）   ★ 主流说法
                    ┌── 数学专家   ← 只喂数学数据 + 数学奖励
   base ckpt ──┬────┼── 代码专家   ← 只喂代码数据 + 代码奖励
        (同一份)│    ├── Agent 专家
               │    └── 通用专家
               │
               └────→ 合训 / 合并 → 上线模型

   ★★ 四个分支都从【同一个 base ckpt】出发，彼此独立、并行跑
   ★★ 分支模型【绝大多数不上线】


含义 B ── 串行分阶段（sequential / stage-wise）
   base ckpt → 通用训练 → 再拿代码数据接着训 → 上线
   ⚠️ 这个会【灾难性遗忘】（catastrophic forgetting）

为什么串行不行：一个被工业报告实锤的问题

✅ GLM-5 报告（arXiv:2602.15763，论文 §3.5）的原文是："In our multi-stage RL pipeline, sequentially optimizing for distinct objectives can lead to the cumulative degradation of previously acquired capabilities."（在我们的多阶段 RL 流水线里，顺序地优化不同目标会导致先前获得的能力累积性退化。）✅ 这句话是我从归档的 ../业界模型技术报告/papers/ 正文提取里逐字核对过的。

   GLM-5 的实际阶段顺序（✅ 报告披露）：

   SFT → Reasoning RL → Agentic RL → General RL
                                       ↑ 训到这里，前面 Reasoning 的能力已经掉了一截

   ★ GLM 的解法不是"别串行"，而是在最后【加一个阶段把丢掉的捡回来】—— 见 08 章
     ✅ 报告原文把这一步叫 "on-policy cross-stage distillation as the final stage"，
        目的是 "swiftly recover the skills acquired in earlier SFT and RL stages"。

为什么会遗忘（机制），分三层说：

# 机制 可以验算的部分
① 后训练的数据量远小于预训练，所以没有"后续数据"来把被覆盖的东西修回去 ⚠️ 按 token 算是小三到四个数量级，不是"六个"——"六个"那个说法是拿 10¹² token 除以 10⁶ 条，量纲不同。逐步算法见 01.3
② 学习率相对高，而且 Adam 下每步位移 ≈ 学习率，与梯度大小无关 位移预算的算法见 02.4：典型 SFT 学习率下两千步能把权重挪动自身尺度的几个百分点，若照搬预训练峰值学习率则能挪到六成
③ 串行阶段的数据分布互不重叠，梯度方向在阶段之间完全不同，参数会被最后一个阶段的数据整体"拽走" ★ 这一条是"串行"独有的。合训（所有域混在一起）时，各域梯度在同一次优化里互相制约，不存在"最后一个说话的人赢"

而且结果对顺序极度敏感——换个顺序结果完全不同，这意味着你没法做受控实验：你永远不知道某个域掉分是"这个域难"还是"它恰好排在了前面"。

3.2 ★★★ 分训到底在干嘛：四个用途

最反直觉的一点先说：分训的产物不是"要拼起来的零件"，分训主要是一次【实验】和一次【造数据】。

用途一：得到"单域天花板"，作为合训的参照系

⚠️ 下面这组分数是为讲解构造的，不是任何一次真实实验的结果。 要看的是算法，不是数值。

评测 单域分训的天花板 合训之后 绝对差（百分点） 相对差
GSM8K（小学数学应用题） 82 78 −4 个百分点 −4 / 82 = −4.9%
HumanEval（代码补全） 71 68 −3 个百分点 −3 / 71 = −4.2% 
★ 有了左边那一列，你立刻知道"混合的代价"是 4 个和 3 个百分点。
★ 没有这个参照，你只看到 78 分，
  根本不知道这是【配比没调好】还是【数据本身只值 78 分】。

⚠️ 注意上表两列差的写法：
   "掉 4 个百分点" 和 "相对掉 4.9%" 是两个不同的数，不能混着说。
   ★ 本教程约定：绝对差一律写【百分点】。见 01.3。

这个代价业界俗称 能力税。目标不是消灭它（消灭不了），是把它压到可接受范围。

用途二：探超参和数据量的边际收益

每个域的最优 epoch、学习率、数据量差别很大（见 02.4）。在单域上扫参，比在混合数据里扫一个全局参数便宜得多、也干净得多——混合数据里你永远分不清"分数变化"是哪个域造成的。

用途三：★ 专家模型当 teacher —— 这是分训最大的价值

数学专家模型（分训产物）
      │
      │ 对一道题采样 8 个答案
      ▼
   答案1 错   答案2 对   答案3 错   答案4 对  ...
      │
      │ 用验证器判对错（数学：比对标准答案；代码：跑单元测试）
      ▼
   只留正确的，挑最短/最清晰的一条
      ▼
   变成新的训练样本

这叫 拒绝采样（rejection sampling），也叫 RFT / STaR 路线，是 2024 年之后扩充后训练数据的主力手段。

★★★ 注意这条链路：分训模型的价值不是它的权重，是【它吐出来的数据】。

用途四：诊断——是数据问题还是基座问题

某个域【单域分训也拉不上去】
   ⟹ 不是配比的锅，是 base ckpt 里预训练/中期训练语料就缺
   ⟹ 正确动作是回去补语料，而不是在后训练里加数据

★ 这一条能省掉大量无效试错。

3.4 合训：为什么要回到原始 base

❌ 错误做法：base → 数学 → 代码 → 对话（串行接力）
   结果：最后一个域独大，前面的被覆盖，且换顺序结果全变

✅ 正确做法：把所有域的数据混在一起，从【原始 base ckpt】重新训一遍
   ★ 让所有域的梯度在【同一次优化】里竞争、达成平衡

这是分训/合训范式里最容易被误解的一点，也是最该记住的一句话。

配比怎么定：四步

① 均匀起步
   按每个域的可用数据量直接混，跑一版 baseline

② 单域消融（leave-one-out）
   抽掉某个域重训 → 看其他域涨了还是掉了
   ⟹ 找出【互相打架的域】。典型冲突对：
      · 安全数据 ↑ → 通用有用性 ↓（过度拒答）
      · 长思维链数学 ↑ → 简单对话变啰嗦
      · 单轮问答 ↑ → 多轮上下文跟随 ↓

③ 小模型代理实验（proxy model）
   用 1B~3B 的小 base 跑几十组配比，拟合「配比 → 各域分数」
   ⚠️ 外推到大模型不总是成立，只当先验用

④ 迭代补弱
   看能力矩阵里哪个域掉得最多 → 加权重 / 加数据 → 重训
   ★ 反复好几轮，是后训练最耗人力的地方

📎 配比的方法论（DoReMi、RegMix、混合定律）和预训练同源，
见 ../数据格式和数据处理/10-数据配比.md。
后训练阶段的差别是：数据量小、迭代快，所以【可以真的多试几轮】。

跷跷板效应（seesaw effect）

加了 A 域权重，B 域必掉。这是常态，不是 bug。

★★ 所以评测必须是【逐域回归的能力矩阵】，不能只看总分。
   总分不变，很可能是"数学涨 3、代码掉 3"。   → 10 章

两阶段合训（2026 年最主流的形态）

阶段 1：量
   百万级中等质量数据，覆盖全部域，2~3 epoch
   目标：把格式、角色、指令跟随打牢

阶段 2：退火（annealing）
   万级 ~ 十万级【人工精修 + 严格筛过】的高质量数据
   学习率衰到阶段 1 的 1/10 甚至更低，1~2 epoch
   目标：把回答风格、深度、细节质量拉上去

★ 直觉：阶段 1 教"怎么说话"，阶段 2 教"说得好听"。
★ 顺序不能反：高质量数据太少，先训会被后面的大批数据冲掉。

⚠️ 这和 3.1 说的"串行会遗忘"不矛盾：
串行的禁忌是"按域串"（每阶段只有一个域）；
按质量档位串是安全的，因为阶段 2 的数据仍然是全域的，且学习率很低。

3.5 工程细节：这些不做对，配比调得再准也白搭

① loss mask ★★★
   只在 assistant 的 token 上算损失。写错不会报错。（见 02.1）

② packing + 文档掩码
   拼样本时必须开文档级注意力掩码，否则样本间串味。
   → ../数据格式和数据处理/13-打包与文档掩码.md

③ 全局 shuffle，不要按域分桶 ★★
   一个 batch 全是数学、下一个全是代码 → 梯度方向来回摆
   ⟹ 训练不稳，且事实上退化成了"串行训练"

④ 长样本会让域权重跑偏 ★★
   Megatron 的 blend 权重作用在【样本】层面，但梯度是按 token 产生的。
   ⟹ 你按"条数"设的配比，和模型实际看到的"token 配比"不是一回事。
   ✅ 正确做法：先统计每个域的真实 token 总数，再反推权重（下面算一遍）

⑤ 分训在工程上就是 N 个独立 job
   同一个 --load <base_ckpt>，不同的 --data-path，并行提交。
   合训是一个 job，多个 data path 加权 blend。没有特殊机制。

★★ 把第 ④ 条算一遍：按「条」设的配比，实际是多少

⚠️ 下面的条数和平均长度是构造的例子，但每一步除法都能自己验算。 假设你设了"数学 10% / 代码 20% / 通用对话 70%"（按条数），总共 100 万条：

域 条数 平均长度（token/条） token 总量 你设的配比（按条） 模型实际看到的配比（按 token）
长思维链数学 10 万 4000 10万 × 4000 = 4.0×10⁸ 10% 4.0 / 9.9 = 40.4%
代码 20 万 1200 2.4×10⁸ 20% 2.4 / 9.9 = 24.2%
通用对话 70 万 500 3.5×10⁸ 70% 3.5 / 9.9 = 35.4%
合计 100 万 — 9.9×10⁸ 100% 100% 
★★★ 读出来的东西：
   你设的 10% 数学，模型实际看到的是 40.4% ——【高了四倍】
   你设的 70% 通用，模型实际看到的是 35.4% ——【只有一半】

⟹ 你以为在训一个"以对话为主、带点数学"的模型，
   实际在训一个"以长思维链数学为主"的模型。
   ★ 而这件事不会报任何错，只会让通用对话的回归分数莫名其妙掉下来。

反推：要让 token 配比真的是 10% / 20% / 70%，条数权重该设多少？

目标 token 占比 p_d，域内平均长度 L_d
   ⟹ 条数权重 w_d ∝ p_d / L_d        （先按长度折算，再归一化）

   数学：   0.10 / 4000 = 2.500 × 10⁻⁵
   代码：   0.20 / 1200 = 1.667 × 10⁻⁴
   通用：   0.70 /  500 = 1.400 × 10⁻³
   ───────────────────────────────────
   合计                 = 1.5917 × 10⁻³

   归一化后的【条数】权重：
   数学 2.500e-5 / 1.5917e-3 = 1.57%
   代码 1.667e-4 / 1.5917e-3 = 10.47%
   通用 1.400e-3 / 1.5917e-3 = 87.96%

验算一遍（每 100 万条）：

域 反推出的条数权重 条数 × 平均长度 = token token 占比 对上目标了吗
数学 1.57% 1.57 万 1.57万 × 4000 = 6.28×10⁷ 6.28 / 62.82 = 10.0% ✅
代码 10.47% 10.47 万 1.256×10⁸ 20.0% ✅
通用 87.96% 87.96 万 4.398×10⁸ 70.0% ✅
合计 100% 100 万 6.282×10⁸ 100% —

🔑 这件事的实操版本只有一句话：配比表里永远多写一列"该域的 token 总数"，并且以 token 列为准。 ⚠️ 顺带注意：token 总量 这一列在开了 packing（把多条短样本拼成定长序列）之后才是真正的"模型看到的量"，因为 packing 之后 padding 浪费几乎为零——没开 packing 时短样本会被 padding 撑成定长，实际浪费的那部分既不产生梯度也占着算力。packing 的细节见 ../数据格式和数据处理/13-打包与文档掩码.md。

3.6 ★★ 合并的三条路线

"把多个专家变成一个模型"有三种做法，分别在三个不同的空间里合并。 "空间"这个词是字面意思——合并这个动作具体作用在什么东西上：

路线一：数据空间 路线二：参数空间 路线三：函数空间
合的是什么 各个专家用的训练数据 各个专家的权重张量 各个专家的输出概率分布
具体做法 把所有域的数据混在一起，从原始 base 重训一遍（本章 3.4） 直接加权平均：
W_合 = 0.3·W_数学 + 0.3·W_代码 + 0.4·W_对话		 学生自己生成轨迹，在它写的每个 token 上向对应专家的输出分布对齐
代表方法 混合 SFT / 混合 RL Model Soup / Task Arithmetic / TIES / DARE On-Policy 蒸馏（OPD）★ 2026 年主流
一次要多久 ⚠️ 一次完整训练 ✅ 几分钟，可以试几十种组合 ⚠️ 比路线一还贵：要同时跑学生 rollout + 多个教师前向
效果 ✅ 最稳、可预期 ⚠️ 通常明显差一截；分支跑太远会直接崩 ✅ 最好，且能同时合并"能力"和"风格"
改配比要重做吗 ⚠️ 要重训 ✅ 换几个系数重算一次平均即可 ⚠️ 要重跑蒸馏
本教程 本章 3.4 下面这一小节 08 章的全部内容 
★ 一个帮助记住的类比：

   数据空间  = 把三个厨师的【食材】倒进一口锅，从头再炒一遍
   参数空间  = 把三个厨师的【肌肉记忆】直接做个平均
   函数空间  = 让一个学徒自己炒，每下一刀都问对应的师傅"你会怎么下"

⟹ 第二种听起来最省事，但"把三个人的肌肉记忆平均一下"
   本来就不该指望它还会炒菜。下面那一小节讲的就是这件事。

为什么参数空间合并（路线二）在工业界不是主线

✅ KAT-Coder-V2.5 报告（arXiv:2607.05471，Bo Huang 等，2026-07）说得最直白：

参数平均、Task Arithmetic、顺序多域 SFT 都会出现"跷跷板"——提升一个域就损害另一个。
原因：参数空间的合并破坏了专家特有的结构；离线监督又引入训推不匹配。
所以 MOPD 改在【函数空间】做融合。

✅ DeepSeek-V4 报告（arXiv:2606.19348，PDF 已归档在 ../业界模型技术报告/papers/）也给了同样的判断：权重合并会因为参数空间不对齐而失效；混合 RL 会让不同领域的奖励互相冲突。所以选 OPD——成本高，但效果最好。

⚠️ 参数合并的正确定位（不是没用）：
   它最常见的成功用法是【同一阶段多个 ckpt 的平均】——
   同一次训练不同随机种子、不同数据版本的几个 ckpt 平均，
   用来降方差、涨零点几分。
   ★ 用来【跨域合并】才是它不擅长的事。

路线三是 08 章的全部内容，那里会讲清楚 OPD 的机制和五家的不同用法。

3.7 五家 2026 年报告怎么做的

⚠️ 下表数字来自各家一手报告。其中 DeepSeek / Kimi / GLM / openPangu 这四家的逐项对照（教师怎么选、目标函数写成什么形式、教师概率从哪个引擎来）在 ../业界模型技术报告/模型技术对比.md 的「后训练」那一节里展开得更细。⚠️ 注意那一节的"五家"里第五家是 MiniMax，和本表的 Nemotron 不是同一组，两张表的第五列不可对照。

分了几个专家 分法 怎么合
DeepSeek-V4 数学 / 代码 / Agent 等 每个专家 = SFT + GRPO（专用奖励） OPD，全词表逆 KL loss
Kimi-K3 9 个 3 领域 × 3 档推理强度 MOPD，log 概率比当 RL reward
GLM-5 不分域专家 分阶段（SFT / Reasoning / Agentic / General） 跨阶段 OPD，log 比当 GRPO advantage
★ 目的是找回被后续阶段遗忘的能力
openPangu-2.0 4 个（Reasoning / General / Agentic / Code） 四路专家 RL Multi-Expert OPD，同 GLM 形式
Nemotron 3 Ultra 一个不断演进的教师面板 STEM / 对话 / 指令 / 终端 / SWE / 搜索 / 安全 / 编码… MOPD ×N 轮迭代 
★★ 读这张表最重要的一个观察：
   五家【分法各不相同】（按域 / 按档位 / 按阶段），
   但【合法高度一致】—— 全都是 on-policy 蒸馏。

⟹ 这说明"怎么分"还是各家的经验活，
   但"怎么合"在 2026 年已经收敛成了一个标准答案。

3.8 一份最小可执行 SOP

1. 把数据按能力域切好，统计每个域的【token 总数】（不是条数）
2. 每域各起一个 job，从同一 base 训 → 记录单域天花板 + 最佳超参
3. 天花板明显偏低的域 → 判断是缺数据还是基座缺语料
4. 用表现最好的分支做 teacher，拒绝采样扩充该域数据
5. 从 base 起合训：均匀配比 → 逐域回归评测 → 建能力矩阵
6. leave-one-out 消融找出打架的域，调权重，重训（2~4 轮）
7. 高质量数据退火：低学习率 + 小批精修数据，1~2 epoch
8. 进入 RL 阶段（04~07 章）；最后用 OPD 收口（08 章）

3.9 这一章的三句话总结

① 分训是【实验和造数据】，不是造零件。
   它的产物大多不上线，价值在于参照系、超参、和拒绝采样出来的数据。

② 合训必须【从原始 base 重新起】。按域串行接力一定遗忘；
   按质量档位串行（大批 → 精修退火）则是安全且主流的。

③ 合并有三个空间：数据空间（稳但贵）、参数空间（快但差）、
   函数空间（OPD，2026 年的标准答案）。
