# 03 · ⭐ 分训与合训：领域专家怎么造、怎么合回一个模型

> **这一章回答一个很具体的问题：从一个 base ckpt 出发，业界怎么先训出几个"领域专家"，再把它们变回一个模型？**
>
> ★★ 这是 2026 年五家技术报告后训练章节的**共同骨架**。看懂这一章，那五份报告的第八章就都能读了。

---

## 3.1 先把"分训"这个词拆成两种

**中文里"分训"是个模糊的词，业界指的是第一种：**

```
含义 A ── 并行分支（parallel per-domain training）   ★ 主流说法
                    ┌── 数学专家   ← 只喂数学数据 + 数学奖励
   base ckpt ──┬────┼── 代码专家   ← 只喂代码数据 + 代码奖励
        (同一份)│    ├── Agent 专家
               │    └── 通用专家
               │
               └────→ 合训 / 合并 → 上线模型

   ★★ 四个分支都从【同一个 base ckpt】出发，彼此独立、并行跑
   ★★ 分支模型【绝大多数不上线】


含义 B ── 串行分阶段（sequential / stage-wise）
   base ckpt → 通用训练 → 再拿代码数据接着训 → 上线
   ⚠️ 这个会【灾难性遗忘】（catastrophic forgetting）
```

### 为什么串行不行：一个被工业报告实锤的问题

```
✅ GLM-5 报告（arXiv:2602.15763）的原话大意：
   「多阶段 RL 顺序优化不同目标时，会【累积性地损害】先前获得的能力。」

   SFT → Reasoning RL → Agentic RL → General RL
                                       ↑ 训到这里，前面 Reasoning 的能力已经掉了一截

   ★ GLM 的解法不是"别串行"，而是在最后【加一个阶段把丢掉的捡回来】—— 见 08 章
```

**为什么会遗忘（机制）**：后训练的数据量比预训练小六个数量级，学习率却相对高。参数会被最后一个阶段的数据"拽走"，前面学的东西被覆盖。而且**结果对顺序极度敏感**——换个顺序结果完全不同，没法做受控实验。

## 3.2 ★★★ 分训到底在干嘛：四个用途

**最反直觉的一点先说：分训的产物不是"要拼起来的零件"，分训主要是一次【实验】和一次【造数据】。**

### 用途一：得到"单域天花板"，作为合训的参照系

```
数学单域训完：GSM8K 82 分
代码单域训完：HumanEval 71 分

合训完：GSM8K 78、HumanEval 68
        ↓
   ★ 你立刻知道"混合的代价"是 -4 / -3 分。
   ★ 没有这个参照，你只看到 78 分，
     根本不知道这是【配比没调好】还是【数据本身只值 78 分】。
```

这个代价业界俗称 **能力税**。目标不是消灭它（消灭不了），是把它压到可接受范围。

### 用途二：探超参和数据量的边际收益

每个域的最优 epoch、学习率、数据量差别很大（见 [02.4](02-SFT-监督微调.md)）。**在单域上扫参，比在混合数据里扫一个全局参数便宜得多、也干净得多**——混合数据里你永远分不清"分数变化"是哪个域造成的。

### 用途三：★ 专家模型当 teacher —— 这是分训最大的价值

```
数学专家模型（分训产物）
      │
      │ 对一道题采样 8 个答案
      ▼
   答案1 ✗   答案2 ✓   答案3 ✗   答案4 ✓  ...
      │
      │ 用验证器判对错（数学：比对标准答案；代码：跑单元测试）
      ▼
   只留正确的，挑最短/最清晰的一条
      ▼
   变成新的训练样本
```

这叫 **拒绝采样（rejection sampling）**，也叫 **RFT / STaR 路线**，是 2024 年之后扩充后训练数据的**主力手段**。

> ★★★ **注意这条链路：分训模型的价值不是它的权重，是【它吐出来的数据】。**

### 用途四：诊断——是数据问题还是基座问题

```
某个域【单域分训也拉不上去】
   ⟹ 不是配比的锅，是 base ckpt 里预训练/中期训练语料就缺
   ⟹ 正确动作是回去补语料，而不是在后训练里加数据

★ 这一条能省掉大量无效试错。
```

## 3.3 最典型的公开案例：DeepSeek-R1

✅ **DeepSeek-R1**（[arXiv:2501.12948](https://arxiv.org/abs/2501.12948)，2025-01；PDF 已归档在 [../harness评测框架/papers/](../harness评测框架/papers/)）

**这是"分训 → 造数据 → 回到 base 合训"这条链路最清楚的公开例子：**

```
DeepSeek-V3-Base
      │
      ├─→ R1-Zero（纯 RL，不做 SFT）           ← 探路性质的分支
      │
      ├─→ 冷启动 SFT → 推理 RL → 【推理专家】   ← teacher 性质的分支
      │         │
      │         └─→ 拒绝采样，生成 ~60 万条推理数据
      │                        + ~20 万条非推理数据
      ▼                              │
DeepSeek-V3-Base ←───────────────────┘
      │  ★★ 注意：回到【原始 base】，不是在专家模型上接着训
      └─→ 用这 80 万条重新 SFT（2 个 epoch）→ 再 RL → DeepSeek-R1
```

★ **这里的分支模型从头到尾没上线过。它唯一的作用是生产训练数据。**

## 3.4 合训：为什么要回到原始 base

```
❌ 错误做法：base → 数学 → 代码 → 对话（串行接力）
   结果：最后一个域独大，前面的被覆盖，且换顺序结果全变

✅ 正确做法：把所有域的数据混在一起，从【原始 base ckpt】重新训一遍
   ★ 让所有域的梯度在【同一次优化】里竞争、达成平衡
```

**这是分训/合训范式里最容易被误解的一点，也是最该记住的一句话。**

### 配比怎么定：四步

```
① 均匀起步
   按每个域的可用数据量直接混，跑一版 baseline

② 单域消融（leave-one-out）
   抽掉某个域重训 → 看其他域涨了还是掉了
   ⟹ 找出【互相打架的域】。典型冲突对：
      · 安全数据 ↑ → 通用有用性 ↓（过度拒答）
      · 长思维链数学 ↑ → 简单对话变啰嗦
      · 单轮问答 ↑ → 多轮上下文跟随 ↓

③ 小模型代理实验（proxy model）
   用 1B~3B 的小 base 跑几十组配比，拟合「配比 → 各域分数」
   ⚠️ 外推到大模型不总是成立，只当先验用

④ 迭代补弱
   看能力矩阵里哪个域掉得最多 → 加权重 / 加数据 → 重训
   ★ 反复好几轮，是后训练最耗人力的地方
```

> 📎 配比的方法论（DoReMi、RegMix、混合定律）和预训练同源，
> 见 [../数据格式和数据处理/10-数据配比.md](../数据格式和数据处理/10-数据配比.md)。
> **后训练阶段的差别是：数据量小、迭代快，所以【可以真的多试几轮】。**

### 跷跷板效应（seesaw effect）

```
加了 A 域权重，B 域必掉。这是常态，不是 bug。

★★ 所以评测必须是【逐域回归的能力矩阵】，不能只看总分。
   总分不变，很可能是"数学涨 3、代码掉 3"。   → 10 章
```

### 两阶段合训（2026 年最主流的形态）

```
阶段 1：量
   百万级中等质量数据，覆盖全部域，2~3 epoch
   目标：把格式、角色、指令跟随打牢

阶段 2：退火（annealing）
   万级 ~ 十万级【人工精修 + 严格筛过】的高质量数据
   学习率衰到阶段 1 的 1/10 甚至更低，1~2 epoch
   目标：把回答风格、深度、细节质量拉上去

★ 直觉：阶段 1 教"怎么说话"，阶段 2 教"说得好听"。
★ 顺序不能反：高质量数据太少，先训会被后面的大批数据冲掉。
```

> ⚠️ **这和 3.1 说的"串行会遗忘"不矛盾**：
> 串行的禁忌是**"按域串"**（每阶段只有一个域）；
> 按**质量档位**串是安全的，因为阶段 2 的数据仍然是**全域的**，且学习率很低。

## 3.5 工程细节：这些不做对，配比调得再准也白搭

```
① loss mask ★★★
   只在 assistant 的 token 上算损失。写错不会报错。（见 02.1）

② packing + 文档掩码
   拼样本时必须开文档级注意力掩码，否则样本间串味。
   → ../数据格式和数据处理/13-打包与文档掩码.md

③ 全局 shuffle，不要按域分桶 ★★
   一个 batch 全是数学、下一个全是代码 → 梯度方向来回摆
   ⟹ 训练不稳，且事实上退化成了"串行训练"

④ 长样本会让域权重跑偏 ★★
   Megatron 的 blend 权重作用在【样本】层面。
   长思维链数学样本平均 4000 token、闲聊样本 200 token
   ⟹ 你设的 10% 数学，实际 token 占比可能是 40%
   ✅ 正确做法：先统计每个域的真实 token 总数，再反推权重

⑤ 分训在工程上就是 N 个独立 job
   同一个 --load <base_ckpt>，不同的 --data-path，并行提交。
   合训是一个 job，多个 data path 加权 blend。没有特殊机制。
```

## 3.6 ★★ 合并的三条路线

**"把多个专家变成一个模型"有三种做法，分别在三个不同的空间里合并：**

```
┌─────────────────────────────────────────────────────────────┐
│ 路线一：在【数据空间】合并  —— 混合数据，从 base 重训         │
│    做法：本章 3.4                                            │
│    ✅ 最稳、效果可预期     ⚠️ 最贵，每次改配比都要重训        │
├─────────────────────────────────────────────────────────────┤
│ 路线二：在【参数空间】合并  —— 直接把权重加权平均             │
│    W_合 = 0.3·W_数学 + 0.3·W_代码 + 0.4·W_对话               │
│    方法：Model Soup / Task Arithmetic / TIES / DARE          │
│    ✅ 几分钟出结果，可以试几十种组合                          │
│    ⚠️ 效果通常明显差一截；分支跑太远会直接崩                  │
├─────────────────────────────────────────────────────────────┤
│ 路线三：在【函数空间】合并  —— On-Policy 蒸馏（OPD）★ 2026 主流│
│    学生自己生成轨迹，在它写的每个 token 上向对应专家的         │
│    输出分布对齐                                              │
│    ✅ 效果最好，且能同时合并"能力"和"风格"                    │
│    ⚠️ 贵（要同时跑学生 rollout + 多个教师前向）               │
└─────────────────────────────────────────────────────────────┘
```

### 为什么参数空间合并（路线二）在工业界不是主线

✅ **KAT-Coder-V2.5 报告**（[arXiv:2607.05471](https://arxiv.org/abs/2607.05471)，Bo Huang 等，2026-07）说得最直白：

> **参数平均、Task Arithmetic、顺序多域 SFT 都会出现"跷跷板"——提升一个域就损害另一个。**
> **原因：参数空间的合并破坏了专家特有的结构；离线监督又引入训推不匹配。**
> **所以 MOPD 改在【函数空间】做融合。**

✅ **DeepSeek-V4 报告**（[arXiv:2606.19348](https://arxiv.org/abs/2606.19348)，PDF 已归档在 [../业界模型技术报告/papers/](../业界模型技术报告/papers/)）也给了同样的判断：**权重合并会因为参数空间不对齐而失效；混合 RL 会让不同领域的奖励互相冲突。所以选 OPD——成本高，但效果最好。**

```
⚠️ 参数合并的正确定位（不是没用）：
   它最常见的成功用法是【同一阶段多个 ckpt 的平均】——
   同一次训练不同随机种子、不同数据版本的几个 ckpt 平均，
   用来降方差、涨零点几分。
   ★ 用来【跨域合并】才是它不擅长的事。
```

> **路线三是 08 章的全部内容**，那里会讲清楚 OPD 的机制和五家的不同用法。

## 3.7 五家 2026 年报告怎么做的

⚠️ 下表数字来自各家一手报告，详见 [../业界模型技术报告/模型技术对比.md](../业界模型技术报告/模型技术对比.md) §3.6。

| | 分了几个专家 | 分法 | 怎么合 |
|---|---|---|---|
| **DeepSeek-V4** | 数学 / 代码 / Agent 等 | 每个专家 = SFT + GRPO（专用奖励） | OPD，**全词表逆 KL loss** |
| **Kimi-K3** | **9 个** | 3 领域 × 3 档推理强度 | MOPD，**log 概率比当 RL reward** |
| **GLM-5** | 不分域专家 | **分阶段**（SFT / Reasoning / Agentic / General） | 跨阶段 OPD，**log 比当 GRPO advantage**<br>★ 目的是**找回被后续阶段遗忘的能力** |
| **openPangu-2.0** | **4 个**（Reasoning / General / Agentic / Code） | 四路专家 RL | Multi-Expert OPD，同 GLM 形式 |
| **Nemotron 3 Ultra** | 一个不断演进的**教师面板** | STEM / 对话 / 指令 / 终端 / SWE / 搜索 / 安全 / 编码… | **MOPD ×N 轮迭代** |

```
★★ 读这张表最重要的一个观察：
   五家【分法各不相同】（按域 / 按档位 / 按阶段），
   但【合法高度一致】—— 全都是 on-policy 蒸馏。

⟹ 这说明"怎么分"还是各家的经验活，
   但"怎么合"在 2026 年已经收敛成了一个标准答案。
```

## 3.8 一份最小可执行 SOP

```
1. 把数据按能力域切好，统计每个域的【token 总数】（不是条数）
2. 每域各起一个 job，从同一 base 训 → 记录单域天花板 + 最佳超参
3. 天花板明显偏低的域 → 判断是缺数据还是基座缺语料
4. 用表现最好的分支做 teacher，拒绝采样扩充该域数据
5. 从 base 起合训：均匀配比 → 逐域回归评测 → 建能力矩阵
6. leave-one-out 消融找出打架的域，调权重，重训（2~4 轮）
7. 高质量数据退火：低学习率 + 小批精修数据，1~2 epoch
8. 进入 RL 阶段（04~07 章）；最后用 OPD 收口（08 章）
```

## 3.9 这一章的三句话总结

```
① 分训是【实验和造数据】，不是造零件。
   它的产物大多不上线，价值在于参照系、超参、和拒绝采样出来的数据。

② 合训必须【从原始 base 重新起】。按域串行接力一定遗忘；
   按质量档位串行（大批 → 精修退火）则是安全且主流的。

③ 合并有三个空间：数据空间（稳但贵）、参数空间（快但差）、
   函数空间（OPD，2026 年的标准答案）。
```
