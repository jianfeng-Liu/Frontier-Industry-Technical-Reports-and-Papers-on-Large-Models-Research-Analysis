# 04 · 偏好对齐：RLHF 与 DPO

> **RLHF** = **Reinforcement Learning from Human Feedback**（基于人类反馈的强化学习）
> **DPO** = **Direct Preference Optimization**（直接偏好优化）
>
> **这一章讲 2022～2024 年后训练的主线。** 读完你应该能回答：为什么 SFT 不够、非要上强化学习？奖励模型是怎么训出来的？以及——**为什么 DPO 火了两年之后，2026 年的工业报告里几乎看不见它了。**

---

## 4.1 为什么 SFT 不够：一个很具体的缺口

```
SFT 的数据是【问题 → 一个标准答案】。
它只能告诉模型："这样答是对的"。

但它【无法表达】下面这件事：

   问："帮我写个删除文件的脚本"

   回答 A：给出 rm -rf 一行命令
   回答 B：给出命令，并提示先确认路径、建议加 -i

   两个都"对"。但 B 更好。
   ★★ SFT 没有任何机制表达"B 比 A 好"这个信息。
```

**要表达"更好"，你需要的数据形状不一样：**

```
SFT 数据：     { prompt, response }               ← 一条
偏好数据：     { prompt, chosen, rejected }        ← 一对，外加"谁赢"
```

★ 这个数据形状的改变，是整个 RLHF 体系的起点。

## 4.2 InstructGPT 的三步走（2022 年确立的范式）

✅ **Training language models to follow instructions with human feedback**
（[arXiv:2203.02155](https://arxiv.org/abs/2203.02155)，Long Ouyang 等，2022-03）

```
第一步：SFT
   人工写示范回答 → 监督微调                        （= 本教程 02 章）

第二步：训一个【奖励模型】RM（Reward Model）
   对同一个问题采样 4~9 个回答
        ↓
   人来排序：C > A > D > B
        ↓
   用这些排序训一个模型：输入(问题, 回答) → 输出一个分数
   ★ 这个模型在【模仿人的口味】

第三步：用 PPO 做强化学习
   模型生成回答 → RM 打分 → 分高的提概率、分低的降概率
        ↓
   ★ 加一个约束：别跑得离 SFT 模型太远（KL 惩罚）
```

### 奖励模型怎么训（Bradley-Terry，一句话版）

```
你有一对回答：chosen（人选的）和 rejected（人没选的）

训练目标：让 RM 给 chosen 的分【高于】给 rejected 的分
          具体形式：最大化 log σ( r(chosen) − r(rejected) )
                            ↑ sigmoid，把分差映射到 0~1 的"胜率"

★ 注意 RM 学的是【相对排序】，不是绝对分数。
  它输出的 3.7 分本身没有意义，只有和另一个回答比才有意义。
```

### 为什么要有 KL 惩罚（这一步很重要）

```
如果不加约束，RL 会找到 RM 的漏洞：

   RM 恰好偏好长回答
      ↓
   模型发现"写得越长分越高"
      ↓
   最终输出变成没有信息量的超长废话，但 RM 给它打 9.9 分

★★ 这叫【奖励攻击 reward hacking】，是 RL 后训练永恒的敌人 → 06 章

KL 惩罚 = "你可以变好，但不许离原来的自己太远"
   ⟹ 相当于给优化加了一根绳子
```

## 4.3 PPO 为什么难用

**PPO** = **Proximal Policy Optimization**（近端策略优化），是 InstructGPT 用的 RL 算法。

```
跑一次 PPO，内存里要同时装【四个模型】：

   ① 策略模型 π_θ        ← 正在训练的那个
   ② 参考模型 π_ref      ← SFT 后冻结的，用来算 KL 惩罚
   ③ 奖励模型 RM         ← 打分的
   ④ 价值模型 Critic     ← 估计"从这里往后大概能得多少分"

⚠️ ④ 是最麻烦的一个：它和策略模型一样大，要单独训，还很难训稳。
```

**PPO 的三个实际痛点**：

```
① 显存 4 份模型，训练成本高
② Critic 难训 → 训不好则优势估计有偏 → 整个训练崩掉
③ 超参极其敏感，复现困难（2023 年这是公开的痛）
```

★ **后面所有算法演进，几乎都在解决"怎么把这四个模型减掉几个"。**

## 4.4 DPO：把 RL 整个拆掉

✅ **Direct Preference Optimization: Your Language Model is Secretly a Reward Model**
（[arXiv:2305.18290](https://arxiv.org/abs/2305.18290)，Rafael Rafailov 等，2023-05）

**DPO 做的事，用一句话说：**

> **数学上可以证明，"训一个 RM 再用 PPO 优化它"这个两步流程，等价于在偏好数据上直接做一个类似监督学习的损失。既然等价，那就跳过中间步骤。**

```
PPO 路线：偏好数据 → 训 RM → rollout → RM 打分 → PPO 更新
                              ↑ 贵、慢、要四个模型

DPO 路线：偏好数据 → 【直接一个 loss】更新模型
                     ↑ 只要两个模型（策略 + 参考），不用 rollout，不用 RM

★ 训练代码复杂度和 SFT 差不多。
```

**DPO 的 loss 在直觉上做什么**：

```
对每一对 (chosen, rejected)：
   提高  chosen  的相对概率
   降低 rejected 的相对概率
   "相对"是相对参考模型而言的 —— 这就是隐式的 KL 约束

★ 你可以把 DPO 理解成"带方向的 SFT"：
  SFT 只会说"学这个"，DPO 会说"学这个，别学那个"。
```

**DPO 的影响**：门槛暴跌。2023～2024 年，开源社区的对齐几乎全线改用 DPO 及其变体（IPO、KTO、SimPO、ORPO…）。

## 4.5 ★★ 那为什么 2026 年的报告里几乎没有 DPO 了

**这是本章最值得记住的一段。DPO 有一个结构性的短板：它是 off-policy 的。**

```
DPO 的训练数据是【事先准备好的】一对对回答。
   ⟹ 这些回答不是模型【当前这一版】写出来的
   ⟹ 训着训着，模型已经变了，但数据还是老的
   ⟹ 数据里的 rejected 可能是模型早就不会犯的错误
      数据里的 chosen 可能是模型现在已经能超越的水平

★★ 结果：训到一定程度，DPO 就【没有信息可给了】。
```

**对比 on-policy 的 RL**：

```
on-policy：每一步都让【当前模型】重新生成，
           所以永远在学"我现在还不会的那部分"
           ⟹ 信号永远新鲜
```

> ⚠️ **我的判断**：DPO 没有"被证伪"，它在**数据便宜、算力紧张、只做风格对齐**的场景仍然完全够用（开源微调、垂类模型、小团队）。
> **它退出前沿报告的原因是：前沿的瓶颈已经不是"风格对齐"了，而是"能力"，而能力必须靠 on-policy 的试错才能长出来。**

**一个折中的实践**：**迭代式 DPO（iterative DPO）**——每训一轮就用**当前模型**重新采样、重新排序、重新构造偏好对。★ 这本质上是在**把 DPO 往 on-policy 拉**，也再次印证了 [01.4](01-鸟瞰全景.md) 那条趋势。

## 4.6 RLHF 在 2026 年的位置：没消失，变成了最后一段

**五家报告里 RLHF 仍然在，只是位置变了：**

```
2022：  SFT → RLHF                              ← RLHF 是全部
2026：  SFT → RLVR → Agentic RL → 【RLHF】→ OPD  ← RLHF 是收尾的一段

✅ 一个具体例子（Nemotron 3 Super，arXiv:2604.12374）：
   RL 阶段 = Stage 1 多环境 RLVR
           → Stage 2 SWE-RL（软件工程专项）
           → Stage 3 【RLHF】
   ★ RLHF 排在最后，负责"可验证奖励管不到的那部分"
```

**RLHF 现在负责的是这些**：

```
· 语气、人格、写作质量
· 安全与拒答边界
· 指令遵循的细节（"用三点回答"这种）
· 帮助性 vs 无害性的权衡
—— ★ 共同点：这些【没有客观对错】，只能靠人的偏好定义
```

## 4.7 两个必须知道的副作用

### ① 对齐税（alignment tax）

```
安全对齐做得越狠，通用有用性掉得越多。

   ⟹ 模型开始拒答无害问题（"怎么杀死一个进程" → 拒绝）
   ⟹ 回答变得啰嗦、免责声明堆砌

⚠️ 2026 年有工作把它形式化成【持续学习问题】，
   用正交梯度投影来减轻（arXiv:2602.07892，Safety Alignment as Continual Learning）。
   ⚠️ 学术工作，未见工业报告采用。
```

### ② 打分的人正在被模型替代（RLAIF）

✅ **Constitutional AI: Harmlessness from AI Feedback**
（[arXiv:2212.08073](https://arxiv.org/abs/2212.08073)，Yuntao Bai 等，2022-12）

```
做法：给模型一份【原则清单】（"宪法"），
      让模型自己按原则批评和修改自己的回答，
      再用这些自我修订的结果训 RM。

★★★ 这是整条演进线上一个关键的转折点：
    【人从打分回路里被移出去了】。

⟹ 因为人不 scale。这句话是 11 章那条因果链的核心。
```

## 4.8 这一章的三句话总结

```
① SFT 只能说"这样是对的"，偏好数据才能说"这个比那个好"。
   RLHF 三步走（SFT → RM → PPO）是 2022 年确立的范式。

② DPO 把 RL 拆掉了，门槛暴跌，但它是 off-policy 的 ——
   数据会过期，训到后面就没信息可给。这是它退出前沿的原因。

③ RLHF 在 2026 年没消失，只是从"全部"变成了流水线最后一段，
   负责可验证奖励管不到的东西：语气、安全、写作。
```
