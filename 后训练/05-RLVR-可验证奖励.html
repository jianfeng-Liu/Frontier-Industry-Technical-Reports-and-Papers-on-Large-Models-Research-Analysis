05 · ⭐ RLVR：可验证奖励强化学习

RLVR = Reinforcement Learning with Verifiable Rewards（可验证奖励的强化学习）
一句话：奖励不再来自"人喜不喜欢"，而来自"答案对不对"。

这是 2025 年之后后训练的主线。 读完你应该能回答：GRPO 到底怎么算的？为什么它需要那么多变体来打补丁？"可验证"的边界在哪？以及那个吵了一年多的问题——RL 到底有没有让模型变得更聪明，还是只是让它把会的题答得更稳？

读法：5.2 和 5.4 两节有可以拿计算器跟着按一遍的推演表，按过一遍的数字才会变成直觉。

本章关键词（每个缩写第一次出现都给中英文全称）

RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励的强化学习）—— 用一段程序而不是人或神经网络来判分的强化学习。

GRPO（Group Relative Policy Optimization，组相对策略优化）—— 本章的主算法。靠"同一道题采多条、用组内平均分当基线"删掉了 PPO 的 Critic。

PPO（Proximal Policy Optimization，近端策略优化）—— 2022 年 RLHF 用的标准算法，需要四个模型，机制见 04 章 4.3。

Critic（评论家 / 价值网络）—— PPO 里专门估"这个局面一般能得几分"的那个网络。GRPO 把它删了。

优势 A（Advantage）—— "这一条比平均好多少"。正数就提高这条路的概率，负数就压低。

rollout（采样）—— 让模型真的跑一遍、产出一条完整轨迹。RL 里最贵的一步。

熵（Entropy）—— 模型输出的不确定性 / 多样性。熵掉到 0 意味着它每次都写同一个答案。

pass@k —— 让模型答 k 次，至少一次对的概率。衡量"能力边界"的指标。

clip（截断）—— 一根安全绳：单步更新里，新旧概率的比值不许超出 [1−ε, 1+ε]。

KL 惩罚（Kullback-Leibler penalty）—— "别离原模型太远"的罚款，为什么需要它见 6.4。

5.1 换掉奖励来源，是一次范式转移

RLHF 的奖励：  一个【训出来的奖励模型】说了算
   ⚠️ 问题：RM 是个神经网络，它会被骗（reward hacking）→ 6.4
   ⚠️ 问题：RM 的口味来自标注员，天花板就是标注员的水平
   ⚠️ 问题：标注员的产能就是数据量的上限。人不 scale。

RLVR 的奖励：  一个【程序】说了算
   数学题 → 把最终答案和标准答案做数值/字符串比对  → 0 或 1
   代码题 → 跑单元测试                            → 0 或 1
   格式   → 正则匹配 <think>...</think> 结构       → 0 或 1

   ✅ 不会被骗（至少难得多，边界见本节末）
   ✅ 不要人参与，可以无限次、近乎零成本地判
   ✅ 天花板是【题目本身的正确性】，不是标注员的水平

★★★ 这一步的意义，怎么强调都不为过：它把"人"从训练回路里彻底移了出去。
一旦不需要人打分，RL 的规模就只受算力限制了。这是 2025 年推理模型集体爆发的直接原因。

★★ 先把"可验证"的边界划清：它要同时满足三个条件

这一小节很重要，因为它决定了 RLVR 能干什么、不能干什么。 一个任务要算"可验证"，必须同时满足：

条件 ①  答案判定明确   —— 对错不取决于谁来看
条件 ②  判定是纯程序   —— 判分过程里【没有神经网络】
条件 ③  判定足够便宜   —— 判分成本 << 生成成本，否则判分自己就成了瓶颈
任务 ① 判定明确 ② 纯程序可判 ③ 判分比生成便宜 结论
数学题最终答案（填一个数） ✅ ✅ 数值比对 ✅ 微秒级 ✅ 可验证
单位换算 / 日期计算 ✅ ✅ ✅ ✅ 可验证
代码通过给定单测 ✅ ✅ 跑测试 ✅ 秒级 ✅ 可验证，⚠️ 但"过测试"≠"写对"（见下）
输出结构格式（标签在不在） ✅ ✅ 正则 ✅ ✅ 可验证，但它只约束形状，不约束内容
SQL 查询结果对不对 ✅ ✅ 真库上执行再比对 ✅ 秒级 ✅ 可验证
多步任务"最终状态对不对" ✅ ✅ 跑最终检查 ⚠️ 分钟级，已经和生成成本同量级 ⚠️ 勉强可验证，③ 快要破了 → 07 章
数学证明写得对不对 ⚠️ 等价写法无穷多 ✗ 除非先形式化（Lean 一类） ✗ ✗ 一般不可验证
代码真的写对了（不只是过测试） ✗ 要对无穷多输入成立 ✗ ✗ ✗ 不可验证
翻译质量 ✗ ✗ ✗ ✗ 不可验证
文章"写得好不好" ✗ 纯主观 ✗ ✗ ✗ 不可验证 
★★★ 把这张表竖着读，会看到一条结构性的天花板：

   RLVR 能训的任务集合
        = 你能写出验证器的任务集合
        ⊂ 答案可判定的任务集合
        ⊊ 人们真正想让模型做的任务集合

⟹ 所以 RLVR 有一条【和算力、和模型大小都无关】的上限：
   你给它再多卡，它也只能在"写得出验证器"的那片区域里变强。
   ★ 这就是"RLVR 的适用面就是它的天花板"这句话的确切含义。

⟹ 这也解释了一个很多人注意到的现象：
   2025～2026 年的模型在 AIME、竞赛编程上进步极快，
   在"写一份让人满意的报告"上进步慢得多。
   ⚠️ 这两类任务不在同一片区域里，用的奖励根本不是一回事。
   ⟹ 完整的"可验证程度谱"在 6.5 节。

⚠️ 可验证 ≠ 不可钻

"程序判分"去掉的是【裁判被说服】这个攻击面，
它没有去掉【裁判没检查到的地方】这个攻击面。

最干净的例子：
   任务：  实现 double(x)，返回 2x
   验证器：assert double(1)==2 / double(5)==10 / double(0)==0

   模型可以交出：
      def double(x):
          if x == 1: return 2
          if x == 5: return 10
          return 0
   ⟹ 三条断言全过，奖励 1.0，代码是错的。

★★ 为什么优化器一定会找到这条路：
   "写通用算法"要对无穷多输入成立 —— 这是个推理任务；
   "写查表硬编码"只要对上下文里那 3 个输入成立 —— 这是个抄写任务。
   ⟹ 抄写的成功率远高于推理，所以抄写那条路的【奖励期望更高】。

⟹ ★ 结论：验证器的质量，就是 RLVR 的质量上限。
   ✅ 这件事有实证：LLMs Gaming Verifiers（arXiv:2604.15149）发现
      RLVR 模型会系统性地放弃"归纳出规则"而改走捷径，
      换成同构验证后捷径消失。完整讨论在 6.4 节「钻法三」。

✅ R1 的证明：只用"答案对不对"这一个信号，能走多远

✅ DeepSeek-R1（arXiv:2501.12948，2025-01；PDF 已归档在 ../harness评测框架/papers/）证明了一件之前很多人不信的事：

不需要任何"人写的推理过程"数据，只用"答案对不对"这一个信号做 RL，模型自己就能长出复杂的思维链。

R1-Zero 的配方有多简单，看它的奖励函数就知道（✅ 论文 §2.2）：

Reward_rule = Reward_accuracy + Reward_format      ← 就这两项，【等权相加】

   Reward_accuracy ：答案放在指定位置（比如 \boxed{}）里，
                     程序比对数值。对 = 有分，错 = 没分。
   Reward_format   ：推理过程有没有包在 <think>...</think> 里。正则一判。

✅ 论文 §2.2 的原话（这一句值得记住）：
   "we abstain from applying neural reward models
    —— whether outcome-based or process-based —— to reasoning tasks."
   （我们明确放弃在推理任务上使用神经奖励模型，不管是结果式还是过程式的。）

结果（✅ 以下四个数字全部来自论文 §2.3 与 Supplementary B.4.4 的 Table 7，都是披露值）：

项目 数值 出处
R1-Zero 在 AIME 2024 上的 pass@1：训练开始 15.6% ✅ 论文 §2.3
R1-Zero 在 AIME 2024 上的 pass@1：训练结束 77.9% ✅ 论文 §2.3
同一模型的 cons@16（16 条取多数投票） 86.7% ✅ 论文 §2.3
R1-Zero 这一段 RL 的总算力 101K H800 卡·时（报告按 $2/卡·时 折算 $202K） ✅ 论文 Supplementary B.4.4 的 Table 7 
★★ 15.6% → 77.9% 这个跨度要怎么读：

   ✅ 这是【pass@1 从 15.6 涨到 77.9】，也就是涨了【62.3 个百分点】。
   ⚠️ 换成相对口径是【涨了约 4 倍】（77.9 / 15.6 = 4.99，即提升近 400%）。
   ★ 百分点和百分比不是一个东西。这两个数字都对，但不能互相替换，
     也不能写成"提升了 62.3%"—— 那是第三个、错误的说法。

⟹ 而且这里面【没有一条人写的推理过程】。
   这就是为什么 R1 被当成一次范式转移的证据。

R1-Zero 的代价（✅ 论文正文明确承认）：
   ⚠️ 可读性差、中英文混杂（一条思维链里混着两种语言）
   ⟹ 所以正式版 R1 加了【冷启动 SFT】，
      并且专门补了一项【语言一致性奖励】（✅ 论文 §3.2.1）：
         Reward_language = 目标语言词数 / 总词数
   ⚠️ 论文也承认这一项会让性能【略有下降】，是为可读性付的税。

5.2 ★★ GRPO：一道题从采样到更新，完整走一遍

GRPO = Group Relative Policy Optimization（组相对策略优化）
✅ 出自 DeepSeekMath（arXiv:2402.03300，Zhihong Shao 等，2024-02），R1 用的就是它（✅ R1 论文 §2.1）。

它解决的是 04 章 4.3 那个痛点：把 PPO 的第四个模型（Critic）删掉。

Critic 是干嘛的，为什么能删

PPO 里 Critic 的作用：回答"这条轨迹算好还是算坏？"

   模型这次得了 7 分 —— 是好是坏？
   ⟹ 答不了。要先知道"这道题一般能得几分"。
   Critic 就是在估这个"一般能得几分"（术语叫 baseline，基线）。

⚠️ 代价：Critic 是第四个和策略一样大的网络。
   显存 ×、通信 ×、而且它自己也要训、也会训不准。

★★ GRPO 的洞察：
   既然只是要一个基线，那我【对同一道题多采几条，用这几条的平均分当基线】
   不就行了？—— 基线的定义本来就是"一般能得几分"。
   ⟹ Critic 删除。四个模型变三个（策略 / 参考 / 奖励）。

第一步：采样。取一道题，采 G 条回答

题目 q：  一道数学题，标准答案 17
采样设置：G = 8 条（为了手算清楚；✅ R1-Zero 真实用的是 G = 16，论文 §2.1）
轨迹 i 这条回答干了什么 验证器判定 奖励 r_i
1 4×3=12，12+5=17 ✅ 对 1
2 5+3=8，8×4=32 ✗ 错 0
3 4×3=12，12−5=7 ✗ 错 0
4 3 袋共 12 个，加 5 得 17 ✅ 对 1
5 (5+3)×4=32 ✗ 错 0
6 先算 3×4=12，再 +5=17 ✅ 对 1
7 5×3+4=19 ✗ 错 0
8 5+3+4=12 ✗ 错 0 
奖励向量：r = [1, 0, 0, 1, 0, 1, 0, 0]      ← 3 对 5 错

第二步：算基线。均值和标准差，一步一步算

① 均值 μ = (1+0+0+1+0+1+0+0) / 8 = 3 / 8 = 0.375

② 每条和均值的差：
      对的三条（i = 1,4,6）：1 − 0.375 = +0.625
      错的五条（i = 2,3,5,7,8）：0 − 0.375 = −0.375

③ 平方再求和：
      3 × (0.625)² = 3 × 0.390625 = 1.171875
      5 × (0.375)² = 5 × 0.140625 = 0.703125
      合计 = 1.875

④ 方差 = 1.875 / 8 = 0.234375
   标准差 σ = √0.234375 = 0.484123...   ≈ 0.4841

第三步：算优势。这就是"组内相对"的全部含义

优势公式（✅ R1 论文 §2.1 的式 (3)，一字不差）：

      A_i = ( r_i − mean(r) ) / std(r)
轨迹 i r_i r_i − μ ÷ σ 优势 A_i 对这条轨迹的所有 token 做什么
1 1 +0.625 ÷0.4841 +1.291 提高这些 token 的概率
2 0 −0.375 ÷0.4841 −0.775 降低这些 token 的概率
3 0 −0.375 ÷0.4841 −0.775 降低
4 1 +0.625 ÷0.4841 +1.291 提高
5 0 −0.375 ÷0.4841 −0.775 降低
6 1 +0.625 ÷0.4841 +1.291 提高
7 0 −0.375 ÷0.4841 −0.775 降低
8 0 −0.375 ÷0.4841 −0.775 降低

自己验算一下这张表对不对，用一个很好用的性质：

组内所有优势之和，必须恰好是 0。

   3 × (+1.291) = +3.873
   5 × (−0.775) = −3.875
   两者相加 = −0.002，约等于 0（差的 0.002 是四舍五入造成的）

★ 为什么必然是 0？因为分子是 Σ(r_i − μ)，而 μ 就是 r 的均值，
  "每个数减去均值再求和"恒等于 0。分母 σ 是个常数，提得出来。

⟹ ★★ 这个性质就是"相对"二字的数学含义：
   GRPO 从不判断一条轨迹【绝对】好不好，
   它只说【在这 8 条里，你排在平均线的哪一侧】。
   ⟹ 组里有一半人被提高，就必然有一半人被压低。

⚠️ 这里埋着 GRPO 最大的软肋

★ 一条轨迹里的【每一个 token】都用同一个 A。

   以轨迹 2 为例：它写了"5+3=8"（第 1 步就错了），然后"8×4=32"。
   A = −0.775 会被【平均地摊到这条轨迹的每一个 token 上】，
   包括开头那句无害的"我们来一步一步算"。

   ⟹ 正确的 token 和错误的 token 拿到了完全一样的惩罚。

这就是【结果奖励】的代价 —— 它不做信用分配（credit assignment）。
   ⟹ 为什么不上过程奖励来修它？→ 6.2 节（答案是：试过，更糟）
   ⟹ 在 40 轮的长任务里这件事会被放大到极致 → 7.6 节

第四步：更新。clip 到底在干什么，逐 token 算一遍

GRPO 的目标函数（✅ R1 论文 §2.1 式 (1) 的口语版）：

最大化：  min( 比值 × A ,  clip(比值, 1−ε, 1+ε) × A )   −   β · KL(π_θ ‖ π_ref)
              ↑              ↑                               ↑
        比值 = 当前概率        截断：比值不许超出            别离原模型太远
               ÷ 采样时概率    [1−ε, 1+ε]                   （β 就是 KL 系数）

取 ε = 0.2，也就是比值被限制在 [0.8, 1.2]。挑 5 个 token 算一遍：

来自 token 采样时概率 当前概率 比值 clip 后 A 比值×A clip×A min 取哪个 梯度
轨迹 1 "首先" 0.40 0.44 1.10 1.10（界内） +1.291 1.420 1.420 一样 ✅ 有，继续提高
轨迹 1 "4×3" 0.30 0.42 1.40 1.20（顶到上界） +1.291 1.807 1.549 clip 项 ✗ 归零（已涨够）
轨迹 1 "17" 0.80 0.76 0.95 0.95（界内） +1.291 1.226 1.226 一样 ✅ 有，继续提高
轨迹 2 "5+3" 0.50 0.35 0.70 0.80（掉到下界） −0.775 −0.543 −0.620 clip 项 ✗ 归零（已压够）
轨迹 2 "32" 0.25 0.33 1.32 1.20 −0.775 −1.023 −0.930 比值项 ✅ 有，继续压 
★★★ 把这张表的最后两列读懂，就真的懂 clip 了：

   min() 永远挑【数值更小】的那一项。
   · 挑到 clip 项 ⟹ 那一项里没有 θ（已经被常数截住）⟹ 梯度 = 0
   · 挑到比值项 ⟹ 梯度正常流

   于是规律是这样的（注意它【不对称】）：
      正优势 + 比值冲到 1.2 以上  → 截断，梯度归零  ("这个 token 已经涨够了")
      正优势 + 比值还低           → 不截断，继续推高
      负优势 + 比值掉到 0.8 以下  → 截断，梯度归零  ("已经压够了")
      负优势 + 比值还高           → 不截断，继续压低

★★ 所以 clip 的真实作用不是"限制更新幅度"，而是
   【给每个 token 设一个单步配额，达到配额就停手】。
   —— 这个理解是 5.4 节的全部前提，那一节会说明这个"配额"
      对高概率和低概率 token 极不公平。

这一步到底花多少钱：把 RLVR 最大的成本项算出来

RLVR 的钱几乎全花在"采样"上，而不是"更新"上。 用 R1-Zero 的真实配置把它算出来：

量 数值 来源
每道题采几条（G） 16 ✅ 论文 §2.1
每个训练步几道唯一题 32 ✅ 论文 §2.1
每步的轨迹数 32 × 16 = 512 推算（论文也直接写了 batch 512）
总训练步数 10,400 ✅ 论文 §2.1
单条最大长度 前 8.2k 步 32,768 token，之后 65,536 ✅ 论文 §2.1
跑了几遍数据 1.6 epoch ✅ 论文 §2.1
这一段 RL 的总算力 101K H800 卡·时 ✅ 论文 Supplementary B.4.4 的 Table 7

从这七行能自己推出来的四个数字：

① 总共生成了多少条轨迹
   10,400 步 × 512 条/步 = 5,324,800 条       ≈ 532 万条

② 一共用了多少道【唯一】题目
   10,400 步 × 32 题/步 = 332,800 题次
   332,800 ÷ 1.6 epoch  = 208,000 道唯一题    ≈ 20.8 万道
   ★ 注意这个量级：20 万道题，不是 2000 万道。
     RLVR 的"数据量"比 SFT 小得多 —— 贵的不是题，是采样。

③ 平均每条轨迹摊多少算力
   101,000 卡·时 × 3600 秒/时 = 363,600,000 卡·秒
   363,600,000 ÷ 5,324,800 条 = 68.3 【卡·秒 / 条】
   ⚠️ 这是把采样 + 训练 + 判分的【全部】开销都摊到轨迹上的粗算，
      不是纯采样成本。但量级是对的：一条轨迹 ≈ 一张卡忙一分钟。

④ ⚠️ 总生成量（这一条是估算，论文没披露平均输出长度）
   论文 Figure 1(b) 显示平均响应长度从几百 token 涨到接近 2 万。
   按全程平均 5,000 ~ 10,000 token 估：
      532 万条 × 5,000  ≈ 266 亿 token
      532 万条 × 10,000 ≈ 532 亿 token
   ⚠️ 标记为推断。★ 但它说明了一件事：
      RLVR 的一次训练要【生成】几百亿 token ——
      这已经是一个小型预训练语料的量级，而它们全部是一次性的。

⚠️ 量纲纪律：上面第 ③ 条是 卡·秒 ÷ 条，这个除法合法，结果读作"每条轨迹的卡·秒"。但不能接着写成"每条 X token"再去和卡·时比 —— token 和卡·时是两个计量体系，中间必须显式经过"每 token 多少 FLOPs"和"每卡多少 FLOPS"两次换算。本仓库抓到过好几次这种量纲滑坡。

★★ 一题采 8 次 vs 采 64 次：多花 8 倍的钱买到了什么

先说成本：采样算力和训练算力都大致正比于 G，所以 G 从 8 调到 64，总算力约 8 倍。

⚠️ 措辞纪律：这是【8 倍】，等价于【增加 700%】。
   不要写成"增加 800%"，也不要和"节省 7/8"混用 —— 那是反方向的说法。

再说收益。加大 G 买到的唯一东西是：让这一组不至于"全对"或"全错"。 因为那两种情况下 μ 就是 1 或 0，所有 A_i 全是 0，这 G 条 rollout 的算力完全白花（5.3 节的"病二"）。

设一道题的单条正确率为 p，组内采样近似独立，则这一组退化（全对或全错）的概率是 p^G + (1−p)^G：

这道题的单条正确率 p G = 8 G = 16 G = 64
0.50（中等难度） 0.78% 0.003% ≈ 0
0.90（或 0.10） 43.0% 18.5% 0.12%
0.95（或 0.05） 66.3% 44.0% 3.8%
0.99（或 0.01） 92.3% 85.1% 52.6% 
自己验一格：p = 0.9、G = 8 时
   P(全对) = 0.9^8 = 0.4305
   P(全错) = 0.1^8 = 0.00000001
   合计 = 43.05%，和表里那一格一致

★★★ 这张表给出的结论，比"采得多就好"精确得多：

① 对 p ≈ 0.5 的【中等难度题】：G = 8 的浪费率已经只有 0.78%。
   把 G 加到 64，多花 8 倍算力，省下的那 0.78% —— 几乎什么都没买到。

② 对 p = 0.95 的【简单题】：G = 8 有 66% 的概率白跑！
   加到 64 才降到 3.8%。这里加大 G 是真的有用。

③ 对 p = 0.99 的【过于简单的题】：连 G = 64 都有一半概率白跑。
   ⟹ 这种题【不该留在训练池里】，加大 G 是在错误的地方花钱。

⟹ ★★ 所以"加大 G"的收益【全部集中在难度极端的题上】，
   而对主力的中等难度题几乎无效。
   这就解释了 5.3 节两个补丁为什么是对的：
      · DAPO 的【动态采样】：只对退化的那些组补采，不动其他组
        —— 把钱只花在需要的地方
      · openPangu 的【在线动态过滤】：把 p 太高的题直接踢出训练池
        —— 从根上不让这种题产生退化组（见 7.3 节）

⚠️ 这张表有一个乐观假设：组内 G 条采样【独立同分布】。
   真实情况是它们来自同一个模型、同一个温度，彼此高度相关，
   ⟹ 所以真实的退化率【比表里更高】。表里的数字是下界。

5.3 GRPO 的病，和它的变体家族

GRPO 简单便宜，但一上"大规模 + 长思维链"就暴露一堆问题。2025 年一整年，业界都在打补丁。

病一：熵坍缩（entropy collapse）★★ 最重要

熵 = 模型输出的"不确定性 / 多样性"。熵高 = 同一个位置它还愿意试别的词。

典型现象（⚠️ 下面的量级来自公开实验报道，各家数值不同，本目录未归档一手 PDF）：
   训练开始   熵 ≈ 0.25
   50 步左右   急剧下降
   再往后      ≈ 0

⟹ 模型对每个位置都极度确信
⟹ 同一道题采 8 次，8 条回答几乎一模一样
⟹ 8 条全对或全错 → 所有 A_i = 0 → 【没有梯度】→ 训练安静地停下

★ 这是 GRPO 的头号杀手，而且它最阴险的一点是：它不是训崩，是悄悄地停止学习。 loss 看起来正常，奖励曲线平着走，卡还在烧——但模型已经什么都不学了。

病二：优势归零（zero-advantage）

一道题太简单 → 8 条全对 → μ = 1，所有 A_i = 0 → 这 8 次 rollout 白跑
一道题太难   → 8 条全错 → μ = 0，所有 A_i = 0 → 这 8 次 rollout 白跑

★ 5.2 节末那张表给了这件事的精确形状：
  p = 0.95 的题，G = 8 时有 66.3% 的概率整组白跑。

⚠️ 而训练过程本身会【不断制造这种题】：
   模型越训越强 ⟹ 原本 p = 0.5 的题慢慢变成 p = 0.9、p = 0.99
   ⟹ 训到中后期，大部分 batch 都退化了。
   ⟹ ★ 所以这不是"数据选得不好"，是一个【随训练自动恶化】的问题，
      必须用在线手段（动态采样 / 动态过滤）持续对冲。

病三：长度偏置（length bias）

长思维链训练里，loss 的归一化方式有两种，会导致系统性偏好：

   【序列级归一化】每条轨迹的 loss 先在内部除以自己的长度，再跨轨迹平均
      ⟹ 一条 100 token 的轨迹和一条 10,000 token 的轨迹，权重一样
      ⟹ 短轨迹里【每个 token 的权重被放大了 100 倍】
      ⟹ ⚠️ 偏好短回答（或者说：短轨迹的噪声被放大）

   【token 级归一化】把 batch 里所有 token 放在一起，统一除以总 token 数
      ⟹ 长轨迹贡献更多 token、拿到更大的总权重
      ⟹ ⚠️ 偏好长回答

★ 两种都有偏，只是方向相反。DAPO 选了 token 级，
  并额外加了一项【超长惩罚整形】来压住"偏好长"这一侧。

变体家族对照表

方法 出处 改了什么 治哪个病

   没有一条触及"优势怎么估"这个算法核心。

⟹ 说明 2025 年的主要矛盾不是"想不出更好的算法"，
   而是"把一个简单算法在超大规模长序列上跑稳"。
   ★ 这和 5.5 节 scaling law 的结论是一致的：
     算法选择主要影响"爬得多快"，不影响"爬得多高"。

⚠️ 2026 年的进展：静态的 clip-higher 和熵正则本身也被发现不稳（熵一升上去奖励就掉）。新一批工作转向动态熵控制 / 熵流建模 / 把被裁剪 token 的有界梯度还回来（如 GPPO、CE-GPPO 一类）。⚠️ 这些多为 2026 年的预印本，尚未见工业报告大规模采用，别当定论。

5.4 Clip-Higher 为什么能治熵坍缩：把不公平算出来

这一节是本章最值得按计算器的地方。 结论是一句话：对称的裁剪，对低概率 token 是一种系统性歧视。

先看清 clip 限制的是什么

clip 限制的是【比值】，也就是【乘法倍数】，不是【绝对概率】。

   ⟹ 一个 token 单步最多能涨的【绝对概率】 = p × ε
      （p 是它采样时的概率，ε 是裁剪上界的宽度）

★ 这一行就是全部问题的根源：配额和 p 成正比。
  概率本来就高的 token，配额本来就大。

取 ε = 0.2（上界 1.2），把几个概率档位都算出来：

采样时概率 p 单步最多涨到 单步最多涨的绝对概率 = 0.2p 从 p 一路顶格涨到 0.5，要几步
0.01（一个"没想到的思路"） 0.012 +0.002 ln(50) / ln(1.2) = 3.912 / 0.1823 = 21.5 → 22 步
0.05 0.060 +0.010 ln(10) / ln(1.2) = 13 步
0.10 0.120 +0.020 ln(5) / ln(1.2) = 9 步
0.30 0.360 +0.060 ln(1.667) / ln(1.2) = 3 步
0.90（模型的老套路） 1.08，被概率上限 1.0 挡住 +0.100（实际 +0.10 就满了） 已经在 0.5 之上 
★★★ 把第三列的头尾两格对比一下：
   p = 0.90 的 token，单步能挪 +0.18 的概率质量（0.2 × 0.9）
   p = 0.01 的 token，单步能挪 +0.002
   ⟹ 差【90 倍】。

   翻译成人话：
   模型的老套路每一步大步流星，
   一个"没想到的思路"每一步只能挪一点点 ——
   而且它要连续顶格 22 步才能爬到"一半的可能性"。
   ⚠️ 而真实训练里不可能每步都顶格，所以 22 步是乐观下界。

⟹ 分布越来越尖 ⟹ 熵坍缩。
   ★★ 注意：这不是"模型不想探索"，是【优化器的规则不许它探索得快】。

DAPO 的解法，和它买到的加速（这里有一个很常见的算错）

DAPO 的做法：把上下界【拆开】，只放宽上界。
   ε_low = 0.20  → 下界 0.80（不动，保持对"压低"的约束）
   ε_high = 0.28 → 上界 1.28（放宽，给上升留空间）

重算那个 p = 0.01 的 token：
   ln(0.5 / 0.01) / ln(1.28) = 3.9120 / 0.24686 = 15.85 → 16 步
   （原来是 22 步）

★★★ 这里有一个本仓库反复抓到的算错，必须说清：

   步数从 22 降到 16。

   [对] 说法一：步数减少了 27.3%。算法：(22 − 16) / 22 = 0.273
   [对] 说法二：爬升快了 37.5%，也就是 1.375 倍。算法：22 / 16 = 1.375
   [错] 说法三："加速了 27.3%"。这是把上面两个口径混成了一句话。

   换算公式（记住它）：
      加速倍数 = 1 / (1 − 减少比例)
      代进去：1 / (1 − 0.273) = 1 / 0.727 = 1.375，和说法二对得上

★ 为什么必须分清：减少 50% 对应加速 2 倍，减少 90% 对应加速 10 倍。
  在"减少"比较大的时候，两个口径的数字会差出几倍。

✅ 一手背书：R1 把这个上界直接开到了 10

DAPO 不是唯一撞到这个问题的团队。 ✅ R1 报告在论文 §3.2.1 披露，第一阶段 RL 的 GRPO 裁剪比值 ε 设成了 10——也就是上界 11，而不是 1.2。

✅ 论文原话："Note that the clip ratio plays a crucial role in training. A lower value can lead to the truncation of gradients for a significant number of tokens, thereby degrading the model's performance, while a higher value may cause instability during training."
（裁剪比值这个超参起关键作用。取得太低会让大量 token 的梯度被截掉，从而损害模型性能；取得太高又会造成训练不稳定。）

★★ 这一段是 clip-higher 这条思路最权威的一手背书：
   DAPO（2025-03）和 DeepSeek（R1，2025-01）独立撞到了同一个问题，
   只是药量差很多 —— DAPO 把上界调到 1.28，DeepSeek 直接调到 11。

   用 5.4 的公式算一下 ε = 10 的效果：
      ln(50) / ln(11) = 3.9120 / 2.3979 = 1.63 → 【2 步】
   ⟹ 从 22 步压到 2 步。

⚠️ 一个本文的观察（论文没有这么写）：
   ε = 10 时，下界 1 − ε = −9，而比值恒为非负数，
   ⟹ 【下界永远不会生效】。
   所以这个配置实际上等价于"把裁剪整个关掉"，
   只靠 KL 系数（0.001）和小学习率（3e-6）来约束更新幅度。
   ★ 这说明"裁剪"在 RLVR 里并不是不可替代的安全绳 ——
     但 DeepSeek 自己也在同一段里承认"取得太高会不稳"，
     ⚠️ 所以这不是一个可以照抄的配置。

5.5 RL 也有 Scaling Law 了

2025 年底之前，RL 后训练基本是"炼丹"；之后开始有可外推的曲线。

✅ The Art of Scaling Reinforcement Learning Compute for LLMs（ScaleRL）
（arXiv:2510.13786，Devvrit Khatri 等，2025-10）

核心主张：奖励随算力增长服从【S 形曲线】（sigmoid），有三个参数：

   A      —— 天花板（这个配方最终能到多高）
   B      —— 效率（爬得多快）
   C_mid  —— 爬到一半所需的算力

★★★ 最有用的一个结论：
   【很多算法选择只影响 B（爬得快慢），不影响 A（天花板）】。

⟹ 实操含义：调算法能让你更快到达同一个终点，
   但要抬高终点，得换更大的模型 / 更长的生成预算 / 更大的 batch。
   ★ 这和 5.3 节那张补丁表完全对得上 ——
     DAPO / GSPO / CISPO 都在修"跑得稳不稳、快不快"，不在抬天花板。

⚠️ 论文里那个最常被引用的具体发现，以及它的正确读法：

⚠️ 下面这组数字我【没有回溯到一手 PDF】——本目录 papers/ 是空的
   （见 README 的可靠性说明），这里按公开摘要转述，标记为待核对。

   报告称：一个 17B×16 的 MoE，用【1/6 的 RL 算力】
          就追平并超过了 8B dense 模型。

★ 这句话的口径要掰清楚，它很容易被写错：

   "1/6 的算力" 的两种正确说法：
      算力减少了 83.3%（因为 1 − 1/6 = 0.833）
      每单位算力的效率高 6 倍

   [错] 不能说成"快 6 倍"。那是在说【时间】，而这里说的是【算力】；
        同样的算力摊在更多卡上，时间可以完全不同。
   [错] 也不能说成"省了 6%"。

⚠️ 另外，报告自述这个结论来自 40 万+ GPU 小时的实证研究，
   但它仍然是【单一配方下的观察】——换一个 RL 配方、换一组任务，
   MoE 对 dense 的这个优势比例没有理由保持不变。

⚠️ 另一派主张的是幂律，不是 S 形（arXiv:2509.25300，Zelin Tan 等，2025-09）：认为 RL 后训练的损失-算力-数据关系遵循和预训练类似的幂律，并指出固定算力下，"大模型少训几步"打赢"小模型训很久"。

⚠️ 两派的函数形式不一致（S 形 vs 幂律），说明这门科学【还在很早期】。
   S 形曲线有渐近上界 A，幂律没有 —— 这两件事在数学上是冲突的，
   不可能都对。★ 目前没有定论说谁对。

共同的、可以拿去用的结论只有两条：
   ① 模型规模的杠杆 > 算法调参的杠杆
   ② RL 的收益会饱和，而且饱和点比预训练来得早

5.6 ★★★ 最大的争论：RLVR 到底有没有让模型变强

这是 2025～2026 年这个领域吵得最凶的问题，到今天没有定论。

争论的起点：pass@k 曲线

先把两个指标说清楚：
   pass@1   ——  让模型答 1 次，对的概率        ← 衡量"稳不稳"
   pass@k   ——  让模型答 k 次，【至少一次对】的概率
                 ★ 它衡量的是"这个模型的能力边界在哪"

✅ Yue 等人的发现（[arXiv:2504.13837](https://arxiv.org/abs/2504.13837)，Yang Yue 等，2025-04）：

   k 小时（pass@1）：   RL 模型  >  base 模型     ← RL 赢
   k 很大时：          base 模型 >  RL 模型      ← ★★ base 反超！

   论文的解读：
   RLVR 没有创造新能力，它只是【把 base 模型本来就有的正确路径
   采样得更集中了】—— 顺便把别的路径【剪掉了】。

⚠️ 口径提醒：原文在不同数据集上用的 k 不同（量级在几十到几百）。
   "pass@256 时 base 反超"是一个典型情形，不是对所有任务都成立的定值。
   ⚠️ 本目录 papers/ 未归档该 PDF，具体 k 值与数据集请回原文。

这个结论如果成立，是很扎心的：意味着 RL 只是在"提高中签率"，不是在"提高天花板"。

⚠️ 插一段必须讲清的技术细节：pass@k 有三种算法，其中一种是有偏的

这一段很容易被忽略，而它直接决定上面那场争论的数字可不可信。

算法 怎么算 有偏吗 方差
① 直接采 k 次 采 k 条，看有没有对的，是就记 1 ✅ 无偏 ⚠️ 大。一道题只给你一个 0/1
② 组合式估计量（Codex 论文的做法） 采 n ≫ k 条，数出 c 条对的，算 1 − C(n−c, k) / C(n, k) ✅ 无偏 ✅ 小得多。这是标准做法
③ 从 pass@1 外推 1 − (1 − pass@1)^k ⚠️⚠️ 有偏，会高估 —

③ 为什么会高估，用两道题就能看出来：

假设只有两道题：
   题 A：模型每次都对，p_A = 1.0
   题 B：模型永远不对，p_B = 0.0

   真实的 pass@4 = ( 1 + 0 ) / 2 = 0.50       ← 题 B 采 4 次也还是不对
   pass@1       = ( 1.0 + 0.0 ) / 2 = 0.50
   用 ③ 外推    = 1 − (1 − 0.50)^4 = 1 − 0.0625 = 0.9375

⟹ 0.9375 vs 真实的 0.50 —— 【高估了近一倍】。

★★ 为什么必然是高估：函数 f(p) = 1 − (1−p)^k 在 p 上是【凹】的
   （f'' = −k(k−1)(1−p)^(k−2) < 0）。
   由 Jensen 不等式，E[f(p)] ≤ f(E[p])：
      左边 = 真实的平均 pass@k
      右边 = 用 pass@1 外推出来的值
   ⟹ 外推值永远 ≥ 真实值，题目难度差异越大、高估越多。

⟹ ⚠️ 所以：看到一篇论文的 pass@k 是从 pass@1 推出来的，
   它的"能力边界"结论要打折。这场争论里双方都必须用 ① 或 ②。

⚠️⚠️ 别和 harness评测框架 §I 那张表搞混——那边说「有偏、系统性偏低」，这边说「有偏、会高估」，两边都对，因为说的不是同一个估计量。 区别在于 Jensen 不等式用在了哪根轴上：

本节的 ③ 外推 harness 那边的 算法 B
公式 1 − (1 − p̄)^k 1 − (1 − c/n)^k
p 从哪来 整个数据集的平均 pass@1 这一道题自己的经验通过率 c/n
凹凸 1−(1−p)^k 对 p 是凹的 (1−x)^k 对 x 是凸的
Jensen 方向 mean f(pᵢ) ≤ f(p̄) ⟹ 偏高 E[(1−c/n)^k] ≥ (1−p)^k ⟹ 偏低
偏差的来源 题与题之间的难度异质性（有些题永远做不出来，被平均抹平了） 同一道题内部的采样噪声

⟹ 🔑 一句话记：跨题平均再外推会高估，单题插值会偏低。 两者都不该用——用 ① 或 ②。

✅ 一个正面例子：R1 报告自己就是这么做的（论文 Supplementary D.1）——AIME 和 GPQA 用 k = 64 条采样、MATH 和 CodeForces 用 k = 16、LiveCodeBench 用 k = 8，然后 pass@1 = (1/k)·Σ p_i。这是在用多次采样估 pass@1，而不是用 pass@1 去推 pass@k ——方向正好是安全的那一边。

反方与调和

① 指标质疑：
   数学题的答案空间是离散的（就那么几个数字），k 很大时
   base 模型可能是【蒙对】的 —— pass@k 高不代表真会。
   ★ 这正好是 6.2 节轨迹 C 那个"过程全错、答案蒙对"的情形，
     只是搬到了评测侧。

② 两阶段动态观点（✅ [arXiv:2510.04028](https://arxiv.org/abs/2510.04028)，Xinhao Yao 等，2025-10）：
   "收缩还是扩张"是个假问题 —— 它是【两个阶段】：
   训练早期扩张，后期收缩。结论取决于你在哪一步停下来测。

③ 机制诊断（✅ arXiv:2607.20543，Todd Zhou，2026-07）：
   把失败精确定义为【pass@k 反转】，并指出它发生在"边界题"上 ——
   base 模型有罕见的正确轨迹，但在有限的 rollout 组里【采不到】
   ⟹ 验证器从没见过这条路径的正例
   ⟹ 这条路径被当成"不存在"而剪掉
   ★ 这叫"证据缺失"被当成了"缺失的证据"（absence of evidence
     ≠ evidence of absence）。
   ⚠️ 该文还指出：熵坍缩是一个有用的症状，但【不足以解释】这个现象。
   ⚠️ 2026 年的预印本，本目录未归档 PDF。

★★ 把 ③ 和 5.2 节那张成本表接起来看，这件事就变得很具体：
   一道题如果 base 的正确率是 p = 0.5%，
   采 G = 16 条，一条都采不到正确路径的概率 = (1 − 0.005)^16 = 92.3%。
   ⟹ 这道题在 92% 的训练步里都表现为"全错"，优势全是 0，
      它的正确路径从来没有被奖励过一次。
   ⟹ 而同时，错误路径被持续压低 —— 相当于单方面地把这道题"删掉"。
   ★ 这就是"剪枝"的具体机制，不需要诉诸任何玄学。
   ⚠️ 这一段的 92.3% 是本文按独立假设算的示意，不是论文的数字。

⚠️ 我的判断（2026-09）

⚠️ 以下是本文的判断，不是任何论文的结论。

① RLVR 【确实】主要在重新分配概率质量，而不是凭空造能力。
   —— 5.7 节那个"一道题就够了"的实验是很硬的旁证。

② 但"重新分配"本身就极其值钱 ——
   一个 pass@256 才对的模型是【不能用的产品】，pass@1 就对的才是。
   ⟹ 所以即使 ① 成立，RLVR 也没有白做。
      ★ 争论的真正分歧不在"有没有用"，在"能不能继续往上推"。

③ 真正的破局方向不在算法里，在【环境】里 ——
   当模型能调用工具、能看到真实反馈，它接触到的信息
   就【超出了 base 模型的参数】，这时才谈得上"新能力"。
   ★ 这就是 07 章 Agentic RL 成为主战场的深层原因。

5.7 一个反直觉的实验：一道题就够了

✅ Reinforcement Learning for Reasoning in LLMs with One Training Example
（arXiv:2504.20571，Yiping Wang 等，2025-04）

做法：从 7,500 条数学题里挑【一条】，复制到填满一个 batch（128 份），
     就用这一条题做 RLVR。

结果：数学推理性能和用完整 7,500 条训练的【相当】。

★★ 这个实验最好的解读不是"数据没用"，而是：
   RLVR 在做的事情，更像是【打开一个已经存在的开关】，
   而不是【往模型里灌新知识】。
   —— 它是 5.6 那场争论的一个有力旁证，站在"重新分配"那一侧。

⚠️ 别过度外推：
   ① 它说的是"数学推理"这一类、而且是【已经在 base 里的能力】；
      07 章那种"调工具、看真实反馈"的能力，一条题显然学不出来。
   ② "相当"是在特定评测上的相当，不是全面相当。
   ⚠️ 本目录 papers/ 未归档该 PDF，具体评测口径请回原文。

⚠️ 后续工作（arXiv:2605.01823，2026-05）指出原文用来选那一条题的"奖励方差"信号是误导的，"输出分歧度（熵）"才是更强的预测指标；但该工作规模很小（1.5B + LoRA），⚠️ 结论仍属初步（preliminary），别当定论。

5.8 这一章的五句话总结

① RLVR 的全部革命性在于：把打分的人换成了一段程序。
   人不 scale，程序 scale。
   ✅ R1 论文 §2.2 把这件事做到了极致：
      奖励只有"答案对不对 + 格式对不对"两项，等权相加。

② ★ 但"可验证"有三个硬条件（答案判定明确 / 判定是纯程序 / 判定够便宜），
   满足不了的任务 RLVR 碰不到。
   ⟹ 【RLVR 的适用面就是它的天花板】，和算力、模型大小无关。
   ⟹ 而且"可验证"不等于"不可钻"：验证器的覆盖缺口就是攻击面（6.4）。

③ GRPO 靠"组内平均分当基线"删掉了 Critic，简单便宜；
   代价是一堆工程病（熵坍缩、优势归零、长度偏置），
   DAPO / GSPO / CISPO 都是补丁，没有一条在抬天花板。

④ ★ RLVR 最大的成本项是采样，不是更新。
   ✅ R1-Zero 的一段 RL = 101K H800 卡·时，生成了约 532 万条轨迹。
   而"一题多采几条"的收益【全部集中在难度极端的题上】 ——
   所以正确的省钱方式是动态采样和动态过滤，不是全局加大 G。

⑤ RLVR 是否真的扩展了能力边界，至今没有定论（5.6）。
   ⚠️ 但业界的实际动作已经给出了投票结果：
      都跑去做 Agentic RL 了 —— 因为那里的信息来自环境，
      不受 base 模型参数的约束。
