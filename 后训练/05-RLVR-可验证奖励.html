05 · ⭐ RLVR：可验证奖励强化学习

RLVR = Reinforcement Learning with Verifiable Rewards（可验证奖励的强化学习）
一句话：奖励不再来自"人喜不喜欢"，而来自"答案对不对"。

这是 2025 年之后后训练的主线。 读完你应该能回答：GRPO 到底怎么算的？为什么它需要那么多变体来打补丁？以及那个吵了一年多的问题——RL 到底有没有让模型变得更聪明，还是只是让它把会的题答得更稳？

5.1 换掉奖励来源，是一次范式转移

RLHF 的奖励：  一个训出来的【奖励模型】说了算
   ⚠️ 问题：RM 是个神经网络，它会被骗（reward hacking）
   ⚠️ 问题：RM 的口味来自标注员，天花板就是标注员的水平

RLVR 的奖励：  一个【程序】说了算
   数学题 → 把最终答案和标准答案做字符串/数值比对   → 0 或 1
   代码题 → 跑单元测试                              → 0 或 1
   格式   → 正则匹配 <think>...</think> 结构        → 0 或 1

   ✅ 不会被骗（至少难得多）
   ✅ 不要人参与，可以无限次、零成本地判
   ✅ 天花板是【题目本身的正确性】，不是标注员的水平

★★★ 这一步的意义，怎么强调都不为过：它把"人"从训练回路里彻底移了出去。
一旦不需要人打分，RL 的规模就只受算力限制了。这是 2025 年推理模型集体爆发的直接原因。

R1 的证明

✅ DeepSeek-R1（arXiv:2501.12948，2025-01）证明了一件之前很多人不信的事：

不需要任何"人写的推理过程"数据，只用"答案对不对"这一个信号做 RL，模型自己就能长出复杂的思维链。

R1-Zero：直接在 base 模型上做 RLVR，不做任何 SFT
   ⟹ 模型自发学会了：写长推理、自我检查、"等一下，我再算一遍"
   ⚠️ 代价：可读性差、中英混杂 —— 所以正式版 R1 加了冷启动 SFT

5.2 ★★ GRPO：先把它算一遍

GRPO = Group Relative Policy Optimization（组相对策略优化）
✅ 出自 DeepSeekMath（arXiv:2402.03300，Zhihong Shao 等，2024-02）

它解决的是 04.3 那个痛点：把 PPO 的第四个模型（Critic）删掉。

Critic 是干嘛的，为什么能删

PPO 里 Critic 的作用：回答"这条轨迹算好还是算坏？"
   得到 7 分，是好是坏？   → 要看"一般能得几分"
   Critic 就是在估这个"一般能得几分"（叫 baseline 基线）

★★ GRPO 的洞察：
   既然只是要一个基线，那我【对同一道题多采样几次，用这几次的平均分当基线】不就行了？
   ⟹ Critic 删除。

手算一遍

题目：一道数学题。采样 G=8 条回答，验证器打分：

   轨迹:   r1   r2   r3   r4   r5   r6   r7   r8
   奖励:   1    0    0    1    0    1    0    0     ← 3 对 5 错

   平均 μ = 3/8 = 0.375
   标准差 σ ≈ 0.484

   优势 A_i = (r_i − μ) / σ      ← "组内相对"就是这个意思

   对的三条：A = (1 − 0.375)/0.484 = +1.29   → 提高这些 token 的概率
   错的五条：A = (0 − 0.375)/0.484 = −0.77   → 降低这些 token 的概率

★ 一条轨迹里的【每个 token】都用这同一个 A（这叫"结果奖励"，
  也是它最大的软肋：错在第 3 步的轨迹，第 1、2 步也被一起惩罚了 → 06 章）

GRPO 的完整目标（口语版）：

最大化：  Σ  min( 比值 × A ,  clip(比值, 1−ε, 1+ε) × A )   −  β · KL(π_θ ‖ π_ref)
              ↑                 ↑                              ↑
        比值 = 新概率/采样时概率   截断，防止一步走太远        别离原模型太远

⚠️ 公式看不懂完全不影响后面。只要记住三件事：
   ① 优势 A 来自"组内比平均分高多少"
   ② clip 是一根安全绳，防止单步更新过猛
   ③ KL 项是另一根绳，防止整体跑偏（很多 2025 年的变体把它去掉了）

5.3 GRPO 的病，和它的变体家族

GRPO 简单便宜，但一上大规模长思维链训练就暴露一堆问题。2025 年一整年，业界都在打补丁。

病一：熵坍缩（entropy collapse）★★ 最重要

熵 = 模型输出的"不确定性 / 多样性"。

典型现象（⚠️ 量级来自公开实验报道，各家数值不同）：
   训练开始   熵 ≈ 0.25
   50 步后    急剧下降
   再往后     ≈ 0

⟹ 模型对每个位置都极度确信，8 次采样出来的 8 条回答几乎一模一样
⟹ 8 条全对或全错 → 优势 A 全是 0 → 【没有梯度】→ 训练死掉

★ 这是 GRPO 头号杀手：它不是训崩，是悄悄地停止学习。

病二：优势归零（zero-advantage）

一道题太简单 → 8 条全对 → μ=1, 所有 A=0 → 白跑 8 次 rollout
一道题太难   → 8 条全错 → μ=0, 所有 A=0 → 白跑 8 次 rollout

⚠️ 实践中，训到中后期【大部分 batch 都是这种废样本】，算力全浪费了。

病三：长度偏置

长思维链训练里，token 级和序列级的归一化方式不同，会系统性地偏好长回答或短回答。

变体家族对照表

方法 出处 改了什么 治哪个病
DAPO ✅ arXiv:2503.14476
Qiying Yu 等，2025-03		 ① Clip-Higher：把裁剪上界放宽
② 动态采样：丢掉全对/全错的组，补采到够
③ token 级 loss
④ 超长惩罚整形		 ①治熵坍缩

★★ 看这张表的正确姿势：
   这三个改动都不是"新算法"，是【工程病的补丁】。
   ⟹ 说明 2025 年的主要矛盾不是"想不出更好的算法"，
      而是"把一个简单算法在超大规模长序列上跑稳"。

⚠️ 2026 年的进展：静态的 clip-higher 和熵正则本身也被发现不稳（熵一升上去奖励就掉）。新一批工作转向动态熵控制 / 熵流建模 / 把被裁剪 token 的有界梯度还回来（如 GPPO、CE-GPPO 一类）。⚠️ 这些多为 2026 年的预印本，尚未见工业报告大规模采用。

5.4 Clip-Higher 为什么能治熵坍缩（一个值得懂的细节）

PPO/GRPO 的裁剪是【对称】的：比值被限制在 [1−ε, 1+ε]，比如 [0.8, 1.2]

考虑一个概率只有 0.01 的 token（一个"没想到的思路"）：
   要让它变成 0.012，比值 = 1.2 —— 刚好顶到上界，再多就被裁掉

再考虑一个概率 0.9 的 token（模型的老套路）：
   它涨到 0.99 都还在界内，畅通无阻

★★ 结论：对称裁剪【系统性地偏袒高概率 token】。
   低概率 token（= 探索）每次只能挪一点点，高概率 token 一路狂奔
   ⟹ 分布越来越尖 ⟹ 熵坍缩

DAPO 的解法：把上界单独调大（比如 [0.8, 1.28]），
             给低概率 token 更大的上升空间。

5.5 RL 也有 Scaling Law 了

2025 年底之前，RL 后训练是"炼丹"；之后开始有可外推的曲线。

✅ The Art of Scaling Reinforcement Learning Compute for LLMs（ScaleRL）
（arXiv:2510.13786，Devvrit Khatri 等，2025-10）

核心主张：奖励随算力增长服从【S 形曲线】（sigmoid），有三个参数：

   A      —— 天花板（这个配方最终能到多高）
   B      —— 效率（爬得多快）
   C_mid  —— 爬到一半所需的算力

★★★ 最有用的一个结论：
   【很多算法选择只影响 B（爬得快慢），不影响 A（天花板）】。

⟹ 实操含义：调算法能让你更快到达同一个终点，
   但要抬高终点，得换更大的模型 / 更长的生成预算 / 更大的 batch。

✅ 另一个具体发现：模型规模影响最大——
   一个 17B×16 的 MoE，用【1/6 的 RL 算力】就追平并超过了 8B dense 模型。
   ⚠️ 该结论来自 40 万+ GPU 小时的实证研究，但仍是单一配方下的观察。

⚠️ 另一派用幂律（arXiv:2509.25300，Zelin Tan 等，2025-09）：认为 RL 后训练的损失-算力-数据关系遵循和预训练类似的幂律，并指出固定算力下，"大模型少训几步"打赢"小模型训很久"。

⚠️ 两派的函数形式不一致，说明这门科学【还在很早期】。
   共同的可用结论只有两条：
   ① 模型规模的杠杆 > 算法调参的杠杆
   ② RL 的收益会饱和，且饱和点比预训练来得早

5.6 ★★★ 最大的争论：RLVR 到底有没有让模型变强

这是 2025～2026 年这个领域吵得最凶的问题，而且到今天没有定论。

争论的起点：pass@k 曲线

先解释两个指标：
   pass@1   ——  让模型答 1 次，对的概率
   pass@k   ——  让模型答 k 次，【至少一次对】的概率
                 ★ 它衡量的是"这个模型的能力边界在哪"

✅ Yue 等人的发现（arXiv:2504.13837，Yang Yue 等，2025-04）：

   pass@1（k 小）：  RL 模型  >  base 模型     ← RL 赢
   pass@256（k 大）：base 模型 >  RL 模型      ← ★★ base 赢！

   论文的解读：
   RLVR 没有创造新能力，它只是【把 base 模型本来就有的正确路径，
   采样得更集中了】—— 顺便把别的路径【剪掉了】。

这个结论如果成立，是很扎心的：意味着 RL 只是在"提高中签率"，不是在"提高天花板"。

反方与调和

① 指标质疑：
   数学题答案空间离散（就那么几个数字），k 很大时
   base 模型可能是【蒙对】的，pass@k 高不代表真会。

② 两阶段动态观点（✅ arXiv:2510.04028，Xinhao Yao 等，2025-10）：
   "收缩还是扩张"是个假问题 —— 它是【两个阶段】：
   训练早期扩张，后期收缩。取决于你在哪一步停下。

③ 机制诊断（✅ arXiv:2607.20543，Todd Zhou，2026-07）：
   把失败精确定义为 【pass@k 反转】，发生在"边界题"上 ——
   base 模型有罕见的正确轨迹，但在有限的 rollout 组里【采不到】
   ⟹ 验证器从没见过正例 ⟹ 这条路径被当成"不存在"而剪掉
   ★ 这叫"证据缺失"而非"缺失证据"（absence of evidence）
   ⚠️ 该文还指出：熵坍缩是有用的症状，但【不足以解释】这个现象。

⚠️ 我的判断（2026-09）

这场争论的实际结论，可能是三句话：

① RLVR 【确实】主要在重新分配概率质量，而不是凭空造能力。
② 但"重新分配"本身就极其值钱 —— 一个 pass@256 才对的模型
   是不能用的产品，pass@1 就对的才是。
③ 真正的破局方向不在算法里，在【环境】里 ——
   当模型能调用工具、能看到真实反馈，它接触到的信息
   就【超出了 base 模型的参数】，这时才谈得上"新能力"。
   ★ 这就是 07 章 Agentic RL 成为主战场的深层原因。

5.7 一个反直觉的实验：一道题就够了

✅ Reinforcement Learning for Reasoning in LLMs with One Training Example
（arXiv:2504.20571，Yiping Wang 等，2025-04）

做法：从 7500 条数学题里挑【一条】，复制到填满一个 batch（128 份），
     就用这一条题做 RLVR。

结果：数学推理性能和用完整 7500 条训练的【相当】。

★★ 这个实验最好的解读不是"数据没用"，而是：
   RLVR 在做的事情，更像是【打开一个已经存在的开关】，
   而不是【往模型里灌新知识】。
   —— 它是 5.6 那场争论的一个有力旁证。

⚠️ 后续工作（arXiv:2605.01823，2026-05）指出原文用的"奖励方差"选题信号是误导的，"输出分歧度（熵）"才是更强的预测指标；但该工作规模很小（1.5B + LoRA），⚠️ 结论preliminary。

5.8 这一章的四句话总结

① RLVR 的全部革命性在于：把打分的人换成了一段程序。
   人不 scale，程序 scale。

② GRPO 靠"组内平均分当基线"删掉了 Critic，简单便宜；
   代价是一堆工程病（熵坍缩、优势归零、长度偏置），
   DAPO / GSPO / CISPO 都是补丁。

③ RL 有 scaling law 了，但最有用的结论是：
   算法调参主要影响【爬得多快】，模型规模才影响【爬得多高】。

④ RLVR 是否真的扩展了能力边界，至今没有定论。
   ⚠️ 但业界的实际动作已经给出了投票结果：
      都跑去做 Agentic RL 了 —— 因为那里的信息来自环境，
      不受 base 模型参数的约束。
