07 · ⭐ Agentic RL：环境成为新瓶颈

这是 2026 年后训练的主战场。 五家技术报告里，有几家把一半以上的篇幅砸在这一章讲的东西上。

读完你应该能回答：agent 的强化学习和做数学题的强化学习差在哪？为什么"环境"会变成比模型更难的问题？以及这一章所有工程复杂度的唯一源头是什么。

7.1 先看清楚"一条数据"变成了什么

【RLVR 的一条训练样本】
   输入：一道数学题
   模型输出：一段 2000 token 的推理
   奖励：答案对不对（一次字符串比对，微秒级）
   耗时：几秒


【Agentic RL 的一条训练样本】
   输入："这个仓库的 CI 挂了，修好它"
   模型输出：
      读 README            → 环境返回文件内容
      跑 pytest            → 环境返回 37 个失败
      读 traceback         → 环境返回堆栈
      改 utils.py          → 环境返回 diff 已应用
      再跑 pytest          → 环境返回 3 个失败
      ...（可能 40 轮）
   奖励：最后测试全过了吗（0 或 1）
   耗时：★ 几分钟到几十分钟，且【完全不可预测】

★★★ 这一节只要记住一件事："一条数据"从"一段文本"变成了"一次与真实系统的交互过程"。
后面所有的工程灾难，都是这一句话的直接后果。

7.2 ★★ 官方原话：难点从模型转移到了环境

✅ GLM-5.3 官方博客（2026-08-14，见 ../业界模型技术报告/GLM-5.3.md）的原话：

"As agent capability improves, much of the difficulty in scaling post-training moves from the model to the environment."
（随着智能体能力提升，后训练规模化的难点从模型转移到了环境上。）

"环境"到底是什么（这个词要讲清楚）：

监督学习需要：题目 + 标准答案
强化学习需要：★ 一个能让模型【真的动手】、并且能【自动判分】的沙盒

写代码的环境要有：
   · 一个能跑的容器（装好依赖、能联网装包）
   · 一份真实的代码仓库和它的历史
   · 一套能执行的测试
   · 一个判定"任务完成没有"的规则

⟹ 造这么一个环境的工程量，比造一条 SFT 数据大【三到四个数量级】

GLM-5.3 是这件事最干净的一个证据

✅ 官方原话："Scaling post-training is all we did for GLM-5.3."
✅ 官方原话："It uses the same base model as GLM-5.2 — every gain comes from post-training."

⟹ 基座完全冻结，只加后训练规模 → 编程能力 +50%，
   并且长出了预期外的网络安全能力。

⚠️ 但要注意前提：这个结论成立的条件是【基座本身足够强且未被榨干】，
   不能推广成"任何模型加后训练都能 +50%"。

同步 RL 的规则：★ 必须【全部 128 条都跑完】才能更新一次权重
   ⟹ 最慢那条决定整批时间
   ⟹ 其余 127 张卡在【干等】
   ⟹ GPU 利用率可以低到个位数百分比

解法家族（都是在"打破同步"）：

手段 一句话 谁在用（✅ 一手报告）

Partial rollout 一批里完成了 λ 比例就暂停，剩下的下轮接着跑 Kimi-K3
可抢占 rollout 长任务可以被打断，token 粒度 WAL 日志恢复 DeepSeek-V4（Rust 写的 DSec 沙箱平台）
动态过滤 永远能解出的题踢出训练池 openPangu-2.0（在线动态过滤）

7.4 ★★ 异步带来的新病：训推不一致

这是 2026 年 RL 基建的头号工程问题，值得单独讲清楚。

RL 系统里永远有两套东西在跑：
   训练引擎（更新权重，Megatron 系）
   推理引擎（生成轨迹，vLLM / SGLang 系）

⚠️ 同一份权重，在两个引擎里【算出来的概率不完全一样】
   —— 算子实现不同、并行策略不同、量化不同、甚至 atomicAdd 的
      非确定性都会造成差异

为什么这是致命的：
   RL 的更新公式里有一项  比值 = 训练时概率 / 采样时概率
   这个比值【本该反映"策略更新了多少"】
   ⟹ 但现在它混进了"两个引擎实现不一样"的噪声
   ⟹ 噪声大到一定程度，梯度方向就是错的，训练直接崩

五家的解法（✅ 各家一手报告）：

DeepSeek-V4    ：逐位确定性（双 kernel / DeepGEMM / 消除 atomicAdd）
Kimi-K3        ：★ SFT→RL 全程 QAT，rollout 和训练用同一套量化方案
                 —— 从根上让两边"错得一样"
GLM-5          ：INT4 量化 kernel 训推 bitwise 一致
openPangu-2.0  ：五家里唯一做了完整根因解剖的（显式定义 / 计算图重排 /
                 硬件调度非确定性）+ 两阶段白盒逐层对齐方法论

QAT = Quantization-Aware Training（量化感知训练），训练时就模拟量化误差，让模型提前适应低精度。

7.5 环境从哪来：2026 年真正的数据问题

2024 年的问题："哪儿找一百万条高质量 SFT 数据"
2026 年的问题："哪儿找一万个能跑、能判分、且【没有洞】的环境"

三条路线：

① 真实仓库改造
   从 GitHub 上挑有测试的项目，把一个真实 commit 反向变成任务
   ✅ 最真实   ⚠️ 数量有限、清洗麻烦、容易和评测集污染

② 程序化合成
   自动生成任务 + 自动生成验证器
   ✅ 可以无限造   ⚠️★ 6.4 那个数字：缺陷率可以到 60%+

③ 自演化 / 自对弈
   让模型自己出题、自己加难度
   ✅ DeepMind 的 Evolving Alignment via Asymmetric Self-Play
      （arXiv:2411.00062，Ziyu Ye 等，2024-10）指出了核心动机：
      静态 prompt 集会被【榨干】—— 模型一旦刷满，学习就停止了
   ⟹ 所以模型应该【自己生成自己的训练题目分布】

⚠️ 一个二手但很有信息量的产业数据点：Scale AI 公开表示，其新增数据项目中近一半涉及 RL 环境。⚠️ 厂商自述，当趋势看，别当精确统计。

7.6 长程信用分配：还没解决的那个问题

一条 40 轮的轨迹，最后失败了。

   问题：★ 是哪一轮错的？

   结果奖励只告诉你"整体失败"，
   于是 40 轮里【正确的那 35 轮也一起被惩罚了】。

⚠️ 这就是 05.2 提到的"一条轨迹里每个 token 用同一个优势"
   在长程场景下被放大到极致的样子。

目前的缓解手段（都不完美）：

① 分段奖励：给中间里程碑打分（"测试从 37 个失败降到 3 个"给部分分）
   ⚠️ 但里程碑本身要人设计，且极易被 hack（模型学会"制造进度假象"）
② 优势整形：用轨迹间的对比来近似逐步信用
③ 缩短 horizon：把长任务拆成若干短任务分别训
   ⚠️ 代价是模型学不到"全局规划"
④ 上下文压缩（compaction）：轨迹太长塞不下时，中途压缩历史
   ✅ GLM-5.2/5.3 用的 SAO with compaction 属于这一类

🔮 这是本教程里我认为最重要的未解问题之一，12 章会再讲。

7.7 一条 Agentic RL 训练轨迹的完整生命周期

① 调度器发任务         "修好 repo X 的 CI"
        ↓
② 拉起沙箱             microVM / 容器，装好依赖
   ✅ Kimi-K3：可恢复的 microVM
   ✅ DeepSeek-V4：Rust 写的 DSec 平台，数十万并发沙箱
        ↓
③ rollout 循环         推理引擎生成动作 → 沙箱执行 → 结果回填上下文
   ⚠️ 这里要处理：超时、崩溃、死循环、模型调不存在的工具
   ✅ GLM-5 的 TITO Gateway：拦截所有生成请求，记录 token ID 和元数据，
      把繁琐的 token ID 处理从 agent 逻辑里隔离出来
        ↓
④ 判分                 跑最终测试 / 调 GRM / 规则检查
        ↓
⑤ 轨迹回传训练引擎     ⚠️ 一条轨迹可能几万 token，回传本身也是带宽问题
        ↓
⑥ 权重更新 → 同步给推理引擎
   ⚠️ 几百 GB 的权重要在几秒内同步到几百个推理副本
   → ../强化学习训练框架/03-权重同步.md

★ 看这个循环最大的收获：后训练团队的一半人力，花在了 ①②⑤⑥ 这些"和算法无关"的地方。

7.8 这一章的三句话总结

① Agentic RL 把"一条数据"从一段文本变成了一次真实交互，
   这一句话解释了这一章所有的工程复杂度。

② 瓶颈已经从模型转移到环境：
   2026 年缺的不是数据，是【能跑、能判分、且没有洞的环境】。

③ 长程信用分配（40 轮里到底哪轮错了）目前没有好答案。
   这是把 RL 推向更长任务时最先撞到的墙。
