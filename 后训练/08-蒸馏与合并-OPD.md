# 08 · ⭐ On-Policy 蒸馏（OPD）：五家共同的收口

> **OPD** = **On-Policy Distillation**（在策略蒸馏）
>
> **2026 年后训练最清晰的一次收敛**：五家一手技术报告，在流水线的最后一步用了**几乎同一个数学式子**。
> 读完你应该能回答：on-policy 蒸馏和普通蒸馏差在哪、为什么它同时解决了"合并专家"和"找回被遗忘的能力"两个看起来无关的问题。

---

## 8.1 先讲清楚"蒸馏"和"on-policy 蒸馏"的区别

### 传统蒸馏（off-policy）

```
① 让老师做 10 万道题，把老师的答案存下来
② 学生对着这些答案做 SFT

★ 本质：这就是 SFT，只是标准答案是老师写的而不是人写的。

⚠️ 它的病和 SFT 一模一样（见 02.5）：
   学生只见过【老师的完美前缀】，
   一旦自己写歪了，就进入了训练时从没见过的状态 —— exposure bias。
```

### On-policy 蒸馏

```
① 让【学生自己】做题（学生 rollout）
② 在学生写出的【每一个 token 上】，问老师：
   "这个位置，你会给每个词多少概率？"
③ 让学生的分布向老师的分布靠拢

★★★ 关键差别：
   老师不是在【给出答案】，老师是在【对学生自己走的路做点评】。

   类比：
   off-policy = 看名师的标准解题录像
   on-policy  = 自己做题，老师在旁边逐步说"这步偏了，我会这么走"

   ⟹ 第二种明显更有效，因为点评发生在【学生真的会犯错的那些位置上】。
```

**成本对比**：

```
off-policy：老师跑一次（离线），学生训。便宜。
on-policy ：★ 学生要 rollout（贵）+ 老师要对学生的每条轨迹做前向（贵）
            如果有 N 个老师，就是 N 次前向

⟹ 这就是 DeepSeek-V4 报告那句"OPD 成本高，但效果最好"的来源。
```

## 8.2 ★★ 它和 RL 的关系：其实是"有密集奖励的 RL"

**这是理解 2026 年这批报告的关键一跃。**

```
普通 RL：一整条轨迹跑完，才拿到【一个】0/1 的分数
         ⟹ 信号极其稀疏

OPD ：学生写的【每一个 token】都能立刻拿到一个分数
      （= 老师和学生在这个位置的概率差）
      ⟹ 信号密集到不能再密集

★★ 所以 OPD 可以看成："把老师当成一个免费的、逐 token 的稠密奖励模型"。
```

**这个视角一旦建立，2026 年那几份报告的公式就不神秘了：**

```
它们都在做同一件事 —— 把"老师和学生的 log 概率之差"
                       塞进已有的 RL 框架里当作 advantage 或 reward：

        Â  =  sg[ log( π_teacher / π_student ) ]
                ↑
          stop-gradient（这一项只当数值用，不回传梯度）

翻译成人话：
   老师觉得这个词比学生觉得的【更可能】 → 正的优势 → 提高它
   老师觉得这个词比学生觉得的【更不可能】 → 负的优势 → 压低它
```

> 🔑 **为什么各家宁可写成 RL 的 advantage，而不写成一个 KL loss（数学上近似等价）？**
> ✅ Kimi-K3 报告给了很实际的理由：**这样一来，为长周期任务做的 RL 基建（partial rollout 等）原封不动就能复用。**
> ★ 这是一个典型的"**为了复用系统而选择数学形式**"的决策，很值得记住。

⚠️ **另一个副产品**（✅ GLM-5 报告发现，K3 报告没提）：既然优势直接来自与老师的差距，就**不需要靠组内比较来算基线了**，GRPO 的 group size 可以设成 1 —— 吞吐直接拉满。

## 8.3 五家的对照：同一个式子，五种用法

⚠️ 下表来自各家一手报告，详见 [../业界模型技术报告/模型技术对比.md](../业界模型技术报告/模型技术对比.md) §3.6。

| | 老师是谁 | 目标形式 | ★ 要解决什么问题 |
|---|---|---|---|
| **DeepSeek-V4** | 各领域专家（SFT+GRPO） | **全词表逆 KL loss** | 多个领域专家**无法合并** |
| **Kimi-K3** | **9 个**（3 领域 × 3 档 effort） | **per-token log 比当 RL reward** | 多领域 × 多档位专家**无法合并** |
| **GLM-5** | **前面各阶段的最终 ckpt** | log 比当 GRPO **advantage** | ★ **多阶段 RL 会累积性损害先前能力** |
| **openPangu-2.0** | **4 个领域专家** | log 比当 GRPO **advantage** | 多个领域专家**无法合并** |
| **Nemotron 3 Ultra** | 一个**不断演进的教师面板** | MOPD（多教师） | 广泛能力获取 **+** 定向专精 |

```
★★★ 这张表最值得注意的一格是 GLM-5：
   它的老师不是"领域专家"，而是【自己前面几个阶段的 checkpoint】。

   SFT ckpt   →┐
   Reasoning ckpt →├─→ 都当老师 ─→ 蒸给最终的学生
   Agentic ckpt  →┘

   ⟹ 它不是在"合并专家"，是在【把被后续训练冲掉的自己找回来】。

★ 同一个工具，两种完全不同的用途。
  能看出这个区别，说明你真的读懂了这批报告。
```

**Nemotron 3 Ultra 的完整链路**（✅ [arXiv:2606.15007](https://arxiv.org/abs/2606.15007)，NVIDIA，2026-06）把这套东西做成了迭代：

```
Base → SFT → RLVR → MOPD warmup → MOPD（× N 轮）→ MTP boosting
                                     ↑
              教师面板会【随轮次演进】：STEM / 对话 / 指令遵循 /
              终端工具 / SWE / 搜索 / 办公 / 智能体安全 / 编码 ...
```

## 8.4 为什么它比参数平均好：函数空间 vs 参数空间

```
参数空间合并（Model Soup / Task Arithmetic / TIES / DARE）：
   W_合 = Σ w_i · W_i

   ⚠️ 它隐含一个很强的假设：
      "几个专家的参数是可以线性插值的"
      —— 但专家们各自走远之后，参数空间早就不对齐了，
         同一个神经元在两个专家里可能编码完全不同的东西。

✅ KAT-Coder-V2.5 报告（arXiv:2607.05471）的原话大意：
   参数平均 / Task Arithmetic / 顺序多域 SFT 都会出现跷跷板效应，
   因为【参数空间的合并破坏了专家特有的结构】，
   而离线监督又引入了训推不匹配。
   ⟹ 所以 MOPD 改在【函数空间】做融合。

★★ "函数空间"是什么意思：
   我不管你参数长什么样，我只要求
   【给同样的输入，学生的输出分布 ≈ 老师的输出分布】。
   —— 这个要求是良定义的，而"参数平均"不是。
```

## 8.5 一个 2026 年的新进展：学生能超过老师

✅ **Learning beyond Teacher: Generalized On-Policy Distillation with Reward Extrapolation（ExOPD）**
（[arXiv:2602.12125](https://arxiv.org/abs/2602.12125)，Wenkai Yang 等，2026-02）

```
常识：蒸馏的天花板是老师。学生最多追平老师。

ExOPD 报告：在把多个领域专家合并回原始 base 时，
   它是【唯一】能让统一学生【一致地超过所有领域老师】的方法。

⚠️ 学术工作，单一课题组结果，尚未见工业报告采用。
⚠️ 但方向值得注意：论文把"多教师合并"称为一种
   【有效的新多任务后训练范式】—— 这和五家报告的实际动作是一致的。
```

## 8.6 失败模式：OPD 不是万能的

⚠️ 下面这些来自 OPD 综述（[arXiv:2604.00626](https://arxiv.org/abs/2604.00626)，Mingyang Song 等，2026-04）和社区整理：

```
① 多样性坍缩
   学生一味模仿老师的分布，输出多样性下降
   ⟹ 后续如果还要做 RL，探索空间已经被压扁了（和 02.5 病三同源）

② tokenizer 不匹配
   ★ 老师和学生分词器不同时，"逐 token 对齐"根本无从谈起
   ⟹ 这是跨家族蒸馏（用别家模型当老师）最硬的一道墙

③ 思维模式不兼容
   老师习惯长思维链、学生是 non-thinking 模式 → 蒸不动

④ 老师没有"新东西"可给
   如果老师的能力学生已经有了，OPD 只是在浪费算力
   ✅ 成功条件之一是【老师具备学生没有的能力】
```

```
★ 补一条工程注意：OPD 需要老师的【完整输出分布】（logits）。
  用开源模型当老师可以（拿得到 logits），
  用闭源 API 当老师【做不了标准 OPD】—— 只能退回 off-policy 蒸馏。
```

## 8.7 这一章的三句话总结

```
① on-policy 蒸馏 = 学生自己走路，老师在每一步旁边点评。
   它把老师变成了一个逐 token 的稠密奖励模型 ——
   所以它其实是 RL，不是 SFT。

② 2026 年五家用同一个式子做了两件不同的事：
   【合并多个专家】（DeepSeek / K3 / Pangu / Nemotron）
   【找回被后续阶段遗忘的能力】（GLM-5）

③ 它比参数平均好，是因为它在【函数空间】而不是【参数空间】合并；
   它的硬门槛是老师要能给出 logits，且 tokenizer 要一致。
```
