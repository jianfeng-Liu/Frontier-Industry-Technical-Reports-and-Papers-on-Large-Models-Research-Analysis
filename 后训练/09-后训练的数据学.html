09 · 后训练的数据与配比

这一章讲一件很容易被忽略的事：进入 RL 阶段之后，"数据"这个词的意思变了。

读完你应该能回答：RL 的训练集到底是什么？为什么给 SFT 挑数据的那套方法搬到 RL 上会失效？以及——为什么"最难的题"不是最有价值的题。

📖 和隔壁那一章的分工（别读重了）：../数据格式和数据处理/15-后训练数据格式.md 讲的是格式——字段叫什么、loss_mask 怎么标、SFT / 偏好对 / RLVR 三种格式并排对照。本章讲数据本身的性质：多少条、多难、多散、多干净、怎么配。先看格式那一章，再回来看这一章。

本章关键词

SFT（Supervised Fine-Tuning，监督微调）—— 给"问题 + 标准答案"，只在答案那段 token 上算 loss。

RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励的强化学习）—— 奖励来自一段判分程序（跑单测、对答案、匹配正则），不是奖励模型。

Agentic RL（Agentic Reinforcement Learning，智能体强化学习）—— 一条样本是一次多步工具交互，奖励来自环境的真实反应。

rollout（采样 / 展开）—— 让模型针对一道题真的跑一遍，产出一条完整输出或一整条多步轨迹。RL 里最贵的一步。

拒绝采样（rejection sampling）—— 对同一道题采样 N 次，用验证器筛出做对的，再挑一条当 SFT 数据。

GRPO（Group Relative Policy Optimization，组相对策略优化）—— 同一道题采 G 次，用组内相对好坏当优势，不需要价值网络。本章反复用到它的一个性质：组内全对或全错时，优势为 0。

优势（advantage，记作 Â）—— "这条输出比同组平均好多少"。正的加强，负的削弱，0 就是白跑。

近重复（near-duplicate）—— 不是逐字相同，但措辞高度相似的两条数据。用 MinHash / SimHash 一类方法检出。

这一章后面所有内容，都是在讲下面这张表里的某一格。 先把表看一遍，再往下读。

🔑 三件要一起记的事：
① 这五个维度不能互换。10 万条脏数据换不来 1 万条干净数据，但 1 万条干净数据也换不来"覆盖 15 个任务型"——规模管覆盖面，质量管别学坏，两者是不同的病。
② 维度 ②（难度分布）是后训练独有的。预训练数据没有"难度"这个可操作的概念，因为预训练不按题目组织。
③ ⚠️ "典型值"那一列是量级参考，用来判断"我的数据是不是离谱"，不是目标值。各家实际用什么，多数没有逐一披露。

9.1 ★★ "数据"这个词，在后训练的三个阶段指三种东西

【SFT 阶段】数据 = 问题 + 标准答案
   { "messages": [ {user: "..."} , {assistant: "..."} ] }
   ★ 答案是数据的一部分

【RLVR 阶段】数据 = 问题 + 一个判分程序
   { "problem": "...", "answer": "42" }   <- answer 不给模型看，只给验证器
   ★★ 答案【不是训练材料】，是【裁判的参考】
   => 模型永远看不到标准解法，它只能自己试

【Agentic RL 阶段】数据 = 任务 + 一整套可运行的环境
   { "task": "修好 CI", "repo_snapshot": ..., "dockerfile": ...,
     "test_cmd": ..., "success_criteria": ... }
   ★★★ "一条数据"现在是【一个可以跑起来的系统】

把三个阶段并排放，差别一眼能看出来：

SFT RLVR Agentic RL
一条数据是什么 一段带标准答案的对话 一道题 + 一个判分程序 一个可运行的环境
标准答案给谁看 ★ 给模型看（它就是学习目标） ★ 只给验证器看，模型看不到 常常没有标准答案，只有成功判据
回答从哪来 数据集里给定 ★ 模型训练时自己 rollout 模型多步交互产生
造一条的成本 中（写或筛一条好答案） 低（一道题 + 一个判题器） ★★ 高（接近造一个小型 CI 系统）
造一条需要的技能 NLP / 领域专家 领域专家 + 会写判分脚本 ★★★ DevOps（沙箱、镜像、依赖、并发）
能不能无限扩 ❌ 受标注产能限制 ✅ 判题器不累，可无限采样 ⚠️ 受环境生产产能限制

🔑 这个变化的直接后果：数据团队的工作从"洗文本"变成了"造环境"——需要的技能从 NLP 变成了 DevOps（Development & Operations，开发运维）。
✅ 这也是 ../数据格式和数据处理/19-研究热点与未来方向.md 说"一条数据是什么"的定义正在改变的意思——那一章是从数据侧看同一件事。

9.2 SFT 数据从哪来：三个来源

① 人工编写           占比最小，但质量最高
   用于：退火阶段的精修数据、安全数据、风格标杆
   ⚠️ 贵。一条高质量的长思维链数学解答，标注成本可以到几十美元
      （⚠️ 这是业内流传的量级，没有公开披露的价目表，别当硬数字引用）

② ★ 拒绝采样（主力）  见 03 章
   用现有模型（或领域专家）对题目采样 N 次 -> 验证器筛出对的 -> 挑一条最好的
   ✅ 这是 2024 年之后 SFT 数据的【绝对主力】
   ✅ DeepSeek-R1 用这个方法造了约 60 万条推理数据 + 约 20 万条非推理数据
      （arXiv:2501.12948）

③ 合成 / 改写
   用强模型改写已有数据、造新题、造多轮对话、造工具调用轨迹
   ⚠️ 风险：多样性坍缩，全部数据带同一个模型的口音

一个必须知道的坑：

★★ 拒绝采样有一个内在偏置：它只保留【模型现在就能做对的题】。
   => 数据分布会向"模型已经会的"倾斜
   => 训完之后模型在会的题上更稳，但能力边界没有扩张

⚠️ 这和 05 章那场 pass@k 争论说的是同一件事的两个侧面。
   缓解手段：故意保留一部分"采样 16 次才对 1 次"的难题。

⚠️ 这里要分清两句话：「拒绝采样会让数据偏向模型已会的题」是机制上的必然（筛选条件就是"做对了"）；「所以 SFT 之后能力边界不会扩张」是我的推论，论文没有给出这个因果链的直接证据。

9.3 配比：和预训练的"配比"不是一回事

配比方法论见 03 章。这里先把一个最容易混的点钉死："配比"这个词在预训练和后训练里配的东西不一样。

预训练配比 后训练配比
配的是什么 语料域：网页 / 代码 / 数学 / 书 / 多语 ★ 任务类型 × 难度档：数学 / 代码 / 指令 / 工具 / 安全 × 易-中-难
单位 token 数（占总 token 的百分比） SFT：样本条数
RL：题目数，或 rollout 预算
一次调整的粒度 百分点（网页 70% → 65%） 整类任务的增删（加一个新的工具协议、砍掉一类题）
主要约束 总 token 预算、每份语料重复几遍（epoch） SFT：标注产能
RL：rollout 算力
怎么调 有自动方法：DoReMi / RegMix 等
（见 ../数据格式和数据处理/10-数据配比.md）		 ⚠️ 基本靠人定 + 在线动态过滤（按组内成功率把题踢出题池）
配错的症状 某域 loss 偏高、该域下游基准偏低 ★ 跷跷板：一个能力涨、另一个能力掉（见 10 章的能力矩阵）
奖励尺度问题 不存在 ⚠️ 存在：数学 0/1、代码 0~1、安全 −1~1，不归一化会被尺度大的域主导梯度

🔑 一句话抓住差别：预训练配比问的是"喂多少字"，后训练配比问的是"出哪些题、每类出多少道、多难"。所以预训练的配比工具（DoReMi、RegMix 这类按域优化 token 权重的方法）在后训练里没有直接对应物——这也是后训练配比到 2026 年还基本靠人拍的原因。

三条 RL 阶段特有的补充：

① RL 阶段的"配比"是【题目池的配比】，不是 token 配比
   => 单位是"题目数"或"rollout 预算"，不是 token 数
   ⚠️ 推论：报 RL 数据量时只说"多少 token"等于没说，
      因为同一道题采 8 次和采 64 次，token 差 8 倍，题目数一样。

② 多域混合 RL 会有【奖励尺度冲突】
   数学奖励是 0/1，代码奖励是"通过率 0~1"，安全奖励可能是 −1~1
   ⚠️ 不做归一化，尺度大的域会主导梯度
   ✅ DeepSeek-V4 报告给出的理由是：权重合并会因参数空间不对齐而失效，
      而混合 RL 会让不同领域的奖励互相冲突 —— 这是它选择
      "先分域训专家、再 OPD 合并"的直接依据。
      ⚠️ 这是对报告论点的转述，不是逐字引文；
         原文见 ../业界模型技术报告/DeepSeek-V4.md §八。

③ 但也有反方：统一混训能防止单任务回退
   ✅ Nemotron 3 Super（arXiv:2604.12374）Stage 1 就是
      【多环境 RLVR 联合优化】，覆盖 21 个环境、37 个数据集，
      理由是"统一混合训练让每次更新都感知完整环境分布"

★★ 两条路线并存，说明这件事【还没有共识】。
   ⚠️ 我的判断（不是任何报告的结论）：
      奖励尺度差异大、领域冲突强时分开训；环境同构、奖励可归一时混合训。

9.4 ★★★ SFT 的选数据方法，搬到 RL 上会失效

这是本章最有实用价值的一节。

✅ LearnAlign（arXiv:2506.11480，Shipeng Li 等，2025-06）报告的核心观察是：传统 SFT 数据选择方法在 RLVR 范式下效果有限且不一致，没有一个 SFT 风格的基线能稳定超过"随机采样"。

⚠️ 口径说明：上面这句是对该论文结论的转述，不是逐字引文（本目录 papers/ 未归档 PDF）。引用具体基准数量、提升幅度前请回溯原文。

为什么会失效（原因很干净）：

SFT 的目标：最大化目标输出的似然
   => 【越难的样本信息量越大】 —— 挑难的是对的

RLVR 的目标：最大化奖励
   => 需要的是【和模型当前能力匹配】的难度

   题目太简单 -> 8 次全对 -> 优势全 0 -> 白跑（见 05 章）
   题目太难   -> 8 次全错 -> 优势全 0 -> 白跑

★★★ 所以 RL 要的不是"最难的题"，是【中等难度的题】——
   具体说，是模型成功率在中间区段的那些题。

★★★ 把"中等难度最值钱"算出来：一张逐行推演表

上面那段话听着像经验之谈。其实它可以直接算，而且只需要一行乘方。

  设：模型在某道题上的单次成功率 = p（把每次 rollout 当独立的抛硬币）
      GRPO 一道题采 G 次

  这道题【白跑】的条件是 G 次全对或全错：
      P(全对) = p^G
      P(全错) = (1 − p)^G

  ★★★ 所以这道题【能产生非零梯度】的概率：
      P(有效) = 1 − p^G − (1 − p)^G

代入 G = 8 和 G = 16，逐行算一遍（建议拿计算器跟着按一遍，按过的数字才会变成直觉）：

单次成功率 p p^8 (1−p)^8 P(有效), G=8 P(有效), G=16 这是什么样的题
0.01 ≈0 0.9227 ⚠️ 7.7% 14.9% 几乎做不出
0.05 ≈0 0.6634 33.7% 56.0% 很难
0.10 ≈0 0.4305 56.9% 81.5% 难
0.25 0.0000153 0.1001 90.0% 99.0% ★ 偏难，好用
0.50 0.003906 0.003906 ★★★ 99.2% 100.0% ★★★ 最值钱
0.75 0.1001 0.0000153 90.0% 99.0% ★ 偏易，好用
0.90 0.4305 ≈0 56.9% 81.5% 简单
0.99 0.9227 ≈0 ⚠️ 7.7% 14.9% 几乎必对
1.00 / 0.00 1 / 0 0 / 1 ❌ 0% ❌ 0% ★ 纯浪费

三条能直接拿去用的结论：

① 曲线关于 p = 0.5 对称，峰值在 0.5。
   => "太难"和"太简单"是【同一种病】，不是两种。

② p = 0.99 和 p = 0.01 的有效率都只有 7.7%（G=8）。
   ★ 翻译成钱：你花了 8 次 rollout 的算力，92.3% 的概率什么都没学到。
   ⚠️ 一个常见误解是"简单题至少能巩固一下" —— 不会，优势是 0，梯度就是 0。

③ G 从 8 翻到 16，可用难度窗口明显变宽
   （p=0.1 处：56.9% -> 81.5%）。
   ★★ 所以"组大小 G"和"题目难度分布"是【同一个旋钮的两头】：
      题池偏两端时，加大 G 能救一部分；但 G 的成本是线性的 rollout 算力。

⚠️ 这张表的三个限制，不说清会被用歪：
① 它把 G 次 rollout 当独立同分布。真实 rollout 之间相关（同一个模型、同一个 prompt、温度有限），所以真实的"全对/全错"概率比表里更高，有效率比表里更低——这张表是乐观估计。
② "有效"只是说梯度非零，不等于"价值相同"。优势的方差也影响学习效率，这一层表里没有。
③ P(有效) 是我按二项分布推的（⚠️ 标准做法，但不是某篇论文的结论）。GRPO 里"组内全对/全错 → 优势为 0"这件事本身是算法的定义性质，见 05 章。

几个具体做法：

· 在线过滤：训练中记录每道题的历史成功率，把"永远全对"和
  "永远全错"的题踢出题池
  ✅ openPangu-2.0 的"在线动态过滤"就是这个
· 离线选择：按难度分布采样（有工作让采样概率正比于难度的正态密度，
  即优先取中间难度）
· 让"选题器"自己学一条【课程】（由易到难自动排序）
  ✅ 见 Selector-Guided Autonomous Curriculum for One-Shot RLVR
     （arXiv:2605.01823，Rudray Dave 等，2026-05）
  ⚠️ 该工作规模较小，结论尚属初步

🔑 一个很容易被跳过的实践点：难度是相对于当前这一版模型的，不是题目的固有属性。模型一边训一边变强，昨天 p=0.4 的题今天可能 p=0.8。所以难度过滤必须在线做，离线标一次难度然后一直用，训到后面就全是简单题。

9.5 ★★★ "少而精"还是"多而杂"：把账算出来

✅ One-shot RLVR（arXiv:2504.20571）：1 条题 ≈ 7500 条题的效果（见 05 章）
✅ LIMA（Less Is More for Alignment，"对齐上少即是多"，arXiv:2305.11206）：
   约 1000 条 SFT 数据就能把对话格式教会

⚠️ 这两个结果非常容易被误读成"数据不重要了"。正确读法是：

   ① 它们说明【格式和"开关"类的能力】不需要多少数据
   ② 但【覆盖面】需要数据 —— 你要模型会 15 个域，
      就得有 15 个域的题
   ③ 更重要的是：它们把矛盾从"数据量"转移到了【数据选择】
      —— 既然一条题就能起作用，那"挑哪一条"就是全部问题

📖 这个取舍在 ../数据格式和数据处理/15-后训练数据格式.md §15.9 有一段定性讨论（含 LIMA 的核对说明）。本节补的是那里没有的东西：一笔能自己验算的账。

★★★ 1 万条高质量 vs 10 万条普通：逐行算一遍

先说清这笔账的模型（⚠️ 下面的比例是为讲解构造的，不是任何一家的实测值；但每一步都标了怎么量，你可以拿自己的数据跑一遍）：

   ★★ 关键的一步，也是最反直觉的一步：
      【SFT 里一条错答案不是 0 分，是负分。】
      因为 SFT 的 loss 就是"照着这段文字说"，
      你喂一条错的，它就老老实实把错的学会。

   => 所以不能只算"有多少条对的"，要算【净有效量】：
         净有效量 = 去重后的正确条数 − k × 错误条数
      其中 k = "一条错数据能抵消几条对数据"。
      ★★★ k 是这整件事唯一的决策变量。
步骤 方案 A：1 万条精筛 方案 B：10 万条未筛 这一步怎么量
① 名义条数 10,000 100,000 wc -l
② 答案正确率 98% 75% ★ 抽 300 条人工复核，或用另一个验证器重跑
③ 正确条数 =①×② 9,800 75,000 —
④ 错误条数 =①−③ 200 ⚠️ 25,000 —
⑤ 近重复率 5% 40% MinHash（阈值 0.8）两两比
⑥ 去重后正确条数 =③×(1−⑤) 9,310 45,000 —
⑦ 净有效量（取 k=1） 9,310 − 200 = 9,110 45,000 − 25,000 = 20,000 ★ B 赢
⑦′ 净有效量（取 k=3） 9,310 − 600 = 8,710 45,000 − 75,000 = ⚠️ −30,000 ★★★ A 赢，而且 B 是负的 
   验算第 ⑥ 行 A：9,800 × 0.95 = 9,310  ✓
   验算第 ⑥ 行 B：75,000 × 0.60 = 45,000  ✓
   验算第 ⑦′ 行 B：45,000 − 3 × 25,000 = 45,000 − 75,000 = −30,000  ✓

🔑 这张表真正的结论不是"A 好"或"B 好"，而是：
"少而精 vs 多而杂"根本不是一个可以一般性回答的问题——它取决于 k，而 k 是你自己数据集上的一个可测量。
k 小（错数据几乎无害）→ 加量有用；k 大（错数据毒性强）→ 加量是在倒扣分。
⚠️ 而 k 为什么会大：错答案常常集中在同一类题上（合成管线在哪里失败就在哪里一直失败），于是它不是均匀噪声，而是系统性地教了一个错模式。

★★ 怎么判断自己在哪一侧：四条可操作判据

判据 怎么测 落在哪一侧
① 错误率 随机抽 300 条人工复核
（★ n=300、p≈0.05 时标准误 ≈ 1.3 个百分点，够用了）		 > 5% → ⚠️ 先清洗，加量毫无意义。你在"多而杂"一侧
② 近重复率 MinHash，阈值 0.8 > 30% → 名义条数虚高，先去重再谈规模
③ 任务型覆盖 按目标任务型分桶，数每桶条数 有任何一个目标能力是 0 条 → 缺的是覆盖面，这时"精"救不了你，必须加数据
④ ★★★ 子集学习曲线 用 10% / 30% / 100% 的数据各训一次，画三点 30% → 100% 几乎不涨 → ★ 你已经在"多而杂"一侧，继续加同源数据没有回报；
还在明显上涨 → 加量仍然划算		 
   ★★★ 判据 ④ 是唯一能【直接回答"要不要继续加数据"】的那一条，
      而且它不需要你先猜出 k —— 子集消融把 k 的影响一起测进去了。
   ⚠️ 代价：要多训两次。但比"攒了 50 万条才发现 30% 就够"便宜得多。

   ★ 验算判据 ① 那个标准误：
      SE = sqrt( p(1−p) / n ) = sqrt( 0.05 × 0.95 / 300 )
         = sqrt( 0.0475 / 300 ) = sqrt( 0.00015833 ) = 0.0126
      => 约 1.3 个百分点。
      ⟹ 所以"抽 300 条量错误率"能把 5% 和 10% 分开，
         但分不开 5% 和 6%。（这条公式见 10 章和附录速查表）

★ 一句话：后训练的数据竞争，已经从"谁的数据多"变成了"谁挑得准"——而"挑得准"是可以量化的，不是手感。

9.6 一个容易忽略的坑：评测污染

后训练数据大量来自 GitHub、公开题库、合成、以及模型自己生成。这几个来源都可能把评测题带进训练集。

污染路径 具体怎么发生 n-gram 匹配查得到吗 对策
① 题库直接重叠 RL 题池从公开题库来，AIME / Codeforces / LeetCode 的题和评测集高度重叠 ✅ 查得到 对题池和评测集做 n-gram 去重
② 老师模型"记忆"泄漏 拒绝采样用的老师模型本身见过评测集，把记住的解法写进了你的合成数据 ⚠️ 查不到原题，但可能查到标准解的措辞 ★ 换一个没见过该评测集的老师；或只用私有题
③ 环境重叠 Agentic RL 的仓库环境和 SWE-bench 的仓库重叠 ❌ 完全无效 ★★ 比对代码库 + 提交版本，不是比对文本 
★ 为什么后训练阶段的污染比预训练更隐蔽：
   数据量小、来源杂、迭代快，而且很多团队根本没有对后训练数据建去污染流程
   —— 预训练那边有，后训练这边常常是空的。

⚠️ 这是我的观察，不是哪份报告的统计结论。

9.7 这一章的三句话总结

① "数据"在后训练三个阶段指三种东西：
   带答案的样本 -> 带裁判的题目 -> 能跑起来的环境。
   ★ 而数据只有五个维度：规模 / 难度分布 / 多样性 / 质量 / 去重（见 9.0 那张总表）。

② 给 SFT 挑数据的方法搬到 RL 上会失效，
   因为 SFT 要"最难的"，RL 要"难度刚好匹配当前能力的"
   —— 这件事可以算：G=8 时 p=0.99 的题有效率只有 7.7%（9.4）。

③ "少而精 vs 多而杂"没有一般答案，取决于【一条错数据抵消几条对数据】；
   而"要不要继续加数据"有一条不用猜的判据：★ 画 10%/30%/100% 的子集学习曲线。
