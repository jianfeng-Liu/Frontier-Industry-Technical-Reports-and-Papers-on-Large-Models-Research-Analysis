# 09 · 后训练的数据与配比

> **这一章讲一件很容易被忽略的事：进入 RL 阶段之后，"数据"这个词的意思变了。**
> 读完你应该能回答：RL 的训练集到底是什么？为什么给 SFT 挑数据的那套方法搬到 RL 上会失效？以及——**为什么"最难的题"不是最有价值的题。**

---

## 9.1 ★★ "数据"这个词，在后训练的三个阶段指三种东西

```
【SFT 阶段】数据 = 问题 + 标准答案
   { "messages": [ {user: "..."} , {assistant: "..."} ] }
   ★ 答案是数据的一部分

【RLVR 阶段】数据 = 问题 + 一个判分程序
   { "problem": "...", "answer": "42" }   ← answer 不给模型看，只给验证器
   ★★ 答案【不是训练材料】，是【裁判的参考】
   ⟹ 模型永远看不到标准解法，它只能自己试

【Agentic RL 阶段】数据 = 任务 + 一整套可运行的环境
   { "task": "修好 CI", "repo_snapshot": ..., "dockerfile": ...,
     "test_cmd": ..., "success_criteria": ... }
   ★★★ "一条数据"现在是【一个可以跑起来的系统】
```

> 🔑 **这个变化的直接后果**：
> 数据团队的工作从"洗文本"变成了**"造环境"**——需要的技能从 NLP 变成了 **DevOps**。
> ✅ 这也是 [../数据格式和数据处理/19-研究热点与未来方向.md](../数据格式和数据处理/19-研究热点与未来方向.md) 说"一条数据的定义正在被改写"的意思。

## 9.2 SFT 数据从哪来：2026 年的三个来源

```
① 人工编写           占比最小，但质量最高
   用于：退火阶段的精修数据、安全数据、风格标杆
   ⚠️ 贵。一条高质量的长思维链数学解答，标注成本可以到几十美元

② ★ 拒绝采样（主力）  见 03.2
   用现有模型（或领域专家）对题目采样 N 次 → 验证器筛出对的 → 挑一条最好的
   ✅ 这是 2024 年之后 SFT 数据的【绝对主力】
   ✅ R1 用这个方法造了 60 万条推理数据 + 20 万条非推理数据

③ 合成 / 改写
   用强模型改写已有数据、造新题、造多轮对话、造工具调用轨迹
   ⚠️ 风险：多样性坍缩，全部数据带同一个模型的口音
```

**一个必须知道的坑**：

```
★★ 拒绝采样有一个内在偏置：它只保留【模型现在就能做对的题】。
   ⟹ 数据分布会向"模型已经会的"倾斜
   ⟹ 训完之后模型在会的题上更稳，但边界没有扩张

⚠️ 这和 05.6 那场 pass@k 争论说的是同一件事的两个侧面。
   缓解手段：故意保留一部分"采样 16 次才对 1 次"的难题。
```

## 9.3 配比与跷跷板

配比方法论见 [03.4](03-分训与合训.md)，这里只补三条 RL 阶段特有的：

```
① RL 阶段的"配比"是【题目池的配比】，不是 token 配比
   ⟹ 单位是"题目数"或"rollout 预算"，不是 token 数

② 多域混合 RL 会有【奖励尺度冲突】
   数学奖励是 0/1，代码奖励是"通过率 0~1"，安全奖励可能是 −1~1
   ⚠️ 不做归一化，尺度大的域会主导梯度
   ✅ DeepSeek-V4 报告直言："混合 RL 会让不同领域的奖励互相冲突"
      —— 这是它选择"先分域训专家、再 OPD 合并"的直接理由

③ 但也有反方：统一混训能防止单任务回退
   ✅ Nemotron 3 Super（arXiv:2604.12374）Stage 1 就是
      【多环境 RLVR 联合优化】，覆盖 21 个环境、37 个数据集，
      理由是"统一混合训练让每次更新都感知完整环境分布"

★★ 两条路线并存，说明这件事【还没有共识】。
   ⚠️ 我的判断：奖励尺度差异大、领域冲突强时分开训；
      环境同构、奖励可归一时混合训。
```

## 9.4 ★★★ SFT 的选数据方法，搬到 RL 上会失效

**这是本章最有实用价值的一节。**

✅ **LearnAlign**（[arXiv:2506.11480](https://arxiv.org/abs/2506.11480)，Shipeng Li 等，2025-06）报告：

> **传统 SFT 数据选择方法在 RLVR 范式下效果有限且不一致，没有一个 SFT 风格的基线能在 5 个基准上稳定超过"随机采样"。**

**为什么会失效（原因很干净）**：

```
SFT 的目标：最大化目标输出的似然
   ⟹ 【越难的样本信息量越大】 —— 挑难的是对的

RLVR 的目标：最大化奖励
   ⟹ 需要的是【和模型当前能力匹配】的难度

   题目太简单 → 8 次全对 → 优势全 0 → 白跑（见 05.3）
   题目太难   → 8 次全错 → 优势全 0 → 白跑

★★★ 所以 RL 要的不是"最难的题"，是【中等难度的题】——
   具体说，是模型成功率在中间区段的那些题。
```

```
一张很好用的直觉图：

   样本价值
      ▲
      │        ╱▔▔▔╲
      │      ╱       ╲
      │    ╱           ╲
      │  ╱               ╲
      └─────────────────────────▶ 模型在这道题上的成功率
       0%      50%        100%
       ↑        ↑           ↑
     太难     ★最值钱      太简单
    (全错)               (全对)
```

**几个具体做法**：

```
· 在线过滤：训练中记录每道题的历史成功率，把"永远全对"和
  "永远全错"的题踢出题池
  ✅ openPangu-2.0 的"在线动态过滤"就是这个
· 离线选择：按难度分布采样（有工作让采样概率正比于难度的正态密度，
  即优先取中间难度）
· 让"选题器"自己学一条【课程】（由易到难自动排序），
  ✅ 见 Selector-Guided Autonomous Curriculum for One-Shot RLVR
     （arXiv:2605.01823，Rudray Dave 等，2026-05）
  ⚠️ 该工作规模较小，结论尚属初步
```

## 9.5 数据高效的极限，和它的正确读法

```
✅ One-shot RLVR（arXiv:2504.20571）：1 条题 ≈ 7500 条题的效果（见 05.7）
✅ LIMA（arXiv:2305.11206）：1000 条 SFT 数据就能把对话格式教会

⚠️ 这两个结果非常容易被误读成"数据不重要了"。正确读法是：

   ① 它们说明【格式和"开关"类的能力】不需要多少数据
   ② 但【覆盖面】需要数据 —— 你要模型会 15 个域，
      就得有 15 个域的题
   ③ 更重要的是：它们把矛盾从"数据量"转移到了【数据选择】
      —— 既然一条题就能起作用，那"挑哪一条"就是全部问题
```

★ **一句话**：**后训练的数据竞争，已经从"谁的数据多"变成了"谁挑得准"。**

## 9.6 一个容易忽略的坑：评测污染

```
SFT / RL 的数据大量来自：GitHub、题库、合成、以及【模型自己生成】。

⚠️ 三个污染路径：
   ① 题库直接和评测集重叠（AIME 题在网上到处都是）
   ② 拒绝采样用的老师模型【本身见过评测集】，把答案"记忆"进了合成数据
   ③ Agentic RL 的仓库环境和 SWE-bench 的仓库重叠

★ 后训练阶段的污染比预训练更隐蔽，因为数据量小、来源杂、迭代快，
  很多团队根本没有对后训练数据做去污染。

→ 去污染方法见 ../数据格式和数据处理/08-去污染与隐私许可.md
→ 评测侧的对策见本教程 10 章
```

## 9.7 这一章的三句话总结

```
① "数据"在后训练三个阶段指三种东西：
   带答案的样本 → 带裁判的题目 → 能跑起来的环境。

② 给 SFT 挑数据的方法搬到 RL 上会失效，
   因为 SFT 要"最难的"，RL 要"难度刚好匹配当前能力的"。

③ 数据竞争已经从"谁的多"变成"谁挑得准"，
   而拒绝采样有个内在偏置：它只会保留模型已经会做的题。
```
