# 10 · 评测、能力矩阵与回归

> **这一章讲：怎么知道你这一轮后训练是"变好了"还是"变好了一半、坏了另一半"。**
> 读完你应该能回答：为什么后训练团队最怕的不是分数低而是分数高？pass@1 和 pass@k 该看哪个？以及**为什么 SFT 阶段的分数不能拿来选 RL 的起点。**

---

## 10.1 ★ 后训练的评测，和预训练的评测不是一回事

```
【预训练评测】少数几个指标，看趋势
   loss 曲线 + 几个知识型基准（MMLU 等）
   目标：确认训练没崩、数据没问题

【后训练评测】★★ 一张【能力矩阵】，看的是"有没有哪一格塌了"
   目标：确认这一轮改动【没有把别的能力换掉】
```

**一张典型的后训练能力矩阵长这样**（列是能力，行是训练轮次）：

```
              数学   代码   指令  长文  工具  多轮  安全  中文  幻觉率↓
base           41    35     52    48    12    44    61    55     22
+SFT           68    62     84    71    58    79    88    76     15
+RLVR          79    74     83    70    57    76    86    74     14
                                   ↑     ↑     ↑     ↑
                            ★ 这四格在 RLVR 之后【掉了】
                              ⟹ 这就是"跷跷板"在评测上的样子
+RLHF          78    73     88    73    61    83    94    79     11
                                                      ↑
                              ★ 数学掉 1 分换安全涨 8 分 = alignment tax
```

> 🔑 **后训练团队 90% 的时间在看这张表的"掉了的格子"，而不是"涨了的格子"。**
> ✅ 五家报告都描述了类似机制：GLM-5 的"累积性损害"、DeepSeek-V4 的"领域奖励冲突"、
> Nemotron 3 Super 的"统一混合训练防止单任务回退"，说的都是这张表。

## 10.2 ★★ pass@1 还是 pass@k：一个必须想清楚的选择

先把两个词说清楚：

```
pass@1   让模型答【一次】，对的比例          ← 衡量"稳不稳"
pass@k   让模型答【 k 次】，只要有一次对就算对  ← 衡量"会不会"（能力边界）
         k 常取 8 / 32 / 256
```

```
RL 会让这两个指标【朝不同方向走】：

   分数
    ▲
    │            ┌──── base 的 pass@k（k 很大时）
    │   ┌────────┴───  RL 后的 pass@k
    │  ╱
    │ ╱  ★ RL 明显抬高 pass@1
    │╱   ⚠️ 但在 k 很大时，可能被 base 反超
    └──────────────────────────▶  k
      1     8    32   128  512

★★ 直觉解释：RL 把概率质量【集中】到了它认为对的那条路上。
   ⟹ 抽一次更容易抽到对的（pass@1 ↑）
   ⟹ 但抽 512 次覆盖的解法种类变少了（pass@k 可能 ↓）
```

**该看哪个，取决于你在做什么**：

```
· 上线产品 → 看 pass@1（用户只问一次）
· 判断"RL 到底有没有教会新东西" → 必须看 pass@k
· 做数据生产（拒绝采样） → 看 pass@k（因为你会采 N 次再筛）
· ⚠️ 只报 pass@1 的 RL 论文，无法回答"能力有没有扩张"这个问题

⚠️ 这场争论本身还没结束，见 05.6。我的建议：两个都测、都报。
```

## 10.3 ★★★ 一个反直觉的坑：SFT 分数高 ≠ RL 起点好

✅ [arXiv:2510.01624](https://arxiv.org/abs/2510.01624) 的核心结论：

> **SFT 阶段基准分数最高的那个 checkpoint，往往不是最好的 RL 初始化点。**

```
为什么？

   SFT 训得越久 / 越到位
      ⟹ 输出分布越【尖】（模型对自己的答案越确信）
      ⟹ 采样 8 次得到的 8 条 rollout 越【像】
      ⟹ 组内奖励方差越小
      ⟹ ★ GRPO 的优势 A ≈ 0，梯度接近 0
      ⟹ RL 学不动

   所以一个"分数低一点、但还保留了探索性（熵更高）"的 ckpt，
   反而是更好的 RL 起点。
```

```
★★ 实践含义：选 SFT ckpt 交给 RL 时，
   除了看基准分，还要看【输出熵】和【采样多样性】。
   ⚠️ 这一条在 2026 年之前几乎没有团队系统地做，
      现在开始有报告把"熵"当作 ckpt 选择指标之一。
```

## 10.4 评测污染：后训练阶段更隐蔽

```
预训练污染：15 T token 里混进了评测题 —— 大家都在查
后训练污染：⚠️ 三个更隐蔽的来源

  ① 拒绝采样的【老师模型】见过评测集
     → 它把记住的答案写进了你的 SFT 数据
     → 你的数据里没有原题，但有原题的"标准解"

  ② RL 题池直接从公开题库来
     AIME / Codeforces / LeetCode 的题目和评测集高度重叠

  ③ Agentic RL 的仓库环境和 SWE-bench 的仓库重叠
     ★ 这个最难查，因为"重叠"的不是文本而是【代码库版本】

★ 检测手段：
  · n-gram 匹配（对 ①② 有效，对 ③ 无效）
  · 造【私有 holdout 集】：自己出题，绝不发布，只用来做最终判断
    ✅ 这是 2026 年头部团队的标配做法
  · 看"公开集涨 / 私有集不涨"的差值 —— 差值就是污染量的下界
```

→ 方法细节见 [../数据格式和数据处理/08-去污染与隐私许可.md](../数据格式和数据处理/08-去污染与隐私许可.md)

## 10.5 ★★ 怎么发现 reward hacking（分数涨了但模型变坏了）

奖励作弊的机制见 [06.5](06-奖励从哪来.md)。这里是**评测侧的抓法**：

```
① 训练奖励 ↑ 但【留出集分数不动或 ↓】
   ★ 最经典的信号。奖励和真实能力脱钩了。

② 输出长度异常
   长度暴涨 → 可能在刷"长回答被打高分"的偏置
   长度暴跌 → 可能发现了"短答案更容易通过判分正则"

③ 格式关键词频率突变
   突然每条回答都以某个短语开头/结尾 → 在讨好判分器

④ ★ 人工抽样看 100 条
   ⚠️ 听起来很土，但这是唯一能发现【未知作弊模式】的方法。
      自动指标只能抓你已经想到的作弊方式。

⑤ 换一个判分器复测
   用规则判分训的，就用 LLM-as-judge 复测；反之亦然。
   两个判分器的分差突然拉大 = 在针对其中一个过拟合。
```

✅ 已发表的三个真实案例（数据见 [06.5](06-奖励从哪来.md)）：ARE 的"刷判官"、
Gaming Verifiers 观察到的 ~500 步后作弊分差、代码 RL 环境审计出的 ~61.9% 缺陷率。

## 10.6 一套可操作的回归清单

```
每一轮后训练结束，至少跑这七类：

  □ 能力矩阵（8~15 个域）—— 对比【上一轮】和【base】两个基线
  □ pass@1 + pass@k(k≥8) 各一份
  □ 私有 holdout 集
  □ 长上下文专项（★ 很容易被后训练悄悄破坏，因为 SFT 数据大多是短的）
  □ 多轮对话 / 指令遵循（单轮基准发现不了多轮的退化）
  □ 安全 + 越狱（★ 最容易被 RLVR 洗掉，见 12 章）
  □ 输出长度分布 + 熵 —— 不是能力指标，是【健康度】指标

★ 加两条纪律：
  · 每一格都要能追溯到【是哪一个阶段导致的下降】
    ⟹ 所以每个阶段的 ckpt 都要留，不能只测最终模型
  · 训练奖励曲线和留出集曲线要【画在同一张图上】
    ⟹ 两条线分叉的那一刻，就是 reward hacking 开始的时刻
```

## 10.7 ⚠️ 一个还没解决的问题：评测本身正在失效

```
🔮 三个正在恶化的趋势：

  ① 公开基准饱和 —— 前沿模型在 MMLU / GSM8K 上都 90+，区分不出来了
  ② 污染速度快于出题速度 —— 新基准发布几个月就被吃进训练数据
  ③ ★★ Agentic 能力【没有好的基准】
     "能不能修好一个真实 bug"这件事，
     难以用一个静态数据集刻画，因为它依赖环境、依赖多步交互、
     而且成功标准本身是模糊的

⚠️ 结果是：2026 年很多团队的真实决策依据，
   已经从公开基准转向【内部私有集 + 人工盲测 + 线上 A/B】。
   ⟹ 这也意味着【外部读者越来越难验证一份技术报告的强弱声称】。
```

## 10.8 这一章的三句话总结

```
① 后训练评测看的是【能力矩阵里哪一格塌了】，
   不是总分涨了多少 —— 因为跷跷板是常态。

② pass@1 和 pass@k 会朝不同方向走：
   RL 提高"稳"，但不一定提高"会"。两个都得报。

③ 训练奖励曲线和留出集曲线画在一张图上，
   分叉的那一刻就是 reward hacking 开始的时刻。
```
