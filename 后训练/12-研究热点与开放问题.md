## 12.0 ★★★ 十个热点，其实只有两个源头

在展开之前，先给一张因果图。下面十个方向不是并列的，它们都是从**两件事**长出来的：

```
源头一：人被移出了回路（见 11 章那条主线）
   |
   ├── 谁来定义"好"？        --> ① 奖励作弊 ／ ④ 安全能否存活
   ├── 谁来出题 / 造环境？   --> ② 环境合成
   └── 谁来验证模型？        --> ③ 评测危机（见 10.7）

源头二：RL 成了主要的算力去处
   |   ⚠️ "从约 5% 涨到与预训练同量级"这个说法的口径很糙，见 12.5 的警告
   |
   ├── 花这么多算力值不值？  --> ⑤ RL scaling law ／ ⑦ 持续 / 在线学习
   ├── 怎么才不训崩？        --> ⑥ 熵与多样性 ／ ⑨ OPD 会不会统一一切
   └── 阶段还有必要分吗？    --> ⑧ SFT 该不该存在 ／ ⑩ 多模态与具身

★★ 记住这两个源头，下面十节你可以任意跳读。
```

### ★★★ 十个开放问题的总表：最后一列才是这一章的价值

**读"研究热点"最没用的读法，是只记住"这是个难题"。** 下面这张表的**第四列**给的是**可观察的判据**——一年后你不需要重读文献，只要去看那一列里的东西有没有变，就知道这个方向有没有真的动。

| # | 方向 | 它想解决什么 | 现在卡在哪 | ★★★ 怎么判断它有没有进展（可观察） |
|---|---|---|---|---|
| **①** | **环境合成**（12.1） | Agentic RL 的训练样本 = 可运行环境，而环境造不出量 | 造一个高质量环境接近造一个小型 CI 系统；自动合成有"上限是模型自己"的循环论证风险 | ★ 看报告里有没有出现**「合成环境 vs 人造环境」的同条件消融**，以及"合成环境训出的模型在**真实**环境上的分数"。只报环境数量（21 个、37 个）**不算进展** |
| **②** | **奖励作弊**（12.2） | 优化器会找到"拿高分但没解决问题"的捷径 | 没有可证明抗作弊的奖励；换成 LLM 判官只是把军备竞赛推高一层 | ★★ 看**「作弊率」有没有变成常规上报指标**（像标准误那样默认附带）；以及有没有公开的作弊基准 + 可复现排行榜 |
| **③** | **评测危机**（12.3） | 公开基准饱和 + 污染快于出题，领域失去共同判据 | agentic 能力没有静态数据集能刻画 | ★ 看**新基准从发布到饱和的时间**有没有变长；有没有出现被多方接受的**第三方私有评测**（而不是各家自建私有集） |
| **④** | **安全能否存活**（12.4） | SFT/RLHF 装进去的安全，会不会被后续以成功率为奖励的 RL 洗掉 | 已知"方向取决于环境设计"，即既可能保护也可能放大 | ★★ 看技术报告里有没有**「RL 前 / RL 后」的安全分对照**。现在多数报告只报**最终**安全分——这等于把这个问题藏起来了 |
| **⑤** | **RL 的 scaling law**（12.5） | 继续加 RL 算力还值不值 | S 型 vs 幂律两种拟合在短窗口（几千步）里长得几乎一样 | ★★★ 看有没有人把**观测窗口拉到 10 倍算力**并报出拟合**残差**；以及"RL 的数据量"的自变量（题目数 / rollout 数 / 交互步数）有没有统一 |
| **⑥** | **熵与多样性**（12.6） | 所有后训练都在收窄输出分布，收窄过头就没有自我改进的燃料 | 只有打补丁（clip-higher 等），没有把多样性写进目标 | ★★ 看有没有出现**「健康熵」的推荐区间**（一个可以照着调的数）；以及把多样性写进目标函数的工作有没有**被第三方复现** |
| **⑦** | **持续 / 在线学习**（12.7） | 模型能不能"边用边学" | 灾难性遗忘、无法回滚、安全不可控 | ★★★ **最干净的二元判据**：有没有**任何一家**把在线权重更新用在**生产**模型上。现在是 0。这个数从 0 变成 1 那天，这一节要重写 |
| **⑧** | **SFT 该不该独立存在**（12.8） | SFT 有记忆性、隐式奖励偏置、分数最高的 ckpt 不是最好起点 | 纯 RL 的可读性和语言混杂问题很严重，SFT 冷启动还去不掉 | ★★ 看技术报告里 **SFT 用了多少 token / 占多少算力**。这个数字持续下降 = 判断被验证；SFT 从"一个阶段"变成"一个损失项" = 彻底验证 |
| **⑨** | **OPD 会不会统一一切**（12.9） | 多个专家无法合并、被遗忘的能力要捞回来 | 学生超过老师之后谁当老师（自举边界）；闭源 API 给不了 logits | ★ 看一年后大家**是不是还在用同一个式子** `Â = sg[log(π_teacher / π_student)]`。还在 = 它真的收敛了；出现新的收口方式 = OPD 只是过渡态 |
| **⑩** | **多模态与具身**（12.10） | 文本那一整套要不要原样再走一遍 | 多模态的"可验证奖励"难定义；具身 rollout 慢几个数量级 | ★★ 看有没有出现一个**被广泛接受的多模态可验证奖励**（像单元测试对代码那样确定）。没有这个，整条路线就只能停在偏好对齐 |

```
★★ 这张表怎么用：

  ① 把第四列抄成一张 checklist，半年看一次。
  ② ⚠️ 注意第四列里【几乎没有一条是"看分数涨没涨"】。
     原因：分数会因为污染、脚手架、评测口径而涨（见 10 章），
     ⟹ 🔑 真正的进展标志是【有了新的可测量】或【有了同条件的对照】，
        而不是某个榜单上多了几分。
  ③ ★ 第 ⑦ 行是唯一的二元判据（0 或 1），
     所以它也是这十条里最容易判断、最不会自欺的一条。

⚠️ 第四列是我整理的判据，不是任何论文提出的评价标准。
   它的作用是让你有可观察的抓手，不是权威口径。
```

## 12.1 ① 环境合成：2026 年最贵的东西

```
✅ 已发表：环境是瓶颈，五家报告都说了
   · GLM-5.3 明确把"环境的构建与扩展"列为核心瓶颈
   · Nemotron 3 Super 报告了 21 个环境 / 37 个数据集的规模
     （arXiv:2604.12374）
   · ARE（arXiv:2509.17158，Romain Froger 等，2025-09）把
     "扩大 agent 环境与评测的规模"本身当成了研究对象

⚠️ 我的判断：环境正在成为新的【数据护城河】。
   预训练时代的护城河是"谁清洗了更多网页"，
   Agentic 时代的护城河是"谁有更多能跑起来的真实任务"。
   这也解释了为什么各家都在自建代码托管、终端、浏览器沙箱能力。

🔮 开放问题：
   · 环境能不能【自动合成】？（让模型自己造题 + 自己造验证器）
     ⚠️ 这里有个循环论证的危险：模型造的环境，上限是模型自己
   · 合成环境和真实环境的迁移差距有多大？没有公认的度量
   · 一个环境值多少钱？—— 没有"环境的 scaling law"
```

> **★ 怎么判断它有进展**：看有没有「**合成环境 vs 人造环境**」的同条件消融，以及"合成环境训出来的模型**在真实环境上**得几分"。⚠️ **只报环境数量不算进展**——21 个环境和 37 个数据集这类数字说明的是投入规模，不是方法突破。

## 12.2 ② 奖励作弊：从"偶发 bug"变成"必须建模的对手"

```
✅ 已发表的三个硬证据（细节见 [6.4 节](06-奖励从哪来.md)）：
   · ARE（2509.17158）：agent 学会刷判官而不是完成任务
   · Hack-Verifiable Environments: Towards Evaluating Reward Hacking
     at Scale（arXiv:2605.20744，Amit Roth 等，2026-05）
     ★ 这篇的意义是它把"作弊"变成了一个【可以被规模化评测的对象】，
       而不是一个个案故事
   · 代码 RL 环境审计：105 个环境里 65 个 FAIL，缺陷率 ~61.9%

⚠️ 我的判断：观念正在从
   「作弊是奖励函数写得不好」→「作弊是优化过程的【必然产物】」。
   只要奖励是真实目标的一个【有损压缩】，
   足够强的优化器一定会去找压缩误差最大的那个方向。
   ⟹ 所以正确的问题不是"怎么写出不会被作弊的奖励"，
      而是"怎么在作弊发生时【尽早发现】"（见 10.5）。

🔮 开放问题：
   · 有没有可能设计出【可证明抗作弊】的奖励？（目前看希望不大）
   · 用 LLM 当判官（GRM），判官自己会不会被作弊？
     ✅ AgentV-RL: Scaling Reward Modeling with Agentic Verifier
        （arXiv:2604.16004，Jiazheng Zhang 等，2026-04）
        的路线是让判官本身变成一个会用工具去核实的 agent
     ⚠️ 但这只是把军备竞赛推高了一层
```

> **★ 怎么判断它有进展**：看「**作弊率**」有没有变成**常规上报指标**——就像标准误那样，报一个 RL 结果时默认附带。⚠️ 现在的状态是：作弊只在**出事后**被当案例讲，没有一家把它当成每轮都要量的东西。从"案例"变成"指标"，就是这个方向真正动了。

## 12.3 ③ 评测危机

见 [10.7](10-评测与回归.md)。一句话：

```
⚠️ 公开基准饱和 + 污染快于出题 + agentic 能力没有好基准
   ⟹ 真实决策依据转向私有集，而外部读者越来越难验证任何强弱声称。

🔮 这件事最坏的后果不是"排行榜不准"，
   而是【领域失去了共同的实验判据】——
   两篇论文说自己更好，但没有第三方能复现这个比较。
```

> **★ 怎么判断它有进展**：**两个**可观察量——**①** 新基准从发布到饱和的时间有没有变长（现在是几个月）；**②** 有没有出现被多方接受的**第三方**私有评测。⚠️ 各家自建私有集**不算**解决——那只是把不可验证从"榜单"搬到了"内部"。

## 12.4 ④ 安全能否在 on-policy RL 之后存活

```
这是一个很多人没意识到的问题：
   你在 SFT / RLHF 阶段辛辛苦苦装进去的安全行为，
   接下来一轮以"解题成功率"为奖励的 RL，会不会把它洗掉？

✅ Safety Training Modulates Harmful Misalignment Under On-Policy RL,
   But Direction Depends on Environment Design
   （arXiv:2604.12500，Leon Eshuijs 等，2026-04）
   ★ 结论很有意思：安全训练确实会调制 on-policy RL 之后的失准程度，
     但【方向取决于环境怎么设计】—— 也就是说，
     它既可能保护、也可能反而放大问题。

✅ Safety Alignment as Continual Learning: Mitigating the Alignment Tax
   via Orthogonal Gradient Projection
   （arXiv:2602.07892，Guanglong Sun 等，2026-02）：
   把安全对齐当【持续学习】问题，用正交梯度投影缓解对齐税（见 04.7）。

⚠️ 我的判断：这就是为什么 2026 年五家都把
   【通用 RL / RLHF 放在最后一个 RL 阶段】—— 不是巧合，
   是因为安全必须是【最后写进去】的，否则会被后面的阶段覆盖掉。

🔮 开放：安全能不能做成"不会被后续训练覆盖"的形式？
   （参数隔离？专门的子空间？目前都还在研究阶段）
```

> **★ 怎么判断它有进展**：看技术报告里有没有「**RL 前 / RL 后**」的安全分**对照**。⚠️ 这一条很尖锐：**现在绝大多数报告只报最终安全分**，于是"中间那一轮 RL 洗掉了多少"这件事在纸面上根本不存在。只要有人开始报这个对照（哪怕数字很难看），这个问题就从"说不清"变成了"可讨论"。★ 怎么自己测：把 RL 前后的 ckpt 在同一套安全集上跑，用 [10 章](10-评测与回归.md) 的 McNemar 配对检验判。

## 12.5 ⑤ RL 的 scaling law：S 型还是幂律

```
✅ ScaleRL（arXiv:2510.13786）：RL 的性能-算力曲线是【S 型饱和曲线】，
   可以用三个参数拟合（A 天花板 / B 效率 / C_mid 半程点），
   并且【大多数算法改动影响的是 B（爬得多快），不是 A（能爬多高）】。
✅ 也有工作（arXiv:2509.25300）主张是【幂律】而非饱和型。

⚠️ 我的判断：这个分歧非常重要，因为它决定一件事：
   【继续加 RL 算力，还值不值得？】
   S 型说：会饱和，加到某个点就该换招。
   幂律说：一直有回报，接着堆。
   ⚠️ 目前观测窗口都太短（几千步），两种曲线在短窗口里长得很像。

🔮 开放：
   · RL 的"数据量"该怎么定义？题目数？rollout 数？环境交互步数？
     —— 连自变量都还没统一，谈 scaling law 是很危险的
   · 有没有"预训练算力 vs RL 算力"的最优分配比？（类似 Chinchilla）
     ⚠️ 这可能是 2026–2027 年最有价值的一个实证问题
```

> ⚠️⚠️ **"RL 算力从约 5% 涨到与预训练同量级"这句话的口径必须说清**，它在本教程里出现了好几次：分子（某一代模型的 RL 阶段卡时）和分母（预训练卡时）**很少来自同一份披露**，而"2026 年已到同量级"这一半**没有任何一家逐一披露过**。⟹ 🔑 把它当作**量级印象**，不要当作可引用的比值。详见 [附录速查表 §C](附-速查表.md) 对这一条的口径说明。

> **★ 怎么判断它有进展**：**①** 有没有人把观测窗口**拉到 10 倍算力**并报出拟合**残差**（现在的分歧全部发生在几千步的短窗口里，两种曲线在那儿长得几乎一样，谁都能说自己拟合得好）；**②** "RL 的数据量"这个自变量有没有统一（题目数？rollout 数？环境交互步数？）。⚠️ 第 ② 条没解决之前，任何"RL 的 scaling law"都不可比——因为横轴都不是同一个东西。

## 12.6 ⑥ 熵与多样性：RL 的慢性病

```
✅ 已知：熵坍缩是 GRPO 类算法的标准病（见 05.3），
   clip-higher（DAPO）等手段能缓解但不能根治。
✅ 已知：on-policy 蒸馏也有多样性坍缩风险（见 08.6）。

⚠️ 我的判断：这几件事其实是【同一件事】：
   所有形式的后训练都在【收窄】模型的输出分布，
   而收窄到某个程度之后，模型就失去了自我改进的燃料
   （没有多样性 → 采样不出新解法 → RL 没有正样本可学）。

   ⟹ 这也是 pass@k 争论（05.6）、SFT ckpt 选择（10.3）、
      拒绝采样偏置（09.2）背后的同一个物理量。
   ★★ 如果要我押一个"2027 年会被系统研究的量"，我押【熵】。

🔮 开放：
   · 能不能把"保持多样性"写进目标函数，而不是靠打补丁？
   · 有没有一个"健康的熵"的量化标准？现在基本靠经验拍
```

> **★ 怎么判断它有进展**：看有没有出现「**健康熵的推荐区间**」——一个你能照着调的数，哪怕是"这个规模、这个阶段，token 级平均熵掉到 X 以下就该停"。⚠️ 现在连这个数的**单位和口径**都不统一（逐 token 熵？序列熵？温度归一化前还是后？）。★ 一个更容易观察的代理指标：技术报告里有没有把熵或 rollout 多样性画成一条**曲线**（而不是只提一句"我们监控了熵"）。

## 12.7 ⑦ 持续学习 / 在线学习：模型什么时候能"边用边学"

```
现状：⚠️ 前沿模型的权重更新【全部是离线的】。
     你和模型聊一百万轮，它的权重一个 bit 都不会变。

✅ Just-In-Time Reinforcement Learning: Continual Learning in LLM Agents
   Without Gradient Updates（arXiv:2601.18510，Yibo Li 等，2026-01）
   ★ 它的路线很典型：既然改权重难，那就【不改权重】——
     把"学到的东西"存在上下文/记忆里，而不是参数里。

⚠️ 我的判断：这是一条务实但有天花板的路。
   记忆里的知识不会像权重里的知识那样被"内化"成能力，
   而且上下文长度是硬约束。
   真正的在线权重更新还卡在三件事上：
     ① 灾难性遗忘  ② 无法回滚（学坏了怎么办）
     ③ 安全（一个能自我更新的模型，怎么保证它不越跑越偏）

🔮 开放：这可能是通向"模型真正持续进步"的必经之路，也可能是个死胡同。
   ★ 目前没有任何一家把在线权重更新用在生产模型上。
```

> **★ 怎么判断它有进展**：★★★ **这是十条里唯一的二元判据**——有没有**任何一家**把在线权重更新用在**生产**模型上。现在是 **0**。⟹ 🔑 所以这一节不需要跟踪文献，只需要跟踪这个计数器；它从 0 变成 1 的那天，这一节要整节重写。⚠️ 注意别把"记忆/上下文里的持续学习"算进来——那是**不改权重**的路线，它做得再好，这个计数器还是 0。

## 12.8 ⑧ SFT 还该不该是一个独立阶段

```
✅ 反方证据：
   · SFT Memorizes, RL Generalizes（2501.17161）
   · SFT 的隐式奖励偏置（DFT，2508.05629）
   · SFT 分最高的 ckpt 不是最好的 RL 起点（2510.01624）
   · CHORD：把 SFT 变成 on-policy RL 里的一个【加权辅助损失项】，
     而不是一个前置阶段
✅ 正方证据：
   · R1-Zero 证明了纯 RL 可行，但 R1 最终还是加回了 SFT 冷启动 ——
     因为纯 RL 的可读性和语言混杂问题很严重
   · SFT 是把"新格式 / 新工具协议"注入模型最便宜的方式

⚠️ 我的判断：SFT 不会消失，但会【降级】——
   从"一个大阶段"变成"RL 训练循环里的一个正则项 / 冷启动小步骤"。
```

**把正反方摆成一张表，分歧点其实很清楚**：

| | 反方：SFT 该降级 | 正方：SFT 还得留着 |
|---|---|---|
| **核心论点** | SFT 是**记忆**，RL 才**泛化** | 纯 RL 的**可读性 / 语言混杂**问题很严重 |
| **证据** | ✅ SFT Memorizes, RL Generalizes（arXiv:2501.17161）<br>✅ SFT 的隐式奖励偏置（DFT，arXiv:2508.05629）<br>✅ SFT 分最高的 ckpt 不是最好的 RL 起点（arXiv:2510.01624） | ✅ R1-Zero 证明纯 RL 可行，**但 R1 最终还是加回了 SFT 冷启动**（arXiv:2501.12948） |
| **它的替代方案** | CHORD：把 SFT 变成 on-policy RL 里的一个**加权辅助损失项**<br>（⚠️ 本教程未核对该工作的 arXiv 编号，见速查表 §G 的清单说明） | — |
| **不可替代的地方** | — | ★ SFT 是把**新格式 / 新工具协议**注入模型**最便宜**的方式；也是给 RL 提供"能采出正确答案的起点"的唯一实用办法 |
| **所以** | SFT 降级为**损失项** | SFT 保留为**冷启动** |

```
★★ 两边其实不冲突：反方攻击的是"SFT 作为一个【大阶段】"，
   正方守的是"SFT 作为一个【小步骤】"。
   ⟹ 🔑 分歧在【规模】，不在【存废】。
```

> **★ 怎么判断它有进展**：看未来的技术报告里 **SFT 用了多少 token、占多少算力**。这个数字**持续下降** = 上面的判断在被验证；SFT 从"一个独立章节"变成"RL 章节里的一个损失项" = 彻底验证。⚠️ 反过来，如果新一代报告里 SFT 的 token 数**回升**，说明纯 RL 的可读性问题比现在以为的更难，这一节要改写。

## 12.9 ⑨ On-Policy 蒸馏会不会统一一切

```
✅ 已发生：2026 年多家都在用 OPD 做收口（见 08 章），
   而且用的是同一个式子 Â = sg[log(π_teacher / π_student)]。
   ⚠️ 口径更正：是 DeepSeek-V4 / Kimi-K3 / GLM-5 / openPangu-2.0 四家
      （外加 NVIDIA Nemotron 这个独立样本），
      ★ 【不是"五家全部"】—— MiniMax-M3 没有技术报告，这一项未披露。
      出处见 ../业界模型技术报告/模型技术对比.md §3.6 的开头说明。
✅ 已发生：OPD 被用来做两件不同的事 ——
   合并多个专家（DeepSeek / K3 / Pangu / Nemotron）
   和 找回被遗忘的能力（GLM-5）。

⚠️ 我的判断：OPD 之所以强，是因为它把【SFT】【蒸馏】【RL】
   统一进了同一个 2×2 框架（见下表）：
   ★★ 它落在【on-policy × 稠密】这个格子里，而这个格子信息量最大。

🔮 开放：
   · 老师从哪来？—— 学生超过老师之后（✅ ExOPD 已观察到），
     谁来当下一轮的老师？【自举的边界在哪】没人知道
   · 闭源 API 老师给不了 logits ⟹ 真正的 OPD 只有能拿到权重的人能做
     ⚠️ 这会加剧开源与闭源之间的差距，方向和大家期待的相反
```

**那个 2×2 框架**（★ 这张表是本节的全部论点）：

| | **信号稀疏**（一条轨迹一个标量） | **信号稠密**（逐 token 都有信号） |
|---|---|---|
| **off-policy**<br>（数据不是当前模型生成的） | 离线偏好学习 / DPO<br>⚠️ 数据会过期 | ★ **SFT**<br>（逐 token 交叉熵，**是稠密的**）<br>⚠️ 但学的是别人的轨迹 |
| **on-policy**<br>（学生自己生成） | **RL / RLVR**<br>⚠️ 一条几千 token 的轨迹只回来一个 0/1 | ★★★ **OPD**<br>信息量最大的那一格 |

```
⚠️ 一处口径更正：SFT 的监督是【稠密】的 —— 它对每一个目标 token 都算交叉熵。
   ★ SFT 的问题从来不是"信号稀疏"，而是【off-policy】：
     学的是老师写的轨迹，不是自己走出来的轨迹。
   ⟹ 🔑 所以 OPD 的真正增量是【把 SFT 的稠密信号搬到了 on-policy 轨迹上】，
      而不是"把稀疏变稠密"。这一句写反过，现已更正。
```

## 12.10 ⑩ 多模态与具身：同一条路要不要再走一遍

```
⚠️ 现状：文本后训练的那一整套（SFT → RLVR → Agentic RL → OPD）
   正在被【原样搬到】多模态和具身智能上。

✅ 已观察到的困难：
   · 多模态的"可验证奖励"更难定义
     （一张图描述得对不对，没有 unit test）
   · 有工作报告了多模态"先 SFT 再 RL"会留下负债
     （SFT 阶段固化的错误模式，RL 阶段要花额外代价去改）
   · 具身场景 rollout 极慢（真机交互 / 仿真都比文本慢几个数量级）
     ⟹ 长尾问题（07.3）被放大

🔮 开放：Agentic RL 在物理世界里的对应物是什么？
   → 见本仓库 [../具身智能与世界模型/](../具身智能与世界模型/)
```

> **★ 怎么判断它有进展**：看有没有出现一个**被广泛接受的多模态可验证奖励**——像单元测试对代码那样确定、零成本、可无限次调用的东西。⚠️ 这是整条路线的闸门：**没有它，多模态后训练就只能停在偏好对齐（第一代）**，走不到 RLVR（第二代）。★ 候选方向可以盯：渲染回环（生成图 → 用程序量它是否满足约束）、几何/物理一致性检查、可执行的图表到代码。
