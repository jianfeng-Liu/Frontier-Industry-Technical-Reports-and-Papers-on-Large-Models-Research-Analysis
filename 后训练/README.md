## 🧭 这个领域的一句话地图

**先建立方位感。后训练（post-training）要解决的，其实是三个完全不同的问题**，初学时最容易搅在一起：

```
问题一：格式问题  ——  「怎么说话」
        预训练模型不知道"对话"是什么，你问它它会接着往下编题目
        → 教它 system/user/assistant 的轮次结构、什么时候停下来
        → 手段：SFT（监督微调）        → 02 章

问题二：偏好问题  ——  「怎么说得好」
        两个回答都对，但一个啰嗦一个清晰，模型怎么知道该学哪个
        → 手段：RLHF / DPO（偏好对齐） → 04 章

问题三：能力问题  ——  「怎么做对」
        这道数学题它就是算错，多好的格式和语气都救不了
        → 手段：RLVR / Agentic RL（强化学习） → 05、07 章
```

> ★★★ **这三个问题的重要性排序，在过去四年里被彻底颠倒过一次。**
> **2022 年大家 90% 的精力在问题一和二上；2026 年 90% 的精力在问题三上。**
> [11 章](11-演进主线-三代范式.md)专门讲这个颠倒是怎么发生的——**它是整份教程的脊柱，看不懂别的章节时可以先去看它。**

## 📐 全教程通用的记号约定

```
base / 基座      预训练跑完存下的权重，只会"续写"，不会对话
ckpt             checkpoint，存到磁盘上的一份模型权重
策略 policy      在 RL 里，"模型"就叫策略。π_θ 表示参数为 θ 的模型
                 ★ 看到 π 就读成"模型"，不会有任何理解损失
rollout          让模型真的跑一遍任务，产出一条完整轨迹（一段回答、
                 或一串"调工具→看结果→再调"的过程）
                 ★ RL 里最贵的一步，2026 年占 RL 总开销的大头
轨迹 trajectory  一次 rollout 的产物
奖励 reward      给一条轨迹打的分。这个分从哪来，是 06 章的全部内容
on-policy        用【当前这一版模型自己生成的】数据来训它自己
off-policy       用【别人/旧版模型生成的】数据来训。SFT 是极端的 off-policy
                 ★★ 这一组词是理解 2026 年后训练的钥匙，01.5 会细讲

数量级速记：
   预训练         10~40 T token，几万卡·月
   SFT            10 万 ~ 700 万条样本，几十~几百卡·天
   RL             几千 ~ 几十万条 prompt，⚠️ 但算力可以逼近预训练
```
