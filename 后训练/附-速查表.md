### A.4 RL 机制类

| 词 | 中文 | 一句话 | 章 |
|---|---|---|---|
| **rollout** | 采样 / 展开 | 让模型针对一个 prompt 自己生成一整条输出（agentic 场景下是一整条多步轨迹） | [01](01-鸟瞰全景.md) |
| **trajectory** | 轨迹 | 一次完整交互：提问→思考→调工具→看结果→…→给答案 | [07](07-AgenticRL-环境成为瓶颈.md) |
| **on-policy** | 同策略 | 训练用的数据是**当前这版**模型刚生成的 | [01](01-鸟瞰全景.md) |
| **off-policy** | 异策略 | 训练用的数据是**别人/旧版模型**生成的（会过期） | [01](01-鸟瞰全景.md) |
| **policy π** | 策略 | 就是模型本身；π(y\|x) = 给定输入 x 输出 y 的概率 | [01](01-鸟瞰全景.md) |
| **advantage Â** | 优势 | "这条输出比平均水平好多少"；正的就加强，负的就削弱 | [05](05-RLVR-可验证奖励.md) |
| **entropy collapse** | 熵坍缩 | 模型输出越来越单一，失去探索能力 | [05](05-RLVR-可验证奖励.md) |
| **partial rollout** | 部分展开 | 长轨迹先跑一半、存下来、下一轮接着跑，避免拖慢整批 | [07](07-AgenticRL-环境成为瓶颈.md) |
| **train-inference consistency** | 训推一致性 | rollout 用推理引擎、训练用训练引擎，两边概率必须对得上，否则 RL 崩 | [07](07-AgenticRL-环境成为瓶颈.md) |
| **QAT** | Quantization-Aware Training（量化感知训练） | 训练时就带上量化，使训练和推理的数值行为一致 | [07](07-AgenticRL-环境成为瓶颈.md) |
| **pass@1 / pass@k** | — | 答一次的正确率 / 答 k 次至少对一次的比例 | [10](10-评测与回归.md) |
| **SE** | standard error（标准误） | 同一套评测重跑一遍，分数典型的抖动幅度。★ **比 SE 小的差异不能叫"提升"** | [10](10-评测与回归.md)、§C |
| **pp** | percentage point（百分点） | 两个百分数相减的单位。⚠️ 40% → 44% 是涨 **4 个百分点**，不是"涨 4%" | §C |
| **McNemar 检验** | McNemar's test | 两个模型跑**同一批题**时的配对显著性检验，只看**分歧的题**。⚠️ **不要把两个 SE 相加** | [10](10-评测与回归.md)、§C |
| **alignment tax** | 对齐税 | 为了安全和风格，牺牲掉的一部分硬能力 | [04](04-偏好对齐-RLHF与DPO.md) |
| **catastrophic forgetting** | 灾难性遗忘 | 学新的把旧的挤掉了 | [03](03-分训与合训.md) |
| **seesaw effect** | 跷跷板效应 | 一个域涨、另一个域就掉 | [03](03-分训与合训.md) |
| **logits** | — | 模型在词表上每个 token 的原始打分（过 softmax 前）；OPD 的硬门槛是老师得给得出它 | [08](08-蒸馏与合并-OPD.md) |

**分训与合训**（★ 和上面那条主线是正交的一维）：

```
  分训（并行分支，各练各的）
     base ──┬── 数学专家
            ├── 代码专家
            ├── Agent 专家
            └── 通用专家

  合训（把它们变回一个模型）
     四个专家  ──>  OPD 收口  ──>  统一模型

  ★★ 关键纪律：合训必须【回到原始 base】重训，
```

### ★★★ RLHF 四个模型的显存账（7B 为例，逐项能验算）

**先把"每个参数要多少字节"拆开**——这是整笔账的地基，也是最常被算错的地方：

| 这一份是什么 | 精度 | 字节/参数 | 只有"要训练的模型"才有吗 |
|---|---|---|---|
| ① 模型权重 | BF16 | **2** | 所有模型都要 |
| ② 梯度 | BF16 | **2** | ★ 只有要训练的才有 |
| ③ FP32 主副本（master weights） | FP32 | **4** | ★ 只有要训练的才有 |
| ④ Adam 一阶动量 `m` | FP32 | **4** | ★ 只有要训练的才有 |
| ⑤ Adam 二阶动量 `v` | FP32 | **4** | ★ 只有要训练的才有 |
| **合计（要训练的模型）** | — | ★★★ **16** | — |
| **合计（只前向的模型）** | — | **2** | 只要 ① |

```
⚠️⚠️ 两个最常见的算错：
  ① 把 Adam 的 m 和 v 当成"一共 4 字节"。
     ★ 不对：m 和 v 【各】占 4 字节（FP32），合起来 8 字节。
  ② 忘记 FP32 主副本。
     ★ 混合精度训练里，优化器更新作用在 FP32 副本上，
       BF16 权重只是它的一份舍入拷贝 —— 这 4 字节是真实存在的。

  ★ 16 = 2（BF16 权重）+ 2（BF16 梯度）+ 4（FP32 主副本）
            + 4（Adam m）+ 4（Adam v）
```

**代进 7B（按 7 × 10⁹ 个参数算）**：

| # | 模型 | 在 PPO/RLHF 里干什么 | 要不要训练 | 字节/参数 | **显存** |
|---|---|---|---|---|---|
| ① | **策略**（Actor） | 就是你要训出来的模型 | ★ **要** | 16 | `7e9 × 16 =` **112 GB** |
| ② | **参考模型**（Reference） | 算 KL 惩罚的锚点，权重冻结 | ❌ 只前向 | 2 | `7e9 × 2 =` **14 GB** |
| ③ | **奖励模型**（Reward Model） | 给回答打分，权重冻结 | ❌ 只前向 | 2 | **14 GB** |
| ④ | **价值网络**（Critic） | 估计状态价值，和策略同尺寸 | ★ **要** | 16 | **112 GB** |
| | **合计** | | | | ★★★ **252 GB** |

```
★ 验算：112 + 14 + 14 + 112 = 252 GB
   （= 252 × 10⁹ 字节 ÷ 2³⁰ ≈ 234.7 GiB，⚠️ 口径差约 7%，写方案时说清 GB 还是 GiB）

⟹ 🔑 一台 8×H100（8 × 80 GB = 640 GB）装得下这 252 GB 的权重与优化器状态，
   ⚠️ 但【激活值、rollout 的 KV cache、以及推理引擎自己那一份权重】全都还没算进去。
   ★★ 这就是"PPO 只有大厂能跑"这句话的具体含义 —— 不是算力不够，是显存先爆。
```

### ★★★ SFT / DPO / PPO / GRPO 要素对照（要几个模型、要不要采样、要不要奖励模型）

| | **SFT** | **DPO** | **PPO**（RLHF） | **GRPO**（RLVR） |
|---|---|---|---|---|
| **训练中要几个模型** | **1** | **2** | ⚠️ **4** | **2** |
| 哪几个 | 策略 | 策略 + 参考 | 策略 + 参考 + 奖励模型 + 价值网络 | 策略 + 参考 |
| **要价值网络(Critic)吗** | ❌ | ❌ | ✅ 要，**和策略同尺寸** | ★★ ❌ **扔掉**，改用组内相对 |
| **要奖励模型吗** | ❌ | ❌（偏好对里隐含） | ✅ 要，**得先单独训一个** | ❌ 用**判分程序** |
| **要在线采样(rollout)吗** | ❌ | ❌ | ✅ 要 | ✅ 要，**同题采 G 次** |
| on-policy / off-policy | 极端 off-policy | off-policy | **on-policy** | **on-policy** |
| 一条数据长什么样 | 问题 + 答案 | `chosen` / `rejected` 偏好对 | prompt（答案自己采） | prompt + 验证器 |
| **数据会过期吗** | — | ⚠️ **会**（模型一变，偏好对就不对口了） | 不会 | 不会 |
| **7B 显存**（权重+优化器状态） | **112 GB** | **126 GB** | ⚠️ **252 GB** | **126 GB** |
| 主要成本在哪 | 标注答案 | 标注偏好对 | ★ **显存** + rollout | ★ **rollout** |

```
★ 验算显存那一行：
   SFT  = 112                      （只有策略，要训）
   DPO  = 112 + 14 = 126            （策略要训 + 参考只前向）
   GRPO = 112 + 14 = 126            （同上；奖励是程序，不占显存）
   PPO  = 112 + 14 + 14 + 112 = 252 （多一个奖励模型 + 一个价值网络）

⟹ 🔑🔑 GRPO ÷ PPO = 126 ÷ 252 = 【正好一半】。
   ★★ 这就是"GRPO 把 RL 从只有大厂能跑变成学术组也能跑"的量化版本：
      省掉的不是算力，是【价值网络那 112 GB + 奖励模型那 14 GB】。
```

### ★★★ 噪声门槛：差多少才算真的变好

```
   ★★★ 一个分数自己的抖动（标准误）：

        SE ≈ sqrt( p × (1 − p) ÷ n )

      n = 题数，p = 准确率。★ 拿不准 p 时取 0.5 —— 这是最保守（SE 最大）的取法。
```

| 题量 n | 典型例子 | **SE**（p=0.5） | 95% 区间 ≈ ±1.96·SE | ⟹ 差多少才值得当真 |
|---|---|---|---|---|
| 30 | AIME 一年的题 | ⚠️ **9.1 pp** | ±17.9 pp | ★ 单跑一遍几乎没有可比性 |
| 100 | 自建的小评测集 | 5.0 pp | ±9.8 pp | 差 10 个点以下别下结论 |
| 164 | HumanEval | 3.9 pp | ±7.7 pp | 差 8 个点以下要慎重 |
| 300 | SWE-bench Lite | 2.9 pp | ±5.7 pp | 差 5 个点约等于噪声 |
| **500** | SWE-bench Verified / MATH-500 | ★★★ **2.2 pp** | ±4.4 pp | 差 4 个点以下要慎重 |
| 1,000 | 中等规模基准 | 1.6 pp | ±3.1 pp | 差 3 个点以下要慎重 |

```
★ 验算最关键那一行：n=500、p=0.5
     SE = sqrt( 0.25 ÷ 500 ) = sqrt( 0.0005 ) = 0.0224  =>  约 2.2 个百分点

⚠️⚠️ 比较【两个模型】时的一句话规矩：

   ❌ 不要把两个 SE 相加（2.2 + 2.2 = 4.4 pp）—— 那个门槛过于保守，
      会让你【系统性漏掉真实的能力回退】。

   ✅ 两个模型跑的是【同一批题】时，用 McNemar 配对检验，
      它只看【双方判断不同】的那些题：

           SE(差) = sqrt( n01 + n10 ) ÷ n

        n01 = 旧版对、新版错 的题数
        n10 = 旧版错、新版对 的题数
        ★ 双方都对、都错的题【完全不进这个公式】—— 它们不含信息。
      ⟹ |差| > 1.96 × SE(差) 才叫"真的变了"。

   ★ 例：n=500，分数差 3 pp（= 15 道题），分歧 45 道（30 : 15）
        SE = sqrt(45) ÷ 500 = 6.708 ÷ 500 = 1.34 pp
        z  = 3.0 ÷ 1.34 = 2.24  >  1.96   =>  ✅ 这个回退是真的
      ⚠️ 而用"两个 SE 相加"的门槛 3.71 pp 判，会判成"噪声" —— 漏报。
```

> 📖 完整的标准误表、各基准题量、以及"采样 k 次取平均消掉哪种噪声"的推导，见 [../harness评测框架/评测入门/11-怎么读懂一张榜单.md](../harness评测框架/评测入门/11-怎么读懂一张榜单.md)。**本页和那边是同一个口径。** 后训练侧怎么用，见 [10 章](10-评测与回归.md)。

### ⚠️⚠️ 两个几乎每份报告都会被读错的换算

**换算一：「时间减少 X%」≠「加速 X%」**

```
   ★★★ 加速倍数 = 1 ÷ (1 − 时间减少比例)
```

| 报告说"耗时减少" | **加速倍数** | 等价于"加速了" | ⚠️ 容易被误读成 |
|---|---|---|---|
| 20% | `1 ÷ 0.8 =` **1.25×** | 25% | "加速 20%" ❌ |
| 33% | `1 ÷ 0.67 =` **1.5×** | 50% | "加速 33%" ❌ |
| **50%** | `1 ÷ 0.5 =` **2.0×** | **100%** | "加速 50%" ❌（差一倍！） |
| 80% | `1 ÷ 0.2 =` **5.0×** | 400% | "加速 80%" ❌（差 5 倍） |
| 90% | `1 ÷ 0.1 =` **10×** | 900% | "加速 90%" ❌ |

```
★ 反方向也要会：报告说"加速 2 倍" => 时间减少 1 − 1/2 = 50%
                报告说"加速 1.5 倍" => 时间减少 1 − 1/1.5 = 33.3%
⟹ 🔑 两个方向混用是技术报告里最高频的数字事故之一。
```

**换算二：百分比（%）vs 百分点（pp）**

```
   ★ 两个百分数【相减】，单位是【百分点 pp】。
   ★ 一个数【相对于另一个数涨了多少】，单位才是【百分比 %】。
```

| 场景 | 绝对变化 | 相对变化 | ⚠️ 说"涨了 4%"指哪个 |
|---|---|---|---|
| 准确率 40% → 44% | **+4 个百分点** | `4 ÷ 40 =` **+10%** | 歧义！两个都能叫"4" |
| 准确率 80% → 84% | **+4 个百分点** | `4 ÷ 80 =` **+5%** | ★ 同样 4 pp，相对提升只有一半 |
| 错误率 20% → 10% | **−10 个百分点** | `10 ÷ 20 =` **−50%** | ★ "错误率降低一半"说的是后者 |
| 错误率 2% → 1% | **−1 个百分点** | **−50%** | ⚠️ 相对降 50%，但绝对只省 1 pp |

```
⟹ 🔑 一条纪律：★★ 写"涨了 N 个百分点"，不写"涨了 N%"。
   ⚠️ 读别人的报告时，看到"提升 50%"先问一句：50 个百分点，还是相对 50%？
      在 80 分的基准上，这两句话差了【40 分】和【不可能】。
```

## §F 常见误解速查

| 你可能以为 | 实际上 | 在哪讲 |
|---|---|---|
| 有了 RLVR 就不用 SFT 了 | 七个阶段全都还在，是叠起来的层 | [11.7](11-演进主线-三代范式.md) |
| 分训完把专家串起来接着训就行 | ❌ 会灾难性遗忘，必须回到原始 base | [3.4 节](03-分训与合训.md) |
| 两阶段联合训练不是也串行吗 | 那是按**质量档位**串行，不是按**域**串行，且第二阶段仍是全域低学习率 | [3.4 节](03-分训与合训.md) |
| SFT 分数越高，RL 起点越好 | ❌ 反了，太尖的分布让 GRPO 优势≈0 | [10.3](10-评测与回归.md) |
| 给 RL 挑最难的题最有价值 | ❌ 太难和太简单都让优势=0，要**难度匹配** | [09.4](09-后训练的数据学.md) |
| DPO 更简单所以应该更流行 | 它的数据会过期（off-policy），2026 年报告里基本消失 | [04.5](04-偏好对齐-RLHF与DPO.md) |
| 过程奖励（PRM）比结果奖励好 | 它会惩罚探索和自我纠错，工业界反而选"笨但难作弊"的结果奖励 | [6.2 节](06-奖励从哪来.md) |
| 参数平均（模型融合）能合并专家 | 只适合**同阶段** ckpt 平均；跨领域专家要在**函数空间**合（OPD） | [08.4](08-蒸馏与合并-OPD.md) |
| 训练奖励涨了就是变好了 | 可能是奖励作弊。要和留出集曲线画在同一张图上 | [10.5](10-评测与回归.md) |
| 某一格掉了 2 分就是能力回退了 | ❌ n=500 时 SE ≈ **2.2 个百分点**，2 分在噪声里。先过噪声门槛再说 | [10.1](10-评测与回归.md)、§C |
| 比两个模型要把两个 SE 相加 | ❌ 过于保守，会**漏掉真实回退**。跑同一批题就用 **McNemar 配对检验** | [10.1](10-评测与回归.md)、§C |
| `1 − (1−c/n)^k` 是 pass@k 的无偏估计 | ❌ 反了，它**系统性偏低**。无偏的是 `1 − C(n−c,k)/C(n,k)`；"直接采 k 次"也无偏，只是方差极大 | [10.2](10-评测与回归.md) |
| "耗时减少 50%" = "加速 50%" | ❌ 是**加速 2 倍（100%）**。`加速倍数 = 1/(1−减少比例)` | §C |
| 准确率从 40% 到 44% 是"涨了 4%" | ⚠️ 是涨了 **4 个百分点**；相对涨幅才是 `4/40 = 10%` | §C |
| 后训练的配比和预训练的配比是一回事 | ❌ 预训练按**语料域**配 token，后训练按**任务类型 × 难度**配题目 | [9.3](09-后训练的数据学.md) |
