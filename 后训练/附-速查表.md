## §A ★ 缩写总表

### A.1 训练阶段类

| 缩写 | 英文全称 | 中文 | 一句话 | 章 |
|---|---|---|---|---|
| **base** | base model / pretrained checkpoint | 底座模型 | 只会续写、不会对话的原始预训练产物 | [01](01-鸟瞰全景.md) |
| **ckpt** | checkpoint | 检查点 | 一份保存下来的模型权重快照 | [01](01-鸟瞰全景.md) |
| **mid-training** | mid-training | 中期训练 | 预训练和后训练之间新长出来的一段，用高质量/长上下文/推理数据继续训 | [01](01-鸟瞰全景.md) |
| **SFT** | Supervised Fine-Tuning | 监督微调 | 给"问题+标准答案"，只在答案上算 loss | [02](02-SFT-监督微调.md) |
| **RFT** | Rejection sampling Fine-Tuning | 拒绝采样微调 | 采 N 次→验证器筛对的→拿对的去做 SFT | [03](03-分训与合训.md) |
| **RLHF** | Reinforcement Learning from **Human** Feedback | 基于人类反馈的强化学习 | 用人的偏好训一个奖励模型，再用它做 RL | [04](04-偏好对齐-RLHF与DPO.md) |
| **RLAIF** | Reinforcement Learning from **AI** Feedback | 基于 AI 反馈的强化学习 | 把 RLHF 里打分的人换成模型 | [04](04-偏好对齐-RLHF与DPO.md) |
| **CAI** | Constitutional AI | 宪法式 AI | 人只写原则，模型照原则自己给自己打分 | [04](04-偏好对齐-RLHF与DPO.md) |
| **RLVR** | Reinforcement Learning with **Verifiable** Rewards | 可验证奖励的强化学习 | 奖励来自判分**程序**而不是奖励模型 | [05](05-RLVR-可验证奖励.md) |
| **Agentic RL** | Agentic Reinforcement Learning | 智能体强化学习 | 一条样本是一次多步工具交互轨迹，奖励来自环境 | [07](07-AgenticRL-环境成为瓶颈.md) |
| **OPD** | **On-Policy** Distillation | 同策略蒸馏 | 学生自己生成，老师逐 token 打分 | [08](08-蒸馏与合并-OPD.md) |
| **MOPD** | **Multi-domain** On-Policy Distillation | 多领域同策略蒸馏 | 用 OPD 把多个领域专家合成一个模型 | [08](08-蒸馏与合并-OPD.md) |

### A.2 算法类

| 缩写 | 英文全称 | 中文 | 一句话 | 章 |
|---|---|---|---|---|
| **PPO** | Proximal Policy Optimization | 近端策略优化 | 经典 RL 算法，要 4 个模型（含 Critic） | [04](04-偏好对齐-RLHF与DPO.md) |
| **DPO** | Direct Preference Optimization | 直接偏好优化 | 把 RLHF 化简成一个分类损失，不用 RL | [04](04-偏好对齐-RLHF与DPO.md) |
| **GRPO** | **Group** Relative Policy Optimization | 组相对策略优化 | 扔掉 Critic，同题采 G 次，用组内相对好坏当优势 | [05](05-RLVR-可验证奖励.md) |
| **DAPO** | Decoupled clip & Dynamic sAmpling Policy Optimization | — | GRPO 的四个补丁：clip-higher / 动态采样 / token 级 loss / 超长惩罚整形 | [05](05-RLVR-可验证奖励.md) |
| **GSPO** | **Sequence**-level Policy Optimization | 序列级策略优化 | 重要性比率算在整条序列上而不是逐 token | [05](05-RLVR-可验证奖励.md) |
| **CISPO** | Clipped IS-weight Policy Optimization | — | 被裁剪掉的 token 也保留梯度 | [05](05-RLVR-可验证奖励.md) |
| **DFT** | Dynamic Fine-Tuning | 动态微调 | 一行改动，修正 SFT 梯度里的隐式奖励偏置 | [02](02-SFT-监督微调.md) |
| **CHORD** | — | — | 把 SFT 变成 on-policy RL 里的一个加权辅助损失 | [02](02-SFT-监督微调.md) |
| **BT** | Bradley-Terry model | 布莱德利-特里模型 | 由"A 比 B 好"这类比较，反推出每个选项的分数 | [04](04-偏好对齐-RLHF与DPO.md) |
| **KL** | Kullback-Leibler divergence | KL 散度 | 衡量两个概率分布差多远；RL 里当"狗绳"防止模型跑飞 | [04](04-偏好对齐-RLHF与DPO.md) |

| **verifier** | — | 验证器 / 判分器 | 一段确定性程序：跑单测、对答案、匹配正则 | [05](05-RLVR-可验证奖励.md) |

### A.4 RL 机制类

| 词 | 中文 | 一句话 | 章 |
|---|---|---|---|
| **rollout** | 采样 / 展开 | 让模型针对一个 prompt 自己生成一整条输出（agentic 场景下是一整条多步轨迹） | [01](01-鸟瞰全景.md) |
| **trajectory** | 轨迹 | 一次完整交互：提问→思考→调工具→看结果→…→给答案 | [07](07-AgenticRL-环境成为瓶颈.md) |
| **on-policy** | 同策略 | 训练用的数据是**当前这版**模型刚生成的 | [01](01-鸟瞰全景.md) |
| **off-policy** | 异策略 | 训练用的数据是**别人/旧版模型**生成的（会过期） | [01](01-鸟瞰全景.md) |
| **policy π** | 策略 | 就是模型本身；π(y\|x) = 给定输入 x 输出 y 的概率 | [01](01-鸟瞰全景.md) |
| **advantage Â** | 优势 | "这条输出比平均水平好多少"；正的就加强，负的就削弱 | [05](05-RLVR-可验证奖励.md) |
| **entropy collapse** | 熵坍缩 | 模型输出越来越单一，失去探索能力 | [05](05-RLVR-可验证奖励.md) |
| **partial rollout** | 部分展开 | 长轨迹先跑一半、存下来、下一轮接着跑，避免拖慢整批 | [07](07-AgenticRL-环境成为瓶颈.md) |
| **train-inference consistency** | 训推一致性 | rollout 用推理引擎、训练用训练引擎，两边概率必须对得上，否则 RL 崩 | [07](07-AgenticRL-环境成为瓶颈.md) |
| **QAT** | Quantization-Aware Training（量化感知训练） | 训练时就带上量化，使训练和推理的数值行为一致 | [07](07-AgenticRL-环境成为瓶颈.md) |
| **pass@1 / pass@k** | — | 答一次的正确率 / 答 k 次至少对一次的比例 | [10](10-评测与回归.md) |
| **alignment tax** | 对齐税 | 为了安全和风格，牺牲掉的一部分硬能力 | [04](04-偏好对齐-RLHF与DPO.md) |
| **catastrophic forgetting** | 灾难性遗忘 | 学新的把旧的挤掉了 | [03](03-分训与合训.md) |
| **seesaw effect** | 跷跷板效应 | 一个域涨、另一个域就掉 | [03](03-分训与合训.md) |
| **logits** | — | 模型在词表上每个 token 的原始打分（过 softmax 前）；OPD 的硬门槛是老师得给得出它 | [08](08-蒸馏与合并-OPD.md) |

## §F 常见误解速查

| 你可能以为 | 实际上 | 在哪讲 |
|---|---|---|
| 有了 RLVR 就不用 SFT 了 | 七个阶段全都还在，是叠起来的层 | [11.7](11-演进主线-三代范式.md) |
| 分训完把专家串起来接着训就行 | ❌ 会灾难性遗忘，必须回到原始 base | [03.3](03-分训与合训.md) |
| 两阶段联合训练不是也串行吗 | 那是按**质量档位**串行，不是按**域**串行，且第二阶段仍是全域低学习率 | [03.5](03-分训与合训.md) |
| SFT 分数越高，RL 起点越好 | ❌ 反了，太尖的分布让 GRPO 优势≈0 | [10.3](10-评测与回归.md) |
| 给 RL 挑最难的题最有价值 | ❌ 太难和太简单都让优势=0，要**难度匹配** | [09.4](09-后训练的数据学.md) |
| DPO 更简单所以应该更流行 | 它的数据会过期（off-policy），2026 年报告里基本消失 | [04.5](04-偏好对齐-RLHF与DPO.md) |
| 过程奖励（PRM）比结果奖励好 | 它会惩罚探索和自我纠错，工业界反而选"笨但难作弊"的结果奖励 | [06.3](06-奖励从哪来.md) |
| 参数平均（模型融合）能合并专家 | 只适合**同阶段** ckpt 平均；跨领域专家要在**函数空间**合（OPD） | [08.4](08-蒸馏与合并-OPD.md) |
| 训练奖励涨了就是变好了 | 可能是奖励作弊。要和留出集曲线画在同一张图上 | [10.5](10-评测与回归.md) |
