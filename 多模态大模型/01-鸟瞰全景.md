## 1.1 先把名词的混乱解决掉

这是本领域对初学者最不友好的地方：**同一个东西有五个名字，五个名字又指着不完全相同的东西。**

| 缩写 | 全称 | 通常指 | ⚠️ 坑 |
|---|---|---|---|
| **VLM** | Vision-Language Model | 能看图 + 说话的模型 | 最常用，但严格说 CLIP 也是 VLM，而 CLIP 不会说话 |
| **MLLM** | Multimodal Large Language Model | "以 LLM 为主干、外接感官"的模型 | 学术论文最爱用 |
| **LMM** | Large Multimodal Model | 同上 | OpenAI 系文档偏爱 |
| **omni / 全模态** | — | 文/图/音/视频**都能进、也都能出** | 各家定义都不一样，见 [10 章](10-语音与实时全双工.md) |
| **原生多模态** | natively multimodal | **从预训练第一步就混着多模态数据训** | ★ 这是一个**训练流程**的说法，不是架构说法。见 1.4 |
| **VLA** | Vision-Language-**Action** | VLM 后面接电机输出，给机器人用 | 在隔壁目录 [具身智能与世界模型](../具身智能与世界模型/01-具身智能与VLA.md) |

> 🔑 **本教程的用法**：统一说 **"多模态大模型"**，需要区分时才用具体缩写。
> 全部缩写在 [附-速查表](附-速查表.md) 里有一张总表。

## 1.2 三大件与它们的重量

```
    ┌──────────────┐   ┌──────────┐   ┌────────────────────────┐
    │  视觉塔       │──→│  连接器   │──→│      语言模型主干        │
    │ vision tower │   │connector │   │        LLM             │
    └──────────────┘   └──────────┘   └────────────────────────┘
       0.3 ~ 6 B          0.02 ~ 1 B         7 B ~ 2000 B
       ↑ 02 章             ↑ 03 章            ↑ 隔壁目录讲
```

**★ 注意这个参数量比例**，它解释了很多事：

```
    Kimi K3：  MoonViT-V2 约 0.4B   vs   主干 2.78T 总参
               ⟹ 视觉塔占整个模型的 0.015%
               ✅ 出处：../业界模型技术报告/Kimi-K3.md §六
```

> ⟹ ⚠️ **推论一**：视觉塔便宜。所以"换个更好的视觉塔"是一个诱人但收益有限的动作——
> 真正决定模型聪不聪明的还是那个巨大的语言主干。
>
> ⟹ ⚠️ **推论二**：但视觉塔是**信息瓶颈**。视觉塔没编码进去的信息（比如糊掉的小字），
> 后面 2.78T 参数再多也变不出来。**便宜 ≠ 不重要。**

## 1.3 ★★ 两条路线：拼接式 vs 原生多模态

这是本领域最重要的一条分界线，也是 2025~2026 年各家技术报告的主要卖点差异。

### 路线 A：拼接式（也叫"外挂式"、后融合）

```
    第 1 步：拿一个【已经训好的】纯文本 LLM      （比如 Qwen3-32B）
    第 2 步：拿一个【已经训好的】视觉塔          （比如 SigLIP）
    第 3 步：中间塞一个连接器，只训连接器        ← 便宜！几十张卡几天
    第 4 步：再拿多模态指令数据微调一下

    ✅ 优点：便宜、快、可以蹭现成的强 LLM，学术界和中小团队几乎只能走这条
    ⚠️ 缺点：LLM 在预训练时【从没见过视觉 token】，是被"硬塞"的
             ⟹ 视觉能力像是贴上去的，深度推理时容易退化回纯文本习惯
```

**LLaVA（2023）是这条路的经典代表**，一个 MLP 连接器 + 60 万条指令数据就能做出可用的模型，
**它几乎以一己之力启动了开源多模态生态**。

### 路线 B：原生多模态（也叫早融合）

```
    从预训练的【第 0 步】开始，语料里就混着图文
    视觉塔和 LLM 一起训（或分阶段但很早就联合）

    ✅ 优点：视觉不是外挂，是模型世界观的一部分
    ⚠️ 缺点：贵得离谱。得在预训练那个量级（几十 T token）上重来一遍
             ⟹ ⟹ 只有几家大厂玩得起
```

**2026 年前沿模型的态度**（✅ 均出自本仓库已核对的一手报告）：

| 模型 | 多模态？ | 做法 |
|---|---|---|
| **Kimi K3** | ✅ 原生 | MoonViT-V2 **完全从零训练**，不用 CLIP/SigLIP 初始化 |
| **MiniMax M3** | ✅ 原生 | 32 层 ViT，3D RoPE，2×2 patch merge |
| **GLM-5.3-Flash** | ✅ 原生 | GLM-5 系列首个；**30T 多模态语料** |
| **DeepSeek-V4** | ❌ 纯文本 | — |
| **openPangu-2.0-Pro** | ❌ 纯文本 | 但 tokenizer 选型时**为多模态预留了位置** |

> ★★ **这张表本身就是一个信号**：2026 年的旗舰模型里，**"要不要原生多模态"仍然不是共识**。
> 五家里三家做了、两家没做，而没做的那两家都是以**代码/推理**为主打的模型。
> ⟹ ⚠️ 我的读法：**多模态目前还没有被证明能提升纯文本智能**，
> 它更像是一个**产品维度的扩张**，而不是一个能力维度的必需品。
> [13 章](13-业界横向对照.md)会把这五家的多模态做法逐项排开。

## 1.4 ⚠️ "原生多模态"这个词，可信度最低

**它没有公认定义。** 至少被用来指过三件不同的事：

```
    ① 预训练第一步就混多模态数据          ← 最严格、也最贵的意思
    ② 预训练中后期加入多模态数据           ← 大多数号称"原生"的其实是这个
    ③ 只是"不用外挂第三方视觉编码器"        ← 最松，几乎等于"视觉塔是我自己训的"
```

> 🔑 **看到"原生多模态"四个字，问三个问题**：
> ① 多模态数据是从**第几个 token** 开始进的？
> ② 视觉塔是**从零训**还是拿 CLIP/SigLIP 初始化的？
> ③ 视觉塔在预训练时**冻着**还是跟着一起更新？
>
> ⚠️ 三个问题都答得上来的报告很少。**K3 是少见的三个都说清楚的**
> （✅ 从零训、用 next-token prediction 训、给了梯度范数曲线作证据）。

## 1.5 四个战场

这个领域被叫做"多模态"，但里面其实是**四拨追求完全不同的人**：

```
 ┌───────────────────────────────────────────────────────────────┐
 │ 战场①  理解：看懂                                                │
 │   看图问答 → 文档/表格/OCR → GUI 截图 → 长视频                    │
 │   ★ 商业价值最确定的一块，也是本教程 02~08 章的主线                 │
 │   ⟹ 2026 年最热的落地点：让 agent 能看懂屏幕（GUI agent）          │
 ├───────────────────────────────────────────────────────────────┤
 │ 战场②  生成：画出来                                              │
 │   文生图 / 文生视频 / 图像编辑                                    │
 │   ★ 技术栈原本【和 LLM 完全无关】（扩散模型），近两年才开始合流       │
 │   ⟹ 09 章：三条统一路线，以及"统一"到底值不值                      │
 ├───────────────────────────────────────────────────────────────┤
 │ 战场③  实时交互：听和说                                          │
 │   语音输入输出、打断、全双工                                       │
 │   ★ 难点根本不在智能，在【延迟】和【打断】                          │
 │   ⟹ 10 章                                                      │
 ├───────────────────────────────────────────────────────────────┤
 │ 战场④  具身：动起来                                              │
 │   VLA、机器人、自动驾驶                                           │
 │   ⟹ 不在本目录，见 ../具身智能与世界模型/                          │
 └───────────────────────────────────────────────────────────────┘
```

> ⚠️ **初学者最容易搞混①和②。** 它们都叫"多模态"，但：
> **理解型模型的心脏是 Transformer 的自回归解码；生成型模型的心脏是扩散去噪。**
> 这是两套数学、两套训练流程、两拨人。**它们真正开始融合是 2024 年之后的事**（09 章）。

## 1.6 一条极简时间线

```
  2021  CLIP        ★ 用 4 亿图文对做对比学习，让图和文落进同一个向量空间
                       ⟹ 至今所有视觉塔的思想源头（02 章）
        ViT          把 Transformer 用在图像上：切块、当序列、硬train

  2022  Flamingo    ★ 第一次系统地把"冻住的视觉塔 + 冻住的 LLM"用
                       cross-attention 缝起来（03 章路线 B 的源头）

  2023  BLIP-2      Q-Former：用固定数量的 query 把图压成 32 个 token
        LLaVA       ★★ 一个 MLP + 60 万条数据 ⟹ 开源多模态的起点
        Qwen-VL / CogVLM / InternVL  国内开源三条线起步

  2024  高分辨率之年   AnyRes / 动态分辨率 / NaViT 式原生分辨率（04 章）
        Chameleon    ★ 早融合 + 图像也用词表：统一理解与生成的第一次严肃尝试
        GPT-4o       ★★ 端到端语音，把"延迟"变成产品卖点（10 章）
        Video-MME    长视频评测开始成为独立赛道

  2025  推理进入多模态  把 o1/R1 那套长思维链 RL 搬到图上（08 章）
        GUI agent    看屏幕、点按钮成为主要落地场景

  2026  原生多模态成为旗舰标配之一（但不是全部，见 1.3 那张表）
        ⚠️ 本行以下属于本仓库涉及的 2026 年报告，见 13 章：
        Kimi K3      ★ 视觉塔【从零训练】，实证"对比学习初始化不是必需的"
        MiniMax M3   3D RoPE、时空 patch merge
        GLM-5.3-Flash ★ 视觉进入【编程回路】：让模型看自己渲染出的界面
```

> ⚠️ **2021~2025 这几行是公开常识**；**2026 那几行来自本仓库已归档的一手报告**

## 1.7 ★★ 这个领域真正的三个难题

读完全书，你会发现所有章节都在绕这三个问题打转：

```
 难题①  token 预算     一张图上千 token、一段视频上万 token，而注意力是平方开销
                        ⟹ 04、05、12 章
 难题②  幻觉           模型会"看见"图里没有的东西，而且比纯文本幻觉更难发现
                        ⟹ 08 章。★ 这是理解型多模态最大的落地障碍
 难题③  尺子           多模态评测集互相不通用，分数几乎无法横向比较
                        ⟹ 11 章。本仓库 模型技术对比 已经实证了这一点：
                          ✅ K3 和 M3 之间【零个共享的视觉 benchmark】
```

> 🔑 **如果你只想记一句话**：
> **多模态的技术史，就是一部"想尽办法在有限 token 预算里塞进更多视觉信息、
> 同时不让模型开始编"的历史。**
