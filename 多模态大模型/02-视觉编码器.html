02 · 视觉编码器：图片怎么变成"有意义的"向量

三大件的第一件。输入像素，输出一串向量。
这一章讲：它内部怎么转（ViT）、它怎么学会"意义"（CLIP/SigLIP）、2026 年的一个反转结论，以及 2.7 节那笔最容易被低估的算力账。

2.1 ViT：把图片当句子读

📖 ViT = Vision Transformer，视觉 Transformer（2020，arXiv 2010.11929）。一句话：把图片切成小方块，每块当一个"词"，然后用和 GPT 一模一样的 Transformer 去处理。

   (1) 切块 patchify
       1092x1092 的图，每 14x14 像素切一块 -> 78x78 = 6084 块
       每块拉平成一个向量：14 x 14 x 3(RGB) = 588 个数

   (2) 线性投影
       588 维 --[一个矩阵 W: 588x1152]--> 1152 维
       ★ 就这一个矩阵，参数量 588x1152 = 677,376 ≈ 68 万
       整件事没有任何"卷积魔法"

   (3) 加位置编码
       ⚠️ 必须加！否则模型不知道哪块在左上、哪块在右下
       （Transformer 天生看不见顺序，位置怎么编是 05 章的主题）

   (4) 过 N 层 Transformer
       每层：注意力（让每块去看其它所有块）+ FFN
       ==> 一块原本只是"一小片浅蓝"，看过邻居后变成"天空的一部分"
       ==> ★ 这一步就是"理解"发生的地方

   (5) 输出 6084 个 1152 维向量  <- 交给连接器（03 章）

2.1.2 ★ 把 MoonViT-V2 的 401 M 自己加出来

K3 报告只给了"27 层 / 约 0.4 B / patch 14"，没给宽度。但如果它真的是照着 SigLIP-SO400M 的形状选的（宽 1152、FFN 中间维 4304），参数量就该能算准：

部件 算式 参数量
每层注意力（Q/K/V/O 四个矩阵） 4 × 1152² 5.31 M
每层 FFN（1152 → 4304 → 1152） 2 × 1152 × 4304 9.92 M
一层合计 5.31 + 9.92 15.22 M
27 层 27 × 15.22 M 411 M
patch 嵌入矩阵 588 × 1152 0.68 M
推算合计 ≈412 M
✅ 报告给的实际值 401 M
差 +2.7 %

⚠️ 差 2.7% 就是 LayerNorm、位置编码这些零碎项的量级。 所以 MoonViT-V2 的形状和 SigLIP-SO400M 几乎一样。K3 报告说它是从零训的 ✅，但尺寸显然是照着这个业界标配选的 —— ⚠️ 报告没说这一点，这是我用上表反推出来的结论，不能当报告结论引用。

2.2 ★★ 关键问题：它怎么知道"这块是猫"？

上面第 (4) 步说"理解发生在这里" —— 但凭什么？ 一个随机初始化的 Transformer 什么也不懂。答案在怎么训这个视觉塔。历史上有三种训法：

训法① 分类监督（2012~2020 的老路）

拿 ImageNet 的 1000 类标签训分类。问题：模型只学会区分那 1000 类，"泰勒·斯威夫特""SQL 报错弹窗"这些它一概不知。天花板被标签集卡死。

训法② ★★ 对比学习：CLIP

📖 CLIP = Contrastive Language-Image Pre-training，对比式图文预训练（OpenAI，2021，arXiv 2103.00020）。一句话：从网上爬 4 亿组"图片 + 它的说明文字"，训练模型把配对的图和文拉近、不配对的推远。

具体怎么算？看一个 batch 为 4 的例子。表里每个格子是"这张图的向量"和"这句话的向量"的余弦相似度（取值 −1 到 1，1 = 方向完全一致）：

图片 ↓ ＼ 文本 → "一只橘猫" "日落海滩" "报错弹窗" "红色跑车"
[猫图] 0.9 0.1 0.0 0.1
[海滩照] 0.1 0.8 0.1 0.0
[报错截图] 0.0 0.1 0.9 0.0
[跑车照] 0.1 0.0 0.1 0.8 
    训练目标：让【加粗的对角线】尽量大，其它 12 个格子尽量小
    做法：每一行做一次 softmax 四选一分类（"这张图配哪句话"）
          每一列也做一次 softmax 四选一分类（"这句话配哪张图"）
          两个方向的交叉熵损失加起来

🔑 为什么这招这么强：它的"标签"就是互联网上现成的图片说明文字，不用人标注，所以能吃下 4 亿对。规模换来了开放词汇的理解能力。 ⟹ 这就是为什么 CLIP 认识泰勒·斯威夫特 —— 网上有几百万张带她名字的图。

⚠️ 代价（后面会反复咬人）：CLIP 的训练目标是"整张图和整句话对得上"，它从来没被要求关心细节。图里有 3 只猫还是 4 只猫，说明文字一般都写"几只猫"。⟹ 这是多模态模型数不清数、分不清左右、看不清小字的病根。 2.5 节展开。

训法③ SigLIP：把 softmax 换成 sigmoid

📖 SigLIP = Sigmoid Loss for Language-Image Pre-training，用 sigmoid 损失做的图文预训练（Google，2023，arXiv 2303.15343）。

    CLIP：  每一行必须做 softmax  ==> 必须知道【整个 batch 的所有格子】
            ==> 多卡训练时要把全部特征 all-gather 到一起，batch 越大通信越贵

    SigLIP：每个格子【独立】判断"这对图文配不配"，做二分类
            ==> 不需要全局归一化 ==> 大 batch 便宜得多，小 batch 效果还更好

回到上面那张 4×4 表，两种训法的区别一句话就能说清：

CLIP（softmax） SigLIP（sigmoid）
一个格子的目标 "在这一行里，你是最大的那个吗" "你自己是 1 还是 0"
算一个格子要用到 整行 / 整列的格子 只用这一个格子
多卡时要不要 all-gather 全部特征 要 不要
batch 越大 通信开销越贵 几乎不涨

⟹ 结果：SigLIP-SO400M 成了 2024~2025 开源多模态的默认视觉塔，几乎所有开源 VLM 都在用它。
⚠️ 这也带来一个隐患：大家的视觉能力上限被同一个视觉塔绑在了一起 —— 它看不清的东西，所有人都看不清。
✅ 顺带一个一手证据：DeepSeek-ViT 的第一阶段仍然用 SigLIP 的 sigmoid 对比损失（约 470 亿图文对，分辨率限死 224×224；报告明说"更高分辨率在这阶段收益不大，白费算力"）。⟹ 所以 SigLIP 这个损失函数并没有过时，过时的只是"把 SigLIP 的权重拿来当初始化"这件事 —— 下一节就是它。

2.3 ★ 2026 年的反转：视觉塔可以不用对比学习

Kimi K3 做了一件反直觉的事，而且给了证据：

✅ 官方结论（本仓库已核对）：MoonViT-V2 完全从零、用 next-token prediction（预测下一个 token）训练，不拿 SigLIP/CLIP 初始化。结果在视觉评测上追平了 SigLIP 初始化的基线。 报告的原话结论是：在规模化的多模态语言模型上，对比学习预训练作为初始化是不必要的。

理由是稳定性 ✅：报告给了梯度范数曲线（Fig. 6）—— SigLIP 初始化的版本梯度范数持续更高且频繁 spike，从零训的版本全程平稳。架构上还移除了所有线性层和注意力投影的 bias 项、改用 RMSNorm，来进一步稳定优化。

出处：../业界模型技术报告/Kimi-K3.md 报告 §六

怎么读这个结论（⚠️ 以下是我的解读，不是报告原话）：

    对比学习是【小数据时代的拐杖】：
      你只有 60 万条指令数据 ==> 视觉塔必须自带知识 ==> 必须用 CLIP 初始化
      你有几十 T 的多模态 token ==> 视觉知识可以在联合训练里自己长出来
                                ==> 拐杖反而成了包袱（优化目标不一致 ==> 梯度打架）

    ==> 🔑 这条结论【只对能负担原生多模态预训练的玩家成立】。
        如果你是在自己微调一个 7B 模型，老老实实用 SigLIP。

⚠️ 而且这条结论目前只有一家实证，另一家还走着相反的路：DeepSeek-ViT 也是从零自己训，但它的第一阶段仍然是 SigLIP 式的对比学习 ✅（470 亿图文对、224×224），只是对比学习之后再接一个 4 B 的 MoE LLM 做 2360 亿 token 的自回归微调，训完把 LLM 扔掉只留视觉编码器。

⟹ 两家都"从零训"，但"从零"的含义不一样：K3 是全程不用对比学习，DeepSeek 是自己做一遍对比学习。⟹ 🔑 看到"视觉塔从零训练"这句话，要接着问"用什么目标训的"。

2.4 三个必须知道的工程细节

① 取哪一层的输出？—— 通常不是最后一层

    ⚠️ 惯例是取【倒数第二层】的输出，而不是最后一层
    原因：最后一层是为"对比学习那个目标"高度特化过的，
          丢掉了很多对下游有用的细节 ==> 倒数第二层更"通用"
    ⚠️ 注意这条惯例的前提是"视觉塔是用对比学习训的"。
       按 2.3 节 K3 那条路线（全程 next-token prediction），这条惯例未必还成立，
       ⟹ 而 K3 报告没说它取哪一层。

② CLS token 还是全部 patch？

    CLIP 原本只输出一个 [CLS] 向量（整张图的摘要）—— 一个 token
    ==> ⚠️ 对"这张图是什么"够用，对"左下角写的什么字"完全不够
    ==> 所以多模态大模型一律用【全部 patch 的向量】，不用 CLS
    ==> 这也正是 token 数爆炸的来源（04 章）

📖 CLS token = classification token，一个额外加在序列最前面的"汇总位"，训练时让它去代表整张图。

③ 冻结还是一起训？

阶段 视觉塔 连接器 LLM 为什么
一 · 对齐 冻结 训 冻结 便宜、稳；只学"翻译"
二 · 预训练 解冻 训 训 效果好，但容易训崩
三 · 指令微调 常常再次冻结，或用很小的学习率 训 训 保住已经长出来的视觉能力

⚠️ "视觉塔用比 LLM 小 10~100 倍的学习率"是一条广泛流传的工程经验，各家实现不一，本仓库的一手报告里没有统一口径。见 06 章。

2.5 ★★ 视觉塔的四个已知短板

这四条是多模态模型出错时最常见的根因，值得单独记：

短板 典型症状 病根 治好了吗
① 数不清 "图里有几个人？" —— 5 个以上基本靠猜 CLIP 的训练文本几乎不含精确计数 ❌ 没有
② 分不清空间关系 "杯子在书的左边还是右边？" patch 顺序信息只靠位置编码，且对比学习不惩罚这类错误 ⚠️ 2D/3D RoPE 有改善（05 章）
③ 看不清小字 读不出截图里的报错行号 分辨率被 patch 大小卡死（00 章 0.6 节） ✅ 唯一被工程手段基本解决的一条（04 章的动态分辨率）
④ "CLIP 盲对" 两张人眼一看就不同的图，视觉塔给出几乎相同的向量 对比学习只要求"整图配整句"，细节差异不产生损失 ❌ 没有 
 ⟹ 第 ④ 条最要命：视觉塔没编码进去的信息，后面多大的 LLM 都救不回来
 ⟹ 有一类工作专门造这种对抗样本来测（如 V* 类基准，见 11 章）

🔑 一条排错原则：多模态模型答错时，先问 "是没看见，还是看见了但想错了？" 把图放大、裁剪出关键区域再问一遍 —— 如果裁剪后就对了，那是视觉塔的分辨率问题（04 章），不是模型笨。

2.6 ⚠️ 一条少数派路线：干脆不要视觉编码器

有人提出过更激进的做法：把 patch 直接线性投影后就丢进 LLM，中间什么塔都不要。（Adept 的 Fuyu 是最出名的例子；学术上有 EVE 等"无编码器 VLM"。）

    ✅ 好处：架构极简；天然支持任意分辨率（没有塔就没有塔的尺寸限制）
    ⚠️ 坏处：所有视觉学习的担子全压在 LLM 主干上 ==> 要非常大的数据才追得上
    ⚠️ 还有一条很少被提的好处：2.7 节那笔账直接消失一半
       —— 没有视觉塔，就没有"在 n 个 patch 上跑 27 层注意力"这件事

⚠️ 我的判断：这条路线目前是少数派，但它和 2.3 的 K3 结论指向同一个方向 —— 当预训练规模足够大时，"专门的视觉预训练"这件事的必要性在下降。 这可能是未来几年的一个变化方向，但现在还不是主流，14 章会再提。

2.7 ★★ 算一笔计算量的账：为什么 0.1% 的参数能吃掉一半算力

这是本章最该带走的一节。视觉塔只占总参数的 0.014%~0.15%（01 章 1.2 节那张表），但它吃掉的算力完全不是这个比例。

2.7.1 先把公式摆出来

一层标准 Transformer 的前向 FLOPs（浮点运算次数，乘加各算 1 次）：

    矩阵乘部分（Q/K/V/O + FFN）：24 x n x d^2      <- 和 token 数 n 成【正比】
    注意力部分（QK^T 和 乘 V）：  4 x n^2 x d      <- 和 token 数 n 成【平方】

    n = patch 数（★ 注意：视觉塔跑在【压缩前】的 patch 数上，不是压缩后的 token 数）
    d = 视觉塔宽度

代入 27 层、d = 1152 的视觉塔（也就是 SigLIP-SO400M / MoonViT-V2 那个形状），整座塔就是：

    视觉塔 FLOPs = 27 x (24 x 1152^2) x n  +  27 x (4 x 1152) x n^2
                 = 8.60e8 x n             +  1.244e5 x n^2

2.7.2 把分辨率一档一档代进去

输入边长 patch 数 n 矩阵乘项 注意力项（n²） 合计 n² 项占比
336² 576 0.50 TFLOP 0.04 TFLOP 0.54 TFLOP 7.7 %
448² 1024 0.88 0.13 1.01 12.9 %
1024² 5329 4.58 3.53 8.12 43.5 %
1092² 6084 5.23 4.61 9.84 46.8 %
1344² 9216 7.93 10.57 18.49 57.1 %
2016² 20736 17.83 53.50 71.33 75.0 %
3584² 65536 56.37 534.4 590.7 90.5 %

★★ 看最后一列：336² 时注意力只占视觉塔开销的 8%，到 3584² 时它占 90%。同一座塔，什么都没改，只是喂了更大的图，开销结构就彻底翻了个个儿。

⚠️ 这里有个"边长翻倍"的陷阱：边长翻倍 → patch 数变 4 倍 → 矩阵乘项变 4 倍、注意力项变 16 倍。所以 "支持 2 倍分辨率"在算力上不是 2 倍代价，是 4~16 倍。

2.7.3 和 LLM 那边比一比

LLM 侧的 prefill FLOPs 有个简单估法：2 × 激活参数量 × token 数。而视觉 token 数 = patch 数 ÷ 4（2×2 合并）。拿 GLM-5.3-Flash 的 18 B 激活当参照：

输入边长 视觉塔 FLOPs 视觉 token LLM prefill FLOPs 视觉塔占两者之和
336² 0.54 TFLOP 144 5.18 TFLOP 9.4 %
448² 1.01 256 9.22 9.9 %
1024² 8.12 1332 47.95 14.5 %
1344² 18.49 2304 82.94 18.2 %
2016² 71.33 5184 186.6 27.7 %
3584² 590.7 16384 589.8 50.0 %

★★ 最后一行值得单独记住：一张 3584×3584 的图，视觉塔消耗的算力，和一个 18 B 激活参数的 LLM 把那 16384 个 token 过一遍，刚好一样多（591 对 590 TFLOP）。 而这座塔只有 0.4 B 参数 —— 是 LLM 激活量的 1/45。

把这个"打平点"算成一个通用结论，让 视觉塔 FLOPs = LLM prefill FLOPs 解出激活参数量 P：

    8.60e8 x n + 1.244e5 x n^2 = 2 x P x (n / 4)
    ==> P = 2 x (8.60e8 + 1.244e5 x n)
输入边长 patch 数 n LLM 激活参数多大时两边打平
1024² 5329 3.0 B
1344² 9216 4.0 B
2016² 20736 6.9 B
3584² 65536 18.0 B

🔑 这张表是本章的结论：LLM 的激活参数量比打平值小，视觉塔就是瓶颈；比它大，LLM 才是瓶颈。
⟹ 所以同一座视觉塔，在不同模型里的地位完全不同：接在 18 B 激活的 GLM-5.3-Flash 后面，3584² 输入时它吃掉一半算力；接在 104.2 B 激活的 Kimi K3 后面（✅ 报告数字），同样的输入它只占 ⚠️ 14.7%（590.7 ÷ (590.7 + 2×104.2e9×16384÷1e12)）。
⟹ 🔑 "视觉塔是不是瓶颈"这个问题，在 MoE 把激活参数压到十几 B 的 2026 年，答案变了。

2.7.4 换成墙上时间

    H100 SXM5 的 BF16 稠密峰值 = 989 TFLOPS
      ⚠️ 别用 1979 —— 那是 2:4 稀疏值，常规算子用不上
    取一个现实的 40% MFU（模型算力利用率）==> 有效约 400 TFLOPS

    1092x1092 一张图：  9.84 TFLOP / 400 TFLOPS  ≈  25 毫秒
    3584x3584 一张图：  590.7 TFLOP / 400 TFLOPS ≈  1.48 秒   <- ★ 一张图！

⟹ 1.48 秒这个数字，一下就解释了 GLM-5.3-Flash 为什么要把视觉编码单独拆成一个部署池（EPD 分离）：

✅ 官方原文："our production-grade Encode–Prefill–Decode (EPD) disaggregated architecture separates multimodal encoding, prompt prefill, and token-by-token decoding into independently scheduled and scalable worker pools"（把多模态编码、prompt 预填充、逐 token 解码拆成三个独立调度、独立扩缩容的 worker 池）。出处 ../业界模型技术报告/GLM-5.3.md 报告 §7.2。

⚠️ 必须区分哪句是官方的、哪句不是：官方原文只说了"拆成三池"这件事本身。"视觉编码是纯计算密集、挤在一起会把 decode 的卡堵住"是本仓库归档时自己加的解释，不是报告结论 —— 本节这笔账算的就是它到底成不成立（结论：成立，而且量级比直觉大得多）。GLM-5.3-Flash 的视觉塔是 24 层 / 0.30 B ✅（这个数字倒是一手的，来自报告 §5.2 按 config.json 做的参数推演）。

部署侧细节见本教程 12 章。

2.8 🔑 这一章的五句话

  1. ViT = 把图切块当句子读。 没有魔法，就是一个线性投影 + 标准 Transformer。
  2. CLIP/SigLIP 用"图文配对"这个免费监督信号，换来了开放词汇的视觉理解。 SigLIP 因为大 batch 便宜而成为事实标准。
  3. ✅ 2026 年 K3 证明了：在足够大的规模上，对比学习初始化不是必需的，从零训反而更稳。⚠️ 但 DeepSeek-ViT 走的是"自己做一遍对比学习再自回归微调"，"从零训"这四个字含义不统一，要追问训练目标。
  4. ⚠️ 视觉塔是整条链路的信息瓶颈：它没编码的东西，后面 2.78 T 参数也变不出来。排错先怀疑它。
  5. ★★ 它同时还可能是算力瓶颈：2.7 节算出来，3584² 输入下一座 0.4 B 的视觉塔，吃掉的算力等于一个 18 B 激活 LLM 的全部 prefill。参数量占比和算力占比是两件事，差三个数量级。
