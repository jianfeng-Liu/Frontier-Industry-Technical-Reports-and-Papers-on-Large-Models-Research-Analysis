# 03 · 连接器：怎么把视觉向量"翻译"给语言模型

> 三大件的第二件，**也是最小的一件**（几千万参数），
> 但它决定了两件大事：**视觉 token 占多少上下文**、**信息在这里丢多少**。

---

## 3.1 它到底要解决什么

视觉塔吐出来的是 6084 个 **1152 维**向量，LLM 要的是 **4096 维**向量。
所以最起码得做一次形状转换。但真正的问题有三个：

```
    问题① 形状不对    1152 维  ⟹  4096 维              ← 一个矩阵就能解决
    问题② 数量太多    6084 个 token 塞进上下文太贵       ← ★ 真正的难点
    问题③ 分布不对    视觉塔的向量【长得不像】文字 embedding
                     ⟹ LLM 会"读不懂"，需要学一个映射把它拉进同一片空间
```

> 🔑 **连接器 = 一个降数量 + 换形状 + 对齐分布的小模块。**
> ⚠️ 它参数很少，但它是**唯一一个必须从零训练的部件**（视觉塔和 LLM 都可以拿现成的）。

---

## 3.2 ★★ 两大流派：塞进去 vs 挂旁边

这是本章最重要的一张图。**所有连接器方案都属于这两类之一。**

### 流派 A：输入端拼接（prefix / decoder-only 式）

```
    视觉 token 直接【混进输入序列】，和文字 token 平起平坐

    序列：[图1][图2]...[图1521][「这][「个][「报][「错]...
           └──── 视觉 ────┘  └──── 文字 ────┘
                    ↓
              一个标准 LLM，什么都不用改

    ✅ 优点：LLM 一个字都不用改；图文可以任意交错；实现极简
    ⚠️ 缺点：★ 视觉 token 吃掉上下文预算，而且参与全部注意力计算（平方开销）
```

**代表**：LLaVA 系列、Qwen-VL 系列、InternVL、以及**本仓库里 K3 / M3 / GLM-5.3-Flash 三家 2026 年模型**
（⚠️ 后者是我从"2×2 merge 后投影进主干"这个描述反推的，报告没有明说流派归属）。

### 流派 B：交叉注意力（cross-attention 式）

```
    视觉 token 【不进序列】，而是挂在旁边当"资料库"
    在 LLM 的某些层之间，插入新的一层：让文字 token 去【查阅】视觉 token

    序列：[「这][「个][「报][「错]...       ← 序列里只有文字
                  ↕ 第 4、12、20... 层插入 cross-attention
            [图1][图2]...[图6084]        ← 视觉在"外面"

    ✅ 优点：★ 视觉 token 不占上下文；6084 个也无所谓；开销是 n_text × n_image（线性，不是平方）
    ⚠️ 缺点：必须【改 LLM 结构、加新层】⟹ 新层要从零训 ⟹ 需要多得多的训练数据
             图文交错的位置关系表达起来别扭
```

**代表**：Flamingo（2022，arXiv 2204.14198，这条路的开创者）、Llama 3.2 Vision。

### 一张对照表

| | 流派 A 拼接 | 流派 B 交叉注意力 |
|---|---|---|
| LLM 要不要改 | **不用** | 要加层 |
| 视觉 token 占上下文吗 | **占** | 不占 |
| 计算量随图像 token 数 | **平方** | 线性 |
| 训练数据需求 | 小（60 万条就能起步） | 大 |
| 图文交错灵活度 | **高** | 低 |
| 2024 年后的主流 | **★ 是** | 少数派 |

> ⚠️ **为什么流派 A 赢了？** 我的判断是三条：
> ① **生态惯性**——不用改 LLM，意味着能直接蹭所有现成的推理框架（vLLM/SGLang）和训练框架；
> ② **数据效率**——学术界和创业公司拿不出 Flamingo 那个量级的数据；
> ③ **长上下文变便宜了**——2023 年 4K 上下文时"视觉 token 占位置"是致命的，
> 2026 年动辄 1M 上下文，**这个缺点被硬件和算法进步稀释掉了**。
>
> ⟹ 🔑 **一个通用规律：当某个资源变便宜时，为省它而设计的复杂架构就会被淘汰。**
> 这和 [../推理框架/](../推理框架/) 里 KV cache 相关设计的演化是同一个逻辑。

## 3.3 流派 A 内部的三种具体做法

### 做法① 线性层 / MLP —— ★ 现在的主流

```
    每个视觉向量【独立地】过一个小网络：
      1152 ──[Linear]──→ 4096 ──[GELU]──→ [Linear] ──→ 4096

    参数量：1152×4096 + 4096×4096 ≈ 2150 万  ← 整个模型里可以忽略不计
    token 数：★ 【不变】。进来几个，出去几个
```

**LLaVA（2023）用的是单个线性层；LLaVA-1.5 换成两层 MLP，分数明显上涨。**
就这么简单的改动 ⟹ ⚠️ 说明这一层的**表达能力确实是瓶颈之一**，但也就到两层为止，再深收益很小。

### 做法② 空间合并（pixel shuffle / patch merge）—— ★ 2026 年标配

**这是目前砍 token 最主流、也最粗暴有效的手段**：

```
    把相邻 2×2 = 4 个 patch 的向量【直接拼起来】，当成一个 token

      [a][b]          a,b,c,d 各 1152 维
      [c][d]   ⟹   拼接成 4608 维 ⟹ 过 MLP ⟹ 4096 维

    ⟹ token 数除以 4，信息【一点没丢】（只是换了个装法，由后面的 MLP 去消化）
    ⟹ ★★ 注意力开销直接除以 16
```

> ✅ **三家 2026 年模型全用了这一招**（本仓库一手报告）：
> - **Kimi K3**：投影前用 **2×2 pixel shuffle** 把视觉 token 数降 4 倍，
>   *"让 3584×3584 的输入在 1M 上下文里放得下"*
> - **MiniMax M3**：**2×2 空间 + 2 帧时间** patch merge
> - ⟹ 出处：[../业界模型技术报告/Kimi-K3.md](../业界模型技术报告/Kimi-K3.md) §六、[../业界模型技术报告/模型技术对比.md](../业界模型技术报告/模型技术对比.md) §多模态行
>
> 🔑 **"2×2 合并"在 2026 年已经不算技术，算常识了。** 看到某个模型没做，反而要问为什么。

### 做法③ Q-Former / Perceiver Resampler —— ★ 已退潮，但必须认识

> 📖 **Q-Former**（BLIP-2，2023，arXiv 2301.12597）/ **Perceiver Resampler**（Flamingo）：
> 准备 **固定数量**（比如 32 个）的"提问向量"（learnable query），
> 让它们用交叉注意力去"采访"那 6084 个视觉 token，最后只输出这 32 个。

```
    32 个 query  ──cross-attn──→  6084 个视觉 token
         ↓
    输出【永远是 32 个】token —— 不管原图多大

    ✅ 优点：token 数【完全可控且极小】，一张图只占 32 个位置
    ⚠️ 致命缺点：★ 6084 → 32 是一个【硬信息瓶颈】
                 普通照片够用，但文档、表格、小字直接死掉
    ⚠️ 缺点二：这个模块要单独训，训练不稳定、收敛慢
```

> ★★ **为什么它退潮了**：2024 年之后，**文档 / 截图 / 表格成了主要应用场景**，
> 而这些场景恰恰是"32 个 token 装不下"的。
> ⟹ 🔑 **业界的选择是：宁可多花 token，也不要丢信息。**
> ⟹ 这个转折是理解 2023→2026 多模态演进的一条关键线索（[14 章](14-演进主线与开放问题.md)）。

## 3.4 ★ 一个容易被忽略的细节：特殊标记

视觉 token 塞进序列时，两边要加标记：

```
    ... 用户说：<|image_start|> v1 v2 ... v1521 <|image_end|> 这个报错怎么修？ ...
                └── 这两个是【真正的文本 token】，在词表里有编号 ──┘
```

**为什么需要**：
```
    ① 让模型知道"这一段是图，不是文字"
    ② 多图时能分清哪些 token 属于哪张图
    ③ ★ 有的模型还会插入行分隔符（每行 patch 结束插一个 <|row_end|>）
       ⟹ 帮助模型建立【二维空间感】—— 因为序列本身是一维的（05 章）
```

> ⚠️ **实操陷阱**：这些特殊 token 的数量会被算进你的账单，而且不同模型的模板完全不同。
> **自己拼 prompt 时把模板拼错，是多模态调用最常见的低级错误。**

## 3.5 训练时谁冻谁

连接器是唯一必须从零训的部件，所以训练流程一般这样安排（细节见 [06 章](06-训练流程三阶段.md)）：

```
    阶段一 对齐        视觉塔 ❄️冻   连接器 🔥训   LLM ❄️冻
                      ⟹ 只学"翻译"，几百万图文对，几十卡·天
                      ⟹ ★ 这一阶段冻住 LLM 是为了【不破坏它的语言能力】

    阶段二 联合训练     视觉塔 🔥     连接器 🔥     LLM 🔥
                      ⟹ 真正长本事的阶段，也是最贵的阶段

    阶段三 指令微调     视觉塔 ❄️/🔥小lr  连接器 🔥   LLM 🔥
```

> ⚠️ **"阶段一必须冻住 LLM"是 LLaVA 时代的经验**，前提是数据少。
> **原生多模态路线（如 GLM-5.3-Flash 的 30T 多模态语料）根本没有"阶段一"这回事**——
> 它从第 0 步就是全部一起训的。**别把小规模微调的经验直接套到大规模预训练上。**

---

## 3.6 🔑 这一章的四句话

1. 连接器要干三件事：**换形状、降数量、对齐分布**。参数很少，但它是信息瓶颈的所在。
2. **两大流派：拼进序列（主流）vs 挂旁边做交叉注意力（少数派）。** 主流赢在生态和数据效率，而不是赢在原理更优。
3. **2026 年的标配组合是"2×2 空间合并 + 两层 MLP"** ✅——K3、M3 都是这一套。够用、无信息损失、极简。
4. ⚠️ **Q-Former 那种"压到固定 32 个 token"的路线已经退潮**，因为文档和截图场景装不下。
   **这是"宁可贵也不丢信息"这个价值取向的胜利**，也是下一章的引子。
