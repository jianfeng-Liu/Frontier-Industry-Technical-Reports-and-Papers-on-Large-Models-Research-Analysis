# 06 · 训练流程：三个阶段，谁冻谁训

> 前五章讲的是"模型长什么样"，这一章讲"它是怎么被训出来的"。
> **两条路线的训练流程完全不同**（01 章 1.3 节），先讲便宜的那条，再讲贵的那条。

---

## 6.1 ★ 拼接式路线：三阶段流水线

这是**开源社区和绝大多数团队实际会走的路**，也是你自己动手时会走的路。

```
 ┌── 阶段一：对齐（alignment / 预对齐）──────────────────────────┐
 │  数据：几百万 ~ 几千万条【图 + 一句说明】（图文对）              │
 │  冻结：视觉塔 ❄️   连接器 🔥   LLM ❄️                          │
 │  目标：让连接器学会"把视觉向量翻译成 LLM 听得懂的话"             │
 │  代价：几十张卡 × 几天                                        │
 │  ★ 为什么冻 LLM：数据量小、质量参差，放开会【破坏语言能力】        │
 └──────────────────────────────────────────────────────────┘
                              ↓
 ┌── 阶段二：多模态预训练（也叫 continued pretraining）─────────────┐
 │  数据：几百 B ~ 几 T token，图文交错文档 + OCR + 图表 + 视频      │
 │  冻结：视觉塔 🔥   连接器 🔥   LLM 🔥（全放开）                  │
 │  目标：真正长本事——认字、读表、懂图表、理解画面里的世界            │
 │  代价：★ 这一阶段占多模态训练总成本的大头                        │
 └──────────────────────────────────────────────────────────┘
                              ↓
 ┌── 阶段三：多模态指令微调（SFT）────────────────────────────────┐
 │  数据：几十万 ~ 几百万条【图 + 问题 + 标准答案】                  │
 │  冻结：视觉塔 ❄️ 或小学习率   连接器 🔥   LLM 🔥                 │
 │  目标：学会【按人类期望的方式回答】——格式、拒答、不瞎编            │
 │  ⟹ 机制和纯文本 SFT 一模一样，见 ../后训练/02-SFT-监督微调.md    │
 └──────────────────────────────────────────────────────────┘
                              ↓
 ┌── 阶段四（2025 年后新增）：多模态后训练 / RL ────────────────────┐
 │  ⟹ 单独用一章讲：08 章                                         │
 └──────────────────────────────────────────────────────────┘
```

## 6.2 ★★ loss 加在哪：一个初学者一定会踩的坑

```
    序列：[<img>][v1][v2]...[v1521][</img>][「这][「个][「报][「错]...[答][案]

    ⚠️ 天真做法：所有 token 都算 next-token prediction loss
       ⟹ 但视觉 token 是【连续向量】，根本不在词表里，
         "预测下一个视觉 token"这件事在标准 LLM 的输出头上【无法定义】

    ★ 标准做法：视觉 token 位置【不算 loss】（用 loss mask 屏蔽），
       只在文本 token 上算。视觉 token 只作为【上下文】参与注意力。

    ⟹ 🔑 这就是为什么理解型多模态模型【只能吐字，不能吐图】——
       它的输出头就只有一个词表那么宽。
    ⟹ ★★ 想让它吐图，就必须改输出头，这是 09 章的全部内容。
```

> 📖 **loss mask（损失掩码）**：只在序列的某些位置计算损失、其余位置置零。
> 纯文本 SFT 里"只在答案上算 loss"用的是同一个机制，见 [../后训练/02-SFT-监督微调.md](../后训练/02-SFT-监督微调.md)。

## 6.3 原生多模态路线：没有"阶段一"

```
    ✅ GLM-5.3-Flash：预训练语料就是【30T 多模态语料】
       —— 不是"先训文本再加视觉"，而是从头就混着
       出处：../业界模型技术报告/GLM-5.3.md §五、§九

    ✅ Kimi K3：视觉塔 MoonViT-V2 【从零、用 next-token prediction 训练】
       ⟹ 连"拿 SigLIP 当起点"这一步都省了
       出处：../业界模型技术报告/Kimi-K3.md §六
```

**两条路线的对照**：

| | 拼接式 | 原生多模态 |
|---|---|---|
| 起点 | 现成的 LLM + 现成的视觉塔 | 从零 |
| 有没有"冻结阶段" | ★ 有，而且很关键 | 基本没有 |
| 多模态数据量 | 几 B ~ 几百 B token | **几 T ~ 几十 T token** |
| 谁能做 | 几乎所有人 | ⚠️ 只有大厂 |
| 视觉能力上限 | 受视觉塔限制 | 更高（理论上） |
| 纯文本能力 | ★ 容易掉 | 也可能掉，但有数据配比兜底 |

## 6.4 ⚠️ 三个真实会咬人的问题

### 问题① 灾难性遗忘：加了视觉，文本变笨了

```
    现象：多模态微调后，MMLU / 数学 / 代码分数【掉几个点】
    原因：阶段二三的数据里图文占比过高，模型往"看图说话"漂移

    ★ 标准解法：在多模态训练数据里【混入相当比例的纯文本数据】
    ⚠️ 混多少？各家不披露，这是多模态训练里最重要的一个"暗数"之一
    ⟹ 数据配比的通用方法论见 ../数据格式和数据处理/10-数据配比.md
```

> 🔑 **判断一个多模态模型是否"健康"的最快方式：看它的纯文本分数有没有掉。**
> ⚠️ 很多模型的多模态版本会悄悄比文本版本弱一截，而模型卡上通常不会并排放这两组数字。

### 问题② 训练不稳定

```
    ✅ 一手证据（K3）：SigLIP 初始化的视觉塔在联合训练时
       【梯度范数持续更高且频繁 spike】；从零训的 MoonViT-V2 全程平稳。
       K3 还【移除了视觉塔中所有线性层和注意力投影的 bias 项】来进一步稳定优化。

    ⚠️ 我的解读：视觉塔和 LLM 是【在完全不同的目标下训出来的】，
       梯度尺度天差地别 ⟹ 硬接在一起就打架。
       ⟹ 这也是"视觉塔用小 10~100 倍学习率"这条工程经验的由来。
```

### 问题③ 分辨率课程

```
    ★ 常见做法：低分辨率起步 → 逐步提高
       前期：448² 训得快、token 少 ⟹ 用同样算力看更多样本
       后期：切到 1792² 或更高 ⟹ 学"看清小字"

    ⟹ ⚠️ 和长上下文扩展是同一个套路：
       ✅ K3 报告的原则是"把昂贵的长序列计算【集中在总训练预算的一小部分里】"
          （出处 ../业界模型技术报告/Kimi-K3.md §七）
       ⟹ 贵的东西留到最后、只训一小段，是大模型训练的通用节俭原则。
```

## 6.5 ⚠️ "多模态到底该在哪个阶段进来"——一个未解决的问题

```
    观点 A（原生派）：越早越好。
      视觉应该是世界观的一部分，后加的永远是外挂。
      ✅ GLM-5.3 的论证：编程模型需要【自己决定何时去看】渲染结果，
         这要求视觉是原生的能力，而不是一个可选插件。

    观点 B（拼接派）：越晚越好。
      文本 token 的信息密度远高于图像 token，
      ⚠️ 用宝贵的预训练算力去看图，可能不如多看几 T 文本划算。
      ⟹ 证据：DeepSeek-V4、openPangu-2.0-Pro 这两个【纯文本】模型
         在代码和推理上依然处于第一梯队。

    🔑 目前【没有公开的对照实验】能回答这个问题——
       因为做这个实验要花两次预训练的钱。
```

> ⚠️ **我的判断**：这个问题的答案很可能和**你想要什么**有关，而不是有一个普适最优：
> 做**通用助手/GUI agent** ⟹ 原生；做**代码/数学推理引擎** ⟹ 纯文本可能更划算。
> **五家 2026 年旗舰"三家做、两家不做"，且不做的那两家都是推理/代码导向**（01 章那张表），
> 这个分布本身就是对上述判断的一点支持。

---

## 6.6 🔑 这一章的四句话

1. 拼接式的三阶段是 **对齐（只训连接器）→ 联合预训练（全放开）→ 指令微调**，冻结策略是核心。
2. **视觉 token 不算 loss**——这条决定了理解型模型"只进不出"，也是 09 章统一生成的起点。
3. ⚠️ **加视觉会让纯文本变笨**，靠混纯文本数据兜底；**混多少是各家最不肯说的暗数之一**。
4. ✅ **训练稳定性是原生路线的真实痛点**，K3 用"从零训 + 去 bias"给出了一个有证据的答案。
