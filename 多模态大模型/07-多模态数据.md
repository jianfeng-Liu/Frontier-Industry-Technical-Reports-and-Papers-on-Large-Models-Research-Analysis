## 7.1 数据的六个家族

**先把"什么数据、多大规模、从哪来、喂给哪个阶段"一次排清。** 阶段编号对应 [06 章 6.1 节](06-训练流程三阶段.md) 那张表。

| 家族 | 一条样本长什么样 | 典型规模 | 来源 | 主要喂哪个阶段 | 教会模型什么 | ⚠️ 主要坑 |
|---|---|---|---|---|---|---|
| ① **图文对**<br>image-text pair | 一张图 + 一句 alt-text | 几亿 ~ 几十亿条 | 网页 `<img alt="...">` | ★ 视觉塔预训练（CLIP / SigLIP）+ 阶段一对齐 | "这张图 ←→ 这句话" | ★★ **质量极差**，见 7.2 |
| ② **交错图文文档**<br>interleaved | 一整篇网页 / 文章，图和文按原顺序混排 | 几亿篇文档 / 几百 B ~ 几 T token | Common Crawl 保序抽取（MMC4、OBELICS） | ★★ **阶段二的主粮** | "这张图**在这段上下文里**意味着什么" | 正文抽取 + 保住图片位置，脏活极重，见 7.3 |
| ③ **OCR / 文档** | 发票、论文 PDF、表格、手写 + 对应文字 | 几千万 ~ 几亿页 | PDF 库、扫描件、自建拍摄 | 阶段二 + 阶段三 | ★ 认字。**2024 年后最重要的增量** | 版面还原比识字难；非英语语种覆盖差 |
| ④ **图表与结构化图形** | 折线图 / 饼图 / 流程图 / UML / 电路图 + 问答 | 几百万 ~ 无上限 | ★ **可以程序化生成**，见 7.4 | 阶段二 + 阶段三 | 读数、比较、趋势判断 | ⚠️ 合成图表**风格分布很窄**，见 7.4 末 |
| ⑤ **GUI / 截图与操作轨迹** | 截图 + "点了哪个按钮（坐标）" + 结果截图 | 几十万 ~ 几千万条轨迹 | 自建环境录制、无障碍树导出 | 阶段二 + 阶段三 + ★ 阶段四 RL | GUI grounding（"点哪里"）、多步操作 | ★★ 最贵，必须自己搭环境；**2026 年最有商业价值的一类** |
| ⑥ **视频** | 视频 + 字幕 / ASR 转写 / 人工描述 / 时间戳标注 | 几百万 ~ 几千万条 | 视频平台、自建拍摄 | 阶段二（少量）+ 阶段三 | 时序、因果、动作 | ⚠️ 最贵最稀缺；**带时间标注的几乎没有公开大规模数据集** |

> 📖 **ASR（Automatic Speech Recognition，自动语音识别）**：把语音转成文字。视频数据里的"转写"大多是 ASR 自动产出的，所以**它本身就带识别错误**——这是视频语料噪声的一个常被忽略的来源。ASR 本身在 [10 章](10-语音与实时全双工.md) 展开。

> 🔑 **这张表最值得记的一列是"喂给哪个阶段"**：⚠️ **初学者最常见的误解是"多模态预训练就是拿几十亿图文对去训"**。不是。**图文对主要是视觉塔的口粮和阶段一的对齐材料；真正撑起阶段二的是家族 ②③④。**

## 7.2 ★★ 第一个反直觉：网上的图片说明文字基本是垃圾

```
真实的 alt-text 长这样：
  "IMG_20230412_183045.jpg"
  "点击查看大图"
  "banner-final-v3-USE-THIS-ONE"
  "红色连衣裙 春季新款 包邮 限时折扣 XL 加大码"   ← 电商 SEO 关键词堆砌

⟹ ⚠️ 里面几乎不含"图里到底有什么"的信息
```

> ⚠️ **公开图文对语料的标准筛法是拿 CLIP 算图文相似度、设一个阈值扔掉不匹配的对**（LAION 系列是最有名的做法）。**但这只能筛掉"明显不匹配"，筛不掉"匹配但没信息"**——"红色连衣裙"配一张红裙照片，CLIP 分数很高，可它一个字都没说画面里的构图、场景、文字和空间关系。**7.5 节会讲这个筛法自带的第二个问题。**

### 2023 年后的标准解法：重写说明（recaptioning / 合成 caption）

```
① 拿一个已经能看图说话的模型（一个中等大小的 VLM，或专门微调的 captioner）
② 让它给这几亿张图【重新写一段详细描述】
③ 用【重写后的描述】去训下一代模型

⟹ ★ 这是多模态版的"合成数据"，收益极大
⟹ ⟹ 纯文本领域的同一个思想见 ../数据格式和数据处理/12-合成数据.md
   （WRAP / Rephrasing the Web 那一路）
```

### ★ 同一张图，两种说明文字：逐项对照

拿一张"会议室长桌上放着两台打开的笔记本电脑，白板上写着 Q3 Roadmap"的照片：

| 对照项 | 原始 alt-text | 合成 caption |
|---|---|---|
| 实际文本 | `IMG_4471.jpg` | "一间会议室，长桌上放着两台打开的笔记本电脑，桌面还有两个马克杯；左侧墙上的白板写着 'Q3 Roadmap'，下方列了三条待办。" |
| 长度 | 12 个字符 | 约 70 个汉字 |
| 有没有说**物体** | 没有 | 有（笔记本、马克杯、白板） |
| 有没有说**数量** | 没有 | ★ 有（两台、两个、三条） |
| 有没有说**空间关系** | 没有 | ★ 有（桌上、左侧墙上、下方） |
| 有没有说**图中的文字** | 没有 | ★★ 有（`Q3 Roadmap`）—— **这一项是 OCR 能力的直接来源** |
| ⚠️ 有没有可能是**错的** | 不会——它什么都没说 | ★★ **会**——captioner 可能把两台写成三台 |

> 🔑 **最后两行是这一节的全部重点**：**原始 alt-text 的问题是"没有信息"，合成 caption 的问题是"有错误的信息"。** ⟹ 前者是**噪声**，几亿条平均下来会互相抵消；后者是**偏置**，它有系统性的方向，**不会被平均掉，只会被下一代模型继承并放大**。⟹ ★ 这也是 [08 章](08-幻觉与多模态后训练.md) 讲的幻觉，在数据侧的一个源头。

### 合成 caption 解决了什么、引入了什么

| | ✅ 解决的 | ⚠️ 引入的 |
|---|---|---|
| 信息量 | 从"关键词"变成"完整描述"，数量 / 空间关系 / 画面文字这三类信息第一次出现在监督信号里 | — |
| 可控性 | 可以指定 captioner 必须描述哪几项（主体、环境、空间位置、可见文字、风格、颜色） | 风格**高度同质**（"这是一张展示……的图片，画面中……"），模型的输出腔调变死板 |
| 正确性 | 比"点击查看大图"强太多 | ★★ **captioner 自己会幻觉**，编出来的细节被当成真标签写进训练集 |
| 分布 | 覆盖了 alt-text 根本不涉及的描述维度 | ★ **过拟合到合成 caption 的句式分布**——模型只认这一种说法 |
| 成本 | 一次重标可以覆盖全量数据，人工标注做不到这个规模 | ⚠️ 给 10 亿张图重写描述**本身就是一次大规模推理任务**，不便宜 |

> ✅ **一个有具体数字的一手配方**：DALL·E 3 的技术报告（James Betker 等，*Improving Image Generation with Better Captions*，OpenAI，2023）明确给出的训练配比是 **95% 合成 caption + 5% 原始 alt-text**；报告做了 80% / 90% / 95% 三档的消融，结论是**单调的**——合成比例越高，提示词遵循越好。报告同时说明了**为什么还要留那 5%**：防止模型过拟合到合成 caption 的分布；并承认**captioner 自己会幻觉细节**。
> ⚠️ **口径提醒**：这是一个**文生图**模型的结论（指标是 CLIP score 和提示词遵循），**不能直接当成"理解型多模态模型也该用 95%"**。本仓库没有任何一手报告披露过理解型模型的合成 caption 比例——**那是和纯文本配比一样的"暗数"**（06 章 6.5 节）。

## 7.3 ★ 第二个反直觉：交错数据比图文对重要得多

```
图文对教会的是：      这张图 ←→ 这句话
交错文档教会的是：    这张图 在这段上下文里 意味着什么

⟹ 只有后者能产生这些能力：
   · 多图对比（"这两张图哪里不一样"）
   · 图上下文学习（给几个"图→答案"的例子，模型照着做新的）
   · 长文档理解（论文里的图 3 和正文第 4 段的关系）
```

**公开代表**：MMC4、OBELICS 这类"从 Common Crawl 里保留图文顺序"的语料。

> ⚠️ **工程上的难点被严重低估**：网页正文抽取本身就难（见
> [../数据格式和数据处理/02-数据源与文本抽取.md](../数据格式和数据处理/02-数据源与文本抽取.md)），
> **还要同时保住图片和它在正文中的准确位置**——广告图、图标、间隔线还得剔掉。
> **这部分脏活是各家的真实差距所在，而且没人写进报告。**

> ★ **为什么"保住位置"这么要紧**：一旦图的插入位置偏了一段，模型学到的就是**错的图文对应关系**。⟹ ⚠️ 而这种错误**在数据质量指标上完全看不出来**：文本是干净的，图片是清晰的，CLIP 分数也不低——**只有图和文的配对关系是错的**。这是多模态数据里最隐蔽的一类脏。

## 7.4 ★★ 多模态独有的一张王牌：可以"渲染"出完美数据

**这是多模态相对纯文本最大的数据优势，初学者往往完全没意识到。**

```
纯文本领域：想要"这道数学题的正确答案"，得有人做题或有验证器
多模态领域：★ 你可以【先有答案，再生成图】

例：造图表理解数据
  ① 随机生成一份数据表（我知道每个数值）
  ② 用 matplotlib 画成折线图                 ← 图有了
  ③ 自动出题："2019 年的值是多少？" 答案我【本来就知道】
  ⟹ 完美标注，无限量，零人工，零幻觉

同理可造：
  · HTML/CSS  →  渲染截图  →  "写出这个页面的代码"（图→码，完美配对）
  · LaTeX     →  渲染公式  →  OCR 数学公式训练数据
  · 合成表格  →  渲染成图  →  表格结构还原
  · 程序化 UI →  截图 + 元素坐标 →  ★ GUI grounding（"点哪里"）的坐标标注
```

> 🔑 **这是"可验证奖励"思想在多模态上的对应物**——见 [../后训练/05-RLVR-可验证奖励.md](../后训练/05-RLVR-可验证奖励.md)。
> **凡是"能被程序渲染出来的东西，就能被程序无限量地标注"。**
>
> ✅ **2026 年的一手证据**：GLM-5.3 的多模态训练方法就是**面向视觉编程的数据合成流水线**，
> 核心是 *self-visual judgment（自我视觉判断）*：
> **让模型与环境交互 → 检查自己的输出 → 迭代改进**，
> 并把验证范围*"从功能正确性扩展到渲染结果和可交互产物"*。
> 出处：[../业界模型技术报告/GLM-5.3.md](../业界模型技术报告/GLM-5.3.md) §六 ✅

> ★ **和 7.2 的合成 caption 对比一下，差别是根本性的**：合成 caption 是**让模型去描述一张已有的图**，所以它**可能描述错**；渲染合成是**先有结构化的真值、再把它画成图**，所以它**不可能错**。⟹ 🔑 **一个是"模型当标注员"（引入模型的偏置），一个是"程序当标注员"（标注就是真值本身）。** 这两条路的可信度完全不在一个量级上。

> ⚠️ **但渲染数据有它自己的天花板**：合成图表的**风格分布很窄**
> （都是 matplotlib 的默认配色），真实世界的图表是扫描件、是手绘、是 PPT 截图。
> **在合成数据上刷高的分，不一定迁移到真实场景。**

## 7.5 多模态特有的清洗动作

| 动作 | 干什么 | ⚠️ 坑 |
|---|---|---|
| **CLIP 分数过滤** | 用 CLIP 算图文相似度，扔掉不匹配的对 | ★ 会**系统性偏爱 CLIP 自己已经懂的东西**，把新概念一起扔掉 |
| **图像去重** | 感知哈希（pHash）找近似重复图 | 网上同一张图有几万个变体（水印、裁剪、压缩） |
| **★ 去污染** | 把评测集里的图从训练数据剔除 | ★★ 比文本去污染**难得多**——同一张图裁一刀、加个水印，字符串匹配就失效了 |
| **NSFW / 人脸 / 隐私** | 过滤不良内容、模糊人脸、去水印 | 法规要求；也影响能力（过滤太狠，模型认不出人） |
| **中文 / 多语 OCR 平衡** | 保证非英语文字的覆盖 | 英文 OCR 数据远多于其他语种 |

> ★★ **"CLIP 分数过滤"这一条的坑值得想一遍，因为它是个循环**：你用 CLIP 筛数据，筛出来的数据去训下一代视觉塔。⟹ **凡是当前 CLIP 看不懂的概念（新出现的物体、冷门领域的图示、非英语的文字），图文分数都低，都会被扔掉。** ⟹ 🔑 **下一代模型于是继续看不懂它们**。⚠️ 这是一个**自我强化的盲区**，而且它不会体现在任何一个指标上——因为你的评测集也是从同一个分布里采的。

> ★★ **图像去污染这条值得多说一句**：
> 一张 MMMU 测试图，**换个 JPEG 压缩率、裁掉 5 个像素，哈希就完全不同**，
> 但模型看到的内容几乎一样。⟹ **多模态榜单的污染风险，客观上比文本榜单更高、更难查。**
> ⟹ 这一条会在 [11 章](11-多模态评测.md) 再出现一次，也可对照
> [../harness评测框架/评测入门/06-数据污染.md](../harness评测框架/评测入门/06-数据污染.md)。

## 7.6 数据量级速记，以及"token"这个词的陷阱

```
视觉塔预训练（CLIP 类）    几亿 ~ 几十亿 图文对
多模态继续预训练           几百 B ~ 几十 T token（✅ GLM-5.3-Flash：30T 多模态语料）
多模态 SFT                 几十万 ~ 几百万条
多模态 RL / 偏好            几万 ~ 几十万条 prompt
```

### ⚠️ 先把三个单位分清：像素 ≠ patch ≠ token

**这三个词在多模态语境里被混用得非常厉害**，而它们之间差着两个数量级。拿全书的那张跑例图（1092×1092，patch 14，2×2 合并）：

| 单位 | 这张图有多少个 | 换算关系 | 它是什么 |
|---|---|---|---|
| **像素** | 1092 × 1092 = **1,192,464** 个<br>（× 3 通道 = 3,577,392 个数） | — | 原始输入，模型从不直接按这个计数 |
| **patch**（小块） | (1092/14)² = 78² = **6,084** 个 | 1 个 patch = 14 × 14 = **196 个像素** | 视觉塔内部的序列长度，★ **注意力开销按这个算** |
| **视觉 token** | 6084 / 4 = **1,521** 个 | 1 个视觉 token = **4 个 patch** = **784 个像素** | 进入 LLM 的序列长度，★ **计费和上下文窗口按这个算** |

```
⟹ 同一张图，三种口径的数相差：1,192,464 : 6,084 : 1,521 ≈ 784 : 4 : 1
⟹ ⚠️ 所以"一张图多少 token"这句话，必须先问"合并前还是合并后"——答案差 4 倍。
```

### ⚠️ 于是"30T 多模态 token"这个数不可考

```
三种可能的口径，各自对应多少张图（假设其中有 10T 是图像贡献的）：

  口径 A  图完全不计入 token 数，30T 全是文字
          ⟹ 那这个数和纯文本模型的 30T 可以直接比
  口径 B  图按【视觉 token】计（1521 / 张）
          ⟹ 10T ÷ 1521 ≈ 66 亿张图
  口径 C  图按【patch】计（6084 / 张，2×2 合并之前）
          ⟹ 10T ÷ 6084 ≈ 16 亿张图

⟹ ★ 口径 B 和 C 对应的图片张数差【正好 4 倍】——就是 2×2 合并那一步。
⟹ ⚠️ 报告一般不说用的是哪个口径。
```

> ★ **再做一次量级自检，看看口径 B 合不合理**：66 亿张图，按 JPEG 平均 200 KB 一张算，**原始图片就是 1.3 PB 的存储**（66×10⁸ × 200 KB ≈ 1.3×10⁹ MB）。这个量级对大厂是可行的、对中小团队是不可能的。⟹ 🔑 **所以"30T 多模态语料"这个数字，本身就是一张入场券的价目表。**
> ⚠️ **这一段的 1.3 PB 是本文按假设推的，不是任何报告披露的数字**，只能用来判断量级合不合理，不能当成 GLM-5.3 的真实存储规模。

> 🔑 **看到多模态的"XX T token"，先问这三个问题**：
> ① 图像 token 算不算进这个数？
> ② 算的话是按合并前的 patch 还是合并后的视觉 token？
> ③ 同一张图被反复看（多分辨率、多轮训练）时算一次还是算多次？
>
> ⚠️ **三个问题都答不上来的"XX T token"，不要跨模型比较。**

## 7.7 🔑 这一章的六句话

1. 六个数据家族里，**交错图文文档（②）才是阶段二的主粮**，图文对（①）主要喂视觉塔和阶段一对齐——⚠️ **"多模态预训练就是拿几十亿图文对去训"是最常见的误解**。
2. **网上的 alt-text 基本是垃圾**，合成 caption 是 2023 年后最大的数据进步之一。✅ DALL·E 3 的公开配方是 **95% 合成 + 5% 原始**，留那 5% 是为了防止过拟合到合成句式。
3. ★★ **原始 alt-text 的问题是"没有信息"（噪声，会被平均掉），合成 caption 的问题是"有错误的信息"（偏置，会被继承放大）。** 这个区分是本章最重要的一句。
4. ★★ **多模态有一张纯文本没有的王牌：渲染合成**。它和合成 caption 的根本差别是**"程序当标注员"而不是"模型当标注员"**，所以标注不可能错。✅ GLM-5.3 的视觉编程数据就是这么造的。
5. ⚠️ **CLIP 分数过滤是一个自我强化的盲区**，当前模型看不懂的概念会被系统性扔掉；**图像去污染又比文本难得多**，裁一刀哈希就变了。
6. ⚠️ **像素 : patch : 视觉 token ≈ 784 : 4 : 1**，"30T 多模态 token"按哪个口径算，对应的图片张数差 4 倍。**这类数字不要跨模型比较。**
