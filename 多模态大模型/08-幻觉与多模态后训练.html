08 · ⭐ 幻觉与多模态后训练：落地路上最大的一堵墙

📖 前置：本章大量借用纯文本后训练的概念，它们的全称是：
SFT（Supervised Fine-Tuning，监督微调）、RL（Reinforcement Learning，强化学习）、
DPO（Direct Preference Optimization，直接偏好优化）、
RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励强化学习）、
GRPO（Group Relative Policy Optimization，组相对策略优化）。
这些机制本身不在本章重复——它们有一个专门的目录：../后训练/，
先扫一眼 ../后训练/README.md 的那张地图。本章只讲多模态特有的部分。

8.1 先看它错成什么样

[一张只有一只猫的照片]
问：图里的狗是什么品种？
答：⚠️ "这是一只金毛寻回犬，毛色偏浅……"    ← ★ 图里根本没有狗

[一张手写的 "3 + 5 = 9"]
问：这个算式对吗？
答：⚠️ "对的，3 + 5 = 8。"    ← ★ 它把 9 看成了 8，还顺手确认了"对"

[一张会议室照片]
问：桌上有几台笔记本电脑？
答：⚠️ "三台。"（实际是两台）

📖 多模态幻觉：模型给出的描述在图里没有依据。

★ 五类幻觉：例子、机制、缓解、能不能程序化判错

类别 一个具体例子 ★ 为什么会这样 主要缓解手段 能不能程序化判错
① 物体幻觉
说出不存在的东西		 只有一只猫的照片，问"图里的狗是什么品种" → "金毛寻回犬" 问题预设了"有狗"，而训练数据里几乎没有"图里没有 X"这种句子 ⟹ 模型没学过否认（yes 偏置，8.3 节③） 造负样本教它说"没有"；把对抗式问法放进训练集 ★★ 能——拿物体标注比一下就行
② 属性幻觉
颜色 / 材质 / 状态说错		 一辆白色的车 → "这辆红色的车很醒目" 属性和物体在语言里强共现（"消防车—红色"）；而属性这类细节正是视觉编码为了语义而压掉的（09 章 9.6 节） 反事实对（同一张图，只改一处属性）；提高有效分辨率 ★ 能，前提是标注里有属性字段
③ 关系幻觉
左右 / 上下 / 包含说反		 杯子在书的左边 → "杯子在书的右边" ★ 对比学习不惩罚词序错乱（02 章）⟹ 视觉塔特征里的空间关系本来就弱；位置编码是唯一的来源（05 章） grounding（输出坐标）——把关系变成可算的数值；交错数据 ★ 能——拿两个框的坐标直接比大小
④ 数量幻觉
数目说错		 桌上两台笔记本 → "三台" 数数需要"逐个遍历并计数"这种串行操作，一次前向里没有这个机制；注意力是并行加权求和，天生不擅长计数 先逐个 grounding 再数；用渲染合成造"已知数量"的数据（07 章 7.4 节） ★★ 能——数字相等判断，最干净的一类
⑤ OCR 幻觉
把不认识的字"脑补"成常见词		 手写 3 + 5 = 9 → 读成 3 + 5 = 8 ★★ 最危险的一类：语言先验（"3+5 应该等于 8"）直接覆盖了视觉证据。字越小、越模糊，先验的权重越大 分辨率拉满（04 章）；OCR 专项数据；⚠️ 这一类目前压不干净 ⚠️ 评测集里能判（和真值串比），但生产环境里没有真值可比——见 8.7 节

⚠️ 这五类不互斥：一句"图中三辆红色轿车停在楼的左侧"可以同时犯②③④。做评测时按最严格的那一类计。
★ 按落地危害排序，不是按发生频率排序：⑤ > ④ > ③ > ② > ①。① 最容易被发现（你一眼就看出图里没狗），⑤ 最难被发现（数字看起来完全合理）。

8.2 ★★ 多模态幻觉和纯文本幻觉的根本差别：它可以被客观判错

这是本章最值得先建立的一个直觉，因为后面所有能上 RL 的路线都建立在它上面。

纯文本幻觉 多模态幻觉
典型例子 "爱因斯坦 1952 年获诺贝尔化学奖" "图里的狗是金毛寻回犬"
真值在哪里 ★ 在模型外面的世界里 ★★ 就在输入里——图是跟问题一起交上来的
判错需要什么 外部检索 + 一个会判断的裁判（常常只能是人，或一个更强的模型） 这张图的物体 / 属性 / 坐标标注，一次字符串或数值比较
判错的成本 高、慢 ★ 低、快、可程序化批量跑
判错的客观性 ⚠️ "这句话到底算不算幻觉"经常要讨论（口径、时效、模糊表述） ★★ "图里没有狗"是一个客观事实，不需要讨论
能不能做可验证奖励 难——这正是纯文本 RL 只能靠数学题和单元测试起步的原因 ★ 能——这是 8.5 节那几条奖励来源的全部基础
⚠️ 可测的边界 — 只有"存在 / 数量 / 位置 / 属性"这类客观项能测；"这张图的氛围如何""这个设计好不好看"测不了

🔑 一句话总结这张表：多模态幻觉比文本幻觉更容易犯（因为模态多了一道，8.3 节讲为什么），但同时更容易查（因为真值和问题一起交上来了）。 ⟹ ★ 这个"更容易查"是整个领域的一个杠杆：它让"幻觉"从一个需要人去评判的软指标，变成了一个能自动算分、能当奖励信号的硬指标。

⚠️ 别把这个杠杆用过头。能客观判错的只有画面里的客观属性。"图里有没有狗"可判；"这张图传达了一种孤独感"不可判。 ⟹ 后者才是语音和视频评测里真正难的部分（10 章 10.6 节②、11 章）。

8.3 ★★ 病根：语言先验压过了视觉证据

幻觉不是 bug，是训练目标的必然产物。

① 主干是个语言模型，它 99% 的参数是在【纯文本】上训出来的
   ⟹ 它对"什么话说出来像话"的先验，远强于对"图里有什么"的证据

② 训练数据里，"厨房"这个词后面高概率跟着"冰箱、水槽、微波炉"
   ⟹ 给它一张厨房照片，即使画面里没有微波炉，
     ★ 模型顺着语言概率往下滑，就把微波炉"说"出来了

③ ⚠️ 更要命的：训练数据【几乎从不说"图里没有什么"】
   所有的图片描述都在描述【存在的东西】
   ⟹ 模型从没学过"否认"这个动作
   ⟹ ★★ 这解释了那个著名的【yes 偏置】：
     问"图里有 X 吗"，不管有没有，模型都倾向答"有"

④ SFT 数据奖励【详细的长描述】
   ⟹ 模型学到"说得越细越像好答案" ⟹ 细节不够就编

⑤ ★ 还有一条训练侧的结构性原因（06 章 6.3 节那笔账）：
   视觉 token 占了序列的 95%，却【不产生任何 loss 项】
   ⟹ 监督信号全部来自文本位置
   ⟹ ⚠️ 换句话说：模型被明确训练去"说出像样的话"，
     而"说的话和图一致"只是前者的一个【副产品】，从来没有被单独奖励过

🔑 一句话：幻觉的本质是"模型在语言概率和视觉证据冲突时，选了语言"。
⟹ ⚠️ 所以那些"提高分辨率就能解决幻觉"的说法是错的——
看清了也可能编，因为问题出在它更信自己的语言直觉。
⟹ ★ 回头看 8.1 那张表的第 ⑤ 行：3 + 5 = 9 被读成 = 8，不是因为像素不够，是因为"3+5=8"这个先验太强。

8.4 四类缓解手段

手段① 数据侧：教模型说"没有"

★ 造【负样本】：
  图里没有狗 → 造一条 "问：有狗吗？ 答：没有，画面中只有一只猫。"
★ 造【反事实对】：
  同一张图，一个正确描述 + 一个只改了一处的错误描述

✅ 最直接、最有效，也最枯燥
⚠️ 副作用：造多了模型会【过度保守】，什么都说"看不清、不确定"
⟹ ★ 判断是不是造过头了，看 8.7 节那个指标：
  准确率不动、但"答否"的比例飙升，就是已经过头了

手段② 训练侧：用偏好对齐去压幻觉

造偏好对：  chosen = 无幻觉的描述
          rejected = 有幻觉的描述（可以【故意让模型不看图去生成】来批量造）
然后跑 DPO ⟹ 机制和纯文本完全一样
⟹ 见 ../后训练/04-偏好对齐-RLHF与DPO.md

★ 一个巧妙的造数据技巧：
  让模型【蒙着眼】（不给图）回答同一个问题
  ⟹ 它答出来的东西，必然全是语言先验 ⟹ 天然的 rejected 样本
  ⟹ 🔑 这个技巧的漂亮之处：它把 8.3 节的病因【直接做成了负样本的生成器】

手段③ 解码侧：对比解码

同一个问题跑两遍：
  logits_有图  −  α × logits_无图（或图被加噪）
  ⟹ 差值放大了【真正来自视觉的那部分证据】
  ⟹ 削弱纯语言先验

✅ 不用训练，推理时即插即用
⚠️ 推理成本 ×2，且 α 要调；生产上用得不多
⟹ ★ 注意这是【吞吐减半】，不是【延迟加倍】：两遍可以并发跑在同一个 batch 里，
  延迟只涨一点，但同样的卡只能服务一半的请求。⚠️ 这两件事别混（10 章 10.5 节会再展开）

手段④ ★★ Grounding：逼模型给出"证据坐标"

⚠️ 普通问法：  "图里有几个人？"  → "三个"   ← 无法核实
★ grounding：  "图里有几个人？请给出每个人的框"
               → "三个：[0.12,0.34,0.28,0.71] [0.55,...] [0.81,...]"
               ⟹ ★ 现在你可以【把框画回图上，一眼看出它是不是在编】

🔑 这是我认为最有价值的一条路线：
   它把幻觉从【不可验证】变成了【可验证】
   ⟹ 而"可验证"是能上 RL 的前提（下一节）
   ⟹ ★ 它同时治 8.1 表里的 ③ 关系 和 ④ 数量两类：
     关系变成"比较两个框的坐标"，数量变成"数有几个框"

📖 grounding（视觉定位）：让模型输出坐标框，把回答"锚"在画面的具体位置上。
坐标一般被归一化到 0~1 后当成普通文本 token 输出（比如直接写 [0.12,0.34,...]），
⟹ ⚠️ 所以它的精度受限于数字 token 的分词方式，这是一个真实存在的、很少被讨论的精度上限。

★ 把这个精度上限算一下：
  坐标写成两位小数（0.00 ~ 1.00）⟹ 只有 101 个可选值
  ⟹ 在一张 1092 像素宽的图上，一格 = 1092 / 100 ≈ 11 个像素
  ⟹ ✅ 框一只猫够用；⚠️ 框一个 8 像素宽的勾选框，不够

  写成三位小数 ⟹ 一格 ≈ 1.1 像素，精度够了
  ⟹ ⚠️ 但坐标字符串变长，一个框从 ~12 个 token 涨到 ~16 个
  ⟹ ★ 输出 50 个框时，这是 600 vs 800 个 token 的差别
⚠️ 以上是按"一个数字字符约一个 token"的粗口径估的，具体分词器会有出入。

8.5 ★ 多模态 RL：奖励从哪来

纯文本 RL 之所以在 2025 年爆发，是因为找到了可验证奖励（数学题对不对、单测过不过）。多模态的对应问题是：看图这件事，怎么自动判分？ ⟹ ★ 8.2 那张表已经给了答案的一半：真值就在输入里。

来源① 有唯一答案的多模态题
     多模态数学题、图表读数、OCR 精确匹配
     ✅ 直接复用 RLVR，见 ../后训练/05-RLVR-可验证奖励.md

来源② ★★ 渲染回环（render loop）—— 多模态独有
     让模型写前端代码 → 真的渲染出来 → 【把渲染结果截图给模型自己看】
     → 和目标图对比 → 差异就是奖励
     ✅ 一手证据：GLM-5.3 用【环境反馈的强化学习】做前端方向，
        并把验证范围 "beyond functional correctness to the rendered
        and interactive product"（从功能正确性扩展到渲染结果和可交互产物）
        官方演示是 "Initial Version with Layout Issues" →
        "After Visual Self-Verification" 的前后对比
        出处：../业界模型技术报告/GLM-5.3.md §六

来源③ GUI 任务成功率
     "在这个 App 里把飞机票退掉" → 环境返回成功/失败
     ⟹ ★ 这是标准的 Agentic RL，瓶颈在【环境】不在算法
     ⟹ 见 ../后训练/07-AgenticRL-环境成为瓶颈.md

来源④ 幻觉惩罚
     用一个检测器核对描述里的每个物体是否真的在图里 → 扣分
     ⚠️ 检测器本身会错 ⟹ 奖励噪声大 ⟹ 容易被【奖励攻击】
     ⟹ ★ 典型的攻击形态：模型学会【只说最保险的那几个物体】，
       描述变得又短又空，幻觉分数很高但一点用都没有
     ⟹ 见 ../后训练/06-奖励从哪来.md

四条来源的可靠度排一下：

奖励来源 真值从哪来 噪声 能不能规模化 ⚠️ 主要风险
① 唯一答案的题 人工或程序生成的标准答案 ★ 极低 受题库限制 只覆盖"有唯一答案"的任务
② 渲染回环 ★★ 程序渲染出来的真实结果 ★ 极低 ★★ 无上限（能渲染就能造） 只覆盖"能被渲染"的任务（前端、图表、文档）
③ GUI 成功率 环境返回的成功 / 失败 中（环境本身会抖） ⚠️ 受环境搭建速度限制 环境是瓶颈；一次 rollout 很慢很贵
④ 幻觉惩罚 ⚠️ 另一个模型（检测器）的判断 ⚠️ 高 高 ★★ 奖励攻击：学会"少说话"来骗分

★★ 来源②值得单独强调：它是多模态版的"单元测试"。
代码能被跑，界面能被渲染，渲染结果能被自己看 ⟹ 闭环成立 ⟹ 可以无限自我改进。
⟹ 🔑 这就是 GLM-5.3 那句"视觉需要原生集成进模型，让它自己决定何时去看"的真正分量（✅ 官方原话）：
视觉在这里不是一个输入模态，而是一个 agent 的"传感器 + 验证器"。
⟹ ★ 注意它和 ④ 的区别：② 的真值是程序算出来的，④ 的真值是另一个模型猜出来的——这正是 07 章 7.4 节"程序当标注员 vs 模型当标注员"那个区分，在奖励侧的翻版。

8.6 多模态长思维链：先看，再想，再看一眼

纯文本的推理模型会写很长的思考过程。搬到多模态上，出现了一个新动作：回头再看。

⚠️ 传统流程（一次性）：
   图 → 一次编码 → 全程只能靠这一次编码的记忆去推理
   ⟹ 图里那行小字如果第一次没看清，后面想破头也没用

★ agentic 视觉（2025~2026 的方向）：
   图 → 想 → "我需要看清右下角" → 【调工具裁剪+放大】→ 再编码 → 接着想
   ⟹ ★★ 把"看"变成一个【可以重复调用的动作】，而不是一次性的输入
   ⟹ 这和纯文本 agent 调用搜索工具是同一个结构

★ 为什么这条路在 token 账上是赚的（04 章口径：patch 14 + 2×2 合并）：
  做法 A  把整张 2184×2184 的图一次拉满
          (2184/14)² = 24336 patch → 6084 视觉 token
  做法 B  先看 1092×1092 的缩略图，再把右下角那块裁出来按原分辨率看
          缩略图 (1092/14)² / 4 = 1521 token
          + 裁出来的 546×546 一块  (546/14)² / 4 = 380 token
          合计 1901 token
  ⟹ ★ 1901 vs 6084，省了约 69% 的视觉 token，而要看的那行小字分辨率一样
  ⟹ ⚠️ 代价：多了一轮编码 + 一轮生成，【延迟变长】。
    省的是 token（钱和吞吐），付的是往返次数（延迟）——又是一次延迟换吞吐的交换。

🔑 这可能是理解型多模态未来两年最重要的一条线：
从"把图喂给模型"变成"让模型自己决定看哪、看几次"。
⚠️ 这是我的判断，上面那笔 token 账也是我按通用口径算的，不是某篇论文报告的结果。
可以对照的一手材料是 GLM-5.3 那句
"enabling it to decide when to observe and use visual feedback to guide subsequent actions" ✅——
官方说的是"何时去看"，和这里说的"看哪里"是同一个思想的两个面。

8.7 ⚠️ 一个必须说的坏消息

幻觉【没有被解决】，只是被压到了"日常使用中不太容易撞见"的水平。

· 榜单上的幻觉指标已经刷得很高
· 但那些榜单问的是"图里有没有 X"这类【简单存在性】问题
· 真实场景里的幻觉是：★ 把发票金额看错一位、把合同条款的否定词漏掉

⟹ ⚠️ 而这类错误的共同特征是：【它看起来完全合理】
   —— 你不逐字核对，根本发现不了

★ 算一笔账：为什么"幻觉榜单分数很高"这句话本身没有信息量

POPE（Polling-based Object Probing Evaluation，轮询式物体探测评测，arXiv 2305.10355）是最常被引用的幻觉榜单。它的构造是：拿图的物体标注，问一批 Is there a {物体} in the image?，答案设计成 yes / no 各一半。

设一共 500 道题，250 道真答案是 yes、250 道是 no。现在考虑一个完全不看图、一律答 yes 的"模型"：

指标 算式 结果
真正例 TP 答 yes 且真有 250
假正例 FP 答 yes 但没有 250
假负例 FN 答 no 但真有 0
准确率 Accuracy (250 + 0) / 500 50.0%
精确率 Precision 250 / (250 + 250) 50.0%
召回率 Recall 250 / (250 + 0) 100%
F1 2 × 0.50 × 1.00 / (0.50 + 1.00) ★★ 66.7% 
⟹ ★★ 一个【完全盲的】模型，F1 就能拿到 66.7%。
⟹ ⚠️ 所以看到"POPE F1 = 72"这种数字，先在脑子里减掉 66.7 —— 剩下的才是视觉带来的部分。
⟹ 🔑 真正要看的两个数：
   ① 【答 yes 的比例】—— 远超 50% 就是在猜（POPE 论文自己就报这一项）
   ② 【Precision 和 Recall 的不对称】
      Recall 高、Precision 低  ⟹ yes 偏置（在编）
      Recall 低、Precision 高  ⟹ 过度保守（8.4 节手段①造过头了）

★ POPE 的采样设计本身就是针对 8.3 节②那条病因的：它的 adversarial 一档专门挑"和图中物体共现频率最高、但图里确实没有"的物体来问——比如给一张厨房照片，就问"有微波炉吗"。⟹ 🔑 这一档的分数才是在直接测"语言先验压不压得住"，random 一档几乎没有区分度。

🔑 给使用者的一条硬建议：
凡是"从图里读出一个数字 / 名字 / 条款"并且这个值会被下游用掉的场景，
都必须有人工或程序复核。 这不是保守，这是当前技术水平的客观边界。
⟹ ★ 理由就是 8.1 那张表的最后一列：⑤ OCR 幻觉在评测集里能判错，在生产里没有真值可比。

8.8 🔑 这一章的六句话

  1. 五类幻觉（物体 / 属性 / 关系 / 数量 / OCR）里，危害排序和发生频率排序是相反的：物体幻觉最容易被一眼看破，OCR 幻觉最难——因为看错的那个数字看起来完全合理。
  2. ★★ 多模态幻觉比文本幻觉更容易犯，但更容易查——因为真值和问题一起交上来了。"图里没有狗"是客观事实，不需要讨论。这个"可客观判错"是本领域所有自动奖励的基础。
  3. 病根是"语言先验压过视觉证据"，不是"看不清"。提高分辨率解决不了它。⚠️ 训练数据里几乎没有"图里没有 X"这样的句子 ⟹ 模型没学过否认 ⟹ 著名的 yes 偏置。
  4. 四类手段里，grounding（输出坐标）最有价值——它把关系幻觉变成"比坐标"、数量幻觉变成"数框"。⚠️ 它的精度上限受坐标的小数位数限制：两位小数在 1092 像素宽的图上一格 11 个像素。
  5. ★★ 多模态 RL 最有前途的奖励来源是"渲染回环"：写代码 → 渲染 → 自己看 → 对比。✅ GLM-5.3 已经这么做了。⚠️ 而"用检测器扣幻觉分"噪声最大，典型攻击是学会少说话来骗分。
  6. ⚠️ 幻觉没有被解决。一个完全不看图、一律答 yes 的模型在 POPE 上 F1 就有 66.7%——幻觉榜单的高分里有一大截是白送的。读数字的场景必须复核。
