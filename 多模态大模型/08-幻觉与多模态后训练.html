08 · ⭐ 幻觉与多模态后训练：落地路上最大的一堵墙

📖 前置：本章大量借用纯文本后训练的概念（SFT / DPO / RLVR / GRPO）。
不熟的话先扫一眼 ../后训练/README.md 的那张地图，这里只讲多模态特有的部分。

8.1 先看它错成什么样

    [一张只有一只猫的照片]
    问：图里的狗是什么品种？
    答：⚠️ "这是一只金毛寻回犬，毛色偏浅……"    ← ★ 图里根本没有狗

    [一张手写的 "3 + 5 = 8"]
    问：这个算式对吗？
    答：⚠️ "对的，3 + 5 = 8。"（图里其实写的是 3 + 5 = 9）

    [一张会议室照片]
    问：桌上有几台笔记本电脑？
    答：⚠️ "三台。"（实际是两台）

📖 多模态幻觉：模型给出的描述在图里没有依据。常见四类：
物体幻觉（说了不存在的东西）、属性幻觉（颜色/数量说错）、
关系幻觉（左右、上下、包含关系说反）、OCR 幻觉（把不认识的字"脑补"成常见词）。

8.2 ★★ 病根：语言先验压过了视觉证据

这是本章最重要的一段。幻觉不是 bug，是训练目标的必然产物。

    ① 主干是个语言模型，它 99% 的参数是在【纯文本】上训出来的
       ⟹ 它对"什么话说出来像话"的先验，远强于对"图里有什么"的证据

    ② 训练数据里，"厨房"这个词后面高概率跟着"冰箱、水槽、微波炉"
       ⟹ 给它一张厨房照片，即使画面里没有微波炉，
         ★ 模型顺着语言概率往下滑，就把微波炉"说"出来了

    ③ ⚠️ 更要命的：训练数据【几乎从不说"图里没有什么"】
       所有的图片描述都在描述【存在的东西】
       ⟹ 模型从没学过"否认"这个动作
       ⟹ ★★ 这解释了那个著名的【yes 偏置】：
         问"图里有 X 吗"，不管有没有，模型都倾向答"有"

    ④ SFT 数据奖励【详细的长描述】
       ⟹ 模型学到"说得越细越像好答案" ⟹ 细节不够就编

🔑 一句话：幻觉的本质是"模型在语言概率和视觉证据冲突时，选了语言"。
⟹ ⚠️ 所以那些"提高分辨率就能解决幻觉"的说法是错的——
看清了也可能编，因为问题出在它更信自己的语言直觉。

8.3 四类缓解手段

手段① 数据侧：教模型说"没有"

    ★ 造【负样本】：
      图里没有狗 → 造一条 "问：有狗吗？ 答：没有，画面中只有一只猫。"
    ★ 造【反事实对】：
      同一张图，一个正确描述 + 一个只改了一处的错误描述

    ✅ 最直接、最有效，也最枯燥
    ⚠️ 副作用：造多了模型会【过度保守】，什么都说"看不清、不确定"

手段② 训练侧：用偏好对齐去压幻觉

    造偏好对：  chosen = 无幻觉的描述
              rejected = 有幻觉的描述（可以【故意让模型不看图去生成】来批量造）
    然后跑 DPO ⟹ 机制和纯文本完全一样
    ⟹ 见 ../后训练/04-偏好对齐-RLHF与DPO.md

    ★ 一个巧妙的造数据技巧：
      让模型【蒙着眼】（不给图）回答同一个问题
      ⟹ 它答出来的东西，必然全是语言先验 ⟹ 天然的 rejected 样本

手段③ 解码侧：对比解码

    同一个问题跑两遍：
      logits_有图  −  α × logits_无图（或图被加噪）
      ⟹ 差值放大了【真正来自视觉的那部分证据】
      ⟹ 削弱纯语言先验

    ✅ 不用训练，推理时即插即用
    ⚠️ 推理成本 ×2，且 α 要调；生产上用得不多

手段④ ★★ Grounding：逼模型给出"证据坐标"

    ⚠️ 普通问法：  "图里有几个人？"  → "三个"   ← 无法核实
    ★ grounding：  "图里有几个人？请给出每个人的框"
                   → "三个：[0.12,0.34,0.28,0.71] [0.55,...] [0.81,...]"
                   ⟹ ★ 现在你可以【把框画回图上，一眼看出它是不是在编】

    🔑 这是我认为最有价值的一条路线：
       它把幻觉从【不可验证】变成了【可验证】
       ⟹ 而"可验证"是能上 RL 的前提（下一节）

📖 grounding（视觉定位）：让模型输出坐标框，把回答"锚"在画面的具体位置上。
坐标一般被归一化到 0~1 后当成普通文本 token 输出（比如直接写 [0.12,0.34,...]），
⟹ ⚠️ 所以它的精度受限于数字 token 的分词方式，这是一个真实存在的、很少被讨论的精度上限。

8.4 ★ 多模态 RL：奖励从哪来

纯文本 RL 之所以在 2025 年爆发，是因为找到了可验证奖励（数学题对不对、单测过不过）。
多模态的对应问题是：看图这件事，怎么自动判分？

 来源① 有唯一答案的多模态题
      多模态数学题、图表读数、OCR 精确匹配
      ✅ 直接复用 RLVR，见 ../后训练/05-RLVR-可验证奖励.md

 来源② ★★ 渲染回环（render loop）—— 多模态独有
      让模型写前端代码 → 真的渲染出来 → 【把渲染结果截图给模型自己看】
      → 和目标图对比 → 差异就是奖励
      ✅ 一手证据：GLM-5.3 用【环境反馈的强化学习】做前端方向，
         并把验证范围 "beyond functional correctness to the rendered
         and interactive product"（从功能正确性扩展到渲染结果和可交互产物）
         官方演示是 "Initial Version with Layout Issues" →
         "After Visual Self-Verification" 的前后对比
         出处：../业界模型技术报告/GLM-5.3.md §六

 来源③ GUI 任务成功率
      "在这个 App 里把飞机票退掉" → 环境返回成功/失败
      ⟹ ★ 这是标准的 Agentic RL，瓶颈在【环境】不在算法
      ⟹ 见 ../后训练/07-AgenticRL-环境成为瓶颈.md

 来源④ 幻觉惩罚
      用一个检测器核对描述里的每个物体是否真的在图里 → 扣分
      ⚠️ 检测器本身会错 ⟹ 奖励噪声大 ⟹ 容易被【奖励攻击】
      ⟹ 见 ../后训练/06-奖励从哪来.md

★★ 来源②值得单独强调：它是多模态版的"单元测试"。
代码能被跑，界面能被渲染，渲染结果能被自己看 ⟹ 闭环成立 ⟹ 可以无限自我改进。
⟹ 🔑 这就是 GLM-5.3 那句"视觉需要原生集成进模型，让它自己决定何时去看"的真正分量（✅ 官方原话）：
视觉在这里不是一个输入模态，而是一个 agent 的"传感器 + 验证器"。

8.5 多模态长思维链：先看，再想，再看一眼

纯文本的推理模型会写很长的思考过程。搬到多模态上，出现了一个新动作：回头再看。

    ⚠️ 传统流程（一次性）：
       图 → 一次编码 → 全程只能靠这一次编码的记忆去推理
       ⟹ 图里那行小字如果第一次没看清，后面想破头也没用

    ★ agentic 视觉（2025~2026 的方向）：
       图 → 想 → "我需要看清右下角" → 【调工具裁剪+放大】→ 再编码 → 接着想
       ⟹ ★★ 把"看"变成一个【可以重复调用的动作】，而不是一次性的输入
       ⟹ 这和纯文本 agent 调用搜索工具是同一个结构

🔑 这可能是理解型多模态未来两年最重要的一条线：
从"把图喂给模型"变成"让模型自己决定看哪、看几次"。
⚠️ 这是我的判断。可以对照的一手材料是 GLM-5.3 那句
"enabling it to decide when to observe and use visual feedback to guide subsequent actions" ✅——
官方说的是"何时去看"，和这里说的"看哪里"是同一个思想的两个面。

8.6 ⚠️ 一个必须说的坏消息

    幻觉【没有被解决】，只是被压到了"日常使用中不太容易撞见"的水平。

    · 榜单上的幻觉指标（POPE 等）已经刷得很高
    · 但那些榜单问的是"图里有没有 X"这类【简单存在性】问题
    · 真实场景里的幻觉是：★ 把发票金额看错一位、把合同条款的否定词漏掉

    ⟹ ⚠️ 而这类错误的共同特征是：【它看起来完全合理】
       —— 你不逐字核对，根本发现不了

🔑 给使用者的一条硬建议：
凡是"从图里读出一个数字/名字/条款"并且这个值会被下游用掉的场景，
都必须有人工或程序复核。 这不是保守，这是当前技术水平的客观边界。

8.7 🔑 这一章的五句话

  1. 多模态幻觉的病根是"语言先验压过视觉证据"，不是"看不清"。提高分辨率解决不了它。
  2. 训练数据里几乎没有"图里没有 X"这样的句子 ⟹ 模型没学过否认 ⟹ 著名的 yes 偏置。
  3. 四类手段里，grounding（输出坐标）最有价值——它把幻觉从不可验证变成可验证。
  4. ★★ 多模态 RL 最有前途的奖励来源是"渲染回环"：写代码→渲染→自己看→对比。✅ GLM-5.3 已经这么做了。
  5. ⚠️ 幻觉没有被解决，只是被压到了不容易撞见的水平。读数字的场景必须复核。
