# 11 · ⭐ 多模态评测：这个领域最缺的是尺子

> 📖 **前置**：评测的通用方法论（few-shot、答案抽取、污染、LLM 当裁判）在
> [../harness评测框架/评测入门/](../harness评测框架/评测入门/)。**本章只讲多模态特有的坑。**
> ⚠️ **先给结论**：**多模态分数目前几乎无法跨模型比较。** 这不是我的偏见，下面有一手实证。

---

## 11.1 榜单家族速览

| 类别 | 代表 | 测什么 |
|---|---|---|
| 综合学科 | **MMMU**（arXiv 2311.16502）、MMMU-Pro | 大学水平的多学科图文题 ← ★ 最常被拿来当门面 |
| 综合能力 | MMBench、MM-Vet、SEED-Bench | 感知 + 推理的细分能力矩阵 |
| 数学与图表 | **MathVista**（2310.02255）、ChartQA | 看图算题、读折线图 |
| 文档 / OCR | DocVQA、OCRBench、**OmniDocBench** | 读票据、论文、表格 |
| 幻觉 | **POPE**（2305.10355）、HallusionBench | ★ 图里有没有 X（存在性） |
| 细粒度视觉 | BLINK、V* 类 | ★ 专挑 CLIP 看不出差别的图 |
| 视频 | **Video-MME**（2405.21075）、MVBench、MMVU | 长短视频理解 |
| GUI / agent | ScreenSpot、OSWorld 类 | 看屏幕、点对位置 |
| 生成 | GenEval 等 | 生成图和提示词符不符 |

## 11.2 ★★ 陷阱①：一半的题不看图也能做对

**这是多模态评测最严重、也最容易被忽略的问题。**

```
    题目： "图中这位穿白大褂的人最可能的职业是？
            A. 医生  B. 宇航员  C. 消防员  D. 厨师"

    ⚠️ 一个【纯文本模型】、【完全不给图】，也能答对
    ⟹ 因为常识 + 题干 + 选项的分布，本身就泄露了答案
```

> 🔑 **所以任何一份多模态评测报告，都应该给出【盲测基线】**：
> **把图去掉、只给文字，同一个模型能得多少分？**
> ⟹ ⚠️ **绝大多数榜单和技术报告不给这个数。**
> ⟹ **不给盲测基线的多模态分数，你无法知道其中有多少是"看图"挣来的。**

**推论**：模型 A 比模型 B 高 3 分，可能只是因为 **A 的语言能力更强**，和视觉毫无关系。

## 11.3 陷阱②：选择题的老毛病，在这里更严重

```
    · 选项顺序偏置：把正确答案挪到 D，分数会变
    · "四选一"猜也有 25 分 ⟹ 60 分和 70 分的差距，比看起来小
    · 答案抽取：模型答"应该是医生吧" ⟹ 正则没匹配到 "A" ⟹ 判错
      ⟹ ★ 这一条在多模态里更常见，因为多模态模型的指令遵循普遍弱一截
```

> ⟹ 通用机制见 [../harness评测框架/评测入门/05-答案抽取与打分.md](../harness评测框架/评测入门/05-答案抽取与打分.md)。

## 11.4 ★ 陷阱③：同一个模型，两次评测能差很多分

**因为多模态评测有一堆"你不说我不知道"的口径**：

```
    ① 分辨率给了多少？   ✅ 04 章那张表：576 token vs 2637 token，是两个模型
    ② 视频抽了几帧？     ✅ GLM-5.3 报告披露的口径是【1 fps，超限均匀采样】，
                          但别家可能是"固定 8 帧""固定 64 帧"
    ③ 图放在 prompt 的哪个位置？前面还是后面？
    ④ 用了什么提示词模板？CoT 提示给不给？
    ⑤ 单图还是允许多次"看"（8.5 节的 agentic 视觉）？

    ⟹ ⚠️ 这五项任何一项不同，分数都能差好几个点
    ⟹ ⟹ 🔑 而技术报告里【几乎从不完整披露这五项】
```

## 11.5 ★★ 陷阱④：本仓库的一手实证——各家根本没在同一把尺子上

这一节不是推断，是本仓库已核对的事实：

> ✅ **五份 2026 年一手报告的多模态评测口径**（出处
> [../业界模型技术报告/模型技术对比.md](../业界模型技术报告/模型技术对比.md)）：
>
> | 模型 | 用的视觉 benchmark |
> |---|---|
> | **Kimi K3** | OmniDocBench / Video-MME / PerceptionBench |
> | **MiniMax M3** | MMMU_Pro 78.1 / Video-MME-v2 85.4 / claw-eval |
> | **GLM-5.3** | BabyVision / Treasury Bulletin PDF / MVBench / MMVU |
> | DeepSeek-V4 | —（纯文本） |
> | openPangu-2.0-Pro | —（纯文本，报告明说只评非多模态子集） |
>
> ✅ **原文结论**：*"K3 和 M3 之间**零个共享的视觉 benchmark**……
> **多模态这一维目前完全无法横向比较**。"*

```
    ⚠️ 注意 K3 和 M3 都测了"Video-MME"，看起来像共享的 ——
       但 M3 测的是 【Video-MME-v2】，是不同版本的题
    ⟹ ★★ 这正是多模态评测的典型状态：连"看起来一样"的都不一样
```

> 🔑 **对比一下纯文本**：五家至少都测 MMLU-Pro、GPQA、AIME、SWE-bench、LiveCodeBench，
> 有一张**互相可桥接的网**（见 [模型技术对比](../业界模型技术报告/模型技术对比.md) §5）。
> **多模态这张网根本不存在。**
> ⟹ ⚠️ 我的判断：**这不完全是技术问题，也是选择问题**——
> **每家都倾向于报告自己强的那几个 benchmark，而多模态的 benchmark 足够多，
> 多到人人都能找到自己赢的那几个。**

## 11.6 陷阱⑤：图像污染查不出来

已经在 [07 章 7.5 节](07-多模态数据.md)说过，这里再强调一次它对榜单的后果：

```
    文本污染：字符串/n-gram 匹配，能查出个八九不离十
    图像污染：★ 同一张图【重新压缩一次】，哈希就完全不同，
              但模型看到的内容一模一样

    ⟹ ⚠️ 意味着：多模态榜单的分数【被污染的概率更高，而且更难自证清白】
    ⟹ 通用背景见 ../harness评测框架/评测入门/06-数据污染.md
```

---

## 11.7 ★ 那怎么办：自己评的五条实操建议

```
 ① 必做盲测基线
    同一套题，把图去掉跑一遍。⟹ 差值才是【视觉真正贡献的分数】
    ★ 这一条只要做了，你的评测就比大多数技术报告严谨。

 ② 对齐口径再比较
    比两个模型时，把分辨率上限、抽帧策略、prompt 模板【显式对齐】，
    并把这些参数写进结果表。

 ③ 加扰动测稳健性
    同一张图：旋转 90°、加噪、改亮度、换 JPEG 质量 ⟹ 答案变不变？
    ★ 一个稳健的模型不该因为压缩率变了就改口。

 ④ 自己造一小份【私有】测试集
    用你自己业务里的真实图（发票、工单截图、监控画面），100 张就够。
    ★★ 它有两个不可替代的价值：没被污染 + 分布贴合你的场景。
    ⟹ 造法参考 ../harness评测框架/评测入门/12-自己搭一套评测.md

 ⑤ 人工抽查，而且要【逐字核对数字】
    ⟹ 8.6 节的结论：多模态最危险的错是"看起来完全合理的错"，
       只看总分永远发现不了。
```

---

## 11.8 🔑 这一章的五句话

1. **多模态榜单最大的问题是"不看图也能答对"** ⟹ **没有盲测基线的分数是不可解释的。**
2. **分辨率、抽帧数、prompt 模板任何一项不同，分数就差几个点**，而报告几乎从不完整披露。
3. ✅ **一手实证：K3 和 M3 之间零个共享的视觉 benchmark** ⟹ **2026 年的多模态分数客观上无法横向比较。**
4. ⚠️ **图像污染比文本污染更难查**，重压一次哈希就变了。
5. **自己评的四件事：盲测基线、对齐口径、加扰动、造一份私有小测试集。** 做到第一条你就赢过多数报告了。
