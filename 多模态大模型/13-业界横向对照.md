## 13.2 ★ 从这张表能读出的四件事

### ① 五家里三家做，两家不做——而不做的两家都是推理/代码导向

```
    做了：K3、M3、GLM-5.3-Flash
    没做：DeepSeek-V4（招牌是 Codeforces 3206 / LiveCodeBench 93.5 的算法竞赛）
          openPangu-2.0-Pro（报告明说 Claw-Eval 只评非多模态子集）

    ⟹ ⚠️ 我的读法：【多模态尚未被证明能提升纯文本智能】。
       它是产品维度的扩张，不是能力维度的必需品。
       ⟹ 如果多模态能提升推理，V4 这种把宝全押在推理上的模型没有理由不做。
```

### ② 三家的视觉塔"形状"高度趋同

```
    patch 14：K3 ✅、M3 ✅   （两家都是 14）
    2×2 合并：K3 ✅、M3 ✅   （两家都做）
    27~32 层的中等 ViT：K3 27 层、M3 32 层

    ⟹ 🔑 ★ 架构层面【已经收敛】了。这不是巧合，是 SigLIP-SO400M 那套配置
       （27 层 / patch 14 / 400M）成了事实标准之后的行业惯性。
    ⟹ ⟹ 也意味着：★★ 差距不在架构，在【数据和训练】。
```

### ③ 只有 GLM-5.3 认真回答了"为什么"

其它几家都在讲**怎么做**，只有 GLM 讲了**为什么值得做**，而且论证是产品级的：

> ✅ *"For tasks such as frontend development, game development, and 3D simulation,
> the final output is not code alone, but an interface, an interaction, or a world
> experienced by the user. **Many failures only surface through rendering, interaction,
> or playtesting.**"*
>
> ✅ *"Vision therefore needs to be **natively integrated** into the model, enabling it
> to decide **when to observe** and use visual feedback to guide subsequent actions."*

```
    ⟹ 🔑 这个论证的关键在于：★★ 它把视觉从【一个输入模态】
       重新定义成了【agent 的验证器】。
    ⟹ 在这个框架下，"多模态能不能提升智能"这个问题被换掉了：
       ★ 视觉不是让模型更聪明，而是让模型【能看见自己干得对不对】。
    ⟹ ⚠️ 我认为这是目前为止多模态最有说服力的一个存在理由，
       比"让模型能看图说话"强得多。
```

### ④ 评测各说各话（11 章已详述）

```
    ✅ K3 和 M3 之间【零个共享的视觉 benchmark】
    ⟹ 这张主表最下面那一行，是全表信息量最低、也最诚实的一行：
       ★ 我们其实不知道这三家谁的视觉更强。
```

## 13.3 开源生态的坐标（⚠️ 可信度较低）

上面五家是本仓库有一手材料的。**开源多模态生态还有另外一批玩家**，
它们才是大多数人真正会用到的：

```
    ⚠️ 以下为背景性介绍，【时效性和细节未经本轮核实】，仅用于建立方位感。

    · LLaVA 系列        学术界起点。★ "MLP 连接器 + 指令数据"这套范式的发明者
    · Qwen-VL 系列      国内最有影响力的开源多模态线之一；
                        Qwen2-VL 的"naive dynamic resolution + M-RoPE"
                        是 04、05 两章讲的那套东西的主要工程参考
    · InternVL 系列     以 dynamic tiling（动态切图）和大视觉塔著称
    · MiniCPM-V 系列    端侧方向，主打"小模型也能看清"
    · Molmo / Idefics   偏研究、强调数据与训练配方的公开可复现
```

> 🔑 **一条选型经验（⚠️ 我的判断）**：
> **做通用看图问答，挑一个主流开源 VLM 微调即可；
> 做文档/表格/发票，一定要看它的"最大支持分辨率"和"是否有 OCR 专项训练"，
> 这两项比它的 MMMU 分数重要得多。**

## 13.4 ⚠️ 三盆冷水

```
 ① "原生多模态"目前更像是一个营销标签
    01 章 1.4 节的三个问题（多模态数据从第几个 token 进、视觉塔怎么初始化、
    训练时冻不冻），五家里【只有 K3 三个都答了】。
    ⟹ 其余的"原生"字样，你无法核实它到底有多原生。

 ② 多模态能力的分数【无法验证】
    ✅ GLM-5.3 报告的多模态分数是【图片格式，无法文本核对】；
    ✅ M3 没有技术报告，只有模型卡上的几个数字；
    ✅ K3 的视觉 benchmark 和另外两家零重叠。
    ⟹ ★★ 也就是说：这一章唯一能确定的是【他们做了什么】，
       ⟹ 完全不能确定【谁做得更好】。

 ③ 多模态在这些报告里的【篇幅占比极低】
    ⚠️ K3 的视觉部分只有一节；M3 只有 config 里的一行；
       GLM-5.3 相对最多，也就一章。
    ⟹ 对比：注意力机制、MoE、后训练、RL 基建各占好几章。
    ⟹ 🔑 这个篇幅分布本身就是一个信号：
       ★ 在 2026 年的旗舰模型里，多模态仍然不是主战场。
```

## 13.5 🔑 这一章的四句话

1. ✅ **五家里三家原生多模态，两家纯文本**——而**纯文本的两家都是推理/代码导向**，这个分布很有信息量。
2. ✅ **视觉塔的架构已经收敛**（patch 14 + 2×2 合并 + 二三十层 ViT）⟹ **差距在数据和训练，不在架构**。
3. ★★ **只有 GLM-5.3 给出了"为什么要多模态"的硬论证：把视觉变成 agent 的验证器**，而不是又一个输入通道。
4. ⚠️ **我们知道他们做了什么，但完全不知道谁做得更好**——分数是图片、口径不通用、benchmark 零重叠。
