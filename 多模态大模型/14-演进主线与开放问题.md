## 14.1 ★★ 三代范式，一条因果链

**先一眼看完三代**，下面再逐代展开：

| | **第一代**（2021~2023）<br>对齐时代 | **第二代**（2023~2025）<br>看清时代 | **第三代**（2025~2026）<br>使用时代 |
|---|---|---|---|
| **一句话** | 把图变成一句话 | 把 token 预算花对地方 | 视觉是 agent 的眼睛和验尺 |
| **要解决的问题** | LLM 根本不认识图 | 看不清 | 看清之后干什么 |
| **★ 心智模型** | 一张图 ≈ **一句话** | 一张图 = 几千 token，是一份**预算** | 视觉 = **传感器 + 验证器** |
| **典型分辨率** | 224² → 336² | 动态，上限做到 3584² | 由任务自己决定看几次 |
| **⟹ 留下的副作用** | 分辨率被 CLIP 卡死 ⟹ **看不清** | token 暴涨 ⟹ **KV 爆炸、EPD 分离、评测口径失控** | 🔮 还在进行中 |

### 第一代（2021~2023）：**对齐时代** —— "把图变成一句话"

```
    要解决的问题：LLM 根本不认识图
    核心动作：    CLIP（Contrastive Language-Image Pre-training，对比式图文预训练）
                 把图和文拉进同一个空间；连接器把视觉向量翻译给 LLM
    典型形态：    冻住的视觉塔 + 一个 MLP + 冻住的 LLM，60 万条指令数据
    ★ 心智模型：  一张图 ≈ 一句话的信息量

    ⟹ 留下的问题：★★ 224×224 的输入，模型【看不清任何细节】
                  patch 14 下只切出 16×16 = 256 个 patch；
                  后来升到 336×336 也只有 24×24 = 576 个
                  ⟹ 文档、表格、小字全糊
```

### 第二代（2023~2025）：**看清时代** —— "把 token 预算花对地方"

```
    要解决的问题：看不清
    核心动作：    动态分辨率、AnyRes 切图、2×2 合并、
                 2D/3D RoPE（Rotary Position Embedding，旋转位置编码）、
                 recaption 重写数据、原生多模态预训练
    ★ 心智模型：  一张图 = 几千个 token，是一份【要精打细算的预算】

    ⟹ ★ 这一代的成果是压倒性的：
       模型第一次真的能读 PDF、读发票、读代码截图
       ✅ 2026 年的量级：输入边长从 224 做到了 3584（K3），token 预算最高 16384
    ⟹ 留下的问题：① 幻觉没解决（看清了照样编）
                  ② 尺子没有（各家 benchmark 零重叠）
                  ③ ★★ 更根本的：看清了【然后呢】？
                     "描述这张图"本身不是一个有多大商业价值的任务
```

### 第三代（2025~2026）：**使用时代** —— "视觉是 agent 的眼睛和验尺"

```
    要解决的问题：看清之后干什么
    核心动作：    · GUI（Graphical User Interface，图形界面）agent：
                   看屏幕 → 决定点哪 → 看结果
                 · ✅ 渲染回环：写代码 → 渲染 → 【自己看】→ 改
                 · agentic 视觉：主动裁剪放大，"再看一眼"
                 · 多模态 RL（Reinforcement Learning，强化学习）：
                   奖励来自环境反馈，而不是人类偏好
    ★★ 心智模型： 视觉不是【输入模态】，是【传感器 + 验证器】

    ✅ 一手佐证（GLM-5.3）：
       "Vision therefore needs to be natively integrated into the model,
        enabling it to decide when to observe and use visual feedback
        to guide subsequent actions."
```

### ★★ 把三代连成因果链

```
     LLM 不认识图
     │
     ├── 【第一代】用 CLIP 对齐，图 ≈ 一句话
     │   └── 副作用：分辨率被 CLIP 的 224 卡死 ⟹ 看不清
     │
     ├── 【第二代】动态分辨率 + token 预算管理（治上面那个副作用）
     │   ├── 成果：能读 PDF、发票、代码截图了
     │   └── 副作用：token 暴涨 ⟹ EPD 分离 / KV 爆炸 / 评测口径失控
     │
     └── 【第三代】"看"从请求开始时的一次性输入，变成 agent 循环里的一个动作
         └── 视觉的价值从"理解世界"变成"验证自己"
```

> 🔑 **每一代的副作用都是下一代的起点**，这是这条链唯一的规律：
> ⟹ 对齐 ⟹ 看不清 ⟹ 看清 ⟹ token 账失控 ⟹ 拿去用（于是"看多少"由任务自己决定，预算问题被转化掉了）。

> 🔑 **如果这份教程只留一句话**：
> **多模态的重心，正在从"让模型看懂图"转移到"让模型用眼睛检查自己干的活"。**
> ⚠️ 这是我的判断，但它有一条硬证据：✅ **GLM-5.3 是五家里把多模态的存在理由论证得最完整的一家，而它给的理由正是这一条。**
> ⚠️ **一处必须修正的措辞**：这句话原来写的是"唯一给出多模态存在理由的"，**这已经不准确了**——✅ DeepSeek-V4.1-Flash 也给了理由，但它给的是**语料覆盖**（爬虫偏文本，从 Common Crawl 重新自举），不是能力，也不是 agent 自检（见 13.4 ③）。

## 14.2 ⚠️ 顺带解释三个"为什么"

| 为什么…… | 旧解释 | ⚠️ 2026 年要改的地方 |
|---|---|---|
| **Q-Former 死了？**（03 章） | "图 ≈ 一句话"的前提变了，硬压到 32 token 不再可接受 | ✅ 仍成立。但★ **压缩本身没死**，只是倍数变小（2×2 主流，V4.1 用 3×3） |
| **2026 年还有旗舰是纯文本？**（13 章） | "看得清对代码和数学推理没帮助" | ⚠️ **兜不住了**：V4.1-Flash 更推理导向却做了原生多模态；现在只剩 openPangu 一家 |
| **"统一理解与生成"雷声大雨点小？**（09 章） | 它解决的是交互形态问题，不是能力问题 | ✅ 有硬数据支持：13 章主表"会不会生成图"一行**五家全是 ❌** |

**下面是三条的完整版**：

```
 ⚠️ 为什么 Q-Former（Querying Transformer，查询式 Transformer）死了？（03 章）
    因为第一代的心智模型是"图 ≈ 一句话"⟹ 压到 32 个 token 完全合理。
    第二代的心智模型变成"图 = 一份预算"⟹ 硬压缩就成了不可接受的信息损失。
    ⟹ ★ 不是它技术差，是【前提变了】。
    ⟹ ★ 但"压缩"本身没死，只是倍数变小了：
       ✅ 2×2（÷4）是主流，DeepSeek-V4.1 用 3×3（÷9）。
       🔑 死的是"压到固定 32 个"这种【与图无关的硬上限】，不是压缩这件事。

 ⚠️ 为什么 2026 年还有旗舰模型是纯文本？（13 章）
    ⚠️ 这个问题的答案在 2026 年【缩水了】：五家里现在只剩 openPangu 一家纯文本。
    原来的解释是"看得清对代码和数学推理没有直接帮助"，
    ⟹ 但 ✅ DeepSeek 从 V4（纯文本）到 V4.1-Flash（原生多模态）这一跳，
       是在【更推理导向】的前提下发生的，所以那个解释兜不住了。
    ⟹ 🔑 更站得住的说法：★ 多模态已经从"要不要做的战略选择"
       变成了"默认要做的一项基础设施"，
       ⟹ 而它的理由可以各不相同（GLM 是 agent 自检，DeepSeek 是语料覆盖）。

 ⚠️ 为什么"统一理解与生成"雷声大雨点小？（09 章）
    因为它解决的是【交互形态】问题，不是【能力】问题，
    而三代主线一直在追能力。
    ⟹ ✅ 一个硬数据：13 章那张主表里"会不会生成图"一行，
       五家【全是 ❌】—— 旗舰侧一个采用者都没有。
    ⟹ ★ 它可能要等到"生成"本身成为 agent 回路的一部分才真正起飞
      （比如：模型画一张设计草图 → 自己看 → 改）。
```

## 14.3 🔮 八个开放问题

**先给一张总览**，每个问题"想解决什么"和"现在卡在哪"：

| 🔮 问题 | 它想解决什么 | 现在卡在哪 |
|---|---|---|
| ① 多模态能提升纯文本智能吗 | 决定多模态值不值得占预算 | ⚠️ **没人做得起对照实验**（要两次预训练的钱） |
| ② 还需要独立视觉编码器吗 | 省掉一个部件和它的训练流程 | 两家最新报告**结论相反**（见下） |
| ③ patch 是最好的视觉表示吗 | 让 token 花在有信息的地方 | 替代方案都试过，没一个成为主流 |
| ④ 幻觉能被根治吗 | 让看图结论可信 | 主干 99% 参数来自文本，不对称是结构性的 |
| ⑤ 多模态的尺子什么时候有 | 让分数可比 | ⚠️ **没有人有动力统一** |
| ⑥ 长视频的正确形态是什么 | 让 1 小时视频进得去 | 硬塞/摘要/检索三条路都不干净 |
| ⑦ 实时和智能的对立怎么破 | 边想边说 | 用户不会等 30 秒 |
| ⑧ 视觉预训练数据会耗尽吗 | 判断这条路还能走多远 | 高质量图文配对并非无穷 |

### 🔮 ① 多模态到底能不能提升纯文本智能？

```
    ⟹ 至今【没有公开的对照实验】：同样的算力，一次纯文本、一次混多模态，
       比最终推理分数。
    ⟹ 因为做一次要花两次预训练的钱。

    ⚠️⚠️ 这一条的间接证据在 2026 年【翻转了，但没有变成正面证据】：
       · 旧的说法是"最强的推理模型（V4）是纯文本的" ⟹ 间接证据偏负面
       · ✅ 而 V4.1-Flash 比 V4 更推理导向，却是原生多模态 ⟹ 旧证据作废
       · ⚠️ 但 V4.1 自己给的理由是【语料覆盖】，不是【能力】
       ⟹ 🔑 所以正确的状态是：★★ 负面的间接证据没了，
          正面的证据也【一个都没有】。这个问题比以前更悬而未决。

    ★ 怎么判断它有没有进展：
      ⟹ 盯一件事——【有没有人公布同算力的纯文本 vs 多模态对照实验】。
      ⟹ 在那之前，任何"多模态让模型更聪明"的说法都是营销。
      ⚠️ 退一步的弱证据也行：同一家在同一代里给出
         "加了多模态数据后纯文本基准的前后分数"，并注明算力口径。
```

### 🔮 ② 还需要独立的视觉编码器吗？

```
    ⚠️⚠️ 这一条在 2026 年出现了【两家互相矛盾的一手证据】，必须一起看：
      · ✅ K3：MoonViT-V2 完全从零、用 next-token prediction 训，
        追平了 SigLIP 初始化的基线 ⟹ 报告结论是
        "对比学习预训练作为初始化是不必要的"
      · ✅ V4.1-Flash：视觉塔也是从零自训，但【第一阶段仍然用
        SigLIP 式 sigmoid 对比损失】（470 亿图文对），第二阶段才自回归微调

    ⟹ 🔑 所以"对比学习不必需"这句话要讲准：
       ★★ K3 证明的是【它作为初始化不必需】，
       ⚠️ 而不是【业界已经放弃对比学习】——更新的那份报告还在用。
    ⟹ ⚠️ 本章上一版把这一条写成了"K3 已经证明…"，容易读成后一种意思，这里更正。

    ⟹ 再往前一步就是 Fuyu 那条"干脆不要编码器"的路（02 章）。
    🔮 如果规模继续涨，视觉塔会不会像 tokenizer 一样，
       退化成一个几乎无参数的预处理步骤？

    ★ 怎么判断它有没有进展：
      ⟹ 看视觉塔占总参数的比例是涨还是跌。
         ✅ 2026 年的刻度：K3 是 0.4B / 2.78T ≈ 0.014%，
            GLM-5.3-Flash 是 0.39B / 321B ≈ 0.12%（报告自己算的）。
      ⟹ 如果三年后这个比例继续掉一个数量级，这条路就走通了。
```

### 🔮 ③ patch 是最好的视觉表示吗？

```
    ⚠️ "把图切成方格"是从 2020 年 ViT 沿用至今的，没有人认真挑战过。
       ✅ 一个旁证：13 章四家原生多模态里，patch 边长【全是 14】。
    它的问题很明显：★ 均匀切分意味着【天空和人脸花一样多的 token】。

    🔮 有没有一种"按信息量分配 token"的表示？
       （区域提议、可变形 patch、目标为中心的表示……都试过，都没成为主流）

    ★ 怎么判断它有没有进展：
      ⟹ 判据很具体：★★ 【有没有模型做到"同一张图，token 数随内容复杂度变化"】。
      ⚠️ 注意别被动态分辨率混淆：那是 token 数随【尺寸】变，
         不是随【内容】变 —— 一张纯白的 2016² 图和一张密排文字的 2016² 图，
         现在花的 token 完全一样（都是 5184，见 13.2）。
```

### 🔮 ④ 幻觉能被根治吗？

```
    ⚠️ 08 章的结论是：幻觉源于"语言先验 vs 视觉证据"的冲突。
    只要主干 99% 的参数来自文本，这个不对称就存在。
       ✅ 把 ② 里那两个比例反过来读就是这件事的量化版：
          视觉塔占总参数 0.014%~0.12%，★ 剩下的全是语言。
    🔮 grounding（强制输出坐标）是我看好的方向，因为它让错误【可验证】。
    ⟹ 但"可验证"到"不犯错"之间还隔着整个 RL 的路要走。

    ★ 怎么判断它有没有进展：
      ⟹ 看 POPE / HallusionBench 这类【存在性】基准上，
         ★ "答有"和"答无"两类题的准确率差距有没有缩小。
      ⚠️ 只看总分会被骗：一个全答"有"的模型在正样本上 100 分。
         ⟹ 🔑 必须看【yes-bias 这个缺口】，而不是总分。
```

### 🔮 ⑤ 多模态的尺子什么时候会有？

```
    ✅ 现状（11、13 章）：K3 和 M3 零个共享 benchmark；
       唯一同名的那一组（M3 的 MMMU_Pro vs V4.1 的 MMMU-Pro）
       一个是后训练、一个是 Base，⚠️ 也不能比。
    ⚠️ 我不认为这会自然好转 —— 因为 benchmark 太多，
       每家都能找到自己赢的那几个，【没有人有动力统一】。
    🔮 可能的转机：像 SWE-bench 之于代码那样，
       出现一个【任务真实、判分客观、没法刷】的多模态 agent 基准。
       ⟹ GUI 任务成功率是最有希望的候选，因为它的判分是环境给的。

    ★ 怎么判断它有没有进展：
      ⟹ 判据只有一个，而且很好查：★★ 【任取两家旗舰，数一下共享的视觉
         benchmark 有几个，并且确认版本号和模型阶段（Base/后训练）一致】。
      ⟹ 这个数从 0 变成 1，就是这个领域第一次有尺子。
```

### 🔮 ⑥ 长视频的正确形态是什么？

```
    ⚠️ 三条路（硬塞 / 摘要 / 检索）都不干净（05 章）。
       ✅ 硬塞的代价是可以算出来的：1 小时视频按 1 fps、每帧 256 token，
          = 3600 × 256 ≈ 92 万 token ⟹ ★ 把 1M 上下文全占满还装不下别的。
    🔮 我倾向检索路线会赢，因为它和文本 RAG（Retrieval-Augmented Generation，
       检索增强生成）同构，而文本领域已经证明了"长上下文"和"检索"
       是互补而不是替代关系。

    ★ 怎么判断它有没有进展：
      ⟹ 看视频基准上【时长和分数的关系曲线】有没有变平。
      ⚠️ 同时必须盯住抽帧口径（见 11.5）：
         ★ 一个模型"支持 2 小时视频"但抽 32 帧，等于每 3.75 分钟看一眼。
         ⟹ 🔑 真正的进展是【帧数随时长增长】，不是【时长上限数字变大】。
```

### 🔮 ⑦ 实时和智能的对立怎么破？

```
    ⚠️ 10 章：端到端语音模型不能做长思维链，因为用户不会等 30 秒。
       ⚠️ 量级对照（10 章那两笔延迟账）：级联方案的首声延迟是【秒级】，
          端到端是【几百毫秒级】，而自然对话能容忍的是后者。
          ★ 精确数字和口径请看 10 章本身，那里标了哪些已核、哪些没核。
    🔮 可能的解法是【分层】：一个快模型维持对话节奏，
       一个慢模型在后台想 —— 这和具身智能的"双系统架构"是同一个思路
       （见 ../具身智能与世界模型/01-具身智能与VLA.md，该文 §1.4）。
    ⟹ ★ 不同领域撞到同一堵墙、长出同一个解法，通常说明这个解法是对的。

    ★ 怎么判断它有没有进展：
      ⟹ 判据是【首响延迟和推理深度能不能同时给】：
         ★ 有没有模型敢同时报"首字 300 ms"和"会用思维链"这两个指标。
      ⚠️ 现在的报告总是只报一个。
```

### 🔮 ⑧ 视觉预训练数据会不会耗尽？

```
    ⚠️ 文本数据的枯竭已经在讨论（见 ../数据格式和数据处理/11-喂多少-ScalingLaw.md）。
    图像看起来无穷无尽，但【高质量、有信息的图文配对】并不是。
       ✅ 一个 2026 年的直接佐证：DeepSeek-V4.1-Flash 报告说自己的爬虫
          "过于偏向文本网页"，因此【从 Common Crawl 重新自举】
          来改善多模态覆盖 ⟹ ★ 数据不够这件事已经逼得一家重做爬虫了。
       ✅ 而同一份报告又说，多模态数据【刻意不做大规模合成】，
          理由是"原始网页数据本身就富含多模态知识"。
       ⟹ ⚠️ 这两条放在一起有点矛盾：既然原始数据够富，为什么要重做爬虫？
          ★ 我的读法是：富的是【量】，缺的是【覆盖面】。但这是推断。

    🔮 而多模态有一张纯文本没有的牌：★ 渲染合成（07 章）——
       能被程序画出来的东西可以无限量地完美标注。
    ⟹ 这可能让多模态的数据墙比文本来得晚。⚠️ 但它只覆盖"合成得出来"的那部分世界。
    ⟹ ⚠️ 而且注意：K3 和 DeepSeek 在这件事上【选择相反】——
       一家靠合成，一家刻意不靠。⟹ 🔮 谁对，几年后才知道。

    ★ 怎么判断它有没有进展：
      ⟹ 看各家报告里【多模态语料的量和配比】有没有继续往上走。
         ✅ 2026 年唯一公开的刻度是 V4.1-Flash 的"文本:多模态 = 7:1"、
            总 45T token。⟹ 🔑 这是目前唯一一个能用来做纵向对比的锚点，
            下一代如果有人报出 5:1 或 3:1，就说明这条路还有空间。
```

## 14.4 🔑 全教程的五句话总结

1. **多模态的全部难点，是在没有词典的情况下把图/音变成"像文字一样的向量"**，然后管理好它带来的 token 账。
2. **三代范式：对齐（图≈一句话）→ 看清（图=一份预算）→ 使用（视觉=agent 的传感器与验证器）。** 每一代的副作用都是下一代的起点。
3. ✅ **2026 年架构的部件收敛了**（patch 14、24~32 层的中等 ViT），⚠️ **但预算没收敛——一张图的 token 从 256 到 16384，差 64 倍**；而**五家里只剩 openPangu 一家不做多模态**。
4. ⚠️ **两件事仍然没解决：幻觉（源于语言先验压过视觉证据，而视觉塔只占总参数 0.1% 量级）和尺子（各家 benchmark 零重叠）。**
5. 🔮 **最重要的开放问题仍是"多模态能不能提升纯文本智能"**——⚠️ 2026 年的变化是**原来那条偏负面的间接证据失效了，但正面证据一条都没有**，所以它比以前更悬。
