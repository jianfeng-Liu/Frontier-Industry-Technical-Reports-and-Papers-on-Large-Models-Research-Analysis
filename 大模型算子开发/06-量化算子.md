# 06 · 量化算子：带宽减半 = 速度翻倍

> **前置**：[02 章（屋顶线）](02-屋顶线与性能剖析.md)、[03 章（GEMM）](03-GEMM深度剖析.md)  
> **目标**：搞清楚量化的数学原理、主流方案（INT8/FP8/GPTQ）、实际部署里的量化 kernel 实现，以及 DeepSeek 的 FP8 训练实践。

---

**本章关键词**

**量化**（Quantization）—— 用位宽更低的数据类型（INT8、FP8、INT4）表示原本是 FP16/BF16 的张量，减少内存占用和带宽消耗。  
**对称量化 / 非对称量化** —— 是否有零点偏移（zero point），对称量化用 `q = round(x / scale)`，非对称量化用 `q = round(x / scale) + zero_point`。  
**Per-tensor / Per-channel / Per-token 量化** —— 量化粒度，粒度越细精度越高，但计算开销和存储开销也越大。  
**W8A16 / W8A8 / W4A16** —— 权重（W）和激活值（A）分别用几位来表示的简写，例如 W8A16 表示权重 INT8、激活 FP16。  
**SmoothQuant** —— 通过平滑激活值的分布（把"刺"从激活迁移到权重），让 W8A8 量化更精准。  
**FP8（E4M3 / E5M2）** —— 8 位浮点格式，H100 原生硬件支持，是当前训练量化的主流选择。  
**GPTQ** —— 训练后仅量化权重的方案，用二阶梯度信息最小化量化误差，支持 INT4/INT3。  
**AWQ**（Activation-aware Weight Quantization）—— 保留对激活值影响大的权重通道不量化，其余量化为 INT4，精度优于 GPTQ。

## 6.1 为什么量化能提速

大模型推理几乎全是 Memory Bound（见第 02 章）。瓶颈是 HBM 带宽，不是算力。

```
H100 带宽：3.35 TB/s
H100 FP16 算力：989 TFLOPS
屋脊点：295 FLOP/Byte

推理 batch=1 的 GEMM 算术强度：约 1 FLOP/Byte
→ 99.7% 的时间在等 HBM，算力空转 99.7%
```

量化的直接效果：

```
FP16 → INT8：每个数从 2 Bytes → 1 Byte，带宽需求减半
FP16 → INT4：每个数从 2 Bytes → 0.5 Byte，带宽需求减为 1/4

推理 batch=1 时，带宽减半 ≈ 速度翻倍
（前提：量化 kernel 的额外开销不显著）
```

此外：
- 显存占用减少，可以装更大的模型或更大的 batch
- batch 越大时收益逐渐下降（因为大 batch 时权重带宽已被分摊，算力开始成为瓶颈）

## 6.2 量化的数学基础

### 均匀量化（Uniform Quantization）

把浮点数映射到固定范围的整数：

```
对称量化（常用于权重）：
  scale = max(|x|) / (2^(b-1) - 1)     b = 位宽（8 → 127）
  q = round(x / scale)                  q ∈ [-127, 127]
  x̂ = q × scale                        反量化

非对称量化（常用于激活值，分布不对称）：
  scale = (max(x) - min(x)) / (2^b - 1)
  zero_point = round(-min(x) / scale)
  q = round(x / scale) + zero_point     q ∈ [0, 255]（INT8 无符号）
  x̂ = (q - zero_point) × scale
```

### 量化粒度

量化粒度决定了精度和灵活性的权衡：

```
Per-tensor：整个张量共用一个 scale（最粗，精度最低）
  scale = max(|W|) / 127

Per-channel（权重量化的标准做法）：每个输出通道一个 scale
  scale[i] = max(|W[i, :]|) / 127

Per-token（激活量化的常用做法）：每个 token（每行）一个 scale
  scale[j] = max(|X[j, :]|) / 127

Per-group（GPTQ/AWQ 常用）：每 g 个权重共用一个 scale
  通常 g = 128，是 per-channel 和 per-tensor 的折中
```

粒度越细，精度越高，但也需要存储更多 scale 参数，且矩阵乘法后需要处理不同 scale 的混合。

## 6.3 W8A16：最保守的量化

权重用 INT8 存储，激活值保持 FP16。

**前向计算流程**：

```
weight_int8 (存储在 HBM) → 加载时反量化为 FP16 → 正常 FP16 GEMM
```

**优点**：
- 精度损失极小（权重分布通常比较平滑，容易量化）
- 不需要校准数据
- 现有 FP16 GEMM kernel 完全可用

**缺点**：
- 计算阶段仍用 FP16，Tensor Core 吞吐没有提升
- 带宽省一半（权重从 HBM 读出是 INT8，但计算前要反量化）
- 反量化的开销约占 5–10%

**适用场景**：模型太大放不进显存，或需要节省显存，对速度要求不那么极致。

---

## 6.4 W8A8（SmoothQuant）：算力 + 带宽双重提升

权重和激活值都用 INT8，可以使用 INT8 Tensor Core（H100：1979 TOPS，是 BF16 的 2 倍）。

**难点：激活值里的"刺"**

权重的分布通常比较平滑，容易量化。但激活值（尤其是大模型里的中间层输出）常有少数极大的异常值（Outlier）：

```
激活值分布示意：
  ████████████████  ← 99% 的值在 [-2, 2]
                             ██  ← 1% 的值高达 ±100

如果直接量化：
  scale = 100 / 127 ≈ 0.79
  正常值 2.0 → round(2.0 / 0.79) = round(2.53) = 3   ← 量化误差极大！
  正常范围 [-2, 2] 被压缩到 [-3, 3]，实际精度只有 3 位
```

### SmoothQuant 的解决方案

把激活值的"刺"**迁移**到权重侧，让两边都变得容易量化：

```
原始：Y = X · W   （X 有刺，W 较平滑）

引入对角矩阵 s（平滑因子）：
Y = (X · diag(s)⁻¹) · (diag(s) · W)
    ────────────────    ─────────────
         X̃（平滑后）     W̃（吸收了"刺"）

选择 s_j = max(|X[:, j]|)^α / max(|W[j, :]|)^(1-α)   α ∈ [0, 1]

α=0.5 时：把刺的"责任"平均分给 X 和 W
```

平滑后，X̃ 和 W̃ 的动态范围都更接近正态分布，INT8 量化误差大幅降低。

**实测效果（LLaMA-65B，INT8）**：
- W8A8（无 SmoothQuant）：PPL 上升约 2–5
- W8A8（SmoothQuant）：PPL 几乎不变（vs FP16 基准差 < 0.1）

## 6.5 FP8：H100 时代的主流选择

FP8 是用 8 位表示浮点数，有两种格式：

```
E4M3（4 位指数，3 位尾数）：
  范围：约 [-448, 448]，精度约 3 位有效数字
  适合：前向传播（权重、激活值，不需要太大范围）

E5M2（5 位指数，2 位尾数）：
  范围：约 [-57344, 57344]，精度约 2 位有效数字
  适合：反向传播（梯度可能有极大值，需要大范围）
```

**为什么 FP8 优于 INT8**：
- FP8 保留了浮点的非均匀精度分布（小数附近精度高，大数附近精度低）
- 梯度和激活值的分布通常是近似正态或对数正态，FP8 的非均匀分布与之匹配更好
- H100 原生支持 FP8 MMA 指令，吞吐是 BF16 的 2 倍（1979 vs 989 TFLOPS）

### DeepSeek-V3 的 FP8 混合精度训练

DeepSeek-V3/V4 技术报告（2024）中详细描述了 FP8 训练策略：

```
组件                精度        原因
────────────────────────────────────────────
主要 GEMM（FFN、QKV 投影）  FP8 E4M3  速度 + 显存
注意力计算（QK^T、PV）      FP8 E4M3  同上
梯度                        FP8 E5M2  需要更大范围
梯度累加                    FP32      防止舍入误差累积
残差连接                    BF16      稳定性
LayerNorm / RMSNorm         BF16      敏感操作
嵌入层 / LM head            BF16      精度要求高
```

**训练结果**：
- 与全 BF16 训练相比，PPL 差异 < 0.02%（可忽略）
- 训练速度提升约 1.6 倍
- 显存减少约 30%（主要来自激活值缓存）

**关键工程细节**：
- 每 128 个元素一组，共用一个 FP8 scale（per-group 量化）
- scale 存为 FP32，在 BF16 Tensor Core 上单独计算
- 每隔几步更新一次 scale（历史最大值的指数移动平均）

## 6.6 GPTQ：训练后仅量化权重

GPTQ（Frantar et al., 2022）是目前最广泛用于端侧/低显存部署的权重量化方案，支持 INT4/INT3。

### 核心思路：用二阶信息最小化量化误差

朴素的 round-to-nearest 量化：直接四舍五入。
GPTQ：**每量化一个权重，就把这个量化误差补偿到剩余的权重上**，最小化整体 GEMM 输出误差。

```
对于权重矩阵 W（每列独立处理）：
  按列逐一量化：
    w_q[i] = quantize(w[i])              量化第 i 列
    err[i]  = w[i] - w_q[i]             量化误差
    w[i+1:] -= err[i] × H⁻¹[i, i+1:] / H⁻¹[i, i]   补偿到剩余列
  
  H 是 Hessian 矩阵（用少量校准数据计算）
```

实际上用的是 OBS（Optimal Brain Surgeon）的近似：只需要少量校准数据（约 128 条样本）计算 Hessian 的近似。

### GPTQ 实测效果

| 模型 | 精度 | FP16 PPL | INT4（GPTQ）PPL | 大小（FP16→INT4）|
|---|---|---|---|---|
| LLaMA-2 7B | INT4/group=128 | 5.47 | 5.68 | 13 GB → 3.5 GB |
| LLaMA-2 13B | INT4/group=128 | 4.88 | 5.02 | 26 GB → 7 GB |
| LLaMA-2 70B | INT4/group=128 | 3.32 | 3.44 | 140 GB → 35 GB |

> ✅ INT4 GPTQ 的 70B 模型可以装进一块 40 GB 的 A100，而 FP16 需要 4 块。

## 6.7 AWQ：激活感知权重量化

AWQ（Lin et al., 2023）的核心洞察：**不是所有权重都同等重要**。对激活值影响大的权重通道（对应激活值大的输入维度），量化误差传播也更大。

```
直觉：
  y[j] += w[i, j] * x[i]

  若 x[i] 很大（激活值的"刺"所在维度），
  则 w[i, j] 的量化误差被放大 |x[i]| 倍，
  传播到输出的误差也是 |x[i]| 倍。
```

AWQ 的做法：
1. 找出哪些输入维度 i 对应的 `|x[i]|` 最大（约 1% 的维度）
2. 这些维度的权重**不量化**（保持 FP16），其余量化为 INT4
3. 对这 1% 的权重用 FP16 乘法，其余用 INT4 乘法

**效果**：AWQ 在 INT4 精度下通常比 GPTQ 高 0.1–0.3 PPL，尤其对小模型（7B）效果明显。

## 6.8 量化 kernel 的实现要点

量化 GEMM 和普通 GEMM 的区别：

```
W8A8 INT8 GEMM 流程：
  1. 从 HBM 加载 X_int8, W_int8（已量化存储）
  2. 在 SRAM 里用 INT8 Tensor Core 做矩阵乘，输出 INT32 累加
  3. 把 INT32 结果反量化：Y = Y_int32 × scale_X × scale_W
  4. 写回 Y_fp16 到 HBM

关键：步骤 3 的反量化可以在 GEMM Epilogue 里融合（CUTLASS 支持）
```

INT4 packed GEMM（GPTQ/AWQ）：

```
INT4 没有原生硬件支持（H100 最低是 INT8）
实现方式：把两个 INT4 值 pack 进一个 INT8
  [i4₀ | i4₁] → u8（高 4 位 + 低 4 位）

计算时：
  先 unpack 为 INT8
  用 INT8 Tensor Core 计算（相当于每次 GEMM 处理效率减半）

所以 W4A16（GPTQ 常用）实际上是：
  INT4 权重 → unpack 为 INT8 / FP16 → FP16 Tensor Core GEMM
  带宽省 4×（读权重时），但计算速度不提升（还是 FP16 GEMM）
```

## 6.9 量化方案选型速查

| 方案 | 权重精度 | 激活精度 | 适用场景 | 精度损失 | 速度收益 |
|---|---|---|---|---|---|
| BF16 基准 | BF16 | BF16 | 训练、高精度推理 | 无 | 基准 |
| FP8 E4M3 | FP8 | FP8 | H100 训练/推理 | 极小 | 1.5–2× |
| W8A8 SmoothQuant | INT8 | INT8 | 生产推理（A100/H100）| 小 | 1.3–1.8× |
| W8A16 | INT8 | FP16 | 显存受限部署 | 极小 | 1.1–1.3× |
| W4A16 GPTQ | INT4 | FP16 | 端侧/单卡部署 | 中 | 1.5–2.5×（带宽）|
| W4A16 AWQ | INT4 | FP16 | 端侧/单卡部署 | 小→中 | 同上 |

## 6.10 本章小结

```
量化的核心逻辑：
  推理是 Memory Bound → 减少位宽 → 减少 HBM 带宽需求 → 速度提升

精度损失来源：
  1. 量化粒度（粒度越粗误差越大）
  2. 激活值异常值（"刺"）
  3. 反量化运算的舍入累积

主要方案：
  FP8 训练   → H100 原生硬件支持，精度几乎不损，DeepSeek-V3 标配
  W8A8       → 算力+带宽双提升，需要 SmoothQuant 处理激活值
  W8A16      → 最保守，精度高，只省带宽
  W4A16 GPTQ/AWQ → 端侧部署，模型尺寸减 4×，精度有损失

量化 kernel 的关键工程：
  反量化融合进 GEMM Epilogue（CUTLASS）
  INT4 需要 pack/unpack，无原生 INT4 Tensor Core（H100）

下一章：Triton，用 Python 写 GPU kernel 的正确方式。
```
