大模型算子开发

系列定位：从零讲清"一行 torch.matmul 到底在加速卡里发生了什么"，以及业界为什么能把同一个矩阵乘法优化到快 50 倍。
目标读者：看懂了大模型架构（注意力、MoE、量化）但不清楚它们是怎么跑在硬件上的工程师。
风格：通俗 + 彻底。每章先讲"为什么"，再讲"怎么做"，再给出实测数字。

⚠️ 先读 00 · 总纲。它给出平台无关的骨架——算子优化的四个通用手段、GPU 与 NPU 的两种硬件哲学、性能诊断的通用漏斗。后面每一章都是往这个骨架上挂具体技术；跳过它，各章会显得零散。

两条硬件路线怎么组织的

昇腾内容不是单独一卷，而是按性质分流：

  • 硬件与编程语言是平台专属的，独立成章（12、13），和 GPU 侧的 01、07 并列在同一卷里；
  • 算子原理是平台共享的，所以 FlashAttention、量化、MoE 都在原章节末尾加「在昇腾上」小节（§4.9、§6.10、§8.9），读到哪一章就能看到那一章的两个平台实现；
  • 迁移是独立任务，单独成章（14）。

反向指引也是通的：01、02、03、05、07、09、11 各章末尾都有「昇腾对照」一行，指向对应的昇腾内容。

关于昇腾数字的可信度

华为未发布昇腾 910B/910C 的完整数据手册，公开数字彼此矛盾的地方很多（同一款 910B 的 FP16 算力有 256 和 320 两种说法，HBM 带宽从 400 GB/s 到 2.4 TB/s 都有人写）。凡涉及昇腾规格，本系列标注：

  • ✅ 披露 —— 华为官方产品页 / CANN 官方文档明确写出
  • ⚠️ 推断 —— 第三方分析、芯片拆解、学术论文或社区实测，仅供量级参考

任何要写进方案、用于容量规划的数字，请按 12 章 §12.4.3 的方法在自己的卡上实测（npu-smi info + CANN 的 platform_config/*.ini），不要引用本系列。
