## B. 关键公式速查

### B.1 算术强度与屋顶线

```
算术强度 I = FLOPs / Bytes（读写总字节数）

屋顶线性能上界：
  P = min(峰值算力, 峰值带宽 × I)
  H100 屋脊点 = 989 TFLOPS / 3350 GB/s ≈ 295 FLOP/Byte

  I < 295：Memory Bound，P ≈ 3350 × I (GFLOPS，I 单位 FLOP/Byte)
  I ≥ 295：Compute Bound，P → 989 TFLOPS
```

### B.2 GEMM 算术强度

```
A: M×K，B: K×N，C: M×N（FP16，2 Bytes/元素）

FLOPs  = 2·M·K·N
Bytes  = 2·(M·K + K·N + M·N)

I ≈ M·K·N / (M·K + K·N + M·N)

特殊情形：
  M=1（推理 batch=1）：I ≈ 1 FLOP/Byte
  M=64：              I ≈ 64 FLOP/Byte（近似，K=N 时）
  M=N=K=大数：        I ≈ M/2 FLOP/Byte → Compute Bound
```

### B.3 MFU（模型算力利用率）

```
MFU = (tokens/s × 6N) / 峰值 TFLOPS

N = 参数量（6N ≈ 每 token 的 FLOPs，包含前向 + 反向 × 2 + 优化器）
业界顶级：MFU ≈ 40–50%（单机 8×H100）
```

### B.4 注意力内存开销

```
朴素 Attention 中间矩阵 S = QK^T：
  大小 = B × H × N × N × 2 Bytes（FP16）
  N=8192, H=32, B=1：≈ 4 GB
  N=32768：≈ 64 GB（超出 H100 80 GB 显存！）

FlashAttention 重计算后：
  保存量 = O(N)，与序列长度线性
```

### B.5 KV Cache 大小

```
每 token 每层 KV Cache（FP16）：
  = 2 × 2 × d_model × sizeof(FP16)
  = 2 × 2 × d_model × 2 Bytes
  = 8 × d_model Bytes

LLaMA-3 70B 示例（d_model=8192，80 层）：
  每 token = 8 × 8192 = 65536 Bytes ≈ 64 KB（单层）× 80 层 = 5 MB/token
  注：GQA 时按实际 KV head 数折算
```

### B.6 量化误差与位宽

```
对称量化（scale-only）：
  x_q = round(x / s)，x_dq = x_q × s
  s = max(|x|) / (2^(b-1) - 1)

FP8 E4M3：动态范围 ±448，精度 ~3 有效位（十进制）
FP8 E5M2：动态范围 ±57344，精度 ~2 有效位（十进制）
INT8：   动态范围 [-128, 127]，精度 ~2.4 有效位
INT4：   动态范围 [-8, 7]，精度 ~1.2 有效位
```

## G. MoE 关键数字（DeepSeek-V3 规模参考）

```
模型规模：671B 参数，37B 激活
专家配置：256 专家，Top-8 路由，EP=32（每节点 8 卡）
隐藏维度：H = 7168

All-to-All 通信量（每层，单向）：
  = tokens × H × sizeof(BF16) × (EP-1)/EP
  例：batch=4096 tokens，H=7168，EP=32
  ≈ 4096 × 7168 × 2 × 31/32 ≈ 1.76 GB（发送）

Grouped GEMM 的不规则性：
  Top-K=8，每专家平均 tokens = batch × 8 / 256 = batch/32
  batch=4096 → 每专家约 128 tokens（实际按 Poisson 分布，有专家空 / 过载）
```

## I. 常见维度对齐要求

```
Tensor Core 对齐（BF16/FP16）：M, N, K 均须是 16 的倍数
高效 GEMM 对齐：通常要求 128 的倍数（8 × 16）
INT8 Tensor Core：M, N, K 须是 16 的倍数
FP8 Tensor Core：M, N, K 须是 16 的倍数
共享内存 bank：32 个 bank，每 bank 4 Bytes（32-bit）
Warp 大小：固定 32 线程，Block 大小应是 32 的倍数
```

## K. GPU ↔ 昇腾 术语对照

### K.1 硬件概念

| NVIDIA GPU | 昇腾 NPU | 说明 |
|---|---|---|
| SM（Streaming Multiprocessor） | AI Core | 基本计算单元 |
| CUDA Core | **无对应物** | 昇腾没有通用标量并行核 |
| Tensor Core | Cube 单元 | Tensor Core 是 warp 级接口，Cube 是核级 |
| — | Vector 单元 | 非矩阵运算的专用通路（AIV） |
| — | Scalar 单元 | 核内流程控制 |
| HBM / Global Memory | GM（Global Memory） | 一致 |
| L2 Cache | L2 Cache | 一致，都是硬件管理 |
| 共享内存（Shared Memory） | UB（Unified Buffer） / L1 Buffer | **昇腾是 scratchpad，不自动填充** |
| — | L0A / L0B / L0C | Cube 专用缓冲，GPU 无对应物 |
| — | BT / FP Buffer | Bias 表 / 量化参数，910B 分离架构新增 |
| `cp.async` 指令 | MTE（存储转换引擎） | 昇腾是**独立硬件流水线** |
| Warp（32 线程） | **无对应物** | 昇腾没有 warp |
| Thread / Block / Grid | **无对应物** | 只有"核"这一层 |
| Bank Conflict | **无对应物** | padding 技巧用不上 |
| Occupancy | **无对应物** | 延迟靠流水重叠掩盖，不靠超额订阅 |
| NVLink | HCCS | 卡间互联 |
| NVSwitch | HCCS Full Mesh | 机内全互联 |
| Row Major / ND | FRACTAL_NZ | 昇腾片上的分形格式 |

### K.3 编程概念（最容易误解的几个）

| 概念 | GPU 含义 | 昇腾含义 | 风险 |
|---|---|---|---|
| **blockDim** | 每个 block 的线程数 | **参与计算的核数** | 撞名，极易误解 |
| **UB** | — | Unified **Buffer**（片上存储） | 和 CloudMatrix 的 Unified **Bus**（总线）撞名 |
| `GetBlockIdx()` | ≈ `blockIdx.x` | 本核编号 | 基本一致 |
| `GetBlockNum()` | ≈ `gridDim.x` | 总核数 | 基本一致 |
| mask | `tl.load(mask=)` | **不存在** | 尾块要手写，静默精度 bug 来源 |

### K.4 Attention 算子对照

| GPU 侧 | 昇腾侧 | 场景 |
|---|---|---|
| `flash_attn_func` | `torch_npu.npu_fusion_attention`（FlashAttentionScore） | 训练正反向 |
| `flash_attn_varlen_func` | `npu_prompt_flash_attention`（PFA） | 推理 Prefill |
| PagedAttention decode kernel | `npu_incre_flash_attention`（IFA） | 推理 Decode |
| 统一 kernel | FusedInferAttentionScore | Prefill + Decode |
| `cu_seqlens` 变长 | `input_layout="TND"` + `actual_seq_qlen` | 变长/连续批处理 |

**迁移四坑**（详见 [04 章 §4.9.3](04-FlashAttention全系.md)）：

```
① atten_mask 语义相反 —— NPU 侧 True = 屏蔽，要 torch.logical_not()
② sparse_mode：替换 flash-attn ≤2.0 用 2，≥2.1 用 3
③ 定长 kernel 要求序列长 128 的倍数 → 变长场景必须换 TND 布局
④ head_dim 对齐要求比 GPU 严（FRACTAL_NZ 分形格式）
①② 都是静默错误，不报错只是结果不对 —— 必须逐层比对
```

### L.2 Ascend C 三段式骨架

```
CopyIn  (MTE2)  →  Compute (Vector/Cube)  →  CopyOut (MTE3)
   AllocTensor        DeQue                    DeQue
   DataCopy           计算 API                 DataCopy
   EnQue              EnQue + FreeTensor       FreeTensor

TPipe  管片上内存      pipe.InitBuffer(que, BUFFER_NUM, bytes)
TQue   管传递 + 同步   EnQue / DeQue
TBuf   管临时变量      tmpBuf.Get<T>()
BUFFER_NUM = 2         开启双缓冲 —— 不是优化，是基本功
```

### L.3 TPosition 对照

| TPosition | 物理落点 | 用途 |
|---|---|---|
| `VECIN` / `VECOUT` / `VECCALC` | UB | Vector 的输入/输出/临时 |
| `A1` / `B1` | L1 | 矩阵第一级 |
| `A2` / `B2` | L0A / L0B | 矩阵第二级（Cube 直接吃） |
| `CO1` / `CO2` | L0C / GM | 矩阵结果 |

### L.4 四类瓶颈与对策

| 瓶颈 | 流水图现象 | 对策 |
|---|---|---|
| **Cube Bound** | Cube 占比高 | 理想状态，剩余收益在换更大 tiling |
| **Vector Bound** | AIV 高、AIC 空转 | CV 流水并行；部分计算挪给 Cube |
| **MTE Bound** | MTE2/MTE3 占比高 | ① 确认 BUFFER_NUM=2 ② 调大 tileLength ③ 32 Byte 对齐 ④ 查 ND↔NZ 隐式转换 |
| **下发 Bound** | 三级都不满但总耗时长 | 开 ACLGraph 或 TorchAir 图模式；合并小算子 |

### L.6 三种执行模式选型

| 模式 | 机制 | 用在哪 |
|---|---|---|
| 单算子（Eager） | 逐个下发 aclnn | 开发调试 |
