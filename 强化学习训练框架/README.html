强化学习训练框架：技术报告调研与分析

这个目录回答一个问题：大模型的 RL 后训练，工程上到底有哪几种搭法？

RL = Reinforcement Learning（强化学习）。RLHF = Reinforcement Learning from Human Feedback（基于人类反馈的强化学习）。
「后训练」指预训练之后、模型上线之前的那一段训练，RL 是其中最吃工程的一环。

⚠️ 先说清楚三件事

1. 这个目录不讲 RL 原理。
四个模型分别是什么、显存怎么算、为什么生成和训练是两种负载——这些在 训练框架/分布式训练入门/14-RL训练框架.md 里已经写过了。本目录引用它，不重写它。没读过的先读那一篇，再回来。

2. 这个目录的主线是「框架」，不是「算法」。
PPO 和 GRPO 的公式差别不是重点，重点是「换了算法之后，框架必须跟着改哪里」。

3. 这是一份会过时的调研。
开源 RL 框架的迭代速度远快于训练框架。所有联网材料都标了访问日期，所有源码引用都钉了 commit。以官方仓库现状为准。

🧭 这个领域的一句话地图

RL 训练框架的全部复杂度，来自一句话：

生成（rollout）和训练（update）是两种完全不同的负载，但它们必须共用同一份权重。

所有设计分歧都是这句话的推论：

  • 共用同一批 GPU 还是分开放？→ colocated vs disaggregated（02）
  • 生成的样本必须来自最新权重吗？→ 同步 / 一步离策略 / 全异步（02）
  • 权重怎么传过去、传的时候生成要不要停？→ 传输层 × 中断模型（03）
  • 两边算出来的概率不一样怎么办？→ 训推一致性（04）
