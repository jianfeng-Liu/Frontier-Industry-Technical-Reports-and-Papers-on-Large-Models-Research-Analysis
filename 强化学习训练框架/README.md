# 强化学习训练框架：技术报告调研与分析

> 这个目录回答一个问题：**大模型的 RL 后训练，工程上到底有哪几种搭法？**
>
> RL = Reinforcement Learning（强化学习）。RLHF = Reinforcement Learning from Human Feedback（基于人类反馈的强化学习）。
> 「后训练」指预训练之后、模型上线之前的那一段训练，RL 是其中最吃工程的一环。

开源 RL 框架的迭代速度远快于训练框架。所有联网材料都标了访问日期，所有源码引用都钉了 commit。**以官方仓库现状为准。**

## 🧭 这个领域的一句话地图

RL 训练框架的全部复杂度，来自**一句话**：

> 生成（rollout）和训练（update）是两种完全不同的负载，但它们必须共用同一份权重。

所有设计分歧都是这句话的推论：

- 共用**同一批 GPU** 还是**分开放**？→ colocated（同置）vs disaggregated（分离）（[02](02-架构主轴-同步到全异步.md)）
- 生成的样本必须来自**最新权重**吗？→ 同步 / 一步离策略 / 全异步（[02](02-架构主轴-同步到全异步.md)）
- 权重**怎么**传过去、传的时候生成要不要停？→ 传输层 × 中断模型（[03](03-权重同步.md)）
- 两边算出来的概率**不一样**怎么办？→ 训推一致性（[04](04-训推一致性.md)）
- 换个算法，上面这四件事要跟着改什么？→ 算法与框架的接口（[05](05-算法与框架的接口.md)）
- 生成的那一侧如果还要跑真实代码呢？→ 环境与沙箱（[06](06-AgenticRL-环境与沙箱.md)）

### ⚠️ 三个反复出现的口径陷阱

本目录涉及大量性能数字，下面三条在正文里反复用到，集中放在这里（[07 章 §7.3 坑 4](07-选型与实践.md) 有完整推演）：

| 陷阱 | 正确算法 |
|---|---|
| 「时间减少 X%」≠「加速 X%」 | `加速倍数 = 1 ÷ (1 − 时间减少比例)`。时间减少 50% = 加速 **2 倍**；加速 50% 只对应时间减少 **33.3%** |
| 「百分比」≠「百分点」 | 两个比例相减得到的是**百分点**。40% → 55% 是涨了 **15 个百分点**，相对涨幅 **37.5%** |
| 带宽单位 | **GB/s 与 Gb/s 差 8 倍**。NVLink 900 GB/s 是**双向聚合**（单向 450）；IB 400 Gb/s = 50 GB/s。同口径下 NVLink : IB = **9 倍，不是 18 倍** |
