⚠️ 先说清楚三件事

① 这份教程不预设你懂推理系统。

KV Cache、连续批处理、分页注意力、前缀缓存、投机解码、PD 分离——这些词你一个都不用提前知道。教程从「为什么生成第 1000 个字比生成第 1 个字慢」这个最朴素的问题开始，每个名词第一次出现都会先给 英文全称 + 中文 + 一句话解释，再使用。

② 对你的唯一要求：会写 Python，知道「Transformer 里有注意力和前馈两块」。只要这些就够了。

    推理框架/    ← 你在这里。「模型训好了，怎么服务几万个用户」

🧭 这个领域的一句话地图

推理优化这件事，说穿了在和三个瓶颈搏斗：

瓶颈一：显存装不下 KV Cache  ——  「batch 开不大，卡就闲着」
        → 省 KV Cache 的四条路：
             不浪费    → PagedAttention 分页          （05 章）
             不重复    → 前缀缓存 / RadixAttention    （05 章）
             结构上砍  → MQA / GQA / MLA              （07 章）
             精度上砍  → KV Cache 量化                （09 章）

瓶颈二：解码阶段访存受限   ——  「算力有 99% 在空转」
        → 提高「每次搬运权重能干多少活」：
             把 batch 做大  → 连续批处理             （04 章）
             一次多出几个字 → 投机解码               （08 章）
             权重搬得更少   → 量化                   （09 章）
             别让 CPU 拖后腿 → CUDA Graph            （12 章）

瓶颈三：Prefill 和 Decode 互相打架  ——  「一个长 prompt 卡住所有人」
        → 两条路线：
             混着调度，切碎 → chunked prefill        （04 章）
             干脆拆开部署   → PD 分离                （10 章）

外加一个贯穿全场的维度：
        模型太大，一张卡放不下 → TP / PP / EP / DP   （06、11 章）

★ 全教程的核心张力就一句话：
推理是在「单个用户等多久（延迟）」和「一张卡服务多少人（吞吐）」之间做交易。
几乎每一个优化技巧，都要先问它牺牲的是哪一头。13 章讲怎么把这两头量化。
