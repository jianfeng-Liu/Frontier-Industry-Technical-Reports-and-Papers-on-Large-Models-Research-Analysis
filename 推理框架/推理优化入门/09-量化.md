# 09 量化

> **一句话**：把数字存得更短。这是唯一一个**同时**打中「权重搬运量」和「KV Cache 大小」两个瓶颈的手段——所以它是投入产出比最高的优化。

---

## 9.1 量化在推理里为什么比在训练里重要得多

```
    训练：主要用 BF16，因为★ 反向传播对数值精度敏感，
          梯度是小量，精度不够会累积误差、训练发散。

    推理：★★ 只有前向，误差【不累积到梯度里】。
          而且 01 章说了，Decode 阶段是【访存受限】——
          ⟹ 权重从 16 位变 8 位，搬运量直接【减半】，速度直接【翻倍】

    ⟹ ★ 训练量化是「省显存」，推理量化是「省显存【并且】提速」。
       性质完全不同。
```

> 📖 **量化（quantization）**——用更少的比特表示同一个数值。
> BF16（16 位）→ FP8（8 位）→ INT4（4 位）。
> 每降一档，显存和搬运量减半。

---

## 9.2 三个可以独立量化的对象

初学者最容易混淆的一点：**「量化」这个词在不同语境下指的是不同的东西**。

```
┌─────────────┬────────────────────┬─────────────────────────────┐
│  量化对象    │  收益               │  难度                       │
├─────────────┼────────────────────┼─────────────────────────────┤
│ ① 权重      │ ★ 显存↓ + 搬运↓    │ ✅ 容易——权重是静态的，       │
│  (Weight)   │   ⟹ Decode 直接提速│    可以离线慢慢算最优量化点   │
├─────────────┼────────────────────┼─────────────────────────────┤
│ ② 激活值    │ ★ 能用上 INT8/FP8  │ ⚠️ 难——激活值随输入变化，     │
│ (Activation)│   的【计算单元】    │    而且有【离群值】（见 9.4） │
│             │   ⟹ 算力翻倍       │                             │
├─────────────┼────────────────────┼─────────────────────────────┤
│ ③ KV Cache  │ ★★ 直接决定并发数   │ ✅ 中等——FP8 几乎无损         │
└─────────────┴────────────────────┴─────────────────────────────┘
```

```
    ★★ 命名规则：常见的 W4A16、W8A8 就是在说前两项
       W4A16 = Weight 4 位、Activation 16 位   （只量化权重）
       W8A8  = Weight 8 位、Activation 8 位    （权重和激活都量化）

    ★ 为什么 W4A16 更常见？
      因为 Decode 是【访存受限】——瓶颈在搬权重，不在算。
      量化激活值只能提升算力，而算力本来就是空的。
      ⟹ ★ 只量化权重，就已经吃到了大部分收益。
      ⟹ 而 Prefill 是算力受限，W8A8 才对 Prefill 有意义。
```

> 🔑 **这解释了一个实践现象**：同一个 INT4 模型，Decode 快了一倍，Prefill 却几乎没变化。**不是量化没生效，是 Prefill 的瓶颈不在那儿。**

## 9.3 权重量化的两大流派

### ① GPTQ：逐层重建，用二阶信息补偿

> ✅ 论文 arXiv 2210.17323（`papers/GPTQ-Post-Training-Quantization-arXiv-2210.17323.pdf`）

```
    ★ 思路：一层一层地量化。每量化一个权重，就产生一点误差，
      ⟹ 立刻【调整这一层剩下还没量化的权重】去补偿这个误差。
      调整的方向用 Hessian（二阶导，海森矩阵）算出来。

    ✅ 优点：4 位下质量保持得很好
    ⚠️ 缺点：需要一批【校准数据】跑一遍；量化过程本身比较慢
```

### ② AWQ：★ 保护那 1% 的重要权重

> ✅ 论文 arXiv 2306.00978（`papers/AWQ-Activation-Aware-Quantization-arXiv-2306.00978.pdf`）

```
    ★★ AWQ 的核心观察（论文标题里的 Activation-aware 就是指这个）：
       权重的重要性，不看权重自己有多大，
       ★ 要看【和它相乘的那个激活值】有多大。

    ⟹ 只有约 1% 的权重通道是「重要」的
    ⟹ 把这些通道【放大】再量化（等价于给它们更多有效位），
       在下一层用一个缩放因子把它除回去
    ⟹ ★ 不需要反向传播，不需要重训，对校准数据不敏感
```

```
    ⟹ ★ 实践选择：AWQ 更快更稳，GPTQ 生态更老。
      两个 vLLM 都支持：
      ✅ [auto_awq.py](../源码/vLLM/vllm/model_executor/layers/quantization/auto_awq.py)
      ✅ [auto_gptq.py](../源码/vLLM/vllm/model_executor/layers/quantization/auto_gptq.py)
```

## 9.4 ★ 激活值量化的拦路虎：离群值

> ✅ SmoothQuant 论文 arXiv 2211.10438（`papers/SmoothQuant-arXiv-2211.10438.pdf`）

```
    ★★ 现象：大模型的激活值里，有极少数几个通道的数值
       比其他通道大【上百倍】。这叫【离群值（outlier）】。

    ⟹ 量化要把整个范围映射到 256 个格子（INT8）。
       如果范围被一个 100 倍的离群值撑开了，
       ★ 剩下 99% 的正常数值全都被挤进了前 2 个格子
       ⟹ 精度彻底崩掉
```

```
    ★★ SmoothQuant 的解法（一个非常优雅的技巧）：
       激活值难量化、权重好量化 ⟹ ★ 把难度【从激活转移一部分给权重】

       Y = (X · diag(s)⁻¹) · (diag(s) · W)
            └────┬─────┘     └─────┬────┘
            激活除以 s，变平滑    权重乘以 s，变陡一点
       ★ 数学上完全等价，但两边现在【都好量化了】
       ★ 而且 diag(s) 可以【离线融合进前一层】，运行时零开销
```

## 9.5 ★★ KV Cache 量化——对推理最直接的收益

这是三项里**对并发数影响最直接**的一项。回到 02 章的账：

```
    Llama-3-8B，BF16 KV：  每 token 128 KB
    ★ 换成 FP8 KV：        每 token  64 KB

    一张 H100 的 58 GB KV 空间：
      BF16 ⟹ 47.5 万 token
      FP8  ⟹ ★★ 95 万 token   ⟹ 并发数【直接翻倍】
```

```
    ★ 为什么 KV 量化几乎无损？（⚠️ 我的理解，非论文原文）
      ① KV 只被 softmax 加权求和消费，softmax 本身有归一化的平滑作用
      ② 误差不会像权重那样在层间【反复相乘放大】
    ⟹ 实践上 FP8 KV Cache 是「几乎白拿」的，很多部署默认就开
    ⚠️ 但 INT4 KV 就有明显损失了，尤其在长上下文任务上
```

> ✅ **源码可查**：vLLM 有专门的 KV 量化模块
> [quantization/kv_cache.py](../源码/vLLM/vllm/model_executor/layers/quantization/kv_cache.py)，
> 启动参数是 `--kv-cache-dtype fp8`。

## 9.6 硬件才是真正的裁判

**一个初学者最容易忽略的事实**：量化能不能提速，取决于**这张卡有没有对应的计算单元**。

```
┌──────────┬───────────────────────────────────────────────┐
│  精度     │  硬件支持情况                                  │
├──────────┼───────────────────────────────────────────────┤
│  BF16    │  A100 起全面支持                               │
│  ★ FP8   │  ★ H100 / H200 起【原生 Tensor Core 支持】     │
│          │  ⟹ 在 H100 上，FP8 是【最优选择】：            │
│          │    显存减半 + 算力翻倍 + 几乎无损               │
│  ★ MXFP4 │  ★ Blackwell (B200) 起原生支持                 │
│  INT4    │  ⚠️ 没有原生 INT4 Tensor Core                  │
│          │  ⟹ 实际做法：存 4 位，★ 算之前【解压回 16 位】  │
│          │  ⟹ 省了搬运（Decode 提速）✅                   │
│          │     但没省计算（Prefill 不提速）⚠️              │
└──────────┴───────────────────────────────────────────────┘
```

> ✅ vLLM 的量化目录直接反映了这个硬件版图：
> `fp8.py`、`input_quant_fp8.py`、`fbgemm_fp8.py`（FP8 一族）、
> `mxfp4.py`（Blackwell）、`moe_wna16.py`（MoE 专用的权重量化）、
> `experts_int8.py`、`torchao.py`、`modelopt.py`（对接 NVIDIA 的量化工具链）。
> ★ 从文件数量就能看出：**FP8 是当前的主战场**。

## 9.7 怎么选——一张决策表

⚠️ 以下是经验法则，不是论文结论：

```
    ★ 有 H100/H200，追求稳妥          ⟹ FP8 权重 + FP8 KV Cache
      （几乎无损，显存减半，算力翻倍，是当前的默认答案）

    ★ 卡是 A100，显存不够            ⟹ AWQ / GPTQ 的 W4A16
      （A100 没有 FP8 单元，只能靠 INT4 省搬运）

    ★ 单卡放不下，想避免上多卡通信    ⟹ 先量化，再考虑 TP（回收 06 章 §6.6）

    ★ 并发数是瓶颈（而不是模型放不下）⟹ ★ 优先量化 KV Cache，
      这比量化权重对并发的帮助更直接

    ⚠️ 任何量化上线前都要跑一遍你【自己场景】的评测。
       论文里的困惑度（perplexity）持平，不代表你的业务指标持平。
```
