## 三条贯穿全书的主线

读的时候留意这三条线，它们在多章之间反复呼应：

```
    ★ 主线一：「让搬一次权重干更多活」
      01 提出 → 02 说明障碍 → 05/07/09 移除障碍 → 08 换个方向 → 13 验证

    ★ 主线二：「Prefill 和 Decode 性格相反」
      03 提出 → 04 混合批（同机共处）→ 09 两阶段量化收益不同
      → 10 PD 分离（干脆拆开）→ 12 两种批次两种图模式 → 13 分别看 MFU/MBU

    ★★ 主线三：「通信量大的维度放最近」
      这是从 [训练框架](../../训练框架/) 带过来的唯一原则，它【没有变】。
      变的是各维度的通信量：
        训练 DP 要 all-reduce 2Ψ 梯度 ⟹ 贵 ⟹ 必须近
        推理 DP 是独立副本，通信为 0  ⟹ 免费 ⟹ 可以最远
      ⟹ ★ 同一条原则，推出了相反的排布。这就是 06 章的全部内容。
```

## 两个反复出现的「失效规律」

```
    ⚠️ 规律一：★★【填补空闲的优化，在忙碌时都会失效】
       投机解码（08）：高并发时算力不空闲 ⟹ 负收益
       CUDA Graph（12）：大 batch 时 kernel 够大 ⟹ 收益消失
       ⟹ 这两个必须按负载动态开关，不能一开了之

    ⚠️ 规律二：★★【省显存的优化，彼此会抢同一块显存】
       CUDA Graph 的缓冲区、前缀缓存的驻留块，
       都是从 KV Cache 的池子里扣的
       ⟹ ★ 开了会降低并发数，要算总账
```
