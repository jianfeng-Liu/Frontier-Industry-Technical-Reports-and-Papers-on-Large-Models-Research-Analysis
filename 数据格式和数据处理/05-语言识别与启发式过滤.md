# 05 · 语言识别与启发式过滤

> **流水线上最便宜的一刀，也是砍掉份额最大的一刀。**
> 这一章全是"规则"，没有模型，没有数学——但它决定了后面所有昂贵步骤要处理多少数据。
>
> ⚠️ **本章数字口径（后面几章沿用）**：容量一律用**十进制**，1 GB = 10⁹ 字节、1 TB = 10¹² 字节；需要二进制单位时写 GiB / TiB（1 GiB = 2³⁰ 字节，比 1 GB 大 7.4%；1 TiB 比 1 TB 大 10%）。**"字符""字节""token"是三个不同的东西**，本章凡是用到都会写明是哪一个——见 5.5 节，在中文上这三者能差到三倍。

## 5.1 为什么第一刀必须用规则，而不是模型

先算一笔账。⚠️ 下面的页面数是量级估算：Common Crawl 每月做一次快照，**公开的月度统计里页面数在 20 亿~35 亿之间浮动**，这里取 25 亿当代表值。

```
输入规模：一次 Common Crawl 快照 ≈ 25 亿个网页

假设用一个小模型给每篇打分：
    一篇 1 毫秒（已经很快了）
    → 2.5e9 篇 × 1 ms = 2.5e6 秒 = 28.9 天 × 单机单核
    → 就算 1000 路并行，也要 2.5e6 / 1000 = 2500 秒 ≈ 42 分钟，而且要 1000 块 GPU

而一条正则 / 一次计数：
    一篇 10 微秒
    → 2.5e9 × 10 us = 2.5e4 秒 = 6.9 小时 × 单机单核
    → 100 倍便宜，而且纯 CPU，不占 GPU

★★ 所以流水线的顺序是【固定的、由成本决定的】：
      便宜的规则先跑，把量砍下来 → 昂贵的模型后跑
   这个原则叫【级联过滤 cascade】，在整个领域里到处都是。
```

成本梯度（⚠️ **以下单篇耗时全是我的量级估算，不是实测值**，只用于建立"差几个数量级"的直觉）：

| 手段 | 量级耗时 / 篇 | 算力类型 | 在哪一章 |
|---|---|---|---|
| 正则 / 计数 | ~ 10 μs | CPU | ★ 本章 |
| 语言识别 fastText | ~ 50 μs | CPU | ★ 本章 |
| MinHash 签名 | ~ 1 ms | CPU | [06 章](06-去重.md) |
| 困惑度（小 n-gram 语言模型） | ~ 5 ms | CPU | [07 章](07-质量过滤.md) |
| 轻量分类器（BERT 级） | ~ 20 ms | GPU | [07 章](07-质量过滤.md) |
| 大模型打标签 | ~ 1 s | GPU | [07 章](07-质量过滤.md)（所以必须蒸馏成小模型） |

> ★ **跨度 5 个数量级**（10 μs → 1 s，10⁵ 倍）。顺序错了，总成本差几百倍：先用大模型给 25 亿篇打标签、再用正则把 90% 砍掉，等于 90% 的 GPU 钱白烧。

## 5.2 语言识别（LID）

**LID** = **Language IDentification**（语言识别），判断一段文字是哪种语言。

### 为什么必须先做

```
① 后面几乎所有规则都是【语言相关】的
   "平均词长 > 10 就丢掉" —— 对英文合理，对德文误杀，对中文毫无意义
   "标点占比" —— 中文用「，。」英文用「,.」，判断逻辑不同
   ★ 所以必须先分流，再按语言各走各的规则

② 配比是按语言定的（"中文 30% 英文 60%"），不识别就没法配（见 10 章）

③ 大量网页是【机器翻译】或【乱码混杂】的，LID 的置信度分能顺手筛掉
```

### 怎么做：fastText

**fastText** 是 Facebook（现 Meta）开源的一个轻量文本分类库。它的语言识别模型 `lid.176.bin` 认 176 种语言，**文件约 126 MiB（≈ 132 MB；⚠️ 官方页面只写 "131 MB"，没声明是十进制还是二进制口径）**，单条判断几十微秒，是这个领域事实上的标准。

原理很简单，不需要神经网络的直觉也能懂：

```
① 把文本切成【字符 n-gram】（连续的 n 个字符）
      "hello world" → "hel","ell","llo","lo ","o w",...

② 每个 n-gram 查一个 embedding 向量，全部【求平均】
      ★ 注意：只是平均，没有顺序、没有注意力 —— 所以极快

③ 平均向量过一个线性分类器 + softmax → 176 个语言的概率

为什么有效：不同语言的字符组合分布差别巨大
      "th","he","in" → 强烈的英文信号
      "de","la","es" → 西班牙/法语信号
      汉字本身 → 中文信号
```

### 用法与阈值

```python
import fasttext
model = fasttext.load_model("lid.176.bin")

def detect(text):
    # ★ 必须先把换行去掉，fastText 用 \n 分隔样本
    labels, probs = model.predict(text.replace("\n", " "), k=1)
    return labels[0].replace("__label__", ""), probs[0]

lang, score = detect(doc["text"])
if lang == "en" and score >= 0.65:      # ✅ FineWeb 用的就是 0.65
    keep(doc)
```

> ✅ **FineWeb 的阈值是 0.65。** 论文原话（我从 [papers/FineWeb-Decanting-the-Web-arXiv-2406.17557.pdf](papers/) 里核对过）是 "applied a fastText language classifier ... to keep only English text with a score >= 0.65"。

阈值怎么取舍，一张表说完（⚠️ "会留下 / 会丢掉"两列是我的归纳，不是论文里的实测分档）：

| 阈值 | ★ 会留下什么 | ⚠️ 会丢掉什么 |
|---|---|---|
| **0.4 左右（宽松）** | 多语言混排的技术博客、注释夹英文的中文页面 | 几乎不丢——代价是**混进乱码、机翻、语言拼盘** |
| **0.65（FineWeb）** | 主体语言明确的正常文档 | 中英混排较重的技术文档、双语对照页 |
| **0.9 以上（严格）** | 纯度很高的单语文档 | ★ 大量真实可用的技术内容。**不推荐**，除非下游确定只要单语 |

> ⚠️ **0.6~0.7 是常见区间。** 更重要的一句：**阈值不是独立旋钮。** 调高 LID 阈值等于提前砍掉一批多语言技术文档，而这批文档往往正是 [07 章](07-质量过滤.md)的质量分类器最想要的——两个环节的取舍会互相抵消，必须一起看。

### 三个坑

```
① ★ 代码文件会被判成各种奇怪的语言
   Python 代码常被判成英文（因为关键字是英文），也可能被判成别的
   → 代码源【不要过 LID】，单独走一条线

② 短文本极不准
   < 50 字符的文本，LID 基本靠猜 → 通常先按长度过滤再做 LID

③ 简繁体 / 方言 / 罗马化
   lid.176 把中文当一类，不区分简繁；粤语、闽南语支持很差
```

## 5.3 ★ 启发式规则：三代规则集

"启发式（heuristic）"就是**人拍脑袋想出来、但确实管用的经验规则**。这个领域有三套被反复引用的规则集。

★ 下面每一代都用**同一张表的格式**：**它拦掉什么**（这条规则存在的理由）和**它误杀什么**（这条规则的代价）。⚠️ 两列里带 ✅ 的是论文明说的，其余是我的归纳——**"误杀什么"这一列几乎没有论文会写**，但它才是你上线后真正会被投诉的地方。

### 第一代：C4 规则（2019，[arXiv:1910.10683](https://arxiv.org/abs/1910.10683) 附录）

C4 是 Google T5 论文里构建的语料，它的规则是这个领域的起点。✅ 论文里明确列出的那几条：

| ✅ C4 规则 | ★ 它拦掉什么 | ⚠️ 它误杀什么 |
|---|---|---|
| 只保留**以句末标点结尾**的行（`.` `!` `?` `"`） | 导航栏、按钮文字、标签云、商品属性行 | ★★ 代码、列表、表格、诗歌、字幕、API 文档——**全灭** |
| 丢掉**少于 5 句话**的页面 | 空壳页、跳转页、"页面不存在" | 短定义条目、单条 FAQ、词典页 |
| 只保留**至少 3 个词**的行 | 单词按钮行、分隔符行 | 标题行；⚠️ 中文按空格切常常只得到 1 个"词"→ 整篇全删 |
| 丢掉含**脏词表**里任何词的页面 | 色情站 | ⚠️ **系统性删掉 LGBTQ、医学、法律、性教育内容**——这条后来被广泛批评 |
| 丢掉含 `javascript` 字样的**行** | "请开启 JS"提示条 | 讲 JavaScript 的技术文章里的正文行 |
| 丢掉含 `lorem ipsum` 的页面 | 没上线的模板页（`lorem ipsum` 是排版占位文） | 讲排版 / 印刷史的文章 |
| 丢掉含 `{` 的**页面** | 泄漏的模板代码、CSS 残留 | ★★ **所有代码页面**——见下 |
| 丢掉含 `terms of use` / `privacy policy` / `cookie` 的**行** | 页脚样板文 | 讲隐私合规、讲 GDPR 的文章 |

> ★ 那条"丢掉含 `{` 的页面"是 C4 一个著名的副作用：**C4 里几乎没有代码。** 后来大家发现代码对推理能力很重要，这条规则就成了反面教材。
>
> ⚠️ 我的归纳：**C4 规则的时代特征是"宁可错杀"**——2019 年数据管够，纯度比数量重要。到了 2024 年数据不够用了，风向就反过来了（见 [12 章](12-合成数据.md) Nemotron-CC 主动放松过滤）。

### 第二代：Gopher 规则（2021，DeepMind）

Gopher 的规则更"统计化"，不看具体词，看**分布特征**。⚠️ 下面这组阈值在业界被广泛复用（FineWeb、Dolma、RefinedWeb 都实现了 Gopher 系规则），**具体数值以各自实现为准**。

**文档级规则：**

| 规则 | 丢掉的条件 | ★ 它拦掉什么 | ⚠️ 它误杀什么 |
|---|---|---|---|
| 词数 | 不在 `[50, 100000]` | 空壳页；被拼接成一坨的整站 dump | 短定义、短问答；⚠️ **中文按空格分词后词数几乎总是 < 50 → 全灭** |
| 平均词长 | 不在 `[3, 10]` | base64 残留、乱码、丢了空格的粘连文本 | 德语复合词、化学式、URL 密集的文档 |
| 含 `#` 的行占比 | > 10% | markdown 目录页、标签墙 | 讲 C 预处理器 / markdown 语法 / Shell 注释的文章 |
| 以省略号结尾的行占比 | > 30% | ★ **"阅读全文…"列表页**——量最大的一类 | 对话体小说、剧本里的省略号 |
| 以项目符号开头的行占比 | > 90% | 纯列表页、站点地图 | 要点式笔记、API 参数清单、变更日志 |
| 含字母的词占比 | < 80% | 纯数字表格、价目表 | 数据表、财报、体育比分、化学/数学内容 |
| 停用词个数（the/be/to/of/and…） | < 2 个 | 关键词堆砌页、导航栏、非自然语言 | ⚠️ **中文文档一个英文停用词都没有** → 必须换中文停用词表 |

**重复度规则（★ Gopher 最有价值的部分）：**

| 规则 | 丢掉的条件 | 它抓的具体形态 |
|---|---|---|
| 重复**行**占比 | > 30% | 同一行在本篇里出现多次（页脚、"立即购买"按钮行） |
| 重复**段落**占比 | > 30% | 同一段在本篇里出现多次（多次贴上的免责声明） |
| 最高频 **2-gram** 占比 | > 20% | 一个词组被刷屏（"包邮 包邮 包邮…"） |
| 重复 **5-gram** 占**总字符数** | > 15% | 一个短语被反复嵌进不同句子（SEO 关键词注入） |

> ★★ **重复度那一组特别重要，它抓的是"文档内部重复"，和 [06 章](06-去重.md)的"文档之间重复"是两回事，极易混。**
> 例子：一个商品页把"包邮 正品保证 七天退换"重复了 200 遍。它和别的文档都不重复（去重抓不到它），但它本身没有任何信息量。
> ⚠️ 注意最后一行的口径是**占总字符数**，不是占词数——这两个分母在中文上差三倍，见 5.5 节。

### 第三代：FineWeb 自己加的三条（2024）

✅ FineWeb 论文报告，他们在 C4 + Gopher 之上又加了几条自研过滤器，其中效果最好的三条大意是：

| ✅ FineWeb 自研规则（方向性描述） | ★ 它拦掉什么 | ⚠️ 它误杀什么 |
|---|---|---|
| 行末不带标点的行占比过高 → 丢 | 表格残骸、字段列表、属性墙 | 代码、诗歌、歌词、字幕 |
| 极短行（< 30 字符）占比过高 → 丢 | 菜单、面包屑导航、评论计数行 | 对话体文本、聊天记录、剧本 |
| 重复行的**字符数**占比过高 → 丢 | 页脚被重复贴上的样板文 | 带重复表头的长表格 |

⚠️ 具体阈值请以 [papers/FineWeb-Decanting-the-Web-arXiv-2406.17557.pdf](papers/) 为准；我这里只保留方向性描述，避免转述出错。

> ★ 对照着看三代的差别，这条演进线很清楚：**C4 看具体词 → Gopher 看分布统计 → FineWeb 看行级形态**。判据一代比一代"不依赖语言知识"，因此一代比一代好迁移到中文——但没有一代是**天生**适配中文的，5.5 节会讲要改什么。

## 5.4 ★★ 逐步推演：拿一段脏文本，看它在第几条被拦下

上面三张表都是"规则说明书"。下面把一段**真实感的脏文本**完整走一遍，每一条规则算出具体数值、和阈值比一比。✅ **下面每一个数字我都在本机跑过一遍**，不是估算。

**输入（一个很典型的电商列表页，12 个非空行）：**

```
Best Laptop Deals 2024 | Top 10 Picks
Home | Shop | Blog | Contact | About Us | Login
Dell XPS 13 - Great value, free shipping, 7-day returns…
HP Pavilion 15 - Great value, free shipping, 7-day returns…
Lenovo ThinkPad E14 - Great value, free shipping, 7-day returns…
Asus VivoBook 14 - Great value, free shipping, 7-day returns…
Acer Aspire 5 - Great value, free shipping, 7-day returns…
MSI Modern 14 - Great value, free shipping, 7-day returns…
Read more…
Read more…
Read more…
Terms of use | Privacy policy | Cookie settings
```

**先量三个基数**（后面所有占比的分母都来自这里，★ 分母是什么必须写清，否则同一条规则两个人算出两个结果）：

| 基数 | 值 | 怎么来的 |
|---|---|---|
| 非空行数 `n_l` | **12** | 按 `\n` 切，去掉空行 |
| 空格分词后词数 `n_w` | **95** | `text.split()`，`\|` 这种分隔符也算一个"词" |
| 总字符数 `n_c` | **528** | Unicode 码位数（⚠️ 不是字节数，这段纯 ASCII 所以两者恰好相等） |

**逐条过：**

| # | 规则 | 算出来的值 | 阈值 | 结果 |
|---|---|---|---|---|
| ① | 词数 ∈ `[50, 100000]` | 95 | 在区间内 | 通过 |
| ② | 平均词长 ∈ `[3, 10]` | 528 字符 ÷ 95 词 ≈ **4.57** | 在区间内 | 通过 |
| ③ | 停用词 ≥ 2 个 | 只命中 **1** 个（`of`，来自 `Terms of use`） | < 2 | ★ **拦下** |
| ④ | 以省略号结尾的行占比 ≤ 30% | **9 / 12 = 75%** | > 30% | **拦下** |
| ⑤ | 以项目符号开头的行占比 ≤ 90% | 0 / 12 = 0% | ≤ 90% | 通过 |
| ⑥ | 无句末标点的行占比 ≤ 70% | **12 / 12 = 100%** | > 70% | **拦下** |
| ⑦ | 重复**行**多占的字符占比 ≤ 30% | `Read more…` 重复 3 次 → 多占 2 × 10 = 20 字符 → **20 / 528 ≈ 4%** | ≤ 30% | 通过 |
| ⑧ | 最高频 5-gram 覆盖的字符占比 ≤ 15% | `- Great value, free shipping,` 出现 **6** 次，6 × 29 = 174 → **174 / 528 ≈ 33%** | > 15% | **拦下** |

**★★ 三个必须从这张表里读出来的结论：**

```
① 它在第 ③ 条就被拦下了 —— 停用词不够。
   ★ 但另外还有 ④ ⑥ ⑧ 三条也会单独拦住它。
   ⟹ 这一篇被【四条规则同时命中】。

② ⑦ 和 ⑧ 抓的是两种不同的重复，看数值就知道：
   ⑦ 重复【行】：只有 4%  ← "Read more…" 虽然重复 3 次，但行太短，占不了几个字符
   ⑧ 重复【5-gram】：33%  ← "- Great value, free shipping," 嵌在 6 个不同的行里
   ⟹ ★ 只做行级去重会放过 ⑧ 这一类，这就是 Gopher 要同时做两套的原因。

③ ⑥ 这一条是 100% —— 整篇一行都不以句末标点结尾。
   ★ 这就是 C4 那条"只保留以句末标点结尾的行"为什么极其有效：
     列表页天生不带句号。
   ⚠️ 也正因为它太有效，代码和表格跟着一起死。
```

> ★★ **因此有一条实践铁律：统计"被哪条规则拒掉"时，必须记录【全部命中的规则】，不能只记第一条。**
> 如果只记第一条，上面这篇会被归到 ③ 停用词 名下，于是你的报表会说"停用词规则砍掉了 X%"——而其实把 ③ 关掉，这篇一样会被 ④⑥⑧ 砍掉，**总量一点不变**。
> ⚠️ 这是一个真实的决策陷阱：**按"只记第一条"的报表去删规则，你会以为删掉某条能救回很多数据，实际上救回来的接近于零。**

### 一段能跑的实现

★ 注意这段代码和上一节的推演是严格对应的：它返回**所有**被违反的规则名，而不是第一条。

```python
import re
from collections import Counter

STOPWORDS_EN = {"the", "be", "to", "of", "and", "that", "have", "with"}
END_PUNCT = (".", "!", "?", '"', "。", "！", "？", "”")

def heuristic_check(text, lang="en"):
    """返回【所有】被违反的规则名；返回空列表 = 保留。"""
    lines = [l for l in text.split("\n") if l.strip()]
    words = text.split()
    n_w, n_l = len(words), len(lines)
    n_c = max(len(text), 1)                 # ★ 字符数，占比的分母，别和词数混用
    if n_w == 0 or n_l == 0:
        return ["empty"]

    bad = []
    # ---- ① 长度 ----
    if not (50 <= n_w <= 100_000):
        bad.append("word_count")

    # ---- ②③ 只对空格分词的语言有意义 ----
    if lang in ("en", "de", "fr"):
        if not (3 <= sum(len(w) for w in words) / n_w <= 10):
            bad.append("avg_word_len")
        norm = {w.strip(".,|-").lower() for w in words}
        if len(STOPWORDS_EN & norm) < 2:
            bad.append("no_stopwords")

    # ---- ④⑤⑥ 行级形态 ----
    if sum(l.rstrip().endswith(("…", "...")) for l in lines) / n_l > 0.30:
        bad.append("ellipsis_lines")        # ★ 抓"阅读全文…"列表页
    if sum(l.lstrip().startswith(("•", "-", "*", "·")) for l in lines) / n_l > 0.90:
        bad.append("bullet_lines")
    if sum(not l.rstrip().endswith(END_PUNCT) for l in lines) / n_l > 0.70:
        bad.append("no_terminal_punct")

    # ---- ⑦ 重复【行】多占的字符数 / 总字符数 ----
    dup_chars = sum(len(l) * (c - 1) for l, c in Counter(lines).items() if c > 1)
    if dup_chars / n_c > 0.30:
        bad.append("dup_lines")

    # ---- ⑧ 最高频 5-gram 覆盖的字符数 / 总字符数 ----
    grams = [" ".join(words[i:i + 5]) for i in range(max(n_w - 4, 0))]
    if grams:
        top_gram, top_cnt = Counter(grams).most_common(1)[0]
        if top_cnt * len(top_gram) / n_c > 0.15:
            bad.append("dup_5gram")

    return bad
```

> ★ **实践建议：把 `bad` 这个列表落盘，按规则名做计数，每天看一张表。**
> 每条规则各砍掉多少、和别的规则重叠多少，是调流水线唯一可靠的抓手。
> ⚠️ 一个真实的失败模式：某条规则因为一个 bug 砍掉了 80% 的数据，而你只看总量的话完全发现不了——因为总量本来就该掉 80%~90%。

## 5.5 中文特有的问题

### 先把三个容易混的单位分清

★★ 这一节的所有坑都源自同一件事：**上面的规则默认"词"是靠空格切出来的，而中文不打空格。** 顺带把三个单位一次性说清，后面几章都要用：

| 单位 | 定义 | "深度学习模型" 这 6 个字 | "deep learning model" |
|---|---|---|---|
| **字符** | Unicode 码位个数 | **6** | 19（含 2 个空格） |
| **字节** | UTF-8 编码后的字节数 | **18**（★ 常用汉字在 UTF-8 下是 **3 字节/字**） | 19（ASCII 是 1 字节/字符） |
| **token** | 分词器切出的单元个数 | ⚠️ 约 **3~4 个**（1 个 token 常覆盖 1~2 个汉字，随分词器变，见 [09 章](09-Tokenizer与词表.md)） | 约 3 个 |
| **空格分词的"词"** | `text.split()` 的结果数 | ★ **1 个**（整段算一个"词"！） | 3 个 |

> ★★ **请把最后一行读两遍。** 一段 500 字的中文文章，`text.split()` 往往只切出三五个"词"，平均"词长"一百多——于是 Gopher 的**词数规则和平均词长规则同时判死它**。这不是"效果差"，是**整条规则在中文上的行为完全颠倒了**。
>
> ⚠️ 由此派生出一个报数陷阱：说"我们的中文语料有 1 T"，必须问清是 **1 T 字符**、**1 T 字节**还是 **1 T token**。按上表，同一份中文语料的字节数约是字符数的 3 倍、token 数约是字符数的 0.5~0.7 倍——**最大最小两个口径之间差 4~6 倍。**

### 五条规则的中文改法

| 英文规则 | 英文上的作用 | ⚠️ 直接搬到中文会怎样 | ★ 中文替代做法 |
|---|---|---|---|
| 词数 ∈ `[50, 100000]` | 砍空壳页 | 几乎每篇都 < 50 → **全灭** | 改成**字符数** ∈ `[100, 200000]` |
| 平均词长 ∈ `[3, 10]` | 抓乱码、粘连文本 | 平均词长动辄 100+ → **全灭** | 改成**标点密度** = 标点字符 / 总字符，正常中文约在 2%~20% |
| 停用词 ≥ 2 个 | 抓非自然语言 | 一个英文停用词都没有 → **全灭** | 换中文停用词表（的 / 了 / 在 / 是 / 和 / 就 / 不 / 都 / 一 / 有） |
| 以句末标点结尾的行 | 抓导航栏 | 只判 ASCII `. ! ?` → 中文全被判"不以标点结尾" → **全灭** | 标点表必须含 `。！？；：""》）` |
| 项目符号 `• - * ·` 开头 | 抓纯列表页 | 中文列表用 `一、` `1．` `（1）` `①` | 补全角序号和中文数字序号的前缀表 |

> ⚠️ **"只判 ASCII 标点"这个 bug 是真的常见**，而且它的症状是**中文分片的留存率接近 0**——如果你看到某个语言分片留存率异常低，先怀疑标点表。

### 中文互联网特有的垃圾形态

```
① 采集站 / 伪原创（同义词替换过的洗稿）
   → 06 章的近似去重能抓一部分，精确去重完全抓不到

② 小说站的分章页（每页只有几百字正文 + 大段导航）
   → 字符数规则 + 行级形态规则配合才能抓

③ ★ 全角空格和不可见字符插入（专门用来绕过平台查重）
   → ★★ 必须做 Unicode 归一化 + 零宽字符清除，否则后面的去重会【静默失效】

④ 简繁混排、全角半角混排
   → 需要 Unicode 归一化（NFKC）
```

**NFKC** = **Normalization Form KC**（Unicode 兼容分解 + 标准合成），作用是把"全角 Ａ"和"半角 A"、"①"和"1"这类**看起来不同但语义相同**的字符统一掉。

```python
import unicodedata, re

# ★ 零宽字符：U+200B~U+200F、U+202A~U+202E、U+FEFF
ZERO_WIDTH = re.compile(r"[​-‏‪-‮﻿]")

def normalize_zh(text):
    text = ZERO_WIDTH.sub("", text)             # ★ 必须先清零宽字符，再做别的
    text = unicodedata.normalize("NFKC", text)  # 全角→半角、兼容字符归一
    text = re.sub(r"[ \t]+", " ", text)
    text = re.sub(r"\n{3,}", "\n\n", text)
    return text.strip()
```

> ⚠️ **零宽字符这一条我特别想强调**：内容农场会在正文里插入零宽空格来绕过平台查重。如果不清掉，**你的 MinHash 去重（[06 章](06-去重.md)）会认为两篇一模一样的洗稿文是不同文档**，于是全部留下来。
> ★ 这是一个**静默失效**的坑：去重程序没报错、没告警，留存率看起来也正常，但它实际上什么都没去掉。

## 5.6 挂回真实系统

| 语料 | LID | 启发式规则 |
|---|---|---|
| **C4** | langdetect | ✅ 自己那套（句末标点、脏词表、`{`） |
| **CCNet** | fastText | 轻量规则 + ✅ **困惑度**（见 [07 章](07-质量过滤.md)） |
| **RefinedWeb** | fastText | ✅ 明确采用 Gopher 系规则 + 行级修正 |
| **Dolma** | fastText | Gopher 系 + C4 系（✅ 全流程开源可复现） |
| **FineWeb** | ✅ fastText，阈值 **0.65** | ✅ C4 + Gopher + **自研三条** |
| **Nemotron-CC** | — | ✅ **主动放松**启发式规则以保留更多唯一 token |

> ★ 注意最后一行的方向反转：**Nemotron-CC 明确主张放松过滤**，理由是长周期训练（15 T token 以上）时，**唯一 token 的数量比纯度更值钱**——因为数据不够就得重复，而重复的边际收益递减（[11 章](11-喂多少-ScalingLaw.md)）。这是 2024 年之后的新共识方向之一，[07 章](07-质量过滤.md)会给它的具体数字。

**一个可以校核的留存率数字**（✅ 我从 [papers/Dolma-Open-Corpus-of-Three-Trillion-Tokens-arXiv-2402.00159.pdf](papers/) 里核对过原文）：

```
Dolma 论文转述 CCNet 流水线的整体效果：
    "filters out 84.2% of the content in Common Crawl, from 175.1 TB to 27.7 TB"

★ 自己验一遍：1 − 27.7 / 175.1 = 1 − 0.1582 = 84.18%  ✅ 和论文的 84.2% 一致
⚠️ 口径提醒：论文只写了 "TB"，没说是十进制 TB 还是二进制 TiB。
   如果原意是 TiB，换算成十进制 TB 是 192.5 → 30.5 ——
   ★ 比例不变（84.2%），但绝对值差 10%。报绝对容量时务必声明口径。
```

## 5.7 小结

```
① ★★ 流水线顺序由【成本】决定：便宜的规则先跑砍量，昂贵的模型后跑
   成本跨度 5 个数量级（正则 ~10 μs → 大模型打标 ~1 s，⚠️ 量级估算）

② 语言识别（LID = Language IDentification）必须最先做，
   因为后面的规则全是语言相关的
   工具：fastText lid.176.bin（176 种语言，约 126 MiB），几十微秒一条
   ✅ FineWeb 阈值 0.65（论文原文核对过）
   坑：代码别过 LID；短文本不准；不区分简繁
   ★ 阈值不是独立旋钮：调高 LID 阈值会提前砍掉 07 章想要的多语言技术文档

③ 三代启发式规则集，每一代都要同时看【拦掉什么】和【误杀什么】：
   C4（2019）    —— 看具体词和标点，宁可错杀
                    ★ "丢掉含 { 的页面" 把代码全删了，著名反面教材
   Gopher（2021）—— 看分布统计 + ★【文档内部重复度】
   FineWeb（2024）—— 看行级形态，再加自研三条

④ ★★ 5.4 节的推演给出两条硬结论：
   · 一篇垃圾通常被【多条规则同时命中】（例中被 ③④⑥⑧ 四条同时拦下）
   · ⟹ 统计必须记录【全部命中的规则】，只记第一条会让你误判
     "删掉某条规则能救回很多数据"——实际上救回来的接近于零

⑤ ★ 区分两种"重复"，极易混淆：
   文档【内部】重复 —— 一句话在同一篇里重复 200 遍  → 本章的 Gopher 规则
   文档【之间】重复 —— 两篇文档一模一样            → 06 章的去重
   ★ 而文档内部重复又分【行级】和【n-gram 级】，5.4 的例子里一个是 4%、
     一个是 33% —— 只做行级会放过后者

⑥ ★★ 三个单位必须分清（中文上差 4~6 倍）：
   字符（Unicode 码位） / 字节（UTF-8，汉字 3 字节） / token（约 1~2 汉字）
   ⟹ 报"语料有 1 T"时必须声明是哪一个
   ⟹ 中文要单独一套规则：字符数代替词数、标点密度代替平均词长、
      中文停用词表、中文句末标点表

⑦ ★ Unicode 归一化（NFKC）+ 零宽字符清除是【必做前置】，
   否则洗稿文的去重会【静默失效】：不报错、不告警、也没去掉任何东西
```
