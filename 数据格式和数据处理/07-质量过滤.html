07 · ⭐ 质量过滤：从"数规则"到"用模型打分"

05 章的规则回答的是"这是不是一段正常的文字"。
这一章回答的是一个更难、也更主观的问题："这段文字值不值得学"。

★ 这是整条流水线上最没有共识、各家差距最大的一环。

7.1 先承认一件事：没人知道"质量"是什么

下面哪一篇"质量高"？

  A. 一篇写得很好的明星八卦报道
  B. 一篇语法糟糕但讲清楚了某个 API 用法的技术问答
  C. 一段法律条文
  D. 一条 Reddit 上的口语化闲聊

★ 答案是：【取决于你想要模型会什么】
   要写作流畅 → A 有用
   要能答技术问题 → B 有用
   要口语自然 → D 有用

所以业界实际用的"质量"定义，几乎全都可以翻译成同一句话：

★★ "质量高" ≈ "长得像我心目中的好文本"。
你先挑一批种子样本当作"好"的标准，然后训一个分类器去找长得像种子的网页。

⚠️ 于是：质量过滤的效果，几乎完全由"你挑了什么当种子"决定。 这是本章最重要的一句话。

还有一个更麻烦的问题：怎么知道你的过滤器管用？

唯一真正可靠的验证方式：
   用过滤后的数据【训一个模型】，看下游评测分

  ⟹ 一次实验 = 训一个模型 = 几万到几十万美元
  ⟹ ★ 所以质量过滤是整条流水线上【反馈最慢、最贵】的一环

业界的应对（三个层次）：

① 代理模型（proxy model）
   用 1 亿 ~ 10 亿参数的小模型跑 ablation，假设结论能外推到大模型
   ⚠️ 这个假设【不总是成立】——小模型上有效的过滤，大模型上可能收益消失

② 标准化评测台
   ✅ DCLM（[2406.11794](https://arxiv.org/abs/2406.11794)）最大的贡献其实不是数据集，
      而是它把"数据过滤"变成了一个【有统一评测协议的公开竞赛】：
      固定模型、固定算力、只让你改数据 → 分数直接可比
   ★ 在此之前，各家说"我的数据更好"是没法互相验证的

③ 更便宜的验证信号
   ✅ Ultra-FineWeb（[2505.05427](https://arxiv.org/abs/2505.05427)）的核心贡献就是这个：
      提出一套【高效验证】策略，先低成本判断"种子数据靠不靠谱"，
      再去训分类器 —— 避免了"训模型→评测→改过滤器"这个昂贵的大循环

7.2 ★ 四代方法，一条清晰的演进线

第一代（2019）  数规则         ← 05 章
   "少于 5 句话就丢"

第二代（2019）  困惑度         ← 7.3  CCNet
   "拿维基百科训个语言模型，看这段文字它觉得有多意外"

第三代（2023-24）轻量分类器    ← 7.4  DCLM / FineWeb-Edu / Nemotron-CC
   "挑一批好样本当正例，训个 fastText / BERT 打分"

第四代（2025）  大模型打标签   ← 7.5  Essential-Web
   "让大模型给每篇文章打一整套结构化标签，再蒸馏成小模型"

★★ 这条线的方向非常一致：
   【判据越来越像"人的判断"，成本越来越高 → 于是必须不断蒸馏回小模型】

7.3 第二代：困惑度过滤（CCNet）

✅ CCNet（arXiv:1911.00359，Wenzek 等，Facebook，2019-11）。

困惑度（perplexity, PPL） 先解释清楚：

一个语言模型看一段文字，会对每个词给出"我预测它出现的概率"。
困惑度 = 这些概率的几何平均的倒数。

    PPL(x) = exp( − (1/T) · Σ_{t=1..T} log P(x_t | x_<t) )

★ 一句话：【困惑度低 = 这段文字对模型来说"意料之中"、"眼熟"】
                    ↑ 注意，这是"眼熟"，不是"正确"，7.3 末尾会讲这个坑

CCNet 的做法：

① 在【维基百科】上训一个 5-gram 的 Kneser-Ney 语言模型（用 KenLM 工具）
   ★ 为什么用 n-gram 而不是神经网络？因为要处理几十亿篇文档 —— 必须极快
   ★ 为什么用维基百科？因为它是"标准书面语"的现成代表

② 给每个段落算困惑度

③ ✅ 按困惑度把语料【三等分】：
      head    （困惑度最低的 1/3）—— 最像维基百科
      middle  （中间 1/3）
      tail    （困惑度最高的 1/3）—— 最不像

④ ★ 论文并不是简单地"只要 head"。它把三档都发布出来，
   让下游自己决定用哪些 —— 因为"像维基"不等于"有用"

import kenlm
model = kenlm.Model("wiki_5gram.arpa")     # 在维基上训好的 n-gram LM

def perplexity(text):
    # kenlm 返回 log10 概率
    logp = model.score(text, bos=True, eos=True)
    n = len(text.split()) + 1
    return 10 ** (-logp / n)

ppl = perplexity(doc["text"])
bucket = "head" if ppl < TH_LOW else ("tail" if ppl > TH_HIGH else "middle")

⚠️ 困惑度过滤的两个致命坑，必须知道：

```
① ★ 低困惑度 ≠ 高质量
"的的的的的的的的" 困惑度极低（模型完全预料得到），但毫无价值
模板化的样板文（隐私政策、商品参数表）困惑度也很低

② ★★ 它会系统性地【压缩多样性】
你拿维基训的模型，就会偏爱像维基的文本
→ 口语、诗歌、方言、非西方语言的文本困惑度天然偏高 → 被系统性删掉
⚠️ 这是"用一个分布当标准去筛另一个分布"的通病，
第三代的分类器【继承了这个毛病】，只是种子换了而已
```

7.4 ★★ 第三代：轻量分类器（这一代是现在的主流）

通用配方

① 挑正例（种子）—— ★★ 全部魔法都在这一步
② 挑负例      —— 通常就是从未过滤的网页里随机抽
③ 训一个【极快】的分类器（fastText，几百微秒一篇）
④ 给全语料打分，卡阈值

三家的种子选择，一眼看出各自的取向

┌─ DCLM-Baseline（2024，[2406.11794](https://arxiv.org/abs/2406.11794)）────────────────┐
│  ✅ 正例 = OpenHermes-2.5（指令数据）                                │
│           + r/ExplainLikeImFive 里高赞的帖子                        │
│  ✅ 负例 = RefinedWeb 里随机抽                                       │
│  ✅ 分类器 = fastText                                                │
│                                                                     │
│  ★ 取向：【像"有人在好好回答一个问题"的文本】                        │
│     ELI5 = Explain Like I'm Five，"用五岁小孩听得懂的话解释"         │
│     —— 选它当正例，等于把"讲得清楚"直接编码进了过滤器                │
│  产出：DCLM-Baseline，3.8 T token                                   │
└─────────────────────────────────────────────────────────────────────┘

┌─ FineWeb-Edu（2024，[2406.17557](https://arxiv.org/abs/2406.17557)）─────────────────┐
│  ✅ 正例的来源不是"现成数据集"，而是【让大模型来标】：                │
│     用 Llama-3-70B-Instruct 给一批 FineWeb 网页打 0~5 分的           │
│     "教育价值"分 → 用这些标注训一个小分类器 → 给全量 FineWeb 打分     │
│  ✅ 卡阈值后得到 FineWeb-Edu，1.3 T token                            │
│     （★ 从 15 T 筛到 1.3 T —— 只留了不到 9%）                        │
│                                                                     │
│  ★ 取向：【像教科书/科普的文本】                                     │
│  ✅ 效果：在 MMLU、ARC 这类知识型评测上大幅优于全量 FineWeb           │
│  ⚠️ 代价：只剩 9%，多样性和"网感"被砍掉很多                          │
└─────────────────────────────────────────────────────────────────────┘

┌─ Nemotron-CC（2024，[2412.02595](https://arxiv.org/abs/2412.02595)）─────────────────┐
│  ✅ 做法：【多个分类器集成】 + 分成质量档，而不是一刀切               │
│     ★ 它【不丢掉】低质档，而是把低质档拿去让模型改写（见 12 章）      │
│                                                                     │
│  ✅ 论文报告的两个结果（这是本章最值得记的数字）：                    │
│     · 高质量子集：MMLU 比 DCLM 高 5.6 分                             │
│     · 全量版本：达到与 DCLM 相当的效果，但有【4 倍多的唯一 token】    │
│                          ↑★★ 这一条才是重点                          │
└─────────────────────────────────────────────────────────────────────┘

★★★ Nemotron-CC 那第二条结果，是这个领域近两年最重要的转向。

在此之前所有人都在比"谁筛得更狠、剩下的更精"。Nemotron-CC 说的是：

```
如果你要训 15 T token，而 FineWeb-Edu 只有 1.3 T
→ 你必须把它【重复 11 遍】
→ 而重复的边际收益是递减的（见 11 章）

⟹ ★ "更纯但更少" 和 "稍差但更多" 之间存在一个真实的权衡点，
而这个点【随训练预算变化】：预算越大，越应该放松过滤。
```

这也解释了 05 章末尾那个方向反转——Nemotron-CC 主动放松了启发式规则。

一段能跑的实现

import fasttext, random, json

with open("cls_train.txt", "w", encoding="utf-8") as f:
    for t in load_seed_positive():          # 指令数据 / 高赞问答 / 教科书
        f.write("__label__hq " + t.replace("\n", " ")[:2000] + "\n")
    for t in random.sample(load_raw_web(), len(seed) * 3):   # ★ 负例可以多一些
        f.write("__label__lq " + t.replace("\n", " ")[:2000] + "\n")

# ---- ② 训（几分钟，CPU 就够）----
clf = fasttext.train_supervised("cls_train.txt", epoch=5, lr=0.1,
                                wordNgrams=2, dim=256, minCount=3)
clf.quantize(input="cls_train.txt", retrain=True)   # ★ 量化后模型小 10 倍，更快

# ---- ③ 打分 + 卡阈值 ----
def score(text):
    labels, probs = clf.predict(text.replace("\n", " ")[:2000], k=2)
    return dict(zip(labels, probs)).get("__label__hq", 0.0)

for doc in docs:
    doc["q"] = score(doc["text"])

# ★ 阈值不要拍脑袋定，而是【按目标 token 量反推分位数】
import numpy as np
scores = np.array([d["q"] for d in docs])
th = np.quantile(scores, 1 - TARGET_KEEP_RATIO)     # 想留 20% 就取 80 分位
keep = [d for d in docs if d["q"] >= th]

★ "按分位数定阈值"是实践中的标准做法，因为分类器的绝对分数没有可比性（换一批负例分数分布就变了），但排序是稳定的。

7.5 第四代：大模型打标签 + 蒸馏（Essential-Web）

第三代给每篇文档一个标量分数。但一个分数丢掉了太多信息——它没告诉你这篇文章是关于什么的。

✅ Essential-Web v1.0（arXiv:2506.14111，Essential AI，2025-06）：

① 不打分，打【一整套结构化标签】：
   ✅ 12 个类别维度，包括主题分类、网页类型、内容复杂度、
      文档质量、以及是否含广告/导航污染 等

② 用一个大模型（Qwen2.5-32B-Instruct）先标一批

③ ★★ 蒸馏成一个 0.5B 的小模型 EAI-Distill-0.5b
   ✅ 论文报告：与 32B 老师的一致性差距在 3% 以内，
      而吞吐提升约 50 倍
   ★ 这就是 7.2 说的"成本越来越高 → 必须蒸馏回小模型"

④ ★ 于是筛数据变成了【写 SQL】：
   SELECT * FROM web WHERE topic='mathematics' AND quality>=4 AND ads=false

   ✅ 论文报告用这种方式筛出的领域数据集，
      与各领域 SOTA 数据集相比：网页代码 +14.3%、STEM +24.5%、医学 +8.6%，
      数学 −8.0%（★ 唯一落后的一项，论文如实报告了）

   规模：24 T token

★★ 为什么这是范式转变：前三代是破坏性的——过滤即删除，一次决定终身。
第四代是非破坏性的——先给所有数据打好标签全部留着，用的时候再按需查询。

旧：每换一个配方 → 重跑整条流水线（几天到几周） 新：每换一个配方 → 改一句 SQL（几分钟） ★ 这直接把"数据配方"的实验迭代速度提高了几个数量级

⚠️ 我的判断：这个方向大概率会成为下一代的默认做法，但目前公开采用它的还很少（数据是 2025 年的）。

7.6 ⚠️ 三个必须知道的风险

① ★★ 分布收窄（distribution narrowing）
   所有分类器都在做同一件事：【把语料的分布往种子的分布上拽】
   → 筛得越狠，语料越单一，越像种子
   → 表现：知识型评测涨，但创造性、口语、长尾领域变差
   ⚠️ 而知识型评测正好是大家最常报的指标 → ★ 这个代价很容易被指标掩盖

② 评测污染（间接的）
   用"像 MMLU 题目"的种子去筛数据，等于变相往训练集里塞评测题的近亲
   → 分数涨了，真实能力没涨。★ 08 章专门讲这个

③ 分类器学到的是【表面特征】
   fastText 只看词袋和 n-gram，很容易学成"有没有出现某些词"
   ⚠️ 一个真实的失败模式：分类器学会了"含 'Abstract' 'Figure 1' 就是高质量"
      → 于是筛出一堆论文的【参考文献页】
   ★ 缓解：一定要人工抽样看【被留下的】和【被删掉的】各 100 篇

★ 实践铁律（和 05 章那条同源）：
上线任何过滤器之前，随机抽 100 篇被它删掉的文档，自己读一遍。
这是唯一能发现"筛错了整整一类内容"的办法，而且成本只有半小时。

7.7 挂回真实系统

语料 质量过滤方法 保留规模
C4（2019） 纯规则 ~750 GB
CCNet（2019） ✅ 维基 5-gram 困惑度，分 head/middle/tail —
RefinedWeb（2023） ✅ 只用规则 + 重度去重，不用分类器 5 T（公开 600 B）
Dolma（2024） 规则 + 质量分类器 3 T
FineWeb（2024） 规则（C4+Gopher+自研三条） 15 T
FineWeb-Edu ✅ Llama-3-70B 标注 → 小分类器，教育价值 0~5 ✅ 1.3 T
DCLM-Baseline（2024） ✅ fastText，正例 = OpenHermes-2.5 + ELI5 ✅ 3.8 T
Nemotron-CC（2024） ✅ 分类器集成 + 分质量档 + 低质档改写 ~6.3 T
Ultra-FineWeb（2025） ✅ 高效验证策略 + fastText ~1 T 英文 + 120 B 中文
Essential-Web v1.0（2025） ✅ 12 维标签（32B 标注 → 0.5B 蒸馏） ✅ 24 T

★ RefinedWeb 那一行值得单独看：它故意不用任何模型分类器，只靠规则 + 狠去重，照样训出了 Falcon。
⚠️ 我的读法：这说明去重的收益比质量分类器更确凿（06 章）——如果算力有限，先把去重做扎实，再考虑分类器。

7.8 小结

① ★★ "质量"没有客观定义。业界的实际定义是：
   "长得像我挑的那批种子样本" → ★ 所有效果都取决于【种子怎么挑】

② 验证一个过滤器好不好，唯一可靠办法是训个模型 → 极慢极贵
   应对：① 小代理模型跑 ablation（⚠️ 外推不一定成立）
         ② ✅ DCLM 建立统一评测协议，让各家数据可比
         ③ ✅ Ultra-FineWeb 的高效验证策略，绕开大循环

③ 四代方法：
   规则(05章) → 困惑度(CCNet) → 轻量分类器(DCLM/FineWeb-Edu) 
              → 大模型打标签+蒸馏(Essential-Web)
   ★ 判据越来越像人的判断，成本越来越高 → 每一代都要蒸馏回小模型

④ 困惑度：PPL 低 = 模型觉得"眼熟"
   ⚠️ 眼熟 ≠ 有价值（"的的的的"PPL 极低）；且会系统性压缩多样性

⑤ 三家种子选择直接体现取向：
   DCLM        = OpenHermes + ELI5   → "有人在好好回答问题"
   FineWeb-Edu = Llama-3-70B 打教育分 → "像教科书"（15T → 1.3T，只剩 9%）
   Nemotron-CC = 分类器集成 + 分档，低质档【改写而非丢弃】

⑥ ★★★ Nemotron-CC 的转向（本章最重要的结论）：
   高质量子集 MMLU 比 DCLM 高 5.6 分；
   而全量版本效果与 DCLM 相当，却有【4 倍多的唯一 token】
   → 训练预算越大，越应该【放松】过滤，因为重复的边际收益递减

⑦ Essential-Web：从"打一个分数并删除"变成"打一整套标签并保留"
   → 筛数据变成写 SQL，配方迭代从几周变成几分钟

⑧ ⚠️ 三个风险：分布收窄（指标涨但多样性掉）/ 间接评测污染 /
   分类器学到表面特征
   ★ 铁律：上线前随机抽 100 篇【被删掉的】自己读一遍
