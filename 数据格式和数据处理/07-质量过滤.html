07 · ⭐ 质量过滤：从"数规则"到"用模型打分"

05 章的规则回答的是"这是不是一段正常的文字"。
这一章回答的是一个更难、也更主观的问题："这段文字值不值得学"。

★ 这是整条流水线上最没有共识、各家差距最大的一环。

⚠️ 本章数字口径：容量沿用 05 章的十进制约定。★ 规模一律写明是 token 数还是容量——7.7 节的对照表里 C4 报的是 GB、别家报的是 T token，这两列不能直接比，那一节会给换算。

7.1 先承认一件事：没人知道"质量"是什么

下面哪一篇"质量高"？

  A. 一篇写得很好的明星八卦报道
  B. 一篇语法糟糕但讲清楚了某个 API 用法的技术问答
  C. 一段法律条文
  D. 一条 Reddit 上的口语化闲聊

★ 答案是：【取决于你想要模型会什么】
   要写作流畅 → A 有用
   要能答技术问题 → B 有用
   要口语自然 → D 有用

所以业界实际用的"质量"定义，几乎全都可以翻译成同一句话：

★★ "质量高" ≈ "长得像我心目中的好文本"。
你先挑一批种子样本当作"好"的标准，然后训一个分类器去找长得像种子的网页。

⚠️ 于是：质量过滤的效果，几乎完全由"你挑了什么当种子"决定。 这是本章最重要的一句话，7.4 节会给出"种子和阈值到底怎么定"的具体做法。

还有一个更麻烦的问题：怎么知道你的过滤器管用？

唯一真正可靠的验证方式：
   用过滤后的数据【训一个模型】，看下游评测分

  ⟹ 一次实验 = 训一个模型 = 几万到几十万美元（⚠️ 我的量级估算）
  ⟹ ★ 所以质量过滤是整条流水线上【反馈最慢、最贵】的一环

业界的应对（三个层次）：

① 代理模型（proxy model）
   用 1 亿 ~ 10 亿参数的小模型跑 ablation，假设结论能外推到大模型
   ⚠️ 这个假设【不总是成立】——小模型上有效的过滤，大模型上可能收益消失

② 标准化评测台
   ✅ DCLM（[2406.11794](https://arxiv.org/abs/2406.11794)）最大的贡献其实不是数据集，
      而是它把"数据过滤"变成了一个【有统一评测协议的公开竞赛】：
      固定模型、固定算力、只让你改数据 → 分数直接可比
   ★ 在此之前，各家说"我的数据更好"是没法互相验证的

③ 更便宜的验证信号
   ✅ Ultra-FineWeb（[2505.05427](https://arxiv.org/abs/2505.05427)）的核心贡献就是这个：
      提出一套【高效验证】策略，先低成本判断"种子数据靠不靠谱"，
      再去训分类器 —— 避免了"训模型→评测→改过滤器"这个昂贵的大循环

7.3 第二代：困惑度过滤（CCNet）

✅ CCNet（arXiv:1911.00359，Wenzek 等，Facebook，2019-11）。

困惑度（perplexity，简称 PPL） 先解释清楚：

一个语言模型看一段文字，会对每个词给出"我预测它出现的概率"。
困惑度 = 这些概率的几何平均的倒数。

    PPL(x) = exp( − (1/T) · Σ_{t=1..T} log P(x_t | x_<t) )

★ 一句话：【困惑度低 = 这段文字对模型来说"意料之中"、"眼熟"】
                    ↑ 注意，这是"眼熟"，不是"正确"，本节末尾会讲这个坑
⚠️ 困惑度是【绝对值】，不是百分比。说"困惑度降了 3"和"困惑度降了 3%"
   是两回事（[06 章](06-去重.md) 6.1 的 Wiki-40B 那条数字就是绝对值降 3）。

CCNet 的做法：

① 在【维基百科】上训一个 5-gram 的 Kneser-Ney 语言模型（用 KenLM 工具）
   ★ 为什么用 n-gram 而不是神经网络？因为要处理几十亿篇文档 —— 必须极快
   ★ 为什么用维基百科？因为它是"标准书面语"的现成代表

② 给每个段落算困惑度

③ ✅ 按困惑度把语料【三等分】：
      head    （困惑度最低的 1/3）—— 最像维基百科
      middle  （中间 1/3）
      tail    （困惑度最高的 1/3）—— 最不像

④ ★ 论文并不是简单地"只要 head"。它把三档都发布出来，
   让下游自己决定用哪些 —— 因为"像维基"不等于"有用"
   ⟹ ★ 这是第二代唯一"半可逆"的地方（见 7.2 的表）

import kenlm
model = kenlm.Model("wiki_5gram.arpa")     # 在维基上训好的 n-gram 语言模型

def perplexity(text):
    # kenlm 返回 log10 概率
    logp = model.score(text, bos=True, eos=True)
    n = len(text.split()) + 1
    return 10 ** (-logp / n)

ppl = perplexity(doc["text"])
bucket = "head" if ppl < TH_LOW else ("tail" if ppl > TH_HIGH else "middle")

⚠️ 困惑度过滤的两个致命坑，必须知道：

```
① ★ 低困惑度 ≠ 高质量
"的的的的的的的的" 困惑度极低（模型完全预料得到），但毫无价值
模板化的样板文（隐私政策、商品参数表）困惑度也很低

② ★★ 它会系统性地【压缩多样性】
你拿维基训的模型，就会偏爱像维基的文本
→ 口语、诗歌、方言、非西方语言的文本困惑度天然偏高 → 被系统性删掉
⚠️ 这是"用一个分布当标准去筛另一个分布"的通病，
第三代的分类器【继承了这个毛病】，只是种子换了而已
```

★ 顺带一个中文的坑：拿中文维基训 KenLM，必须先定好切分口径（按字 / 按词 / 按 token）。⚠️ 同一段中文按"字"算和按"词"算，困惑度的绝对值完全不可比——而这个口径几乎没人在报数时写出来（见 05 章 5.5 的三个单位）。

⚠️ "只剩 8.7%"的口径：1.3 T ÷ 15 T = 8.67%，分母是 token 数。★ 这也可以说成"砍掉了 91.3%"或"压缩到 8.7%"/"压缩 11.5 倍"，但不能说成"压缩了 8.7%"（见 06 章 6.7）。

★★★ Nemotron-CC 那第二条结果，是这个领域近两年最重要的转向。

在此之前所有人都在比"谁筛得更狠、剩下的更精"。Nemotron-CC 说的是：

```
如果你要训 15 T token，而 FineWeb-Edu 只有 1.3 T
→ 你必须把它【重复 11.5 遍】（15 ÷ 1.3）
→ 而重复的边际收益是递减的（见 11 章）

⟹ ★ "更纯但更少" 和 "稍差但更多" 之间存在一个真实的权衡点，
而这个点【随训练预算变化】：预算越大，越应该放松过滤。
```

这也解释了 05 章末尾那个方向反转——Nemotron-CC 主动放松了启发式规则。

★★★ 正负样本怎么选：四条具体做法

这一节是本章唯一"必须照着做"的部分，因为 7.1 已经说了：效果几乎完全由种子决定。

① 正例从哪来 —— 三条路，成本递增
   (a) 借现成的高质量数据集     ★ 最省，DCLM 走这条（OpenHermes + ELI5）
   (b) 借现成的"权威"语料       ★ 维基、教科书、arXiv —— 但会把分布拽向书面语
   (c) ✅ 让大模型现场标注       ★ FineWeb-Edu 走这条，最贵但最贴合你的目标

② 正例要多少
   ⚠️ fastText 在几万到几十万条正例上就已经饱和，再加收益很小。
   ★ 所以不要在"攒更多正例"上花时间，该花在【正例覆盖得够不够全】上：
     把你希望模型会的每一类能力，都至少放几千条进去。

③ ★★ 负例怎么选 —— 这里有一个必踩的坑
   标准做法：从【未过滤的原始网页】里随机抽。
   ⚠️ 坑在于：随机网页和你的正例在【长度、语言、排版】上系统性不同。
      例：OpenHermes 的条目普遍是几百词的完整回答，
          而随机网页里有大量 50 词以下的碎片。
      ⟹ ★ 分类器会发现"判长度就能拿高分"，于是学成了一个【长度分类器】。
   ★ 两条缓解：
      (a) 按长度分层抽负例：让负例的长度分布和正例对齐
      (b) 上线前做"长度分桶保留率"诊断（见 7.6）

④ 负例 : 正例 的比例
   ⚠️ 1:1 会让分类器的分数分布挤在中间，阈值很难切；
      常见做法是负例多一些（1:3 ~ 1:10），让高分区更稀疏、排序更稳。
   ★ 但记住：【比例只影响分数的绝对值，不影响排序】——
     而下一节会说明，我们只用排序，所以这个旋钮没那么要紧。

★★★ 阈值怎么定：先算预算，再定分位数

★ 关键认识：阈值不是一个"质量问题"，是一个"预算问题"。 走一遍完整算术。

给定：手上是 FineWeb 全量 15 T token；计划训一个消耗 8 T token 的模型。

想留的比例 留下的 token 训 8 T 要重复几遍 阈值该取在哪个分位数 对应现实
8.7% 1.3 T 8 ÷ 1.3 = 6.2 遍 第 91.3 分位 ✅ FineWeb-Edu 的实际口径
20% 3.0 T 8 ÷ 3.0 = 2.7 遍 第 80 分位 —
42% 6.3 T 8 ÷ 6.3 = 1.3 遍 第 58 分位 ≈ ✅ Nemotron-CC 全量规模
★ 53.3% 8.0 T ★ 1.0 遍（刚好不用重复） 第 46.7 分位 ★ 预算决定的"自然阈值"
100% 15 T 0.53 遍（用不完） 不过滤 — 
★★ 这张表怎么用（三步）：

  第 1 步：算出"1 epoch 刚好够"的那个保留比例 = 训练预算 ÷ 手上总量
           = 8 T ÷ 15 T = 53.3%
  第 2 步：★ 这个比例就是阈值的【上界】——
           留得比它【多】，数据根本用不完，过滤白做；
           留得比它【少】，就必须重复，而重复的边际收益递减（11 章）。
  第 3 步：在 [0, 53.3%] 这个区间里做 ablation，而不是在 [0, 100%] 里瞎试。
           ⟹ ★ 这一步把搜索空间砍掉一半，而且砍掉的那一半是确定无用的。

⚠️ 一个常见的错误顺序：先按"质量"定一个阈值，训完发现数据不够，
   再回头放松阈值 —— 等于把最贵的那一步（训模型）做了两遍。

为什么一定要用分位数、不能用绝对分数：

★ 分类器输出的绝对分数【没有可比性】：
    换一批负例 → 分数分布整体平移；
    重训一次（换随机种子）→ 分数分布也会变。
  ⚠️ 所以"阈值 = 0.7"这种写法在换了一次模型之后就失去意义。

★ 但【排序是稳定的】—— 同一批文档，两个版本的分类器给出的排名高度一致。
  ⟹ 所以阈值要写成"保留分数最高的 X%"，而不是"分数 ≥ 0.7"。

一段能跑的实现

import fasttext, random, numpy as np

# ---- ① 造训练集（★ 负例按长度分层抽，避免学成长度分类器）----
seed = load_seed_positive()              # 指令数据 / 高赞问答 / 教科书
raw  = load_raw_web()

def len_bucket(t):                       # ★ 按词数分桶，负例按正例的桶分布来抽
    n = len(t.split())
    return 0 if n < 200 else 1 if n < 800 else 2 if n < 3000 else 3

pos_dist = np.bincount([len_bucket(t) for t in seed], minlength=4)
pos_dist = pos_dist / pos_dist.sum()
NEG_RATIO = 3                            # ★ 负例是正例的 3 倍
neg = []
by_bucket = {b: [t for t in raw if len_bucket(t) == b] for b in range(4)}
for b in range(4):
    k = int(len(seed) * NEG_RATIO * pos_dist[b])
    neg += random.sample(by_bucket[b], min(k, len(by_bucket[b])))

with open("cls_train.txt", "w", encoding="utf-8") as f:
    for t in seed:
        f.write("__label__hq " + t.replace("\n", " ")[:2000] + "\n")
    for t in neg:
        f.write("__label__lq " + t.replace("\n", " ")[:2000] + "\n")

# ---- ② 训（几分钟，CPU 就够）----
clf = fasttext.train_supervised("cls_train.txt", epoch=5, lr=0.1,
                                wordNgrams=2, dim=256, minCount=3)
clf.quantize(input="cls_train.txt", retrain=True)   # ★ 量化后模型小 10 倍，更快

# ---- ③ 打分 ----
def score(text):
    labels, probs = clf.predict(text.replace("\n", " ")[:2000], k=2)
    return dict(zip(labels, probs)).get("__label__hq", 0.0)

for doc in docs:
    doc["q"] = score(doc["text"])

# ---- ④ ★ 阈值按目标 token 量反推分位数，不要拍绝对分数 ----
TRAIN_BUDGET_TOKENS = 8e12
total_tokens = sum(d["n_tokens"] for d in docs)
keep_ratio = min(TRAIN_BUDGET_TOKENS / total_tokens, 1.0)   # ★ 8/15 = 0.533
scores = np.array([d["q"] for d in docs])
th = np.quantile(scores, 1 - keep_ratio)                    # ★ 留 53.3% → 取 46.7 分位
keep = [d for d in docs if d["q"] >= th]

⚠️ 注意 keep_ratio 是按 token 数算的，而 np.quantile 是按文档数算的 ——这两个分母不一样。 如果高分文档系统性更长（很常见），按文档数取 46.7 分位实际会留下远多于 53.3% 的 token。★ 严谨做法是按分数排序后累加 token 数，加到预算为止：

python docs.sort(key=lambda d: -d["q"]) acc, keep = 0, [] for d in docs: if acc >= TRAIN_BUDGET_TOKENS: break keep.append(d); acc += d["n_tokens"]

★ 这是 06 章 6.1 那个"分母"问题在本章的翻版：只要同时存在"按文档"和"按 token"两个口径，就一定要检查自己用的是哪个。

7.5 第四代：大模型打标签 + 蒸馏（Essential-Web）

第三代给每篇文档一个标量分数。但一个分数丢掉了太多信息——它没告诉你这篇文章是关于什么的。

✅ Essential-Web v1.0（arXiv:2506.14111，Essential AI，2025-06）。✅ 下面的数字我从 papers/Essential-Web-v1.0-24T-tokens-arXiv-2506.14111.pdf 逐句核对过：

① 不打分，打【一整套结构化标签】：
   ✅ 每个网页拿到 12 个类别的标签（论文把这套体系叫 EAI-Taxonomy），
      分属 5 个逻辑组，包括主题分类、网页类型、内容复杂度、
      文档质量、以及是否含广告/导航污染 等

② 用一个大模型（Qwen2.5-32B-Instruct）先标一批

③ ★★ 蒸馏成一个 0.5 B 的小模型 EAI-Distill-0.5b
   ✅ 论文报告它与 32B 老师的差距：
        标注一致性（annotator agreement）  3% 以内
        NMI（归一化互信息）               14% 以内
        领域召回（domain-recall）          1% 以内
   ★ 这就是 7.2 说的"成本越来越高 → 必须蒸馏回小模型"

④ ★ 于是筛数据变成了【写 SQL】：
   SELECT * FROM web WHERE topic='mathematics' AND quality>=4 AND ads=false

   规模：✅ 23.6 B 篇文档 / 24 T token

✅ 蒸馏省了多少，论文给了可验算的数字：

配置 ✅ 吞吐（RPS/GPU，每 GPU 每秒处理的请求数） 相对提升
原始做法：给 32B 模型发完整 prompt 1.4 基线
★ 换成 0.5B + 去掉 prompt + 压缩生成长度 70 ★ 50 倍 
★ 自己验一遍：70 ÷ 1.4 = 50.0 倍   ✅ 和论文说的 "50× faster annotation" 一致
⚠️ 注意这是【吞吐倍数】，不是"时间减少 50%"（见 06 章 6.7 那三组说法）：
   吞吐 ×50 ⟺ 同样的量耗时变成 1/50 ⟺ 时间减少 98%。
✅ 即便如此，给 23.6 B 篇文档全部打标仍然用了约 9 万 MI300X 卡时 ——
   ★ 这就是第四代"一次性成本极高"的具体量级。

✅ 论文报告用 SQL 方式筛出的领域数据集，和各领域此前 SOTA 数据集相比：

领域 ✅ 相对 SOTA 的变化
网页代码（web code） +14.3%
STEM +24.5%
医学（medical） +8.6%
数学（math） ⚠️ −8.0%（★ 唯一落后的一项，论文如实报告了）

★★ 为什么这是范式转变：前三代是破坏性的——过滤即删除，一次决定终身。
第四代是非破坏性的——先给所有数据打好标签全部留着，用的时候再按需查询。

旧：每换一个配方 → 重跑整条流水线（几天到几周） 新：每换一个配方 → 改一句 SQL（几分钟） ★ 这直接把"数据配方"的实验迭代速度提高了几个数量级

⚠️ 我的判断：这个方向大概率会成为下一代的默认做法，但目前公开采用它的还很少（数据是 2025 年的）。

7.6 ⚠️ 三个必须知道的风险，和四张诊断表

① ★★ 分布收窄（distribution narrowing）
   所有分类器都在做同一件事：【把语料的分布往种子的分布上拽】
   → 筛得越狠，语料越单一，越像种子
   → 表现：知识型评测涨，但创造性、口语、长尾领域变差
   ⚠️ 而知识型评测正好是大家最常报的指标 → ★ 这个代价很容易被指标掩盖

② 评测污染（间接的）
   用"像 MMLU 题目"的种子去筛数据，等于变相往训练集里塞评测题的近亲
   → 分数涨了，真实能力没涨。★ [08 章](08-去污染与隐私许可.md)专门讲这个

③ 分类器学到的是【表面特征】
   fastText 只看词袋和 n-gram，很容易学成"有没有出现某些词"
   ⚠️ 一个真实的失败模式：分类器学会了"含 'Abstract' 'Figure 1' 就是高质量"
      → 于是筛出一堆论文的【参考文献页】

★★ 上线前必须算的四张交叉表（+ 一次人工抽样）

⚠️ 这五件事总共花不到一天，而它们是唯一能在训模型之前发现"筛错了整整一类内容"的办法。

诊断 怎么算 ⚠️ 看到什么就该警惕 对应的真实失败模式
① 长度分桶保留率 按词数分 4~5 桶，算每桶的保留率 保留率随长度单调上升 ★ 分类器学成了"长度分类器"——因为种子正例普遍比随机网页长（见 7.4 的坑 ③）
② 语言分桶保留率 按 05 章的 LID 结果分桶 某个语言分片保留率接近 0 种子全是英文 → 分类器把"有英文停用词"当成了质量信号；也可能是中文标点表的 bug
③ 域名集中度 取保留下来的文档的 top 1000 域名，看它们占了多少比例 保留的文档集中在极少数站点 分类器学成了"站点分类器"，多样性直接塌掉
④ 留/删两组的高频词对比 分别统计被留下和被删掉的文档的高频词，看差异最大的那几十个 差异词里出现 Abstract Figure 1 References 这类格式词 ⚠️ 上面那个"筛出一堆参考文献页"的案例，就是这张表能抓到的
⑤ ★ 人工抽样 随机抽 100 篇被删掉的，自己从头读一遍 发现整整一类你本来想要的内容被删了 ★ 这是唯一能发现"整类误杀"的办法，成本只有半小时

★ 实践铁律（和 05 章 5.4 那条同源）：
上线任何过滤器之前，随机抽 100 篇被它删掉的文档，自己读一遍。
⚠️ 注意是读被删掉的，不是被留下的。读留下的只能让你安心，读删掉的才能让你发现问题——因为误杀是沉默的：它不会出现在任何指标里。

7.7 挂回真实系统

语料 质量过滤方法 保留规模
C4（2019） 纯规则 ✅ 约 750 GB（⚠️ 容量口径，见下）
CCNet（2019） ✅ 维基 5-gram 困惑度，分 head/middle/tail —
RefinedWeb（2023） ✅ 只用规则 + 重度去重，不用分类器 ✅ 5 T token（公开发布 600 B）
Dolma（2024） 规则 + 质量分类器 ✅ 3 T token（跨 40 亿+ 篇文档）
FineWeb（2024） 规则（C4 + Gopher + 自研三条） ✅ 15 T token
FineWeb-Edu ✅ Llama-3-70B 标注 → 小分类器，教育价值 0~5 ✅ 1.3 T token（= 15 T 的 8.7%）
DCLM-Baseline（2024） ✅ fastText，正例 = OpenHermes-2.5 + ELI5 ✅ 3.8 T token
Nemotron-CC（2024） ✅ 分类器集成 + 分质量档 + 低质档改写 ✅ ~6.3 T token
Ultra-FineWeb（2025） ✅ 高效验证策略 + fastText ~1 T 英文 + 120 B 中文 token
Essential-Web v1.0（2025） ✅ 12 维标签（32B 标注 → 0.5B 蒸馏） ✅ 24 T token（23.6 B 篇文档）

⚠️⚠️ 这张表的"保留规模"一列混了两种口径，不能直接比。 C4 那一行报的是容量（✅ T5 论文原文 "about 750 GB"，★ 而且论文没有声明这个 GB 是十进制还是二进制——如果原意是 GiB，换成十进制就是 805 GB，差 7.4%）；别的行报的是 token 数。

★ 粗略换算一下好有个概念（⚠️ 我的估算，不是论文数字）：英文纯文本在常见分词器下大约 4 字节 / token，于是

```
750 GB ÷ 4 字节/token ≈ 1.9 × 10¹¹ token ≈ 190 B token

⟹ ★ C4 的量级大约是 FineWeb（15 T）的 1.3%、是 FineWeb-Edu（1.3 T）的 15%。
⚠️ 这个换算对中文【完全不适用】：中文 UTF-8 是 3 字节/字、
1 token 约覆盖 1~2 个字 ⟹ 约 2~6 字节/token，口径一变结论就变
（见 05 章 5.5）。
```

顺带一个可以验算的成本锚点（✅ 我从 FineWeb 论文核对过原文）：

✅ "Applying the classifier to the 15 trillion tokens of FineWeb
    required 6,000 H100 GPU hours."

★ 自己换算：
    15e12 token ÷ 6000 卡时 = 2.5e9 token / 卡时
                            = 2.5e9 / 3600 ≈ 69 万 token / 卡秒
    每 1 T token 要 400 H100 卡时。

⟹ ★ 这是"第三代轻量分类器"真实的算力量级：
     给 15 T token 全量打分，6000 卡时 —— 几十块 H100 跑一周左右。
   ⚠️ 对比 7.5 节第四代的约 9 万 MI300X 卡时（打 24 T token），
      ★ 按每 T token 折算约是 3750 卡时，是第三代的近 10 倍。
      （⚠️ 不同卡型不能严格比，这里只看数量级。）

★ RefinedWeb 那一行值得单独看：它故意不用任何模型分类器，只靠规则 + 狠去重，照样训出了 Falcon。
⚠️ 我的读法：这说明去重的收益比质量分类器更确凿（06 章）——如果算力有限，先把去重做扎实，再考虑分类器。

7.8 小结

① ★★ "质量"没有客观定义。业界的实际定义是：
   "长得像我挑的那批种子样本" → ★ 所有效果都取决于【种子怎么挑】

② 验证一个过滤器好不好，唯一可靠办法是训个模型 → 极慢极贵
   应对：① 小代理模型跑 ablation（⚠️ 外推不一定成立）
         ② ✅ DCLM 建立统一评测协议，让各家数据可比
         ③ ✅ Ultra-FineWeb 的高效验证策略，绕开大循环

③ 四代方法（7.2 有完整对照表）：
   规则(05章) → 困惑度(CCNet) → 轻量分类器(DCLM/FineWeb-Edu)
              → 大模型打标签+蒸馏(Essential-Web)
   ★ 纵向看两条线：
     · "需要你准备什么"越来越重 → 各家差距从第三代开始拉开
     · "可逆吗"在第四代翻转：前三代是删除，第四代是打标、全部留着

④ 困惑度（PPL）：低 = 模型觉得"眼熟"
   ⚠️ 眼熟 ≠ 有价值（"的的的的"PPL 极低）；且会系统性压缩多样性
   ⚠️ PPL 是绝对值："降了 3"和"降了 3%"是两回事
   ⚠️ 中文要先定切分口径（按字/按词/按 token），否则绝对值不可比

⑤ 三家种子选择直接体现取向：
   DCLM        = OpenHermes + ELI5   → "有人在好好回答问题"，3.8 T
   FineWeb-Edu = Llama-3-70B 打教育分 → "像教科书"（15 T → 1.3 T，剩 8.7%）
   Nemotron-CC = 分类器集成 + 分档，低质档【改写而非丢弃】，~6.3 T

⑥ ★★★ 正负样本与阈值的具体做法（7.4）：
   正例：借现成数据集 / 借权威语料 / ✅ 让大模型现场标；
         ★ 几万~几十万条就饱和，该花力气在【覆盖得全不全】
   负例：⚠️ 必须【按长度分层抽】，否则分类器会学成"长度分类器"
         负例 : 正例 取 1:3 ~ 1:10；★ 比例只影响分数绝对值，不影响排序
   阈值：★★ 阈值是【预算问题】不是质量问题 —— 先算
         "1 epoch 刚好够"的保留比例 = 训练预算 ÷ 手上总量（例：8T/15T = 53.3%）
         ⟹ 这就是阈值上界，ablation 只在 [0, 53.3%] 里做
   ⚠️ 阈值要写成"保留最高的 X%"（分位数），不能写成"分数 ≥ 0.7"
      —— 绝对分数换一批负例就平移，但排序是稳定的
   ⚠️ 而且要注意分位数是按【文档数】、预算是按【token 数】——
      严谨做法是排序后累加 token 到预算为止

⑦ ★★★ Nemotron-CC 的转向（本章最重要的结论）：
   ✅ 高质量子集 MMLU 比 DCLM 高 5.6【个百分点，绝对分】；
   ✅ 而全量版本效果与 DCLM 相当，却有【4 倍多的唯一 token】
   → 训练预算越大，越应该【放松】过滤，因为重复的边际收益递减

⑧ ✅ Essential-Web：从"打一个分数并删除"变成"打一整套标签并保留"
   12 个类别 / 23.6 B 篇文档 / 24 T token
   0.5B 蒸馏模型与 32B 老师的一致性差距在 3% 以内，吞吐 1.4 → 70 RPS/GPU（50 倍）
   ⚠️ 50 倍是【吞吐倍数】，等于耗时变成 1/50、时间减少 98%
   领域效果：代码 +14.3% / STEM +24.5% / 医学 +8.6% / ⚠️ 数学 −8.0%

⑨ ⚠️ 三个风险：分布收窄（指标涨但多样性掉）/ 间接评测污染 /
   分类器学到表面特征
   ★ 上线前必算五件事（7.6）：长度分桶保留率、语言分桶保留率、
     域名集中度、留删两组高频词对比、★ 随机抽 100 篇【被删掉的】自己读
   ★ 注意读的是【被删掉的】—— 误杀是沉默的，不会出现在任何指标里

⑩ ⚠️ 规模口径：7.7 的表里 C4 报 GB、别家报 T token，不能直接比
   按英文约 4 字节/token 粗算，750 GB ≈ 190 B token
   ⚠️ 这个换算对中文完全不适用（中文约 2~6 字节/token）
