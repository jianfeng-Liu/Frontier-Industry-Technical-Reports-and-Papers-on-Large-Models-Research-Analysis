08 · 去污染、隐私与许可

前面三章删数据，理由都是"这数据不好"。
这一章删数据，理由是"这数据好，但不能要"。

★ 这是唯一一章里，删错了不会让模型变差，但会让你的评测分数变成废纸（去污染），
或者让你上不了线（隐私与许可）。

8.1 评测污染：为什么它是最危险的一种脏

一句话说清楚

你训练时用了 100 T 网页数据。
而 MMLU、GSM8K、HumanEval 这些评测题，★ 全都公开挂在网上。
   （MMLU = 57 学科选择题 / GSM8K = Grade School Math 8K，小学应用题 8000 道
     / HumanEval = OpenAI 的 164 道 Python 编程题）
   → 它们大概率【已经在你的训练数据里了】

于是评测的时候：
   模型不是在"推理"，而是在【回忆】它见过的答案
   → 分数虚高，而且【你完全不知道虚高了多少】

✅ 这不是理论担忧。06 章引的 Lee et al.（2107.06499）明确报告：标准数据集的验证集里，超过 4% 的内容能在训练集里找到。

★★ 为什么说它比"数据脏"更危险？

```
数据脏 → 模型变差 → ★ 你的评测分会告诉你
数据污染 → 模型没变好，但评测分【涨了】
→ ★★ 你的仪表盘在骗你，而你无从察觉

更糟的是：你会据此做出错误决策
"这个数据配方 MMLU 涨了 3 分，采纳！"
—— 实际上只是这个配方多混进了一些 MMLU 的题
```

三种污染，一种比一种难查

① 逐字污染（verbatim）
   训练数据里出现了一模一样的题目和答案
   → ★ 可以查，本章 8.2 讲怎么查

② 改写污染（paraphrased）
   题目被翻译成中文、被改写成另一种问法后出现在训练集里
   → ⚠️ n-gram 匹配【完全查不到】，需要语义匹配

③ ★ 间接污染（indirect / 分布污染）
   训练数据里没有原题，但有大量【专门针对这个评测写的题解和练习题】
   （比如各种 "MMLU 备考题库"、"GSM8K 风格数学题集"）
   → ⚠️ 这个几乎【无法定义边界】：
      "刷了很多同类型的题"和"学会了这个能力"到底怎么区分？
   ★ 而 7.4 讲的质量分类器，会【主动把这类内容筛出来】——因为它们"像好数据"

⚠️ 我的判断：现在公开报告的评测分数，基本都受 ② 和 ③ 不同程度的影响，只是没人能量化。这也是为什么业界越来越依赖 私有测试集、发布日期晚于模型截止日期的新题（比如 LiveBench 类做法）和 人工对战评测。

8.2 怎么做去污染：n-gram 匹配

最标准的做法，✅ GPT-3 论文用的是 13-gram：

① 把所有评测集（MMLU / GSM8K / HumanEval / MATH / ...）的题目和答案收集起来
② 切成 n-gram（n 通常取 8~13）
③ 建一个巨大的哈希集合
④ 扫训练语料，★ 任何文档只要撞上一个 n-gram，整篇丢掉

N = 13
def build_eval_ngrams(eval_texts):
    s = set()
    for t in eval_texts:
        w = normalize(t).split()
        for i in range(len(w) - N + 1):
            s.add(hash(" ".join(w[i:i+N])))     # 只存哈希，省内存
    return s

EVAL = build_eval_ngrams(all_benchmark_texts)

def is_contaminated(text):
    w = normalize(text).split()
    return any(hash(" ".join(w[i:i+N])) in EVAL for i in range(len(w) - N + 1))

★ n 怎么选：一个真实的权衡

n 小（比如 5）：
   → 灵敏，但【误杀严重】
   ★ "the quick brown fox jumps" 这种常见短语会撞上无数正常文档

n 大（比如 20）：
   → 几乎不误杀，但【改一个词就漏】

⚠️ 业界常用 8~13。★ 但要注意：这个选择【本身就是一个未经充分研究的旋钮】，
   各家取值不同，导致各家报的"已去污染"根本不是一回事。

更麻烦的：什么时候做去污染

★★ 一个关键的时序问题：

  评测集是【不断增加】的。
  你 2024 年训模型时做了去污染，2025 年出了新评测 —— 
  它的题目可能早就在你 2024 年的训练数据里了。

  ⟹ ★ "已去污染"只对【当时已知的评测集】成立，
       对未来的评测集完全不成立。

两个业界做法（⚠️ 我的整理）：

① Canary string（金丝雀字符串）
   ★ BIG-bench 这类评测在自己的文件里塞一个独一无二的 GUID 字符串。
     如果一个模型能背出这个 GUID，就【证明】它训练时吃过这个文件。
   ★ 同时它也给数据方一个明确的信号：看到这个字符串就把整个文件删掉。

② 事后检测（membership inference / 成员推断）
   不看训练数据，只看模型行为：
   把题目喂给模型，看它对【正确答案】的概率是不是异常地高，
   或者看它能不能补全出题目的后半句。
   ⚠️ 这类方法只能给出统计倾向，不能给出确证。

8.3 隐私：PII 的识别与处理

PII = Personally Identifiable Information（个人可识别信息），指能定位到具体某个人的信息。

典型的 PII：
   姓名、邮箱、手机号、身份证号、住址、
   银行卡号、社保号、车牌、IP 地址、生物特征

★ 为什么大模型场景下特别危险：
   模型会【逐字背下】训练数据（06 章：去重前逐字复制率 >1%）
   → 有人在网上贴过自己的手机号 → 模型可能在对话里把它吐出来
   → ★ 这已经不是"数据质量问题"，是【合规事故】

两种识别手段

① 正则（快，覆盖结构化的）
   邮箱、手机号、身份证号、银行卡、IP —— 这些都有明确格式
   ★ 中国身份证号还能用【校验位】验证，误报率可以做到很低

② NER 模型（Named Entity Recognition，命名实体识别）
   姓名、地址这类没有固定格式的，只能靠模型
   ⚠️ 但姓名的问题在于：★【无法区分公众人物和普通人】
      "马云宣布……" 该留，"张三的电话是……" 该删
      → 实践中一般【不删姓名】，只删"姓名 + 联系方式"同时出现的段落

处理方式：删除 vs 替换

★ 主流做法是【替换】而不是删除整篇：

   原文：请联系 zhangsan@example.com 或拨打 13812345678
   替换：请联系 <EMAIL> 或拨打 <PHONE>

   ★ 为什么替换更好：
     ① 保留了句子结构和语言信息（这段文字仍然是有效的语言样本）
     ② 删整篇会损失大量正常内容（PII 常出现在正常文档的角落里）
     ③ 模型反而学会了"这个位置是个联系方式"这个结构知识

⚠️ 但要小心【替换标记本身】被模型学成一个高频 token，
   在生成时莫名其妙冒出 <EMAIL>。★ 通常会做随机化处理。

✅ Dolma（2402.00159）是这方面披露最完整的开源语料——它把 PII 检测与掩码作为流水线的标准环节，并且整套工具链开源。⚠️ 具体规则请以其 PDF 与开源仓库为准。

import re
PATTERNS = {
    "<EMAIL>": re.compile(r"[\w.+-]+@[\w-]+\.[\w.-]+"),
    "<PHONE_CN>": re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)"),
    "<IP>": re.compile(r"(?<!\d)(?:\d{1,3}\.){3}\d{1,3}(?!\d)"),
    "<IDCARD_CN>": re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)"),
}

def mask_pii(text):
    hits = {}
    for tag, pat in PATTERNS.items():
        text, n = pat.subn(tag, text)
        if n: hits[tag] = n
    return text, hits          # ★ 一定要把命中统计留下来，用于审计

⚠️ 一个中文特有的坑：手机号正则如果不加 (?<!\d) / (?!\d) 边界，会把长数字串（订单号、时间戳）里的一段误判成手机号，在电商类语料上误伤极大。

8.4 许可与合规：不是技术问题，但会决定项目生死

三个已经发生过的真实事件

① Books3 下架
   ★ Books3 是 The Pile（2101.00027）的一个组成部分，包含约 19.6 万本书。
     因版权争议被下架。⚠️ 所有基于早期 Pile 训练的模型都受到牵连。
   → 教训：★ 你用的开源语料，【它的合规风险是你的风险】

② robots.txt 的收紧
   越来越多站点在 robots.txt 里明确禁止 AI 爬虫（GPTBot、CCBot 等）
   → [02 章](02-数据源与文本抽取.md)提过：Common Crawl 的可用内容在逐年缩水

③ 代码许可证
   GitHub 上的公开代码【不等于】可以随便用来训练。
   GPL 类传染性许可证的代码用于训练，法律地位至今没有定论。
   ★ 实践：按 SPDX 许可证白名单过滤（MIT / Apache-2.0 / BSD 等）

现在的三条路线

① 照用不误 + 事后应对        —— ⚠️ 多数商业模型的实际做法
② 只用明确开放许可的数据      —— Common Pile 是这条路线的代表
                                ★ 代价：数据量小得多，能力有差距
③ 买 / 签授权                —— 大厂与出版商、论坛、代码平台签独家协议
                                ★ 这正是 02 章说的"数据侧的真实差距"

中文场景下必须额外注意的

⚠️ 以下是我的整理，不构成法律意见，落地前请咨询法务：

① 《个人信息保护法》（PIPL）—— 对 PII 的要求比很多地区更严格
② 《生成式人工智能服务管理暂行办法》—— 对训练数据来源合法性有明确要求
③ 数据出境 —— 训练数据的跨境流动有单独的合规要求
★ 实践含义：中文语料的 PII 处理和来源存证，通常要做得比英文语料更重
   → ★ 一定要保留【每一条数据的来源、抓取时间、许可依据】，
      这叫【数据溯源 / provenance】，是合规审计的唯一抓手

8.5 ★ 数据溯源：一个被低估的工程要求

在你的每条记录里，除了 text，至少还要有：

  {
    "id": "...",
    "text": "...",
    "source": "commoncrawl/CC-MAIN-2024-10",   ← 哪来的
    "url": "https://...",                       ← 原始地址
    "crawl_date": "2024-03-01",                 ← 什么时候抓的
    "license": "CC-BY-4.0" | "unknown",         ← 许可依据
    "pipeline_version": "v3.2",                 ← ★ 哪一版流水线处理的
    "filters_passed": ["lid", "gopher", "dedup", "quality>=3.5"]
  }

★★ 为什么 pipeline_version 和 filters_passed 极其重要：
   半年后你发现"某条规则有 bug"，
   → 有这两个字段：直接定位受影响的数据，只重跑那部分
   → 没有：★ 只能【整条流水线从头重跑】，几周时间 + 几十万成本

★ 这一条是我最想强调的工程建议之一，因为它在事故发生前看起来完全没必要，而在事故发生后是唯一的救命稻草。同样的逻辑在 05 章（记录每条规则砍掉多少）和 07 章（人工抽样看被删的）都出现过——可观测性是数据流水线里最容易被省掉、也最不该省的东西。

8.6 小结

① ★★ 评测污染比"数据脏"危险，因为它【让指标骗你】：
   数据脏 → 分数掉 → 你看得见
   污染   → 分数涨 → ★ 你看不见，还会据此做出错误决策
   ✅ Lee et al.：标准验证集有 >4% 能在训练集里找到

② 三种污染，一种比一种难查：
   逐字 → n-gram 能查
   改写/翻译 → ⚠️ n-gram 查不到
   ★ 间接（针对性题库）→ 几乎无法定义边界，
     而质量分类器还会【主动把它们筛进来】

③ 去污染标准做法：n-gram 匹配，✅ GPT-3 用 13-gram
   n 小 → 误杀；n 大 → 漏检；⚠️ 各家取值不同 → "已去污染"不是一回事
   ★ 时序问题："已去污染"只对当时已知的评测集成立

④ PII = 个人可识别信息。危险在于模型会逐字背诵
   正则抓结构化的（邮箱/手机/身份证），NER 抓姓名地址
   ★ 主流是【替换成 <EMAIL> 这类标记】而非删整篇
   ⚠️ 中文坑：手机号正则不加数字边界会误伤长数字串

⑤ 许可：Books3 下架 / robots.txt 收紧 / 代码许可证不明
   三条路线：照用不误 / 只用开放许可（Common Pile）/ 买授权
   ⚠️ 中文场景还要考虑 PIPL 与生成式 AI 管理办法

⑥ ★★ 数据溯源（provenance）：每条记录都要带
   source / url / crawl_date / license / pipeline_version / filters_passed
   → 出了问题能定点重跑，而不是整条流水线从头再来
