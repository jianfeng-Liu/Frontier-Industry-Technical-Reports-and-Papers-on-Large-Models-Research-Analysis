# 10 · ⭐ 数据配比：网页 70%、代码 20%、数学 10% 是怎么定的

> **前面所有章节都在做"减法"（删掉不要的）。这一章开始做"加法"：**
> **留下来的这些数据，各自应该占多大比例？**
>
> ★ 这是数据领域里**搜索空间最大、验证最贵、各家最不愿意公开**的一环。

---

## 10.1 先说清楚"配比"到底指什么

```
你手上有 8 个清洗好的数据集：

   网页(en) 8 T   网页(zh) 3 T   代码 1.5 T   数学 0.3 T
   论文 0.4 T     书籍 0.2 T     百科 0.05 T  合成 1 T

而你只打算训 【15 T token】。

★ 配比 = 这 15 T 里，每一类各占多少
   例：  网页en 45% + 网页zh 20% + 代码 15% + 数学 6%
       + 论文 5% + 书籍 3% + 百科 3% + 合成 3%   = 100%
```

**两个立刻要注意的点：**

```
① ★ 权重 ≠ 数据量的比例
   百科只有 0.05 T，但你给了它 3%（= 0.45 T）
   ⟹ 它要被【重复用 9 遍】。这叫【上采样 up-sampling】
   ⟹ 反过来，网页(en) 有 8 T 但只用 6.75 T → 【下采样】，有一部分根本没用上

② ★★ "占多少"的单位必须是【token】，不是文档数、不是文件大小
   ⚠️ 04 章提过：Megatron 的 blend 权重实际作用在【样本】层面，
      不同数据集平均文档长度差异大时会跑偏。
      → 稳妥做法：先从 .idx 统计每个数据集的真实 token 总数，再反推权重。
```

---

## 10.2 为什么这件事很难

```
① ★ 搜索空间是连续的、高维的
   8 个数据源 → 8 维单纯形上的连续搜索
   （单纯形 simplex：所有分量非负且加起来等于 1 的那个空间）

② ★★ 验证一个配方 = 训一个模型 = 几十万美元、几周
   → 你最多试几十次，而空间是连续无穷的

③ 目标函数本身不明确
   "更好"是指 MMLU 更高？代码更强？中文更自然？长文本更稳？
   ★ 这些目标【互相冲突】：加代码会挤掉中文，加数学会挤掉常识

④ ⚠️ 最优配比【随模型规模变化】
   小模型上的最优配方，在大模型上不一定最优
   → 这直接威胁到"用小模型做代理实验"这整套方法论
```

---

## 10.3 第一代：人工拍脑袋（但没那么糟）

The Pile、Llama 早期版本，配比都是**人工定的**。逻辑大致是：

```
① 网页占大头 —— 因为它量最大、多样性最好
② 高质量小数据集【上采样】—— 百科、书籍重复 2~5 遍
③ 代码给 5~20% —— ★ 不是为了写代码，是因为公认能提升【推理能力】
④ 各语言按目标市场分配
⑤ ★ 然后跑几个小规模 ablation 微调一下
```

> ★ **别小看人工配比。** 直到现在，很多能力很强的模型仍然是**人工配比 + 少量消融**定下来的。
> ⚠️ 我的判断：**自动配比方法的收益，主要体现在"省掉了几十次昂贵试错"，而不是"找到了人类想不到的配方"**——下面 RegMix 那个反直觉结论是少数例外。

---

## 10.4 ★★ DoReMi：让小模型自己学出配比

✅ **DoReMi**（[arXiv:2305.10429](https://arxiv.org/abs/2305.10429)，Sang Michael Xie 等，Google/Stanford，2023-05）
名字来自 **Do**main **Re**weighting with **Mi**nimax optimization（用极小极大优化做领域重加权）。

### 核心思想

```
★ 不去问"哪个领域更重要"，而是问"哪个领域【学得最吃力】"，
  然后把权重加到那些领域上。

  直觉类比：一个学生各科成绩不均衡，
           与其平均分配复习时间，不如【多花时间在还没学好的科目上】
```

### 三步走

```
① 训一个【参考模型】（小，比如 280M）
   用一个基线配比（比如就用各数据集的自然大小比例）
   → 它给出每个领域的"正常水平损失" L_ref(domain)

② 训一个【代理模型】（同样 280M），但训练时【动态调整领域权重】
   ★ 用的是 Group DRO（Group Distributionally Robust Optimization，
     组分布鲁棒优化）—— 一个"最小化最差那一组的损失"的优化框架

   每一步：
     计算每个领域的【超额损失】
         excess(d) = max( L_proxy(d) − L_ref(d),  0 )
                     └─ 这个领域比"正常水平"差多少 ─┘
     ★ 超额损失大的领域 → 提高它的权重
     
     α(d) ← α(d) · exp( η · excess(d) )   然后归一化
            └────── 指数梯度上升 ──────┘

   ★★ 为什么要减掉 L_ref？
      因为不同领域的损失【绝对值本来就不同】——
      代码的熵天然比自然语言低。直接比绝对损失会系统性偏向某些领域。
      减掉参考模型的损失，比的就是【相对难度】了。

③ 把代理模型最终收敛的权重 α，拿去训【真正的大模型】
```

### ✅ 论文报告的结果

```
· 代理模型 280M → 直接用于训练 8B 模型，★ 规模差【30 倍】
· 在 The Pile 上：平均少样本准确率 ★ 提升 6.5 个百分点
· 达到基线的准确率，★ 只需要 2.6 倍更少的训练步数
· ⚠️ 有意思的是：DoReMi 学出来的权重会【降低】某些看起来"高质量"
   领域的权重 —— 因为那些领域模型学得很轻松，不需要多给
```

> ★★ **DoReMi 最重要的贡献不是那个具体配方，而是证明了：**
> **一个 280M 的小模型学出来的配比，能直接迁移到 30 倍大的模型上。**
> 这让"用代理模型搜配比"这条路在方法论上站住了脚。

## 10.5 ★★ RegMix：把配比当成回归问题

✅ **RegMix**（[arXiv:2407.01492](https://arxiv.org/abs/2407.01492)，Qian Liu 等，Sea AI Lab，2024-07）
思路和 DoReMi 完全不同，而且**更简单粗暴**：

```
① ★ 随机采样几百个【不同的配比】
   （从单纯形上随机撒点，比如用 Dirichlet 分布采样）

② 每个配比训一个【很小很小】的模型（1M ~ 100M 参数，训几千步就停）
   → 得到几百个 (配比向量 → 验证损失) 的样本点

③ ★★ 拟合一个【回归模型】：配比 → 损失
   ✅ 论文用的是 LightGBM（梯度提升树）
   → 现在你有了一个【几毫秒就能预测任意配比效果】的代理函数

④ ★ 在这个回归模型上做优化：
   随机生成一百万个候选配比 → 用回归模型全部预测一遍 → 选预测最好的
   ⟹ 因为预测是免费的，可以搜得极其彻底

⑤ 用选出的配比训大模型
```

```
★ 和 DoReMi 的关键差别：

  DoReMi：一次训练过程中【动态调整】权重 → 得到一个配方
          ⟹ 只探索了权重空间里的【一条轨迹】

  RegMix：撒一大把点【离散采样】整个空间 → 拟合出全局曲面 → 全局搜索
          ⟹ 探索的是【整个空间】，而且能看出"哪个领域的权重最敏感"

✅ 论文报告：RegMix 用【约 10% 的计算量】就达到或超过了 DoReMi 的效果
```

### ✅ 一个反直觉的发现

```
✅ RegMix 的回归模型优化出来的配方，
   把【网页数据（Pile-CC）】的权重推到了远高于人类直觉的水平。

★ 这挑战了当时的普遍做法 —— 大家都在想方设法【提高精选高质量数据的比例】，
  而回归结果说：网页数据的边际价值被系统性低估了。

⚠️ 具体的权重数值请以 [papers/RegMix-...-arXiv-2407.01492.pdf](papers/) 为准，
   我这里只保留方向性结论。
```

> ★ 这个发现和 [07 章](07-质量过滤.md) Nemotron-CC 的转向、[05 章](05-语言识别与启发式过滤.md)末尾的"主动放松过滤"，**指向的是同一件事**：
> **2024 年之后，业界对"狠筛出精品"的信心在下降，对"保住多样性和唯一 token 量"的重视在上升。**

## 10.6 ★★★ 现在真正在用的：多阶段配比（退火）

上面两种方法都假设**配比在整个训练过程中是固定的**。

**但现在几乎没有人这么做了。** 主流做法是：

```
★★ 训练过程分成几个阶段，每个阶段用【不同的配比】。

┌──────────────────────────────────────────────────────────────┐
│ 阶段一：主训练（占总 token 的 80~90%）                        │
│    配比：网页为主，量大管饱                                    │
│    目标：★ 建立语言能力和世界知识的【广度】                    │
│    学习率：高位平台                                            │
├──────────────────────────────────────────────────────────────┤
│ 阶段二：★ 退火 / 中训练（annealing / mid-training，最后 10~20%）│
│    配比：★★ 大幅提高【数学、代码、教科书、精选高质量、合成】   │
│          网页比例大幅下降                                      │
│    目标：把能力"定型"到高质量分布上                            │
│    学习率：★ 同时衰减到接近 0                                  │
└──────────────────────────────────────────────────────────────┘
```

**为什么这样有效？** ⚠️ 下面是我整理的直觉，不是某一篇论文的原话：

```
① ★ 学习率高时改的是"大方向"，学习率低时改的是"细节"
   → 最后阶段学习率很低，此时看到的数据【对最终权重的影响权重更大】
   → 所以要把最好的数据留到最后

② 高质量数据太少，如果均匀撒在整个训练里，
   会被海量网页"稀释"掉；集中在最后反而形成明确的信号

③ ★ 这跟人的学习也像：先大量泛读建立语感，最后集中刷高质量题
```

> ★★ **这个做法有很多名字，看到别慌，说的是同一件事：**
> **退火（annealing）/ 中训练（mid-training）/ 稳定-衰减（stable-decay）/ 课程学习（curriculum）的最后一段。**
>
> ⚠️ 我的补充：**这也让"最优配比"这个问题本身变得更复杂了**——现在要搜的不是一个权重向量，而是**一条随时间变化的权重轨迹**。DoReMi 和 RegMix 都还没有覆盖这个设定。

## 10.7 落到 Megatron 上怎么写

```
--data-path 的写法（权重 前缀 交替）：
    --data-path 0.45 /d/web_en_text_document \
                0.20 /d/web_zh_text_document \
                0.15 /d/code_text_document   \
                0.06 /d/math_text_document   \
                ...
```

```python
# ★ 先统计真实 token 数，再反推权重（04 章的坑⑤）
import numpy as np

def total_tokens(prefix):
    lengths, _, _ = read_idx(prefix + ".idx")     # 04 章的 .idx 读取
    return int(np.sum(lengths))

target = {                     # 你想要的【token 占比】
    "web_en": 0.45, "web_zh": 0.20, "code": 0.15, "math": 0.06,
    "paper": 0.05, "book": 0.03, "wiki": 0.03, "synth": 0.03,
}
avg_len = {k: total_tokens(P[k]) / n_docs[k] for k in target}   # 各集平均文档长度

# ★ 样本级权重 = token 目标占比 / 平均文档长度，再归一化
raw = {k: target[k] / avg_len[k] for k in target}
s = sum(raw.values())
sample_weight = {k: v / s for k, v in raw.items()}

# ★ 顺手算一下每个数据集被重复几遍 —— 这个数直接决定 11 章的结论
TOTAL = 15e12
for k in target:
    epochs = TOTAL * target[k] / total_tokens(P[k])
    flag = "  ⚠️ 重复过多" if epochs > 4 else ""
    print(f"{k:8s} 目标 {target[k]*100:4.1f}%  重复 {epochs:5.2f} 遍{flag}")
```

> ★★ 最后那个循环是本章**最实用的一段代码**。它把配比翻译成了"每个数据集要重复几遍"——
> 而 [11 章](11-喂多少-ScalingLaw.md) 会告诉你，**重复超过约 4 遍之后，收益开始明显衰减**。
> **配比表和重复次数表必须一起看，只看配比是看不出问题的。**

## 10.8 挂回真实系统

| 方法 | 怎么定配比 | 代价 | 出处 |
|---|---|---|---|
| **The Pile / 早期 Llama** | 人工 + 少量消融 | 低 | [2101.00027](https://arxiv.org/abs/2101.00027) |
| **DoReMi**（2023） | 小代理模型 + Group DRO 动态调权 | 中 | ✅ [2305.10429](https://arxiv.org/abs/2305.10429) |
| **RegMix**（2024） | 几百个微型模型 + 回归 + 全局搜索 | ✅ 低（DoReMi 的 ~10%） | ✅ [2407.01492](https://arxiv.org/abs/2407.01492) |
| **Data Mixing Laws** | 拟合"配比 × 规模 × 步数"的嵌套标度律 | 中 | ⚠️ 该论文不在本目录 papers/ 内 |
| **★ 多阶段退火** | 主训练 + 最后 10~20% 换高质量配比 | — | ★ 现在的事实标准 |

> ⚠️ **五家国产模型的配比披露**：详见 [16 章](16-五家报告的数据章节.md)。
> **总体上，配比是这一代技术报告里披露最少的部分**——多数只说"经过精心设计的多阶段数据配比"，不给具体数字。这是可以理解的：**配比是少数几个可以直接抄的东西。**

## 10.9 小结

```
① 配比 = 训练预算里每类数据各占多少【token】
   ★ 权重 ≠ 数据量比例：小而精的数据要【上采样】（重复用），
     大而杂的数据往往【下采样】（用不完）
   ⚠️ Megatron 的 blend 权重作用在【样本】层面 → 先统计 token 数再反推

② 难在哪：搜索空间连续高维 / 验证一次 = 训一个模型 /
   目标互相冲突 / ⚠️ 最优配比随模型规模变化

③ ✅ DoReMi（2305.10429）：不问"谁重要"，问"谁学得吃力"
   参考模型给基线损失 → 代理模型用 Group DRO 按【超额损失】动态提权
   ★ 减掉参考损失是为了消除各领域损失绝对值的天然差异
   结果：280M 代理 → 8B 模型（★ 差 30 倍），平均少样本 +6.5 分，
        2.6 倍更少步数

④ ✅ RegMix（2407.01492）：撒几百个随机配比 → 训微型模型 →
   拟合回归（LightGBM）→ 在回归上全局搜索
   ★ 只用 DoReMi 约 10% 的算力就达到或超过它
   ★ 反直觉发现：网页数据的权重应该比人类直觉【高得多】
     → 和 07 章 Nemotron-CC、05 章"放松过滤"指向同一件事

⑤ ★★★ 现在真正在用的是【多阶段退火】：
   前 80~90%：网页为主，建立广度，学习率高
   后 10~20%：★ 大幅提高数学/代码/教科书/合成，学习率衰减到近 0
   别名：退火 / 中训练 / stable-decay / 课程学习末段 —— 都是同一件事
   ⚠️ 于是要搜的不再是一个权重向量，而是一条【随时间变化的轨迹】，
      DoReMi 和 RegMix 都还没覆盖这个设定

⑥ ★★ 实践铁律：配比表要和【每个数据集重复几遍】的表一起看
   （重复超过约 4 遍收益明显衰减 —— 见 11 章）
```
