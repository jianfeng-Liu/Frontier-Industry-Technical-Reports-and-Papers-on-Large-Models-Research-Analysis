# 11 · ⭐ 喂多少：Scaling Law 与"数据不够用了"

> **这一章回答两个问题：**
> **① 给定算力，应该训多大的模型、喂多少数据？**
> **② 数据不够怎么办——重复用行不行、能重复几遍？**
>
> ★ 第二个问题的答案（**约 4 遍**）是本章最实用的一个数字。

---

## 11.1 先建立记号

```
N_p = 模型参数量        （很多论文里写作 N）
N_d = 训练总 token 数   （很多论文里写作 D）
C   = 训练总计算量，单位 FLOPs（浮点运算次数）

★★ 一个必须记住的近似公式：
        C ≈ 6 · N_p · N_d

   为什么是 6？
     前向传播：每个参数对每个 token 做 1 次乘 + 1 次加 = 2 FLOPs
     反向传播：★ 大约是前向的 2 倍          = 4 FLOPs
                                       合计 = 6 FLOPs
   ⚠️ 这是个粗略估计，忽略了注意力里与序列长度相关的那部分。
      序列很长时会低估。但做数量级判断完全够用。
```

**这个公式的用处**：把"算力"翻译成"模型大小 × 数据量"的一条**等高线**。

```
你有 1e24 FLOPs 的算力预算，那么：
    N_p = 10 B, N_d = 16.7 T   ✓ 都满足 6·N_p·N_d = 1e24
    N_p = 70 B, N_d = 2.4 T    ✓
    N_p = 500 B, N_d = 0.33 T  ✓

★ 全都"花光了预算"，但效果完全不同 —— 那到底该选哪个？
  ⟹ 这就是 Chinchilla 要回答的问题。
```

## 11.2 ★★ Chinchilla：算力应该怎么分配

✅ **Training Compute-Optimal Large Language Models**
（[arXiv:2203.15556](https://arxiv.org/abs/2203.15556)，Jordan Hoffmann 等，DeepMind，2022-03）

### 它推翻了什么

```
在它之前（2020 年 Kaplan 等的工作影响下），业界的共识是：
   ★ "算力主要应该花在【把模型做大】上，数据量增长可以慢一点"
   → 于是有了 GPT-3（175B，训了约 300 B token）
     和 Gopher（280B，训了约 300 B token）

Chinchilla 说：★★ 这些模型全都【严重欠训练】。
```

### 它的结论

```
★★★ 参数量和数据量应该【等比例增长】。

   算力翻倍 → 模型大小 × √2，数据量也 × √2
   
   最优比例（论文的核心经验法则）：
       ★ N_d / N_p ≈ 20
       "每 1 个参数配约 20 个训练 token"
```

### 它的证据

```
✅ 论文训了【400 多个】模型（70 M ~ 16 B 参数，5 B ~ 500 B token），
   用三种独立方法拟合，三种方法给出了一致的结论。

✅ 最有力的验证：
   训了一个叫 Chinchilla 的模型 —— 70 B 参数、1.4 T token
   用的算力和 Gopher（280 B 参数、300 B token）★ 完全相同
   → Chinchilla 在几乎所有评测上【全面超过】4 倍大的 Gopher
   ★ 参数少 4 倍，数据多 4.7 倍，效果更好
```

### 拟合出来的公式

✅ 论文拟合的损失函数形式（这是本章唯一需要看的公式）：

```
    L(N_p, N_d)  =  E  +  A / N_p^α  +  B / N_d^β
                    │      └────────┘   └────────┘
                    │      模型不够大    数据不够多
                    │      带来的损失    带来的损失
                    └─ 不可约损失：★ 语言本身的熵，再多算力也降不下去

✅ 论文拟合值：E = 1.69，A = 406.4，B = 410.7，α = 0.34，β = 0.28
⚠️ 具体数值请以 [papers/Chinchilla-...-arXiv-2203.15556.pdf](papers/) 为准。

★ 怎么读这个公式：
  α 和 β 很接近（0.34 vs 0.28）
  → ★★ 说明"加参数"和"加数据"的边际收益【差不多】
  → 所以最优策略是【两者等比例增长】—— 这就是 N_d/N_p ≈ 20 的来源
```

```python
# ★ 一个能跑的最优分配计算器
def chinchilla_optimal(C, E=1.69, A=406.4, B=410.7, a=0.34, b=0.28):
    """给定算力 C（FLOPs），返回最优 (参数量, token 数)"""
    import numpy as np
    from scipy.optimize import minimize_scalar
    # 在 6·N·D = C 的约束下最小化 L
    f = lambda logN: (E + A / np.exp(logN)**a
                        + B / (C / (6*np.exp(logN)))**b)
    r = minimize_scalar(f, bounds=(np.log(1e6), np.log(1e13)), method="bounded")
    N = np.exp(r.x)
    return N, C / (6*N)

for C in [1e21, 1e23, 1e25]:
    N, D = chinchilla_optimal(C)
    print(f"C={C:.0e}  N_p={N/1e9:8.1f} B   N_d={D/1e12:7.2f} T   D/N={D/N:5.1f}")
```

## 11.3 ★★★ 但现在没有人按 Chinchilla 训了

这是本章**最重要的一段**，也是新手最容易被误导的地方。

```
Llama-3-8B：8 B 参数，训了 15 T token
   → N_d / N_p = 1875
   ★★ 是 Chinchilla 最优（20）的【约 94 倍】

按 Chinchilla 的标准，这是【极度过训练（over-trained）】。
那 Meta 是算错了吗？—— ★ 没有。是【优化目标不同】。
```

### 为什么

```
★★ Chinchilla 优化的是【训练算力】。
   但一个模型训完之后，要被【推理几万亿次】。

   总成本 = 训练成本（一次性） + 推理成本（× 调用次数）
                                  └─ ★ 商业上这一项通常大得多 ─┘

   而推理成本 ∝ 参数量。
   
⟹ ★★★ 于是正确的做法变成：
     【故意把模型做小，用远超 Chinchilla 最优的数据量硬训】
     
     牺牲一点训练效率，换来永久的推理成本下降。
```

```
一张对照表帮你记住（⚠️ 我的整理，用于建立直觉）：

  目标                    最优策略                D/N 典型值
  ─────────────────────────────────────────────────────────
  ★ 只关心训练算力         Chinchilla                 ~20
  ★ 关心部署后的推理成本   过训练小模型             100 ~ 2000
  ★ 追求绝对能力上限       两者都拉满                 视预算
```

> ★★ **给小白的一句话总结**：
> **Chinchilla 告诉你"在给定算力下损失最低的点在哪"，但那个点【不是商业上最优的点】。**
> 现在的模型几乎全都**故意站在 Chinchilla 曲线的右边**（数据更多、模型更小）。
>
> ⚠️ 所以看到有人说"这个模型不符合 Chinchilla 最优、训练是浪费的"，这是**对 Chinchilla 的误用**。

### ★ 这直接引出了本教程的核心矛盾

```
模型故意变小 + 数据量拉到极致
   ⟹ ★★ 对【数据量】的需求爆炸式增长
   ⟹ 而高质量网页是【有限的】
   ⟹ 于是有了 11.4 的问题：不够了怎么办？
```

## 11.4 ⚠️ 数据墙：到底还剩多少数据

```
⚠️ 以下是我整理的量级估算，不是任何一篇论文的精确结论：

   Common Crawl 全部快照去重后的英文文本    ~ 几十 T token 量级
   加上所有语言、代码、论文、书籍            ~ 100 ~ 数百 T token 量级
   
   而单个前沿模型的训练量已经到了 15 ~ 30 T token
   
★★ 结论：数量级上已经【在同一个量级】了。
   这就是被广泛讨论的"数据墙（data wall）"。
```

**三条出路**，本教程各有一章：

```
① 重复用          → ★ 本章 11.5
② 造新的（合成）   → [12 章](12-合成数据.md)
③ 放松过滤，把之前扔掉的捡回来 → [05 章](05-语言识别与启发式过滤.md) / [07 章](07-质量过滤.md)（Nemotron-CC 路线）
```

## 11.5 ★★★ 重复几遍还有用？答案是"约 4 遍"

✅ **Scaling Data-Constrained Language Models**
（[arXiv:2305.16264](https://arxiv.org/abs/2305.16264)，Niklas Muennighoff 等，2023-05，NeurIPS 2023 最佳论文亚军）

**这是本教程最实用的一篇论文。** 它系统地回答了"数据不够时重复用会怎样"。

### 实验设置

```
✅ 训了约 400 个模型，最大到 90 亿参数、9000 亿 token
✅ 固定一个较小的唯一数据集，反复训多个 epoch，看损失怎么变
```

### ✅ 核心结论

```
★★★ 结论一（最重要的一条）：
   【重复最多约 4 个 epoch，效果与使用同等数量的全新数据几乎没有差别。】
   
   也就是说：你有 1 T 唯一数据，训 4 T token（重复 4 遍），
   ★ 效果接近于你真有 4 T 唯一数据。这是【免费的 4 倍】。

   ✅ 论文给的具体实例（★ 这是"几乎没有差别"的量化）：
      90 亿参数模型，用 440 亿唯一 token 重复【4 遍】，
      最终验证 loss 只比"用 1780 亿唯一 token 训 1 遍"★【高 0.5%】。

★★ 结论二：★ 超过 4 个 epoch 之后收益衰减，但【不是立刻归零】。
   ✅ 论文给了两个更精确的刻度：
      · ★ 一直到约【16 个 epoch】仍能拿到有意义的收益，
        ✅ 论文的说法是"16 epoch 之后收益衰减得极快"
        （这个 16 来自它拟合出的"epoch 半衰期"参数 R*_D ≈ 15）
      · ★★ 到【40 个 epoch】，重复已经【毫无价值】
   ⟹ ★ 所以"4"是【零代价线】，"16"是【还值得做线】，"40"是【死线】。
   ⚠️ 注意：这些是【loss】上的刻度。
      ✅ 论文另外报告：下游任务表现在【约 4 个 epoch 之后就开始下滑】，
      ⟹ ★★ 也就是说【下游任务比 loss 更早变差】—— 实践中按 4 来把关更稳。

★ 结论三：
   论文还给出了一个【修正版的 Chinchilla 公式】，
   把"重复数据的价值衰减"显式建模了进去
   （直觉：第 k 遍的数据，其"有效 token 数"按指数衰减）
   
★ 结论四：
   在数据受限的情况下，一些平时"有害"的做法反而变得划算，
   比如【混入代码数据】来扩充可用 token，
   以及★【放宽过滤阈值】—— 
   ⟹ 这直接为 Nemotron-CC 的"主动放松过滤"提供了理论依据
```

```
一张示意图（⚠️ 我画的定性示意，不是论文的实测曲线）：

  相对
  收益
   1.0 ┤████ ████ ████ ███▉
       │                  ▝▚▖        ← ★ 约 4 遍之后开始明显衰减
   0.5 ┤                     ▝▀▚▄▖
       │                          ▀▀▀▄▄▄▖   ← ★ 约 16 遍之后衰减极快
   0.0 ┤                                 ▀▀▀▀▀▀▀▀▀▀  ← ★ 约 40 遍已毫无价值
       └──┬────┬────┬────┬────┬────┬────┬────┬────┬──→ epoch
          1    2    3    4    8   16   32   64  128
                         ↑ 零代价线  ↑ 还值得做线
```

> ★★★ **这个"4"是本章最该记住的数字。** 它直接给了你一条**可操作的检查规则**：
>
> ```
> 回到 [10 章](10-数据配比.md)最后那段代码 —— 它会打印每个数据集重复几遍。
> ★ 任何一项超过 4，就要警惕：
>    这部分权重可能是【浪费】的，不如降下来给别的数据。
> ```
>
> ⚠️ **注意边界条件**：这个"4"是在**该论文的实验设定下**得出的。数据质量越高、越多样，可重复次数可能更多；反之更少。**把它当作一个数量级参考，而不是一条物理定律。**

## 11.6 把三章串起来：一个完整的决策流程

```
输入：算力预算 C，手头的唯一数据量 U，部署时的推理量

  ① 先按 Chinchilla 算一个参考点
        N_p*, N_d* = chinchilla_optimal(C)      # 11.2

  ② 根据推理量【往右修正】：推理量越大，模型越往小调
        N_p = N_p* / k       （k 常见取 2 ~ 10）
        N_d = C / (6 · N_p)   ← 数据量相应放大 k 倍      # 11.3

  ③ 检查数据够不够
        if N_d <= 4 · U:    ✅ 够，重复不超过 4 遍     # 11.5
        else:               ⚠️ 不够，三选一或组合：
              · 放松过滤，把 U 做大                    # 05 / 07 章
              · 合成数据                              # 12 章
              · ★ 承认上限，把 N_d 压回 4·U，把省下的算力给 N_p

  ④ 在 N_d 内部分配各领域配比                          # 10 章
  ⑤ 检查每个数据集各自的重复次数是否也 ≤ 4             # 10.7 的代码
  ⑥ 设计多阶段退火，把最好的数据留到最后 10~20%        # 10.6
```

> ★ 这六步就是"数据侧顶层设计"的全部骨架。**记住这个流程，比记住任何一个具体数字都有用。**

## 11.7 小结

```
① ★★ C ≈ 6 · N_p · N_d  —— 把算力翻译成"模型大小 × 数据量"
   （前向 2 + 反向 4；⚠️ 忽略了注意力里与序列长度相关的部分）

② ✅ Chinchilla（2203.15556）：参数量和数据量应【等比例增长】
   ★ 最优 N_d / N_p ≈ 20（"每个参数配 20 个 token"）
   证据：400+ 个模型 + 三种方法一致；
        ★ 70B/1.4T 的 Chinchilla 在同等算力下全面超过 280B/300B 的 Gopher
   公式：L = E + A/N_p^α + B/N_d^β
        ✅ E=1.69, A=406.4, B=410.7, α=0.34, β=0.28
        ★ α≈β → 加参数和加数据的边际收益差不多 → 所以等比例增长

③ ★★★ 但现在没人按 Chinchilla 训（本章最重要的一段）：
   Llama-3-8B 的 D/N = 1875，是 Chinchilla 最优的约 94 倍
   ★ 原因：Chinchilla 只优化【训练】算力，而商业上【推理】成本大得多
   ⟹ 故意把模型做小、用远超最优的数据量硬训，
      牺牲训练效率换永久的推理成本下降
   ⚠️ 所以"不符合 Chinchilla 就是浪费"是对它的误用

④ ⚠️ 这直接造成了【数据墙】：
   可用文本总量（~100 至数百 T token 量级）与单模型训练量（15~30 T）
   已经在同一个数量级上

⑤ ★★★ ✅ Scaling Data-Constrained LMs（2305.16264）——最实用的一篇：
   · 重复最多约 【4 个 epoch】，效果 ≈ 同等数量的全新数据（免费的 4 倍）
     ✅ 实例：90 亿模型重复 4 遍，验证 loss 只高 0.5%
   · ★ 三条刻度：4 遍=【零代价线】/ 16 遍=【还值得做线】/ 40 遍=【死线】
     ⚠️ 但下游任务比 loss 更早变差（约 4 遍后就开始下滑）⟹ 按 4 把关最稳
   · 给出了把"重复衰减"建模进去的修正版 Chinchilla 公式
   · ★ 数据受限时，混入代码、放宽过滤反而划算
     → 为 Nemotron-CC 的"主动放松过滤"提供了理论依据
   ⚠️ "4"是该实验设定下的结论，当量级参考用，别当物理定律

⑥ ★ 决策流程六步：Chinchilla 算参考点 → 按推理量往小调模型 →
   检查 N_d ≤ 4·U → 定配比 → 检查各数据集重复次数 → 设计退火
```
