12 · 合成数据：数据不够就自己造

11 章结尾给了三条出路，这一章讲第二条：用模型生成训练数据。

★ 这是 2023 年之后增长最快、也是争议最大的一个方向。
★★ 11.5 算出了"重复用"这条路的硬上限（有效 token 最多 16.4 倍唯一数据）。合成数据存在的理由，就是想突破那个上限。

12.1 先破除一个直觉障碍

新手听到"用模型生成数据来训模型"，第一反应通常是：

"这不是自己教自己吗？能有什么新信息？"

这个疑问很合理，答案分三层：

① ★ 大多数合成数据不是"凭空造"，而是【改写已有数据】
   原料是真实网页的信息，模型只负责【换一种表达方式】
   ⟹ 信息量没变，但【形式变好了】—— 这就是价值

② ★★ 训练的瓶颈往往不是"信息量"，而是【信息的呈现形式】
   同一个知识点：
     · 埋在一篇有广告、有导航、语无伦次的网页里
     · 写成一段清晰的教科书式讲解
   ⟹ 后者的【学习效率】高得多。这不是新信息，但确实更好学。

③ ★★★ 在【可验证】的领域，合成数据能产生【真正的新信息】
   数学题：生成一道题 + 解法 → ★ 可以用求解器验证对不对
   代码：  生成一个函数 + 测试 → ★ 可以直接运行验证
   ⟹ 验证器提供了模型自身没有的【外部信号】
   ⟹ ★ 这就是为什么合成数据在数学和代码上效果最好、争议最小

★★ 记住这个三层结构，本章后面所有方法都能归到这三类里。

12.2 两大范式与四条技术路线

★ 先按"原料从哪来"分成两大范式

① 改写型（source-rephrasing） ② 生成型（generator-driven）
输入 一篇真实网页 一个主题 / 提示词 / 一组种子概念
动作 让模型换个风格重写 让模型从头写一篇
输出 内容相同、表达更好的文本 全新的教科书、习题、对话
✅ 优点 ★ 事实锚定在原文上，幻觉风险低；
多样性由原始语料天然保证		 ★ 质量上限高，
可以精确控制难度和形式
❌ 缺点 受限于原文的信息，
★ 上限就是原语料		 ⚠️ 幻觉风险高；
★★ 多样性【极难保证】
它能不能突破 11.5 的 16.4 倍上限 ⚠️ 不能真正突破——信息还是那些，
但 ★ 能把"唯一 token 量"做大（见 12.5）		 ★ 理论上能，
但只在可验证领域站得住（见 12.7）
代表工作 WRAP、Nemotron-CC phi 系列、Cosmopedia

★★ 再按"具体怎么造"分成四条技术路线

这四条路线在实践中经常混用，但它们"需要什么 / 产出什么 / 风险在哪"完全不同。下面这张表是本节的核心：

技术路线 它需要什么 它产出什么 ⚠️ 风险是什么 属于哪个范式
① 蒸馏
（distillation）		 ★ 一个比目标模型更强的教师模型 + 一批种子提示词 (提示词, 教师回答) 对，
或教师的 logits / 推理轨迹		 ★ 上限被教师锁死，学不会教师不会的；
会连教师的错误与文风一起继承；
⚠️ 许可风险最大（见 12.6 风险三）		 多为生成型
② 自我博弈 / 自我改进
（self-play / self-improvement）		 ★★ 一个能打分的验证器或奖励模型（必需！）
+ 模型自己多次采样		 从自己的 N 个输出里筛出来的那几个，
以及"错的"那些（可做负例）		 ★★ 没有可靠验证器时会放大自身偏差；
⚠️ 多样性坍缩（反复筛同一类解法）；
奖励模型本身会被"钻空子"（reward hacking）		 生成型
③ 规则 / 程序生成
（procedural generation）		 ★ 一个程序或语法（题目模板、符号求解器、编译器、数据库 schema） 海量格式完全规整、
★ 答案天然正确的样本		 ★ 分布极窄，和真实分布不匹配；
⚠️ 模型会学到模板捷径（看到句式就套答案，不理解）；
难度分布要人工设计		 生成型
④ 回译 / 反向生成
（back-translation）		 ★ 大量无标注的高质量目标端文本
+ 一个"从答案倒推问题"的反向模型		 (伪造的输入, 真实的输出) 对
★ 输出端是人写的，这是它最大的优势		 ⚠️ 伪造的输入可能不自然、和真实提问分布不符；
反向模型的错误会传播；
★ 需要一道筛选把低质配对丢掉		 介于两者之间 
★★★ 这张表最该记住的一行是【④ 回译】，因为它的风险结构和其他三条相反：

   ①②③ 的产出【输出端是模型写的】→ 幻觉和风格坍缩的风险都在输出端
   ④    的产出【输出端是人写的】  → ★ 输出端完全可信，风险全在输入端
                                      而输入端（提问）出点问题，危害小得多

★ 回译在机器翻译里是二十年的老技术（用目标语的单语语料反译成源语）。
  ✅ 它在大模型时代的对应物是【指令回译】：
     Self-Alignment with Instruction Backtranslation
     （[arXiv:2308.06259](https://arxiv.org/abs/2308.06259)，Xian Li 等，Meta AI，2023-08，ICLR 2024）
     ✅ 做法两步：
        · self-augmentation（自我增广）：给一篇真实网页，让模型反推
          "什么样的指令会让人写出这篇文章"
        · self-curation（自我筛选）：再让模型给这些 (指令, 文章) 对打分，
          ★ 只留高分的
     ✅ 论文报告：在 LLaMa 上迭代两轮，在 Alpaca 榜上超过了所有
        【不依赖蒸馏数据】的同底座模型。
     ⚠️ 该论文不在本目录 papers/ 内，以上转述其公开摘要。

12.3 改写型代表：WRAP

✅ Rephrasing the Web (WRAP)
（arXiv:2401.16380，Pratyush Maini 等，CMU / Apple，2024-01）

做法：用一个中等大小的开源指令模型，
      把 C4 的网页按【四种风格】各改写一遍：

   ① easy      —— ★ "像给小孩解释一样"（对应 07 章 DCLM 用 ELI5 当种子的同一直觉）
   ② medium    —— 维基百科风格
   ③ hard      —— 学术论文风格
   ④ Q/A       —— ★ 改写成一问一答的形式

★★ 为什么要【多种风格】而不是只用最好的那种？
   因为不同风格覆盖不同的下游能力，而且★多风格本身就是一种【多样性保护】
   ⟹ 这一条直接针对 12.2 表里"生成型 = 多样性极难保证"那个缺点

✅ 论文报告的结果：

· 在合成数据 + 真实数据混合训练下，
  ★ 预训练速度提升约 3 倍（达到同样效果所需的算力）
· 在 Pile 的多个子集上困惑度下降
· 零样本问答准确率提升约 10%

⚠️ "提速 3 倍"这句话要按 11 章的口径读一遍：
   它的意思是【达到同样效果所需的算力降到约 1/3】，
   ★ 不是"训练时间减少 3 倍"（那句话没有意义），
   也不是"时间减少 3%"。
   ⟹ 换算：算力降到 33%，等价于【减少 67%】。
     ★ 「加速 3 倍」和「时间减少 67%」是同一件事的两种说法，
       而「加速 300%」通常指的是 4 倍 —— ⚠️ 这个说法建议直接避免。

★ WRAP 的关键设计：合成数据是和真实数据【混着用】的，不是替代。
这一点后面 12.6 讲"模型坍塌"时会非常重要。

12.4 生成型代表：phi-1 与 Cosmopedia

✅ phi-1：Textbooks Are All You Need

（arXiv:2306.11644，Suriya Gunasekar 等，Microsoft，2023-06）

✅ 配置（★ 这组数字非常震撼，值得记住）：
   模型：1.3 B 参数（★ 极小）
   算力：8 张 A100，4 天
   数据：· 6 B token —— 从 The Stack + StackOverflow 里【筛出来】的
                       "教科书质量"的代码
                       ★ 筛选器是用 GPT-4 标注训的分类器（07 章第三代方法）
         · 1 B token —— ★ 用 GPT-3.5 生成的合成教科书与习题
                       ⟹ 这就是 12.2 表里的【① 蒸馏】路线

✅ 结果：HumanEval pass@1 = 50.6%，MBPP = 55.5%
   ★ 用当时几十倍大的模型的水平，只花了 1.3 B 参数和 4 天

★ 顺手用 11 章的公式估一下它的训练算力（⚠️ 我的估算，不是论文数字）：
   C ≈ 6 × 1.3e9 × 7e9 = 5.5e19 FLOPs
   8 张 A100（BF16 稠密峰值 312 TFLOPS）× 4 天 = 768 卡时
     → 可用算力 = 768 × 312e12 × 3600 = 8.6e20 FLOPs
   ⟹ 5.5e19 / 8.6e20 ≈ 6.4%
   ⚠️ 这个比例远低于正常 MFU（30~45%），说明它大概训了【多个 epoch】
      或者卡时数是上限口径。★ 这里的用处只是建立"1.3 B 模型有多便宜"的量级感。

★★ phi-1 的论点是"数据质量可以换算力和参数量"，这在当时是很激进的。

⚠️ 必须同时知道的批评：phi 系列一直被质疑合成数据里可能间接混入了评测题的近亲（08 章的间接污染）——用 GPT-3.5 生成"编程习题"，而 GPT-3.5 自己见过 HumanEval。这个质疑至今没有被完全澄清。
★ 所以 phi 的正确读法是：它证明了这条路走得通，但具体分数要打折看。
★★ 更一般地：凡是"用闭源强模型造数据"（蒸馏路线），去污染就从"查训练集"变成了"查一个你看不见的训练集"——这是 12.2 表里蒸馏那一行风险最隐蔽的部分。

Cosmopedia：★ 一个把"多样性问题"讲得最清楚的案例

HuggingFace 用 Mixtral-8x7B 生成的合成教科书语料（约 250 亿 token）。

★★ 它遇到的核心难题，正是生成型范式的命门：
   如果你就用"写一篇关于 X 的教科书"这个提示词，
   ⟹ 模型生成的几万篇文章会【高度雷同】：
      同样的开头、同样的结构、同样的例子

★ 它的解法：把提示词做成【组合爆炸】
   种子主题（几十万个，从真实语料里抽）
     × 受众（小学生 / 大学生 / 专业人士 / 完全外行）
     × 体裁（教科书章节 / 博客 / 维基条目 / 课堂讲稿 / 故事）
     × 风格
   ⟹ 每一篇的提示词都不同 → ★ 多样性由【提示词的多样性】来保证

★ 感受一下组合爆炸的量级（⚠️ 下面是示意算术，不是 Cosmopedia 的实际配置）：
   30 万个种子主题 × 4 种受众 × 5 种体裁 × 4 种风格
     = 30万 × 80 = ★ 2400 万个互不相同的提示词
   ⟹ 要造 250 亿 token、每篇按 1000 token 算 = 2500 万篇，
     ★ 恰好和提示词数量同量级 —— 这不是巧合，而是设计目标：
       【让提示词的数量和文章的数量同量级，这样几乎没有两篇共享同一个提示词。】

★★★ 这引出了生成型范式最重要的一句话：
     【合成数据的多样性上限，由种子的多样性决定，不由生成模型决定。】

12.5 ★★★ Nemotron-CC：把两件事合起来的做法

✅ 07 章讲过 Nemotron-CC（2412.02595）的分档过滤。它的合成数据用法极其巧妙，值得单独讲：

传统流水线：
   低质量数据  ──→  ★ 直接丢掉

Nemotron-CC：
   低质量数据  ──→  ★★ 交给模型【改写】成高质量  ──→  留下来用

⟹ 一石二鸟：
   ① 提升了这部分数据的质量
   ② ★ 保住了它的【唯一 token 量】—— 而这正是 11 章说的稀缺资源

✅ 论文报告：全量版本达到与 DCLM 相当的效果，但有4 倍多的唯一 token。

★★ 把这个"4 倍"接到 11.5 那张表上，才能看出它值多少钱：

   假设你原本有 U 的唯一 token，需要训 4U 的量：
     不改写 → 重复 4 遍 → 有效 token = 3.726 U（有效率 93.1%）
     改写后 → 唯一量变成 4U → 训 1 遍 → 有效 token = 4.000 U（100%）
   ⟹ 这一档差 7%，★ 看着不多。

   但如果你需要训 16U：
     不改写 → 重复 16 遍 → 有效 token = 10.582 U（有效率 66.1%）
     改写后 → 唯一量 4U，重复 4 遍 → 有效 token = 4 × 3.726 = 14.90 U（93.1%）
   ⟹ ★★ 差 41%。而且距离"重复用"的天花板（16.4 U）越近，这个差距越大。

★★★ 所以"唯一 token ×4"的真正价值不是"多了 3 倍数据"，而是
     【把你在 11.5 那条衰减曲线上的工作点，从陡降段拉回平坦段】。

★★★ 这是本章我最想让你记住的一个思想转变：

旧观念：过滤 = 一个【二分类】问题，好的留、坏的删 新观念：过滤 = 一个【分诊】问题 高质量 → 直接用 中质量 → 用 ★ 低质量 → 【改写后再用】，而不是删 垃圾 → 才删

这把 07 章的"质量过滤"和本章的"合成数据"缝成了一件事。

12.6 ⚠️ 三个真实的风险

风险一：★★ 模型坍塌（model collapse）

✅ 出处：AI models collapse when trained on recursively generated data，Shumailov、Shumaylov、Zhao、Papernot、Anderson、Gal，Nature 631(8022), 755–759（2024-07-24，开放获取，DOI 10.1038/s41586-024-07566-y）。✅ 它的核心主张是：不加区分地学习其他模型产出的数据会导致"模型坍塌"——模型会逐渐忘掉真实的底层分布，即使这个分布本身完全没有变化；✅ 并且在大语言模型、VAE（变分自编码器）和高斯混合模型上都复现了这个现象。⚠️ 该论文不在本目录 papers/ 内，以上是对其公开摘要的转述。

现象：如果【递归地】用模型生成的数据训下一代模型，
     一代一代下去，模型会逐渐【丢失分布的尾部】，
     最后收敛到一个方差极小、乏味的分布上。
     ★ 像复印件的复印件。

★★ 机制：三条，其中第一条可以算出来

⚠️ 下面这三条机制是我整理的解释与算术，不是论文的原文推导；但它们都能自己验算。

★★★ 机制一：有限采样会【整块地丢掉】低概率事件（最主要的一条）

  设真实分布里有一个稀有表达，出现概率 p = 1e-4
  （量级参照：在一个 10 亿 token 的语料里出现 10 万次，不算罕见）。

  你用模型生成 10,000 个样本当作下一代的训练语料。
    这个表达出现次数的期望 = 10,000 × 1e-4 = 1 次

  但它【一次都不出现】的概率是多少？
    P(count = 0) = (1 − 1e-4)^10000 ≈ e^(−1) = ★ 36.79%

  ⟹ ★★ 期望出现 1 次的事件，有超过三分之一的概率【彻底消失】。
     一旦在合成语料里是 0 次，下一代模型就几乎学不到它
     （只剩子词兜底和平滑的残留），它的概率会掉向 0。

  一代一代算下去，这个表达的"存活率"：
    第 1 代后：63.21%
    第 2 代后：63.21%² = 39.96%
    第 3 代后：25.25%
    第 4 代后：15.96%
    第 5 代后：★★ 10.09%
    第 10 代后：★★★ 1.02%

  ⟹ ★★★ 只要递归五轮，p = 1e-4 这一档的表达就只剩 10% 还活着。
     而"语言的长尾"恰恰主要由这一档和更稀有的事件组成。

  ★ 这一条机制的名字：有限样本带来的【统计近似误差】。
    它和模型大小、训练质量【完全无关】—— 哪怕用一个完美的模型，
    只要你是在"采样"而不是"复制分布"，这个损失就一定发生。

★★ 机制二：解码策略会【硬性截断】尾部（比机制一更狠，而且是确定性的）

  真实部署里没人用纯采样，大家用 top-p（nucleus sampling，核采样）：
    保留概率从高到低累积到 p = 0.9 的那一小撮 token，
    ★ 其余的概率【直接置 0】。

  代进数字：词表 15 万。某一步 top-0.9 的"核"里可能只有 40 个 token。
    ⟹ 剩下的 149,960 个 token 在这一步的概率是【精确的 0】，
       ★ 不是"很小"，是【不可能被采到】。

  ⟹ ★★ 这不是采样噪声，是【分布支撑集被硬性缩小】。
     合成语料的支撑集严格小于真实分布的支撑集，而且每一代都再小一圈。
  ★ top-k 同理，而且更硬。

★ 机制三：温度 < 1 会把尾部【相对压低】

  采样温度 T 的作用是把概率取 1/T 次幂再归一化。
  取两个 token：常见的 p = 0.1，稀有的 p = 0.001，原始比例 1 : 100。

    T = 1.0：比例仍是 1 : 100
    T = 0.7：比例变成 (0.001/0.1)^(1/0.7) = 0.01^1.4286 = 1.39e-3
             ⟹ ★ 1 : 720

  ⟹ 稀有 token 相对变稀有了 720/100 = ★ 7.2 倍。
    而大多数生产环境的默认温度就在 0.6 ~ 0.8。

但要把话说全（⚠️ 这是我的判断）：

★ 坍塌实验的设定是【完全替换 + 递归】：用生成数据【取代】真实数据，一代接一代。
  而实践中没有人这么干 —— 上面三条机制也正好告诉你该怎么挡：

  ① 合成数据总是和真实数据【混着用】（WRAP 就是这样）
     ★ 为什么管用：真实数据每一代都把尾部【重新注入】回来，
       机制一的"存活率连乘"链条被打断了。
  ② 合成数据要经过和真实数据【一样的过滤和去重】
     ★ 为什么管用：去重直接打掉机制二/三造成的"高概率模式反复出现"。
  ③ ★ 生成器通常比被训模型【更强】（用大模型给小模型造数据）
     —— 这是【蒸馏】，不是"自己教自己"：教师的分布比学生的更宽，
        ★ 尾部是在【变宽】而不是变窄。
  ④ ★ 生成时刻意【把温度调高、把 top-p 放宽】，或者用多样化的提示词
     （Cosmopedia 的组合爆炸就是在做这件事）
     ★ 为什么管用：直接针对机制二和机制三。

⟹ ★ 正确的结论不是"合成数据有毒"，而是：
   【合成数据的比例和多样性必须被主动管理，不能放任】
★★ 而且注意一个容易被忽略的推论：机制二和三说明
   【你怎么"采"比你用什么模型"生成"更要紧】——
   同一个模型，贪心解码造出来的语料和高温多样采样造出来的语料，
   对下一代的伤害完全不是一个量级。

风险二：⚠️ 事实错误的规模化

模型改写时会【悄悄改错事实】：
   原文 "1969 年阿波罗 11 号登月"
   改写 "1968 年阿波罗 11 号登月"   ← ★ 流畅、自信、错误

★ 而且这个错误会被写成【教科书风格】—— 比原始网页的错误更有欺骗性，
  因为质量分类器（07 章）反而会给它【高分】。
  ⟹ ★★ 这是本章最阴险的一条：你的质量过滤器会【主动把这些错误捞上来】。

★ 缓解：
  ① 改写时明确要求"不得引入原文没有的信息"
  ② 对数字、日期、专有名词做【原文回查】
     ★ 这一步可以完全自动化：正则抽出所有数字/日期/实体，
       逐个在原文里检索，对不上的整篇丢掉
  ③ ★ 在可验证领域用验证器（见 12.7）

风险三：许可与合规

⚠️ 用某个闭源模型的输出去训练竞品模型，
   通常【违反其服务条款】。
★ 这是很多技术报告在合成数据部分语焉不详的真实原因之一。
★★ 对照 12.2 的四条路线，这条风险的分布很不均匀：
   ① 蒸馏      → ⚠️⚠️ 风险最高（直接用别人模型的输出）
   ② 自我博弈  → ✅ 用自己的模型，基本没有这个问题
   ③ 规则生成  → ✅ 没有这个问题
   ④ 回译      → ⚠️ 取决于反向模型是谁的；原料是真实网页，还有版权维度（08 章）

12.7 ★★ 可验证领域：合成数据真正的甜区

★★★ 一个判断合成数据靠不靠谱的简单标准：
     【你能不能自动验证生成结果是对的？】

  能验证：
    数学   → 用符号计算/求解器验证；或生成时【先有答案再倒推出题】
             ★ 注意"先有答案再出题"就是 12.2 的【④ 回译】路线
    代码   → ★ 直接跑单元测试，跑不过就丢
    形式化证明 → 用证明检查器（Lean/Coq）验证
    结构化任务 → 用规则检查（JSON 格式、SQL 能否执行）

  不能验证：
    历史、常识、观点、开放式写作
    → ⚠️ 只能靠"改写型"（事实锚定在原文上），不要用"生成型"

⟹ ★★ 这解释了一个现象：
   为什么各家的合成数据几乎都集中在【数学、代码、推理】上？
   不是因为这些领域更重要，而是因为★【只有这些领域造得出可信的新数据】。

★★★ 而且回到 12.1 第③层：验证器是【唯一】能让合成数据突破
     "信息量不增"这个天花板的东西 ——
     它把外部世界的真值（编译器会不会报错、方程解不解得开）
     注入到了训练数据里。没有验证器的合成，本质上还是在重排已有信息。

# ★ 可验证合成的标准循环（以代码为例）
def synth_code_batch(seed_tasks, generator, n=8):
    kept = []
    for task in seed_tasks:
        for _ in range(n):                       # ★ 一题多次采样
            sol  = generator(f"实现：{task.desc}")
            test = generator(f"为下面的函数写单元测试：\n{sol}")
            if run_tests(sol, test) and run_tests(task.ref_impl, test):
                #  ↑ 生成解通过        ↑ ★ 参考实现也要通过，
                #                        否则说明是测试本身写错了
                kept.append({"task": task.desc, "solution": sol, "test": test})
                break
    return kept          # ★ 通过验证的才留下 —— 这一步提供了外部信号

★ 这段代码里 n=8（一题采 8 次）不是随手写的，它对应 12.2 表里
  【② 自我博弈】那一行："模型自己多次采样 + 验证器筛"。
  ⚠️ 代价要算清楚：生成 8 份解 + 8 份测试 = 16 次推理，
     如果通过率是 25%，那么【每拿到 1 条可用数据要付约 16 次推理的成本】。
  ★ 所以可验证合成是【用推理算力换训练数据】——
    11.3 那笔"推理比训练贵"的账在这里反过来用了一次。

12.8 挂回真实系统

工作 范式 技术路线（12.2） 做法 规模 / 效果
phi-1（2023） 生成型 ★ ① 蒸馏 ✅ GPT-3.5 造教科书+习题 ✅ 1.3 B / HumanEval 50.6%
WRAP（2024） ✅ 改写型 — ✅ 四种风格改写 C4 ✅ 预训练提速约 3×（= 算力降到约 1/3）

Nemotron-CC（2024） ✅ 改写型 — ★★ 低质档改写而非丢弃 ✅ 唯一 token ×4
指令回译 / Humpback（2023） 介于两者 ★ ④ 回译 ✅ 从真实网页反推指令 + 自我筛选 ✅ Alpaca 榜上超过所有不用蒸馏数据的同底座模型
数学 / 代码的拒绝采样 生成型 ★ ② 自我博弈 一题多采 + 验证器筛 见 12.7（⚠️ 各家做法不公开）
五家国产模型 — — ⚠️ 多数只承认"使用了合成数据"，不给细节 见 16 章

⚠️ 一个诚实的说明：合成数据是当前技术报告里披露最少的部分——比配比还少。
原因既有竞争因素，也有 12.6 风险三提到的合规因素。
★ 所以本章的公开材料主要来自学术论文，而不是前沿模型的技术报告，读的时候要意识到这个偏差。

✅ 不过有两处一手印证值得记住（详见 16 章）：某家报告写了"网页过滤时要剔除批量自动生成的内容，以防模型坍塌"——★ 这正是 12.6 风险一在生产环节的落地；另一家写了用专门微调的模型改写低清洁度数据以保住长尾知识，并严格保持原有语义——★ 前半句是 12.5 的分诊思想，后半句正是 12.6 风险二的防范措施。

12.9 小结

① ★★ "自己教自己"的疑问，答案分三层：
   ① 多数合成是【改写】真实数据 → 信息没变，形式变好
   ② 训练瓶颈常常是【呈现形式】而非信息量
   ③ ★ 在【可验证】领域，验证器提供了真正的外部新信号
      ★★ 验证器是唯一能突破"信息量不增"天花板的东西

② 两大范式：
   改写型（WRAP / Nemotron-CC）—— ★ 事实锚在原文，幻觉低，上限受原语料限
   生成型（phi / Cosmopedia）—— 质量上限高，⚠️ 幻觉高、★★ 多样性极难保证

③ ★★ 四条技术路线，"需要什么 / 产出什么 / 风险是什么"各不相同（12.2 那张表）：
   ① 蒸馏      需要更强的教师 → ★ 上限被教师锁死，⚠️⚠️ 许可风险最高，
                               去污染变成"查一个看不见的训练集"
   ② 自我博弈  ★★ 必须有验证器或奖励模型，否则只会放大自身偏差；
                 ⚠️ 多样性坍缩、reward hacking
   ③ 规则生成  需要程序/求解器 → 答案天然正确，⚠️ 但分布窄、会学到模板捷径
   ④ 回译      需要大量真实的【输出端】文本 →
                ★★★ 风险结构和其他三条相反：输出端是人写的，完全可信
                ✅ 大模型版本 = 指令回译（2308.06259，ICLR 2024）

④ ✅ WRAP（2401.16380）：四种风格改写 C4（easy/medium/hard/QA）
   → ★ 预训练提速约 3 倍，零样本问答 +约 10%
   ⚠️ "提速 3 倍" = 算力降到约 1/3 = 时间减少约 67%，
      ★ 不要写成"时间减少 3 倍"或"加速 300%"
   ★ 关键：合成数据是【混着真实数据用】，不是替代

⑤ ✅ phi-1（2306.11644）：1.3 B / 8×A100 / 4 天 / 6 B 筛选代码 + 1 B 合成
   → HumanEval 50.6%
   ⚠️ 但一直被质疑合成数据里混入了评测题近亲（08 章的间接污染）
   ★ 读法：证明了路走得通，具体分数打折看

⑥ ★★★ Cosmopedia 的教训：
   【合成数据的多样性上限，由【种子】的多样性决定，不由生成模型决定】
   → 解法是提示词的组合爆炸（主题 × 受众 × 体裁 × 风格）
   ★ 设计目标是让提示词数量和文章数量同量级，使几乎没有两篇共享提示词

⑦ ★★★ Nemotron-CC 的思想转变（本章最重要）：
   过滤不是【二分类】（好留坏删），是【分诊】：
   高质量直接用 / 中质量用 / ★ 低质量【改写后再用】/ 垃圾才删
   ✅ 结果：唯一 token 量 ×4
   ★★ 这个 4 倍值多少钱要用 11.5 的衰减表算：
      要训 4U 时它只省 7%，要训 16U 时它省 ★ 41%
      ⟹ 真正的价值是【把工作点从衰减曲线的陡降段拉回平坦段】

⑧ ⚠️ 三个风险：
   · ★★ 模型坍塌 ✅（Shumailov 等，Nature 631:755–759, 2024）
     ★★ 三条机制，第一条可以算：
        机制一（有限采样）：p=1e-4 的表达，在 1 万样本里【一次不出现】的
           概率 = e⁻¹ = 36.8% ⟹ 递归 5 代后只剩 ★ 10.1% 存活，10 代后 1.0%
           ★ 这一条与模型质量无关，只要是"采样"就一定发生
        机制二（top-p 截断）：15 万词表里核外的约 14.996 万个 token
           概率是【精确的 0】⟹ ★ 支撑集被硬性缩小，不是噪声
        机制三（温度 < 1）：T=0.7 时 1:100 的概率比变成 1:720，
           ★ 稀有 token 相对再稀有 7.2 倍
     ★ 但那是"完全替换 + 递归"的设定；四条挡法各自对应上面的机制：
        混真实数据（断开机制一的连乘）/ 过滤去重（打掉机制二三的高频模式）/
        用更强的教师做蒸馏（尾部变宽而非变窄）/ ★ 生成时提高温度与多样性
     ★★ 推论：【怎么"采"比用什么模型"生成"更要紧】
   · 事实错误规模化（★ 改写后质量分类器反而给高分 ⟹ 过滤器会主动把错误捞上来；
     ★ 缓解里最可自动化的一条是对数字/日期/实体做原文回查）
   · 合规（用闭源模型输出训竞品通常违反条款 —— 报告语焉不详的真实原因之一）
     ★ 四条路线里只有蒸馏和回译有这个风险，自我博弈和规则生成没有

⑨ ★★ 判断合成数据靠不靠谱的唯一简单标准：【能不能自动验证】
   数学/代码/形式化证明 → 能验证 → 甜区
   历史/常识/观点      → 不能 → 只用改写型，别用生成型
   ⟹ 这就是为什么各家合成数据几乎都集中在数学和代码上
   ⚠️ 代价要算：一题采 8 次 + 8 次写测试 = 16 次推理，
      通过率 25% ⟹ ★ 每条可用数据约 16 次推理的成本
      —— 可验证合成本质是【用推理算力换训练数据】
