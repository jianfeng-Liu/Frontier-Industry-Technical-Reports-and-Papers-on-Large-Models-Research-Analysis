# 16 · ⭐⭐ 五家报告的数据章节：把前 15 章挂回真实模型

> **前 15 章讲的都是"方法"。这一章把[隔壁目录](../业界模型技术报告/)那五份技术报告里的【数据章节】逐一读一遍，看看这些方法在真实的前沿模型里到底怎么用。**

## 16.1 先看一张总表

| | ✅ 语料规模 | ✅ 阶段划分 | ✅ 最终上下文 |
|---|---|---|---|
| **DeepSeek-V4** | 语料 **> 32 T**；Flash 训 **32 T**、Pro 训 **33 T** | 预训练 + mid-training（引入 agentic 数据） | **1 M** |
| **Kimi K3** | ⚠️ 报告未给总 token 数 | 预训练 + cooldown（冷却期） | **1 M** |
| **GLM-5.2** | 起步语料 **27 T**；base 合计 **28.5 T** | 预训练 + **mid-training** 三段扩上下文 | **200 K** |
| **MiniMax-M3** | 恒定阶段 **19.9 T** + 衰减阶段 **9.3 T** ≈ **29.2 T** | constant phase + decay phase | **192 K** |
| **openPangu-2.0** | **34 T** | ★ 三阶段课程：General **25 T** / Reasoning **8 T** / Annealing **1.4 T** | **512 K** |

```
★★ 第一个观察：语料规模全部落在【28 T ~ 34 T】这个很窄的带里。
   ⟹ 这一代前沿模型的"数据预算"事实上已经收敛了。
   ⚠️ 我的判断：这个数字更可能是【高质量数据的供给上限】，
      而不是"算出来的最优值" —— 正是 [11 章](11-喂多少-ScalingLaw.md)说的【数据墙】。

★★ 第二个观察：★ 五家【全部】都是多阶段的。
   名字各不相同（mid-training / cooldown / decay / annealing / 三阶段课程），
   ⟹ 但做的是同一件事：[10.6 节](10-数据配比.md)讲的【配比随时间变化 + 学习率衰减】。
   ★ 单一固定配比在这一代已经【完全消失】了。
```

## 16.2 DeepSeek-V4：本教程最好的一处一手佐证

✅ 出处：[`DeepSeek-V4-正文提取.txt`](../业界模型技术报告/papers/) §4.1 Data Construction。

```
✅ 报告明确写到的几件事：

① 网页数据：★ 过滤掉【批量自动生成的内容和模板化内容】，
   ✅ 报告给的理由是：【缓解模型坍塌（model collapse）的风险】
   ⟹ ★★ 这正是 [12.6 节](12-合成数据.md)风险一说的那件事，
        而且是【一家前沿模型在自己的报告里点名承认在防它】。
   ⚠️ 注意这里防的不是"自己用合成数据"，而是
      "★ 网上已经充斥着别的模型生成的内容，你抓下来就吃进去了"。

② 多语言：扩大语料以更好地覆盖【不同文化的长尾知识】
   ⟹ 呼应 [05 章](05-语言识别与启发式过滤.md)的语言识别与低资源语言问题

③ ★ 长文档：特别强调长文档的数据策划，
   优先【科学论文、技术报告】等"具有独特学术价值"的材料
   ⟹ 呼应 [02 章](02-数据源与文本抽取.md)：真正长而连贯的文本是稀缺资源

④ Tokenizer：★ 在 V3 的 tokenizer 上只加了几个用于上下文构造的特殊 token，
   ✅【词表大小保持 128 K 不变】
   ✅ 沿用 V3 的 token-splitting 和 FIM（Fill-in-Middle，中间填充）策略
   ⟹ 呼应 [09.7 节](09-Tokenizer与词表.md)：预留 token 的价值就在这里体现
```

### ★★★ 最值得单独拎出来的两句

> ✅ **报告原文（我按原意转述）：**
> ```
> ① 「我们把来自不同来源的文档【打包】进合适的序列，
>     以【最小化样本截断】。」
>
> ② 「与 DeepSeek-V3 不同，我们在预训练中采用了
>     ★★★【样本级注意力掩码（sample-level attention masking）】。」
> ```

**为什么这两句极其重要？**

```
★★★ 这就是 [13 章](13-打包与文档掩码.md)整章讲的东西，出现在一份前沿模型报告里：

  第①句 = 13.3 的【装箱打包】，目的正是 13.1 说的"避免截断"
  第②句 = 13.5 的【块对角文档掩码】

★★ 而"与 V3 不同"这四个字信息量最大：
   ⟹ 它说明【上一代还没做】。
   ⟹ 也就是说，13 章那个"默认关闭、很多人不知道自己踩了"的坑，
      ★ 是真实存在的，连 DeepSeek-V3 这一级别的模型都是后来才补上的。

⟹ 如果你只从本章记住一件事，就记这一条：
   ★★★【文档掩码不是学术上的洁癖，是一家前沿实验室在新一代里专门补上的东西。】
```

## 16.3 Kimi K3：改写型合成数据的完整配方

✅ 出处：[`Kimi-K3-正文提取.txt`](../业界模型技术报告/papers/) §3.1 Pre-Training Data。

```
✅ 四个文本域 + 一个视觉语料：
   Web Text（网页）/ Code（代码）/ Mathematics（数学）/ Knowledge（知识）
   + 大规模视觉语料（图文交错文档、OCR、感知、视频、视觉编码数据）

✅ 每个域的过滤方式（★ 这句话几乎是本教程 05-07 章的目录）：
   「规则启发式 + 基于分类器的质量打分 + 去重」三者组合
   ⟹ 05 章 + 07 章 + 06 章，一句话全齐了

✅ ★★ 而各域的【采样率】怎么定：
   「由【在小模型上做的消融实验】确定」
   ⟹ 呼应 [10 章](10-数据配比.md)：这就是"代理模型搜配比"的思路，
      ⚠️ 但报告说的是【消融】而非 DoReMi/RegMix 那样的自动搜索方法。
```

### ✅ 改写配方：本教程 12 章的一手对照

> ✅ 报告写道：沿用 Kimi K2 的 **rephrasing recipe**，对**知识和数学语料**进行改写，用到三件事：

```
① ★ 风格与视角多样化的提示（style and perspective-diverse prompting）
   ⟹ ★★ 这正是 [12.4 节](12-合成数据.md) Cosmopedia 的结论：
        【多样性由提示词的多样性来保证】

② 分块自回归生成（chunk-wise autoregressive generation）
   ⚠️ 我的理解：长文档不能一次性改写完，要分块，
      而且后一块的生成要能看到前一块 —— 否则改写出来的文章会前后不连贯

③ ★★★ 对照源文档做【保真度验证（fidelity verification）】
   ⟹ 这正是 [12.6 节](12-合成数据.md)风险二"事实错误规模化"的解药：
      改写完要回头和原文比对，确认没有改错事实。
   ★ 这是我在五份报告里看到的、对合成数据【质量控制】写得最具体的一句。
```

```
★★ 把 12 章和这里对上：
   WRAP（学术界）  = 四种风格改写 C4
   Kimi K3（工业界）= 风格/视角多样化改写知识与数学语料 + ★ 保真度验证
   ⟹ 工业界比论文多做的那一步，就是【验证】。
```

### ✅ 长上下文数据的专门管线

> ✅ 报告直白地说明了一件很多人不知道的事：**自然来源的长文档和视频里有大量低质内容**——近重复、二进制块、截断文件、无效的机器生成日志。

```
✅ 它的处理办法（★ 几乎是 06 + 07 章的组合拳）：
   · 精确去重 + 模糊去重
   · ★ 视频用【逐帧感知哈希（perceptual hashing）】去重
   · 启发式 + 分类器质量过滤
   · 结构验证

✅ ★★ 然后是一句非常重要的话：
   「因为真正长而连贯的文档和视频，相对于短文本来说是【稀缺】的，
     所以我们把它们【上采样】，使长上下文分布不会在 cooldown 阶段
     被短序列淹没。」

⟹ ★★★ 三个呼应一次到位：
   · [10.1 节](10-数据配比.md)的【上采样】—— 小而稀缺的数据要重复用
   · [10.6 节](10-数据配比.md)的【退火/cooldown 阶段】
   · [13 章](13-打包与文档掩码.md)：如果不刻意保护，
     短文档会在打包时把长文档"稀释"掉
```

## 16.4 GLM-5.2：质量分类器用得最细的一家

✅ 出处：[`GLM-5-正文提取.txt`](../业界模型技术报告/papers/) §2.2 Pre-training Data。

```
✅【网页】两个分类器：
  ① ★ 一个基于【句子嵌入】的 DCLM 分类器
     ⟹ 直接点名 [07 章](07-质量过滤.md)讲的 DCLM（2406.11794）！
     ✅ 用途：找出"标准分类器之外的"高质量数据
  ② ★★ 一个【世界知识分类器】（World Knowledge classifier）
     用维基百科条目 + 大模型标注的数据来优化，
     ✅ 用途：从【中低质量数据里】把有价值的长尾知识【蒸馏出来】

★★★ 第②点是本节最重要的一句：
   注意它不是"把中低质量数据删掉"，而是"★ 从里面把有用的挖出来"。
   ⟹ 这和 [12.5 节](12-合成数据.md) Nemotron-CC 的【分诊】思想是同一个方向：
      ★ 业界正在从"筛掉"转向"抢救"。
```

```
✅【代码】：
  · 刷新各大代码托管平台的快照 + 收集更多"含代码的网页"
    → ✅ ★【模糊去重后的唯一 token 数增加了 28%】
      ⟹ ★★ 注意它汇报的指标是【去重后的唯一 token】，
         而不是"数据量增加了多少" —— 这正是 [11 章](11-喂多少-ScalingLaw.md)
         强调的那个真正稀缺的资源。这个措辞本身就说明了行业共识的变化。
  · 修复 Software Heritage 代码文件的【元数据对齐】问题
    ⟹ 呼应 [08.5 节](08-去污染与隐私许可.md)：元数据是一等公民
  · 采用更准确的【编程语言分类】管线
    ⟹ 呼应 [05 章](05-语言识别与启发式过滤.md)：语言识别在代码上同样是个难题
  · ★ 为 Scala / Swift / Lua 等【低资源编程语言】单独训分类器
    ⟹ 呼应 [07.6 节](07-质量过滤.md)的"分布窄化"风险：
       统一的分类器会系统性地歧视小语种（包括小众编程语言）

✅【数学与科学】：
  · 精化网页内容抽取和 PDF 解析（⟹ [02 章](02-数据源与文本抽取.md)）
  · ★ 用大模型给候选文档打分，只保留最有教育价值的
    ⟹ 就是 07.4 讲的 FineWeb-Edu 路线
  · ★★ 长文档用【分块打分再聚合（chunk-and-aggregate）】的算法
    ⚠️ 我的理解：一篇长文档整体喂给打分模型，
       前面的内容会被后面稀释，分数不准；分块打分再聚合更可靠。
       ★ 这是一个很实用、但论文里很少写的工程细节。
```

### ✅ ★★★ 一句和 12 章形成正面张力的话

> ✅ **GLM-5 报告在数学与科学数据部分明确写道：**
> **「过滤管线被用来【严格避免】使用合成的、AI 生成的、或模板化的数据。」**

```
★★★ 把这句话和 [12 章](12-合成数据.md)放在一起看，非常有意思：

  · openPangu：★ 语料来源里【明确包含】合成数据
  · Kimi K3：  ★ 明确对知识与数学语料【做改写】
  · GLM-5.2：  ★★ 在数学与科学数据上【严格避免】合成/AI 生成内容
  · DeepSeek-V4：★ 过滤掉批量自动生成内容以防模型坍塌

⟹ ⚠️ 这【不是矛盾】，而是两件不同的事，新手极易混淆：
   ① 主动生成、经过验证的合成数据（自己造、自己验）→ 大家都在用
   ② 从网上抓到的、来源不明的 AI 生成内容 → ★ 大家都在过滤
   
★★ 记住这个区分：【自产的合成数据是资产，野生的 AI 内容是污染。】
   区别在于你【知不知道它是怎么来的、有没有验证过】。
```

✅ **Mid-training**：分三段逐级扩上下文——**32 K（1 T token）→ 128 K（500 B）→ 200 K（50 B）**。
★ 注意那个**急剧递减的 token 预算**：扩上下文的边际成本很高，所以越到后面给的量越少。

## 16.5 MiniMax-M3：把"打包"写进了报告

✅ 出处：[`MiniMax-M2-正文提取.txt`](../业界模型技术报告/papers/) §3 Pre-Training Data。

```
✅ 语料来源：网页文档、学术文献、书籍、编程代码、结构化问答内容

✅ 质量评估：★【模型打的奖励分 + 辅助分类器】组合，多维度评估
   ⟹ 07 章的第三代方法（模型打分），而且是【多个维度】而非单一分数

✅ 采样策略：「上调高质量内容的权重，★【同时保留足够的类别多样性】」
   ⟹ ★★ 这一句把 [07.6 节](07-质量过滤.md)的"分布窄化"风险
      写成了显式的设计约束 —— 说明这个风险在工业界是被明确意识到的

✅ 配比：★ 代码、数学、STEM 内容相对其【自然分布】被显著【上采样】
   ⟹ [10.3 节](10-数据配比.md)人工配比的第③条："代码给 5~20%"，一手印证
```

### ✅ ★★★ 长上下文数据的三个来源

> ✅ 报告写道，衰减阶段（decay phase，9.3 T token）的长上下文训练样本主要来自三处：

```
① 高质量【代码拼接】（code concatenation）
   ★ 把同一个仓库里相关的代码文件拼成一条长序列

② 天然长篇的 PDF 文档

③ ★★★【主题相关的文档打包】（thematically related document packing）
```

```
★★★ 第③点值得单独讲，因为它是对 [13 章](13-打包与文档掩码.md)的一个【重要延伸】：

  13 章讲的打包，是【随机地】把文档塞进箱子里 —— 
     所以才需要文档掩码来防止"串味"。

  ★ 而 MiniMax 的做法是【故意挑主题相关的文档打在一起】：
     ⟹ 此时"跨文档注意力"不再是污染，★ 反而是【有价值的长程依赖信号】
     ⟹ 这是在【用打包制造长上下文训练数据】，
        而不是仅仅把打包当成一个省 padding 的技巧

⚠️ 我的判断：这条路解决的是 [11 章](11-喂多少-ScalingLaw.md)那个真问题 —— 
   ★【真正天然的长文档太少了，不够训 192 K 的上下文窗口】。
   于是"把相关短文档拼成假的长文档"成了必需的手段。
   ⚠️ 但报告没有说明此时是否关闭文档掩码，这一点无法从原文确认。
```

✅ 上下文扩展路径：**8 K → 32 K → 192 K**；恒定阶段 **19.9 T**、衰减阶段 **9.3 T**。

## 16.6 openPangu-2.0：披露最完整、也最贴合本教程的一家

✅ 出处：[`openPangu-2.0-正文提取.txt`](../业界模型技术报告/papers/) §3.1 Data Construction。

```
✅ 语料 34 T token，★ 三阶段课程（这是五家里写得最清楚的一份）：

┌─ Phase 1 · General（25 T）────────────────────────────────┐
│    建立通用知识与广泛语言能力的基础                        │
│    ✅ 序列长度 4 K                                         │
├─ Phase 2 · Reasoning（8 T）───────────────────────────────┤
│    ✅ 提高高质量 STEM 与代码数据的比例                     │
│    ✅ 序列长度 8 K                                         │
├─ Phase 3 · Annealing（1.4 T）────────────────────────────┤
│    ✅ 精炼模型行为与 agentic 能力                          │
│    ✅★ 【刻意把长文档和复杂轨迹数据留到这最后一个阶段】    │
│    ✅ 上下文逐级扩到 32 K(800 B) → 128 K(400 B) → 512 K(200 B) │
└──────────────────────────────────────────────────────────┘

★★ "刻意把最好的数据留到最后"—— 这正是 [10.6 节](10-数据配比.md)
   我给出的那个直觉解释（学习率低时数据影响权重更大），
   ✅ 在这里得到了一家厂商的明确表述。
```

✅ **语料来源**：网页、书籍、PDF、多语言文本、代码仓库、STEM 文献、**行业领域数据**、agentic 任务、**以及合成数据**。
★ 重点扩容的是 **ARC**（**A**gent、**R**easoning、**C**ode）数据，做法是"**彻底重做基于规则的启发式 + 整合基于模型的评估管线**"——即 [05 章](05-语言识别与启发式过滤.md) + [07 章](07-质量过滤.md) 的组合。

### ✅ ★★★ 两处对本教程的直接印证

> ✅ **印证一（对应 [12.5 节](12-合成数据.md) Nemotron-CC 的"分诊"）——报告原文大意：**
> 「为了**保留那些清洁度或流畅度分数较低的样本里有价值的长尾知识**，我们训练了几个专门的微调模型，让它们**改写并规范化文本格式，同时严格保持原有的语义**。」

```
★★★ 这就是 12.5 节说的那个思想转变，出现在一家厂商的报告里：
     【低质量数据不是删掉，而是【改写后再用】】
   ✅ 而且它把动机说得比 Nemotron-CC 还直白：★ 为了保住【长尾知识】。
   ★ 注意"严格保持原有语义"这一句 —— 正是 12.6 风险二的防范措施。
```

> ✅ **印证二（对应 [07.5 节](07-质量过滤.md) Essential-Web 的非破坏性标注）——报告原文大意：**
