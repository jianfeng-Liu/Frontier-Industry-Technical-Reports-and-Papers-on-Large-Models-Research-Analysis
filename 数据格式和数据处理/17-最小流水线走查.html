17 · ⭐⭐ 最小流水线走查：把 16 章串成一条能跑的线

前面每一章都是一个零件。这一章把它们装成一条【完整的、能跑的、小规模的】流水线。

★ 规模刻意选小（几十 GB 原始数据 → 一次几小时的小模型训练），
目的是让你亲手把每一步跑通一遍——很多东西只有跑过才会真正懂。

17.1 目录结构：先把摊子铺开

mypipeline/
├── 00_raw/            ← 原始抓取物（WARC / 已有 jsonl）
├── 01_extracted/      ← 正文抽取后         (02 章)
├── 02_lid/            ← 语言识别打标后     (05 章)
├── 03_heuristic/      ← 启发式过滤后       (05 章)
├── 04_dedup/          ← 去重后             (06 章)
├── 05_quality/        ← 质量打分与过滤后   (07 章)
├── 06_clean/          ← 去污染 + PII 掩码后 (08 章)
├── tokenizer/         ← 训练好的 tokenizer  (09 章)
├── 07_bin/            ← .bin / .idx        (04 章)
├── stats/             ← ★★ 每一步的统计报告
└── run.sh

★★★ stats/ 是这一章我最想让你记住的一个目录。
```
每一步都必须往 stats/ 里写三个数：
进来多少篇 / 出去多少篇 / 各条规则各砍掉多少篇

★ 05、07、08 三章都强调过同一件事：可观测性是最容易被省掉、
也最不该省的东西。这里把它变成【目录结构上的强制约定】。
```

统一的中间格式（03 章：JSON Lines + zstd 压缩）：

{"id":"...","text":"...","meta":{"url":"...","crawl_date":"2024-03-01",
 "lang":"zh","lang_score":0.94,"quality":3.7,"filters_passed":["lid","gopher"]}}

★ 注意 meta 里那几个字段就是 08.5 节的数据溯源要求。

17.2 每一步的代码骨架

Step 1 · 正文抽取（02 章）

# 01_extract.py
import trafilatura, json, zstandard as zstd
from warcio.archiveiterator import ArchiveIterator

def extract_warc(warc_path, out):
    for rec in ArchiveIterator(open(warc_path, "rb")):
        if rec.rec_type != "response": continue
        html = rec.content_stream().read()
        text = trafilatura.extract(html, include_comments=False,
                                   include_tables=True)
        if not text: continue                    # ★ 抽不出正文的直接丢
        out.write(json.dumps({
            "id": rec.rec_headers.get_header("WARC-Record-ID"),
            "text": text,
            "meta": {"url": rec.rec_headers.get_header("WARC-Target-URI"),
                     "crawl_date": rec.rec_headers.get_header("WARC-Date")[:10]},
        }, ensure_ascii=False) + "\n")

★ 这一步的典型留存率：★ 20% ~ 40%（大量记录是图片、CSS、重定向、空页）
⚠️ 一定要打印：★ 抽取失败率。突然升高通常意味着上游 WARC 有问题。

Step 2 · 语言识别（05 章）

# 02_lid.py
import fasttext
model = fasttext.load_model("lid.176.bin")

def tag_lang(doc):
    labels, probs = model.predict(doc["text"].replace("\n", " "), k=1)
    doc["meta"]["lang"] = labels[0].replace("__label__", "")
    doc["meta"]["lang_score"] = float(probs[0])
    return doc

KEEP = {"zh", "en"}
THRESH = 0.65          # ✅ FineWeb 用的就是 0.65
def keep(doc):
    return doc["meta"]["lang"] in KEEP and doc["meta"]["lang_score"] >= THRESH

★ 这里就该动手做第一个实验：把 THRESH 分别设成 0.5 / 0.65 / 0.8，
各抽 30 篇被砍掉的文档人工看一遍。你会立刻明白阈值到底在砍什么。

Step 3 · 启发式过滤（05 章）

# 03_heuristic.py —— ★ 关键在于【逐条统计】，不是逐条过滤
from collections import Counter
REJECT = Counter()

RULES = {
    "too_short":      lambda d: len(d["text"]) < 200,
    "too_long":       lambda d: len(d["text"]) > 500_000,
    "low_alpha":      lambda d: alpha_ratio(d["text"]) < 0.6,
    "bullet_heavy":   lambda d: bullet_line_ratio(d["text"]) > 0.9,
    "no_terminal":    lambda d: terminal_punct_ratio(d["text"]) < 0.15,
    "dup_line":       lambda d: dup_line_ratio(d["text"]) > 0.3,
    "bad_words":      lambda d: has_blocklist_word(d["text"]),
}

def heuristic(doc):
    for name, fn in RULES.items():
        if fn(doc):
            REJECT[name] += 1      # ★★ 每条规则单独计数 —— 写进 stats/
            return None
    doc["meta"].setdefault("filters_passed", []).append("gopher")
    return doc

★★ 跑完必须看 REJECT 这张表。你要问自己两个问题：
   ① 有没有哪条规则砍掉了【异常多】的文档？→ 多半是规则写错了
   ② 有没有哪条规则【几乎没砍】？→ 那它就是白跑的开销，可以去掉
⚠️ 中文特有：★ alpha_ratio 和 no_terminal 这两条规则如果直接套英文实现，
   会在中文语料上大规模误杀 —— 中文的"句号"是"。"不是"."。

Step 4 · 去重（06 章）

# 精确去重（整篇）—— 一行 shell 就够，先做这一步最划算
zstdcat 03_heuristic/*.jsonl.zst \
  | python3 -c "
import sys,json,hashlib
seen=set()
for line in sys.stdin:
    d=json.loads(line)
    h=hashlib.blake2b(normalize(d['text']).encode(),digest_size=16).digest()
    if h in seen: continue
    seen.add(h); print(line,end='')
" | zstd -o 04_dedup/exact.jsonl.zst

# 模糊去重：MinHash + LSH（06.5 节的完整实现在那一章）
K, B, R = 128, 16, 8          # ★ 阈值 ≈ (1/B)^(1/R) ≈ 0.75
sigs = {doc_id: minhash(doc["text"]) for ...}
buckets = defaultdict(list)
for doc_id, sig in sigs.items():
    for b in range(B):
        band = tuple(sig[b*R:(b+1)*R])
        buckets[(b, band)].append(doc_id)     # ★ 同桶 = 候选对
# → 并查集聚类 → 每个簇保留一篇

★ 典型留存率：★ 精确去重砍 10~30%，模糊去重再砍 15~40%
   （具体取决于你抓了几个 CC 快照 —— 06.2 节说过跨快照重复是最大的一块）

⚠️ 一定要检查【最大的那几个簇】：
   如果某个簇有几十万篇，★ 多半是 06.5 节说的【巨型连通块】问题，
   而不是真的有几十万篇重复文档。

Step 5 · 质量过滤（07 章）

# 05_quality.py —— fastText 分类器（07.4 节）
import fasttext
clf = fasttext.load_model("quality.ftz")

def score(doc):
    lab, prob = clf.predict(doc["text"][:2000].replace("\n", " "), k=1)
    p = float(prob[0]) if lab[0] == "__label__high" else 1 - float(prob[0])
    doc["meta"]["quality"] = round(p * 5, 2)     # 映射到 0~5 分
    return doc

★★★ 这一步【不要直接删】。按 07.5 / 16.6 讲的【非破坏性】做法：
   ① 先给【全部】文档打分并写进 meta
   ② 分数只用来【采样时加权】，不用来删除
   ⟹ 好处：想换阈值时不用重跑整条流水线，改一下采样脚本就行

★ 阈值怎么定：不要拍一个绝对分数，而是【按分位数】定。
   例：先算全量分数的直方图，取前 30% 分位对应的分数当阈值。

Step 8 · 转成训练格式（04 章）

python tools/preprocess_data.py \
    --input 06_clean/zh.jsonl \
    --output-prefix 07_bin/zh \
    --tokenizer-type HuggingFaceTokenizer \
    --tokenizer-model tokenizer/tokenizer.json \
    --append-eod  --workers 32
# → 产出 07_bin/zh_text_document.bin 和 .idx

★★ 跑完立刻做三件自检（04 章的坑）：
   ① 检查 .bin 的 dtype：vocab 65536 → ⚠️ 已经【超过】65535 了，
      会用 int32 而不是 uint16！★ 想省一半存储要用 65535 或更小
   ② 随机抽 5 条样本【解码回文本】打印出来，肉眼确认不是乱码
   ③ 统计总 token 数 —— ★ 这是 10 章反推配比权重的输入

17.3 ★★ 一张"每步该看什么"的检查表

★ 这张表是本章的核心产出。 流水线跑完不看这些数字，等于没跑。

步骤 ★ 必看的数字 ⚠️ 出问题的征兆
01 抽取 抽取成功率 突然下降 → 上游格式变了
02 语言识别 各语言占比、分数分布 ★ 短文本大量落在低分区 → 阈值在按长度筛而不是按语言筛
03 启发式 ★★ 每条规则各砍多少 某条砍 >30% → 规则写错；某条砍 <0.1% → 白跑
04 去重 留存率、★ 最大簇大小 最大簇几十万篇 → 巨型连通块
05 质量 分数直方图 ★ 双峰或全部挤在一端 → 分类器没训好
06 去污染 命中评测集的篇数、PII 各类命中数 ★ PII 命中数异常高 → 正则边界写漏了
07 tokenizer ★ 各语料的压缩率 中文压缩率 <2 → 训练语料里中文太少
08 转格式 ★ 总 token 数、dtype dtype 是 int32 → 存储翻倍，确认是否有意为之
09 训练 ★ 每个数据集重复几遍 ★ >4 遍 → 11 章说的收益衰减区 
★★★ 最后那一行是整条流水线的【收口】：
   把 10.7 节那段"算每个数据集重复几遍"的代码跑一遍，
   如果有数据集重复超过 4 遍 —— 
   ⟹ 要么降它的权重，要么去找更多这类数据，
     ★ 而不是假装没看见。

17.4 ★ 一个真实的量级感受

⚠️ 下面这组数字是我按前面各章的典型留存率推算的示意，不是某次真实运行的记录，用来建立量级直觉：

100 TB 原始 WARC
   │  正文抽取（留存 ~30%）
   ▼
 30 TB 纯文本
   │  语言识别 + 只留中英（留存 ~40%）
   ▼
 12 TB
   │  启发式过滤（留存 ~60%）
   ▼
  7 TB
   │  精确 + 模糊去重（留存 ~45%）      ★ 这一步砍得最狠
   ▼
  3 TB
   │  质量过滤（留存 ~30%）             ★ 这一步争议最大
   ▼
0.9 TB  ≈ 2000 亿 token

★★★ 总留存率：100 TB → 0.9 TB，约 【0.9%】
⟹ 这就是 [01 章](01-鸟瞰全景.md)开头那句话的来历：
   【数据工作的主体不是"收集"，是"扔掉"。】

⚠️ 但要立刻补一句 [07 章](07-质量过滤.md)和 [16 章](16-五家报告的数据章节.md)的话：
   ★ 最后那个 30% 的质量过滤，正是 2024 年之后业界在【主动放松】的一步 ——
     因为扔掉的不只是垃圾，还有【唯一 token】和【长尾知识】。
   ★ Nemotron-CC / openPangu 的做法是把这部分【改写后留下】而不是删掉。

17.5 ★★ 从小规模到大规模，会变的三件事

① ★★ 单机 → 分布式
   上面的脚本都是"读一个文件、写一个文件"。
   到 TB 级就必须换成 Spark / Ray / Slurm 数组作业。
   ★ 好消息：每一步的【逻辑】完全不变，变的只是调度。
   ⚠️ 唯一真正变形的是【去重】—— 因为它是全局操作，
      不能简单地分片并行。见 06 章的分桶策略。

② ★ 一次跑通 → 反复重跑
   大规模下你一定会中途发现某条规则有 bug。
   ⟹ 所以 [08.5 节](08-去污染与隐私许可.md)的 pipeline_version 和
     filters_passed 字段是【必需品】，不是锦上添花。

③ ★★★ 从"删除"转向"标注"
   小规模下每步都删是最简单的。
   ★ 大规模下你会痛苦地发现：每换一次阈值就要重跑几天。
   ⟹ 于是必然演化成 [07.5 节](07-质量过滤.md) / [16.6 节](16-五家报告的数据章节.md)
      的做法：★【一次标注、多次采样】。
   ⟹ ★ 如果你打算认真做，建议【一开始就用标注式】，别等到痛了再改。

17.6 小结

① 目录即流程：00_raw → 01_extracted → 02_lid → 03_heuristic →
   04_dedup → 05_quality → 06_clean → 07_bin
   ★★★ 外加一个 stats/：每步必写"进来多少/出去多少/各规则砍多少"

② 统一中间格式：JSON Lines + zstd，meta 里带全 08.5 的溯源字段
   （url / crawl_date / lang / quality / pipeline_version / filters_passed）

③ ★★ 关键实操点逐条对应：
   抽取看★失败率 / LID 阈值 ✅0.65 且要人工看被砍的 /
   启发式★逐条规则计数 / 去重先做精确再做模糊、★查最大簇 /
   ★★★质量分只【打标不删】、阈值按分位数定 /
   去污染 13-gram + PII 掩码 / ★tokenizer 采样按最终配比

④ ⚠️ 两个容易忽略的边界：
   ★ vocab 65536 已经【超过】65535 → .bin 变 int32、存储翻倍
   ★ --reset-position-ids / --reset-attention-mask 默认关，要手动开

⑤ ★★ "每步该看什么"检查表是本章核心产出；
   ★★★ 最后一行【每个数据集重复几遍】是整条流水线的收口，
      >4 遍就要动手调，而不是假装没看见

⑥ ★ 量级直觉（⚠️ 示意推算，非实测）：
   100 TB → 30 → 12 → 7 → 3 → 0.9 TB，★ 总留存率约 0.9%
   ⟹ 数据工作的主体是【扔掉】
   ⚠️ 但最后那步质量过滤正是业界在【主动放松】的一步

⑦ ★★ 放大到生产会变三件事：单机→分布式（★ 只有去重真正变形）/
   一次跑通→反复重跑（★ 所以要有版本字段）/
   ★★★【从删除转向标注】—— 建议一开始就用标注式
