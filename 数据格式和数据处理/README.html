大模型数据处理与数据格式入门（小白向）

📖 随时可以查缩写：这个领域全是 WARC、MinHash、LSH、DCLM、THD、cu_seqlens 这类缩写。附录速查表的 §H 缩写总表 把本教程出现的每一个缩写都列了英文全称 + 中文 + 一句话解释 + 在哪一章讲。看到不认识的词，先去那里查一下。

从零看懂：15 万亿个 token 是怎么从互联网上被"洗"出来、"配"起来、"打包"进 GPU 的

⚠️ 先说清楚三件事

① 这份教程不预设你懂任何数据处理知识。

Common Crawl、WARC、去重、MinHash、困惑度过滤、数据配比、tokenizer、packing、.bin/.idx——这些词你一个都不用提前知道。教程从"网上抓下来的一个网页到底长什么样"开始讲起，每个名词第一次出现时都会先解释再使用。

② 对你的唯一要求：会写代码，看得懂循环、数组、字典、哈希表、以及"读一个文件、按行处理"这件事。只要这些就够了。 涉及数学的地方（scaling law 那两章）会先用类比讲一遍，公式看不懂可以跳过。

③ 怎么读：

第一遍  →  只看每章的【类比】【ASCII 图】【加粗句】，公式和代码全部跳过
           目标：把整条流水线的形状看清楚

第二遍  →  回头看伪代码，照 17 章那条最小流水线自己搭一遍
           目标：搞清每个环节到底在动什么

第三遍  →  读每章末尾的「挂回真实系统」，然后去看 papers/ 里的原始论文

第一遍看不懂公式是完全正常的，不影响你读懂后面的章节。 每章的结构都是固定的：

直觉类比  →  ASCII 图  →  具体的数据长什么样  →  Python 伪代码  →  挂回真实系统

🧭 这个领域的一句话地图

在开始之前，先建立一个总的方位感。大模型的"数据"这件事，其实是三个完全独立的问题，初学时最容易把它们搅在一起：

问题一：内容问题  ——  「喂什么」
        从 100 TB 的网页垃圾里，挑出 15 TB 值得学的东西
        → 抽取、过滤、去重、质量分、配比、合成
        → 第二、三部分（05 ~ 12 章）

问题二：格式问题  ——  「怎么存」
        挑出来的文本，用什么文件格式落盘，才能让几千张卡同时读得动
        → JSONL / Parquet / .bin+.idx / WebDataset
        → 第一部分（03、04 章）

问题三：喂法问题  ——  「怎么送进去」
        一堆长短不一的文档，怎么拼成定长的 [B, L] 张量，还不能互相串味
        → tokenize、packing、文档掩码、shuffle、断点续训
        → 第四部分（13 ~ 15 章）

⚠️ 而 19 章会告诉你：这张地图正在被改写。当『一条数据』从【一篇文档】变成【一次交互轨迹 + 一个可运行的环境】时，上面三个问题的答案都要重写。

★ 这三个问题的负责人在真实团队里往往都不是同一批人，论文里也常常只讲其中一个。你读一篇数据论文时，第一件事就是判断它在解决哪一个——这能省掉大量困惑。

📐 全教程通用的记号约定

文档  document   一篇独立的文本（一个网页、一本书的一章、一个代码文件）
                 ★ 数据领域最基本的单位。全教程说"一条数据"都是指一篇文档
token            文本被切分后的最小单位，一个整数 id。中文约 1 字 ≈ 0.6~1 token
                                                   英文约 1 词 ≈ 1.3 token
语料 corpus      一堆文档的集合（FineWeb、The Pile 都是语料）
分片 shard       语料被切成的一个个文件块，典型 100 MB ~ 2 GB 一片

L   = 序列长度（一条训练样本有多少 token），如 4096、8192
B   = batch size
V   = 词表大小（vocabulary size，五家都是 15 万左右）
N_d = 训练集总 token 数        ← Chinchilla 里的 D
N_p = 模型参数量               ← Chinchilla 里的 N

单位换算： 1 T token = 10¹² 个 token
          15 T token 的原始文本 ≈ 60 TB 左右的 UTF-8 纯文本 ⚠️ 粗估
