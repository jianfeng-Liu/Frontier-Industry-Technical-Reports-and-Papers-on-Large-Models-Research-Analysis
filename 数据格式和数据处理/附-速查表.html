A. 记号与单位

文档 document   一篇独立文本（一个网页 / 一本书的一章 / 一个代码文件）
                ★ 数据领域最基本的单位
token           文本切分后的最小单位，一个整数 id
语料 corpus     一堆文档的集合（The Pile、FineWeb 都是语料）
分片 shard      语料被切成的文件块，典型 100 MB ~ 2 GB 一片

L   = 序列长度（一条训练样本多少 token），如 4096 / 8192
B   = batch size
V   = 词表大小（vocabulary size）
N_d = 训练集总 token 数            ← Chinchilla 里的 D
N_p = 模型参数量                   ← Chinchilla 里的 N

1 T token = 10¹² 个 token
⚠️ 粗估：15 T token 的原始文本 ≈ 60 TB 左右的 UTF-8 纯文本
中文 1 字 ≈ 0.6~1 token ／ 英文 1 词 ≈ 1.3 token

B. 核心公式

① Jaccard 相似度（去重的定义式，[06 章](06-去重.md)）
      J(A,B) = |A ∩ B| / |A ∪ B|
   ★ MinHash 的性质：P[minhash(A) == minhash(B)] = J(A,B)
      ⟹ 这就是为什么能用哈希来估相似度

② LSH 分带的命中概率（[06 章](06-去重.md)）
      P(候选) = 1 − (1 − s^R)^B          s = 真实 Jaccard
      B 个带 × 每带 R 行 = K 个 minhash
   ★ 阈值近似：s* ≈ (1/B)^(1/R)
      例：K=128, B=16, R=8 → s* ≈ 0.75

③ 困惑度（[07 章](07-质量过滤.md)）
      PPL = exp( −(1/N) Σ log p(x_i | x_<i) )
   ★ 越低 = 模型越"熟悉"这段文本。⚠️ 但低 ≠ 好（见 07.3）

④ Chinchilla 最优（[11 章](11-喂多少-ScalingLaw.md)）
      给定算力 C ≈ 6 · N_p · N_d 时，N_p 与 N_d 应【同比例】增长
   ★ 经验落点：N_d / N_p ≈ 20（"20 token per parameter"）
   ⚠️ 这是【训练最优】，不是【推理最优】—— 实际都远超 20

⑤ 数据受限下的重复（[11 章](11-喂多少-ScalingLaw.md)）
   ✅ 2305.16264 的三个数字（均为报告原文）：
      · ★ 重复到约 4 个 epoch，loss 与"同等数量的全新数据"差别可忽略
        （✅ 实例：8.7 B 模型重复 4 遍，验证 loss 只高 0.5%）
      · ★ 一直到约 16 个 epoch 仍有有意义的收益，★ 之后收益衰减极快
      · ★ 到 40 个 epoch，重复已经【毫无价值】

⑥ 偏好损失（[15 章](15-后训练数据格式.md)）
      L = −log σ( r(chosen) − r(rejected) )      σ = sigmoid

⑦ 打包利用率（[13 章](13-打包与文档掩码.md)）
      利用率 = 总 token 数 / (箱子数 × L)
   ★ 打印这个数字，它是打包好坏的唯一指标

D. ★ 三条因果链（全教程骨架）

【链一】数据墙 → 从"筛掉"转向"抢救"
  高质量网页快用完（11 章）
    → 唯一 token 变得昂贵（GLM 汇报口径变成"去重后唯一 token"）
    → 扔掉低质数据的代价变高
    → ★ Nemotron-CC：低质数据【改写后留下】（12.5）
    → ★★ Essential-Web / openPangu：★【根本不删，只打标签】（07.5 / 16.6）
    → 标签驱动【课程采样】⟹ ★ 标注是因，课程是果

【链二】文档长度分布重尾 → 打包 → 污染 → 掩码 → 变长算子
  文档长短不一（13.1）
    → 补齐浪费巨大（✅ 极端 89%）→ 必须【拼接/打包】
    → ★★★ 一条样本混入多篇不相干文档 → 跨文档污染
    → ✅ 加 <eod> 分隔符【不能】解决 → 必须用【块对角掩码 + 位置 id 重置】
    → ★ 但稠密算子下掩码不省算力 → 必须走 THD + cu_seqlens
    → ✅ 一手佐证：DeepSeek-V4「与 V3 不同，采用样本级注意力掩码」

【链三】确定性 → 断点续训
  训练会崩（14 章）
    → 续训必须喂【完全相同】的数据顺序
    → ⟹ 数据顺序必须是【seed 的纯函数】，不能依赖 listdir/dict 顺序
    → ⟹ checkpoint 里数据侧只需存一个数：★ consumed_train_samples
    → ⚠️ 但 train-iters / GBS / 配比 / seed 任一改变，等价性就破了

【Megatron 数据预处理】（[04 章](04-训练格式-Megatron索引.md)）

      --input data.jsonl --output-prefix out/zh \

  → 产出 out/zh_text_document.bin 和 .idx

【训练时的数据相关参数】
  --data-path 0.5 A 0.4 B 0.1 C   ★ 配比权重 + 数据集前缀（10 章）
  --split 998,1,1                 train/valid/test 划分
  --seq-length 4096               = L
  --reset-position-ids            ★★ 每篇文档位置 id 从 0 重数（13 章，默认关）
  --reset-attention-mask          ★★ 块对角文档掩码（13 章，★ 默认关）
  --eod-mask-loss                 对 eod 位置不算 loss
  --seed 1234                     ★ 数据顺序的唯一来源（14 章）
  --make-vocab-size-divisible-by 128   ★ 词表补齐（9.4）

【三个索引】（[04 章](04-训练格式-Megatron索引.md)）
  document_index (Do_idx)  文档顺序（每个 epoch 打乱一次）
  sample_index   (Sa_idx)  每条样本从哪篇文档的哪个偏移开始
  shuffle_index  (Sh_idx)  ★ 样本的最终乱序表
  ⟹ ★★★ O(1) 查表：真实样本编号 = Sh_idx[ step × GBS + j ]

【断点续训只需存一个数】（[14 章](14-采样-shuffle-与断点续训.md)）
  consumed_train_samples
  ★ 外加两个断言：data_seed 没变、数据配置 hash 没变
