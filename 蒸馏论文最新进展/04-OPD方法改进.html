本章关键词

OPD（On-Policy Distillation，在策略蒸馏）—— 学生自己采样，老师在学生写的每个 token 上给信号。基础见 后训练/08。

on-policy（在策略）/ off-policy（离策略） —— 区别在于训练用的数据是不是当前这个策略自己采出来的。⚠️ 4.4 节会说明：这句话里藏着两个独立的东西，拆开之后 Lightning OPD 的「矛盾」就消失了。

offline（离线） —— ⚠️ 和 off-policy 不是同一个词。offline 指「不在训练循环里实时跑某个组件」，off-policy 指「数据不是当前策略产的」。Lightning OPD 做的是 offline，它的 on-policy 性质只丢了一部分。4.4 节详述。

logits（对数几率） —— 模型在输出层给每个词的原始分数。白盒蒸馏要的就是它。

逆 KL（reverse KL） —— KL(学生 ‖ 老师)。OPD 的标准目标函数。

advantage（优势） —— 策略梯度里乘在 ∇log π 前面的那个标量，决定这一步「往上推还是往下压、推多少」。

baseline / centering（基线 / 中心化） —— 从奖励里减去一个与动作无关的期望值。不改变梯度的期望，但能降方差。

teacher-base（老师的基座模型） —— 老师在做推理微调之前的那个版本。OPD² 的全部机制都压在它身上。

ExOPD / G-OPD（Generalized OPD with reward extrapolation，带奖励外推的广义在策略蒸馏）—— 一个被本篇三篇论文共同拿来当基线的方法：把「老师 − 老师基座」的差放大 λ>1 倍，让学生越过老师。⚠️ 注意它和 OPD² 都用 teacher-base，但用法不同，见 4.2。

rubric（评分细则） —— 把「好不好」拆成一张可以逐条打勾的检查表。基础见 后训练/06。

Rubricator / Verifier（细则生成器 / 验证器） —— ROPD 的两个角色：前者造细则，后者按细则给学生答卷打勾。

AUC（Area Under the ROC Curve，ROC 曲线下面积）—— 衡量一个分数能多好地区分两类样本。0.5 = 完全随机，1.0 = 完美，低于 0.5 = 反着预测。4.5 节有一个 0.35。

χ²散度（chi-square divergence，卡方散度） —— 另一种分布距离，χ²(p‖q) = E_q[(p/q)²] − 1。Lightning OPD 的误差界用它。

trust region（信赖域） —— 限制每一步更新不要走太远的机制。

GRPO（Group Relative Policy Optimization，组相对策略优化）—— 见 后训练/05。

pass@1 / pass@k —— 采 1 次 / 采 k 次里至少对一次的比例。

4.2 OPD²：「Delta」到底是哪个差

⚠️ 先避开最容易搞反的一处

「Delta」不是「老师减学生」。 标准 OPD 的奖励本来就是老师减学生，那不叫 delta。OPD² 的 Delta 是：

标准 OPD 的奖励     R_t^OPD = log π*(y_t) − log π_θ(y_t)
├── log π*(y_t)        【老师】给这个 token 的 log 概率
└── log π_θ(y_t)       【学生】给这个 token 的 log 概率

OPD² 的 delta 信号   R_t^Δ   = log π*(y_t) − log π*_base(y_t)
├── log π*(y_t)        【老师】给这个 token 的 log 概率
└── log π*_base(y_t)   【老师自己】做推理微调【之前】那个基座给的 log 概率

✅ 论文 §2.2 式 (5)。学生根本不出现在 delta 信号里。

为什么要这么定义（✅ 论文 §1 + §2.2）：老师的能力 = 预训练学到的基础语言能力 + 推理微调加上去的推理能力。后训练阶段的学生只需要后面那一半——前面那一半它自己已经有了。log π* − log π*_base 恰好就是「推理微调这一步到底改了什么」的差分。

⚠️ 这个思路和 后训练/08 讲的 task vector（微调后权重 − base 权重）是同一个直觉，只是这里差分做在输出概率上而不是参数上。⚠️ 这个类比是我画的，论文没有这么说。

★★ 一个可以按计算器验算的小算例

场景：学生正在写一道题，写到一个属于错误推理的 token（比如把「加法」写成了「乘法」里的那个 ×）。三个模型对这个 token 给出的概率：

模型 对这个 token 的概率 自然对数
老师 π*（推理微调过） 0.02 ln 0.02 = −3.912
老师的基座 π*_base 0.10 ln 0.10 = −2.303
学生 π_θ 0.005 ln 0.005 = −5.298

两种奖励分别算出来：

标准 OPD：  R^OPD = −3.912 − (−5.298) = +1.386        ( = ln(0.02/0.005) = ln 4 )
            ⟹ 【正号】⟹ "把这个 token 的概率推上去"
            ⟹ ★ 但这是一个错误推理的 token！

delta：     R^Δ   = −3.912 − (−2.303) = −1.609        ( = ln(0.02/0.10) = ln 0.2 )
            ⟹ 【负号】⟹ "压下去"

★ 这就是 OPD² 的全部论点，而且它完全是算术性的：

标准 OPD 的奖励是【两个不同模型】的 log 概率差。
老师给 0.02 —— 老师已经认为这是个坏 token 了。
但学生给 0.005 —— 学生认为它【更坏】。
一减，正号。⟹ OPD 会把一个【师生都不喜欢】的 token 往上推，
             只因为学生比老师更不喜欢它。

delta 的奖励是【同一个模型的前后两个版本】的差。
它们从同一份权重出发，推理微调过的那个在推理相关的词上
【系统性地更敏感】⟹ 两者之间有稳定的"优劣关系"，
不会出现上面那种符号翻转。

✅ 论文 §2.2「Token-level signals」原话："OPD keeps showing positive signals in the incorrect reasoning part, which is due to the magnitude difference... simply, student signals are stronger than those of the teacher." 论文用三道故意写错的简单题（数学/科学/代码）做了 token 级可视化来展示这一点。

另外两个零件：centering 和符号门

⚠️ delta 信号单独用会跑飞，论文 §2.3 说得很清楚：R^Δ 里压根没有 π_θ，所以优化它会把学生推向「delta 最大的那个 token」的 one-hot 分布——没有收敛点。两个零件是来修这个的：

① centering（中心化，✅ 论文 §2.3 式 (6)(7)） —— 减掉在学生分布下的期望，变成真正的 advantage：

A_t^OPD = R_t^OPD − E_{ỹ~π_θ}[ log π*(ỹ) − log π_θ(ỹ) ]
A_t^Δ   = R_t^Δ   − E_{ỹ~π_θ}[ log π*(ỹ) − log π*_base(ỹ) ]

⚠️ 实现上这个期望在学生的 top-k（k=1024） 上算，不是全词表（✅ 论文 §2.3 + §3.1），为了省显存。

② 符号门（joint condition，✅ 论文 §2.3 式 (8)） —— 这一条最容易写反：

A_t^D2 = A_t^Δ        当  A_t^Δ · A_t^OPD > 0   （两个信号【同号】）
         0            其他情况                   （两个信号【异号】）

★ 正确的读法：OPD² 只在 delta 和标准 OPD 方向一致时才动，动的幅度由 delta 决定。两者打架的时候它不是听 delta 的，是什么都不做。

⟹ ⚠️ 所以回到上面那个算例：delta 说「压下去」、OPD 说「推上去」，两者异号，OPD² 的实际动作是零，不是把它压下去。它买到的好处是「不做那件错事」，而不是「做对那件事」。⚠️ 这个区别很细但必须说准，论文 §2.3 的原话是 "restricts updates to sign-consistent common descent directions"。

符号门同时解决了收敛点问题：当学生追平老师、π_θ = π* 时，A^OPD = 0，乘积不大于 0，门关掉，梯度归零（✅ 论文 §2.3）。

4.3 Uni-OPD：它「统一」了什么，以及这个词值多少钱

先按论文的说法摆开

✅ 论文 §1 自己给的「两个视角」：

学生视角：学生有没有充分探索到【有信息量的状态】
          ⟹ 两个数据平衡策略

老师视角：老师在学生的 rollout 上给的 token 级监督【可不可靠】
          ⟹ 结果奖励引导的 margin 校准

② 老师侧：order consistency 和 margin 校准

★ 这一半是 Uni-OPD 真正有东西的地方。

先定义轨迹级蒸馏回报（✅ 论文 §3.4 式 (5)），就是把 token 级奖励按长度取平均：

G_OPD(q, τ) = (1/|τ|) · Σ_t  log[ π_T(o_t | q, o_<t) / π_θ(o_t | q, o_<t) ]

然后提出一个本该成立但经常不成立的性质（✅ 论文 §3.4 式 (8)），叫序一致性（order consistency）：

对同一道题 q，设 S⁺ = 答对的轨迹集合，S⁻ = 答错的轨迹集合，

   期望：  G_OPD(τ⁺) ≥ G_OPD(τ⁻)    对所有 τ⁺ ∈ S⁺、τ⁻ ∈ S⁻
   读法：  答对的轨迹，蒸馏回报【应该】比答错的高

✅ 论文给了一个具体的反例（§3.4 Fig. 5）：一道三角形内切圆的几何题，标准答案 108°。

轨迹 最终答案 蒸馏回报 G_OPD
轨迹 A ⚠️ 30°（错） −0.11（高）
轨迹 B ✅ 108°（对） −0.19（低）

⟹ 序反了：答错的那条拿了更高的蒸馏回报。如果直接用，OPD 会去强化那条错的。

✅ 论文 §3.1 把这种失效归成三类：(a) OOD 退化（学生走到老师稀疏/分布外的区域，log π_T 变噪声）、(b) 高估错轨迹（局部 token 模式恰好落在老师的高置信区）、(c) 低估对轨迹（正确但风格新颖，偏离老师的主导模式）。

校准怎么做（✅ 论文 §3.4 式 (9)–(12)）：

先定义【最对抗的那一对】之间的间隔：
   m(q) = min_{τ∈S⁺} G_OPD(q,τ)  −  max_{τ∈S⁻} G_OPD(q,τ)
   ├── 被减数：S⁺ 里【最差】的那条对轨迹
   └── 减数：  S⁻ 里【最好】的那条错轨迹

   m(q) ≥ 0  ⟺  所有对轨迹都排在所有错轨迹前面
   要求更严一点：m(q) ≥ δ，δ > 0 是对抗估计噪声的安全边际

两种修法：
├── margin mask（掩码）：m(q) < δ 的整组【丢掉】，只用可靠的组训练
└── margin shift（平移）：对 m(q) < δ 的组，令 λ(q) = δ − m(q)，
                         把 λ(q) 【只加到答对的轨迹上】
                         ⟹ 保持 S⁺ 内部的相对次序不变
                         ⟹ 校准后的间隔【恰好等于 δ】

⚠️ 为什么取「最差的对」减「最好的错」而不是取均值：✅ 论文 §3.4 原话——错配常常集中在少数极端样本上，一条过度自信的错轨迹或一条被严重低估的对轨迹就足以搅乱整组的监督信号，均值口径看不出来。

✅ 单独把这个机制加到 OPD 上的效果（论文 Table 6，Qwen3-4B，4 个数学榜均分）：

方法 AIME24 AIME25 HMMT25 Feb HMMT25 Nov 均分

+ margin mask 62.3 56.2 34.3 38.1 47.7

⚠️⚠️ 现在说「统一」这个词：它值多少钱

「统一」类论文最常见的毛病是把「换了个记号」说成「统一了」。 逐条查一下 Uni-OPD：

它说的「统一」 具体是什么 ⚠️ 这个统一推出了新东西吗
单教师 / 多教师的统一目标 ✅ 论文 §3.2 式 (4)：J = Σ_i w_i · KL(π_θ ‖ π_Ti)，令 M=1 就退回单教师 ⚠️ 没有。多个逆 KL 的加权和是多教师知识蒸馏的标准写法，式 (4) 本身不蕴含任何新结论，也没有从它推出任何定理
LLM 和 MLLM 的统一 同一套配方在纯文本和多模态上都跑了（Qwen3 / Qwen3-VL） ⚠️ 这是覆盖面，不是统一。换个数据集跑一遍不等于把两件事统一进一个框架

★ 序一致性 + margin 校准 把轨迹当作一个宏动作（macro-action），结果奖励就是一步的轨迹级回报，由此导出了一个蒸馏回报本该满足的序关系 ✅ 这个是真的新。它从一个前提推出了一个可证伪的预言（「实际中序会被违反」），论文用一个具体反例和消融验证了它，而且 margin shift 有一条可验证的保证（式 (12)：校准后间隔恰为 δ）

★ 我的判断：标题里的「Unifying」基本是一把伞，真正的贡献是伞下面那个 margin 校准。 值得读的是 §3.4，不是 §3.2 的式 (4)。

⚠️ 但要给它一个公道：序一致性这个发现被另一篇论文从完全不同的角度独立佐证了——ROPD 用 AUC 测出「老师的 log 概率对学生 rollout 的对错是反向预测」（见 4.5）。两篇互不引用、方法完全不同，得出了同一个结论。这种跨论文的互证，比任何单篇的消融都更可信。

4.4 ★★★ Lightning OPD：Offline 和 On-Policy 为什么不矛盾

矛盾在哪

标题里的两个词，字面上就是反的：

On-Policy  =  训练用的数据必须是【当前这个策略】采出来的
Offline    =  不在训练循环里实时跑，提前算好存盘

⟹ 提前算好的东西，怎么可能跟着一个【每一步都在变】的策略走？

★★★ 解法：「on-policy」这个词里其实压着两件事

这是本篇最值得记的一张图。把 OPD 的每一步拆开看：

OPD 每一步要用到两样东西：

 ① rollout 从谁的分布来      ←── "采样分布"
 ② advantage 里的 log 概率是谁的  ←── "逐 token 信号"

标准 OPD 的目标函数（✅ 论文 §3.1 式 (2)(3)）：

A_t(θ) = log π_T(a_t | s_t)  −  log π_θ(a_t | s_t)
├── log π_T(a_t|s_t)   【老师】的，★ 完全不含 θ
└── log π_θ(a_t|s_t)   【学生】的，★ 含 θ

J_on(θ) = E_{q~p,  x ~ π_θ }[ Σ_t A_t(θ) ]
└── rollout x 从【当前学生】π_θ 采样

Lightning OPD 的目标函数（✅ 论文 §3.1 式 (4)）：

J_off(θ) = E_{q~p,  x ~ π_ref }[ Σ_t A_t(θ) ]
└── rollout x 从【SFT 模型】π_ref 采样，★ 固定不变

★ 注意 A_t(θ) 【一模一样，没有改】

⟹ ★★★ 所以被搬到线下的到底是什么：

成分 依赖 θ 吗 Lightning OPD 怎么处理 这算近似吗
log π_T(a_t\|s_t)（老师的 log 概率） ✗ 完全不依赖 ✅ 一次性预先算好存盘 ✅ 不是近似，是精确的。老师的 log 概率是 (提示词, 回答) 这个固定二元组的函数，提前算和当场算数值完全一样
log π_θ(a_t\|s_t)（学生的 log 概率） ✅ 依赖 ✅ 每一步在线重算，一点没省 ——
rollout x 从哪个分布来 ✅ 依赖 ⚠️ 冻结成 π_ref 的采样 ⚠️ ★ 只有这一处是近似

★★ 一句话收口：Lightning OPD 的「offline」指的是「老师服务器下线」，不是「信号变陈旧」。 老师那一项提前算是严格无损的——它根本不含 θ。真正被牺牲掉的只有一样：rollout 不再跟着当前学生走。

⚠️ 这也解释了为什么不能把「学生的 log 概率」也提前算：那一项每一步都在变，提前算就真的错了。论文的算法 1 第 13 行明确写着学生项是在线计算的。

为什么「冻住 rollout」这一步损失可以接受：三条定理

✅ 论文 §3.3。四条假设（3.1 有界绝对优势、3.2 支撑集覆盖、3.3 有界得分函数、3.4 有界教师失配），然后：

定理 3.5（梯度差距界）

‖ ∇J_on(θ) − ∇J_off(θ) ‖₂  ≤  G · σ_A · √( χ²(π_θ ‖ π_ref) )

★ 在初始点 π_θ = π_ref 时，χ² = 0 ⟹ 两个梯度【精确相等】

⚠️ 读法：这不是「两者总是接近」，而是「学生离 SFT 模型漂移多远，误差界就有多大」。漂移小的时候界很紧，漂移大了这个界就没用了。

定理 3.6（共享不动点）：J_on(θ) = −KL(π_θ‖π_T) ≤ 0，最大值在 argmin KL 处。当老师可被学生的分布族表示时（π_T ∈ Π_Θ），最优点处 A_t(θ*) = 0，它同时是在线和离线两种更新的零点。

⚠️⚠️ 这条定理的前提是个强假设：π_T ∈ Π_Θ 意味着「学生有能力完全表示老师」——在强到弱蒸馏里这显然不成立（4B 学生表示不了 32B 老师）。✅ 论文自己接着说了：当 π_T ∉ Π_Θ 时，只能靠定理 3.5 保证「只要漂移小，离线更新就离在线更新不远」。⟹ ⚠️ 所以严格说，「同一个最优解」只在一个不现实的前提下成立；现实中的保证是「漂移小的时候两者接近」。

★★ 定理 3.7（梯度分解）—— 本篇最漂亮的一个结果

∇J_off(θ) = ∇J_on(θ) − Cov_{π_ref}[ w(x;θ),  f(x;θ) ]

其中 w(x;θ) = π_θ(x) / π_ref(x) 是重要性权重
     f(x;θ) = Σ_t A_t(θ) · ∇log π_θ(a_t|s_t) 是单条轨迹的梯度

⟹ ★ 离线梯度 = 在线梯度 − 一个协方差项。这个协方差项在初始点为零（因为 w ≡ 1），随漂移增大而增大，方向上拉着学生别跑远。

✅ 论文 §3.3 的原话：它「经验上起到信赖域的作用，不需要显式 KL 惩罚就能稳住训练」。

★★ 这才是这篇最值钱的一句话：让它变成 offline 的那个操作（忽略重要性权重 w），顺手免费送了一个信赖域。 省算力和稳训练这两件事在这里是同一件事的两面，不是各自独立的好处。⚠️ 论文说这是「经验上」观察到的（Fig. 3a），不是证明出来的——定理 3.7 只给了分解式，没有证明这个协方差项一定指向收缩方向。

★ 顺带发现的那条流水线铁律：teacher consistency

这篇还抓到一条和 offline 无关、但对所有 OPD 都成立的约束（✅ 论文 §1 + §3.3 定理 3.8/3.9）：

OPD 流水线里其实有【两个】老师：
├── SFT 阶段的老师：生成 SFT 训练轨迹的那个模型
└── OPD 阶段的老师：提供参考分布的那个模型

★ 这两个【必须是同一个模型】。

✅ 论文直接点名了一个违反的例子：Thinking Machines Lab 的做法是在 OpenThoughts-3（轨迹由 QwQ-32B 生成）上训 Qwen3-8B-Base，却用 Qwen3-32B 当 OPD 老师。

定理 3.8/3.9 的内容：设 Δ_t = log π_T^SFT − log π_T^OPD，其二阶矩上界为 σ_Δ。则失配会给离线和在线两种范式都带来一个偏置，上界 G·σ_Δ，而且 ★ 这个偏置和 χ² 无关——也就是说，它不会随着漂移变小而消失，它是一个持续的、不可约的偏置。

✅ 实验验证（论文 Table 4，AIME 2024 pass@1）：

OPD 老师 = Qwen3-32B OPD 老师 = QwQ-32B
标准 OPD，SFT 老师 = Qwen3-32B ✅ 68.5（对角） 64.8
标准 OPD，SFT 老师 = QwQ-32B 65.0 ✅ 66.5（对角）

✅ 论文给的机制解释（§4.5）：失配的 SFT 老师同时污染了 π_ref 的两个角色——它既是参考分布，又是固定 rollout 的来源；而标准 OPD 每一步都从当前学生重新采 rollout，能部分自救。⟹ ⟹ ★ teacher consistency 对 Lightning OPD 比对标准 OPD 更要命，这是它为「省掉老师服务器」付的真正代价。

⚠️ 噪声提醒：AIME 2024 只有 30 道题，单榜噪声门槛约 6~9 个百分点（见 4.7），上表里任何单格之间的差异都在噪声里。⟹ 但：连同 4B 规模的那一半表，一共 8 组行内比较，对角线 8 次全赢。⚠️ 如果把这 8 次当成独立的方向性检验，全中的概率是 (1/2)^8 = 1/256 ≈ 0.4%。⚠️ 这 8 次并不真的独立（共享模型、共享数据），所以真实的 p 值比 0.4% 大；但「方向的一致性」确实比「单格的幅度」有说服力得多。这是我做的分析，论文没有做任何显著性检验。

③ 两个估计为什么对不上

⑤ Uni-OPD 的账：基本免费，但它给了一个有用的量级

✅ 更有用的是它顺带给出的 OPD 主成本量级：

OPD 单步的主导成本来自两个阶段，都【随总 rollout token 数线性、随隐藏维度 d 立方】：
├── ① 从学生采 B·N 条 on-policy rollout
└── ② 老师对这些 rollout 做一次 prefill 拿 token 级 log 概率

✅ 该文设置下的典型值：B=64, N=16, 平均长度 ~8k

4.8 这一篇的六句话总结

① 四篇动的是 OPD 流水线的不同环节，几乎不重叠。 OPD² 换奖励的定义（老师 − 老师自己的基座，不是老师 − 学生）；Uni-OPD 换数据构成 + 轨迹级校准；Lightning OPD 换基础设施（老师下线）；ROPD 换信号来源（logits → 评分细则）。⚠️ 理论上可叠加，但没有一篇做过组合实验。

② Lightning OPD 的「Offline」和「on-policy」不矛盾，因为「on-policy」里压着两件独立的事。 被搬到线下的是 log π_T——它完全不含 θ，提前算是精确无损的；学生那一项 log π_θ 仍然每步在线重算。唯一的近似是 rollout 冻结在 π_ref。✅ 而定理 3.7 说明了一件漂亮的事：忽略重要性权重这个「偷懒」动作，等价于加了一个免费的信赖域，省算力和稳训练是同一件事的两面。

③ 算力账的真相是：老师的 FLOPs 不贵，贵的是耦合。 ✅ Lightning OPD 的分项显示老师把全部数据过一遍只要 2 / 4 GPU 小时（占总预算 10~13%），而标准 OPD 要 72 / 120 GPU 小时。⚠️ 我按 OPD² 的墙钟表反推，老师前向约占 OPD 单步时间的 四分之一（Qwen3 族）。⟹ 4 倍的差距不是算力省出来的，是「每步同步等老师」这个耦合解开来的。

④ 两篇独立论文从不同角度指向同一个结论：OPD 的信号和「答案对不对」的相关性靠不住。 ✅ Uni-OPD 给了具体反例（错轨迹蒸馏回报 −0.11，高于对轨迹的 −0.19）；✅ ROPD 在 3,120 条 rollout 上测出老师 logit 预测正确性的 AUC = 0.35（低于 0.5 ⟹ 反向预测）。⚠️ 两篇互不引用、方法完全不同。这是本篇里我最愿意当结论的一条，但限定在数学推理和它们各自测过的师生对上。

⑤ 按噪声门槛筛一遍，真正站得住的只有少数几条。 ✅ 站得住：ROPD 在白盒上比 LOPD 高 13.05 pp、比 ExOPD 高 10.62 pp；标准 OPD 把 Gemma4-E4B 的代码能力打掉 18.3 pp；Lightning OPD 用 1/4 的算力做到性能持平；ROPD 去掉多老师参考掉 17.94 pp。⚠️ 不能当结论的：Uni-OPD 在数学上的 +1.5 pp、OPD² 比 ExOPD 的 +3.2~3.8 pp、ROPD「学生超过老师」的 +1.67 pp、ROPD 跨架构的 +50% 相对提升（绝对只有 3.33 pp）。⚠️ 四篇全部是单次运行，没有种子方差。

⑥ 「统一」这个词要当心，但也别一棍子打死。 ⚠️ Uni-OPD 式 (4) 的多教师加权 KL 是标准写法，没有从它推出任何新结论；「统一 LLM 和 MLLM」是覆盖面不是统一。✅ 但伞下面那个序一致性 + margin 校准是真的新——它从「把轨迹当宏动作」这个前提导出了一个可证伪的预言，而且 margin shift 有可验证的保证（校准后间隔恰为 δ）。⟹ 读这篇读 §3.4，别读标题。
