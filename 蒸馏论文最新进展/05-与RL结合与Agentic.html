05 · 蒸馏与 RL 的结合，以及 Agentic 方向

这一章讲三篇论文，它们回答的是同一个问题的三个侧面：蒸馏（一个稠密但静态的信号）和强化学习（一个稀疏但自适应的信号），到底该怎么拼在一起？

三篇给的答案互不相同，而且有一处互相矛盾（5.6 节会把它单独列出来）。

可靠性声明（本章最重要的一句）：下面每个数字，凡是我从 PDF 正文 / 表格里直接读到的，标 ✅ 并给出处（写成「论文 §5.2」「论文 Table 3」的形式）；凡是我自己算出来或推出来的，标 ⚠️ 并写明推导过程，让你能拿计算器复核。我没读到的，我会说没读到。

三篇 PDF 我都做了全文文本提取并通读（14 页 / 43 页 / 41 页），包括附录。下面标 ✅ 的内容都有具体出处。

读法：没时间就只看 5.1 的对照表和 5.6 的分歧表。想搞懂机制，5.2.2（RLAD 的三种 advantage 情形）、5.3.3（文本反馈怎么变成梯度）、5.4.2（信用分配）是本章三个核心推演。

本章关键词（每个缩写第一次出现给中英文全称，不靠上下文猜）

RL（Reinforcement Learning，强化学习）—— 模型自己生成，环境给一个分数，再按分数调整。

KD（Knowledge Distillation，知识蒸馏）—— 大模型（老师）教小模型（学生）。

OPD（On-Policy Distillation，在策略蒸馏）—— 学生自己采样，老师在学生写出来的每个 token 上给方向。基础见 后训练/08，本章不重复。

MOPD（Multi-teacher On-Policy Distillation，多教师在策略蒸馏）—— 多个老师依次（或混合）教同一个学生。

KL 散度（Kullback-Leibler divergence，KL 散度）—— 量两个概率分布差多远。

逆 KL（reverse KL）—— 指 KL(学生 ‖ 老师)。三篇论文里的蒸馏项全都是逆 KL，方向别搞反。

RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励强化学习）—— 奖励来自能机器判对错的检查器（数学答案、单元测试），不是来自打分模型。见 后训练/05。

GRPO（Group Relative Policy Optimization，组相对策略优化）—— 对同一道题采 G 个答案，用组内平均分当基线算优势，省掉价值网络。三篇论文的共同基线。

PPO（Proximal Policy Optimization，近端策略优化）—— GRPO 的前身，核心是重要性比值 + 裁剪（clip）。

trust region（信赖域）—— 「这一步别迈太大」的约束。PPO/GRPO 用 clip 实现。

importance ratio（重要性比值）—— 新策略给这个 token 的概率 ÷ 旧策略给这个 token 的概率。用旧策略采的样去估新策略的梯度，就要乘这个比值做修正。

advantage（优势，记作 A）—— 「这条轨迹比平均水平好多少」。正数表示该加强，负数表示该抑制。

ORM（Outcome Reward Model，结果奖励模型）—— 只看最终答案对不对，整条轨迹一个分。

PRM（Process Reward Model，过程奖励模型）—— 对中间每一步打分。

credit assignment（信用分配）—— 本章第三篇的主题：一条 50 步的轨迹最后失败了，该怪哪一步？

multi-turn（多轮）/ long-horizon（长程）—— 多轮 = 模型和环境来回交互多次；长程 = 一个任务要很多步才能完成。两者常一起出现，但不是一回事。

rollout（采样轨迹）—— 模型自己跑一遍生成的完整序列。

mode seeking（寻峰）/ mode covering（覆盖）—— 逆 KL 让学生挤到老师分布的一个峰上（寻峰），正向 KL 让学生摊开覆盖老师所有峰。第三篇用这个解释 MOPD 的行为。

pass@k / avg@k（又写作 mean@k）—— 采 k 次，至少一次对 = pass@k；k 次的平均正确率 = avg@k（等价于 Pass@1 的无偏估计）。⚠️ 这两个指标在本章里会打架，5.6 节专讲。

PlanPhys 认为在长程任务里 RL 的信用分配根本就是坏的——与其修奖励，不如直接用老师的逐 token 分布当监督，接受「上限 = 老师」这个代价。

5.2 RLAD：「reinforcement-aware」到底 aware 了什么

5.2.1 先回答标题里那个问题

「蒸馏时知道 RL 的什么信息？」—— 答案是：知道这个 token 的 advantage（优势）是正是负。 ✅ 论文 §4 开篇把这件事说得很直接：KDRL 那类方法的 KL 正则项「is independent of the estimated advantage」（与估计出的优势无关），所以老师的影响是均匀施加的，包括在老师的行为和高奖励轨迹不一致的地方。

把这件事摊开来看：

传统做法（论文称为 KDRL，Xu et al. 2025）：
  总目标 = GRPO 的奖励项  −  beta * KL(学生 || 老师)
                              ^^^^^^^^^^^^^^^^^^^^^
                              这一项不看 advantage。
                              不管这个 token 是好是坏，
                              都往老师那边拽同样的力。

  两个后果（论文 §1 列的）：
  ├── 后果一：两项打架。beta 调大了压死奖励，调小了蒸馏没用。
  │            超参敏感，要仔细配平。
  └── 后果二：学生自己写的轨迹，可能落在老师的低概率区。
               老师在那里本来就没什么意见，KL 的监督信号很弱。

RLAD 的做法：
  不加这一项。把老师塞进【重要性比值的分母】里。
  advantage 乘在外面 ==> 老师的影响自动被 advantage 调制。

5.2.2 ★★★ TRRD 的机制：一个公式，三种情形

TRRD = Trust Region Ratio Distillation（信赖域比值蒸馏），是 RLAD 的核心组件。✅ 论文 §4.1 式 (3)：

r_TRRD(θ)  =  [ π_S(y_t) / π_S,old(y_t) ]^α  *  [ π_S(y_t) / π_T(y_t) ]^(1−α)

             \________ GRPO 原本的比值 ______/    \___ 对老师的比值 ___/

把它整理一下，就能看出它在干什么 ✅（论文 §4.1「TRRD as a Trust-Region Update」）：

令  r_mix(y_t)  =  π_S,old(y_t)^α  *  π_T(y_t)^(1−α)      <== 混合锚点

则  r_TRRD      =  π_S(y_t) / r_mix(y_t)

一句话：PPO 原本把信赖域的中心放在「上一版自己」，TRRD 把中心挪到「上一版自己和老师的几何加权平均」。 其余一切（clip、advantage、梯度）原封不动。

为什么这就叫 selective imitation（选择性模仿）？ ✅ 论文 §4.1 最后一段把梯度拆成三种情形。下面这张表是对那一段的逐条还原，你可以对着 clip 的上下界 [1−ε, 1+ε] 自己验算：

advantage 老师对这个 token 的态度 混合锚点 r_mix 比值 π_S/r_mix 碰到 clip 边界的时机 实际效果
A > 0（该加强） 老师也觉得这个 token 好（π_T 大） 变大 分母大了，比值涨得慢 → 更晚碰到 1+ε ✅ 允许学生把概率提得更多
A > 0（该加强） 老师觉得这个 token 不好（π_T 小） 变小 分母小了，比值涨得快 → 更早碰到 1+ε ✅ 即使 advantage 是正的，也只准小幅提升
A < 0（该压制） 老师觉得这个 token 好 变大 下界 1−ε 对应的 π_S 降幅变小 ✅ 不准学生猛砍老师喜欢的动作
A < 0（该压制） 老师觉得这个 token 不好 变小 下界对应的降幅变大 ✅ 奖励和老师都反对 → 准许大力压制
A ≈ 0 无所谓 无所谓 整项趋近于 0 ✅ 老师的影响消失（奖励信号没信息时不乱动）

★ 这五行就是「reinforcement-aware」的全部含义：老师不提供独立的梯度方向，它只改变「这一步最多能迈多大」。方向永远由 advantage 决定。

✅ 论文 §5.2.3 的弱老师消融正好验证了这个设计意图：用 Qwen3-0.6B 当 Qwen3-1.7B 的老师（老师比学生弱），RLAD 的逻辑推理 Avg 是 0.946，GRPO 是 0.950，几乎没掉；而 KDRL 掉到 0.910（论文 Table 5）。论文给的解释是：「the teacher shifts the trust-region center and clipping thresholds, but does not introduce an independent gradient term that can dominate the advantage direction」（老师挪动信赖域中心和裁剪阈值，但不引入一个能压过 advantage 方向的独立梯度项）。

5.2.3 ⚠️ 一处论文自己写反了：α 的方向

这是本章我最想让你记住的一个「别抄错」。

论文 §4.1 正文写着：「When α = 0, TRRD recovers standard GRPO; when α = 1, the trust region is fully teacher-anchored」（α=0 退化成标准 GRPO；α=1 完全锚定老师）。

⚠️ 这句话和它自己的公式 (3) 相反。 把 α=1 代入式 (3)：指数 1−α = 0，老师那一项整个变成 1，只剩 GRPO 的比值 —— 所以 α=1 才是 GRPO。

✅ 而论文附录 C 写的是正确的：「When α = 1, the anchor collapses to the student old policy and TRRD reduces to standard GRPO... as α→0, the anchor approaches the teacher」。附录 C 和公式一致。

来源 α = 1 是什么 α = 0 是什么 和公式 (3) 一致吗
论文 §4.1 正文 完全锚定老师 标准 GRPO ✗ 不一致
论文 公式 (3) 标准 GRPO 完全锚定老师 ——
论文 附录 C 标准 GRPO 趋近 DPO 式的模仿 ✅ 一致

⚠️ 结论（我的判断）：以公式 (3) 和附录 C 为准，§4.1 正文那一句是笔误。 实验里固定用 α = 0.5（✅ 论文 §5 和附录 A），所以这个笔误不影响实验结果，但影响你复现时的理解方向。

顺带一个实用细节 ✅ 论文附录 B：光靠 clip 还不够。训练早期老师和学生差太远，π_S/π_T 会炸出极端值，所以他们额外把 log(π_S/π_T) 硬截断到 [−1, 1]。⚠️ 这条在正文和伪代码里都没提，只在附录 B，复现时很容易漏。

5.3 Text Feedback：把「为什么错」救回来

5.3.1 论文开场那句话值得抄下来

✅ 论文摘要第一句：「The success of RL for LLM post-training stems from an unreasonably uninformative source: a single bit of information per rollout as binary reward or preference label.」（RL 后训练的成功，来自一个信息量少得不合理的来源：每条轨迹只有一个比特。）

这就是全篇的出发点。 把它和蒸馏并排放，就看出中间那块空白：

信息密度从低到高：

标量奖励 / 偏好标签
├── 每条轨迹 1 bit
├── 便宜、可规模化
└── 丢掉了【为什么错】和【怎么改】

文本反馈                        <== 这篇论文占的位置
├── 一段自然语言批评
├── 能【定位错在哪一步】、【指出违反了哪条约束】、【建议怎么改】
└── 人类本来就在大量产生它（用户吐槽、单测报错、编译器错误、judge 的批注）

完整示范（蒸馏 / 模仿学习）
├── 一整条正确解法，逐 token 都有监督
├── 信息最密
└── 贵、难规模化，而且【前沿模型没有更强的老师可以模仿】

5.3.2 ⚠️ 先纠一个很容易写反的方向

文本反馈不是用来「替代奖励函数」的。 这篇论文里标量奖励 R 从头到尾都在，文本反馈是叠加在它之上的第二条信道。

✅ 证据有三处：(1) 论文 §2 的交互协议里，每一轮都既有 r_h = R(x_0, y_h) 又有 c_h ~ M(·|x_h, y_h)；(2) RLTF-SD 的优势估计 A_i^(0) = R(x_0, y_1^i) − b^(0)（论文 式 (7)）里，R 就是那个标量奖励；(3) RLTF-FM 的总目标是 max J_MultiTurn(π) − λ * ℓ_FeeMol(π)（论文 式 (10)），第一项就是普通的多轮 RL 奖励目标。

⚠️ 所以正确的说法是：它没有换掉奖励函数，它是在稀疏奖励之外，额外开了一条稠密的监督通道。 如果你在笔记里写成「用文本反馈替代奖励」，就把论文说反了。

5.3.3 ★★★ 核心难点：文字不可直接优化，那怎么办

文字没法求导。 你不能对一段中文/英文批评做梯度下降。论文给了两条把它「转成可优化信号」的路，而且两条路转换方式完全不同。

另一个前提也要先说清 ✅（论文 §1 脚注 1 和 §2）：训练时有反馈，测试时没有。 论文明确选了更难的那一半——人类反馈类的、测试时拿不到的反馈（而不是单测报错那种测试时也能拿到的）。所以目标不是「学会在有反馈时改得好」，而是把反馈内化进第一轮。

✅ 论文 §1 和 §5.1 都验证了朴素做法行不通：直接做多轮 RL，第二轮确实变好了，但第一轮几乎没涨——因为目标函数里反馈完全可以被当成「多余的上下文」忽略掉，把反馈换成无意义 token 目标也仍然成立。

RLTF-SD（Self Distillation，自蒸馏）的转换路径：

  x0 (题目)
   |
   +--> 学生采样 y0 ----> 奖励 r0 ----> 用来当基线 b(0)
   |                 |
   |                 +--> judge 写批评 c0   <== 文字在这里
   |                                   |
   +--> x1 = concat(x0, y0, c0) -------+
         |
         +--> 学生【在 x1 条件下】采样 y1     <== 这就是「老师」
               |
               +--> 用 y1 去更新 π(· | x0)     <== 注意：更新的是【第一轮】的策略
                     权重 = R(x0, y1) − b(0)

  [!] 文字 c0 从来没有直接进入损失函数。
    它的作用是【改变了 y1 的分布】，而 y1 是可以求导的 token 序列。
    所以：文字 --> 更好的轨迹 --> 奖励加权的模仿。转了两道弯。

★ 这里的「老师」就是学生自己，只不过多看到了一条批评。 ✅ 论文 §3 原话：「we treat the policy acting under the post-feedback prompt as an implicit teacher, and distill it into the original one-shot policy」。⚠️ 这在结构上就是特权信息自蒸馏——老师 = 学生 + 一段学生在测试时看不到的上下文。和本目录 03 特权信息章 是同一个母题，只是特权信息的内容是「批评」而不是「标准答案」。

第二条路 RLTF-FM（Feedback Modeling，反馈建模）更直接：✅ 论文 §4 式 (9)，把批评 c_h 本身当成要预测的文本，做标准交叉熵：

ℓ_FeeMol(π)  =  E[ sum_h  −log p_π(c_h | x_h, y_h) ]

总目标  =  J_MultiTurn(π)  −  λ * ℓ_FeeMol(π)          λ = 0.2  (论文 Table 2)

✅ 论文特别注明：y_h 按常数处理（不回传梯度），所以这一项是纯监督学习，不会引入额外的信用分配。

⚠️ FM 这条路比 SD 更「文字原生」：它没有把文字转成轨迹再转成奖励，而是直接把文字当成语言建模目标。代价是：它训练的是「会不会批评」，而不是「会不会做对」——论文 §4.1 自己承认「its benefit is not obvious a priori」（它为什么有用并不是一眼能看出来的），所以专门写了一整节表示学习的理论去解释。

5.3.4 ★ 第一轮基线 vs 第二轮基线：一个能算出来的坑

✅ 论文 §3.1 指出了一个非常具体的失效模式，叫 gradient-signal collapse（梯度信号坍缩）。

如果你按 GRPO 的习惯，用第二轮的组内平均当基线，那么只要组内 N 个样本的奖励全一样（全对或全错），中心化之后优势全是 0，这一步完全没有梯度。✅ 论文给的概率是 p1^N + (1−p1)^N，其中 p1 是第二轮的成功率。

而反馈越有用，p1 就越接近 1，坍缩就越频繁。 拿论文 Table 2 披露的组大小 N = 8 ✅ 代入算一下（⚠️ 这张表是我按论文公式算的，论文没列）：

第二轮成功率 p1 p1^8 (1−p1)^8 这一步梯度为 0 的概率
0.5 0.0039 0.0039 0.78%
0.7 0.0576 0.0000656 5.8%
0.8 0.1678 0.0000026 16.8%
0.9 0.4305 ~0 ★ 43.0%
0.95 0.6634 ~0 ★ 66.3%
0.99 0.9227 ~0 ★ 92.3%

★ 读法：反馈质量越高，这个 bug 越严重。 老师（= 带反馈的自己）几乎每次都做对，恰恰是你最想学的时候，而这时 93% 的 batch 给不出任何梯度。这是一个反直觉但能用计算器验证的失效模式。

✅ 论文的修法：基线改用第一轮的组内平均 b(0) = (1/N) Σ R(x_0, y_0^j)（式 (7)）。两个好处：(a) 它和 y_1 之间没有样本内耦合，期望上是 0，梯度仍然无偏；(b) 只要学生自己还没做对（b(0) < 1），优势就不为零——只在学生已经会了的时候才归零，这正是我们想要的。

5.3.5 ★ 重要性采样为什么被整个扔掉：一个 ✅ 实测数字

理论上，用第二轮的样本去估第一轮的梯度，要乘重要性比值 π(y1|x0) / π(y1|x1) 才无偏。✅ 论文 §3 式 (4) 证明了这一点。

但论文 §3.2 指出：这个估计量的方差由二阶矩控制，而二阶矩是概率比值本身的期望（E_q[w²] = 1 + χ²），不是对数比值。对长序列，逐 token 的偏移会连乘累积。

5.4.2 ★★★ 信用分配：50 步失败了，该怪哪一步

这是长程任务的核心难点，也是蒸馏在这里的真正作用。

ORM（结果奖励模型）在长程任务里的困境：

  一条 50 步的轨迹
  step 1   step 2   step 3   ...   step 48   step 49   step 50
    OK       OK      WRONG    ...     OK        OK       FAIL
                      ^^^^^
                      真正的错因在这里

  环境最后只说一个字：失败。
  GRPO 的组相对优势是【整条轨迹一个数】，
  这个负优势会被平摊到【全部 50 步】上
  ==> 48 个对的动作被一起压低了概率。

  这就是【错误的信用分配】。

✅ 论文 §5.2.1 的原话：「In long-horizon tasks, when both non-optimal action ratio and RL task horizon increase, correct and incorrect actions are mixed in very long trajectories. ORM based GRPO will assign rewards incorrectly, failing to optimize long horizon agent tasks.」

还有一个更狠的后果：长程 + 低质量时，GRPO 连梯度都没有。 ⚠️ 下面这张推演表是我算的（论文只给了现象，没给这个算法），但它能解释论文观察到的「梯度消失」：

设每步正确的概率为 q，整条 T 步轨迹全对才算成功：P(成功) = q^T
GRPO 组大小 G，若组内 G 条【全部失败】，组内奖励全相同
==> 中心化后优势全为 0 ==> 这个 prompt 这一步【完全没有梯度】
P(组内全失败) = (1 − q^T)^G
单步正确率 q 轨迹长度 T P(整条成功) = q^T G=8 时 P(组内全败) 后果
0.95 5 0.774 0.0000 正常学习
0.95 10 0.599 0.0007 正常学习
0.95 20 0.358 0.029 开始有空转
0.95 50 ★ 0.0769 ★ 52.7% ⚠️ 一半的 batch 零梯度
0.90 50 ★ 0.0052 ★ 96.0% ⚠️ 几乎学不动
0.80 50 0.0000143 99.99% ⚠️ 彻底卡死

✅ 论文确实观测到了这个现象（§5.2.2 结果 (2)）：「specific GRPO curves begin exactly at zero and remain completely flat along the x-axis during the initial checkpoint steps... continuously increasing the number of non-optimal actions triggers a vanishing gradient issue」。⚠️ 上表是我给这个观测配的一个可验算解释，论文没写这个推导。

那蒸馏是怎么绕开的？ ✅ 论文 §2.2 式 (2)：Agent-OPD 的损失在每一轮的每一个 token 上都有一项逆 KL：

L_Agent-OPD(θ)  =  E[ sum_{k=1..K}  sum_{t=1..T_k}   D_KL( p_{k,t} || q_{k,t} ) ]
                       \__ 轮 __/     \__ token __/

  ==> 监督信号的数量 = 轮数 * 每轮 token 数，而不是【一条轨迹 1 个数】
  ==> 和【最终成没成功】完全无关

⚠️ 用论文 Figure 8 披露的量级估一下差距（我的估算）：响应长度 150–350 token/轮，15 轮 ⇒ 一条轨迹约 15 × 250 = 3,750 个被监督的位置；而 ORM 只给 1 个数。监督密度相差约 3 个数量级。

★ 机制要点（本章最该记住的一句）：蒸馏在长程任务里不是「更好的奖励」，而是直接把信用分配这个问题取消掉了。 老师在每一步都说「这里该怎么走」，所以根本不需要回答「是哪一步的错」。

★ 但这个取消是有代价的，而且代价很具体：它把「找出哪一步错了」换成了「老师在每一步都是对的」。✅ 论文 §5.2.1 自己点明：「it is clear that the correctness of the teacher planning pattern is extremely important」。5.4.5 节会给出老师不对时会有多惨。

右列（最差质量）：★ 分水岭。 GRPO 在中程和长程上变成负的，OPD 还稳定在 +18.4 到 +18.9。这就是论文标题里「OPD 有更宽的有效区」的全部实证内容。

5.4.4 ✅ 一个不靠准确率的旁证：梯度方向一致性

论文 §5.2.2 没有只看准确率，还直接量了参数更新方向：对每个 checkpoint 的权重增量 ΔW = W(t) − W(base) 做奇异值分解（SVD），取前 5 个左奇异向量，和最终 checkpoint 的对应向量算余弦相似度，再按层平均（✅ 论文 式 (11)–(16)，k=5，最多 75 个训练步）。

意思是：训练早期的更新方向，和最后收敛的方向像不像？ 像 ⇒ 一路朝着一个目标走；不像 ⇒ 在原地打转。

观察 结论 出处
任务越长，GRPO 的方向一致性数值越低 ✅ 粗粒度信用分配让 GRPO 的更新方向变得不一致 论文 §5.2.2 结果 (1)
非最优动作越多，GRPO 的曲线从 0 开始、完全平 ✅ 梯度消失（和 5.4.2 的推演对上了） 论文 §5.2.2 结果 (2)
OPD 在所有配置下都维持较高的一致性 ✅ OPD 的更新方向稳定得多 论文 §5.2.2 结果 (3)

⚠️ 这个证据比准确率更有说服力的原因：准确率可能被评测噪声、checkpoint 选择、超参运气影响；而「早期方向 ≈ 最终方向」是直接量在参数上的，和评测集无关。⚠️ 但它有自己的局限：它只说明更一致，不说明更正确——一个一直朝错方向走的优化器，一致性也会很高。论文的 takeaway 里加了「in ideal teacher condition」（在老师理想的条件下）这个限定 ✅，是对的。

5.5 ★ 算力账：这三种做法各自要多付多少

「蒸馏 + RL」比纯 RL 贵在哪？取决于你让老师干什么。 这里有一个量级上的分水岭：

老师的三种工作强度（从便宜到贵）：

(1) 只算【对数概率】
    老师对学生【已经写好】的 token 序列做一次前向，取出 log p。
    一次批量前向，序列维度可以并行。
    ==> RLAD 和 PlanPhys 的 OPD 属于这一档。

    老师把题从头做到尾。
    ==> 离线蒸馏（SFT on teacher traces）属于这一档。

5.5.3 Agentic 长程蒸馏：⚠️ 一笔必须自己算的账

✅ PlanPhys 也没有给 wall-clock（只知道用 2 张 GPU、模型 100M、RL 最多 75 步、OPD 用 top-k 且 k=100）。但 agentic 场景有一个结构性的坑，值得单独算：

多轮任务里，老师要打分的【上下文在每一轮都变长】：

  第 1 轮：老师读  [题目]                              然后打分 T 个 token
  第 2 轮：老师读  [题目 + 回答1 + 观察1]               然后打分 T 个 token
  第 3 轮：老师读  [题目 + 回答1 + 观察1 + 回答2 + 观察2] 然后打分 T 个 token
  ...
  ==> 如果每轮都重新 prefill（预填充）整个上下文，
      总开销是轮数的【平方】，不是线性。

⚠️ 可验算推演（符号：P = 初始题目长度，T = 每轮学生输出长度，S = 每轮上下文增量 = 输出 + 观察）：

不复用缓存：  Σ_{k=1..K} [ P + (k−1)*S + T ]  =  K*(P+T) + S*K*(K−1)/2
复用前缀缓存：Σ_{k=1..K} T                    =  K*T

⚠️ 代入 PlanPhys 的量级（P=400，T=250，S=300，均由论文 Figure 8 的 prompt/response 长度曲线估得）：

轮数 K 不复用缓存（老师前向 token 数） 复用前缀缓存 ⚠️ 倍数
5 5*650 + 300*10 = 6,250 5*250 = 1,250 5.0×
15（PlanPhys 的典型长度） 15*650 + 300*105 = 41,250 15*250 = 3,750 ★ 11.0×
50（真实 agent 的量级） 50*650 + 300*1225 = 400,000 50*250 = 12,500 ★ 32.0×

★ ⚠️ 结论（我的推断，三篇论文都没给这笔账）：agentic 蒸馏的老师开销，决定性因素不是老师多大，而是你有没有做跨轮的前缀 KV 缓存复用。 50 轮的任务里，这一个工程决定就是 32 倍的差距。

⚠️ 这条属于工程，不属于算法 —— 具体怎么做（KV 缓存复用、训推权重同步、老师服务的部署形态）在 强化学习训练框架目录 里讲；环境侧的瓶颈在 后训练/07 Agentic RL 里讲。本章只负责把这笔账的量级算出来。

5.6 ★ 三篇互相矛盾的地方

把分歧列出来，比假装一致有用得多。

分歧一：蒸馏到底抬的是 Pass@1 还是 pass@K

论文 说法 出处
RLAD ✅ KL 式蒸馏（KDRL）抬的主要是 Pass@32，不是 Pass@1；它的提升「driven primarily by stronger imitation of teacher solution modes」。而 RLAD 自己抬的是 Pass@1 论文 §5.2.2
PlanPhys ✅ OPD 抬的主要是 pass@1（avg@8），GRPO 反而有更高的 pass@8 天花板；因为「OPD suppresses diversity and directly follows the planning pattern of the teacher」 论文 §5.2.1 结果 (2)

★ 方向正好相反。 RLAD 说「模仿 ⇒ 多样性更好 ⇒ 高 K 指标涨」；PlanPhys 说「模仿 ⇒ 寻峰 ⇒ 多样性被压 ⇒ 高 K 指标反而是 RL 更好」。

⚠️ 我的判断（请当成判断而非结论）：PlanPhys 的机制解释更符合逆 KL 的标准性质（逆 KL 是 mode seeking，必然降熵），而且它有熵的实测曲线和模式分布坍缩到 1.00 两个直接证据支撑；RLAD 那一条是从 Pass@1 / Pass@32 的相对涨幅反推出来的，没有直接测多样性。⚠️ 但两者场景差太远（真实 Qwen3 做数学 vs 100M 模型做合成规划），也完全可能两边都对，只是适用区间不同。

✅ 两篇的实测数都在上面的表里，你可以自己核。PlanPhys 的「4 最优:4 次优」那一组，pass@8 是 GRPO 的 +9.44/+11.25/+10.69 对 OPD 的 +3.54/+2.71/+2.36，差距明确。

分歧二：pass@k 还能不能当「能力上限」

✅ PlanPhys §5.2.1 结果 (3) 直接质疑了这个指标：长程设定里 RL 前的 pass@k 几乎是 0，RL 后大幅上升，但这不代表 RL 提升了能力上限——「the necessary knowledge or solution patterns may exist in the pretrained model but are rarely sampled」。它的 takeaway 写得很硬：「we do not think that RL improves the model's capability ceiling... pass@k is distorted in this setting」。

✅ RLAD 则沿用了相反方向的文献共识（引 Yue et al. 2025a）：RL 主要提升 Pass@1 而不是大 K 指标，并用这一点来论证 RLAD「更像真正的 RL」。

⚠️ 这两者不是严格矛盾（一个在质疑指标本身，一个在用指标做论证），但如果你接受 PlanPhys 的质疑，RLAD §5.2.2 那整段论证的前提就动摇了。这一点值得记。

分歧三：重要性采样该留还是该扔

论文 做法 理由
RLAD ✅ 留着，而且重要性比值就是整个机制 比值的分母是 π_S,old 和老师的几何混合
RLTF ✅ 整个扔掉，连裁剪版本都不如不要 「variance dominates bias」

⚠️ 这不是真矛盾，是分母离得远不远的差别，值得写清楚：RLAD 的分母是上一版的自己（PPO 的标准设定，两者很近）；RLTF 的分母是第二轮的自己（看过批评之后，分布差很远——✅ 实测轨迹级 log 比值 142.16）。⚠️ 所以可提炼的规则是：重要性采样能不能用，取决于两个分布的实际距离，不取决于理论上是否无偏。

分歧四：老师更强 = 更好吗

论文 证据 结论
RLAD ✅ 弱老师消融（0.6B 教 1.7B）：RLAD 0.946 vs GRPO 0.950，几乎不掉；KDRL 掉到 0.910 老师弱不致命（前提是机制设计对）
PlanPhys ✅ 满分老师（100.00）+ 程序性知识不匹配 ⇒ 学生 pass@8 从 44.03 掉到 36.60，比不训练还差 老师强完全不够，知识要对得上

⚠️ 合起来的可操作结论（我的归纳）：「老师的 benchmark 分数」是选老师时最不重要的指标之一。 真正决定成败的是 (a) 蒸馏信号有没有被 advantage 调制（RLAD 的答案），(b) 老师和学生的内部程序性知识是不是同一套（PlanPhys 的答案）。

分歧五：⚠️ 本章没有解决的一个空白

数据质量本来就好的时候，蒸馏是不是有害？ ✅ PlanPhys 的 Region A 一列给出的是 OPD −1.1 到 −1.7 点（三个 RL 长度都是负的），而 RLAD 从来没在「数据已经很好」的条件下测过。⚠️ 两篇没有冲突，是没有交集。如果你的预训练/SFT 数据质量很高，本章三篇都没有告诉你该不该上 OPD。

5.7 这一章我能确定的、和不能确定的

✅ 能确定的（都有一手出处）：

RLAD 的机制是把老师塞进 PPO 的重要性比值分母，老师只改信赖域中心和裁剪阈值，不提供独立梯度方向（论文 §4.1）。

RLAD 实测训练开销按 Table 9 自己算是 +15.5%，推理时零开销（论文 §5.2.4 + Table 9）。

RLTF 的文本反馈不替代标量奖励，是叠加的第二条信道（论文 §2 / 式 (7) / 式 (10)）。

RLTF 把文字转成梯度有两条路：SD 转成「带反馈的第二轮生成当示范」，FM 直接把批评当交叉熵目标（论文 §3 / §4）。

RLTF 的重要性采样在实测中不可用：AIME24 上轨迹级 log 比值 142.16（论文附录 D.5 Table 3）。

PlanPhys 的 OPD 在「低质量预训练 + 长程」里比 GRPO 宽一个区域：+18.6 vs −1.6（论文 Figure 7 + Table 3）。

PlanPhys 的满分老师 + 知识不匹配会让学生比不训练还差：pass@8 36.60 vs Instruct 44.03（论文 Table 4）。

MOPD 是 mode seeking 的，最终三个领域的模式分布同时坍缩到单一模板 1.00（论文 Figure 18 / 19）。
