（Tencent，89 页）		 ⚠️ 把 OPD 形式化为「在学生采样的轨迹上最小化 f-散度」，按目标函数 / 信号来源 / 训练动态三个轴整理全领域，并给出 OPD 与「KL 约束下的 RL」的形式联系 01 章 ⚠️ 仅摘要（89 页，正文未读）
Revisiting On-Policy Distillation: Empirical Failure Modes and Simple Fixes
（中科院自动化所 CASIA）		 ⚠️ 标准 OPD 把分布匹配退化成了「采样 token 的对数比值」，在长 rollout 上很脆。给出三个失效模式（token 级监督不均衡 / 老师在学生前缀上不可靠 / tokenizer 与特殊 token 不匹配），修法是 teacher top-K 局部支撑匹配 + top-p 采样 + 特殊 token 掩码，报告 +19.8%（⚠️ 摘要没说是百分点还是相对） 01 章 ⚠️ 仅摘要
Why Does Self-Distillation (Sometimes) Degrade the Reasoning Capability of LLMs?
（Microsoft Research + KAIST + SNU）		 ⚠️ ★ 数学推理里自蒸馏会缩短响应长度的同时把性能做坏。归因于压制了 epistemic verbalization（模型在推理中表达不确定性）。老师被喂越多上下文，不确定性被压得越狠 ⇒ 域内优化快、OOD 受害。报告最多掉 40%（⚠️ 口径未核） 01 章 ⚠️ 仅摘要

A.2 自蒸馏（4 篇）→ 02 章

论文 一句话主张 在哪一章 本表读到什么程度
Embarrassingly Simple Self-Distillation Improves Code Generation（Apple） ⚠️ 不要验证器、不要老师、不要 RL：按特定温度和截断配置采样自己的输出，再拿它做普通 SFT。Qwen3-30B-Instruct 在 LiveCodeBench v6 上 pass@1 42.4% → 55.3%。机制归因于「精度–探索冲突」 02 章 ⚠️ 仅摘要
Self-Distilled Reasoner: On-Policy Self-Distillation for LLMs（UCLA + Meta） ⚠️ 提出 OPSD：同一个模型分饰两角，老师看到特权信息（已验证的推理轨迹），学生只看到题目，在学生自己的 rollout 上最小化逐 token 散度。主打 token 效率 02 章 ⚠️ 仅摘要
Reinforcement Learning via Self-Distillation
（ETH Zurich 等，提出 SDPO）		 ⚠️ ★ RLVR 每次尝试只有一个标量 ⇒ 信用分配瓶颈。很多可验证环境其实提供丰富文本反馈（运行时错误、judge 评语）。SDPO 把「条件在反馈上的当前模型」当自教师，把它的下一 token 预测蒸馏回策略。声称在 LCB v6 上用 4× 更少的生成量达到 GRPO 的最终精度 02 章 ⚠️ 仅摘要
Unifying Group-Relative and Self-Distillation Policy Optimization via Sample Routing
（CASIA 等，提出 SRPO）		 ⚠️ ★ 直接挑战上一篇：SDPO 早期涨得快，但长训会崩。归因两点——在已经做对的样本上做自蒸馏引入优化歧义、自教师信号可靠性逐渐退化。修法是按样本路由：做对的走 GRPO，做错的走 SDPO，再加熵感知动态加权。Qwen3-8B 五基准均值比 GRPO +3.4%、比 SDPO +6.3%，每步算力降 最多 17.2% 02 章 ⚠️ 仅摘要

A.3 特权信息（3 篇）→ 03 章

论文 一句话主张 在哪一章 本表读到什么程度
Privileged Information Distillation for Language Models（ServiceNow + Mila） ⚠️ 前沿 agent 只暴露动作、不暴露思维链，标准蒸馏管线因此断掉。提出 π-Distill（同一个模型里同时训练「条件在特权信息上的老师」和「无条件的学生」）和 OPSD（用学生与特权老师之间的逆 KL 惩罚跑 RL）。声称在多个 agentic benchmark 上超过「带完整 CoT 的 SFT + RL」 03 章 ⚠️ 仅摘要
HDPO: Hybrid Distillation Policy Optimization via Privileged Self-Distillation（NVIDIA） ⚠️ ★ 瞄准 cliff prompt（所有 rollout 全失败 ⇒ GRPO 优势全相同 ⇒ 梯度完全消失）。做法：识别出这类 prompt，给模型喂标准答案生成「特权 rollout」，过滤出正确的，再把老师的 token 级分布蒸馏给学生。因为师生共享权重、只差输入，可实现性差距有界。实测提升很小：pass@4 +0.8~1.1%、pass@8 +0.4~1.7% 03 章 ⚠️ 仅摘要
POPE: Learning to Reason on Hard Problems via Privileged On-Policy Exploration（CMU） ⚠️ ★ 同样针对「难题上 RL 采不出一条正确轨迹」。先否掉三种常规解法（熵奖励 / 放宽裁剪 / 直接优化 pass@k），再指出难易混训会因 ray interference 而适得其反。做法：给难题拼上标准解法的前缀当引导，绝不把 oracle 当训练目标，让引导出来的行为迁移回无引导的原题 03 章 ⚠️ 仅摘要

A.4 OPD 的方法改进（4 篇）→ 04 章

论文 一句话主张 在哪一章 本表读到什么程度
On-Policy Delta Distillation（NAVER AI Lab，OPD²） ⚠️ ★ 不要直接模仿老师的输出分布，改成模仿 delta signal = 老师 − 老师自己指令微调前的 base 模型，也就是「推理微调到底改了什么」这个差分 04 章 ⚠️ 仅摘要
Uni-OPD: Unifying On-Policy Distillation with a Dual-Perspective Recipe（浙大 + 腾讯） ⚠️ 指出 OPD 的两个瓶颈：学生对信息量大的状态探索不足、老师在学生 rollout 上监督不可靠。对策是学生侧做数据平衡、老师侧做「结果引导的 margin 校准」，恢复「聚合后的 token 级指导」与结果奖励之间的序一致性。覆盖 5 个能力域 / 16 个 benchmark，含单老师、多老师、强教弱、跨模态 04 章 ⚠️ 仅摘要
Lightning OPD: Efficient Post-Training for Large Reasoning Models with Offline On-Policy Distillation（NVIDIA） ⚠️ ★ 标准 OPD 全程要挂一个活的老师服务器。本文把老师的 log 概率在 SFT rollout 上预计算一次离线复用。朴素做会失败，根因是一个此前没人提的条件——teacher consistency（SFT 和 OPD 必须用同一个老师）。满足该条件后与标准 OPD 同最优解。Qwen3-8B-Base 30 GPU 小时到 AIME24 69.9%，称 4.0× 训练效率 04 章 ⚠️ 仅摘要
Rubric-based On-policy Distillation（NUS + 中科大 + 腾讯，ROPD） ⚠️ ★ OPD 依赖老师 logits ⇒ 只能白盒。本文用结构化语义 rubric（评分细则）替代 logits：从师生对比里诱导出题目专属的 rubric，再用它给学生 rollout 打分。声称多数场景超过基于 logits 的 OPD，样本效率最多 10× 04 章 ⚠️ 仅摘要

A.5 与 RL 结合 / Agentic（3 篇）→ 05 章

论文 一句话主张 在哪一章 本表读到什么程度
Reinforcement-aware Knowledge Distillation for LLM Reasoning（AWS，RLAD / TRRD） ✅ 不加 KL 正则项，而是把老师塞进 PPO/GRPO 的重要性比值分母，信赖域中心变成「上一版学生与老师的几何混合」。老师只改「这一步能迈多大」，方向永远由 advantage 决定。逻辑推理 avg 0.76 → 0.94（+18 个百分点，vs GRPO），数学 Avg 61.0 → 66.5 05 章 ★ ✅ 通读（含附录）
Expanding the Capabilities of Reinforcement Learning via Text Feedback（CMU，RLTF） ✅ 一条 rollout 只有 1 bit。文本反馈信息比标量奖励密、又比完整示范便宜。训练时有反馈、测试时没有，所以要把反馈内化进第一轮。两条路：SD（把「看过批评的第二轮生成」当示范蒸馏回第一轮）和 FM（直接把批评当交叉熵目标预测）。⚠️ 它没有替代奖励函数，标量奖励全程都在 05 章 ★ ✅ 通读（含附录）
The Physics of Multi-Turn Long-Horizon Planning（中科院自动化所，PlanPhys / MOPD） ✅ 在一个 100M 从零预训练模型 + 合成规划 gym 里做受控实验。核心结论：长程 + 低质量数据下 ORM 的信用分配是错的，GRPO 梯度会消失，OPD 的有效区更宽（+18.6 vs −1.6）。但老师满分 ≠ 能蒸馏：程序性知识不匹配会让学生比不训练还差。MOPD 是寻峰的，最终三个领域的模式分布一起坍缩到单一模板 05 章 ★ ✅ 通读（含附录）

B.2 散度与目标函数

缩写 英文全称 中文 一句话
KL Kullback-Leibler divergence KL 散度 量两个概率分布差多远。不对称：KL(P‖Q) ≠ KL(Q‖P)
逆 KL reverse KL 逆向 KL 指 KL(学生 ‖ 老师)。★ mode seeking（寻峰）：学生挤到老师的一个峰上，降熵、丢多样性
正 KL forward KL 正向 KL 指 KL(老师 ‖ 学生)。★ mode covering（覆盖）：学生被迫摊开去覆盖老师的所有峰
JSD Jensen-Shannon Divergence JS 散度 KL 的对称化版本，介于正反 KL 之间
f-散度 f-divergence f-散度 KL / 逆 KL / JSD 的共同母类。⚠️ 综述那篇用它把 OPD 统一形式化
CE Cross Entropy 交叉熵 普通的下一词预测损失。SFT 用的就是它
K1 / K2 近似 Schulman's K1 / K2 estimators —— 用采样 token 估 KL 的两种写法：K1 = log p − log q；K2 = (log p − log q)² / 2

分歧一：★ 自蒸馏到底有增益还是会退化推理能力

这是本目录最激烈的一组对撞，而且三篇是直接互相引用的。

会退化，且有机制解释 Why Does Self-Distillation (Sometimes) Degrade...（Microsoft） ⚠️ ★ 也直接引用了 SDPO 的作者（Hübotter et al. 2026）。数学推理里自蒸馏缩短响应长度的同时把性能做坏，根因是压制了不确定性表达；老师被喂的上下文越丰富，压得越狠 ⇒ 域内快、OOD 坏。报最多 −40% ⚠️ 仅摘要

⚠️ 一个交叉提醒：05 章 里的 RLTF-SD 和上面的 SDPO 机制几乎同源——都是「把看过反馈的自己当老师，蒸馏回看不到反馈的自己」。区别在于 RLTF-SD 蒸的是第二轮的完整生成（轨迹级、奖励加权），SDPO 蒸的是反馈条件下的下一 token 预测（token 级分布）。⚠️ 两篇我都没有做交叉核对，这只是摘要层面的观察。

★ 至少 5 篇在解决同一个底层问题：一组 rollout 全失败时，GRPO 的梯度是零。

论文 它给这个问题起的名字 它的解法
HDPO（NVIDIA） ⚠️ cliff prompt（悬崖题） 给模型喂标准答案造特权 rollout，过滤后蒸馏
POPE（CMU） ⚠️ 难题上「rarely explores even a single correct rollout」 给难题拼上 oracle 解法的前缀当引导
Self-Distilled Reasoner ⚠️ 「when all samples are either correct or incorrect, the gradient signal vanishes」 用特权推理轨迹条件化的自教师
SDPO（ETH） ⚠️ 「credit-assignment bottleneck」 用文本反馈条件化的自教师
PlanPhys（05 章） ✅ 长程下的「vanishing gradient」+「incorrect credit assignment」 用老师的逐 token 分布直接取代奖励

⚠️ 我的归纳：这个「零梯度」问题可能才是本目录大多数论文的真正共同母题，而「蒸馏」只是大家不约而同选中的解法形态。05 章 的 5.4.2 节给了这个问题的一张可验算推演表（50 步、单步正确率 0.9 时，G=8 的组有 96% 的概率零梯度），可以直接拿来理解上面这五篇为什么都要动手。

D. 口径纪律（这几条全仓统一）

★ 这一节是「怎么不把论文的数字读错」。每条都给可验算的例子。

D.1 「时间减少 X%」≠「加速 X%」

加速倍数  =  1 / (1 − 时间减少比例)
时间减少比例  =  1 − 1 / 加速倍数
时间减少了 加速倍数 反过来：说「加速 N 倍」 等于时间减少
10% 1.11× 1.5× 33.3%
25% 1.33× 2× 50%
50% ★ 2.00× 3× 66.7%
75% ★ 4.00× 4× ★ 75%
80% 5.00× 5× 80%
90% 10.00× 10× 90%

★ 最常被写错的一行：时间减少 50% = 加速 2 倍，不是「加速 50%」。

✅ 用本目录的论文验算（⚠️ 数字来自 Lightning OPD 摘要与 Figure 1，我没核正文）：

设置 标准 OPD Lightning OPD 时间减少 加速倍数 验算 1/(1−r)
Qwen3-8B-Base 120 GPU 小时 30 GPU 小时 90/120 = 75% 120/30 = 4.0× 1/(1−0.75) = 4.00 ✅ 对上
Qwen3-4B-Base 72 GPU 小时 20 GPU 小时 52/72 = 72.2% 72/20 = 3.6× 1/(1−0.722) = 3.60 ✅ 对上

⚠️ 反例（容易被误读的写法）：SRPO 摘要说「每步算力降低最多 17.2%」。这是时间减少，对应的加速只有 1/(1−0.172) = 1.21×。不要写成「快了 17.2 倍」，也不要写成「加速 17.2%」——后者虽然口语上接近，但严格说加速是 21%。

D.2 百分比 vs 百分点

50%  -->  55%

绝对变化： 55 − 50 = 5           ==>  涨了 5 个【百分点】(percentage point, pp)
相对变化： (55 − 50) / 50 = 10%  ==>  涨了 10%（相对）

★ 判据：看到「%」先问一句——分母是 100，还是基线？

✅ 用本目录的论文验算：

论文 基线 → 结果 百分点 相对 论文自己写的
RLAD（逻辑，Qwen3-0.6B @8K） 0.76 → 0.94 +18.0 pp +23.7% ⚠️ 写「+18%」，实际是 18 个百分点
RLAD（逻辑，Qwen3-0.6B @2K） 0.70 → 0.90 +20.0 pp +28.6% ⚠️ 写「+20%」，同上
SSD（Apple，LiveCodeBench v6） 42.4% → 55.3% +12.9 pp +30.4% ✅ ★ 它两个都标了（图里同时写「+12.9」和「+30% relative」），是正确示范
Revisiting OPD 未给基线 ？ ？ ⚠️ 只写「a +19.8% performance gain」，基线和口径都没给，无法判断

⚠️ 本仓库的写法约定：绝对差值一律写「X 个百分点」或「X 点」；相对变化一律写「相对 +X%」。只写「+X%」而不说清楚的，视为口径不明，标 ⚠️。

D.3 噪声门槛：差多少才算真的差

一个准确率估计自己是有波动的。 二项比例的标准误（Standard Error）：

SE  ≈  sqrt( p * (1 − p) / n )

p = 准确率，n = 题目数（不是采样次数！）
p = 0.5 时 SE 最大，所以下表是【最坏情况上界】
题目数 n SE（百分点，p=0.5） 典型 benchmark
30 ★ 9.13 ⚠️ AIME24 / AIME25 各只有 30 题
40 7.91 AMC23
100 5.00
160 3.95 PlanPhys 每格 160 个任务（见 05 章）
200 3.54
500 ★ 2.24 MATH500
1000 1.58
1319 1.38 GSM8K 测试集
1440 1.32 PlanPhys 的 S/M/L Mean 列
5000 0.71

★ ★ 最该记住的一条：AIME 只有 30 题，SE 上界约 9 个百分点。 这意味着AIME 上 10 个点以内的差距，在单次训练、单次评测下基本说明不了问题。本目录有多篇论文的主打数字就落在 AIME 上。

⚠️ 三条补充规则：

(1) n 是题目数，不是采样次数。 采 32 次只是把每道题的成功率估得更准，不会增加题目的数量。题目之间的差异才是主要噪声源。

(2) 「多次解码的标准差」不是「训练的方差」。 很多论文报 STD@k，那是固定一个 checkpoint 反复解码的抖动。换个随机种子重训一遍能差多少，绝大多数论文没测。

(3) ★ 比较两个模型时，别把两个 SE 相加。 这是本节最容易犯的错。

D.4 ★ 比较两个模型：用 McNemar 配对检验

为什么不能把两个 SE 加起来：两个模型跑的是同一批题，它们的错误是相关的——两个模型都会在难题上栽。把误差当独立处理，会把门槛抬得过高，把真实的差异误判成噪声。

把两个模型在同一批题上的结果列成四格：

              B 做对      B 做错
   A 做对        a           b
   A 做错        c           d

  ==> 【a 和 d 两格对「谁更好」完全没有信息】，
      因为两个模型在那些题上表现一样。
      有信息的只有 b（只有 A 对）和 c（只有 B 对）。

McNemar 统计量：   chi2  =  ( |b − c| − 1 )^2  /  ( b + c )
差值的标准误：     SE_diff  ≈  sqrt(b + c) / n

⚠️ 一个能看出区别的算例（我构造的，用来说明方法差异）：

n = 500 题，模型 A 得 55%，模型 B 得 50%，差 5 个百分点。
实际的配对分布：b = 40（只有 A 对），c = 15（只有 B 对）
                  验算：(40 − 15) / 500 = 5.0 个百分点  ==> 和总分差对上了

三种判法：
  [错] 把两个 SE 相加：     2 * 2.24 = 4.47 个百分点  ==> 5.0 勉强超过，"大概显著"
  [仍不对] 按独立算差值：   sqrt(2) * 2.24 = 3.16      ==> 5.0 / 3.16 = 1.6 倍，"不显著"
  [对] McNemar：           chi2 = (25−1)^2 / 55 = 10.47  ==> 约 3.2 个标准差，p 约 0.001
                            SE_diff = sqrt(55)/500 = 1.48 个百分点

★ 三种算法给出三种结论，只有第三种是对的。 前两种都会把一个真实存在的差异判成「不确定」。

⚠️ 实操建议：如果论文没公开逐题结果（绝大多数没有），你算不了 McNemar。这时候正确的做法是承认不确定，而不是退回去用 D.3 的 SE 硬判。本仓库的写法是：这种情况标 ⚠️ 并写明「论文未提供逐题结果，无法做配对检验」。

D.5 提升幅度必须带三样东西

⚠️ 一个光秃秃的「提升了 5 个点」是没有信息量的。 本仓库要求任何提升幅度都附带：

必须写出来 为什么 不写会怎样
★ 基线是什么 从 0.76 涨到 0.94，和从 0.95 涨到 0.99，表面都是「涨了」，难度差一个数量级 没法判断是不是已经接近饱和
★ 哪个数据集，多少题 决定了 D.3 的噪声门槛 ⚠️ AIME（30 题）和 MATH500（500 题）上的「5 个点」完全不是一回事
★ 采样多少次、什么指标 Pass@1 / avg@8 / pass@32 的行为完全不同（见 C 节分歧二） 可能在比较两个不可比的量

F. 一页纸速记

这个领域的三个母题（[推断] 我的归纳，不是任何一篇论文的说法）：

[1] 奖励太稀疏
    ├── 一条 rollout 只有 1 bit
    ├── 全失败时梯度直接是 0（cliff prompt / 零方差题）
    └── 解法们：特权信息、文本反馈、老师的逐 token 分布

[2] 训练分布 != 使用分布
    ├── 离线蒸馏：学生只见过老师的完美前缀
    ├── 曝光偏差沿轨迹累积
    └── 解法：on-policy（让学生自己采样）

[3] 长程任务里信用分配是错的
    ├── 50 步失败，ORM 把惩罚平摊到全部 50 步
    ├── 对的动作被一起压下去
    └── 解法：逐步监督（老师在每一步都说话）==> 绕开而不是解决

三个母题的共同解法形态都是【蒸馏】，所以才有了这 17 篇。

==> 但【蒸馏】也带来三个新问题：
    ├── 老师的上限变成学生的上限（逆 KL 寻峰、降熵）
    ├── 老师和学生的内部知识必须对得上（否则满分老师也白搭）
    └── 什么时候该停下来，没人回答（自蒸馏长训会崩）

三条最容易写错的结论，列在这里做最后提醒：

⚠️ 「文本反馈替代了奖励函数」—— 写反了。 RLTF 里标量奖励全程都在，文本反馈是叠加的第二条信道。

⚠️ 「α=0 退化成 GRPO」—— RLAD 论文正文自己写反了。 以它的公式 (3) 和附录 C 为准：α=1 才是 GRPO。

⚠️ 「RLAD 训练只贵 12%」—— 论文正文这么写，但它自己的 Table 9 算出来是 +15.5%。
