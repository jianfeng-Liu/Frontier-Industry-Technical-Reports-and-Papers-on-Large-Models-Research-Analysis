# 01 · 为什么需要分布式训练

> **这一章的目标**：让你对"一张卡到底不够在哪"有具体的、可以心算的感觉。
> 读完你应该能回答：一张 H100 能训多大的模型？为什么"多买几张卡"不是把问题解决了，而是把问题换了一个？

---

## 1.1 先认识主角：GPU

**GPU**（**G**raphics **P**rocessing **U**nit，图形处理器）现在早就不只是画图的了，它是训练大模型的唯一主力硬件。你只需要记住它的**三个数字**：

```
以 NVIDIA H100（2022 年发布，2024–2026 年的主流训练卡）为例：

  ① 显存容量    80 GB          ← 「能装多少东西」
  ② 显存带宽    3.35 TB/s      ← 「装的东西搬进搬出有多快」
  ③ 算力        ~989 TFLOP/s   ← 「算得有多快」（BF16 稠密算力）
                                  ⚠️ 官方标称含稀疏加速时是两倍，
                                     训练一般用稠密数，本教程一律用稠密数
```

> 📌 **TFLOP/s** = **T**era **FLOP**s per **s**econd，每秒万亿次浮点运算。
> **FLOP** = **FL**oating-point **OP**eration，一次浮点运算（一次加法或一次乘法算一次）。
> 989 TFLOP/s 就是「每秒能做 989 万亿次乘加」。

**这三个数字里，① 显存容量是本教程前半部分的全部矛盾来源。**

---

## 1.2 第一个坎：装不下

### 一个 70B 模型有多大

**70B** = 700 亿个参数（**B** = **B**illion，十亿）。每个参数是一个数。

```
    假设每个数用 BF16 存（2 个字节，10 章会讲什么是 BF16）：

        70 × 10^9 个参数 × 2 字节 = 140 × 10^9 字节 = 140 GB

    而一张 H100 只有 80 GB。

    ★ 光是【把权重放进去】就已经装不下了。
```

**而且这还只是权重。** 训练的时候你还需要：

```
    ① 权重            140 GB     ← 模型本身
    ② 梯度            140 GB     ← 每个参数对应一个梯度
    ③ 优化器状态      840 GB     ← Adam 每个参数要存 3 个额外的数（02 章细讲）
    ④ 激活值          ？？ GB     ← 前向过程中的所有中间结果，和 batch、序列长度成正比
    ─────────────────────────
    总计            > 1120 GB    ★ 需要至少 14 张 H100 才装得下，而且还没算 ④
```

> 🔑 **这就是第一个、也是最硬的动机**：
> **不是"多张卡训得快"，而是"一张卡根本训不了"。** 快是第二位的，装得下是第一位的。

### 推理为什么没这么惨

**你可能见过"单卡跑 70B 模型"的说法。那是【推理】，不是【训练】。**

```
    推理只需要 ①权重（还能量化到 4 bit，只要 35 GB）
    训练需要   ①+②+③+④，是推理的【8 倍以上】

    ★ 训练和推理的显存需求完全不是一个量级。
```

---

## 1.3 第二个坎：太慢

**就算装得下，时间也扛不住。**

### 训练要算多少次

有一个非常好用的经验公式（这是这个领域的通用估算式）：

$$\text{总计算量} \approx 6 \times \Psi \times D$$

- $\Psi$ = 参数量
- $D$ = 训练用的 token 总数
- **6 是怎么来的**：前向每个参数每个 token 要做 1 次乘 + 1 次加 = 2 FLOP；反向大约是前向的 2 倍 = 4 FLOP；合起来 6。

```
    举例：训一个 70B 模型，喂 15 T token（15 × 10^12 个）

        6 × 70×10^9 × 15×10^12 = 6.3 × 10^24 FLOP

    一张 H100 满打满算 989 × 10^12 FLOP/s：

        6.3×10^24 ÷ 989×10^12 = 6.4 × 10^9 秒 ≈ 202 年   ⚠️ 我的估算

    ★ 而且这是【理论峰值】。真实能跑到峰值的 40~55% 就很不错了（12 章讲 MFU）。
      按 45% 算 → 约 450 年。
```

> 🔑 **所以 10,000 张卡不是"豪华配置"，是"唯一能在合理时间内训完的配置"**：
> 450 年 ÷ 10,000 张 ≈ **16 天**。这才是能接受的数字。

### ✅ 真实数字做个校准

**Llama 3.1 405B 的公开数字**（TorchTitan 论文 §1 引用，[papers/TorchTitan-arXiv-2410.06511.pdf](../papers/TorchTitan-arXiv-2410.06511.pdf)）：

> ✅ 原文：*"Llama 3.1 (405B parameters, 15T tokens, 30.84M GPU hours, 16K H100 GPUs)"*

```
    30.84 M GPU 小时 ÷ 16,000 张卡 = 1,928 小时 ≈ 80 天

    ★ 这是真实世界的量级：405B 模型 + 16,000 张 H100 + 80 天。
```

---

## 1.4 于是问题变成了：切什么

**既然一张卡装不下，就要把东西分到多张卡上。** 问题是——**分什么？**

一次训练迭代里，一共只有这么几样东西：

```
┌──────────────────────────────────────────────────────────────┐
│                    一次训练迭代里有什么                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│   数据：  一个 batch，B 条样本，每条 L 个 token               │
│           ↓  能切 B      → 数据并行 DP        （04 章）       │
│           ↓  能切 L      → 上下文并行 CP      （08 章）       │
│                                                              │
│   模型：  l 层，每层几个大矩阵                                │
│           ↓  能切 层     → 流水线并行 PP      （07 章）       │
│           ↓  能切 矩阵   → 张量并行 TP        （06 章）       │
│           ↓  能切 专家   → 专家并行 EP        （09 章，MoE）  │
│                                                              │
│   状态：  梯度、优化器状态                                    │
│           ↓  能切 状态   → ZeRO / FSDP        （05 章）       │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**★ 这张图就是整个第二部分的目录。** 每一章讲一种切法。

---

## 1.5 天下没有免费的午餐

**每一种切法，都要付一样的代价：通信。**

```
    东西切开了 →  这张卡算的时候需要别张卡手里的那一半
              →  必须【等】它传过来
              →  等的时候 GPU 在空转，算力被浪费

    ★ 分布式训练的全部工程，就是在打这一件事：
         让「传」和「算」尽量【同时发生】，而不是排队。
```

**具体有多痛？看一组真实数字**（Horovod 论文，[papers/Horovod-arXiv-1802.05799.pdf](../papers/Horovod-arXiv-1802.05799.pdf)）：

> ✅ 原文：*"we lost about half of our resources due to communication overhead when training on 128 GPUs"*
> ✅ 原文：*"both the Inception V3 and ResNet-101 models were unable to leverage nearly half of our GPU resources"*

```
    ★ 128 张卡，一半的算力被通信吃掉了 —— 这是 2018 年的现实。
      整个领域此后的努力，很大一部分就是在把这一半抢回来。
```

**而现在做到了什么程度？**（MegaScale 论文，[papers/MegaScale-10000-GPUs-arXiv-2402.15627.pdf](../papers/MegaScale-10000-GPUs-arXiv-2402.15627.pdf)）：

> ✅ 原文：*"MegaScale achieves 55.2% Model FLOPs Utilization (MFU) when training a 175B LLM model on 12,288 GPUs"*

```
    12,288 张卡，55.2% 的算力真正用在了模型的计算上。
    ★ 这就是当前工业界的水位线。12 章会讲 MFU 具体怎么算。
```

---

## 1.6 一个容易搞混的问题：为什么不用 CPU 内存

**"服务器内存有 2 TB，为什么不把模型放内存里？"**

```
    因为【带宽】差太多：

        GPU 显存 (HBM)     3.35 TB/s      ← H100
        CPU 内存 (DDR5)    ~0.4 TB/s      ← 差 8 倍
        PCIe 5.0 (卡↔内存)  ~0.06 TB/s     ← ★ 差 55 倍

    ★ 数据从 CPU 内存搬到 GPU 上，走的是最窄的那根管子（PCIe）。
      模型每一层都要搬一次的话，GPU 会 99% 的时间在等数据。
```

> 📌 **但这条路不是完全没用**：**ZeRO-Offload** 和 **ZeRO-Infinity** 这两篇论文就是专门做这件事的（05 章会提），它们的定位是**"用速度换可行性"**——在只有少量卡的时候，让原本跑不了的模型能跑起来。**工业界大规模训练不用它。**

---

## 1.7 本章小结

```
① 一张 H100 = 80 GB 显存 / 3.35 TB/s 带宽 / ~989 TFLOP/s 算力
② 训练一个 70B 模型至少要 1120 GB 显存 —— ★ 一张卡装不下，这是第一动机
   训练显存 ≈ 推理显存的 8 倍以上（多了梯度、优化器状态、激活）
③ 总计算量 ≈ 6 × 参数量 × token 数
   → 70B × 15T token ≈ 6.3×10^24 FLOP，单卡要几百年 —— 这是第二动机
   ✅ 真实校准：Llama 3.1 405B = 16K 张 H100 × 80 天
④ 能切的东西只有六样：batch / 序列 / 层 / 矩阵 / 专家 / 优化器状态
   → 对应 DP / CP / PP / TP / EP / ZeRO，就是第二部分的六章
⑤ ★ 每一种切法的代价都是【通信】。全部工程都在打「让传和算同时发生」
   ✅ 2018 年 128 卡就丢掉一半算力；2024 年 12,288 卡能保住 55.2%
⑥ CPU 内存不能救场：PCIe 带宽比显存带宽窄 55 倍
```

**下一章讲全教程最重要的一件事：那 1120 GB 到底是怎么算出来的。** 这张账本你记住了，后面每一种并行"省了什么"就都是一句话的事。
