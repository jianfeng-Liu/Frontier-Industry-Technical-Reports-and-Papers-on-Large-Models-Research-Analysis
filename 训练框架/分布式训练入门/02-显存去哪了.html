02 · 显存账本：那 1120 GB 到底是怎么来的

这一章是全教程的地基。 把这张账本记住，后面每一种并行"到底省了什么"就都是一句话的事。
读完你应该能回答：为什么是 16 字节/参数？为什么优化器状态比模型本身还大？激活值为什么是唯一一个"和参数量无关"的项？

2.1 显存里只有四样东西

┌────────────────────────────────────────────────────────────────┐
│                  训练时 GPU 显存里的四样东西                     │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  ①  参数     parameters      模型本身的权重                     │
│  ②  梯度     gradients       每个参数对应一个，反向传播算出来的  │
│  ③  优化器状态 optimizer states  Adam 给每个参数额外记的账       │
│  ④  激活值   activations     前向过程中每一层的中间结果          │
│                                                                │
│  ★ ①②③ 合称【模型状态 model states】，大小【只和参数量有关】   │
│  ★ ④   是唯一一个【和 batch、序列长度有关】的项                 │
│    → 这个区别非常重要，它决定了哪一种并行能省哪一项              │
└────────────────────────────────────────────────────────────────┘

✅ ZeRO 论文（papers/ZeRO-...-arXiv-1910.02054.pdf）就是这么分的，原文：
"For large models, the majority of the memory is occupied by model states which include the optimizer states (such as momentum and variances in Adam), gradients, and parameters."
"The remaining memory is consumed by activation, temporary buffers and unusable fragmented memory, which we refer to collectively as residual states."

2.2 先算 ①②③：那个著名的「16 字节/参数」

为什么不能全用 BF16

你可能会想：既然 BF16 是 2 字节，那 70B 参数就是 140 GB，为什么还要 FP32？

📌 先解释三个格式（10 章会详细讲，这里只要知道字节数）：
- FP32 = 32-bit Floating Point，单精度浮点，4 字节，精度高
- FP16 = 半精度浮点，2 字节
- BF16 = Brain Floating Point 16，另一种半精度，2 字节，是现在训练的主流

答案是：参数更新那一步会"更新丢失"。

    举例：一个权重值 w = 1.0，学习率很小，这一步的更新量是 0.00001

        用 BF16 存 w：BF16 只有 8 位尾数，在 1.0 附近能分辨的最小间隔约 0.0078
        1.0 + 0.00001  →  ★ 四舍五入回 1.0，什么都没发生

    ★ 训练几万步，每一步的更新都被吃掉了 → 模型根本不动

✅ 混合精度训练论文（papers/Mixed-Precision-Training-arXiv-1710.03740.pdf）就是为了解决这个问题提出的：
✅ 原文："we maintain a single-precision copy of weights that accumulates the gradients after each optimizer step"
—— 额外留一份 FP32 的"主权重"（master weights），更新在它上面做。

那张账本

于是一个参数需要存这些东西（BF16 混合精度 + Adam 优化器，这是 2024–2026 年的绝对主流配置）：

# 存什么 精度 字节/参数 为什么需要
① 参数（计算用的副本） BF16 2 前向/反向的矩阵乘用它
② 梯度 BF16 2 反向传播的产物
③a FP32 主权重 FP32 4 更新在它上面做，避免更新丢失
③b Adam 一阶动量 m FP32 4 Adam 要记「梯度的滑动平均」
③c Adam 二阶动量 v FP32 4 Adam 要记「梯度平方的滑动平均」
合计 ★ 16 
    ★★★  每个参数 16 字节  ★★★

    这个数字请背下来。它是分布式训练所有讨论的起点。

        70B 模型  →  70×10^9 × 16 = 1120 GB      ← 01 章那个数就是这么来的
        405B 模型 →  405×10^9 × 16 = 6480 GB     ← 需要 81 张 H100 才装得下模型状态

🔑 反直觉但关键的一点：优化器状态（12 字节）比模型本身（2 字节）大 6 倍。
你花 80 GB 显存，只有 10 GB 是"模型"，70 GB 是"训练这件事的开销"。
★ ZeRO 的全部立意就在这一行：这 12 字节，凭什么每张卡都存一份？

Adam 为什么要记两个动量

📌 Adam = Adaptive Moment estimation，自适应矩估计（papers/Adam-Optimizer-arXiv-1412.6980.pdf，Kingma & Ba 2014）。

    朴素梯度下降：  w ← w − lr × g          （g 是这一步的梯度）
                    ❌ 梯度噪声大，会左右横跳
                    ❌ 不同参数的梯度量级差几个数量级，一个学习率不够用

    Adam：
        m ← β₁·m + (1−β₁)·g          一阶动量：梯度的滑动平均 → 平滑噪声
        v ← β₂·v + (1−β₂)·g²         二阶动量：梯度平方的滑动平均 → 度量"这个参数梯度多大"
        w ← w − lr · m̂ / (√v̂ + ε)    ★ 除以 √v：梯度大的参数步子迈小点，反之亦然

    ★ 所以每个参数要额外记 m 和 v 两个数 —— 这就是那 8 字节的来源。

📌 AdamW（papers/AdamW-...-arXiv-1711.05101.pdf）是 Adam 的一个修正版，把权重衰减从梯度里拆出来单独做，显存开销完全一样。现在几乎所有大模型用的都是 AdamW。

📌 ⚠️ Muon 优化器（papers/Muon-...-arXiv-2502.16982.pdf）是近两年的新选择，只需要一个动量而不是两个，所以更省显存。论文原文：✅ "Muon achieves ∼2× computational efficiency compared to AdamW with compute optimal training"、✅ "We open-source our distributed Muon implementation that is memory optimal and communication efficient"。⚠️ 但本教程的账本一律按 AdamW 算，因为它仍是绝大多数框架的默认。

2.3 再算 ④：激活值

激活值 = 前向过程中，所有"反向传播还要用到"的中间结果。

为什么要留着

    前向：  x  →[层1]→  a₁  →[层2]→  a₂  →[层3]→  loss

    反向：  要算「层2 的权重梯度」，链式法则告诉你需要用到【层2 的输入 a₁】
            → ★ 所以 a₁ 在前向算完后【不能扔】，要留到反向用完为止

    ★ 一个 100 层的网络，就要同时留着 100 层的中间结果。

它的大小和什么有关

★ 这是全章最关键的一个区别：

    ①②③ 模型状态：  大小 = 参数量 × 16      ← 和 batch、序列长度【无关】
    ④   激活值：     大小 ∝ b × L × d × l    ← 和参数量【无关】！

        b = micro-batch size（一次前向喂几条）
        L = 序列长度
        d = hidden size
        l = 层数

✅ Megatron 第三篇论文（papers/Megatron-3-...-arXiv-2205.05198.pdf）用一整节推导了这个公式。它的变量表（Table 1，原文）：
s = sequence length, b = microbatch size, h = hidden dimension size, a = number of attention heads, L = number of transformer layers, t = tensor parallel size, p = pipeline parallel size, v = vocabulary size

不带任何优化时，一层 transformer 的激活值大约是：

$$\text{每层激活} \approx s\,b\,h\,\left(34 + 5\frac{a\,s}{h}\right) \text{字节}$$

    ★ 注意括号里第二项 5·a·s/h ：它带一个【额外的 s】
      → 这一项来自注意力矩阵（[b, a, s, s]，那个 s² 的东西）
      → ★ 序列长度翻倍，这一项翻【四】倍

    举例（⚠️ 我按上式代入的估算）：
      s=4096, b=1, h=8192, a=64, L=80 层

        单层 ≈ 4096×1×8192 × (34 + 5×64×4096/8192)
             = 33.6M × (34 + 160) = 33.6M × 194 ≈ 6.5 GB
        80 层 ≈ 520 GB       ★★ 比 70B 的模型状态（1120 GB）小，但也是同一量级

🔑 两个直接推论，请记住：
① 激活值可以靠【减小 micro-batch】来压 —— 但会拖慢（GPU 吃不饱） ② 激活值随序列长度【超线性】增长 —— ★ 这就是长上下文训练的全部困难 → 08 章的上下文并行 CP 就是专门治这一项的

🔑 读这张表的正确方式：
```
「装不下模型状态」 → 找 ①②③ 那三列有 ✅ 的：ZeRO / TP / PP / EP
「装不下激活值」 → 找 ④ 那一列有 ✅ 的：重计算 / SP / CP / 减小 micro-batch

★ 这两类问题的药方完全不同。诊断错了，加再多卡也没用。

⚠️★ 最容易诊断错的就是 PP：它 ①②③ 三列全是 ✅，看着像万能药，
但第 ④ 列上【第一个 stage 一点都不省】——在飞 p 份 × 每卡 L/p 层，p 被约掉了。
⟹ 「激活装不下」时加 PP 是无效处方。详见 §7.8。
```

2.6 一个必须澄清的误解

"我加了 8 张卡做数据并行，显存就够了吧？" —— 不对。

    ★★ 朴素数据并行【每张卡都存一份完整的模型状态】★★

        8 张卡 × 每张 1120 GB = 8960 GB，一点没省，只是复制了 8 份

    → 它只省了【激活值】（因为每张卡的 batch 变小了）
    → ★ 这正是 ZeRO 那篇论文的出发点，原文：

✅ "Basic data parallelism (DP) does not reduce memory per device, and runs out of memory for models with more than 1.4B parameters on current generation of GPUs with 32 GB memory."
✅ "DP replicates the entire model states across all data parallel process resulting in redundant memory consumption"

🔑 「redundant memory consumption」（冗余的显存消耗）这个词就是 ZeRO 名字的来源：
ZeRO = Zero Redundancy Optimizer，零冗余优化器。05 章就讲它怎么把这个冗余削掉。

2.7 本章小结

① 显存里只有四样东西：参数 / 梯度 / 优化器状态 / 激活值
   ★ 前三样合称【模型状态】，只和参数量有关
   ★ 第四样【激活值】只和 batch×序列长度×层数有关，和参数量无关
     → 这个区别决定了「什么病该吃什么药」

② ★★ 16 字节/参数 ★★   （BF16 混合精度 + AdamW）
     参数 BF16   2
     梯度 BF16   2
     FP32 主权重 4    ← 不留它，小的更新会被四舍五入吃掉
     Adam m      4
     Adam v      4
   → 70B 模型 = 1120 GB 模型状态，光这一项就要 14 张 H100
   ★ 优化器状态（12B）是模型本身（2B）的 6 倍 —— ZeRO 的全部立意在此

③ 激活值 ≈ s·b·h·(34 + 5·a·s/h) 字节/层  ✅ Megatron-3 论文
   ★ 括号第二项带额外的 s → 序列长度翻倍，这一项翻【四】倍
   → 这是长上下文训练困难的全部来源，08 章的 CP 专治此项

④ ★ 朴素数据并行【一点显存都不省】，它复制而不是切分
   → ZeRO = Zero Redundancy Optimizer，名字就是冲着这个冗余来的
