# 03 · 通信原语：卡和卡之间怎么说话

> **这一章的目标**：把 all-reduce、all-gather、reduce-scatter、all-to-all 这四个词彻底讲明白。
> 它们是后面每一章的基本词汇——**不认识它们，后面所有并行方案的描述都会变成天书。**

---

## 3.1 先解决一个问题：GPU 之间怎么连

**在讲"传什么"之前，先看"用什么传"。**

```
┌─── 同一台机器内（一台服务器 8 张卡）────────────────────────┐
│                                                            │
│   NVLink   NVIDIA 自家的卡间高速互联                        │
│            H100 上：★ 900 GB/s（双向）                      │
│            → 快得接近显存带宽的 1/4，可以放心大胆地用        │
└────────────────────────────────────────────────────────────┘

┌─── 跨机器（一个集群几千张卡）──────────────────────────────┐
│                                                            │
│   InfiniBand / RoCE   网卡，走网线                          │
│            典型：★ 400 Gbps = 50 GB/s 每张网卡              │
│            → ★★ 比 NVLink 慢【18 倍】★★                    │
└────────────────────────────────────────────────────────────┘
```

> 📌 **术语**：
> - **NVLink**：NVIDIA 的 GPU 直连总线，只在一台机器内部有。
> - **IB** = **I**nfini**B**and，一种高性能网络互联标准，用于跨机器。
> - **RoCE** = **R**DMA **o**ver **C**onverged **E**thernet，用普通以太网实现类似效果的方案。
> - **NCCL**（读作 "nickel"）= **N**VIDIA **C**ollective **C**ommunications **L**ibrary，NVIDIA 集合通信库。**你在框架里写的每一个通信调用，最后都是 NCCL 在执行。**

> 🔑 **★★ 这 18 倍的差距，是整个分布式训练策略设计的第一约束 ★★**
> ```
> 「通信量大的并行方式 → 必须放在机器【内】（走 NVLink）」
> 「通信量小的并行方式 → 才能放到机器【间】（走网络）」
> ```
> **这就是为什么 Megatron 会说：TP 只能在一台机器内做，PP 才能跨机器。**

> ✅ Megatron 第三篇论文原文：*"tensor-level model parallelism is typically limited to a relatively small group of GPUs that are connected with high speed bandwidth, such as GPUs connected with NVLink inside a DGX server."*
>
> ✅ Zero Bubble 论文也说了同一件事：*"NVLink between GPUs within one compute node, a hybrid of DP, TP and ZeRO strategies works efficiently"*、*"PP is particularly advantageous for utilizing cross-server connections, especially at the scale of thousands of GPUs"*

## 3.2 四个基本动作

**先约定一个画法**：4 张卡，每张卡手里有一个数据块。

### ① Broadcast（广播）：一个人说，所有人听

```
    之前                          之后
    ┌────┐                        ┌────┐
    │ A  │  卡0  ──────────┐      │ A  │  卡0
    ├────┤                 │      ├────┤
    │    │  卡1            ├────► │ A  │  卡1
    ├────┤                 │      ├────┤
    │    │  卡2            ├────► │ A  │  卡2
    ├────┤                 │      ├────┤
    │    │  卡3            └────► │ A  │  卡3
    └────┘                        └────┘

    用途：训练一开始，把随机初始化的权重从卡0 发给所有卡（保证起点一致）
```

### ② All-Gather（全收集）：每人拿出一块，最后每人都有全套

```
    之前                          之后
    ┌────┐                        ┌──────────────┐
    │ A  │  卡0                   │ A │ B │ C │ D │  卡0
    ├────┤                        ├──────────────┤
    │ B  │  卡1        ────►      │ A │ B │ C │ D │  卡1
    ├────┤                        ├──────────────┤
    │ C  │  卡2                   │ A │ B │ C │ D │  卡2
    ├────┤                        ├──────────────┤
    │ D  │  卡3                   │ A │ B │ C │ D │  卡3
    └────┘                        └──────────────┘

    ★ 每张卡的数据量【变成 4 倍】
    用途：ZeRO-3 用它把切碎的权重临时拼回完整的一层（05 章）
```

### ③ Reduce-Scatter（归约分散）：所有人的数据【相加】，然后每人只拿走结果的一段

```
    之前（每张卡都有 4 段）              之后
    ┌──────────────┐                    ┌──────────┐
    │ a₀│ b₀│ c₀│ d₀│  卡0              │ a₀+a₁+a₂+a₃│  卡0  ← 只拿第 0 段
    ├──────────────┤                    ├──────────┤
    │ a₁│ b₁│ c₁│ d₁│  卡1     ────►    │ b₀+b₁+b₂+b₃│  卡1  ← 只拿第 1 段
    ├──────────────┤                    ├──────────┤
    │ a₂│ b₂│ c₂│ d₂│  卡2              │ c₀+c₁+c₂+c₃│  卡2
    ├──────────────┤                    ├──────────┤
    │ a₃│ b₃│ c₃│ d₃│  卡3              │ d₀+d₁+d₂+d₃│  卡3
    └──────────────┘                    └──────────┘

    ★ 每张卡的数据量【变成 1/4】
    用途：ZeRO-2 用它做梯度归约，每张卡只留自己负责的那一段梯度（05 章）
```

> 📌 **"Reduce"（归约）是什么意思**：把多份数据按位置**合并成一份**。最常见的合并方式是**求和**（sum），也可以是求平均、取最大值等。**分布式训练里 99% 的 reduce 都是求和。**

### ④ ★ All-Reduce（全归约）：所有人的数据相加，然后每人都拿到完整结果

```
    之前                                 之后
    ┌────┐                               ┌──────────┐
    │ g₀ │  卡0                          │ g₀+g₁+g₂+g₃│  卡0
    ├────┤                               ├──────────┤
    │ g₁ │  卡1              ────►       │ g₀+g₁+g₂+g₃│  卡1
    ├────┤                               ├──────────┤
    │ g₂ │  卡2                          │ g₀+g₁+g₂+g₃│  卡2
    ├────┤                               ├──────────┤
    │ g₃ │  卡3                          │ g₀+g₁+g₂+g₃│  卡3
    └────┘                               └──────────┘

    ★★ 这是分布式训练中最重要、也最常用的一个操作 ★★
    用途：数据并行的梯度同步（04 章）、张量并行每层的输出合并（06 章）
```

**★ 一个关键的恒等式**（记住它，后面反复用到）：

```
        All-Reduce  =  Reduce-Scatter  +  All-Gather

    先各自算出一段的和（数据量 ↓），再把各段拼回来（数据量 ↑）

    ★ 这不只是概念上的等价 —— NCCL 内部就是这么实现的，
      叫「Ring All-Reduce」（环形全归约）。
```

### ⑤ All-to-All（全交换）：每人手里的第 i 段，都发给第 i 个人

```
    之前                                 之后
    ┌──────────────┐                    ┌──────────────┐
    │ a₀│ a₁│ a₂│ a₃│  卡0              │ a₀│ b₀│ c₀│ d₀│  卡0
    ├──────────────┤                    ├──────────────┤
    │ b₀│ b₁│ b₂│ b₃│  卡1     ────►    │ a₁│ b₁│ c₁│ d₁│  卡1
    ├──────────────┤                    ├──────────────┤
    │ c₀│ c₁│ c₂│ c₃│  卡2              │ a₂│ b₂│ c₂│ d₂│  卡2
    ├──────────────┤                    ├──────────────┤
    │ d₀│ d₁│ d₂│ d₃│  卡3              │ a₃│ b₃│ c₃│ d₃│  卡3
    └──────────────┘                    └──────────────┘

    ★ 本质上是一次【矩阵转置】：行变列
    ★ 数据总量不变，但每个人手里的东西全换了
    用途：MoE 的专家并行（09 章）、DeepSpeed-Ulysses 的序列并行（08 章）
```

## 3.3 Ring All-Reduce：为什么通信量是 2Ψ 而不是 NΨ

**这是理解"为什么数据并行能扩展到几千张卡"的关键。**

### 朴素做法（❌ 不能用）

```
    所有卡都把梯度发给卡0，卡0 加完再发回去

    → 卡0 要收 (N−1) 份、发 (N−1) 份
    → ★ 卡0 的网卡成为瓶颈，N 越大越糟，完全不能扩展
```

### Ring All-Reduce（✅ NCCL 的做法）

**把 N 张卡排成一个环，每张卡只和左右邻居说话。**

```
     卡0 ──► 卡1 ──► 卡2 ──► 卡3 ──┐
      ▲                            │
      └────────────────────────────┘

    把每张卡的梯度切成 N 段，然后：

    阶段一：Reduce-Scatter，走 N−1 步
       第 k 步：每张卡把手里"累加中的某一段"传给右邻居，同时收左邻居的
       N−1 步后：★ 卡 i 手里持有第 i 段的【完整求和结果】

    阶段二：All-Gather，走 N−1 步
       把每张卡手里那段完整结果，绕环传一圈
       N−1 步后：★ 每张卡都有全部 N 段
```

**通信量账**（Ψ = 梯度总大小）：

```
    阶段一：每步每张卡发 Ψ/N，走 N−1 步  →  Ψ(N−1)/N
    阶段二：每步每张卡发 Ψ/N，走 N−1 步  →  Ψ(N−1)/N
    ────────────────────────────────────────────────
    合计：每张卡发送  2Ψ(N−1)/N  ≈  ★ 2Ψ

    ★★ 和 N 【几乎无关】！★★
       128 张卡和 1024 张卡，每张卡的通信量几乎一样。
       这就是数据并行能扩展到几千张卡的根本原因。
```

> 🔑 **"2Ψ" 这个数字请记住。** 后面 05 章讲 ZeRO 时，衡量各阶段代价的方式就是"跟这个 2Ψ 比"：
> ```
> ZeRO-1、ZeRO-2  →  通信量仍是 2Ψ  ✅ 白赚
> ZeRO-3          →  通信量变成 3Ψ  ⚠️ 贵 1.5 倍，但省 N 倍显存
> ```

## 3.4 真正决定性能的：能不能和计算重叠

**通信本身有多快，其实是第二位的。第一位的是：通信的时候 GPU 在干什么？**

```
❌ 串行（naive）：
    ┌───── 计算 ─────┐┌──── 通信 ────┐┌───── 计算 ─────┐
                      ↑ GPU 在这段时间【完全空转】

✅ 重叠（overlap）：
    ┌───── 计算 ─────┐┌───── 计算 ─────┐
      └── 通信 ──┘      └── 通信 ──┘
      ↑ 通信在【后台】进行，GPU 一直在算

    ★ 理想情况下，通信时间被完全"藏"在计算时间里 → 通信开销 = 0
```

**具体怎么藏？以数据并行为例**（04 章会展开）：

```
    反向传播是【从最后一层往前】算的：

        层100 的梯度算完了  →  ★ 立刻开始传它，同时继续算层 99
        层99  的梯度算完了  →  ★ 立刻开始传它，同时继续算层 98
        ...

    → 等最后一层（层1）算完时，前面 99 层的梯度早就传完了
    ★ 这叫【梯度桶（gradient bucketing）】+【通信/计算重叠】
```

> ✅ PyTorch DDP 论文（[papers/PyTorch-Distributed-DDP-arXiv-2006.15704.pdf](../papers/PyTorch-Distributed-DDP-arXiv-2006.15704.pdf)）的核心贡献就是这个工程实现。
>
> ✅ FSDP 论文（[papers/PyTorch-FSDP-arXiv-2304.11277.pdf](../papers/PyTorch-FSDP-arXiv-2304.11277.pdf)）原文说得更直白：*"FSDP can squeeze out bubbles using an abundant set of tools to aggressively overlap communication with computation through operation reordering and parameter prefetching."*

> 🔑 **这解释了一个初学者常见的困惑**：
> **"论文说通信量是 2Ψ，那 70B 模型每步要传 140 GB，50 GB/s 的网卡不是要 2.8 秒？"**
> ```
> 答：是要 2.8 秒，但这 2.8 秒和【反向传播的计算时间】重叠了。
>     只要反向计算 ≥ 2.8 秒，通信就是"免费"的。
>     ★ 这也是为什么 batch 不能太小 —— 计算时间太短，就藏不住通信了。
> ```

## 3.5 一个速查表

| 操作 | 每张卡数据量变化 | 一句话 | 主要用在 |
|---|---|---|---|
| **Broadcast** | 1 → 1（复制） | 一个人说，所有人听 | 初始化权重 |
| **All-Gather** | 1 → N | 每人一块，凑成全套 | ZeRO-3 拼权重（[05](05-ZeRO与FSDP.md)）、TP 拼输出（[06](06-张量并行TP.md)） |
| **Reduce-Scatter** | N → 1 | 求和后每人拿一段 | ZeRO-2 归约梯度（[05](05-ZeRO与FSDP.md)） |
| **★ All-Reduce** | 1 → 1（求和） | 求和后每人拿全部 | DP 梯度同步（[04](04-数据并行DP.md)）、TP 每层输出（[06](06-张量并行TP.md)） |
| **All-to-All** | 1 → 1（转置） | 每人的第 i 段发给第 i 个人 | MoE 专家并行（[09](09-专家并行EP.md)）、Ulysses（[08](08-序列并行与上下文并行.md)） |
| **P2P Send/Recv** | — | 点对点，只给指定的一个人 | 流水线并行传激活（[07](07-流水线并行PP.md)） |

```
★ 记住这个恒等式：  All-Reduce = Reduce-Scatter + All-Gather
★ 记住这个数字：    Ring All-Reduce 每卡通信量 ≈ 2Ψ，与卡数 N 【几乎无关】
```

## 3.6 本章小结

```
① 硬件上有两条路，速度差 18 倍：
     NVLink（机器内）  900 GB/s
     InfiniBand（机器间）50 GB/s
   ★ 这个差距是所有并行策略设计的第一约束
   → 通信量大的（TP）必须留在机器内，通信量小的（PP）才能跨机器
   ✅ Megatron-3 和 Zero Bubble 两篇论文都明确说了这一点

② 五个基本动作，全部由 NCCL（NVIDIA 集合通信库）执行：
     Broadcast       一个人说所有人听
     All-Gather      每人一块凑全套           数据量 ×N
     Reduce-Scatter  求和后每人拿一段         数据量 ÷N
   ★ All-Reduce     求和后每人拿全部         最重要
     All-to-All      本质是一次矩阵转置

③ ★ All-Reduce = Reduce-Scatter + All-Gather —— NCCL 就是这么实现的

④ ★★ Ring All-Reduce 每张卡的通信量 ≈ 2Ψ，与 GPU 数【几乎无关】★★
   → 这是数据并行能扩展到几千张卡的根本原因
   → 后面衡量 ZeRO 各阶段的代价，都是跟这个 2Ψ 比

⑤ ★ 真正决定性能的不是通信量，是【能不能和计算重叠】
   反向传播从后往前算 → 每算完一层就立刻开始传，藏在后续计算里
   → 这也解释了为什么 batch 太小会掉性能：计算时间藏不住通信时间
```
