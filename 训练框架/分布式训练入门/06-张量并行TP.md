# 06 · 张量并行 TP：把一个矩阵切开

> **这一章是 Megatron 的立身之本，也是全教程最需要动笔算一遍的一章。**
> 读完你应该能回答：一个矩阵有两种切法（按列 / 按行），为什么 Megatron 要按"先列后行"的顺序配对？为什么一层 transformer 恰好只需要 **2 次 all-reduce**？为什么 TP 度数最多只能到 8？

> 📌 **TP** = **T**ensor **P**arallel，张量并行。也叫 **intra-layer model parallelism**（层内模型并行）。

---

## 6.1 先回到最朴素的事实：矩阵乘法可以分块

**Transformer 里 99% 的计算就是 `Y = X W`。** 张量并行的全部内容，就是把这个 `W` 切开。

**而这件事只有两种切法**：

### 切法 A：按列切（Column Parallel）

$$W = [W_1 \mid W_2], \qquad XW = [XW_1 \mid XW_2]$$

```
         W  [d, 4d]                 切成两半
    ┌──────────────┐          ┌───────┐ ┌───────┐
    │              │    ──►   │  W₁   │ │  W₂   │
    │              │          │[d,2d] │ │[d,2d] │
    └──────────────┘          └───────┘ └───────┘
                                 卡0        卡1

    X [b, d] ★ 两张卡都需要【完整的 X】

    卡0 算 XW₁ → Y₁ [b, 2d]
    卡1 算 XW₂ → Y₂ [b, 2d]

    ★★ 关键：Y = [Y₁ | Y₂]  —— 只要【拼起来】就是正确答案，不需要相加 ★★
       → 如果下一步能接受"切开的 Y"，那就【一次通信都不用】
```

### 切法 B：按行切（Row Parallel）

$$W = \begin{bmatrix}W_1\\ W_2\end{bmatrix},\quad X = [X_1 \mid X_2], \qquad XW = X_1W_1 + X_2W_2$$

```
         W [4d, d]                切成上下
    ┌──────────┐            ┌──────────┐
    │          │            │    W₁    │  卡0
    │          │    ──►     ├──────────┤
    │          │            │    W₂    │  卡1
    └──────────┘            └──────────┘

    X 也必须按对应方向切开：X = [X₁ | X₂]

    卡0 算 X₁W₁ → 一个 [b, d] 的【部分和】
    卡1 算 X₂W₂ → 另一个 [b, d] 的【部分和】

    ★★ 关键：Y = X₁W₁ + X₂W₂  —— 必须【相加】才是正确答案 ★★
       → 需要一次 All-Reduce
```

> 🔑 **★★ 全章的核心洞察在这里 ★★**：
> ```
> 按列切  →  输出是【拼接】关系  →  可以直接喂给下一个"按行切"的矩阵，不用通信
> 按行切  →  输出是【求和】关系  →  必须 All-Reduce
>
> ★ 所以：把「列切」和「行切」【配成一对】，中间那次通信就省掉了！
> ```

---

## 6.2 ★ Megatron 的 FFN：先列后行

**FFN**（**F**eed-**F**orward **N**etwork，前馈网络）是 transformer 两大块之一，形式是：

$$Y = \text{GELU}(X W_1)\, W_2$$

**Megatron 的切法**：

```
   ┌──────────────────────── 卡 0 ────────────────────────┐
   │  X ──► XW₁⁽⁰⁾ ──► GELU ──► [·] W₂⁽⁰⁾ ──► 部分和 Y⁽⁰⁾ │
   │        ↑ 列切              ↑ 行切                     │
   ├──────────────────────── 卡 1 ────────────────────────┤
   │  X ──► XW₁⁽¹⁾ ──► GELU ──► [·] W₂⁽¹⁾ ──► 部分和 Y⁽¹⁾ │
   └──────────────────────────────────────────────────────┘
                              ↓
                    ★ All-Reduce：Y = Y⁽⁰⁾ + Y⁽¹⁾
                              ↓
                  ★★ 整个 FFN 只用了【1 次】通信 ★★
```

### 为什么 W₁ 必须按列切（而不是按行切）

**这一步是 Megatron 论文最漂亮的地方，值得单独说。**

```
    ★ 因为中间夹了一个 GELU 这样的【逐元素非线性函数】。

    如果 W₁ 按【行】切：
        中间结果 = 部分和，必须先 All-Reduce 才是真正的 XW₁
        因为   GELU(a + b) ≠ GELU(a) + GELU(b)   ← ★ 非线性不能拆！
        → 被迫在 GELU 之前插一次 All-Reduce

    如果 W₁ 按【列】切：
        中间结果 = [XW₁⁽⁰⁾ | XW₁⁽¹⁾]，是【拼接】不是【求和】
        每一列都是【完整的、最终的】值
        → ★ GELU 可以直接逐元素作用在各自那一半上，完全不用通信
```

> 🔑 **一句话**：**非线性函数不能作用在"部分和"上，只能作用在"完整值"上。**
> **列切给的正是完整值，所以非线性必须跟在列切后面。**
> **这个约束决定了 Megatron 所有的切分方向。**

## 6.3 注意力：按头切

**多头注意力天然就是"并行的几个头"，切起来更自然。**

```
   假设 16 个头，TP=2：

   ┌─────────── 卡 0：负责第 0~7 号头 ────────────┐
   │  W_Q⁽⁰⁾ W_K⁽⁰⁾ W_V⁽⁰⁾  【列切】(切的是头这一维)│
   │  → 完整地算出第 0~7 号头的注意力输出           │
   │  → W_O⁽⁰⁾ 【行切】 → 部分和                   │
   ├─────────── 卡 1：负责第 8~15 号头 ───────────┤
   │  W_Q⁽¹⁾ W_K⁽¹⁾ W_V⁽¹⁾  【列切】               │
   │  → 完整地算出第 8~15 号头的注意力输出          │
   │  → W_O⁽¹⁾ 【行切】 → 部分和                   │
   └───────────────────────────────────────────────┘
                          ↓
              ★ All-Reduce → 注意力模块也只用【1 次】通信
```

> 🔑 **注意力这里更"干净"**：因为不同的头之间**本来就没有任何计算依赖**——每个头独立地做 softmax、独立地做加权求和。**softmax 的非线性完全发生在单个头内部，不跨卡。**

## 6.4 ★ 结论：一层 transformer = 2 次 All-Reduce

```
    ┌─────────────────────────────────────────────────┐
    │   一层 transformer（前向）                        │
    │                                                 │
    │    注意力模块  ──► All-Reduce  ①                 │
    │         │                                       │
    │    FFN 模块    ──► All-Reduce  ②                 │
    └─────────────────────────────────────────────────┘

    反向传播对称，也是 2 次。

    ★★ 一层 = 前向 2 次 + 反向 2 次 = 4 次 All-Reduce ★★
       80 层的模型，一次迭代 = 320 次 All-Reduce
```

**每次 all-reduce 传多少**：一个 `[b, s, d]` 的激活张量。

```
    举例：b=1, s=4096, d=8192, BF16
       每次 = 1 × 4096 × 8192 × 2 字节 = 67 MB
       一层 4 次 = 268 MB
       80 层     = 21 GB   ★★ 每一步迭代要传 21 GB！

    ⚠️ 我的算例。走 NVLink（900 GB/s）需要 23 ms —— 可以接受。
       走 InfiniBand（50 GB/s）需要 429 ms —— ★★ 完全不可接受 ★★
```

> 🔑 **★★ 这就是"TP 不能跨机"这条铁律的全部来源 ★★**
> ✅ Megatron-3 论文原文：*"tensor-level model parallelism is typically limited to a relatively small group of GPUs that are connected with high speed bandwidth, such as GPUs connected with NVLink inside a DGX server."*
> ✅ PipeDream-2BW 论文也说：*"Tensor (intra-layer) model parallelism leads to expensive all-to-all communication in the critical path, limiting the number of model partitions to the number of GPUs in a single server."*
>
> ```
> ★ 实践铁律：TP ≤ 8（一台机器 8 张卡），几乎从不例外。
> ```

## 6.5 ✅ 效果：Megatron 第一篇论文的成绩单

> ✅ [papers/Megatron-1-...-arXiv-1909.08053.pdf](../papers/Megatron-1-LM-Model-Parallelism-arXiv-1909.08053.pdf) 摘要原文：
> *"We illustrate this approach by converging transformer based models up to 8.3 billion parameters using 512 GPUs. We sustain 15.1 PetaFLOPs across the entire application with 76% scaling efficiency when compared to a strong single GPU baseline that sustains 39 TeraFLOPs, which is 30% of peak FLOPs."*

```
    ✅ 单卡基线：  1.2B 模型，单张 V100 32GB，39 TFLOP/s（峰值的 30%）
    ✅ 扩展后：    8.3B 模型，512 张 GPU，8 路张量并行，15.1 PFLOP/s
    ✅ 扩展效率：  76%

    ⚠️ 验算：512 × 39 TFLOP/s = 19.97 PFLOP/s（理想线性扩展）
             15.1 ÷ 19.97 = 75.6%  ✅ 和论文的 76% 对上了
```

> 📌 **"扩展效率 76%" 是什么意思**：如果 512 张卡是完美的，应该有 512 倍的吞吐。实际拿到了 76%，剩下 24% 被通信和其他开销吃掉了。**这是 2019 年的水平。**

## 6.6 源码里长什么样

**Megatron 把这两种切法做成了两个类**，就在 [../源码/Megatron-LM/megatron/core/tensor_parallel/layers.py](../源码/Megatron-LM/megatron/core/tensor_parallel/layers.py)（Megatron-Core 0.20.0）：

```
✅ ColumnParallelLinear 的 docstring 原文：
    """Linear layer with column parallelism.
    The linear layer is defined as Y = XA + b. A is parallelized along
    its second dimension as A = [A_1, ..., A_p]."""
                                  ↑ 第二维 = 列 ✅ 就是 §6.1 的切法 A

✅ RowParallelLinear 的 docstring 原文：
    """Linear layer with row parallelism.
    The linear layer is defined as Y = XA + b. A is parallelized along its
    first dimension and X along its second dimension.
    A = transpose([A_1 .. A_p])   X = [X_1, ..., X_p]"""
                                  ↑ 第一维 = 行 ✅ 就是 §6.1 的切法 B
                                  ↑ 注意 X 也要跟着切
```

**两个关键参数，正好对应本章的两个洞察**：

| 类 | 参数 | 含义 | 对应本章 |
|---|---|---|---|
| `ColumnParallelLinear` | `gather_output` | 是否把切开的输出拼回完整的 | **设成 `False` 就省掉了那次通信**（§6.1 的核心） |
| `RowParallelLinear` | `input_is_parallel` | 输入是否已经是切开的 | **设成 `True` 表示"上一层是列切，直接接上"**（§6.2 的配对） |

> ✅ `gather_output` 的 docstring 原文：*"If true, call all-gather on output and make Y available to all GPUs, otherwise, every GPU will have its output which is Y_i = XA_i"*
> ✅ `input_is_parallel` 的 docstring 原文：*"If true, we assume that the input is already split across the GPUs and we do not split again."*
>
> 🔑 **★ Megatron 的 FFN 就是 `ColumnParallelLinear(gather_output=False)` 后面直接接 `RowParallelLinear(input_is_parallel=True)`。这两个参数一开一关，中间那次 all-gather 就被省掉了 —— §6.1 的洞察在源码里就是这两行。**

**还有一个类专门处理词表**：`VocabParallelEmbedding`。因为词表很大（15 万左右 × d），embedding 表也值得切开。

## 6.6b ⚠️ 一个新东西：GTP

Megatron-Core 0.20.0 里出现了一个之前没有的并行维度，值得一提：

```
✅ parallel_state.py 里的原文注释（关于 GTP，Generalized Tensor Parallelism）：
   它沿 out_features 维切分权重，前向【和反向都】做逐权重的异步 all-gather；
   ✅ 原注释特意提醒：
      "NOTE: 'remat' here is NOT activation recomputation/checkpointing."
      （这里的 remat 指的是【权重】重物化，不是激活重计算）
```

> ⚠️ **我没有在 papers/ 里找到对应的公开论文**，它看起来是 Megatron-Core 较新的实验特性。**初学阶段可以完全忽略它**，知道"TP 还在演化"就够了。

## 6.7 TP 省了什么、代价是什么

| | TP=8 的效果 |
|---|---|
| ① 参数 | ✅ **÷8** |
| ② 梯度 | ✅ **÷8** |
| ③ 优化器状态 | ✅ **÷8** |
| ④ 激活值 | ⚠️ **部分 ÷8**——但有几块切不掉！ |
| **代价** | ★ 每层 4 次 all-reduce，**必须在机器内** |

**★ 那个"⚠️ 部分"非常重要，是下一章之后 08 章存在的理由**：

```
    一层 transformer 里，有几个地方是【不切】的：

        LayerNorm（归一化）的输入输出
        Dropout
        残差连接

    因为这些操作 Megatron 让【每张卡都做一遍完整的】（更简单）。
    → ★ 这几块激活值在所有 TP 卡上是【重复存储】的，一点没省。

    ✅ Megatron-3 论文原文点名了这件事：
       "In this approach, there are parts of the transformer where activations
        are not split across tensor parallel ranks, adding to activation
        memory overhead."

    → 08 章的【序列并行 SP】就是专门来补这个洞的。
```

## 6.8 本章小结

```
① 一个矩阵只有两种切法：
   ★ 列切：输出是【拼接】关系 → 不需要通信，可以直接喂给下一层
   ★ 行切：输出是【求和】关系 → 必须 All-Reduce

② ★★ Megatron 的核心技巧：把「列切」和「行切」配成一对 ★★
   FFN:  W₁ 列切 → GELU → W₂ 行切 → 1 次 All-Reduce
   为什么 W₁ 必须列切：GELU(a+b) ≠ GELU(a)+GELU(b)
     ★ 非线性只能作用在【完整值】上，列切给的正是完整值

③ 注意力按【头】切，天然干净：头与头之间本无依赖，softmax 不跨卡

④ ★ 一层 transformer = 前向 2 次 + 反向 2 次 = 4 次 All-Reduce
   ⚠️ 我的算例：80 层、s=4096、d=8192 → 每步要传 21 GB
      NVLink 23 ms ✅  /  InfiniBand 429 ms ❌
   → ★★ 铁律：TP ≤ 8，只在一台机器内做 ★★
   ✅ Megatron-3 和 PipeDream-2BW 两篇论文都明确说了这个限制

⑤ ✅ Megatron-1 的成绩单：8.3B 模型、512 张 GPU、8 路 TP、
   15.1 PFLOP/s、76% 扩展效率（单卡基线 39 TFLOP/s = 峰值的 30%）

⑥ 源码：ColumnParallelLinear / RowParallelLinear 两个类
   ★ gather_output=False + input_is_parallel=True 这对参数，
     就是 §6.1 那个洞察在代码里的样子

⑦ ⚠️ TP 有个洞：LayerNorm / Dropout / 残差的激活值【没被切】，
   每张 TP 卡都存一份完整的 —— ✅ Megatron-3 论文点名了这件事
   → 08 章的序列并行 SP 专门来补这个洞
```
