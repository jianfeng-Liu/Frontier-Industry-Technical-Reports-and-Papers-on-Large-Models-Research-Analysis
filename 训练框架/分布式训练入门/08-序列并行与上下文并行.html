8.1 TP 漏掉了什么

回忆 06 章：TP 把注意力和 MLP 的矩阵切开了。但一个 Transformer 层不只有矩阵：

    一个 Transformer 层的完整流程（Pre-Norm）：

        X ──► LayerNorm ──► Attention ──► Dropout ──► (+X) ──►
              ▲▲▲▲▲▲▲▲▲     ✅ TP 切了     ▲▲▲▲▲▲▲    ▲▲▲▲
              ❌ 没切                       ❌ 没切     ❌ 没切
          ──► LayerNorm ──► MLP ────────► Dropout ──► (+) ──► 输出
              ❌ 没切        ✅ TP 切了      ❌ 没切     ❌ 没切

    ★ 为什么没切：LayerNorm 要对【整个 hidden 维】求均值和方差，
      每张卡只有 1/t 的维度就算不出来
      → 所以 TP 的做法是：在这些地方【每张卡都存一份完整的】激活

✅ 这不是我的推断，是 Megatron-3 论文（papers/Megatron-3-...-arXiv-2205.05198.pdf）自己承认的：
"In this approach, there are parts of the transformer where activations are not split across tensor parallel ranks, adding to activation memory overhead."

    ★ 后果：t 张卡各存一份【一模一样】的 LayerNorm/Dropout/残差激活
    → 这部分显存【完全不随 t 减少】
    → t 开得越大，浪费的比例越高

8.2 ★ Megatron 的序列并行 SP：在没切的地方，按序列切

📌 SP = Sequence Parallel，序列并行。注意：本节讲的是 Megatron 语境下的 SP，和 §8.5 的 CP 是两码事（§8.4 会说清）。

8.2.1 先把"漏掉的那部分"精确到每一个张量

§8.1 说"LayerNorm/Dropout 没被切"还是太笼统。论文 §4.1 把一层里每一个需要存下来给反向用的张量都点了名，我们把它们按"TP 切不切得动"分成两堆：

存下来的是哪个张量 大小（字节） TP 切得动吗 原因
LayerNorm ① 的输入 2sbh ❌ 每卡一份 LayerNorm 沿 h 求均值/方差，h 不能切
QKV 三个矩阵乘的共享输入 2sbh ❌ 每卡一份 列并行（06 章）的输入必须是完整的 h
Q、K（留给 QKᵀ 用） 4sbh ✅ ÷t 按注意力头切了
softmax 输出 2as²b ✅ ÷t 按头切了
softmax 后的 dropout 掩码 as²b ✅ ÷t 按头切了
V + softmax-dropout 输出 2as²b + 2sbh ✅ ÷t 按头切了
注意力输出 linear 的输入 2sbh ✅ ÷t 行并行，输入本来就是按 h 切开的
注意力后的 dropout 掩码 sbh ❌ 每卡一份 此刻已 all-reduce 回完整 h
LayerNorm ② 的输入 2sbh ❌ 每卡一份 同 ①
MLP 第一层 h→4h 的输入 2sbh ❌ 每卡一份 列并行，输入必须完整
GeLU 输入 + MLP 第二层 4h→h 的输入 8sbh + 8sbh ✅ ÷t 中间维 4h 被切了
MLP 后的 dropout 掩码 sbh ❌ 每卡一份 同上 
    把两堆分别加起来：

    ❌ 切不动的： 2+2+1+2+2+1 = ★★ 10 sbh ★★   ← t 张卡各存一份【完全一样】的
    ✅ 切得动的： 4+2+2+8+8   =    24 sbh  +  5as²b

    → ✅ 这正好就是论文式 2：

           TP 之后每层激活 = sbh( 10 + 24/t + 5as/(ht) )

    ✅ 论文原话："Quantitatively, the 10sbh part of Equation 2 is due to
       these replicated operations and as a result they are not divided by
       the tensor parallel size t."

⚠️ 归属说明：上面这张【逐张量】的表，论文没有直接列出来。但表里每一项的大小都是 ✅ 论文 §4.1 逐条写明的，"哪些不被切"也是 ✅ 论文明说的（"the input activations to these blocks (for example input to the Q,K, and V matrix multiplies or input to the h→4h linear layer) are not parallelized"）。这张表是我把两处对齐后拼出来的，两边加总都能对上 10 / 24 / 34，可以放心用。

📌 顺带修正一个常见说法：很多博客说"残差加法也占了没切的显存"——其实残差相加不需要存任何东西（它的反向就是把梯度原样传给两条支路）。真正占那 10sbh 的是 2 个 LayerNorm 的输入 + 2 个模块的输入 + 2 个 dropout 掩码。

8.2.3 核心想法：换一个维度切

    激活张量的形状是 [s, b, h]（序列长 × batch × hidden）

    TP 切的是 h 这一维  →  但 LayerNorm 沿 h 求统计量，所以 h 不能切
    ★ 那就换一维切：切 s ！

    LayerNorm 是【逐 token 独立】的：
        第 5 个 token 的 LayerNorm 结果，
        ★ 只用到第 5 个 token 自己的 h 维，和别的 token 完全无关
    → ★★ 沿 s 切开，各算各的，数学上完全等价 ★★

    Dropout、残差加法同理，都是逐元素/逐 token 的操作。

把 [s, b, h] 想象成一张表格（先忽略 batch 维）：行 = token，列 = hidden 的每一维。两种并行就是这张表的两种切法：

                    【TP 切法】按列切              【SP 切法】按行切
                  每卡拿到 全部token × 1/t 的列    每卡拿到 1/t 的token × 全部列

    token 1  ┐    ┌────┬────┬────┬────┐        ┌───────────────────┐ ┐
    token 2  │    │卡0 │卡1 │卡2 │卡3 │        │       卡 0        │ ┘ 卡0
    token 3  │    │    │    │    │    │        ├───────────────────┤ ┐
    token 4  │ →  │    │    │    │    │   或   │       卡 1        │ ┘ 卡1
    token 5  │    │    │    │    │    │        ├───────────────────┤ ┐
    token 6  │    │    │    │    │    │        │       卡 2        │ ┘ 卡2
    token 7  │    │    │    │    │    │        ├───────────────────┤ ┐
    token 8  ┘    └────┴────┴────┴────┘        │       卡 3        │ ┘ 卡3
                                                └───────────────────┘

    ★★ 两种切法是【正交】的：同一个张量，一个横着切一个竖着切。
       Megatron SP 干的事，就是让张量在一层里【在这两种切法之间来回切换】：
         矩阵乘的地方用竖切（TP），非矩阵的地方用横切（SP）。

参数：t = 8（8 路 TP+SP）、s = 4096、b = 1、h = 8192、a = 64 个头，BF16。

8.2.5 为什么换切法非得是 all-gather / reduce-scatter

这是最容易一带而过、但其实最该讲清的一步。

    【SP → TP】为什么要 all-gather？

    ⚠️ 一个容易踩的直觉误区：
       "SP 区域里每张卡都有完整的 h 维啊，那直接做矩阵乘不就行了？"

    ★ 不行。因为 TP 的列并行是"每张卡只有权重 A 的 1/t 列"：
       卡 i 手里只有 A^c_i。它拿自己那 512 个 token 去乘 A^c_i，
       只能算出【自己那 512 个 token × 自己那 1/8 的输出维】。

       但下一步的行并行 B^r_i 需要的是
       【全部 4096 个 token × 自己那 1/8 的输出维】。

    → ★★ 所以必须先把 token 补齐：沿 s 做 all-gather。★★
       换句话说：TP 要求"每卡处理【所有 token】的【一部分维度】"，
                 SP 给的是"每卡持有【一部分 token】的【所有维度】"，
                 补齐 token 就是 all-gather。

    【TP → SP】为什么是 reduce-scatter 而不是 scatter？

    行并行算完，卡 i 手里是 W_i，形状 [4096,1,8192]，
    ★ 但它是【部分和】：真正的答案 W = W_0 + W_1 + ... + W_7

    纯 TP 的做法：all-reduce 把 8 份加起来 → 每卡都拿到完整的 W（67.1 MB）

    TP+SP 的做法：我根本不需要完整的 W，
                 ★ 我只需要【我负责的那 512 个 token 那部分的正确答案】
    → 加起来（reduce）+ 只留我那份（scatter）= ★ reduce-scatter，一步到位

✅ Megatron-3 论文原文（MLP 部分的推导，本章最关键的引用之一）：
"The linear layer with GeLU non-linearity requires the entire input Y and therefore we need to perform an all-gather. ... These two tensors are not parallel anymore and need to be summed as W = W₁ + W₂ before they are fed into the dropout layer. However, dropout needs its input to be parallel in the sequence dimension s. Instead of summing and then parallelizing in the sequence dimension, we combine these two operations into a reduce-scatter operation."

四个算子的对照表（f / f̄ 是纯 TP 的，g / ḡ 是 TP+SP 的）：

算子 前向 反向 出现在哪
f 无操作 all-reduce 纯 TP，进入 TP 区域时
f̄ all-reduce 无操作 纯 TP，离开 TP 区域时
g all-gather（沿 s） reduce-scatter TP+SP，SP→TP（上表第 3、10 步）
ḡ reduce-scatter（沿 s） all-gather TP+SP，TP→SP（上表第 7、13 步）

✅ 论文原话："g and ḡ are conjugate of each other. g is an all-gather in the forward pass and a reduce-scatter in the backward pass, and ḡ is a reduce-scatter in the forward pass and an all-gather in the backward pass."

📌 "共轭（conjugate）" 就是"前向做 A、反向做 A 的逆操作"的意思。all-gather 的反向天然就是 reduce-scatter：前向把碎片拼全，反向就要把梯度加起来再切碎还回去。

8.2.6 换切法要通信，但是【免费的】

    数一数一层里的通信次数：

    纯 TP：       前向 2 次 all-reduce（注意力后 f̄、MLP 后 f̄）
                  反向 2 次 all-reduce（两个 f）
                  ────────────────────────────
                  ★ 一层 fwd+bwd = 4 次 all-reduce

    TP + SP：     前向 2 次 all-gather（两个 g）+ 2 次 reduce-scatter（两个 ḡ）
                  反向 2 次 reduce-scatter（g 的反向）+ 2 次 all-gather（ḡ 的反向）
                  ────────────────────────────
                  ★ 一层 fwd+bwd = 4 次 all-gather + 4 次 reduce-scatter

    ⚠️ 乍一看：8 次 > 4 次，好像变贵了一倍！

    ★★★ 这就是 [03 章 §3.3](03-通信原语.md) 那个恒等式的价值兑现时刻 ★★★

        Ring All-Reduce  =  Reduce-Scatter  +  All-Gather

    → 一次 all-reduce 本来【内部就是】一次 RS + 一次 AG。
      TP+SP 只是把这两个阶段【拆开、中间插进了有用的计算】而已。
      ★ 次数翻倍了，但每次只有原来的一半 → 总字节数完全相同。

具体算一遍字节数（还是 t=8, s=4096, b=1, h=8192，被通信的张量是 [s,b,h] = 67.1 MB）：

    用 03 章 §3.3 的环形通信量公式，每张卡实际收发的字节：

        Ring All-Reduce      : 2 × (t−1)/t × 67.1 MB = 2 × 7/8 × 67.1 = 117.4 MB
        Ring Reduce-Scatter  : 1 × (t−1)/t × 67.1 MB =     7/8 × 67.1 =  58.7 MB
        Ring All-Gather      : 1 × (t−1)/t × 67.1 MB =     7/8 × 67.1 =  58.7 MB
                                                                        ───────
                                                    RS + AG          =  117.4 MB
                                                                     ★ 完全相等 ★

    ┌────────────────────────────────────────────────────────────┐
    │  一层（前向+反向）每张卡的通信总量                            │
    │                                                            │
    │   纯 TP  ：4 × 117.4 MB                        = 469.8 MB  │
    │   TP+SP ：4 × 58.7 MB (AG) + 4 × 58.7 MB (RS) = 469.8 MB  │
    │                                          ★★ 一个字节不多 ★★ │
    └────────────────────────────────────────────────────────────┘

    → 而换来的是：每层激活从 1.11 GB 降到 0.81 GB（见 §8.3）
    → ★ 白捡的显存节省。这在分布式训练里是极其罕见的"没有代价"。

    ⚠️ 严格说还有一笔小账没算进上面这张表：反向为了张量 Y 还要多做
       2 次 all-gather（§8.2.7）。论文因为"可以重叠掉"没把它计入对比，
       但字节确实是多花了 —— 完整的账在 §8.2.8。

✅ Megatron-3 原文：
"Tensor parallelism requires four all-reduces in a single forward and backward pass whereas tensor together with sequence parallelism requires four all-gathers and four reduce-scatters in a single forward and backward pass. At the first look, it seems that tensor with sequence parallelism requires more communications... However, we note that a ring all-reduce is composed of two steps: a reduce-scatter followed by an all-gather. As a result, the communication bandwidth used for tensor parallelism and tensor together with sequence parallelism are the same. Therefore, sequence parallelism does not introduce any communication overhead."

📌 顺带印证了 06 章 §6.4 说的"一层 4 次 all-reduce"——✅ 论文原话就是 "four all-reduces in a single forward and backward pass"。

⚠️ 一个数字上的对账：06 章为了简化，是按"张量本身多大"来估通信量的（67 MB × 4 × 80 层 ≈ 21 GB）。这里因为要精确比较 all-reduce 和 RS+AG，必须用环形算法的真实每卡收发量 2(t−1)/t × 张量大小，所以数字会比 06 章大约 1.75 倍。两者不矛盾，只是精度不同。

8.2.7 唯一的小代价：那个叫 Y 的张量

回到 §8.2.4 的表：第 3 步和第 10 步 all-gather 出来的那个完整张量（论文里叫 Y，就是 LayerNorm 的输出、也是列并行 linear 的输入），有个麻烦：

    ★ 反向传播算【权重 A 的梯度】时，公式是  dA = Yᵀ · dZ
      → 必须要有完整的 Y（全部 4096 个 token）

    ⚠️ 如果老老实实把它存下来：67.1 MB/卡 —— 这一项就没被 ÷t，
       "整除以 t"的漂亮结论就破了。

    ★ Megatron 的做法：只存自己那片 Y^s_i（[512,1,8192] = 8.4 MB），
      反向时【临时再 all-gather 一次】把 Y 拼回来。
      → 用一次额外通信，换回 67.1 → 8.4 MB 的显存
      → 而这次额外通信可以和"算 Y 的梯度"这个计算【重叠】掉（03 章 §3.4）

✅ 论文原文："sequence parallelism along with tensor parallelism divides all the activations required for the backward pass along the parallel dimension except for the tensor Y that is required for the first linear operation. To alleviate this issue, we do not store the full tensor Y... Instead, we store only the Yᵢˢ part on the i-th tensor parallel rank and perform an extra all-gather in the backward pass. To eliminate the latency introduced by this extra all-gather, we overlap this communication with the computation."

📌 串起来看：这个 Y，正是 §8.2.1 表里那两行 ❌「QKV 三个矩阵乘的共享输入 2sbh」和「MLP 第一层 h→4h 的输入 2sbh」。它们本来是"切不动"的 10sbh 里最硬的一块骨头，是靠"不存 + 反向重新 all-gather"这个技巧才被啃下来的。

⚠️ 论文是以 MLP 那一侧为例推导的，注意力那一侧同理——所以一层里其实有两个这样的 Y。

8.2.8 ★ 把这笔"额外 all-gather"的账算到底

上一节说"多一次额外通信"，但一层里到底多几次？多花多少字节？前向也多吗？ 论文没展开，这里补齐——结论先放上：

    ★★ 每层【反向】多 2 次 all-gather，【前向】一次都不多 ★★

    → 不是"每层多 1 次"（论文只举了 MLP 那一侧）
    → 也不是"前向反向各多"（前向根本不需要 Y 的梯度）
    → 一层反向的 all-gather 从 2 次变成 4 次

一层的完整通信账本（术语回顾：AG = all-gather 全收集，每卡把自己那片发出去、凑齐完整张量；RS = reduce-scatter 规约散射，先求和再按维度切开、每卡只拿走自己那片）：

位置 前向 反向（共轭算子） 反向额外
注意力入口：LN 输出 → QKV 列并行 linear AG（g） RS ★ AG（重拼 Y）
注意力出口：行并行 proj RS（ḡ） AG —
MLP 入口：LN 输出 → h→4h 列并行 linear AG（g） RS ★ AG（重拼 Y）
MLP 出口：行并行 4h→h RS（ḡ） AG —
小计 2 AG + 2 RS 2 AG + 2 RS +2 AG

★ 为什么恰好是 2 次，不是 4 次？ 关键在列并行和行并行的输入形状不一样：

    列并行 linear（QKV、h→4h）：
        输入 = LayerNorm 的输出，被 SP 沿【序列维】切了 → 每卡只有 [s/t, b, h]
        反向 dA = Yᵀ·dZ 要完整的 Y  → ★ 必须 all-gather ← 额外通信在这

    行并行 linear（proj、4h→h）：
        输入 = 上一层的输出，被 TP 沿【隐藏维】切了 → 每卡有 [s, b, 4h/t]
        这一片【本来就是完整的自己那份】，序列维一个 token 都没少
        反向算自己那块 A_i 的梯度只用这一片 → ✅ 不需要任何 gather

    → 一层里只有 2 个列并行 linear（QKV、fc1）→ 只有 2 个 Y → 只有 2 次额外 AG

多花多少字节（沿用 §8.2.6 的 t=8, s=4096, b=1, h=8192，一次 AG/RS 每卡收发 58.7 MB）：

    ┌──────────────────────────────────────────────────────────────┐
    │  一层（前向+反向）每张卡的通信总量 —— 补上额外 AG 之后         │
    │                                                              │
    │   纯 TP        ：4 × 117.4                        = 469.8 MB │
    │   TP+SP（基线）：4 × 58.7 (AG) + 4 × 58.7 (RS)   = 469.8 MB │
    │   TP+SP（实际）：469.8 + 2 × 58.7（额外 AG）     = 587.2 MB │
    │                                                              │
    │                              ★ 比纯 TP 多 25%（不是 0）★     │
    └──────────────────────────────────────────────────────────────┘

    ⚠️ 那论文说的"no communication overhead"错了吗？没错，它说的是
       【带宽/字节】口径下 4×AR 与 4×AG+4×RS 相等这件事（§8.2.6），
       额外那 2 次 AG 论文是单独承认的，理由是【延迟被重叠掉】：

           发出异步 all-gather（不阻塞）
                ↓  同时在 GPU 上跑
           grad_input = dZ · Aᵀ        ← 一个大矩阵乘，几百微秒
                ↓
           handle.wait()               ← 通信早就跑完了
                ↓
           dA = Yᵀ · dZ                ← 这时才真正用到拼好的 Y

    → ★ 所以准确的说法是：【字节 +25%，但墙上时间 ≈ +0】
      前提是通信和计算真的能并行（见下面的 CUDA_DEVICE_MAX_CONNECTIONS）

✅ 源码对照（layers.py，LinearWithGradAccumulationAndAsyncCommunication）：

# ── 前向：存的是 all-gather【之前】的分片，正是论文说的"只存 Yᵢˢ" ──
ctx.save_for_backward(input, weight)      # input = [s/t, b, h]  ← 8.4 MB
if sequence_parallel:
    dist_all_gather_func(all_gather_buffer, input, group=tp_group)
    total_input = all_gather_buffer       # 临时 buffer，用完即弃，不进 ctx

# ── 反向：为了 wgrad 重新 all-gather，异步发出 ──
if wgrad_compute:                         # ★ 门控：只有要算 dA 时才 gather
    if ctx.sequence_parallel:
        handle = dist_all_gather_func(..., async_op=True)   # ← 那次额外通信
        total_input = all_gather_buffer

grad_input = grad_output.matmul(weight)   # ← dY = dZ·Aᵀ，通信在这底下跑（重叠）

if ctx.sequence_parallel and wgrad_compute:
    handle.wait()                         # ← 算完 dY 才等 gather 落地

📌 if wgrad_compute: 这个门控是最好的佐证：这次 all-gather 唯一的存在理由就是 dA = Yᵀ·dZ，和 dY = dZ·Aᵀ 那条链路毫无关系——所以它才能安全地和 dY 的计算重叠。

⚠️ 重叠不是自动的：源码注释里明确写了依赖环境变量 CUDA_DEVICE_MAX_CONNECTIONS=1（限制 GPU 上的硬件工作队列只有一条），才能保证通信 kernel 被排在计算 kernel【之前】下发出去、真正跑起来。这也是 Megatron 启动脚本里几乎必设这个变量的原因之一——设错了，这 25% 就从"藏起来的"变成"实打实的延迟"。

⚠️ 两个边界情况（源码可见、论文未展开）：
- 开了完整重计算 --recompute-granularity full 时，反向本来就要重跑一遍前向，这次 AG 变成重计算的一部分，不再是"额外"的。
- 走延迟 wgrad 路径（grad_output_buffer 缓冲、wgrad_deferral_limit）时 wgrad_compute=False，此处不发 AG，推迟到真正算权重梯度时再发。

8.4 ★★ 最容易搞混的一点：SP 和 CP 不是一回事

这是本章最重要的一节。

    两个名字里都有"序列"，切的也都是序列维度，但★解决的是完全不同的问题★：

┌─────────────────────────────────────────────────────────────────┐
│  ① Megatron 的 SP（Sequence Parallel，本章 §8.2）                │
│                                                                 │
│     ★ 是 TP 的【附属品】，并行度【必须等于 t】，不是独立旋钮       │
│     ★ 只在 LayerNorm/Dropout/残差 这些【非矩阵】区域生效          │
│     ★ 注意力计算【完全不受影响】——进注意力前会 all-gather 回完整序列│
│     ★ 目的：补 TP 的漏，省激活显存                                │
│     ★ 因为要 all-gather 回完整序列，所以 ❌【解决不了序列本身太长】  │
│                                                                 │
│     Megatron 参数：--sequence-parallel（一个开关，没有度数）      │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  ② CP（Context Parallel，上下文并行，§8.5）                      │
│                                                                 │
│     ★ 是【独立的一维并行】，有自己的度数 cp                        │
│     ★ 全程都切着，★★ 包括注意力计算本身 ★★                       │
│     ★ 目的：让【单条序列】能超过单卡容纳的长度（1M token 那种）    │
│     ★ 难点：注意力天生要"每个 token 看到所有 token" → 必须专门设计  │
│                                                                 │
│     Megatron 参数：--context-parallel-size N                    │
└─────────────────────────────────────────────────────────────────┘

    ★ 一句话记住区别：

      SP：注意力照常算（进去前拼回完整序列），只是【前后的边角料】切了
      CP：注意力★本身★就是切着算的 —— 这才是真正的难点

    ★ 落到 §8.2.4 那张表上，区别就是【第 4~6 步】：
        SP：第 3 步 all-gather 之后，第 4~6 步拿到的是【完整的 4096 个 token】
            → 注意力和单卡时一模一样，代码都不用改
            → ❌ 所以 s 大到单卡放不下时，SP 一样死在第 3 步
        CP：第 4~6 步每张卡手里【始终只有 512 个 token 的 Q】，
            KV 靠环形传递或 all-to-all 补 → ★ 注意力算子本身要重写

    ⚠️ 更混乱的是：DeepSpeed 把它的 CP 类方案【也叫 "sequence parallelism"】
       （Ulysses 论文全篇用的都是 "sequence parallelism" 这个词）。
       ★ 所以读论文时，要看它切的是不是【注意力内部】来判断到底是哪一种。

8.5 CP：让注意力也切着算

📌 CP = Context Parallel，上下文并行。也有论文叫它 sequence parallelism（见 §8.4 的警告）。

本节的记号约定（和 §8.2.4 保持一致，方便对照）：
s = 序列长度、b = micro-batch、h = hidden 维、a = 注意力头数、d = h/a = 每个头的维度、cp = CP 并行度。
贯穿全节的算例：cp = 4、s = 32768（32K）、b = 1、h = 8192、a = 64 个头（d = 128）、BF16（每个数 2 字节）。
于是每张卡分到 s/cp = 8192 个 token。

8.5.1 为什么需要

✅ Ring Attention 论文（papers/Ring-Attention-arXiv-2310.01889.pdf）给的场景：
"The memory demands imposed by Transformers limit their ability to handle long sequences, thereby posing challenges in utilizing videos, actions, and other long-form sequences."

⚠️ 一个量级感：注意力分数矩阵是 [b, a, s, s]，s 翻倍，它翻 4 倍。s = 1M 时这个矩阵光是一个头就有 10¹² 个元素——任何单卡都放不下。

✅ 论文自己算的一笔账（注意它算的不是注意力矩阵，而是每层输出这种"绕不过去的"激活）：
"processing 100 million tokens with a batch size of 1 requires over 1000GB of memory even for a modest model with a hidden size of 1024. In contrast, modern GPUs and TPUs typically provide less than 100GB of high-bandwidth memory (HBM)."

📌 注意这里的因果链：11 章的 FlashAttention 已经把那个 [s,s] 矩阵消掉了（不 materialize），但每层的输出 [s, b, h] 是消不掉的——下一层的注意力要用到上一层所有 token 的输出。所以 s 长到一定程度，光靠单卡优化已经无解，必须把序列摊到多张卡上。这就是 CP 存在的理由。

8.5.2 难在哪：注意力是"全对全"的依赖

    把 32K 序列切成 4 段放 4 张卡（因果注意力，即每个 token 只看它自己和之前的）：

        卡0: token 0~8191    卡1: 8192~16383   卡2: 16384~24575   卡3: 24576~32767

    ★ 逐 token 独立的算子（LayerNorm、GeLU、Dropout、残差、MLP）
      → 每张卡拿自己那 8192 个 token 算就行，★ 完全不需要通信 ★
      → 这部分 CP 和 SP 一样容易

    ★★ 但注意力不是逐 token 独立的 ★★
        卡3 上的 token 30000 要 attend 到卡0 上的 token 100
        → 卡3 必须拿到卡0 的 K 和 V
        → ★★ 数据必须在卡之间流动，绕不过去 ★★

    ⚠️ 注意：需要跨卡的只有 K 和 V，★ Q 不需要 ★
       因为注意力的输出形状是跟着 Q 走的：Q 有多少个 token，输出就有多少个 token。
       每张卡只负责算"自己那 8192 个 token 的输出"，所以它的 Q 一直待在本地。
       → ★ 这个不对称性，是理解下面两种方案的钥匙。

    ★★★ 两种让数据流动的方式，就是两种 CP 方案：★★★

      A. Ring Attention：Q 不动，★ 让 KV 沿着一个环走一圈 ★
                         → 用 P2P（点对点）通信，通信和计算重叠

      B. Ulysses：      不搬 KV，★ 干脆把"切序列"临时换成"切头" ★
                         → 用 all-to-all（全交换）通信，换完每张卡自给自足

8.5.3 先补一块积木：softmax 为什么能分块算

这是 Ring Attention 的数学地基。不搞懂这一步，"KV 转圈"看起来就像是在耍赖。

    ⚠️ 先看清楚问题在哪：

      softmax(x)_i = e^{x_i} / Σ_j e^{x_j}
                                 ▲▲▲▲▲▲
                          ★ 分母要【所有】分数都到齐才算得出来

    → 卡3 第一轮只拿到了卡3 自己的 KV，它算出的分数只是全部分数的 1/4
    → 分母是错的 → 得到的注意力权重是错的
    ⚠️ 那"先各算各的、最后加起来"显然不行 —— 加权平均的权重都不对，加起来也没意义

解法叫 online softmax（在线 softmax）：不存权重，存两个"修正用的统计量"，等新块来了再回头把旧结果按比例改一改。

    ★ 每张卡为它的 Q 块维护三样东西（每一行 Q 各一份）：

        m  = 到目前为止见过的【最大分数】       ← 防指数爆炸用的
        l  = 到目前为止的【分母累加值】
        Õ  = 到目前为止的【未归一化输出】       （Õ 读作 "O tilde"）

    ★ 来了一个新的 KV 块，做四件事：

        ① 算这一块的局部分数 S = QKᵀ/√d，取局部最大 m_new
        ② l_new = Σ e^{S - m_new}            （这一块自己的分母）
           Õ_new = e^{S - m_new} · V         （这一块自己的未归一化输出）
        ③ ★ 合并：取 m* = max(m, m_new)，把新旧两边都缩放到同一个基准上
              l  ← e^{m - m*}·l  +  e^{m_new - m*}·l_new
              Õ  ← e^{m - m*}·Õ  +  e^{m_new - m*}·Õ_new
              m  ← m*
        ④ 所有块都过完之后：O = Õ / l          ← ★ 到最后一刻才做除法

    ★★ 关键在第 ③ 步那两个 e^{m - m*}：它就是"回头把旧结果改一改"的动作 ★★

用一个能手算的例子验一遍（为了能手算，取 d = 1、一行 Q、两个 KV 块）：

    块1： 分数 S₁ = [1, 3]     值 V₁ = [10, 20]
    块2： 分数 S₂ = [2, 5]     值 V₂ = [30, 40]

    ── 一次性算（标准答案）───────────────────────────────
      e¹=2.718  e³=20.086  e²=7.389  e⁵=148.413   分母 = 178.606
      权重 = [0.0152, 0.1125, 0.0414, 0.8310]
      O = 0.0152×10 + 0.1125×20 + 0.0414×30 + 0.8310×40 = 36.8806

    ── 分块算 ──────────────────────────────────────────
      块1： m=3   l = e⁻²+e⁰ = 1.1353    Õ = 0.1353×10 + 1×20 = 21.3534
      块2： m=5   l = e⁻³+e⁰ = 1.0498    Õ = 0.0498×30 + 1×40 = 41.4936

      合并（m* = max(3,5) = 5，旧的那份要乘 e^{3-5} = 0.1353）：
        l = 0.1353 × 1.1353 + 1 × 1.0498 = 1.2034
        Õ = 0.1353 × 21.3534 + 1 × 41.4936 = 44.3835

      O = 44.3835 / 1.2034 = ★ 36.8806 ★   ←── 和标准答案【逐位相同】

    ★★★ 三个必须记住的结论 ★★★

    ① 这是【精确】的，不是近似。分块 softmax 和一次性 softmax 的结果按位相同。
       （浮点舍入会有微小差异，但这和"近似算法"是两回事。）

    ② 块的【顺序无所谓】。先算块2 再算块1，结果一样。
       ✅ 论文管这叫 permutation invariance（置换不变性）：
          "the self-attention between a query block and a group of key-value blocks
           can be computed in any order, as long as the statistics of each block
           are combined correctly for rescaling"
       ★★ 正因为顺序无所谓，KV 才可以"随便按什么顺序转到你这里" ★★

    ③ 每张卡要额外存的只有 (m, l)：每行 Q 两个标量。
       s/cp = 8192 行 × 2 个数 —— 相比 134 MB 的 KV 块，可以忽略不计。

📌 这和 11 章 §11.5 的 FlashAttention 是【同一个技巧】：FlashAttention 用它在一张卡内部分块（在 SRAM 和 HBM 之间），Ring Attention 用它在多张卡之间分块。
★ 一句话概括两者的关系：Ring Attention = FlashAttention 的外层循环被拆到了多张卡上。

8.5.4 ★★ 方案 A：Ring Attention —— 让 KV 转圈

一句话

    ★ Q 不动（每张卡永远只算自己那 8192 个 token 的输出），
      让 K、V 沿着一个环【一站一站传下去】，
      每转到一站就用 §8.5.3 的公式把结果【累加修正】一次，
      转满 cp 轮，每张卡就见过了全世界的 KV。

跟着 4 张卡走完一次前向

环的方向约定：卡 i 把自己手里的 KV 发给卡 (i+1) mod 4，同时从卡 (i−1) mod 4 收。

轮次 卡0 用谁的 KV 卡1 卡2 卡3 同时在传的是
第 1 轮 KV₀（自己的） KV₁ KV₂ KV₃ 把手里的 KV 发给下家
第 2 轮 KV₃ KV₀ KV₁ KV₂ 继续往下家传
第 3 轮 KV₂ KV₃ KV₀ KV₁ 继续
第 4 轮 KV₁ KV₂ KV₃ KV₀ 传完，不用再发了 
    ★ 竖着看每一列：卡 i 依次见到了 KV_i, KV_{i-1}, ..., 全部 4 块 ✓
    ★ 横着看每一行：任一时刻，4 块 KV 分散在 4 张卡上，★ 没有任何一张卡持有全部 KV ★
      → 这正是省显存的地方

    ★ 一共 cp 步计算 + (cp − 1) 次传递。

📌 ⚠️ 论文的伪代码（Algorithm 1）把"算"和"传"写在同一个循环里、循环 Nh − 1 次，读起来像是少了一轮；实际实现里最后一轮只算不传。这是伪代码的简写，不影响理解。

每一轮里，一张卡具体在干什么

    ★★ 关键是【三件事同时发生】★★

    卡 i 在第 k 轮：

      ┌─ ① 计算（占满 SM）：
      │     用本地 Q_i 和手里这块 KV_j，跑一次 FlashAttention
      │     → 得到这一块的 (m_new, l_new, Õ_new)
      │     → 用 §8.5.3 第 ③ 步合并进本地的 (m, l, Õ)
      │
      ├─ ② 发送（占通信引擎，不占 SM）：
      │     isend(KV_j) → 卡 (i+1)          ← ★ 非阻塞
      │
      └─ ③ 接收（占通信引擎，不占 SM）：
            irecv(KV_{j-1}) ← 卡 (i-1)      ← ★ 非阻塞，收进另一块缓冲区

    ★ 这一轮结束时才 wait 一次，确认 ②③ 完成，然后把缓冲区一换，进入下一轮。

    ★★★ 所以只要 ①的时间 ≥ ②③的时间，通信就完全被算掩盖住了 ★★★
    → 这是 [03 章 §3.4](03-通信原语.md) 那个"能不能和计算重叠"在 CP 上的具体兑现。

✅ 论文原文：
"each host efficiently coordinates by concurrently sending key-value blocks being used for attention computation to the next host while receiving key-value blocks from the preceding host, effectively overlapping transferring of blocks with blockwise computation."
"If the computation time exceeds the time required for transferring key-value blocks, this results in no additional communication cost."
"Our approach enables training and inference of sequences that are up to device count times longer than those achievable by prior memory-efficient Transformers, without resorting to approximations or incurring additional communication and computation overheads."

★ "只要计算 ≥ 通信" 这个条件，到底苛刻不苛刻

这是 Ring Attention 最实用的一段，论文把它推成了一个只有两个变量的不等式。

    设：每张卡算力 F（FLOPS），卡间单向带宽 B（字节/秒），块大小 c（token 数），头维 d。

    ★ 一轮的计算量：QKᵀ 要 2dc²，(权重)·V 再要 2dc²  →  合计 4dc² FLOPs
    ★ 一轮的通信量：K 块 + V 块  →  合计 4cd 字节

    重叠条件：   4dc² / F   ≥   4cd / B
                ▲▲▲▲▲▲▲       ▲▲▲▲▲▲
                 算的时间       传的时间

    ★★★ 两边约掉 4cd，得到：   c ≥ F / B   ★★★

    → 每张卡上的序列长度只要【大于算力带宽比】，通信就是免费的。
    → ★ 注意 c 是【平方】增长的计算 vs 【线性】增长的通信 —— 序列越长，越容易藏住。

✅ 论文原文："To achieve an overlap between communication and computation, the following condition must hold: 4dc²/F ≥ 4cd/B. This implies that the block size, denoted as c, should be greater than or equal to F/B. Effectively, this means that the block size needs to be larger than the ratio of FLOPs over bandwidth."

反向传播怎么办

    ★ 反向要算三个梯度：dQ、dK、dV。

      dQ_i 只跟【卡 i 自己的 Q】有关  → ★ 留在本地累加，好办
      dK_j / dV_j 属于【KV 块的原主人卡 j】
        → ⚠️ 但计算它的是【正在用这块 KV 的那张卡】，不是卡 j
        → ★ 所以 dK/dV 也得跟着 KV 一起在环上转，边转边累加，最后回到原主人手里

    ★ 实现上就是：反向再转一圈，这一圈传的是 (K, V, dK, dV) 四样东西
      → ⚠️ 反向的单轮通信量约是前向的【2 倍】
      → 但反向的计算量也大约是前向的 2 倍，所以重叠条件 c ≥ F/B 大体仍然成立

✅ 论文只用一句话带过："This overlapping mechanism applies to both forward and backward passes of our approach since the same operations and techniques can be used."

⚠️ 上面那段"传四样东西 / 通信量翻倍"是我根据反向传播的依赖关系推出来的，论文没有展开写。各家实现（Megatron 的 ring_exchange、flash-attn 的 ring_flash_attn）在这一步的细节不完全一样。

⚠️ 最大的工程坑：因果掩码让负载严重不均

⚠️ 论文全文没有讨论这个问题（它的实验用的是完整注意力的分析），但这是任何真实实现都必须处理的头号问题。

    ★ 因果注意力：token 只能看到自己和之前的 token。
      → 卡 i 的 Q 块，只需要 KV 块 0 ~ i，★ 后面的全被 mask 掉，算了也白算 ★

    ── 朴素切法（卡 i 拿第 i 段连续序列）的真实工作量 ──

        卡0（最早的 token）: 只需要 KV₀            → 1 块的活
        卡1:                需要 KV₀, KV₁          → 2 块
        卡2:                需要 KV₀, KV₁, KV₂     → 3 块
        卡3（最晚的 token）: 需要全部 4 块         → 4 块  ← ★ 最忙

    ⚠️ 但环是【同步】的：每一轮所有卡一起走，一轮的耗时由最忙的那张卡决定。
       总工作量 = 1+2+3+4 = 10 块
       实际耗时 ≈ 4 轮 × 每轮满负载 = 16 块的时间
       → ★ 利用率只有 10/16 = 62.5%，cp 越大越糟（一般是 (cp+1)/(2cp) → 趋近 50%）

    ★★★ 修法：把序列切成 2·cp 块，每张卡拿【一头一尾】两块 ★★★

    cp = 4 → 切成 8 块，卡 i 拿第 i 块和第 (2·cp − 1 − i) 块：

        卡0 ← 块0 + 块7        卡1 ← 块1 + 块6
        卡2 ← 块2 + 块5        卡3 ← 块3 + 块4

    ★ 验算每张卡的工作量（块 j 作为 query 时要看 j+1 块）：
        卡0：(0+1) + (7+1) = 9
        卡1：(1+1) + (6+1) = 9
        卡2：(2+1) + (5+1) = 9
        卡3：(3+1) + (4+1) = 9      ←── ★★ 完全相等 ★★

    ★ 一般式：(i+1) + (2·cp − i) = 2·cp + 1，★ 和 i 无关 ★ → 恒等配平

    ⚠️ 代价：token 在卡上不再连续，所以【进 CP 前要重排、出 CP 后要还原】，
       位置编码（RoPE）也必须用【原始位置】而不是卡上的局部位置。

✅ 这不是我编的，Megatron-LM 源码里就是这么写的（源码/Megatron-LM/megatron/core/utils.py，_get_batch_on_this_cp_rank_per_sequence_balancing）：

源码的注释也把这套切法直接叫 zigzag（之字形）："The sequence is split into 2 * cp_size equal chunks and assigned in a zigzag pattern: for CP=2, the 4 chunks are assigned as (chunk_0, chunk_3) -> GPU 0 and (chunk_1, chunk_2) -> GPU 1, balancing..."

⚠️ 但要分清来源：zigzag 是【框架的工程实现】，不是 Ring Attention 论文的内容——论文全文没有讨论因果掩码的负载问题。上面那个 (i+1) + (2cp−i) = 2cp+1 的配平验算是我推的，只是用来让你确信它真的均匀。

⚠️ 还有一个连带约束：序列长度必须能被 2 × cp 整除（源码里对文档长度不整除的情况另有一条分支）。

8.5.5 ★★ 方案 B：DeepSpeed-Ulysses —— 让切法换一次

一句话

    ★ 既然注意力要"每个头看完整序列"，那就【在进注意力之前把切法换掉】：

      注意力之外：每张卡持有 【1/cp 的序列】 × 【全部的头】     ← 省激活显存
      注意力之内：每张卡持有 【完整的序列】 × 【1/cp 的头】     ← 每张卡自给自足！

    ★★ 换完之后，每张卡手上是"完整序列的若干个完整头"
       → 它可以【原封不动地调用单卡 FlashAttention】，注意力算子一行都不用改 ★★

✅ 论文原文：
"DeepSpeed-Ulysses partitions individual samples along the sequence dimension among participating GPUs. Then right before the attention computation, it employs all-to-all communication collective on the partitioned queries, keys and values such that each GPU receives the full sequence but only for a non-overlapping subset of the attention heads. This allows the participating GPUs to compute attention for different attention heads in parallel. Finally, DeepSpeed-Ulysses employs another all-to-all to gather the results along the attention heads while re-partitioning along the sequence dimension."

                                        合计 4Nh
      ★★★ 每条链路：4Nh / P ★★★

✅ 论文原文："DS-Sequence performs all-to-all for the QKV projections with an aggregate message size of 3Nh before the attention computation, and another all-to-all for output context projection with a size Nh for each transformer layer. Therefore, DeepSpeed sequence parallelism incurs an aggregate communication volume per link of 4Nh/P (or with the complexity of O(N/P)). Note that this communication volume is constant when both N and P are increased proportionally."

    ★★ 和 Megatron-SP（§8.2）比一比 —— 这是论文最想说的那句话 ★★

    Megatron-SP 每层：2 次 all-gather（各 Nh）+ 2 次 reduce-scatter（各 Nh）= 4Nh
    ⚠️ 但 all-gather / reduce-scatter 的【每链路】代价，在 P 很大时仍然是 M，不是 M/P
       （直觉：all-gather 最终每张卡都要收到【全部】数据，所以它收的字节数就是 M，
         不管有多少张卡分摊——[03 章 §3.3](03-通信原语.md) 的 ring 算法也是这个结论）

      → Megatron-SP 每链路 = 4Nh        ★ 和 P 无关
      → Ulysses    每链路 = 4Nh / P     ★ 被 P 分摊
      ★★★ 差【P 倍】★★★

✅ 论文原文："the cost of each all-gather and reduce-scatter of size M remains M when P » 1, instead of M/P. Therefore, Megatron-LM sequence parallelism incurs a communication volume per link of 4Nh which is P times larger than that for DeepSpeed sequence parallelism."

⚠️ 代入本节算例（我的推算）：

    N = 32768、h = 8192、BF16 → Nh = 536.9 MB

      Ulysses     每层每链路 = 4 × 536.9 / 4 = ★ 536.9 MB ★
      Megatron-SP 每层每链路 = 4 × 536.9     = ⚠️ 2.15 GB ⚠️     ← 4 倍

    ★ 而且这个差距【随 cp 线性拉大】：cp = 8 差 8 倍，cp = 16 差 16 倍。

    ★★★ "N 和 P 同比放大时通信量恒定"是什么意思、为什么重要 ★★★

      序列 32K 用 4 卡  →  每链路 4Nh/P
      序列 64K 用 8 卡  →  N 翻倍、P 翻倍 → ★ 每链路【不变】★

    → 意味着"想训更长的序列，就多加同样比例的卡"这条路是【可以一直走下去】的。
      ✅ 论文实测：1.2B 模型一路做到 100 万 token。

✅ 论文披露的实测结果（papers/DeepSpeed-Ulysses-...-arXiv-2309.14509.pdf）：
"trains 2.5x faster with 4x longer sequence length than the existing method SOTA baseline"
"Communication reduction of over 10x compared to existing systems, resulting in throughput improvements of up to 2.5x, and sustained throughput of over 175 TFlops/GPU (over 54% of hardware peak)"、"enabling training with sequences with over a million tokens"

❌ 硬约束：并行度不能超过头数

    ★ Ulysses 是【按头切】的 → 头分完就没得切了。

      a = 64 个头，cp = 64  → 每卡 1 个头 ✓ 这是极限
      a = 64 个头，cp = 128 → ❌ 分不下去

    ⚠️ 真正卡人的是 GQA：
    📌 GQA = Grouped-Query Attention，分组查询注意力：多个 Q 头【共享】同一组 K/V 头，
       用来省推理时的 KV cache（见 [业界模型技术报告/大模型架构入门-小白向.md](../../业界模型技术报告/大模型架构入门-小白向.md)）。

      一个典型配置：64 个 Q 头，但只有 8 个 KV 头
      → K、V 只能切 8 份
      → ★ Ulysses 实际上限就是 8，再往上就得【把 KV 复制多份】，白白多花显存和通信

    ★★ 对比：Ring Attention 【没有这个上限】——它切的是序列，序列要多长有多长。
       这是两者最本质的分工来源。

⚠️ 这条约束论文没有明写，它只说了 "each GPU receives the full sequence but only for a non-overlapping subset of the attention heads"——"非重叠的头子集"隐含了"份数不能超过头数"。上面关于 GQA 的具体推论是我补的工程常识。

它不省模型状态，所以要配 ZeRO-3

    ⚠️ Ulysses（和所有 CP 一样）只切【激活】，不切【参数/梯度/优化器状态】。
       → 序列能开到 1M，但模型本身还是得放得下

    ★ DeepSpeed 的解法：让 ZeRO-3 把模型状态切在【DP 组 × CP 组】合并成的大组上
      → 相当于分母从 dp 变成了 dp × cp，模型状态切得更碎

✅ 论文原文："with sequence parallelism, training data can be considered in both batch (sample) and sequence dimensions and the associated parallel groups combined to form a larger group for ZeRO parallelism... ZeRO partitions model states across both sequence and data parallel group."

📌 ZeRO-3 是 05 章的主题：把参数、梯度、优化器状态都切开、用时再 all-gather。

8.5.7 USP：把两者乘起来

    ★ 两种方案切的是【不同的维度】（一个切序列、一个切头）
      → ★★ 它们可以【同时用】，并行度相乘 ★★

    典型摆法（2 机 × 8 卡 = 16 卡，总 CP 度 = 16）：

        ┌── 机器 A ────────────┐   ┌── 机器 B ────────────┐
        │ 卡0 卡1 ... 卡7      │   │ 卡8 卡9 ... 卡15     │
        │ ★ 机内 Ulysses = 8   │   │ ★ 机内 Ulysses = 8   │
        └──────────┬───────────┘   └──────────┬───────────┘
                   └──── ★ 机间 Ring = 2 ─────┘

    ★ 为什么这么配：
      机内 NVLink 带宽高、延迟低 → all-to-all 跑得飞快 → 用 Ulysses
      机间 IB 带宽低            → 但 P2P 能和计算重叠   → 用 Ring
      ★★ 并且绕开了 Ulysses 的头数上限：真正的 CP 度 = 8 × 2 = 16，
         而按头切的只有 8 份 ★★

    这套组合叫 USP = Unified Sequence Parallelism（统一序列并行），
    也叫 Hybrid / 2D Sequence Parallelism。

⚠️ USP 不在本章引的这两篇论文里，它是社区在两篇之上做的工程组合（yunchang、ring-flash-attention 等库）。

✅ 但"机内 a2a × 机间 p2p"这个具体配法，Megatron-LM 已经把它做成了一个官方选项——--cp-comm-type a2a+p2p。源码注释（源码/Megatron-LM/megatron/core/transformer/transformer_config.py）写得比任何二手解读都清楚：

""a2a+p2p": A hierarchical implementation of context parallelism to attention. It uses A2A communications in low-level CP groups (e.g., via NVLink), and P2P communications in high-level CP groups (e.g., via IBLink)."

★ 也就是说：上面那张图不是我画的理想方案，就是 Megatron 的实际做法。

8.6 ⚠️ CP 不是免费的

    ① 只对【长序列】有意义
       s = 4096 时开 CP 纯属浪费 —— 通信开销远大于收益
       ★ 经验：s ≥ 32K 才开始考虑 CP

       ★★ 这个"经验值"其实是有出处的，就是 §8.5.4 那个 c ≥ F/B：
          每卡序列太短 → 一轮的计算量（∝ c²）压不住通信量（∝ c）
          → 通信暴露在关键路径上，CP 变成纯亏本
          ✅ 论文 Table 2：A100+NVLink 每卡至少 6.2K token，
             ⚠️ A100+InfiniBand 每卡要 149.5K
          → ★ 所以"32K 才开 CP"这句话，机内偏保守、跨机则远远不够

    ② ★ 它不省【模型状态】（参数/梯度/优化器）
       回忆 [02 章 §2.5](02-显存去哪了.md) 的路由表：
       CP 属于"治激活"那一类药，不治"模型放不下"这个病

    ③ 它占用总卡数预算
       ★ 铁律：TP × PP × CP × DP = N
       开 CP=4 意味着 DP 少 4 倍 → global batch 变小 → 又回到 04 章那个约束

④ ⚠️ **CP 和 TP 同时用时，TP 的价值会被部分挤压**

```
★ TP 的收益分两块：
  一块是【切权重】（参数/梯度/优化器状态）
  一块是【切激活】（就是 §8.2 的 SP，省 LayerNorm/Dropout/残差 区域的激活）

第一块【完全不受影响】：
  → CP（包括所有 CP 方案）只切激活，从来不切模型状态
  → "模型太大放不下"这个病，CP 治不了，TP 还是唯一的解

第二块【边际价值下降】：
  → SP 的任务是把非注意力区域按序列切开，省 1/t
  → 但 CP 已经把序列切成了 1/cp，这些区域的激活本来就小了
  → ★ 效果依然在叠加（总激活 ∝ 1/(t·cp)），但 SP 这一层不再是救命稻草
```

**⚠️ 更要命的卡点：头数约束会让两者【互相抢预算】**

```
回忆 §8.5.5：Ulysses 在注意力内部按【头】切
而 TP 在 QKV 投影矩阵上也是按【头】切（§8.2）
→ 两者同时用时，每张卡持有 a/(t·cp) 个头

★★ 联合约束：t × cp ≤ 头数 ★★

代入 GQA 常见配置（8 个 KV 头）：
  cp = 4  →  TP 最多只能开到 t = 2   （8 ÷ 4 = 2）
  cp = 8  →  TP 只剩 t = 1，即【不能用 TP 切头了】

→ ★ Ulysses 用得越多，留给 TP 的头预算就越少
  → 反过来【限制了 TP 能切多少权重】
  → 这是两者最实质的互相挤压
```

> ⚠️ **Ring Attention 没有这个头数约束**（它切序列不切头），
> 所以跨机场景 Ring 可以无限堆 CP 度、不挤压 TP；
> 而机内 Ulysses 用满 8 头之后，TP 的权重切分空间就被锁死了。

**⚠️ 通信代价也在叠加**（两者都走 NVLink，同一条总线）：

```
TP + SP 每层需要：reduce-scatter + all-gather（§8.2.6 的 g/ḡ 各两次）
Ulysses  每层需要：2 个 all-to-all 阶段（§8.5.5）
→ 叠在一起意味着同一条总线上的通信压力翻倍
```

> ⚠️ **实践中的典型配法**（我的工程观察，非论文披露）：
>
> 机内 8 卡，Ulysses cp=4，GQA 8 个 KV 头：
>   → TP 最多只能开 t=2（8 ÷ 4 = 2）
>   → dp = 8 ÷ 2 ÷ 4 = 1，每组 TP×CP 就是一份完整的模型状态
>   → 这时候模型状态靠 ZeRO-3 在 DP×CP 合并组上切（§8.5.5 末尾）
>
> 跨机场景（§8.5.7 的 USP，机内 Ulysses cp=8 × 机间 Ring cp=2）：
>   → Ulysses 已经把 8 个 KV 头全用完 → TP 往往就不开了
>
> ★★ 一句话：CP 度越高，TP 的生存空间越小 ★★

8.8 本章小结

① ★ TP 有个漏洞：LayerNorm / Dropout / 残差 这些【非矩阵】操作没被切
   ✅ 论文自己承认："there are parts of the transformer where activations
      are not split across tensor parallel ranks"
   → t 张卡各存一份完全相同的激活，纯浪费

② ★ Megatron SP：在那些区域改按【序列维】切
   凭据：LayerNorm/Dropout 都是【逐 token 独立】的
   → 切法转换需要 all-gather ⇄ reduce-scatter（前向 g / ḡ，反向互为共轭）
   → ★ 那 10sbh 的具体成分：2 个 LayerNorm 输入(4) + 2 个模块输入(4)
        + 2 个 dropout 掩码(2)；残差加法【不占】显存

③ ★★★ 而这是【免费】的，因为 All-Reduce = Reduce-Scatter + All-Gather
   ✅ 论文原话："the communication bandwidth used for tensor parallelism
      and tensor together with sequence parallelism are the same.
      Therefore, sequence parallelism does not introduce any communication overhead."
   → 03 章那个恒等式在这里兑现了价值
   → 效果：每层激活从 sbh(34+5as/h) 变成 【整除以 t】
   → ⚠️ 但不是【零成本】：反向要为张量 Y 多做 2 次 all-gather（每层，前向不多），
      字节 +25%，靠与 dY 的矩阵乘重叠把延迟藏掉（§8.2.8）

④ ★★ 一个反直觉的重要结论：PP 不省激活显存
   ✅ "the first stage must store p × L/p = L layers worth of activations
      regardless of the pipeline parallel size p"
   → 层数少了 p 倍，但要压 p 份 micro-batch，正好抵消

⑤ ★★ SP ≠ CP（本章最容易错的一点）
   SP：TP 的附属品，度数 = t，注意力照常算（进去前拼回完整序列）
       → ❌ 解决不了"序列本身太长"
   CP：独立一维，注意力【本身】切着算
       → ✅ 这才是长上下文的解药
   ⚠️ DeepSpeed 把它的 CP 也叫 "sequence parallelism" —— 看它切不切注意力内部

⑥ ★ 一块必备积木：online softmax（§8.5.3）
   softmax 的分母要"所有分数到齐"才算得出来 → 分块算看似不可能
   ★ 解法：存 (m, l, Õ) 三个统计量，新块来了就把旧结果按 e^{m-m*} 缩放一下再合并
   → ✅ 结果和一次性算【逐位相同】，是精确不是近似
   → ✅ 论文管这叫 permutation invariance：块的【顺序无所谓】
   ★★ 正因为顺序无所谓，KV 才可以"随便转到你这里" —— 这就是 Ring 的地基
   → 和 [11 章](11-重计算与激活优化.md) FlashAttention 是同一个技巧，
     ★ Ring Attention ≈ FlashAttention 的外层循环被拆到多张卡上

⑦ CP 两条路（§8.5.4 / §8.5.5）：
