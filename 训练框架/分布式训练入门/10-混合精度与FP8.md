# 10 · 混合精度与 FP8

> **这一章开始换一类思路**：前面六章都在讲"把东西切开分给多张卡"。**这一章和下一章讲的是"不切，也能省"**——本章把每个数字变小，下一章干脆不存。
> 读完你应该能回答：为什么"直接全用 FP16"会训崩？那三根救命稻草（master 权重 / loss scaling / FP32 累加）各救的是什么？BF16 和 FP16 到底差在哪，为什么现在都用 BF16？FP8 的 E4M3 和 E5M2 为什么要有两种？

---

## 10.1 先建立一个浮点数的直觉

**一个浮点数分三段**：

```
    ┌───┬─────────────┬────────────────────┐
    │符号│   指数 E     │      尾数 M         │
    └───┴─────────────┴────────────────────┘
      1位    决定【范围】        决定【精度】

    ★★ 记住这一句就够了：
       ★ 指数位 = 能表示多大/多小的数（动态范围）
       ★ 尾数位 = 能分辨多细的差别（精度）
       ★ 两者【互相抢】那有限的几个 bit
```

| 格式 | 总位 | 指数 | 尾数 | 范围 | 精度 |
|---|---|---|---|---|---|
| **FP32**（单精度） | 32 | 8 | 23 | ~10⁻³⁸ ~ 10³⁸ | 很高 |
| **FP16**（半精度） | 16 | **5** | **10** | ~6×10⁻⁵ ~ 65504 | 较高 |
| **BF16**（brain float） | 16 | **8** | **7** | ✅ **和 FP32 一样** | 低 |
| **FP8-E4M3** | 8 | 4 | 3 | ±448 | 很低 |
| **FP8-E5M2** | 8 | 5 | 2 | ±57344 | 极低 |

> 📌 **BF16** = **B**rain **F**loating point 16，由 Google Brain 提出。**它的设计取舍非常清晰：把 FP32 的 8 位指数原样搬过来，全部的削减都从尾数里出。**

```
    ★★ 一句话对比 FP16 和 BF16 ★★

    FP16：范围小、精度高  →  ⚠️ 容易【溢出/下溢】，要靠 loss scaling 救
    BF16：范围大、精度低  →  ✅ 几乎不会溢出，但小数点后能记的位数少

    → ★ 训练最怕的是"数溢出变成 inf/0"（直接崩），
      而不怕"精度差一点"（梯度本来就有噪声）
    → ★★ 所以现在大模型训练几乎【全部用 BF16】★★
```

✅ **FP8-E4M3 的最大值是 448、E5M2 是 57344**——这是论文 Table 1 的精确数字：*"Max normal ... E4M3: 1.75 × 2⁸ = 448 ... E5M2: 1.75 × 2¹⁵ = 57,344"*。

## 10.2 为什么不能"直接全用 FP16"

**这是 2017 年那篇奠基论文（[papers/Mixed-Precision-Training-arXiv-1710.03740.pdf](../papers/Mixed-Precision-Training-arXiv-1710.03740.pdf)）要回答的问题。**

> ✅ 论文摘要开门见山：
> *"Since FP16 format has a narrower dynamic range than FP32, we introduce **three techniques** to prevent model accuracy loss: **maintaining a master copy of weights in FP32**, **loss-scaling** that minimizes gradient values becoming zeros, and **FP16 arithmetic with accumulation in FP32**."*

```
    ★★ 三根救命稻草，各救一个不同的病 ★★
```

### 稻草一：FP32 master 权重 —— 救"更新被吃掉"

> ✅ 原文：*"we recommend **maintaining a single-precision copy of weights that accumulates the gradients after each optimizer step** (this copy is rounded to half-precision for the forward- and back-propagation)."*

**这个病 [02 章 §2.2](02-显存去哪了.md) 已经算过一遍了，这里给出它的出处**：

```
    ★ 权重 1.0，这一步的更新量是 0.00001

      FP32 里：1.0 + 0.00001 = 1.00001    ✅ 记得住
      BF16 里：★ 1.0 附近相邻两个可表示数差 ≈ 0.0078
              → 1.0 + 0.00001 【四舍五入回 1.0】
              → ★★ 这一步的更新【完全消失了】★★

    → 训练后期更新量普遍很小，如果全用低精度，
      ★ 大量更新会被静默地吃掉，模型就是不收敛
```

```
    ★ 解法：权重存【两份】

      FP32 master 副本  ← 优化器在这上面更新（累加不丢）
            ↓ 每步转成
      BF16 工作副本     ← 前向/反向用这个（快、省带宽）

    ⚠️ 代价：这就是 [02 章](02-显存去哪了.md) 那张 16 字节/参数账单里
       "FP32 master 4 字节"那一项的来源。
```

### 稻草二：Loss Scaling —— 救"小梯度下溢成 0"

```
    ★ 病因：梯度普遍很小，FP16 的最小正规数是 6×10⁻⁵
      → 大量梯度直接【下溢成 0】，反向传播断掉

    ★ 药方（简单得令人叫绝）：

      前向算完 loss，★ 先乘一个大数 S（比如 1024）再反向
        → 链式法则：所有梯度都跟着 ×S，一起被"抬"进可表示范围
      更新前，★ 把梯度再除以 S 还原
        → 数学上完全等价，一点没变
```

> ✅ 论文原文：*"Gradients must be unscaled before weight update to maintain the update magnitudes as in FP32 training. It is simplest to perform this unscaling **right after the backward pass but before gradient clipping** or any other gradient-related computations, ensuring that **no hyper-parameters (such as gradient clipping threshold, weight decay, etc.) have to be adjusted**."*

```
    ★ 注意这个"先 unscale 再裁剪"的顺序 —— 顺序错了，
      梯度裁剪的阈值就全乱了。这是一个真实的踩坑点。

    ✅ 论文用过的 S 范围："scaling factors ranging from 8 to 32K
       (many networks did not require a scaling factor)"
```

**实践中用的是【动态 loss scaling】**：

```
    S 从一个大值开始
      → 如果这一步出现了 inf/NaN：★ 丢弃这一步，S 减半，重来
      → 如果连续 N 步都正常：S 翻倍，试探更大的范围

    ★ 自动找到"尽可能大但不溢出"的那个 S
```

> 🔑 **★ BF16 基本不需要 loss scaling**——因为它的指数位和 FP32 一样宽，下溢风险极低。**这是 BF16 取代 FP16 的最大工程理由：少一整套需要调试的机制。**

### 稻草三：FP32 累加 —— 救"长求和的误差堆积"

> ✅ 原文：*"we use **half-precision arithmetic that accumulates into single-precision outputs**, which are converted to half-precision before storing to memory."*

```
    ★ 病因：矩阵乘是【很长的一串加法】
      d = 8192 的一行内积 = 8192 个数连加

      如果每加一次都存回低精度 → 每次都有舍入误差 → ★ 误差累积 8192 次

    ★ 药方：★★ 乘法用低精度（快），累加器用 FP32（准）★★
      算完整行，最后再转回 BF16 存回显存

    📌 这正是 GPU Tensor Core 的硬件行为：
       输入 BF16 → 内部 FP32 累加 → 输出可选 BF16/FP32
       → ★ 这一条【不需要你做任何事】，硬件已经替你做了
```

### ✅ 总收益

> 原文：*"This **nearly halves memory requirements** and, on recent GPUs, **speeds up arithmetic**."*
> *"half-precision arithmetic throughput on recent GPUs is **2× to 8× higher** than single-precision"*

## 10.3 混合精度的完整一步

```
    ┌─ 显存里常驻 ────────────────────────────────┐
    │  BF16 权重     2 字节/参数   ← 前向反向用     │
    │  FP32 master   4 字节/参数   ← ★ 优化器更新用 │
    │  Adam m, v     8 字节/参数                    │
    └──────────────────────────────────────────────┘

    一步训练：
      ① BF16 权重 → 前向（Tensor Core 内部 FP32 累加）→ loss
      ② loss × S（★ 仅 FP16 需要，BF16 通常省略）
      ③ 反向 → BF16 梯度
      ④ ★ 梯度 ÷ S 还原  →  再做梯度裁剪
      ⑤ 梯度转 FP32，在 ★FP32 master★ 上做 Adam 更新
      ⑥ FP32 master → 舍入成 BF16，供下一步用

    ★ 注意 ④⑤ 的顺序：先还原、再裁剪、再更新。
```

> 📌 **和 [05 章](05-ZeRO与FSDP.md) 的联系**：ZeRO 切的正是 ⑤ 里那些 FP32 的东西（master 权重 + m + v = 12 字节里的大头）。**"混合精度制造了这些额外副本，ZeRO 负责把它们切开"——两章讲的是同一笔账的两面。**

## 10.4 再往下走一格：FP8

**BF16 已经是现在的默认。下一步是 FP8（H100 起硬件支持）。**

### 为什么要两种格式

> ✅ FP8 论文（[papers/FP8-Formats-for-Deep-Learning-arXiv-2209.05433.pdf](../papers/FP8-Formats-for-Deep-Learning-arXiv-2209.05433.pdf)）：
> *"an 8-bit floating point (FP8) binary interchange format consisting of two encodings - **E4M3** (4-bit exponent and 3-bit mantissa) and **E5M2** (5-bit exponent and 2-bit mantissa)."*
> *"The **recommended use of FP8 encodings is E4M3 for weight and activation tensors, and E5M2 for gradient tensors.**"*

```
    ★★ 为什么要分工？回到 §10.1 那句"指数抢尾数"★★

    权重、激活：数值范围比较集中  →  ★ 拿位数换【精度】→ E4M3（尾数 3 位）
    梯度：      跨好几个数量级    →  ★ 拿位数换【范围】→ E5M2（指数 5 位）

    → ★ 这不是两个竞争标准，是【一套里的两个分工】
```

> ✅ 论文还解释了 E4M3 的一个小设计：*"While E5M2 follows IEEE 754 conventions for representation of special values, **E4M3's dynamic range is extended by not representing infinities** and having only one mantissa bit-pattern for NaNs."*
> ⚠️ **翻译**：E4M3 只有 4 位指数，范围本来就紧张，**干脆把"无穷大"这个编码省下来当普通数字用**——省出来的位置让最大值从 256 提到了 448。

### 缩放：loss scaling 的升级版

> ✅ 原文：*"Higher precision values need to be multiplied with a scaling factor prior to their casting to FP8... This is **very similar to the purpose loss-scaling serves in mixed-precision training with FP16**. However, some networks require **per-tensor scaling factors** as FP8 dynamic range is not sufficient to cover the union of all tensors' important values."*

```
    ★ FP16 时代：全模型【一个】 loss scale 就够
    ★ FP8 时代：★★ 每个张量【各自】一个 scale ★★
      因为 8 位的范围太窄，不同层的数值分布差异已经装不进同一个窗口了

    ⚠️ 这就是工程复杂度的来源：要维护成百上千个 scale，
       还要用历史最大值（amax history）来动态更新它们。
```

### ✅ 效果

> *"We show that **FP8 training matches FP16 or bfloat16 training results** for a variety of tasks and neural network model architectures and sizes, **without changing any model or optimizer hyperparameters**. Our study includes the training of very large language models, **up to 175B parameters**."*

```
    ★ "不用改任何超参" 是这篇论文最有价值的一句话 ——
      意味着 FP8 可以当成一个纯粹的加速开关来用。

    ⚠️ 但注意论文的范围：它验证的是【GEMM 用 FP8】，
       ★ 不是"整个训练全 FP8"。master 权重、优化器状态、
         归一化、softmax 这些【依然是高精度】。
```

## 10.5 ⚠️ 一个必须澄清的常见误解

```
    ❌ 误解："用了 BF16，显存就减半了"

    ✅ 真相：回到 [02 章 §2.2](02-显存去哪了.md) 那张账单 ——

       纯 FP32 训练：   参数 4 + 梯度 4 + m 4 + v 4        = 16 字节
       混合精度训练：   BF16 参数 2 + BF16 梯度 2
                        + ★FP32 master 4★ + m 4 + v 4      = 16 字节

       ★★ 模型状态一个字节都没省 ★★

    ✅ 真正省的是：
       ① 激活（那是大头，而且全是 BF16）
       ② 通信量（梯度 all-reduce 传的是 BF16，直接减半）
       ③ 计算速度（Tensor Core，2~8×）

    → ★ 混合精度主要是【加速】技术，其次才是省显存技术。
```

> 📌 **顺带解释一个 Megatron 参数**：`--grad-reduce-in-fp32`。梯度 all-reduce 时用 FP32 更稳（多卡求和会放大舍入误差），但通信量翻倍。✅ Megatron MoE 文档明确把关掉它列为一项优化：*"**BF16 Gradient Reduce** | Reduces gradients in BF16 instead of FP32 for better performance"*。**这是一个典型的"稳定性 ↔ 速度"旋钮。**

## 10.6 挂回 Megatron

```bash
--bf16                          # ★ 现在的默认选择
--fp16                          # 老配置，需要配 loss scaling
  --loss-scale 0                #   0 = 动态 loss scaling
  --initial-loss-scale 4294967296
--grad-reduce-in-fp32           # §10.5 那个稳定性/速度旋钮
--use-precision-aware-optimizer # ✅ 源码 README：优化器状态也可以用 BF16 存
--fp8-format hybrid             # ★ "hybrid" = §10.4 的 E4M3/E5M2 分工
--fp8-param-gather              # ✅ 文档："parameter all-gather in FP8,
                                #    reducing overhead by 50%"
```

```
    源码位置：
      megatron/core/extensions/TransformerEngineMixedPrecision.md
      megatron/core/optimizer/            ← master 权重、loss scaling 的实现
      megatron/core/distributed/          ← 梯度以什么精度 reduce
```

> 📌 **TE** = **T**ransformer **E**ngine，NVIDIA 的一个库，专门做 FP8 的 kernel 和那套 scale 管理。**Megatron 的 FP8 能力基本都是转手调用 TE 的。**

## 10.7 本章小结

```
① ★ 浮点数：指数位管【范围】，尾数位管【精度】，两者抢有限的 bit
   FP16：范围小精度高 → 会溢出，要 loss scaling
   BF16：★ 指数位和 FP32 一样宽 → 几乎不溢出，精度换来的
   → ★★ 训练怕"溢出崩掉"胜过怕"精度差一点"，所以现在全用 BF16 ★★

② ★ 混合精度的三根稻草（✅ 2017 论文原文三件套）：
   ① FP32 master 权重 → 救"小更新被舍入吃掉"（1.0+0.00001 回到 1.0）
   ② loss scaling     → 救"小梯度下溢成 0"；★ 先 unscale 再裁剪
                        ✅ 论文用过 8 ~ 32K；BF16 基本不需要
   ③ FP32 累加        → 救"长求和误差堆积"；★ Tensor Core 自动做

③ ✅ 收益："nearly halves memory requirements"，算术吞吐 2×~8×

④ ★ FP8 有两种格式，是【分工】不是竞争：
   ✅ E4M3（±448）给权重/激活 —— 要精度
   ✅ E5M2（±57344）给梯度   —— 要范围
   ⚠️ E4M3 把"无穷大"编码省下来当数字用，把上限从 256 抬到 448
   ★ scaling 从"全局一个"升级成 ★每个张量一个★
   ✅ "matches FP16 or bfloat16 ... without changing any hyperparameters"，
      验证到 175B；⚠️ 但只是 GEMM 用 FP8，不是全流程

⑤ ★★ 最常见的误解：混合精度【不省模型状态】
   纯 FP32 = 16 字节/参数，混合精度 = 2+2+4+4+4 = ★ 还是 16 字节 ★
   真正省的是：激活、通信量、计算时间
   → ★ 它主要是【加速】技术
```

**下一章讲最后一种"不切也能省"的办法**，也是最"反直觉"的一种：**干脆不存激活，要用的时候现算**。
