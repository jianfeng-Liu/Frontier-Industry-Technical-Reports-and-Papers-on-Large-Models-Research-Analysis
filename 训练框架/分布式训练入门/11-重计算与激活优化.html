11 · 重计算与激活优化

这一章讲最反直觉的一招：明明算过一次了，故意不存，等要用的时候再算一遍。
读完你应该能回答：为什么"扔掉再重算"能省这么多？完全重计算的代价有多大？选择性重计算凭什么能只花 2.7% 的算力换 70% 的显存？FlashAttention 为什么算是同一类思想？

11.1 为什么反向传播需要存激活

先回答一个基础问题：前向算完了，为什么不能把中间结果扔掉？

    考虑最简单的一层：  y = w · x

    反向要算两个梯度：
        dL/dx = dL/dy · w      ← 需要 w（权重，本来就存着）
        dL/dw = dL/dy · ★ x ★  ← ★★ 需要 x，也就是【这一层的输入】★★

    → 所以每一层的【输入】都必须留到反向的时候
    → ★ 这就是"激活值"，也是 [02 章](02-显存去哪了.md) 那笔账里最大的一项

    ★ 关键特征：激活显存 ∝ 层数 × batch × 序列长度
      —— 它和参数量【没有直接关系】，模型再小、序列一长照样爆

11.2 重计算：拿时间换显存

📌 这个技术有三个名字，指的是同一件事：gradient checkpointing（梯度检查点）、activation recomputation（激活重计算）、rematerialization（重物化）。Megatron 用第二个。

想法

    ┌─ 不用重计算 ──────────────────────────────────┐
    │  前向： x₀ → x₁ → x₂ → ... → x₈₀ → loss       │
    │        ★ 全部 81 个中间结果都存着              │
    │  反向： 直接拿来用                             │
    │  显存：★ O(n)     计算：1 遍前向 + 1 遍反向     │
    └────────────────────────────────────────────────┘

    ┌─ 完全重计算 ──────────────────────────────────┐
    │  前向： x₀ →(算)→ x₁ →(算)→ ... → loss         │
    │        ★★ 算完立刻扔，只留每层的【输入】★★     │
    │  反向： 到第 k 层时，★ 用留着的输入重新前向一遍  │
    │        这一层，把中间结果算出来，用完再扔       │
    │  显存：★ 大幅下降   计算：★ 多 1 遍前向        │
    └────────────────────────────────────────────────┘

✅ 最早的系统性工作是陈天奇等人 2016 年的论文（papers/Gradient-Checkpointing-Sublinear-Memory-arXiv-1604.06174.pdf）：
"we design an algorithm that costs O(√n) memory to train a n layer network, with only the computational cost of an extra forward pass per mini-batch."
"In the extreme case, our analysis also shows that the memory consumption can be reduced to O(log n) with as little as O(n log n) extra cost for forward computation."

    ★★ O(√n) 是怎么来的？（这个推导很漂亮，值得看一眼）★★

    把 n 层分成 k 段，每段 n/k 层：
      ① 只在【段的边界】存激活      → 存了 k 份
      ② 反向到某一段时，重算这一段  → 段内峰值 n/k 份

    总显存 = k + n/k
    ★ 对 k 求最小值：k = √n 时最小，总显存 = 2√n

    → n = 100 层：从 100 份降到 20 份，代价是多算一遍前向

⚠️ 代价有多大

✅ Megatron-3 论文给出的实测："recomputation (an extra forward pass) which can introduce as much as 30 − 40% computational time overhead."

    ★ 为什么是 30~40% 而不是 50%？

      前向 : 反向 ≈ 1 : 2（反向要算两个梯度，见 [01 章](01-为什么需要分布式训练.md) 那个 6ΨD 的推导）
      原来：1 + 2 = 3 份工作
      加上重计算：1 + 1 + 2 = 4 份工作
      → 4/3 = 1.33，★ 多了 33%，正好落在 30~40% 区间 ✅

11.3 ★★ 选择性重计算：这一章的核心

Megatron-3 的关键提问：为什么要一刀切地重算【全部】？

✅ 论文原话（本章最重要的引用）：
"we note that not all activations require the same amount of operations to recompute so it is beneficial to be smarter in selecting which activations to store and which to recompute. Instead of checkpointing and recomputing full transformer layers, we propose to checkpoint and recompute only parts of each transformer layer that take up a considerable amount of memory but are not computationally expensive to recompute, or selective activation recomputation."

    ★★ 判据一句话：★ 挑那些【占显存大、但重算便宜】的部分 ★

哪一部分符合这个条件

✅ 论文的分析："the term 5as/h in Equation 5 is due to the attention operations after the width of the network is increased by the linear layer calculating the Q, K, and V values; i.e., QKᵀ matrix multiply, softmax, softmax dropout, and attention over V... These operations generally have large input sizes and thus large activations, however, the number of floating-point operations (FLOPs) per input element is very low. The rest of the transformer layer accounts for the 34 term."

    ★ 回忆 [02 章 §2.3](02-显存去哪了.md) 那个公式的两项：

        每层激活 = sbh × ( 34  +  5as/h )
                          └┬┘    └──┬──┘
                           │        │
              ★ 34 项：矩阵乘的输入   ★ 5as/h 项：注意力分数矩阵那一块
                 —— 重算很贵（要重做矩阵乘）  —— 重算很便宜（每个元素只有几次运算）
                                              但★体积巨大★（∝ s²）

    ★★ 所以：只重算 5as/h 那一项，把 34 那一项好好存着 ★★

为什么这笔账特别划算

✅ 论文的具体数字：
"For GPT-3, a = 96, s = 2048, and h = 12288 and as a result 5as/h = 80. For MT-NLG, a = 128, s = 2048, and h = 20480 so 5as/h = 64. Comparing these numbers to 34... we can see these activations account for a large portion of the total activations. Thus, by using selective activation recomputation we can save 70% and 65% of the required memory for activations for the GPT-3 and MT-NLG models... The recomputation of these activations introduces only 2.7% and 1.6% FLOPs overhead."

    ⚠️ 验算一下 GPT-3 那一栏（帮你确认理解没跑偏）：

      总系数 = 34 + 80 = 114
      扔掉的 = 80
      → 80 / 114 = 70.2%   ✅ 和论文的 "70%" 对上了

    ★★★ 2.7% 的算力，换 70% 的激活显存 ★★★
        对比完全重计算的 "30~40% 算力换 ~94%"，
        ★ 这是一个好得多的交易点。

11.4 ✅ Megatron-3 的完整对照表（论文 Table 2 原样）

这张表是本章和 08 章 的合订本，值得逐行读：

配置 每层激活显存
什么都不用 $sbh\left(34 + \frac{5as}{h}\right)$
只有 TP $sbh\left(\mathbf{10} + \frac{24}{t} + \frac{5as}{ht}\right)$
TP + SP $sbh\left(\frac{34}{t} + \frac{5as}{ht}\right)$
TP + 选择性重计算 $sbh\left(\mathbf{10} + \frac{24}{t}\right)$
TP + SP + 选择性重计算 $\boxed{sbh\left(\frac{34}{t}\right)}$
完全重计算 $sbh(2)$ 
    ★★★ 请特别看第二行那个孤零零的【10】★★★

    它没有除以 t —— ★ 这就是 [08 章 §8.1](08-序列并行与上下文并行.md) 说的
    "TP 漏掉的那部分激活"，在论文的公式里长这个样子。

    加上 SP 之后（第三行），10 + 24/t 合并成了 34/t
    → ★ 那个"10"被彻底消灭了。这是 SP 价值的最硬证据。

    ★ 三个层次，看清楚各自的位置：

      基线    34 + 5as/h        （GPT-3: 114）
      +TP+SP  (34 + 5as/h)/t    （t=8: 14.25）
      +选择性  34/t             （t=8: 4.25）★ 只有基线的 3.7%
      完全重计算 2               ← ⚠️ 更省，但要付 30~40% 的算力

✅ 总成绩

论文摘要："our method reduces activation memory by 5×, while reducing execution time overhead from activation recomputation by over 90%. For example, when training a 530B parameter GPT-3 style model on 2240 NVIDIA A100 GPUs, we achieve a Model Flops Utilization of 54.2%, which is 29% faster than the 42.1% we achieve using recomputation."

📌 MFU = Model FLOPs Utilization，模型算力利用率。"你实际用掉的算力 ÷ 硬件理论峰值算力"，是衡量训练效率最重要的单一指标。** 12 章会专门讲怎么算它。

11.5 FlashAttention：其实是同一种思想

FlashAttention 通常被当成"注意力加速"来讲，但从本章的视角看，它做的是同一件事：不存中间结果，用重算换 IO。

病因：注意力矩阵根本不该被写出来

    标准注意力的四步：

      ① S = QKᵀ           → ★ 写一个 [s, s] 的矩阵到显存
      ② P = softmax(S)    → ★ 再写一个 [s, s]
      ③ P = dropout(P)    → ★ 又一个 [s, s]
      ④ O = PV            → 读回来

    s = 8192 时，一个 [s,s] 矩阵 = 6700 万个数 × 每个头 × 每层
    ★★ 而这些矩阵【只是中间产物】，最终只要 O ★★

    → 时间全花在【搬运】而不是【计算】上

✅ FlashAttention 论文（papers/FlashAttention-arXiv-2205.14135.pdf）的诊断：
"We argue that a missing principle is making attention algorithms IO-aware—accounting for reads and writes between levels of GPU memory. We propose FlashAttention, an IO-aware exact attention algorithm that uses tiling to reduce the number of memory reads/writes between GPU high bandwidth memory (HBM) and GPU on-chip SRAM."

📌 HBM = High Bandwidth Memory，高带宽显存，就是我们平时说的"80 GB 显存"。SRAM = 芯片上的高速缓存，只有几十 MB，但快 10 倍以上。★ 这就是 03 章 那个"带宽层级"的概念，只不过发生在一张卡的内部。

药方

    ★ 把 Q、K、V 切成小块，一块一块地：
      读进 SRAM → 在 SRAM 里算完这一块的注意力 → 只把结果累加到输出

    ★★ 那个 [s, s] 的大矩阵【从来没有被完整地写进 HBM】★★

    反向怎么办？—— ★ 重算 ★
      存下来的只有 O 和 softmax 的归一化统计量（很小）
      反向时用它们【重新算出】需要的那一块

    → ★★★ 这就是本章的思想：不存，要用时再算 ★★★

📌 数学上凭什么能分块？ 靠 online softmax：softmax 可以边扫描边修正归一化因子，分块累加的结果和一次性算完全相同。✅ 论文强调这是 exact attention（精确注意力），不是近似。这也正是 08 章 Ring Attention 能成立的同一个数学基础。

✅ 效果

"FlashAttention trains Transformers faster than existing baselines: 15% end-to-end wall-clock speedup on BERT-large (seq. length 512) compared to the MLPerf 1.1 training speed record, 3× speedup on GPT-2 (seq. length 1K), and 2.4× speedup on long-range arena."
"FlashAttention does not read and write the large N×N attention matrix to HBM, resulting in an 7.6× speedup on the attention computation."

FlashAttention-2（papers/FlashAttention-2-arXiv-2307.08691.pdf）继续优化了 GPU 内部的任务划分：

✅ "These yield around 2× speedup compared to FlashAttention, reaching 50-73% of the theoretical maximum FLOPs/s on A100... FlashAttention-2 reaches training speed of up to 225 TFLOPs/s per A100 GPU (72% model FLOPs utilization)."

    ★ 注意一个隐含的重要后果：
      FlashAttention 让 5as/h 那一项【不再实际占显存】
      → 于是 [02 章](02-显存去哪了.md) 那个 s=4096 的例子里的
        注意力矩阵那一块，在现代框架里其实已经消失了
      ⚠️ 所以本教程引用的 Megatron-3 公式，是【不带 FlashAttention】
         的理论账。真实系统里 5as/h 那项要打很大的折扣。

11.6 第三条路：卸载到 CPU 内存

    ★ 既然 CPU 内存便宜又大（一台机器 1~2 TB），
      那把暂时不用的东西挪过去，要用时再挪回来？

    ✅ 可行，但回忆 [01 章 §1.6](01-为什么需要分布式训练.md) 的那个数字：
       PCIe 5.0 ≈ 0.06 TB/s   vs   HBM3 3.35 TB/s
       ★★ 差 55 倍 ★★

    → ★ 只有当"挪的时间"能被"算的时间"完全盖住时才划算
    → 所以卸载的对象要选【很久才用一次的东西】：
        ✅ 优化器状态（一步用一次）        ← ZeRO-Offload
        ✅ 早期层的激活（前向存、反向才用，中间隔了很久）
        ❌ 当前层的权重（马上就要用）

📌 Megatron 现在也支持细粒度的激活卸载（源码 README 提到 "Pipeline-aware fine-grained activation offloading" 和 --optimizer-cpu-offload）。★ 这里"pipeline-aware"三个字是关键：流水线里前面的 stage 存的激活要等很久才反向，正好是卸载的最佳对象。

11.7 四条路的对比

手段 省什么 代价 用不用
完全重计算 ✅ 激活降到 2sbh ⚠️ 30~40% 算力 最后的手段
选择性重计算 ✅ 激活 −70% ✅ 仅 2.7% 算力 ★ 基本默认开
FlashAttention ✅ 消灭 5as/h 项 ✅ 负代价（更快） ★★ 无脑开
CPU 卸载 ✅ 什么都能省 ⚠️ 慢 55 倍的搬运 显存实在不够时 
    ★★ 开启顺序（工程经验，⚠️ 我的总结不是论文结论）：

      FlashAttention（免费）
        → 选择性重计算（2.7%）
          → SP（免费，见 [08 章](08-序列并行与上下文并行.md)）
            → 部分层完全重计算（按需）
              → CPU 卸载（万不得已）

11.8 挂回 Megatron

--recompute-granularity selective   # ★ §11.3，默认推荐
--recompute-granularity full        #   完全重计算
  --recompute-method uniform        #   均匀分组（对应 §11.2 的 O(√n) 思路）
  --recompute-method block          #   只重算前 N 层
  --recompute-num-layers N
--recompute-modules mla moe mlp moe_act norm
                                    # ✅ v0.13 起的细粒度重计算，
                                    #   可以精确到"重算哪几种模块"
--use-flash-attn                    # §11.5

    源码位置：
      megatron/core/transformer/transformer_block.py
          ★ 重计算的分组逻辑在这里（_checkpointed_forward）
      megatron/core/tensor_parallel/random.py
          ★★ 一个容易忽略但关键的文件：重计算必须复现【同一个 dropout 掩码】，
             否则前向和重算结果不一致，梯度就错了。
             这里管的就是随机数状态的保存与恢复。

🔑 上面那个随机数问题值得多说一句：重计算的正确性前提是"重算一遍得到和第一次完全相同的结果"。dropout 是随机的，所以框架必须在第一次前向时记下随机数种子状态，重算时精确恢复。这是所有重计算实现里最容易出 bug 的地方。

11.9 本章小结

① ★ 反向传播需要每一层的【输入】来算权重梯度 → 这就是激活必须存的原因
   激活 ∝ 层数 × batch × 序列长度，★ 和参数量无关

② ★ 重计算 = 拿时间换显存：不存，反向时重新前向一遍
   ✅ 2016 年论文：O(√n) 显存 + 一遍额外前向；极端可到 O(log n)
   ★ √n 的来历：分 k 段，显存 = k + n/k，k=√n 时最小
   ⚠️ ✅ 代价实测 30~40%（验算：工作量从 1+2 变成 1+1+2，即 +33%）

③ ★★★ 选择性重计算：只重算【占显存大、重算便宜】的那部分
   ✅ 判据原文："take up a considerable amount of memory but are not
      computationally expensive to recompute"
   ★ 对象就是公式里的 5as/h 项（QKᵀ、softmax、dropout、attn over V）
     —— 体积 ∝ s²，但每个元素的运算量极低
   ✅ GPT-3: 5as/h = 80 vs 34 → 省 70%，只花 2.7% 算力
      （验算 80/114 = 70.2% ✅）

④ ✅ Megatron-3 Table 2 是全书最值得记的一张表：
   只 TP：      sbh(★10★ + 24/t + 5as/ht)   ← ★ 那个不除 t 的 10 就是 TP 的漏洞
   TP+SP：      sbh(34/t + 5as/ht)          ← ★ 10 被消灭了
   TP+SP+选择性：sbh(34/t)                   ← ★ 只有基线的 3.7%
   完全重计算：  sbh(2)
   ✅ 总成绩：激活 ÷5，重计算开销 −90%，530B/2240 卡 MFU 54.2% vs 42.1%（快 29%）

⑤ ★ FlashAttention 是同一思想的另一个战场：
   把 [s,s] 注意力矩阵从【显存】里彻底消灭，切块在片上 SRAM 里算，反向时重算
   ✅ 数学基础是 online softmax，是【精确】不是近似
      —— 和 08 章 Ring Attention 同一个基础
   ✅ GPT-2 快 3×，注意力本身快 7.6×；FA2 再快 2×，225 TFLOP/s / 72% MFU
   ⚠️ 副作用：它让 5as/h 那项在真实系统里基本消失了

⑥ CPU 卸载：⚠️ PCIe 比 HBM 慢 55 倍 → 只适合"很久才用一次"的东西
   ✅ 优化器状态、前面 stage 的激活；❌ 当前层权重

⑦ ⚠️ 重计算的隐藏坑：必须复现同一个 dropout 掩码，
   → 框架要保存/恢复随机数状态（megatron/core/tensor_parallel/random.py）

第三部分到此结束。 五种切法 + 两种"不切也能省"，工具箱已经齐了。接下来的第四部分讲工程现实：这些旋钮该怎么组合、怎么判断自己跑得快不快、几千张卡上会坏什么、以及断了怎么接着训。
