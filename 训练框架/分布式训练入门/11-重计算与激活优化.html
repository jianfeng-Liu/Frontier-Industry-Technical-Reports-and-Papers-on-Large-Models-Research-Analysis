11 · 重计算与激活优化

这一章讲最反直觉的一招：明明算过一次了，故意不存，等要用的时候再算一遍。
读完你应该能回答：为什么"扔掉再重算"能省这么多？每省 1 GB 显存，到底要付多少毫秒？选择性重计算凭什么只花 2.7% 的算力换 70% 的显存？开了重计算之后 MFU 和 HFU 为什么会分家、差多少？以及最反直觉的一条：FlashAttention 的重算，为什么连时间都不用赔？

11.1 为什么反向传播需要存激活

先回答一个基础问题：前向算完了，为什么不能把中间结果扔掉？

    考虑最简单的一层：  y = w · x

    反向要算两个梯度：
        dL/dx = dL/dy · w      ← 需要 w（权重，本来就存着）
        dL/dw = dL/dy · ★ x ★  ← ★★ 需要 x，也就是【这一层的输入】★★

    → 所以每一层的【输入】都必须留到反向的时候
    → ★ 这就是"激活值"，也是 [02 章](02-显存去哪了.md) 那笔账里最大的一项

    ★ 关键特征：激活显存 ∝ 层数 × batch × 序列长度
      —— 它和参数量【没有直接关系】，模型再小、序列一长照样爆

🔑 和 10 章 连起来看：10 章的结论是"混合精度一个字节都没省模型状态，真正省的是激活"。这一章处理的正是那个'真正能省的大头'——而且这一次能省掉的不是一半，是 95% 以上。

11.2 重计算：拿时间换显存

📌 这个技术有三个名字，指的是同一件事：gradient checkpointing（梯度检查点）、activation recomputation（激活重计算）、rematerialization（重物化）。Megatron 用第二个。

11.2.1 想法

不用重计算 完全重计算
前向 x₀ → x₁ → x₂ → … → x₈₀ → loss x₀ → x₁ → … → loss
存什么 ★ 全部 81 个中间结果都存着 ★★ 算完立刻扔，只留每层的【输入】
反向 直接拿来用 ★ 到第 k 层时，拿留着的输入把这一层重新前向一遍，用完再扔
激活显存 O(n) ★ 大幅下降
计算量 1 遍前向 + 1 遍反向 ★ 多 1 遍前向

✅ 最早的系统性工作是陈天奇等人 2016 年的论文（papers/Gradient-Checkpointing-Sublinear-Memory-arXiv-1604.06174.pdf）：
"we design an algorithm that costs O(√n) memory to train a n layer network, with only the computational cost of an extra forward pass per mini-batch."
"In the extreme case, our analysis also shows that the memory consumption can be reduced to O(log n) with as little as O(n log n) extra cost for forward computation."

11.2.2 O(√n) 是怎么来的

    把 n 层分成 k 段，每段 n/k 层：
      ① 只在【段的边界】存激活      → 常驻 k 份
      ② 反向走到某一段时，重算这一段 → 段内临时峰值 n/k 份

    总显存 = k + n/k
    ★ 对 k 求最小值：k = √n 时最小，总显存 = 2√n

代几个数进去感受一下（n = 层数，单位是"份激活"）：

n（层数） 不重计算 最优分段 k = √n 2√n（重计算后） 省了多少
16 16 4 段 8 50%
64 64 8 段 16 75%
100 100 10 段 20 80%
400 400 20 段 40 90% 
    ★ 注意这张表的趋势：★★ 网络越深，重计算越划算 ★★
      —— 因为代价永远是"多一遍前向"（固定 33%），而收益随 √n 拉开。

11.2.3 ⚠️ 代价有多大

✅ Megatron-3 论文给出的数字："recomputation (an extra forward pass) which can introduce as much as 30 − 40% computational time overhead."

    ★ 为什么是 30~40% 而不是 50%？把工作量数清楚就行：

      前向 : 反向 = 1 : 2
        （反向要算两个梯度 dL/dx 和 dL/dw，所以是前向的两倍，
          见 [01 章 §1.3](01-为什么需要分布式训练.md) 那个 6ΨD 的推导）

      不重计算：  1（前向） + 2（反向）     = 3 份工作
      完全重计算：1 + ★1（重算）★ + 2      = 4 份工作
      ────────────────────────────────────────
      → 4 / 3 = 1.333，★ 多了 33%，正好落在论文的 30~40% 区间 ✅

📌 这个 33% 换个记号写就是 6N → 8N，下面 §11.4.3 讲 HFU 时要直接用。

    ⚠️ 顺便把 6N 这个公式的边界说清楚（很多人用错）：

      每个 token 的训练 FLOPs ≈ 6N
        = 2N（前向）+ 4N（反向）
      ★ 其中 N 是参数量。

      ⚠️ 这个式子【不含】三样东西：
         ① 优化器更新（Adam 的那几下逐元素运算，量级小但不是 0）
         ② 注意力里那个 s² 的部分（QKᵀ 和 PV，不经过参数）
         ③ 重计算多出来的那一遍前向

      ★ 想把 ② 补上，完整式是：
         每 token FLOPs ≈ 6N + 12·L·s·h
           L = 层数，s = 序列长度，h = hidden size
         （来源：每层注意力前向 4·s·h / token，前向+反向 ×3 = 12·s·h）
      → ★ s 越长这一项占比越大，短序列时可以忽略，长上下文时不行。

11.3 ★★ 选择性重计算：这一章的核心

Megatron-3 的关键提问：为什么要一刀切地重算【全部】？

✅ 论文原话（本章最重要的引用）：
"we note that not all activations require the same amount of operations to recompute so it is beneficial to be smarter in selecting which activations to store and which to recompute. Instead of checkpointing and recomputing full transformer layers, we propose to checkpoint and recompute only parts of each transformer layer that take up a considerable amount of memory but are not computationally expensive to recompute, or selective activation recomputation."

    ★★ 判据一句话：★ 挑那些【占显存大、但重算便宜】的部分 ★

11.3.1 哪一部分符合这个条件

✅ 论文的分析："the term 5as/h in Equation 5 is due to the attention operations after the width of the network is increased by the linear layer calculating the Q, K, and V values; i.e., QKᵀ matrix multiply, softmax, softmax dropout, and attention over V... These operations generally have large input sizes and thus large activations, however, the number of floating-point operations (FLOPs) per input element is very low. The rest of the transformer layer accounts for the 34 term."

    ★ 回忆 [02 章 §2.3](02-显存去哪了.md) 那个公式的两项：

        每层激活 = sbh × ( 34  +  5as/h )
                          └┬┘    └──┬──┘
                           │        │
                           │        └ 注意力分数矩阵那一块：
                           │            体积 ∝ s²，★ 巨大
                           │            每个元素只有几次运算，★ 重算很便宜
                           └ 矩阵乘的输入：
                               体积中等
                               重算要重做 GEMM，★ 很贵

    ★★ 所以：只重算 5as/h 那一项，把 34 那一项好好存着 ★★

把这个判据做成一张可以照着抄的表：

这部分是 占显存 重算它的代价 该怎么办
QKᵀ、softmax、softmax dropout、attention over V ★ 大（∝ s²） ✅ 极低（逐元素运算为主） ★★ 重算
Linear 的输入、LayerNorm 的输入、MLP 中间值 中等 ⚠️ 高（要重做 GEMM） ✅ 存着 
    🔑 一句话判据（值得记一辈子）：
       ★★ 看【每字节激活需要多少 FLOP 才能重算出来】★★
          这个比值低 → 重算
          这个比值高 → 存着
       —— §11.5 会看到 FlashAttention 把这个判据推到了极致。

11.3.2 为什么这笔账特别划算

✅ 论文的具体数字：
"For GPT-3, a = 96, s = 2048, and h = 12288 and as a result 5as/h = 80. For MT-NLG, a = 128, s = 2048, and h = 20480 so 5as/h = 64. Comparing these numbers to 34... we can see these activations account for a large portion of the total activations. Thus, by using selective activation recomputation we can save 70% and 65% of the required memory for activations for the GPT-3 and MT-NLG models... The recomputation of these activations introduces only 2.7% and 1.6% FLOPs overhead."

逐步验算这两栏（自己算一遍，理解就不会跑偏）：

模型 a s h 5as/h 总系数 34 + 5as/h 扔掉的比例 ✅ 论文写的
GPT-3 96 2048 12288 80 114 80 / 114 = 70.2% 70% ✅
MT-NLG 128 2048 20480 64 98 64 / 98 = 65.3% 65% ✅ 
    ★★★ 2.7% 的算力，换 70% 的激活显存 ★★★
        对比完全重计算的"33% 算力换 ~98%"，
        ★ 这是一个好得多的交易点 —— §11.4 会把这句话量化成"每 GB 多少毫秒"。

11.4 把兑换率算出来：三档到底各值多少

"时间换空间"是一句正确的废话。真正要问的是：★ 汇率是多少 ★。这一节把三档都算成"每省 1 GB 显存要付多少毫秒"。

11.4.1 一个从头算到尾的例子

    ⚠️ 下面全部是按公式代入的【举例推算】，不是任何真实系统的实测披露。

    配置：
      层数 L = 80，hidden h = 8192，注意力头 a = 64
      序列 s = 4096，micro-batch b = 1
      TP = 8 且【已开 SP】（见 [08 章](08-序列并行与上下文并行.md)），BF16
      每卡实测算力假设 400 TFLOP/s（≈ H100 稠密峰值 989 的 40%）

    先算两个基准量：
      参数量 N = L × 12h² = 80 × 12 × 8192² = 64.4 × 10⁹
      单位块 sbh = 4096 × 1 × 8192 = 33.55 MB
      5as/h = 5 × 64 × 4096 / 8192 = 160

① 显存这一侧（每张卡，系数取自 §11.4.2 那张表）：

档位 每层系数 每层激活 80 层合计
不重计算（TP+SP） (34 + 160) / 8 = 24.25 813.7 MB 65.1 GB
选择性重计算（TP+SP） 34 / 8 = 4.25 142.6 MB 11.4 GB
完全重计算 2 67.1 MB 5.4 GB

② 时间这一侧（一个 micro-batch = 4096 token）：

    前向 FLOPs = 2NT + 4·L·s·h·T
               = 2 × 64.4e9 × 4096   +   4 × 80 × 4096 × 8192 × 4096
               = 5.28e14             +   4.40e13
               = 5.72e14 FLOP        ← ★ 第二项就是注意力那个 s² 的部分
    分到 8 张卡：7.15e13 / 卡  ÷ 400e12 = ★ 179 ms

    反向 = 前向 × 2 = 357 ms
    ────────────────────────────────
    一步（不重计算）= 179 + 357 = ★ 536 ms
档位 多做的计算 额外耗时 占一步的比例
不重计算 — 0 ms 0%
选择性重计算 只重算注意力那部分前向 = 4.40e13 FLOP 13.7 ms 2.6%
完全重计算 完整多一遍前向 179 ms 33.4% 
    ✅ 校验：选择性的 2.6% 和论文 GPT-3 的 2.7% 对上了（配置不同，量级一致）；
       完全重计算的 33.4% 和 §11.2.3 推的 4/3 也对上了。

11.4.2 ★★★ 汇率表：每省 1 GB 要付多少毫秒

从哪档 → 到哪档 省下显存 付出时间 ★ 汇率
不重计算 → 选择性 53.7 GB 13.7 ms ✅ 0.26 ms / GB
不重计算 → 完全 59.7 GB 179 ms ⚠️ 3.0 ms / GB
选择性 → 完全（★ 边际价格） 只多省 6.0 GB 还要多付 165 ms ⚠️⚠️ 27.5 ms / GB 
    ★★★ 这张表只有一个结论，但它值本章一半的篇幅 ★★★

      第一行 0.26 ms/GB  → 便宜到几乎是白送，★ 无脑开
      第三行 27.5 ms/GB  → ★ 比第一行贵【106 倍】

    ⟹ 🔑 千万别看"平均价"（第二行的 3.0），要看【边际价】（第三行）。
       从选择性再往完全走，你是在用 100 倍的价格买最后那 6 GB。

    ⟹ ★★ 所以工程上的正确姿势是：
         选择性重计算全开，
         ★ 完全重计算【只对个别层开】（--recompute-method block），
           买到刚好够用为止，一层都不多买。

⚠️ 这张表只算了"多做的计算"，没算"省下的搬运"。 激活不存了，随之省掉的那一大笔 HBM 读写也是实打实的时间。把这一项加进来之后，第一行的 0.26 ms/GB 还会往下走，某些配置下甚至会变成负数（省显存的同时还更快）——§11.5.3 会把这条判据完整地讲清楚，它正是 FlashAttention 成立的原因。

11.4.4 HFU 和 MFU：重计算把两个指标撑开

这是看论文时最容易被骗的一个地方：同一次训练，报 HFU 和报 MFU 能差十几个百分点。

📌 MFU = Model FLOPs Utilization，模型算力利用率。分子只算模型定义上必须做的 FLOPs（6N），重计算多做的那一遍不算。
📌 HFU = Hardware FLOPs Utilization，硬件算力利用率。分子算硬件实际做了多少 FLOPs，重计算算进去。

    ★★ 两者的关系，就是 §11.2.3 那个 6N → 8N ★★

      完全重计算：   硬件做了 8N，模型需要 6N
                     ⟹ ★ HFU = MFU × 8/6 = MFU × 1.333 ★

      选择性重计算： 硬件只多做了注意力那一小块
                     ⟹ ★ 系数【小于】4/3，本例是 ×1.026，GPT-3 是 ×1.027 ★

      不重计算：     HFU = MFU
档位 硬件实际 FLOPs HFU / MFU 举例：若 MFU = 45% 对应 HFU
不重计算 6N 1.000 45% 45%
选择性重计算 ≈ 6.16N 1.026 45% 46.2%
完全重计算 8N 1.333 45% 60% 
    ⚠️★ 所以看到"我们达到了 60% 利用率"这种说法，先问一句：
       ★ 分子里算没算重计算？

       同一次训练，MFU 45% 也可以被写成 HFU 60%。
       ★★ 这不是造假，是口径 —— 但读的人如果不问，就会得出完全错误的结论。

    ⟹ 完整的口径辨析（含 Megatron-2 那个著名的 52% 到底是哪个）
       在 [12 章 §12.2](12-并行策略组合与MFU.md)。

11.4.5 ✅ 总成绩

论文摘要："our method reduces activation memory by 5×, while reducing execution time overhead from activation recomputation by over 90%. For example, when training a 530B parameter GPT-3 style model on 2240 NVIDIA A100 GPUs, we achieve a Model Flops Utilization of 54.2%, which is 29% faster than the 42.1% we achieve using recomputation."

    ✅ 验算 "over 90%"：完全重计算的开销 33%，选择性 2.7%
       → (33 − 2.7) / 33 = 92%   ✅ 对上了

    ✅ 验算 "29% faster"：54.2 / 42.1 = 1.287 → 快 28.7% ≈ 29%   ✅

⚠️★ 顺手澄清一个到处都在混的说法：「时间减少 X%」≠「加速 X%」。
```
上面这个例子：42.1% → 54.2% MFU
一步的耗时比 = 42.1 / 54.2 = 0.777
⟹ ★ 时间【减少了 22.3%】，同时【加速了 29%】—— 同一件事，两个数字

再举个极端的：时间减少 60%（剩 40%）
  ⟹ 加速倍数 = 1 / 0.4 = ★ 2.5 倍 ★，不是"快 60%"

★ 换算公式：加速倍数 = 1 / (1 − 时间减少比例)

```
看到"提速 60%"和"耗时降低 60%"，这是两个差很远的数字，别当成一个。

📌 ⚠️ 上面所有 MFU 数字都是 A100 平台（2240 张 A100，BF16 峰值 312 TFLOPS）。MFU 是个比值，换到 H100（989 TFLOPS）上同样的绝对吞吐会算出低得多的 MFU ——★ 引用任何 MFU 数字都必须带上硬件平台，否则没有意义。

11.5 FlashAttention：同一种思想，但两头都赚

FlashAttention 通常被当成"注意力加速"来讲。从本章的视角看，它做的是同一件事：不存中间结果，用重算换 IO。但它的账和 §11.4 那张汇率表【完全不同】——它不需要赔时间。

11.5.1 一分钟版机制

    标准注意力：
      ① S = QKᵀ        → 写一个 [s, s] 矩阵到显存
      ② P = softmax(S) → 再写一个 [s, s]
      ③ dropout(P)     → 又一个 [s, s]
      ④ O = PV         → 全部读回来
      ★ 而这些 [s,s] 矩阵【只是中间产物】，最终只要 O

    FlashAttention：
      把 Q、K、V 切成小块，一块一块读进片上 SRAM，在 SRAM 里算完，
      ★★ 那个 [s, s] 的大矩阵【从来没有被完整写进 HBM】★★
      反向怎么办？—— ★ 重算 ★
        只存 O 和 softmax 的归一化统计量（每行一个数，极小），
        反向时用它们把需要的那一块【重新算出来】

📌 HBM = High Bandwidth Memory，高带宽显存，就是我们平时说的"80 GB 显存"。SRAM = Static Random-Access Memory，芯片上的高速缓存，只有几十 MB，但带宽高一个量级。★ 这就是 03 章 那个"带宽层级"的概念，只不过发生在一张卡的内部。

📌 数学上凭什么能分块？ 靠 online softmax：softmax 可以边扫描边修正归一化因子，分块累加的结果和一次性算完全相同。✅ 论文强调这是 exact attention（精确注意力），不是近似。这也正是 08 章 Ring Attention 能成立的同一个数学基础。

📌 完整的三代演进（在线 softmax 的逐块推演、FA1/FA2/FA3 各改了哪一层、SRAM 预算怎么算、FP8 版本、昇腾上的对应算子）在 大模型算子开发 04 章。本章不重复，只取和"重计算"直接相关的那一节。

11.5.2 ★★★ 为什么它连时间都不赔

大模型算子开发 04 章 §4.6 把这笔账算到了底，结论是本章最该记住的一句话（B=1, H=32, N=8192, d=128, BF16，一层）：

路线 做了什么 耗时
A：存下来，反向读回 写 4.29 GB + 读 4.29 GB @ 3.35 TB/s 2.56 ms
B：不存，反向重算 多做 0.55 TFLOP 的矩阵乘 0.74 ms 
    ★★★ 0.74 ms < 2.56 ms —— 重算比"存下来再读回"【快 3.5 倍】★★★
        而且顺带把 4.29 GB 显存降到 0。

    ⟹ ★★ 这不是"时间换空间"，这是【两头都赚】的买卖。★★

11.5.3 🔑 把两笔账统一起来：一条判据

为什么整层重计算要赔 33% 的时间，而 FlashAttention 的重计算反而省时间？同一条判据就能解释：

    ★★ 判据：比较【重算它要多少 FLOP】和【搬运它要多少 Byte】★★

      重算更快  ⟺  重算 FLOP ÷ 989e12  <  搬运 Byte ÷ 3.35e12
                ⟺  ★ 该激活的「重算 FLOP / 字节」 < 295 ★
                      ↑ 这就是 [10 章 §10.4.1](10-混合精度与FP8.md) 那个 H100 屋脊点

把本章出现过的三样东西都放到这把尺子上量一量（⚠️ 我按 §11.4.1 那组配置的推算）：

要重算的东西 重算 FLOP / 字节 和屋脊点 295 比 结论
整个 transformer 层 ≈ 1100 ⚠️ 高 3.7 倍 存着更快 → ★ 重算必然赔时间（那 33%）
系数 34 那一项（GEMM 的输入） ≈ 5800 ⚠️ 高 20 倍 ★★ 绝对要存
系数 5as/h 那一项（注意力矩阵） ≈ 100 ✅ 低于 295 ★★ 该重算 —— 这正是选择性重计算挑中它的原因
FlashAttention 里的 QKᵀ = d = 128 ✅ 低于 295 ★★★ 重算净赚（上面那张 0.74 vs 2.56 的表） 
    ★★★ 所以 Megatron-3 的"选择性重计算"和 FlashAttention
         不是两个技巧，是【同一条屋顶线判据的两种实现】★★★

      选择性重计算：在【框架层】把注意力那块激活扔掉，反向时整块重算
      FlashAttention：在【kernel 层】让它压根没被写出来过

    ⟹ ★ 后者更彻底，所以后者出现之后，前者的价值就大幅缩水了（见 §11.5.4）。

⚠️ 上面 0.74 / 2.56 / 1100 / 5800 这些数全部是【屋顶线推算】，不是实测。 真实 kernel 有 launch 开销、重算未必能和搬运完美重叠、L2 缓存会吃掉一部分 HBM 流量。但量级关系（注意力那块重算 < 搬运，整层重算 > 搬运）是稳的。

11.5.4 ⚠️ 一个必须知道的副作用

✅ FlashAttention 论文（papers/FlashAttention-arXiv-2205.14135.pdf）："FlashAttention does not read and write the large N×N attention matrix to HBM, resulting in an 7.6× speedup on the attention computation."，端到端 "3× speedup on GPT-2"。
✅ FlashAttention-2（papers/FlashAttention-2-arXiv-2307.08691.pdf）："around 2× speedup compared to FlashAttention... FlashAttention-2 reaches training speed of up to 225 TFLOPs/s per A100 GPU (72% model FLOPs utilization)."（⚠️ A100 平台，BF16 峰值 312 TFLOPS，225 / 312 = 72% ✅）

    ★ 副作用：FlashAttention 让 5as/h 那一项【在真实系统里基本不存在了】

      ⟹ ① [02 章](02-显存去哪了.md) 那个 s=4096 例子里"注意力矩阵"那一块，
           现代框架里已经消失
      ⟹ ② §11.4 引用的 Megatron-3 公式是【不带 FlashAttention】的理论账；
           真实系统里 5as/h 那项要打很大折扣
      ⟹ ③ ★ 于是"选择性重计算"能省的东西也跟着缩水了 ——
           它原本要救的那块显存，FlashAttention 已经先救了

    ⚠️ 所以别把 §11.3 的"省 70%"直接往今天的系统上套。
       ★ 今天更常见的组合是：FlashAttention 打底 + 对个别层开完全重计算。

11.6 第三条路：卸载到 CPU 内存

    ★ 既然 CPU 内存便宜又大（一台机器 1~2 TB），
      那把暂时不用的东西挪过去，要用时再挪回来？

    ✅ 可行，但回忆 [01 章 §1.6](01-为什么需要分布式训练.md) 的那个数字：
       PCIe 5.0 ×16 ≈ 0.06 TB/s   vs   HBM3 3.35 TB/s
       ★★ 差 55 倍 ★★

    → ★ 只有当"挪的时间"能被"算的时间"完全盖住时才划算
    → 所以卸载的对象要选【很久才用一次的东西】：
        ✅ 优化器状态（一步才用一次）      ← ZeRO-Offload
        ✅ 早期层的激活（前向存、反向才用，中间隔了很久）
        ❌ 当前层的权重（马上就要用）

用 §11.5.3 那把尺子量一下就一目了然：卸载的"汇率"是 1 GB 要花 1 GB ÷ 0.06 TB/s ≈ 16.7 ms（还要来回，实际 33 ms），★ 比 §11.4.2 里最贵的那档（27.5 ms/GB）还贵——除非这段时间里 GPU 正好有别的事干，能把搬运完全藏起来。

📌 Megatron 现在也支持细粒度的激活卸载（源码 README 提到 "Pipeline-aware fine-grained activation offloading" 和 --optimizer-cpu-offload）。★ "pipeline-aware"三个字是关键：流水线里靠前的 stage 存的激活，要等很久才轮到反向（见 07 章 那张气泡图），那段空窗期正好够把它搬走再搬回来 —— 这就是"能被算的时间盖住"的典型场景。

11.7 四条路的对比

手段 省什么 代价（§11.4.1 那组配置） 汇率 用不用
FlashAttention ✅ 消灭 5as/h 项 ✅ 负代价（更快） ★ 倒赚 ★★★ 无脑开
选择性重计算 ✅ 激活 −70%（65 → 11 GB） ✅ 仅 2.6% 算力 0.26 ms/GB ★ 默认开（但 FA 开了之后收益缩水）
完全重计算 ✅ 激活再降到 2sbh（11 → 5 GB） ⚠️ 33% 算力 ⚠️ 边际 27.5 ms/GB ⚠️ 按层开，够用就停
CPU 卸载 ✅ 什么都能省 ⚠️ 慢 55 倍的搬运 ⚠️ ≈ 33 ms/GB（除非能藏起来） 显存实在不够时 
    ★★ 开启顺序（⚠️ 工程经验，我的总结，不是论文结论）：

      ① FlashAttention          （倒赚，没有理由不开）
        → ② SP                  （几乎免费，见 [08 章](08-序列并行与上下文并行.md)）
          → ③ 选择性重计算       （0.26 ms/GB）
            → ④ 部分层完全重计算 （27.5 ms/GB，★ 开够就停，别一刀切）
              → ⑤ CPU 卸载       （33 ms/GB，万不得已）

    ★ 这个顺序就是按 §11.5.3 那把尺子从便宜到贵排的 —— 不用背，会算就行。

11.8 挂回 Megatron

--recompute-granularity selective   # ★ §11.3，默认推荐
--recompute-granularity full        #   完全重计算
  --recompute-method uniform        #   均匀分组（对应 §11.2.2 的 O(√n) 思路）
  --recompute-method block          #   ★ 只重算前 N 层 —— §11.4.2 说的"够用就停"
  --recompute-num-layers N          #   ★ 这个 N 就是你要买多少 GB 的旋钮
--recompute-modules mla moe mlp moe_act norm
                                    # ✅ v0.13 起的细粒度重计算，
                                    #   可以精确到"重算哪几种模块"
--use-flash-attn                    # §11.5

    源码位置：
      megatron/core/transformer/transformer_block.py
          ★ 重计算的分组逻辑在这里（_checkpointed_forward）
      megatron/core/tensor_parallel/random.py
          ★★ 一个容易忽略但关键的文件：重计算必须复现【同一个 dropout 掩码】，
             否则前向和重算的结果不一致，梯度就是错的。
             这里管的就是随机数状态的保存与恢复。

🔑 上面那个随机数问题值得多说一句：重计算的正确性前提是"重算一遍得到和第一次完全相同的结果"。dropout 是随机的，所以框架必须在第一次前向时记下随机数种子状态，重算时精确恢复。这是所有重计算实现里最容易出 bug 的地方——而且它的症状特别隐蔽：不报错、不 NaN，只是 loss 降得比应该的慢一点。

11.9 本章小结

① ★ 反向传播需要每一层的【输入】来算权重梯度 → 这就是激活必须存的原因
   激活 ∝ 层数 × batch × 序列长度，★ 和参数量无关

② ★ 重计算 = 不存，反向时重新前向一遍
   ✅ 2016 年论文：O(√n) 显存 + 一遍额外前向；极端可到 O(log n)
   ★ √n 的来历：分 k 段，显存 = k + n/k，k = √n 时最小（n=100 → 100 份降到 20 份）
   ⚠️ ✅ 代价 30~40%（验算：工作量从 1+2 变成 1+1+2，即 4/3 = +33%）
   ★ 记号：6N → 8N。⚠️ 6N = 2N 前向 + 4N 反向，【不含优化器，也不含注意力那个 s² 项】
     补全式：每 token FLOPs ≈ 6N + 12·L·s·h

③ ★★★ 选择性重计算：只重算【占显存大、重算便宜】的那部分
   ★ 对象就是公式里的 5as/h 项（QKᵀ、softmax、dropout、attn over V）
   ✅ GPT-3（a=96, s=2048, h=12288）：5as/h = 80 vs 34
      → 省 80/114 = 70.2%，只花 2.7% 算力  ✅ 和论文对上

④ ★★★ 汇率表（⚠️ 举例配置：80 层 / h=8192 / s=4096 / TP=8+SP，每卡 400 TFLOP/s）：
   不重计算 → 选择性：省 53.7 GB，付 13.7 ms  ⟹ ✅ 0.26 ms/GB
   不重计算 → 完全：  省 59.7 GB，付 179 ms   ⟹ ⚠️ 3.0 ms/GB
   ★ 选择性 → 完全（边际）：只多省 6 GB，要多付 165 ms ⟹ ⚠️⚠️ 27.5 ms/GB，贵 106 倍
   → 🔑 看边际价，不看平均价。完全重计算要【按层买】，够用就停。

⑤ ✅ Megatron-3 Table 2 是全书最值得记的一张表：
   只 TP：      sbh(★10★ + 24/t + 5as/ht)   ← ★ 那个不除 t 的 10 就是 TP 的漏洞
   TP+SP：      sbh(34/t + 5as/ht)          ← ★ 10 被消灭了
   TP+SP+选择性：sbh(34/t)                   ← ★ 只有基线的 3.7%
   完全重计算：  sbh(2)
   ✅ 总成绩（A100 × 2240，530B）：激活 ÷5，重计算开销 −90%（验算 33→2.7 即 −92% ✅），
      MFU 54.2% vs 42.1%（54.2/42.1 = 快 29% ✅）

⑥ ★★ HFU 和 MFU 会被重计算撑开：
   完全重计算 ⟹ ★ HFU = MFU × 8/6 = ×1.333（MFU 45% 可以写成 HFU 60%）
   选择性     ⟹ 系数【小于】4/3，本例 ×1.026、GPT-3 ×1.027
   不重计算   ⟹ 两者相等
   ⚠️ 看到任何"利用率 XX%"先问：分子算没算重计算？（详见 [12 章 §12.2](12-并行策略组合与MFU.md)）
   ⚠️ 引用 MFU 必须带硬件平台；54.2% 那个是 A100（峰值 312 TFLOPS）

⑦ ⚠️「时间减少 X%」≠「加速 X%」：加速倍数 = 1 / (1 − 时间减少比例)
   42.1% → 54.2% MFU：时间减少 22.3%，加速 29%
   时间减少 60% ⟹ ★ 加速 2.5 倍，不是"快 60%"

⑧ ★★★ 一条判据统一整章：★ 重算 FLOP / 字节 < 295（H100 屋脊点）就该重算 ★
   整层         ≈ 1100  → 存着更快，重算必赔 33%
   34 那一项    ≈ 5800  → 绝对要存
   5as/h 那一项 ≈ 100   → 该重算（这正是选择性重计算挑中它的原因）
   FlashAttention 的 QKᵀ = d = 128 → ★★ 重算净赚
   ✅ 04 章 §4.6 的账：存下来再读回 2.56 ms，重算只要 0.74 ms，★ 快 3.5 倍还省 4.29 GB
   ⟹ ★★ FlashAttention 不是"时间换空间"，是【两头都赚】★★
   ⚠️ 副作用：它让 5as/h 项在真实系统里基本消失，选择性重计算的收益随之缩水

⑨ CPU 卸载：⚠️ PCIe 比 HBM 慢 55 倍 ⟹ ≈ 33 ms/GB，比最贵的重计算还贵
   → 只适合"很久才用一次"且搬运能被计算盖住的东西
   ✅ 优化器状态、流水线靠前 stage 的激活；❌ 当前层权重

⑩ ⚠️ 重计算的隐藏坑：必须复现同一个 dropout 掩码，
   → 框架要保存 / 恢复随机数状态（megatron/core/tensor_parallel/random.py）
   → 症状隐蔽：不报错、不 NaN，只是 loss 降得慢一点

第三部分到此结束。 五种切法 + 两种"不切也能省"，工具箱已经齐了。接下来的第四部分讲工程现实：这些旋钮该怎么组合、怎么判断自己跑得快不快（MFU 还是 HFU？）、几千张卡上会坏什么、以及断了怎么接着训。
